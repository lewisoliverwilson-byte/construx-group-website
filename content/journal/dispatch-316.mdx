The `<Image>` component from `next/image` replaces `<img>` with automatic:
- WebP/AVIF conversion
- Responsive `srcset` generation
- Lazy loading with threshold-based preloading
- Cumulative Layout Shift prevention via reserved space

Most of this happens automatically if you configure it correctly.

## Basic usage

```tsx
import Image from 'next/image';

// Local import — dimensions known at build time
import heroImage from '@/public/hero.jpg';

export function Hero() {
  return (
    <Image
      src={heroImage}
      alt="Hero image"
      priority // preload — use for above-the-fold images
      className="w-full h-auto"
    />
  );
}

// Remote URL — must declare dimensions
export function ProductCard({ imageUrl }: { imageUrl: string }) {
  return (
    <Image
      src={imageUrl}
      alt="Product"
      width={400}
      height={300}
      className="rounded-md object-cover"
    />
  );
}
```

## The `priority` prop matters

By default, all images are lazy loaded. For above-the-fold images — the hero, the first product in a list, the user avatar in the header — add `priority`. It disables lazy loading and adds a `<link rel="preload">` in the `<head>`.

Using `priority` on every image defeats the purpose. Use it only for images visible on first render without scrolling.

## Remote image domains

For external image sources, whitelist them in `next.config.ts`:

```ts
// next.config.ts
import type { NextConfig } from 'next';

const config: NextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'your-s3-bucket.amazonaws.com',
        port: '',
        pathname: '/images/**',
      },
      {
        protocol: 'https',
        hostname: '**.cloudfront.net',
      },
    ],
  },
};

export default config;
```

Using `**` wildcards for subdomains is fine for CDNs. Avoid `hostname: '*'` — that's equivalent to no whitelist.

## `fill` for containers with unknown aspect ratios

When you don't know the image dimensions in advance or want the image to fill its container:

```tsx
<div className="relative aspect-video w-full">
  <Image
    src={thumbnailUrl}
    alt={title}
    fill
    sizes="(max-width: 768px) 100vw, 50vw"
    className="object-cover"
  />
</div>
```

The container needs `position: relative` (or `absolute`/`fixed`) and a defined size. `fill` makes the image `position: absolute` to fill its parent.

## The `sizes` prop

`sizes` tells the browser how wide the image will be at different viewport widths. Next.js uses this to generate an optimal `srcset`. Without it, the browser may download a much larger image than needed:

```tsx
<Image
  src={src}
  alt={alt}
  width={800}
  height={600}
  sizes="(max-width: 640px) 100vw, (max-width: 1024px) 50vw, 800px"
/>
```

Read: "On mobile (under 640px), this image is 100% of the viewport. On tablet, it's 50%. On desktop it's 800px max." Next.js generates `srcset` entries matching these breakpoints.

For full-width images: `sizes="100vw"`. For half-width: `sizes="50vw"`. Getting this wrong means users on mobile download 2x-3x the pixels they need.

## Quality and formats

```ts
// next.config.ts
const config: NextConfig = {
  images: {
    formats: ['image/avif', 'image/webp'], // AVIF first (smaller), WebP fallback
    deviceSizes: [640, 750, 828, 1080, 1200, 1920], // srcset breakpoints
    imageSizes: [16, 32, 48, 64, 96, 128, 256, 384], // for small images
    minimumCacheTTL: 60 * 60 * 24 * 30, // 30 days cache
  },
};
```

AVIF is ~40% smaller than WebP for equivalent quality. Next.js tries AVIF first and falls back to WebP if the browser doesn't support it. The default `quality` is 75 — suitable for most photography, may need raising for product images with fine detail.

## SVGs and placeholder images

SVGs are not optimized by `next/image` — serve them as regular `<img>` or import them directly. For loading states, use `placeholder="blur"` with `blurDataURL`:

```tsx
import Image from 'next/image';

// With local imports — blur placeholder is generated automatically
import productImage from './product.jpg';

<Image
  src={productImage}
  alt="Product"
  placeholder="blur"
  // blurDataURL is generated automatically for local imports
/>

// For remote images — provide a base64 placeholder
<Image
  src={remoteUrl}
  alt="Product"
  width={400}
  height={300}
  placeholder="blur"
  blurDataURL="data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mNkYPhfDwAChwGA60e6kgAAAABJRU5ErkJggg=="
/>
```

The blur placeholder prevents the layout shift as the image loads. For remote images, generate a tiny placeholder at build time using a tool like `plaiceholder`.
