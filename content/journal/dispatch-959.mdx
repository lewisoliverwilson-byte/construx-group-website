For ML/AI workloads, GPU memory fragmentation and utilization drops between training steps are the key metrics to watch. CUDA out-of-memory errors (OOM) are almost always caused by gradient accumulation not being tuned correctly or by not calling `torch.no_grad()` during evaluation. nvidia-smi --query-gpu exports metrics in CSV for Prometheus/Grafana integration."

Watch utilization, memory, power. `dmon` for continuous sampling. `--query-gpu` for Prometheus scraping.

## Basic monitoring and process table

```bash
# nvidia-smi: snapshot of all GPUs and their processes
nvidia-smi

# +--------------------------------------------------------------------------------------+
# | NVIDIA-SMI 560.35.03    Driver: 560.35.03    CUDA: 12.6                            |
# +-----------------------------------------+---------------------+--------------------+
# | GPU  Name           Temp  Perf  Pwr:Usage/Cap  Memory-Usage    GPU-Util             |
# |   0  NVIDIA A100 SXM  72C   P0   312W / 400W   38400MiB/40960MiB  93%  Default     |
# |   1  NVIDIA A100 SXM  68C   P0   284W / 400W   31744MiB/40960MiB  71%  Default     |
# +--------------------------------------------------------------------------------------+
# | Processes:                                                                           |
# |  GPU  GI  CI  PID    Type  Process name                              GPU Memory      |
# |    0   0   0  18241   C    python3 train_construx_model.py           32748MiB        |
# |    1   0   0  19312   C    python3 eval_construx_model.py            31744MiB        |
# +--------------------------------------------------------------------------------------+

# Column meanings:
# Temp      — GPU core temperature in Celsius (>85C → throttling starts)
# Perf      — performance state (P0 = max, P8 = idle)
# Pwr:Usage — current power draw (should be near Pwr:Cap during training)
# Memory-Usage — GPU VRAM used / total (OOM if usage reaches max)
# GPU-Util  — fraction of time GPU had at least one kernel running (1s window)

# Watch in real time
watch -n 1 nvidia-smi

# Show specific GPU
nvidia-smi -i 0

# Show GPU topology (NVLink / PCIe connections)
nvidia-smi topo -m
```

## Continuous monitoring with dmon

```bash
# dmon: continuous monitoring, one line per sample per GPU
nvidia-smi dmon -s pucvmet -d 1

# -s: metrics to show (p=power, u=utilization, c=proc_clocks, v=volt, m=mem, e=ECC, t=temp)
# -d: delay in seconds
# -c: number of samples (default: infinite)

# Output format:
# # gpu  pwr  temp    sm   mem   enc   dec  mclk  pclk
# # Idx    W     C     %     %     %     %   MHz   MHz
#      0  312    72    93    81     0     0  1593  1410
#      1  284    68    71    64     0     0  1593  1395

# sm  = streaming multiprocessor utilization (compute)
# mem = memory utilization (bandwidth, not allocation)
# enc/dec = video encoder/decoder utilization

# Useful: watch for utilization drops between batches (pipeline stalls)
nvidia-smi dmon -s u -d 0.5 -i 0 | awk '{print strftime("%H:%M:%S"), $0}'

# Log to file for offline analysis
nvidia-smi dmon -s pucmt -d 5 >> /var/log/gpu-metrics.csv &

# Parse with awk: alert if GPU 0 utilization drops below 50%
nvidia-smi dmon -s u -d 1 -i 0 | awk '$3 < 50 {print "LOW GPU UTIL:", $3"%", strftime("%H:%M:%S")}'
```

## Query and export for Prometheus

```bash
# --query-gpu: machine-readable metric export
nvidia-smi --query-gpu=index,name,temperature.gpu,utilization.gpu,utilization.memory,\
memory.total,memory.free,memory.used,power.draw,power.limit \
  --format=csv,noheader,nounits

# 0, NVIDIA A100 SXM, 72, 93, 81, 40960, 2560, 38400, 312.00, 400.00
# 1, NVIDIA A100 SXM, 68, 71, 64, 40960, 9216, 31744, 284.00, 400.00

# Prometheus textfile exporter (scrape via node_exporter --textfile.directory)
nvidia-smi --query-gpu=index,name,temperature.gpu,utilization.gpu,memory.used,power.draw \
  --format=csv,noheader,nounits | \
  awk -F', ' '{
    printf "gpu_temperature_celsius{gpu=\"%s\",name=\"%s\"} %s\n", $1, $2, $3
    printf "gpu_utilization_percent{gpu=\"%s\",name=\"%s\"} %s\n", $1, $2, $4
    printf "gpu_memory_used_mib{gpu=\"%s\",name=\"%s\"} %s\n", $1, $2, $5
    printf "gpu_power_draw_watts{gpu=\"%s\",name=\"%s\"} %s\n", $1, $2, $6
  }' > /var/lib/node_exporter/textfile_collector/gpu.prom

# Process-level GPU memory usage
nvidia-smi --query-compute-apps=pid,used_memory --format=csv,noheader,nounits
# 18241, 32748   ← training job PID and GPU memory used (MiB)
# 19312, 31744
```

## nvitop — interactive GPU process monitor

```bash
# nvitop: htop-style interactive GPU monitor
pip install nvitop
nvitop

# Layout:
# ┌─ GPU 0 ────────────────────────────────────────────────────────────────────┐
# │  NVIDIA A100 SXM | 93% | 38.4/40.0 GiB | 72°C | 312W/400W               │
# │  ████████████████████████████████████████████████████████████████░ 93%    │
# └──────────────────────────────────────────────────────────────────────────┘
# ┌─ GPU 1 ────────────────────────────────────────────────────────────────────┐
# │  NVIDIA A100 SXM | 71% | 31.7/40.0 GiB | 68°C | 284W/400W               │
# │  ██████████████████████████████████████████████░░░░░░░░░░░░░░░░░░ 71%    │
# └──────────────────────────────────────────────────────────────────────────┘
# ┌─ Processes ─────────────────────────────────────────────────────────────────┐
# │ GPU  PID    USER     %CPU   %MEM   GPU%   GPU-MEM  TIME  COMMAND            │
# │   0  18241  construx  82.4   4.1   93.0  32748MiB  4h22m python3 train.py  │
# │   1  19312  construx  24.1   2.8   71.0  31744MiB  2h14m python3 eval.py   │

# Key bindings: same as htop (q=quit, F5=tree, F6=sort, F9=signal)
# Sort by GPU memory: press F6 → select GPU-MEM

# Monitor-only mode (no interaction, for logging)
nvitop --monitor-mode
```

## Common GPU OOM debugging

```bash
# CUDA out-of-memory: find which process is holding GPU memory
nvidia-smi --query-compute-apps=pid,used_memory,name --format=csv,noheader
# 18241, 32748, python3   ← training job
# Kill it if needed
kill -9 18241

# Python: find where memory is allocated (torch)
# import torch
# print(torch.cuda.memory_summary())  # shows allocations by size
# print(torch.cuda.max_memory_allocated() / 1e9, "GB peak")

# Reserved vs allocated: torch caches allocations in a pool
# torch.cuda.memory_allocated()   — actually in use
# torch.cuda.memory_reserved()    — held in the caching allocator
# Difference = fragmentation (can be released with torch.cuda.empty_cache())

# Set max split size to reduce fragmentation (at cost of throughput)
# PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:512 python train.py

# OOM checklist:
# 1. Reduce batch size
# 2. Enable gradient checkpointing (recompute vs store activations)
# 3. Use mixed precision (fp16/bf16) — halves memory for activations
# 4. Call optimizer.zero_grad(set_to_none=True) instead of optimizer.zero_grad()
# 5. Ensure torch.no_grad() wraps evaluation loops
# 6. Free intermediate tensors explicitly with del tensor; torch.cuda.empty_cache()
```

nvidia-smi vs nvitop vs Grafana: nvidia-smi is the reference tool — always available, scriptable, and the source of truth for GPU state. nvitop gives you the htop experience for GPUs — interactive, sorted, and shows both CPU and GPU metrics side by side. Grafana + Prometheus + the GPU exporter is the right choice for fleet-level monitoring across multiple nodes — dashboards, alerting, and historical trends. The daily workflow: use nvitop during active training to watch for utilization drops (pipeline stalls, data loading bottlenecks), use nvidia-smi --query-gpu for scripted checks and Prometheus export, and use the Grafana dashboard for cross-run comparisons and alerting on temperature or OOM events.
