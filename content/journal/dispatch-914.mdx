excerpt: "journalctl queries the systemd journal — a structured binary log store that collects output from all systemd services, the kernel, and applications that write to the system journal. Unlike syslog's flat text, the journal stores logs as key-value entries with metadata: unit name, PID, UID, priority level, timestamp with microsecond precision, and boot ID. journalctl can filter by unit, priority, time range, and cursor; export as JSON for log aggregation pipelines; and show kernel messages, boot logs, and crash dumps. It's the primary log tool on any systemd-based Linux system."

`-u` for unit, `-p` for priority, `-o json` for pipelines. The journal is indexed — queries are fast.

## Basic filtering

```bash
# Follow a service in real time (like tail -f)
journalctl -u construx-api.service -f

# Last 100 lines from a service
journalctl -u construx-api -n 100 --no-pager

# Logs since a specific time
journalctl -u construx-api --since "2032-06-05 14:00:00" --until "2032-06-05 15:00:00"

# Human-friendly relative time
journalctl -u construx-api --since "1 hour ago"
journalctl -u construx-api --since "yesterday"

# Filter by priority (syslog levels)
# 0=emerg 1=alert 2=crit 3=err 4=warning 5=notice 6=info 7=debug
journalctl -u construx-api -p err                     # err and above
journalctl -u construx-api -p err..warning            # err and warning only
journalctl -u construx-api -p warning --since "today" # All warnings today

# All errors from any unit in the last 5 minutes
journalctl -p err --since "5 minutes ago"
# Jun 05 14:47:03 prod-01 construx-api[1847]: ERROR postgres: connection reset by peer
# Jun 05 14:47:03 prod-01 kernel: Out of memory: Killed process 2941

# Kernel messages only (equivalent to dmesg)
journalctl -k
journalctl -k --since "boot"   # Current boot only

# Boot-specific logs
journalctl --list-boots
# -1 a1b2c3d4 Mon 2032-06-04 00:00:01 — Mon 2032-06-04 23:59:59
#  0 e5f6a7b8 Tue 2032-06-05 00:00:02 —

journalctl -b 0    # Current boot
journalctl -b -1   # Previous boot (useful after a crash)
```

## JSON output for log pipelines

```bash
# JSON output — each log entry is a JSON object with full metadata
journalctl -u construx-api -o json | head -1 | jq .
# {
#   "__REALTIME_TIMESTAMP": "1748592727000000",
#   "__MONOTONIC_TIMESTAMP": "3241847000",
#   "_HOSTNAME": "prod-01",
#   "_SYSTEMD_UNIT": "construx-api.service",
#   "_PID": "1847",
#   "_UID": "1000",
#   "PRIORITY": "6",
#   "MESSAGE": "listening on :8080",
#   "_BOOT_ID": "e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0"
# }

# Extract just timestamp and message
journalctl -u construx-api -o json | jq -r '"\(.__REALTIME_TIMESTAMP) \(.MESSAGE)"'

# Ship to Loki (Grafana log aggregation) — journalctl → JSON → promtail
journalctl -u construx-api -o json -f | \
  jq -c '{stream: {job: "construx-api", host: ._HOSTNAME}, values: [[.__REALTIME_TIMESTAMP + "000", .MESSAGE]]}' | \
  curl -s -X POST http://loki:3100/loki/api/v1/push -H "Content-Type: application/json" -d @-

# Ship to Datadog (native systemd integration)
# /etc/datadog-agent/conf.d/journald.d/conf.yaml:
# logs:
#   - type: journald
#     include_units:
#       - construx-api.service
#       - construx-worker.service

# Export a time range to a file (for incident postmortem archival)
journalctl -u construx-api \
  --since "2032-06-05 14:30:00" \
  --until "2032-06-05 15:00:00" \
  -o json > /var/log/construx-incident-20320605.jsonl
```

## Disk usage and retention

```bash
# How much space is the journal using?
journalctl --disk-usage
# Archived and active journals take up 1.2 GiB on disk.

# Vacuum to a size limit (delete oldest archived journals)
journalctl --vacuum-size=500M
# Vacuuming done, freed 732.4 MiB of archived journals.

# Vacuum to a time limit
journalctl --vacuum-time=30d

# Rotate active journal files (useful before vacuuming)
journalctl --rotate

# Configure retention in /etc/systemd/journald.conf
cat /etc/systemd/journald.conf
# [Journal]
# SystemMaxUse=1G          # Max total disk usage
# SystemKeepFree=500M      # Always keep 500MiB free
# MaxRetentionSec=1month   # Delete entries older than 1 month
# Compress=yes             # LZ4 compress journal files
# ForwardToSyslog=no       # Don't forward to syslog (avoid double-logging)

systemctl restart systemd-journald   # Apply config changes
```

## Advanced filtering and cursor-based tailing

```bash
# Filter by field — any journal field can be filtered
journalctl _PID=1847                               # Logs from a specific PID
journalctl _UID=1000 -p warning                    # Warnings from UID 1000
journalctl _SYSTEMD_UNIT=construx-api.service _COMM=construx-api  # AND condition
journalctl _SYSTEMD_UNIT=construx-api.service + _SYSTEMD_UNIT=construx-worker.service  # OR

# Cursor-based streaming (for log shippers that need to resume after restart)
# Get the current cursor
journalctl -n 0 --show-cursor
# -- cursor: s=e5f6a7b8;i=1a2b;b=c3d4;m=e5f6;t=a7b8c9d0;x=e1f2a3b4

# Resume from cursor (after restart — no missed entries, no duplicates)
journalctl --after-cursor="s=e5f6a7b8;i=1a2b;..." -f

# Check journal integrity
journalctl --verify
# PASS: /var/log/journal/e5f6a7b8/system.journal

# Find which unit generated the most log volume
journalctl --disk-usage
du -sh /var/log/journal/*/
ls -lhS /var/log/journal/$(cat /etc/machine-id)/
```

journalctl vs traditional syslog: syslog writes plain text to /var/log/syslog — easy to grep, no schema, no metadata. The journal writes structured binary with indexed metadata, so `journalctl -p err --since "1 hour ago"` runs in milliseconds even on a 1GiB journal (it's indexed), while `grep ERROR /var/log/syslog | grep "$(date +%H)"` scans every byte. The journal also captures stdout/stderr from any systemd service automatically — no need to configure a logging library. The trade-off: the binary format requires journalctl to read it, making it harder to parse with basic shell tools. The solution: `-o json` exports structured data that any pipeline can consume.
