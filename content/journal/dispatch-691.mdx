TypeScript's Promise gives you async but nothing else. Errors are untyped, cancellation is bolted on, retries are manual, and observability is external. Effect models all of this as part of the type signature.

## Install

```bash
npm install effect
```

## Effect<A, E, R> — three type parameters

```ts
import { Effect } from 'effect';

// Effect<string, ParseError, DatabaseService>
// A = string   (success value)
// E = ParseError (typed error — not unknown)
// R = DatabaseService (requirement — must be provided)

const getUser = (id: string): Effect.Effect<User, UserNotFound | DbError, Database> =>
  Effect.gen(function* () {
    const db   = yield* Database;           // inject the dependency
    const row  = yield* db.findById(id);    // may fail with DbError
    if (!row) yield* Effect.fail(new UserNotFound(id));
    return row;
  });
```

Errors are first-class. The TypeScript compiler catches unhandled error cases at compile time.

## Layers: dependency injection

```ts
import { Context, Layer, Effect } from 'effect';

// Define the interface
class Database extends Context.Tag('Database')<
  Database,
  { findById: (id: string) => Effect.Effect<User | null, DbError> }
>() {}

// Live implementation (Postgres)
const DatabaseLive = Layer.effect(
  Database,
  Effect.gen(function* () {
    const pool = yield* createPool({ connectionString: process.env.DATABASE_URL });
    return {
      findById: (id) =>
        Effect.tryPromise({
          try:   () => pool.query('SELECT * FROM users WHERE id = $1', [id]),
          catch: (e) => new DbError(String(e)),
        }),
    };
  }),
);

// Test implementation (in-memory)
const DatabaseTest = Layer.succeed(Database, {
  findById: (id) =>
    Effect.succeed(id === 'u1' ? { id: 'u1', name: 'Alice' } : null),
});
```

## Error handling

```ts
import { Effect, Data } from 'effect';

class UserNotFound    extends Data.TaggedError('UserNotFound')<{ id: string }> {}
class InvalidInput    extends Data.TaggedError('InvalidInput')<{ field: string }> {}
class ServiceTimeout  extends Data.TaggedError('ServiceTimeout')<{}> {}

const program = getUser('u1').pipe(
  Effect.catchTag('UserNotFound', (e) => Effect.succeed(null)),    // handle one error type
  Effect.catchTags({
    InvalidInput:   (e) => Effect.logWarning(`bad field: ${e.field}`).pipe(Effect.as(null)),
    ServiceTimeout: ()  => Effect.succeed(null),
  }),
  Effect.tapError((e) => Effect.logError(`unhandled: ${e._tag}`)), // log remaining errors
);
```

## Retry and scheduling

```ts
import { Schedule, Effect } from 'effect';

const retryPolicy = Schedule.exponential('100 millis').pipe(
  Schedule.jittered,
  Schedule.upTo('30 seconds'),
  Schedule.whileOutput((n) => n < 10),  // max 10 retries
);

const resilient = Effect.retry(fetchRemoteData, retryPolicy);

// Timeout
const withTimeout = Effect.timeout(fetchRemoteData, '5 seconds');

// Race: take whichever resolves first
const fastest = Effect.race(fetchFromPrimary, fetchFromReplica);
```

## Structured concurrency

```ts
import { Effect } from 'effect';

// All three run in parallel; if one fails, the others are cancelled
const [user, posts, metrics] = yield* Effect.all(
  [getUser(id), getPosts(id), getMetrics(id)],
  { concurrency: 'unbounded' },
);

// Bounded concurrency: process 200 items, max 10 at a time
const results = yield* Effect.forEach(
  items,
  (item) => processItem(item),
  { concurrency: 10 },
);
```

## Running a program

```ts
import { Effect, Layer, Logger } from 'effect';
import { NodeRuntime }            from '@effect/platform-node';

const main = program.pipe(
  Logger.withMinimumLogLevel(Logger.LogLevel.Info),
  Effect.provide(DatabaseLive),
  Effect.provide(ConfigLive),
);

NodeRuntime.runMain(main);
// Handles unhandled errors, logs them, exits with correct code
```

## Effect vs fp-ts vs neverthrow vs plain Promise

Effect: typed errors + DI + concurrency + scheduling + observability in one model. Steep learning curve. neverthrow: typed Result<T, E> for simple error propagation, minimal footprint. fp-ts: functional programming primitives, smaller scope. Plain Promise: familiar, untyped errors, no structured concurrency. Use Effect for long-lived services where unhandled exceptions in production are unacceptable. Use neverthrow for boundary-level typed errors without the full Effect model.
