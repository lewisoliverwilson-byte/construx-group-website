Full-text search and vector search are not competing approaches. They answer different questions.

## Full-text search with tsvector

```sql
-- Add a search column (generated, always up to date)
ALTER TABLE posts ADD COLUMN search_vector tsvector
  GENERATED ALWAYS AS (
    setweight(to_tsvector('english', coalesce(title, '')),   'A') ||
    setweight(to_tsvector('english', coalesce(content, '')), 'B') ||
    setweight(to_tsvector('english', coalesce(excerpt, '')), 'C')
  ) STORED;

-- Index it
CREATE INDEX posts_search_idx ON posts USING GIN (search_vector);
```

```sql
-- Search query
SELECT
  id,
  title,
  ts_rank(search_vector, query) AS rank,
  ts_headline('english', content, query, 'MaxWords=50, MinWords=25') AS snippet
FROM
  posts,
  to_tsquery('english', 'typescript & (bun | node)') AS query
WHERE
  search_vector @@ query
ORDER BY
  rank DESC
LIMIT 10;
```

```ts
// In Drizzle ORM
import { sql } from 'drizzle-orm';

const results = await db
  .select({
    id:    posts.id,
    title: posts.title,
    rank:  sql<number>`ts_rank(search_vector, to_tsquery('english', ${query}))`,
  })
  .from(posts)
  .where(sql`search_vector @@ to_tsquery('english', ${query})`)
  .orderBy(sql`rank DESC`)
  .limit(10);
```

## Vector search with pgvector

```sql
CREATE EXTENSION IF NOT EXISTS vector;

ALTER TABLE posts ADD COLUMN embedding vector(1536);

-- HNSW index — fast approximate nearest neighbour
CREATE INDEX posts_embedding_idx ON posts
  USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);
```

```ts
// Generate embedding with OpenAI or Anthropic
async function getEmbedding(text: string): Promise<number[]> {
  const response = await openai.embeddings.create({
    model: 'text-embedding-3-small',
    input: text,
  });
  return response.data[0].embedding;
}

// Index a post
const embedding = await getEmbedding(`${post.title} ${post.content}`);
await db
  .update(posts)
  .set({ embedding: embedding as unknown as string })
  .where(eq(posts.id, post.id));

// Search by similarity
const queryEmbedding = await getEmbedding(searchQuery);
const results = await db.execute(sql`
  SELECT id, title,
         1 - (embedding <=> ${JSON.stringify(queryEmbedding)}::vector) AS similarity
  FROM posts
  WHERE embedding IS NOT NULL
  ORDER BY embedding <=> ${JSON.stringify(queryEmbedding)}::vector
  LIMIT 10
`);
```

## Hybrid search — combining both

```sql
SELECT
  id,
  title,
  -- Normalise and combine scores
  0.6 * ts_rank(search_vector, fts_query) +
  0.4 * (1 - (embedding <=> $1::vector)) AS combined_score
FROM
  posts,
  to_tsquery('english', $2) AS fts_query
WHERE
  search_vector @@ fts_query
  OR  embedding <=> $1::vector < 0.4   -- within similarity threshold
ORDER BY
  combined_score DESC
LIMIT 20;
```

Hybrid search ranks by both keyword relevance and semantic similarity. FTS catches exact matches. Vector search catches synonyms, related concepts, and queries in different languages.

## When to use which

Full-text search: product names, technical terms, exact phrases, code search, anything where the user knows what they are looking for. Vector search: "find posts like this", cross-language search, semantic Q&A, "what else is related to this topic". Hybrid: most production search experiences. Start with FTS — it is fast, free, and often enough. Add vector search when users complain about missed results.
