Feature flags are one of those things where the SaaS options (LaunchDarkly, GrowthBook, Unleash) look appealing until you're paying $400/month for something a Postgres table and 80 lines of TypeScript could do. The SaaS makes sense at scale — percentage rollouts, user targeting with complex rules, analytics integration. For most products, a simple flag store is enough.

## The schema

```sql
-- Drizzle schema
CREATE TABLE feature_flags (
  key         text PRIMARY KEY,
  enabled     boolean NOT NULL DEFAULT false,
  rollout     integer NOT NULL DEFAULT 100,  -- % of users to show flag to
  description text,
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX ON feature_flags(enabled);
```

```ts
// db/schema.ts
import { pgTable, text, boolean, integer, timestamp } from 'drizzle-orm/pg-core';

export const featureFlags = pgTable('feature_flags', {
  key:         text('key').primaryKey(),
  enabled:     boolean('enabled').notNull().default(false),
  rollout:     integer('rollout').notNull().default(100),
  description: text('description'),
  createdAt:   timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  updatedAt:   timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
});
```

## The flag client

```ts
// lib/flags.ts
import { db }          from '@/lib/db';
import { featureFlags } from '@/db/schema';
import { eq }          from 'drizzle-orm';
import { unstable_cache } from 'next/cache';

export type FlagKey =
  | 'new-onboarding-flow'
  | 'ai-recommendations'
  | 'beta-dashboard'
  | 'partner-api-v2';

export const getFlag = unstable_cache(
  async (key: FlagKey): Promise<boolean> => {
    const flag = await db
      .select()
      .from(featureFlags)
      .where(eq(featureFlags.key, key))
      .get();

    return flag?.enabled ?? false;
  },
  ['feature-flag'],
  { revalidate: 60, tags: ['feature-flags'] },
);

export async function getFlagWithRollout(key: FlagKey, userId: string): Promise<boolean> {
  const flag = await db
    .select()
    .from(featureFlags)
    .where(eq(featureFlags.key, key))
    .get();

  if (!flag || !flag.enabled) return false;
  if (flag.rollout >= 100) return true;

  // Stable hash of userId determines flag bucket
  const hash = userId.split('').reduce((acc, c) => acc + c.charCodeAt(0), 0);
  return (hash % 100) < flag.rollout;
}
```

The `unstable_cache` wrapper caches flag lookups for 60 seconds per process — one DB query per minute instead of per request. `revalidate` can be called manually (e.g., when an admin changes a flag):

```ts
import { revalidateTag } from 'next/cache';

// After updating a flag:
revalidateTag('feature-flags');
```

## Using flags in Server Components

```tsx
// app/dashboard/page.tsx
import { getFlag } from '@/lib/flags';

export default async function DashboardPage() {
  const showNewOnboarding = await getFlag('new-onboarding-flow');
  const showAiRecs        = await getFlag('ai-recommendations');

  return (
    <main>
      {showNewOnboarding ? <NewOnboardingFlow /> : <LegacyOnboarding />}
      {showAiRecs && <AiRecommendations />}
    </main>
  );
}
```

## Percentage rollouts

For a gradual rollout to 10% of users, then 25%, then 100%:

```ts
// app/dashboard/page.tsx
import { getFlagWithRollout } from '@/lib/flags';
import { auth } from '@clerk/nextjs/server';

export default async function DashboardPage() {
  const { userId } = await auth();

  const showBetaDashboard = userId
    ? await getFlagWithRollout('beta-dashboard', userId)
    : false;

  return showBetaDashboard ? <BetaDashboard /> : <StableDashboard />;
}
```

The hash ensures the same user always gets the same flag value — they don't switch sides on every request.

## Admin API

```ts
// app/api/admin/flags/route.ts
import { db }           from '@/lib/db';
import { featureFlags } from '@/db/schema';
import { revalidateTag } from 'next/cache';
import { eq }            from 'drizzle-orm';

export async function PATCH(req: Request) {
  const { key, enabled, rollout } = await req.json();

  await db
    .update(featureFlags)
    .set({ enabled, rollout, updatedAt: new Date() })
    .where(eq(featureFlags.key, key));

  revalidateTag('feature-flags');  // Bust the 60s cache immediately

  return Response.json({ ok: true });
}
```

## When to use a SaaS

This covers: on/off flags, percentage rollouts by user ID, cache-backed lookups. It doesn't cover: real-time push updates, complex targeting rules (user property, geography, plan tier), built-in analytics on flag exposure, audit logs with who changed what.

If you need real-time flag updates (no 60-second cache lag), GrowthBook's self-hosted option or Unleash with a local Redis cache is worth the extra setup. If you need complex targeting, LaunchDarkly. For everything else, a Postgres table is fine.
