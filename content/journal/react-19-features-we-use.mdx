React 19 shipped in late 2024 and Next.js 15 adopted it as the default. All three Construx products run on React 19. Here's the features we've actually adopted and what the impact has been.

## `use` for reading promises

React 19 introduced the `use` hook, which can read a Promise inside a render. The primary use case: reading async data in a client component without `useEffect`.

Before React 19, reading async data in a client component required:

```tsx
const [data, setData] = useState(null);
useEffect(() => {
  fetchData().then(setData);
}, []);
if (!data) return <Loading />;
return <Component data={data} />;
```

With `use` and Suspense:

```tsx
const data = use(fetchDataPromise);
return <Component data={data} />;
```

The component suspends until the promise resolves. Suspense boundaries catch the suspension and show a fallback. This is cleaner than the `useEffect` pattern for data that a component needs to render.

We use this pattern for client-side data in The Hyve, where some channel data is fetched client-side after initial render. The code is significantly cleaner than the equivalent `useEffect` pattern.

## Server Actions: the form submission pattern

Server Actions are the React 19 (and Next.js) mechanism for handling form submissions without a separate API route. We covered this in the App Router post — the contact form on the Construx Group website uses a Server Action.

In React 19, `useActionState` pairs with Server Actions to manage form state (pending, error, result) without manual state management:

```tsx
const [state, formAction] = useActionState(submitContactAction, { status: 'idle' });
```

When the form submits, `formAction` is called, `state.status` transitions to `'pending'`, and updates to `'success'` or `'error'` when the action completes. The form component reads `state` to show the appropriate UI.

This replaces a pattern that previously required `useState`, `useTransition`, and careful coordination of the loading/error/success states. The `useActionState` version is substantially simpler.

## `useOptimistic` for immediate UI feedback

`useOptimistic` allows showing an optimistic (immediately-applied) UI update while waiting for a server action to complete, then reconciling with the actual server result.

We use this in The Hyve for message sending. When a user sends a message to a channel, the message appears immediately in the channel (optimistic), the server action persists it, and if the server returns an error, the optimistic message is rolled back with an error state.

```tsx
const [optimisticMessages, addOptimisticMessage] = useOptimistic(
  messages,
  (current, newMessage) => [...current, { ...newMessage, pending: true }]
);
```

The user experience without optimistic updates: the message sends, a loading indicator shows, the message appears when the server confirms. The experience with optimistic updates: the message appears immediately, feels instantaneous, silently reconciles in the background.

For a real-time collaboration tool, this difference in perceived performance is significant. Channels feel fast.

## What we haven't adopted

**`use` for Context.** React 19 allows using `use(SomeContext)` instead of `useContext(SomeContext)`. The advantage is that `use` can be called conditionally; `useContext` cannot. We haven't adopted this because our context usage doesn't need conditional reading. `useContext` works fine.

**New ref syntax.** React 19 allows passing `ref` as a regular prop to any component (previously required `forwardRef` for class components, and the `ref` callback pattern for function components). We'll adopt this as we write new components, but haven't retrofitted existing components.

**`Document.startViewTransition` integration.** React 19 has hooks for the View Transitions API. We haven't explored this — our navigation is simple and doesn't need complex cross-page transitions.

## The realistic assessment

React 19's additions are evolutionary, not revolutionary. The core React model — components, state, props, effects — is unchanged. The new features simplify specific patterns (data fetching, form handling, optimistic updates) that required more verbose solutions before.

The adoption experience has been smooth. The new features slot in alongside existing patterns; we haven't had to refactor working code to use them. We've adopted them for new features and left older patterns in place where they work correctly.

The biggest practical benefit: `useActionState` with Server Actions makes form handling substantially simpler than the previous pattern. The second biggest: `useOptimistic` makes The Hyve's real-time feel significantly better with minimal additional code.
