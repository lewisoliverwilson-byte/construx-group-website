title: "OpenTelemetry Collector: vendor-neutral telemetry pipeline — receive, process, export"
date: "2033-08-26"
excerpt: "The OpenTelemetry Collector is a vendor-neutral agent and aggregator for telemetry data (traces, metrics, logs). Instead of each application sending data directly to Jaeger, Prometheus, and your logging backend, the application sends all telemetry to the local Collector using OTLP (OpenTelemetry Protocol), and the Collector handles routing, batching, filtering, and exporting to any backend. The Collector pipeline has three stages: receivers (OTLP, Jaeger, Prometheus, Zipkin, Kafka, and 60+ more), processors (batch, filter, attribute transformation, sampling, resource detection), and exporters (Jaeger, Tempo, Prometheus, Loki, Datadog, Splunk, and 100+ more). This makes the backend pluggable: swap Jaeger for Grafana Tempo without changing application code. The Collector also runs as a DaemonSet (collecting node-level metrics), as a Deployment (aggregating from multiple agents), and as a Sidecar (per-pod collection). The Grafana stack (Prometheus + Tempo + Loki + Pyroscope) uses the Collector as the common ingestion path for all telemetry."

## Collector configuration

```yaml
# otelcol-config.yaml: OpenTelemetry Collector pipeline

receivers:
  # OTLP: receive traces, metrics, logs from instrumented applications
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

  # Prometheus: scrape Prometheus-format metrics from services
  prometheus:
    config:
      scrape_configs:
        - job_name: construx-api
          scrape_interval: 15s
          static_configs:
            - targets: ["construx-api:8080"]
          metric_relabel_configs:
            - source_labels: [__name__]
              regex: "go_.*|process_.*"
              action: drop   # drop noisy Go runtime metrics

  # Kubernetes container logs via filelog receiver
  filelog:
    include:
      - /var/log/pods/construx_*/*/*.log
    operators:
      - type: json_parser
        timestamp:
          parse_from: attributes.time
          layout: "%Y-%m-%dT%H:%M:%S.%LZ"

  # Host metrics: CPU, memory, disk, network for the node
  hostmetrics:
    scrapers:
      cpu:
        metrics:
          system.cpu.time:         { enabled: true }
          system.cpu.utilization:  { enabled: true }
      memory:
        metrics:
          system.memory.usage:        { enabled: true }
          system.memory.utilization:  { enabled: true }
      disk:
        metrics:
          system.disk.io:             { enabled: true }
          system.disk.io_time:        { enabled: true }
      network:
        metrics:
          system.network.io:          { enabled: true }

processors:
  # Batch: accumulate telemetry before exporting (reduces network calls)
  batch:
    send_batch_size: 1024
    timeout: 200ms

  # Resource detection: add cloud metadata (AWS region, EKS cluster, pod name)
  resourcedetection:
    detectors: [eks, ec2]
    timeout: 5s
    override: false

  # Attribute filtering: remove sensitive data before export
  attributes/remove_sensitive:
    actions:
      - key: http.request.header.authorization
        action: delete
      - key: db.statement
        action: hash   # hash SQL rather than deleting (preserves pattern without content)

  # Tail-based sampling: sample 100% of traces with errors, 1% of healthy traces
  tail_sampling:
    decision_wait: 10s
    num_traces: 50000
    expected_new_traces_per_sec: 500
    policies:
      - name: errors
        type: status_code
        status_code: { status_codes: [ERROR] }
      - name: slow_spans
        type: latency
        latency: { threshold_ms: 500 }
      - name: probabilistic_sampling
        type: probabilistic
        probabilistic: { sampling_percentage: 1 }

  # Memory limiter: prevent OOM under high load
  memory_limiter:
    check_interval: 1s
    limit_percentage: 75
    spike_limit_percentage: 20

exporters:
  # Traces → Grafana Tempo
  otlp/tempo:
    endpoint: tempo.monitoring.svc.cluster.local:4317
    tls:
      insecure: true

  # Metrics → Prometheus (remote write)
  prometheusremotewrite:
    endpoint: http://prometheus.monitoring.svc.cluster.local:9090/api/v1/write
    tls:
      insecure: true

  # Logs → Loki
  loki:
    endpoint: http://loki.monitoring.svc.cluster.local:3100/loki/api/v1/push
    labels:
      attributes:
        service.name:   "service"
        k8s.pod.name:   "pod"
        k8s.namespace.name: "namespace"

  # Debug: log telemetry to stdout (useful during development)
  debug:
    verbosity: basic

service:
  pipelines:
    traces:
      receivers:  [otlp]
      processors: [memory_limiter, resourcedetection, attributes/remove_sensitive, tail_sampling, batch]
      exporters:  [otlp/tempo]
    metrics:
      receivers:  [otlp, prometheus, hostmetrics]
      processors: [memory_limiter, resourcedetection, batch]
      exporters:  [prometheusremotewrite]
    logs:
      receivers:  [otlp, filelog]
      processors: [memory_limiter, resourcedetection, batch]
      exporters:  [loki]
```

## Kubernetes DaemonSet deployment

```yaml
# Deploy Collector as DaemonSet (one per node) for host metrics + log collection
apiVersion: opentelemetry.io/v1alpha1
kind: OpenTelemetryCollector
metadata:
  name: construx-node-collector
  namespace: monitoring
spec:
  mode: daemonset
  config: |
    receivers:
      hostmetrics:
        scrapers:
          cpu:
          memory:
          disk:
          network:
      filelog:
        include: [/var/log/pods/construx_*/*/*.log]
    processors:
      batch:
        timeout: 5s
      resourcedetection:
        detectors: [eks, ec2]
    exporters:
      otlp:
        endpoint: construx-collector-gateway.monitoring.svc.cluster.local:4317
    service:
      pipelines:
        metrics:
          receivers: [hostmetrics]
          processors: [resourcedetection, batch]
          exporters: [otlp]
        logs:
          receivers: [filelog]
          processors: [resourcedetection, batch]
          exporters: [otlp]
  volumeMounts:
    - name: varlogpods
      mountPath: /var/log/pods
      readOnly: true
  volumes:
    - name: varlogpods
      hostPath:
        path: /var/log/pods
```

```typescript
// TypeScript: instrument an application with OpenTelemetry SDK
// Sends all telemetry to the local Collector via OTLP

import { NodeSDK } from "@opentelemetry/sdk-node";
import { OTLPTraceExporter } from "@opentelemetry/exporter-trace-otlp-grpc";
import { OTLPMetricExporter } from "@opentelemetry/exporter-metrics-otlp-grpc";
import { Resource } from "@opentelemetry/resources";
import { SEMRESATTRS_SERVICE_NAME, SEMRESATTRS_SERVICE_VERSION } from "@opentelemetry/semantic-conventions";
import { getNodeAutoInstrumentations } from "@opentelemetry/auto-instrumentations-node";

const sdk = new NodeSDK({
    resource: new Resource({
        [SEMRESATTRS_SERVICE_NAME]:    "construx-api",
        [SEMRESATTRS_SERVICE_VERSION]: process.env.APP_VERSION ?? "dev",
        "deployment.environment":      process.env.ENVIRONMENT ?? "development",
    }),
    traceExporter:  new OTLPTraceExporter({ url: "http://localhost:4317" }),
    metricExporter: new OTLPMetricExporter({ url: "http://localhost:4317" }),
    instrumentations: [
        getNodeAutoInstrumentations({
            "@opentelemetry/instrumentation-http":       { enabled: true },
            "@opentelemetry/instrumentation-express":    { enabled: true },
            "@opentelemetry/instrumentation-pg":         { enabled: true },
            "@opentelemetry/instrumentation-redis":      { enabled: true },
            "@opentelemetry/instrumentation-kafkajs":    { enabled: true },
        }),
    ],
});

sdk.start();
```

OpenTelemetry Collector vs direct SDK export vs Datadog Agent vs Fluent Bit: Direct SDK export (application sends traces directly to Jaeger, metrics to Prometheus) works at small scale but couples every service to every backend — changing from Jaeger to Tempo requires updating every service. Datadog Agent is excellent if you're committed to Datadog but creates vendor lock-in and high per-host cost. Fluent Bit collects logs efficiently but doesn't handle traces or metrics. The Collector's value is the decoupling: applications speak OTLP to localhost:4317, and the Collector handles multi-backend routing, sampling, batching, and attribute enrichment without touching application code. Tail-based sampling (decide to sample a trace only after seeing all its spans) is only possible at the Collector layer — application-side head sampling commits to keep/drop before seeing downstream spans. For teams running Grafana stack (Prometheus + Tempo + Loki) or needing to export to multiple backends, the Collector is the recommended architecture.
