Authentication is the part of a product most founders underestimate. It looks simple — a login form, a session — but the edge cases accumulate: password resets, email verification, magic links, OAuth providers, session rotation, token refresh, device management, MFA. Getting any of it wrong creates security vulnerabilities that are hard to detect and expensive to remediate.

The general rule: don't roll your own unless you have a specific reason to.

## Option 1: Clerk (hosted)

Clerk handles everything: signup flows, sign-in UI, OAuth providers, MFA, organization management, user profiles. You integrate a few components and an API client. You never touch session management or JWT generation.

```bash
npm install @clerk/nextjs
```

```ts
// middleware.ts
import { clerkMiddleware, createRouteMatcher } from '@clerk/nextjs/server';

const isProtectedRoute = createRouteMatcher(['/dashboard(.*)', '/api/protected(.*)']);

export default clerkMiddleware(async (auth, req) => {
  if (isProtectedRoute(req)) await auth.protect();
});

export const config = {
  matcher: ['/((?!_next|[^?]*\\.(?:html?|css|js(?!on)|jpe?g|webp|png|gif|svg|ttf|woff2?|ico|csv|docx?|xlsx?|zip|webmanifest)).*)', '/(api|trpc)(.*)'],
};
```

```tsx
// app/dashboard/page.tsx
import { auth, currentUser } from '@clerk/nextjs/server';

export default async function Dashboard() {
  const { userId } = await auth();
  if (!userId) return redirect('/sign-in');

  const user = await currentUser();

  return <div>Welcome, {user?.firstName}</div>;
}
```

**When to use Clerk**: early-stage products where shipping fast matters, B2B products that need organizations and teams, anything where you don't want to think about auth at all.

**Trade-offs**: $25/month base, plus per-MAU pricing. You're paying for the abstraction. Your user data lives in Clerk's infrastructure.

## Option 2: Auth.js (self-hosted library)

Auth.js (formerly NextAuth.js) is a framework-agnostic auth library that handles OAuth, email/password, magic links, and JWT/database sessions. You host it, your data stays in your database.

```bash
npm install next-auth@beta
```

```ts
// auth.ts
import NextAuth from 'next-auth';
import GitHub from 'next-auth/providers/github';
import Google from 'next-auth/providers/google';
import Resend from 'next-auth/providers/resend';
import { DrizzleAdapter } from '@auth/drizzle-adapter';
import { db } from '@/db';

export const { handlers, auth, signIn, signOut } = NextAuth({
  adapter: DrizzleAdapter(db),
  providers: [
    GitHub({
      clientId: process.env.AUTH_GITHUB_ID!,
      clientSecret: process.env.AUTH_GITHUB_SECRET!,
    }),
    Google({
      clientId: process.env.AUTH_GOOGLE_ID!,
      clientSecret: process.env.AUTH_GOOGLE_SECRET!,
    }),
    Resend({
      from: 'noreply@construxgroup.io',
    }),
  ],
  callbacks: {
    session: async ({ session, user }) => {
      session.user.id = user.id;
      return session;
    },
  },
});
```

```ts
// app/api/auth/[...nextauth]/route.ts
import { handlers } from '@/auth';
export const { GET, POST } = handlers;
```

```ts
// In server components
import { auth } from '@/auth';

export default async function Page() {
  const session = await auth();
  if (!session) redirect('/login');
  return <div>Hello {session.user?.name}</div>;
}
```

The `DrizzleAdapter` handles storing users, accounts, sessions, and verification tokens in your database automatically.

**When to use Auth.js**: when you want your user data in your own database, when Clerk's pricing doesn't fit, or when you need deep customization of the auth flow.

**Trade-offs**: more setup, you own the maintenance, you handle database schema for auth tables.

## Option 3: Rolling your own JWT auth

For APIs, mobile clients, or specific requirements, sometimes you need full control. Here's a minimal but secure implementation:

```ts
// lib/auth/tokens.ts
import { SignJWT, jwtVerify } from 'jose';
import { cookies } from 'next/headers';

const JWT_SECRET = new TextEncoder().encode(process.env.JWT_SECRET!);

export async function createToken(payload: { userId: string; email: string }): Promise<string> {
  return new SignJWT(payload)
    .setProtectedHeader({ alg: 'HS256' })
    .setIssuedAt()
    .setExpirationTime('7d')
    .sign(JWT_SECRET);
}

export async function verifyToken(token: string) {
  try {
    const { payload } = await jwtVerify(token, JWT_SECRET);
    return payload as { userId: string; email: string };
  } catch {
    return null;
  }
}

export async function getSession() {
  const cookieStore = await cookies();
  const token = cookieStore.get('session')?.value;
  if (!token) return null;
  return verifyToken(token);
}
```

```ts
// lib/auth/password.ts
import { hash, verify } from '@node-rs/argon2';

export async function hashPassword(password: string): Promise<string> {
  return hash(password, {
    memoryCost: 19456,
    timeCost: 2,
    outputLen: 32,
    parallelism: 1,
  });
}

export async function verifyPassword(hash: string, password: string): Promise<boolean> {
  return verify(hash, password);
}
```

Use `@node-rs/argon2` — not `bcrypt`. Argon2id is the modern recommended password hashing algorithm. bcrypt has known weaknesses against GPU cracking.

## Protecting routes in middleware

```ts
// middleware.ts — works for all three approaches
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export async function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl;

  if (pathname.startsWith('/dashboard') || pathname.startsWith('/api/protected')) {
    const session = request.cookies.get('session')?.value;

    if (!session) {
      const loginUrl = new URL('/login', request.url);
      loginUrl.searchParams.set('from', pathname);
      return NextResponse.redirect(loginUrl);
    }
  }

  return NextResponse.next();
}
```

## The decision matrix

| | Clerk | Auth.js | Roll your own |
|---|---|---|---|
| Setup time | < 1 hour | 2–4 hours | 1–2 days |
| User data location | Clerk's cloud | Your database | Your database |
| OAuth providers | Built-in | Built-in | Manual per provider |
| Cost | $25/mo + MAU | Free (infrastructure cost) | Free |
| Customization | Limited | High | Full |
| MFA | Built-in | Manual | Manual |

For most products: Clerk until $1k MRR, Auth.js after that. Roll your own only when Auth.js can't fit your requirements.
