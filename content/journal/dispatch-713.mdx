Components that read from a snapshot re-render only when the specific values they read change. The proxy tracks exactly which properties each component accessed and re-renders precisely those components. Less boilerplate than Zustand, more precise than Context."

Most state management adds ceremony: actions, reducers, selectors, computed values. Valtio removes all of it. You write state mutation like you write any JavaScript object mutation — the proxy handles the reactivity.

## Install

```bash
npm install valtio
```

## Basic state

```ts
// store/posts.ts
import { proxy } from 'valtio';

export const postsStore = proxy({
  posts:    [] as Post[],
  loading:  false,
  error:    null as string | null,
  selected: null as Post | null,

  async fetchPosts() {
    this.loading = true;
    this.error   = null;
    try {
      const res    = await fetch('/api/posts');
      this.posts   = await res.json();
    } catch (e) {
      this.error   = String(e);
    } finally {
      this.loading = false;
    }
  },

  selectPost(id: string) {
    this.selected = this.posts.find((p) => p.id === id) ?? null;
  },
});
```

## Using in components

```tsx
'use client';
import { useSnapshot } from 'valtio';
import { postsStore }  from '@/store/posts';

function PostList() {
  // useSnapshot creates a reactive read-only snapshot
  // PostList only re-renders when posts, loading, or error change
  const snap = useSnapshot(postsStore);

  if (snap.loading) return <Spinner />;
  if (snap.error)   return <p>Error: {snap.error}</p>;

  return (
    <ul>
      {snap.posts.map((post) => (
        <li key={post.id} onClick={() => postsStore.selectPost(post.id)}>
          {post.title}
        </li>
      ))}
    </ul>
  );
}

function PostDetail() {
  // This component only re-renders when 'selected' changes
  const { selected } = useSnapshot(postsStore);
  if (!selected) return null;
  return <article><h1>{selected.title}</h1></article>;
}
```

## Derived state with derive

```ts
import { proxy }  from 'valtio';
import { derive } from 'valtio/utils';

const store = proxy({
  items:    [] as { id: string; price: number; qty: number }[],
  discount: 0,
});

const derived = derive({
  // Recomputes only when items or discount change
  total: (get) =>
    get(store).items.reduce((sum, i) => sum + i.price * i.qty, 0) *
    (1 - get(store).discount),

  itemCount: (get) =>
    get(store).items.reduce((sum, i) => sum + i.qty, 0),
});
```

## subscribeKey: side effects on specific fields

```ts
import { subscribeKey } from 'valtio/utils';

// Persist to localStorage whenever posts change
const unsubscribe = subscribeKey(postsStore, 'posts', (posts) => {
  localStorage.setItem('cached-posts', JSON.stringify(posts));
});

// Later: unsubscribe()
```

## Nested state and arrays

```ts
const store = proxy({
  user: { name: 'Lewis', settings: { theme: 'dark' } },
  tags: ['TypeScript', 'React'],
});

// Direct mutation — Proxy captures all of these
store.user.name = 'Lewis Wilson';
store.user.settings.theme = 'light';
store.tags.push('Next.js');
store.tags = store.tags.filter((t) => t !== 'React');
```

## Valtio vs Zustand vs Jotai

Valtio: mutable state via Proxy, minimal boilerplate, precise re-renders, mental model closest to plain JS. Zustand: immutable updates, explicit selectors, slightly more ceremony, great DevTools. Jotai: atomic model, fine-grained updates, excellent for derived state from multiple sources. Valtio is the right choice when you want the simplest possible state that scales beyond useState without the Redux ceremony. Use Jotai when your state is genuinely atomic with complex derivations.
