A feature flag is a conditional that controls whether a feature is active. The simplest version is a boolean environment variable. The production-ready version is a dynamic system that can target specific users, roll out gradually, and be toggled without a redeploy.

## Why you need them

**Continuous deployment** — merge code before the feature is finished. The flag keeps it hidden. No long-lived feature branches.

**Gradual rollouts** — enable for 10% of users, watch metrics, expand to 50%, then 100%. Roll back instantly if something breaks.

**Kill switches** — if a feature causes problems in production, turn it off in 30 seconds without a redeploy.

**A/B testing** — split traffic between two implementations and measure the difference.

## Simple flags in environment variables

For static flags (true/false, no targeting, no rollout):

```ts
// lib/flags.ts
export const flags = {
  newBillingFlow: process.env.NEXT_PUBLIC_FLAG_NEW_BILLING === 'true',
  aiAssistant: process.env.FLAG_AI_ASSISTANT === 'true',  // server-only
  betaDashboard: process.env.NEXT_PUBLIC_FLAG_BETA_DASHBOARD === 'true',
} as const;
```

```tsx
// Use in component
import { flags } from '@/lib/flags';

export function BillingSection() {
  if (!flags.newBillingFlow) return <LegacyBillingSection />;
  return <NewBillingSection />;
}
```

For flags that never need user targeting, this is all you need.

## Dynamic flags with database storage

Store flags in a database for real-time toggling without redeploys:

```ts
// db/schema.ts
export const featureFlags = pgTable('feature_flags', {
  id: text('id').primaryKey(),
  enabled: boolean('enabled').notNull().default(false),
  rolloutPct: integer('rollout_pct').notNull().default(0),  // 0-100
  allowedUserIds: text('allowed_user_ids').array(),  // always-on users
  description: text('description'),
  updatedAt: timestamp('updated_at').defaultNow(),
});
```

```ts
// lib/flags.ts
import { unstable_cache } from 'next/cache';

const FLAGS_CACHE_TTL = 60;  // revalidate every 60 seconds

const getFlag = unstable_cache(
  async (flagId: string) => {
    return db.query.featureFlags.findFirst({
      where: eq(featureFlags.id, flagId),
    });
  },
  ['feature-flag'],
  { revalidate: FLAGS_CACHE_TTL, tags: ['flags'] },
);

export async function isEnabled(flagId: string, userId?: string): Promise<boolean> {
  const flag = await getFlag(flagId);
  if (!flag || !flag.enabled) return false;

  // Always-on for specific users
  if (userId && flag.allowedUserIds?.includes(userId)) return true;

  // Gradual rollout — deterministic bucketing by user ID
  if (userId && flag.rolloutPct < 100) {
    const hash = await deterministicHash(`${flagId}:${userId}`);
    return hash % 100 < flag.rolloutPct;
  }

  // Full rollout
  return flag.rolloutPct === 100;
}

async function deterministicHash(input: string): Promise<number> {
  const encoder = new TextEncoder();
  const data = encoder.encode(input);
  const hashBuffer = await crypto.subtle.digest('SHA-256', data);
  const hashArray = new Uint8Array(hashBuffer);
  return hashArray[0];  // 0-255, take mod 100 for percentage
}
```

## Using flags in Server Components

```tsx
// app/dashboard/page.tsx
import { isEnabled } from '@/lib/flags';
import { auth } from '@/auth';

export default async function DashboardPage() {
  const session = await auth();
  const showNewLayout = await isEnabled('new-dashboard-layout', session?.user.id);

  if (showNewLayout) return <NewDashboard />;
  return <LegacyDashboard />;
}
```

## Using flags on the edge (middleware)

For routing-level flags (redirect, serve different page):

```ts
// middleware.ts
import { isEnabled } from '@/lib/edge-flags';  // HTTP-only version for edge

export async function middleware(req: NextRequest) {
  const userId = req.cookies.get('session')?.value;

  const showBeta = await isEnabled('beta-homepage', userId);
  if (showBeta && req.nextUrl.pathname === '/') {
    return NextResponse.rewrite(new URL('/beta', req.url));
  }

  return NextResponse.next();
}
```

## Admin UI for flag management

```ts
// app/api/admin/flags/route.ts
export async function PATCH(req: Request) {
  const session = await auth();
  if (session?.user.role !== 'admin') {
    return Response.json({ error: 'Forbidden' }, { status: 403 });
  }

  const { id, enabled, rolloutPct } = await req.json();

  await db.update(featureFlags)
    .set({ enabled, rolloutPct, updatedAt: new Date() })
    .where(eq(featureFlags.id, id));

  // Bust the cache
  revalidateTag('flags');

  return Response.json({ success: true });
}
```

## The flag lifecycle

1. **Create** — add flag to DB as `enabled: false`
2. **Develop** — code ships to production behind the flag
3. **Test** — enable for internal users (`allowedUserIds`)
4. **Roll out** — increase `rolloutPct` in stages: 5% → 25% → 50% → 100%
5. **Remove** — once fully rolled out and stable, delete the conditional from code and the flag from DB

The last step is where most teams fail. Permanent flags accumulate — they add cognitive load and can interact in unexpected ways. A flag that's been at 100% for 30 days should be removed from the codebase.
