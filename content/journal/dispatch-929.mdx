excerpt: "mise (formerly rtx) is a version manager for development tools — it replaces nvm for Node.js, pyenv for Python, rbenv for Ruby, sdkman for Java, and rustup for Rust with a single tool and a single configuration file (.mise.toml). It's written in Rust, activates versions per-directory, and supports 900+ tools from the asdf registry. Unlike nvm (which requires a shell function and adds 70ms to every new shell), mise activates via a shim layer that adds under 1ms overhead. The .mise.toml file replaces .nvmrc, .python-version, .tool-versions, and .node-version with one file checked into the repository."

One `.mise.toml` replaces `.nvmrc`, `.python-version`, `.tool-versions`. One tool replaces four.

## Installation and setup

```bash
# Install mise (no root required)
curl https://mise.run | sh
# Installs to ~/.local/bin/mise

# Add to shell (bash)
echo 'eval "$(mise activate bash)"' >> ~/.bashrc
source ~/.bashrc

# Add to shell (zsh)
echo 'eval "$(mise activate zsh)"' >> ~/.zshrc
source ~/.zshrc

# Verify
mise --version
# mise 2024.7.6

# mise uses shims in ~/.local/share/mise/shims/ — activated automatically per directory
# No shell overhead — unlike nvm which adds ~70ms to every new shell session

# Install a tool globally
mise use --global node@22.4.0
mise use --global python@3.12.4
mise use --global go@1.22.5
mise use --global bun@1.1.18

# Check what's installed globally
mise list --global
# node     22.4.0  ~/.local/share/mise/installs/node/22.4.0
# python   3.12.4  ~/.local/share/mise/installs/python/3.12.4
# go       1.22.5  ~/.local/share/mise/installs/go/1.22.5
```

## .mise.toml — project-level tool versions

```toml
# .mise.toml — checked into the repository alongside package.json, go.mod, etc.
# This file pins the exact tool versions for every developer and CI

[tools]
node    = "22.4.0"
python  = "3.12.4"
go      = "1.22.5"
bun     = "1.1.18"
rust    = "stable"
deno    = "1.44.4"
java    = "temurin-21.0.3+9"   # Eclipse Temurin (OpenJDK)

# Range versions (mise picks the latest matching version)
# node    = "22"      ← picks latest 22.x
# python  = "3.12"    ← picks latest 3.12.x

[env]
# Environment variables set when entering this directory
NODE_ENV = "development"
DATABASE_URL = "postgres://localhost/construx_dev"
RUST_LOG = "debug"

[tasks.dev]
run = "bun run dev"
description = "Start the development server"

[tasks.test]
run = "go test ./..."
description = "Run Go tests"

[tasks.lint]
run = ["bun run lint", "golangci-lint run"]
description = "Run all linters"
```

## Tool management

```bash
# Install all tools specified in .mise.toml (run in the project directory)
mise install
# mise  node@22.4.0      already installed
# mise  python@3.12.4    installing...  ✓  (12.4s)
# mise  go@1.22.5        already installed
# mise  bun@1.1.18       already installed

# See what version is active in the current directory
mise current
# node    22.4.0   .mise.toml
# python  3.12.4   .mise.toml
# go      1.22.5   .mise.toml

# Check where a tool binary lives
mise which node
# ~/.local/share/mise/installs/node/22.4.0/bin/node

# List all installed versions of a tool
mise list node
# node  18.20.4  (not active)
# node  20.15.1  (not active)
# node  22.4.0   active (from .mise.toml)

# Use a different version temporarily (current shell only)
mise shell node@20.15.1
node --version   # v20.15.1

# Upgrade to the latest patch version of a tool
mise upgrade node   # Upgrades 22.4.0 → 22.x.y (latest)

# Prune old versions (free disk space)
mise prune node    # Removes all node versions except the active one
mise prune         # Prunes all tools

# Run a command with a specific tool version (one-shot, no config change)
mise exec node@20.15.1 -- node -e "console.log(process.version)"
# v20.15.1
```

## CI/CD integration

```yaml
# GitHub Actions: use mise to install tools
# .github/workflows/ci.yml

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install mise
        uses: jdx/mise-action@v2
        # Reads .mise.toml and installs all tools automatically

      - name: Verify tools
        run: |
          node --version    # v22.4.0
          python --version  # Python 3.12.4
          go version        # go1.22.5

      - name: Run tests
        run: mise run test   # Uses the [tasks.test] from .mise.toml

      - name: Lint
        run: mise run lint
```

```bash
# Docker: include mise in the build image for reproducible builds
FROM ubuntu:24.04

# Install mise
RUN curl https://mise.run | sh && echo 'eval "$(mise activate bash)"' >> ~/.bashrc

# Copy tool config
COPY .mise.toml /app/.mise.toml
WORKDIR /app

# Install tools from .mise.toml
RUN mise install

# Now node, python, go, bun etc. are all available at the pinned versions
COPY . .
RUN mise run build
```

mise vs nvm vs asdf: nvm is Node.js-only and implemented as a shell function (slow activation, ~70ms per shell), with .nvmrc for per-directory versions. asdf is the general-purpose predecessor to mise — it supports 600+ plugins via shell scripts, but is slower and more complex. mise is a Rust reimplementation of asdf's model: same plugin ecosystem, same .tool-versions compatibility, but 100x faster activation (shim-based rather than shell-function-based), a cleaner .mise.toml config format, and built-in task running. The practical benefit for teams: one file (.mise.toml), one command (`mise install`), and every developer on the team has the exact same Node, Python, and Go versions. No more "works on my machine" version mismatches, no more remembering to run `nvm use` when entering a project directory.
