Feature flags let you deploy code before it's visible. You ship the implementation to production, keep it behind a flag, and flip the flag when you're ready. This decouples deploy from release — a distinction that gets more important as the team grows.

The vendor tools (LaunchDarkly, Flagsmith, GrowthBook) are good but they're another dependency, another API call in the hot path, another thing to configure per environment. For early-stage products, a database-backed flag system is often the right call.

## The schema

```sql
CREATE TABLE feature_flags (
  key        TEXT PRIMARY KEY,
  enabled    BOOLEAN NOT NULL DEFAULT FALSE,
  -- Optional: enable for a percentage of users (0-100)
  rollout_pct INT NOT NULL DEFAULT 100,
  -- Optional: enable only for specific user IDs
  user_ids   TEXT[] DEFAULT '{}',
  description TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Insert initial flags
INSERT INTO feature_flags (key, enabled, description) VALUES
  ('batch-scan-v2', false, 'New batch scan UI with better output display'),
  ('portfolio-alerts', false, 'Email alerts when portfolio item margin crosses threshold'),
  ('ai-scan-enrichment', false, 'Claude-powered scan title and category enrichment');
```

## The flag resolver

```ts
// lib/flags.ts
import { db } from '@/lib/db';
import { eq } from 'drizzle-orm';
import { featureFlags } from '@/lib/schema';

interface FlagContext {
  userId?: string;
}

// In-memory cache with TTL — avoids a DB hit on every request
const cache = new Map<string, { value: boolean; expiresAt: number }>();
const CACHE_TTL_MS = 30_000;  // 30 seconds

export async function isEnabled(key: string, ctx?: FlagContext): Promise<boolean> {
  const now = Date.now();

  const cached = cache.get(key);
  if (cached && cached.expiresAt > now) {
    return cached.value;
  }

  const flag = await db
    .select()
    .from(featureFlags)
    .where(eq(featureFlags.key, key))
    .limit(1);

  if (!flag[0] || !flag[0].enabled) {
    cache.set(key, { value: false, expiresAt: now + CACHE_TTL_MS });
    return false;
  }

  const f = flag[0];

  // User-specific override: if userId is in user_ids, always enabled
  if (ctx?.userId && f.userIds?.includes(ctx.userId)) {
    cache.set(key, { value: true, expiresAt: now + CACHE_TTL_MS });
    return true;
  }

  // Percentage rollout: stable hash so the same user always sees the same state
  if (f.rolloutPct < 100 && ctx?.userId) {
    const hash = hashUserId(ctx.userId);
    const bucket = hash % 100;
    const result = bucket < f.rolloutPct;
    cache.set(key, { value: result, expiresAt: now + CACHE_TTL_MS });
    return result;
  }

  // Fully enabled
  cache.set(key, { value: true, expiresAt: now + CACHE_TTL_MS });
  return true;
}

function hashUserId(userId: string): number {
  let hash = 0;
  for (let i = 0; i < userId.length; i++) {
    hash = ((hash << 5) - hash) + userId.charCodeAt(i);
    hash |= 0;  // Convert to 32-bit int
  }
  return Math.abs(hash);
}
```

The 30-second cache means a flag flip propagates within half a minute. This is almost always fine. If you need instant propagation, you can invalidate the cache via a webhook from your admin UI, or just accept the short lag.

## Usage in route handlers

```ts
// app/api/scan/route.ts
import { isEnabled } from '@/lib/flags';

export async function POST(req: Request) {
  const session = await getSession();
  if (!session) return new Response('Unauthorized', { status: 401 });

  const useEnrichment = await isEnabled('ai-scan-enrichment', {
    userId: session.userId,
  });

  const scanResult = await runScan(asin);

  if (useEnrichment) {
    scanResult.enrichment = await runAiEnrichment(scanResult);
  }

  return Response.json(scanResult);
}
```

## Usage in server components

```tsx
// app/dashboard/page.tsx
import { isEnabled } from '@/lib/flags';

export default async function DashboardPage() {
  const session = await getSession();

  const showPortfolioAlerts = await isEnabled('portfolio-alerts', {
    userId: session?.userId,
  });

  return (
    <div>
      {showPortfolioAlerts && <PortfolioAlertsPanel />}
      <ScanFeed />
    </div>
  );
}
```

## The admin interface

The simplest admin interface is a Next.js route that reads and writes the flags table. You can protect it with an admin role check on the session:

```ts
// app/api/admin/flags/route.ts
export async function PATCH(req: Request) {
  const session = await getSession();
  if (!session?.isAdmin) return new Response('Forbidden', { status: 403 });

  const { key, enabled, rolloutPct } = await req.json();

  await db.update(featureFlags)
    .set({ enabled, rolloutPct, updatedAt: new Date() })
    .where(eq(featureFlags.key, key));

  // Invalidate cache for this key
  cache.delete(key);

  return Response.json({ success: true });
}
```

## What this doesn't give you

This system doesn't give you: real-time propagation without cache invalidation, audit logs of who flipped what when, A/B testing with proper statistical analysis, or targeting by complex user attributes beyond user ID. If you need any of these, move to a proper flag service.

For most products at early scale, you don't. Shipping a feature to 10% of users by user ID bucket and checking the analytics is enough to validate before full rollout.
