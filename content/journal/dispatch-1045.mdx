date: "2033-07-15"
excerpt: "Qdrant is a vector similarity search engine designed for production-scale nearest-neighbour retrieval. You store vectors (embeddings from a language model, image encoder, or other ML model) alongside a payload (arbitrary JSON metadata), then query for the top-K most similar vectors to a query vector — optionally filtered by payload fields. Qdrant's core index is HNSW (Hierarchical Navigable Small World), a graph-based ANN algorithm that achieves sub-millisecond p99 latency at millions of vectors by navigating layers of the graph rather than scanning all vectors. The filter is evaluated during graph traversal, not post-hoc — so `top-10 most similar products where category = 'electronics' and price_pence < 50000` runs in one pass without a full scan. Qdrant supports sparse vectors (for BM25/TF-IDF hybrid search), named vectors (multiple embedding models per point), and binary quantization (1-bit compression that reduces memory 32x with ~5% recall loss)."

```python
def embed_products(products: list[dict]) -> None:
    texts = [f"{p['name']} {p['description']}" for p in products]
    dense_vectors = model.encode(texts, batch_size=256, normalize_embeddings=True)

    points = [
        PointStruct(
            id=p["id"],
            vector={
                "dense": dense_vectors[i].tolist(),
                # sparse BM25 vectors computed separately via tokeniser
                "bm25": SparseVector(

                    values=p["bm25_values"],

            },

                "category":    p["category"],

                "in_stock":    p["in_stock"],

    client.upsert(collection_name="construx_products", points=points, wait=True)
```

## Hybrid search and filtered ANN

```python
# Hybrid search: dense semantic + sparse BM25, re-ranked with RRF

from qdrant_client.models import Prefetch, Query, FusionQuery, Fusion

def search_products(
    query_text: str,
    tenant_id:  str,
    category:   str | None = None,
    max_price:  int | None = None,
    top_k:      int = 20,
) -> list[dict]:
    query_dense  = model.encode(query_text, normalize_embeddings=True).tolist()
    query_sparse = compute_bm25_vector(query_text)   # sparse tokeniser

    # Pre-filters applied during HNSW traversal — not post-hoc
    filters = [FieldCondition(key="tenant_id", match=MatchValue(value=tenant_id))]
    if category:
        filters.append(FieldCondition(key="category", match=MatchValue(value=category)))
    if max_price:
        filters.append(FieldCondition(key="price_pence", range=Range(lte=max_price)))

    payload_filter = Filter(must=filters)

    # Hybrid search: prefetch dense + sparse candidates, fuse with RRF
    results = client.query_points(
        collection_name="construx_products",
        prefetch=[
            Prefetch(
                query=query_dense,
                using="dense",
                filter=payload_filter,
                limit=top_k * 3,
            ),
            Prefetch(
                query=SparseVector(
                    indices=query_sparse.indices,
                    values=query_sparse.values,
                ),
                using="bm25",
                filter=payload_filter,
                limit=top_k * 3,
            ),
        ],
        query=FusionQuery(fusion=Fusion.RRF),   # Reciprocal Rank Fusion re-ranking
        limit=top_k,
        with_payload=True,
    )

    return [
        {
            "id":    hit.id,
            "score": hit.score,
            **hit.payload,
        }
        for hit in results.points
    ]

# Simple dense ANN with filter
results = client.search(

        FieldCondition(key="price_pence", range=Range(lte=5000)),  # ≤ £50

    limit=10,
    with_payload=True,
    score_threshold=0.7,   # minimum cosine similarity — drop irrelevant results
)
```

Qdrant vs pgvector vs Pinecone vs Weaviate vs Chroma: pgvector runs inside PostgreSQL and is operationally simple — if you already have PostgreSQL, you can add vector search without new infrastructure. But pgvector's IVFFlat/HNSW index is slower than Qdrant's at millions of vectors, and filtering requires a post-scan with no index integration. Pinecone is managed, fast, and has good recall, but it's closed-source and expensive at scale. Weaviate adds a graph schema layer that makes simple use cases more complex. Chroma is optimised for development and prototyping — not production at scale. Qdrant's differentiation: the filter is integrated into HNSW traversal (no full scan), sparse vector support enables hybrid BM25 + semantic search in one query, binary quantization makes millions of vectors fit in a reasonable amount of RAM, and the Rust implementation is consistently fast. For RAG pipelines, semantic product search, and recommendation systems at millions of vectors with payload filtering, Qdrant is the production-grade open-source choice.
