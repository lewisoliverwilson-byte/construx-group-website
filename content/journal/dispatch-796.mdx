Write ordinary code. Temporal makes it reliable.

## Core concepts

A **workflow** is a durable function. It can run for minutes, days, or months. It persists state automatically — if the server crashes, it resumes.

An **activity** is a function that does side effects (HTTP calls, database writes, sending email). Activities are retried automatically on failure.

## Workflow definition

```ts
// workflows/userOnboarding.ts
import { proxyActivities, sleep } from '@temporalio/workflow';
import type * as activities        from './activities';

const { sendWelcomeEmail, createDefaultProject, scheduleCheckIn, chargeCard } =
  proxyActivities<typeof activities>({
    startToCloseTimeout: '30 seconds',
    retry: {
      maximumAttempts:    3,
      initialInterval:    '1s',
      backoffCoefficient: 2,
    },
  });

export async function userOnboardingWorkflow(userId: string): Promise<void> {
  // Step 1 — send welcome email (retried automatically if Resend is down)
  await sendWelcomeEmail(userId);

  // Step 2 — create default project
  await createDefaultProject(userId);

  // Step 3 — wait 3 days, then check if they've logged in
  await sleep('3 days');
  await scheduleCheckIn(userId);

  // Step 4 — wait for free trial to end (14 days), charge card
  await sleep('11 days');  // 3 + 11 = 14 days total
  await chargeCard(userId);
}
```

The `sleep('3 days')` is durable — the workflow pauses and resumes 3 days later. No cron job, no queued message, no database timer.

## Activities — side effects

```ts
// workflows/activities.ts
import { resend }    from '../lib/resend';
import { db }        from '../lib/db';
import { stripe }    from '../lib/stripe';

export async function sendWelcomeEmail(userId: string): Promise<void> {
  const user = await db.users.findUnique({ where: { id: userId } });
  if (!user) throw new Error(`User not found: ${userId}`);

  await resend.emails.send({
    to:      user.email,
    subject: 'Welcome to Construx',
    html:    welcomeTemplate(user),
  });
}

export async function chargeCard(userId: string): Promise<void> {
  const subscription = await db.subscriptions.findUnique({ where: { userId } });
  if (!subscription || subscription.status !== 'trial') return;

  await stripe.subscriptions.update(subscription.stripeId, {
    trial_end: 'now',  // End trial, charge immediately
  });
}
```

## Start a workflow

```ts
import { Client, Connection } from '@temporalio/client';

const connection = await Connection.connect({ address: 'localhost:7233' });
const client     = new Client({ connection });

// Start the onboarding workflow — immediately returns a handle
const handle = await client.workflow.start('userOnboardingWorkflow', {
  taskQueue:  'construx-main',
  workflowId: `onboarding-${userId}`,
  args:       [userId],
});

console.log(`Started workflow: ${handle.workflowId}`);
```

## Signals — send events to a running workflow

```ts
// Workflow definition — listens for signal
import { defineSignal, setHandler } from '@temporalio/workflow';

const upgradeSignal = defineSignal<[{ plan: string }]>('upgrade');

export async function userOnboardingWorkflow(userId: string) {
  let plan = 'free';

  setHandler(upgradeSignal, ({ plan: newPlan }) => {
    plan = newPlan;
    console.log(`User upgraded to ${plan}`);
  });

  await sleep('14 days');
  // plan might have been updated by a signal during the sleep
  await chargeCard(userId, plan);
}

// Send signal from anywhere
const handle = client.workflow.getHandle(`onboarding-${userId}`);
await handle.signal(upgradeSignal, { plan: 'pro' });
```

## Worker — runs activities and workflows

```ts
// worker.ts
import { Worker } from '@temporalio/worker';
import * as activities from './workflows/activities';

const worker = await Worker.create({
  workflowsPath: require.resolve('./workflows/userOnboarding'),
  activities,
  taskQueue:     'construx-main',
});

await worker.run();
```

Temporal vs BullMQ: BullMQ is a job queue — it runs a job once and moves on. If the job crashes, you handle retries and state manually. Temporal is a workflow engine — it persists every step, resumes from failures, and supports long-running processes with signals and timers. Use BullMQ for simple background jobs; Temporal for multi-step workflows that must complete reliably. The Construx default: BullMQ for simple background tasks; Temporal for user lifecycle flows, payment workflows, and any process that spans more than one step.
