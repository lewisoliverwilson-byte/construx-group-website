excerpt: "k9s is an interactive terminal UI for Kubernetes — think htop for your cluster. It gives you a real-time view of pods, deployments, services, configmaps, and every other Kubernetes resource, with live log streaming, exec into containers, port-forwarding, and resource editing all from the keyboard. The killer feature is the context-aware navigation: from a deployment, press `l` to see its pods' logs, press `s` to shell into a container, press `d` to describe the resource. k9s also shows resource utilization (CPU/memory) inline if the metrics-server is installed. Most cluster debugging workflows that take 5+ kubectl commands become single-key operations in k9s."

Live pod view. Log streaming. Exec into containers. Port-forward. All from the keyboard.

## Navigation and resource views

```bash
# Install k9s
brew install k9s
# or
curl -sS https://webinstall.dev/k9s | bash

k9s
# Opens interactive TUI against current kubeconfig context

# Key bindings (vim-style):
# :pods          — switch to pods view
# :deployments   — switch to deployments view
# :svc           — services
# :cm            — configmaps
# :secrets       — secrets
# :nodes         — nodes
# :events        — events (sorted by time)
# :hpa           — horizontal pod autoscalers
# :pvc           — persistent volume claims
# :jobs          — jobs and cronjobs

# Context switching (without leaving k9s)
# ctrl-a         — switch Kubernetes context
# :ctx           — list all available contexts

# Namespace filtering
# Press 'n' or use the namespace selector at the top
# :pods -n construx-prod     — pods in a specific namespace
# :pods --all-namespaces     — pods across all namespaces (A key)

# Within any resource list:
# /              — fuzzy filter (type to narrow the list)
# d              — describe the selected resource
# e              — edit the resource in $EDITOR (applies on save)
# y              — YAML view
# ctrl-d         — delete the selected resource (with confirmation)
# u              — undo last delete (if within grace period)
```

## Log streaming and exec

```bash
# From the pods view, select a pod and:
# l              — stream logs (live tail)
# L              — logs for previous container instance (crashed pods)
# ctrl-l         — clear log buffer

# Log filtering within k9s log view:
# /error         — filter to lines containing "error"
# /panic         — filter to lines containing "panic"
# /2032-11-20    — filter to today's logs
# ctrl-c         — exit log view

# From the command line (non-interactive):
k9s --read-only        # prevent destructive actions
k9s --context prod-eu  # open in a specific context
k9s -n construx-prod   # start in a specific namespace

# Shell into a running container
# In pods view: select pod → press 's'
# If the pod has multiple containers, k9s asks which one

# Port-forward to a pod or service
# Select pod/service → press shift-f
# k9s opens a port-forward and keeps it active until you close it

# From the CLI (non-interactive port-forward):
k9s -c port-forward --address 0.0.0.0 --local-port 8080 --remote-port 8080 pod/api-7f9b-xk2m9
```

## Resource utilization and metrics

```bash
# k9s shows CPU/memory if metrics-server is installed
# kubectl top nodes / kubectl top pods equivalent — live in the TUI

# In pods view, columns:
# CPU(cores)    — current CPU usage (millicores)
# MEM(bytes)    — current memory usage
# CPU%          — CPU request utilization
# MEM%          — memory request utilization

# Sort by memory:
# Press 'shift-m' in the pods view → sorted by memory usage
# Press 'shift-c' → sorted by CPU usage
# Press 'shift-n' → sorted by name (default)

# Identify memory hogs:
# :pods → shift-m → top consumers visible immediately

# k9s benchmarking (built-in HTTP benchmarker for services)
# In services view, select a service → press ctrl-b
# k9s runs vegeta-style load test against the service
# Useful for quick before/after comparison during incidents

# Plugin system: extend k9s with custom actions
# ~/.config/k9s/plugins.yaml
plugins:
  log-to-file:
    shortCut: ctrl-l
    description: "Stream logs to file"
    scopes:
      - pods
    command: kubectl
    background: true
    args:
      - logs
      - -f
      - $NAME
      - -n
      - $NAMESPACE
      - --context
      - $CONTEXT
      - ">"
      - /tmp/k9s-$NAME.log
```

## Skins and config

```yaml
# ~/.config/k9s/config.yaml
k9s:
  refreshRate:      2          # seconds between resource list refreshes
  maxConnRetry:     5
  enableMouse:      false      # terminal mouse support
  headless:         false      # hide the header bar
  logoless:         true       # hide the k9s logo
  crumbsless:       false      # breadcrumb navigation bar
  readOnly:         false      # set true for prod clusters you shouldn't touch
  noExitOnCtrlC:   false
  ui:
    enableMouse:    false
    skin:           gruvbox    # color skin (see https://k9scli.io/topics/skins)
    defaultView:    pods       # open to pods view by default

# ~/.config/k9s/aliases.yaml
# Short aliases for resource types
aliases:
  pp:  v1/pods
  dp:  apps/v1/deployments
  svc: v1/services
  cm:  v1/configmaps
  sec: v1/secrets
  ns:  v1/namespaces
  no:  v1/nodes
  ev:  v1/events
  hpa: autoscaling/v2/horizontalpodautoscalers
  pvc: v1/persistentvolumeclaims

# Hotkeys: bind custom kubectl commands to key sequences
# ~/.config/k9s/hotkeys.yaml
hotkeys:
  shift-0:
    shortCut:    Shift-0
    description: "Describe selected pod"
    command:     describe
  shift-1:
    shortCut:    Shift-1
    description: "Switch to production context"
    command:     ctx
    args:
      - construx-prod-eu
```

## Common debugging workflows

```bash
# Workflow: find a crashing pod, read its logs, check previous instance
# 1. Open k9s → :pods → type pod name or component to filter
# 2. See RESTARTS column — high count indicates a crash loop
# 3. Press 'l' for current logs
# 4. Press 'L' for previous container logs (the one that crashed)
# 5. Press 'd' to describe the pod — see events and OOMKilled reason

# Workflow: find what's using the most memory in a namespace
# :pods -n construx-prod → shift-m → top memory consumers visible

# Workflow: exec into a specific container to debug
# :pods → filter to the pod → press 's'
# k9s opens: /bin/sh (or /bin/bash if available)
# Run: env | grep DATABASE, curl http://localhost:8080/health, etc.

# Workflow: edit a ConfigMap and see the change take effect
# :cm → select the ConfigMap → press 'e'
# Opens in $EDITOR (vim/nano/etc.)
# Save and quit — k9s applies the change immediately

# Watch events for a specific pod during a deployment
# :events → filter by pod name → live event stream
# Shows: Scheduled, Pulling image, Started, Readiness probe failed, etc.

# Delete a stuck namespace (finalizers blocking deletion)
# :ns → select namespace → press ctrl-d
# If stuck: press 'e' → remove finalizers from metadata.finalizers → save
```

k9s vs kubectl vs Lens: kubectl is the reference CLI — scriptable, complete, composable in shell scripts. k9s is the interactive debugging and monitoring tool — you reach for it during incidents, when you need to quickly find a failing pod across 50 pods, or stream logs from multiple services. Lens is a full desktop GUI — better for teams less comfortable in the terminal and for cluster overview dashboards. In practice: k9s for day-to-day operations, kubectl for automation and shell scripts, Lens for onboarding and executive dashboards.
