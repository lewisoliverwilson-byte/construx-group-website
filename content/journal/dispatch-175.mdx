First impressions in software are measured in minutes, not months. A user who doesn't understand the product's value within the first session is unlikely to return. Onboarding is the product feature that determines whether every other feature gets used.

Here's what we've learned.

## Scoutr: from setup friction to instant value

Scoutr v1 onboarding required:
1. Create account
2. Connect eBay seller account (OAuth flow)
3. Configure packing cost, preferred margin
4. Complete tutorial scan

Day-7 retention after this flow: 31%.

The problem: the eBay OAuth connection was optional (Scoutr works without it — it just can't pull your actual fee profile). Users who bounced on the OAuth step never saw the product work. Users who completed it often completed a tutorial scan with a product they didn't care about.

Scoutr v2 onboarding:
1. Create account (or skip, try it first)
2. Paste any eBay listing URL → see an instant result

That's it. No configuration, no connection. The default fee profile works for most sellers. Users see value in 60 seconds.

Day-7 retention after this flow: 61%.

The change: reduce the time to first value to its minimum. Configuration can happen later, once the user understands what they're configuring for.

## The Marqet: solving for the wrong user first

The Marqet launched with seller-first onboarding. The reasoning: we needed supply before we had demand, so onboarding focused on helping sellers create listings.

Buyer onboarding was an afterthought: create account, browse listings, send an enquiry. Simple, but invisible — buyers who arrived without a specific search intent churned because they didn't know where to start.

The metrics told us: buyer day-14 retention was 28%. Seller day-14 retention was 58%. The mismatch indicated that buyers weren't finding value as quickly as sellers.

We rebuilt buyer onboarding around intent:
1. Create account
2. "What are you looking for?" (category selection with search)
3. Show curated results in the selected category
4. Highlight: enquiry is free, payment is held securely until you confirm the work is done

The change: give buyers a starting point. A buyer who knows what they want and sees relevant results stays; a buyer facing an unfiltered listing page leaves.

Buyer day-14 retention after: 47%. Not at seller levels, but significantly improved.

## The Hyve: the empty state problem

Every collaboration tool faces the empty state problem: a workspace with no messages is less useful than a workspace with 100 messages. New users join The Hyve's empty workspace and have nothing to react to, respond to, or learn from.

We added workspace onboarding scaffolding: when a workspace is created, three channels are seeded (#general, #links, #ideas) with welcome messages from a system "Construx" account that explain what The Hyve does. The AI agent is introduced in #general with a demonstration response.

This is a common technique (Slack does it, Discord does it) but it works: the empty workspace feels populated rather than abandoned. New members have something to respond to.

Additionally, we added a workspace setup wizard for the first admin user: set the workspace name, invite the first member, create the first real channel. Completing the wizard produces a workspace that feels started rather than empty.

Day-30 retention for workspaces that complete the wizard: 71%. Day-30 retention for workspaces that skip it: 34%.

## The onboarding patterns that work

**Get to value before asking for configuration.** Every step before the first value moment is a potential dropout. Minimise setup, defer configuration until after the user understands what they're configuring.

**Show, don't explain.** Showing a working example of the product beats explaining what it does. Scoutr showing a scan result beats Scoutr explaining how scan results work.

**Make the empty state feel provisional, not permanent.** An empty interface signals that nothing has happened. Scaffold enough content that new users can see what the populated state looks like.

**One clear next step.** Users who don't know what to do next do nothing. Every screen in the onboarding flow should have exactly one clear primary action.

**Don't make users think about things they don't care about yet.** Asking Scoutr users to configure their packing cost before they've seen their first result is asking them to make a decision about something they don't yet understand. Configuration happens after value.

## Measuring onboarding

The metrics we track:

**Time to first value:** How long from signup to the first meaningful product action? For Scoutr, this is first scan completion. For The Marqet, this is first enquiry sent (buyers) or first listing published (sellers). For The Hyve, this is first message in a channel.

**Onboarding completion rate:** What percentage of users who start onboarding complete it? Drop-off points identify friction.

**Day-7, Day-14, Day-30 retention by onboarding cohort:** Users who complete onboarding retain at higher rates than those who don't. The size of this gap tells us how much retention is attributable to onboarding quality vs. product-market fit.

The retention improvements from onboarding changes are the highest-ROI product work we've done. Onboarding is the one part of the product that every user experiences. Getting it right compounds across the entire user base.
