Webpack bundles everything upfront before the dev server starts. On a large project that means a 30-second wait before you see anything. Vite skips the bundle entirely during development — it serves source files as ES modules, transforming only what the browser requests. A 1000-module project starts in milliseconds.

## Setup

```bash
# Scaffold a new project
npm create vite@latest my-app -- --template react-ts

# Or add to an existing project
npm install -D vite @vitejs/plugin-react
```

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react          from '@vitejs/plugin-react';
import { resolve }    from 'path';

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: { '@': resolve(__dirname, './src') },
  },
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target:    'http://localhost:4000',
        changeOrigin: true,
      },
    },
  },
  build: {
    outDir:        'dist',
    sourcemap:     true,
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom'],
        },
      },
    },
  },
});
```

## Environment variables

```ts
// .env
VITE_API_URL=https://api.construxgroup.io
VITE_APP_VERSION=1.0.0

// In source code — only VITE_ prefixed vars are exposed to the client
const apiUrl = import.meta.env.VITE_API_URL;
const isDev   = import.meta.env.DEV;
const isProd  = import.meta.env.PROD;
const mode    = import.meta.env.MODE;  // 'development' | 'production'
```

Type-safe env:

```ts
// src/env.d.ts
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_API_URL:     string;
  readonly VITE_APP_VERSION: string;
}

interface ImportMeta {
  readonly env: ImportMetaEnv;
}
```

## CSS and static assets

```ts
// Import CSS directly — Vite handles it
import './styles/globals.css';

// CSS modules
import styles from './Button.module.css';
// styles.button → 'Button_button_3bfA2'

// Inline SVG as React component
import Logo from './logo.svg?react';

// URL of an asset
import heroUrl from './hero.png';
// heroUrl → '/assets/hero-3bfA2.png' in production

// Raw text
import shader from './shader.glsl?raw';
```

## HMR (Hot Module Replacement)

```ts
// Vite's HMR API — runs when a module is replaced
if (import.meta.hot) {
  import.meta.hot.accept((newModule) => {
    // Called when this module or its deps update
    console.log('Module updated:', newModule);
  });

  import.meta.hot.dispose(() => {
    // Clean up side effects before replacement
    clearInterval(intervalId);
  });
}
```

React's HMR is handled automatically by `@vitejs/plugin-react` — state is preserved across edits.

## Library mode

```ts
// Build a component library, not an app
export default defineConfig({
  build: {
    lib: {
      entry:    resolve(__dirname, 'src/index.ts'),
      name:     'ConstruxUI',
      formats:  ['es', 'cjs'],
      fileName: (format) => `construx-ui.${format}.js`,
    },
    rollupOptions: {
      external:  ['react', 'react-dom'],
      output:    { globals: { react: 'React', 'react-dom': 'ReactDOM' } },
    },
  },
});
```

Outputs `construx-ui.es.js` and `construx-ui.cjs.js` with React as a peer dependency — not bundled.

## Vite vs webpack vs esbuild

Vite: fast dev server via native ESM, Rollup for production. Best for greenfield apps and component libraries. Webpack: mature, enormous plugin ecosystem, handles legacy bundling needs. Still dominant in large enterprise projects. esbuild: 10-100x faster than webpack, but not a full dev server — used as the transformer inside Vite. Use Vite as the dev/build layer; esbuild handles the fast transforms underneath it.
