Transactional email is different from marketing email. You're sending in response to an action — a signup, a password reset, an invoice. It needs to arrive in seconds, not minutes, and never land in spam.

## Resend setup

```bash
npm install resend @react-email/components
```

```ts
// lib/email.ts
import { Resend } from 'resend';

const resend = new Resend(process.env.RESEND_API_KEY!);

export async function sendEmail({
  to,
  subject,
  react,
}: {
  to: string;
  subject: string;
  react: React.ReactElement;
}) {
  const { data, error } = await resend.emails.send({
    from: 'Construx Group <no-reply@construxgroup.io>',
    to,
    subject,
    react,
  });

  if (error) {
    console.error('Email send failed:', error);
    throw new Error(`Email failed: ${error.message}`);
  }

  return data;
}
```

## Email sending patterns

```ts
// lib/emails/index.ts — centralised sending interface
export const emails = {
  async welcome(user: { email: string; name: string }) {
    return sendEmail({
      to: user.email,
      subject: 'Welcome to Construx Group',
      react: <WelcomeEmail name={user.name} loginUrl={`${BASE_URL}/dashboard`} />,
    });
  },

  async passwordReset(user: { email: string }, token: string) {
    return sendEmail({
      to: user.email,
      subject: 'Reset your password',
      react: <PasswordResetEmail resetUrl={`${BASE_URL}/reset?token=${token}`} />,
    });
  },

  async invoicePaid(user: { email: string }, invoice: { amount: number; date: string }) {
    return sendEmail({
      to: user.email,
      subject: `Payment received — ${formatCurrency(invoice.amount)}`,
      react: <InvoicePaidEmail invoice={invoice} />,
    });
  },
};

// Call sites are clean
await emails.welcome(newUser);
await emails.passwordReset(user, resetToken);
```

## Handling failures

Email delivery can fail transiently. Wrap sends that are triggered by user actions in try/catch — a failed welcome email shouldn't break signup:

```ts
// Non-blocking send — don't let email failure fail the operation
async function handleSignup(user: User) {
  // Critical path: create user, create session
  await db.insert(users).values(user);
  const session = await createSession(user.id);

  // Best-effort: send welcome email
  emails.welcome(user).catch((err) => {
    console.error('Welcome email failed:', err);
    // Alert but don't throw — user is already signed up
  });

  return session;
}
```

For important emails (payment failed, security alerts), use a queue with retries rather than fire-and-forget.

## Deliverability: the basics

**Domain authentication** — set up SPF, DKIM, and DMARC records on your sending domain. Resend walks you through this in the dashboard. Without them, you're spam.

**Separate transactional and marketing** — use a subdomain for marketing (`marketing@updates.construxgroup.io`) so marketing unsubscribes don't affect transactional delivery.

**List-Unsubscribe headers** — required for bulk sends. Resend handles this for broadcast emails. For transactional, it's less critical but still good practice.

**Don't send from gmail.com** — always send from your own domain. `from: noreply@gmail.com` is a spam signal.

**Warmup** — if you're sending at high volume on a new domain, warm up gradually. Sending 10,000 emails on day 1 from a new IP triggers spam filters.

The test: send to your own email, check the spam score with mail-tester.com, and verify authentication headers in the raw email source. If authentication is configured and the content is clean, you'll land in inbox.
