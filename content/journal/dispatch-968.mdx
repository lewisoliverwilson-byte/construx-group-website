Live pod view. Log tail. Exec shell. Port-forward. Navigate with vim keys.

## Core navigation

```bash
# Install k9s
brew install k9s                           # macOS
wget https://github.com/derailed/k9s/releases/latest/download/k9s_Linux_amd64.tar.gz

# Launch against current kubeconfig context
k9s
k9s --context prod-eu                      # specific context
k9s --context prod-eu -n construx-prod     # specific namespace
k9s --read-only                            # prevent any destructive actions

# Resource navigation (type the resource kind or use shortcuts)
:pods               # pod list
:deployments        # deployment list
:services           # service list
:configmaps         # configmap list
:secrets            # secret list (values masked)
:nodes              # node list with resource usage
:events             # cluster events, newest first
:hpa                # horizontal pod autoscalers
:pvc                # persistent volume claims
:ingresses          # ingress rules
:jobs               # batch jobs
:cronjobs           # scheduled jobs

# Within any list:
↑↓ or jk           # navigate the list
/                   # fuzzy filter (type to narrow)
Enter               # drill into the resource
Esc                 # go back
d                   # describe (kubectl describe)
e                   # edit in $EDITOR (applied on save)
y                   # show YAML
ctrl-d              # delete (with confirmation prompt)
```

## Logs, exec, and port-forward

```bash
# Pod → logs (the most common operation)
# In :pods view, select a pod:
l                   # stream logs (live tail, follows)
L                   # logs from the previous container instance (post-crash)
ctrl-l              # clear log buffer

# Within log view:
/error              # filter to lines matching "error"
/WARN               # filter to WARN level
/2032-11-26         # filter to today
f                   # toggle follow mode on/off
w                   # toggle word-wrap

# Exec into a running container
# In :pods view, select a pod:
s                   # open shell (selects container if multiple exist)
# Opens: /bin/sh → pod-name:container-name
# Same as: kubectl exec -it pod-name -c container-name -- /bin/sh

# Port-forward to a pod
# In :pods view, select a pod:
shift-f             # opens port-forward dialog
# Enter local port and remote port → k9s holds the forward until dismissed

# Port-forward to a service
# In :services view, select a service:
shift-f             # same dialog

# CLI non-interactive port-forward (for scripts)
k9s -c port-forward pod/api-7f9b-xk2m9 --local-port 8080 --remote-port 8080 &
```

## Resource utilization and sorting

```bash
# k9s shows CPU (millicores) and memory (MiB) inline in the pod list
# Requires metrics-server to be installed in the cluster

# In :pods view, columns shown when metrics-server is present:
# NAME              READY   STATUS    RESTARTS  AGE  CPU(m)  MEM(Mi)
# api-7f9b-xk2m9    2/2     Running   0         14h  42      128
# worker-5dc4-mq7v  1/1     Running   0          2h  12       64

# Sort by column (in pods view):
shift-c             # sort by CPU usage (highest first)
shift-m             # sort by memory usage (highest first)
shift-n             # sort by name (default)
shift-r             # sort by restart count (find crash-looping pods)
shift-a             # sort by age

# Find the most memory-hungry pod in the cluster:
# A (switch to all namespaces) → shift-m → scroll to top

# :nodes view: cluster-wide resource utilization
# NAME              STATUS  CPU%  MEM%  PODS  AGE
# node-prod-eu-01   Ready   42%   61%   28    30d
# node-prod-eu-02   Ready   38%   58%   24    30d

# Sort nodes by CPU or memory to find hot nodes
```

## Aliases and config

```yaml
# ~/.config/k9s/config.yaml
k9s:
  refreshRate:     2          # seconds between list refresh
  maxConnRetry:    5
  readOnly:        false      # override per-session with --read-only
  noExitOnCtrlC:  false
  headless:        false
  logoless:        true       # saves vertical space
  ui:
    skin:          gruvbox    # dracula | gruvbox | monokai | nord | rose-pine
    defaultView:   pods       # start in pods view

# ~/.config/k9s/aliases.yaml — short aliases for resource types
aliases:
  pp:   v1/pods
  dp:   apps/v1/deployments
  sts:  apps/v1/statefulsets
  rs:   apps/v1/replicasets
  svc:  v1/services
  cm:   v1/configmaps
  sec:  v1/secrets
  ns:   v1/namespaces
  no:   v1/nodes
  ev:   v1/events
  hpa:  autoscaling/v2/horizontalpodautoscalers
  pvc:  v1/persistentvolumeclaims
  cj:   batch/v1/cronjobs

# ~/.config/k9s/hotkeys.yaml — bind kubectl commands to key sequences
hotkeys:
  shift-1:
    shortCut:    Shift-1
    description: Switch to prod-eu context
    command:     ctx
    args:
      - prod-eu
  shift-2:
    shortCut:    Shift-2
    description: Switch to staging context
    command:     ctx
    args:
      - staging
```

## Debugging workflows

```bash
# Workflow: debug a crash-looping pod
# 1. :pods → sort by restart count (shift-r)
# 2. Select the pod with the highest RESTARTS
# 3. Press 'd' → see Events section at the bottom (OOMKilled, ImagePullBackOff, etc.)
# 4. Press 'L' → logs from the previous (crashed) container instance
# 5. Press 'e' → edit the deployment to fix the issue (resource limits, env vars, etc.)

# Workflow: trace a slow API request
# 1. :pods → select the api pod
# 2. Press 'l' → live log stream
# 3. Press '/slow' → filter to slow query warnings
# 4. Press 's' → exec into the pod
# 5. curl http://localhost:8080/debug/pprof/goroutine?debug=1 → goroutine dump

# Workflow: force a rolling restart
# :deployments → select deployment → press 'r' (or 'e' to edit and bump an annotation)
# k9s watches the rollout progress live

# Workflow: decode a Kubernetes secret
# :secrets → select secret → press 'x' (decode base64 values inline)

# Watch pod events during a deployment
# :events → filter by deployment name → events stream live
# Scheduled → Pulling → Pulled → Created → Started → ReadinessProbe

# Find which node a pod is running on
# :pods → select pod → press 'd' → look for Node: field
# Or :nodes → see PODS count per node
```

k9s vs Lens vs kubectl: kubectl is the reference tool for scripts and automation — composable, documented, and always available. k9s is the interactive debugging environment — it eliminates the repetition of `kubectl get pods`, `kubectl describe`, `kubectl logs -f`, `kubectl exec` as separate commands. Lens is a full desktop application — better for teams who prefer a GUI and for cluster topology visualization. The practical split: k9s is open 90% of the day during active development or incident response; kubectl is used for scripted operations and CI pipelines; Lens is useful for overview dashboards and for engineers less comfortable in the terminal.
