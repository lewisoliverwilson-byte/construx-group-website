Page transitions should not require an animation library. View Transitions makes them a CSS concern.

## How View Transitions work

```ts
// Trigger a view transition
document.startViewTransition(() => {
  // Update the DOM here
  // The transition animates between the old and new states
  updateDOM();
});
```

The API:
1. Takes a screenshot of the current state
2. Applies DOM update
3. Takes a screenshot of the new state
4. Animates between them using a crossfade by default

## Next.js App Router integration

```tsx
// app/layout.tsx
'use client';
import { useRouter }   from 'next/navigation';
import { useCallback } from 'react';

function NavigatingLink({ href, children }: { href: string; children: React.ReactNode }) {
  const router = useRouter();

  const handleClick = useCallback(
    (e: React.MouseEvent) => {
      e.preventDefault();

      if (!document.startViewTransition) {
        router.push(href);
        return;
      }

      document.startViewTransition(() => {
        router.push(href);
      });
    },
    [href, router],
  );

  return <a href={href} onClick={handleClick}>{children}</a>;
}
```

## Default crossfade

The default view transition is a crossfade. No CSS needed:

```css
/* app/globals.css */
@view-transition {
  navigation: auto;  /* Enable for all same-origin navigations */
}
```

## Custom animations

```css
/* Slide in from right */
::view-transition-old(root) {
  animation: 300ms ease-in both slide-out-left;
}
::view-transition-new(root) {
  animation: 300ms ease-out both slide-in-right;
}

@keyframes slide-out-left {
  to { transform: translateX(-100%); }
}
@keyframes slide-in-right {
  from { transform: translateX(100%); }
}
```

## Scoped transitions — animate specific elements

```css
/* Give elements a view-transition-name for individual animation */
.hero-image {
  view-transition-name: hero;
}

/* The hero image transitions separately from the rest of the page */
::view-transition-old(hero) {
  animation: 400ms ease-in-out scale-down;
}
::view-transition-new(hero) {
  animation: 400ms ease-in-out scale-up;
}
```

```tsx
// Mark the element in React
<img
  src="/hero.jpg"
  style={{ viewTransitionName: 'hero' }}
/>
```

When navigating between pages, the browser matches elements by their `view-transition-name` and smoothly morphs the old position and size into the new one. This is how native app transitions feel — the element appears to fly to its new location.

## Reduced motion

```css
@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(root),
  ::view-transition-new(root) {
    animation: none;
  }
}
```

Always respect `prefers-reduced-motion`. View Transitions should enhance, not distract.

## Browser support

Chrome 111+, Edge 111+, Safari 18.2+, Firefox 130+. All major browsers in 2031. Add a progressive enhancement check (`if (!document.startViewTransition) { ... }`) for users on older browsers.
