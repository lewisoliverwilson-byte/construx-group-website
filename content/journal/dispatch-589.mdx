JavaScript's `for...of` loop works with any iterable — arrays, maps, strings, generators. `for await...of` extends this to asynchronous iterables: objects where each value is a Promise, resolved in sequence.

## The iterator protocol

A synchronous iterator is an object with a `next()` method that returns `{ value, done }`:

```ts
const range = {
  [Symbol.iterator]() {
    let n = 0;
    return {
      next() {
        return n < 3
          ? { value: n++, done: false }
          : { value: undefined, done: true };
      },
    };
  },
};

for (const n of range) {
  console.log(n); // 0, 1, 2
}
```

An async iterator uses `Symbol.asyncIterator` and returns Promises:

```ts
const asyncRange = {
  [Symbol.asyncIterator]() {
    let n = 0;
    return {
      async next() {
        await delay(100); // simulate async work
        return n < 3
          ? { value: n++, done: false }
          : { value: undefined, done: true };
      },
    };
  },
};

for await (const n of asyncRange) {
  console.log(n); // 0, 1, 2 — each after 100ms
}
```

`for await...of` awaits each `next()` call before proceeding to the next iteration.

## Async generators: the clean way to write async iterators

Async generators (`async function*`) produce async iterables without implementing the protocol manually:

```ts
async function* paginate<T>(
  fetchPage: (page: number) => Promise<{ items: T[]; hasNext: boolean }>,
): AsyncIterableIterator<T> {
  let page = 0;
  while (true) {
    const { items, hasNext } = await fetchPage(page);
    for (const item of items) {
      yield item;
    }
    if (!hasNext) break;
    page++;
  }
}

// Usage
for await (const user of paginate((page) => fetchUsers({ page, perPage: 100 }))) {
  console.log(user.name);
}
```

The caller sees a flat stream of items — the pagination logic is hidden inside the generator.

## Node.js streams as async iterables

Node.js Readable streams implement `Symbol.asyncIterator`:

```ts
import { createReadStream } from 'fs';
import { createInterface } from 'readline';

async function processLargeFile(path: string) {
  const stream = createReadStream(path, { encoding: 'utf8' });
  const rl = createInterface({ input: stream });

  for await (const line of rl) {
    // process line-by-line — low memory regardless of file size
    processLine(line);
  }
}
```

Without async iterators, processing a large file required callback-based stream events. `for await...of` makes it sequential and readable.

## Fetch ReadableStream

The Fetch API's `ReadableStream` (browser and Node.js) also works with async iteration:

```ts
async function streamResponse(url: string) {
  const res = await fetch(url);
  const decoder = new TextDecoder();

  for await (const chunk of res.body!) {
    console.log(decoder.decode(chunk));
  }
}
```

This is the same mechanism used for streaming LLM output — the API returns a streaming response, and you consume it chunk by chunk.

## Claude's streaming SDK

The Anthropic SDK's `.stream()` method returns an async iterable:

```ts
const stream = client.messages.stream({
  model:      'claude-opus-4-8',
  max_tokens:  1024,
  messages:   [{ role: 'user', content: 'Count to 10' }],
});

for await (const event of stream) {
  if (event.type === 'content_block_delta' && event.delta.type === 'text_delta') {
    process.stdout.write(event.delta.text);
  }
}
```

The stream is an async iterable. Each event arrives as the model generates it. `for await...of` handles the Promise resolution, backpressure, and cleanup automatically.

## Consuming with Promise.all and early termination

`for await...of` is sequential — it waits for one item before requesting the next. For parallel processing, collect into an array first:

```ts
const items: T[] = [];
for await (const item of asyncSource) {
  items.push(item);
}
await Promise.all(items.map(processItem));
```

Early termination with `break` is safe — the iterator's `return()` method is called automatically, allowing cleanup (closing connections, unsubscribing):

```ts
for await (const event of eventStream) {
  if (event.type === 'done') break;  // stream.return() is called
  handleEvent(event);
}
```

## Error handling

Errors thrown inside or by the async iterator propagate through `for await...of` as normal exceptions:

```ts
try {
  for await (const chunk of stream) {
    processChunk(chunk);
  }
} catch (err) {
  console.error('Stream error:', err);
}
```

The iterator's `return()` method is also called when the loop is exited via an exception, ensuring cleanup runs even on errors.

Async iterators are the right abstraction whenever you're dealing with data that arrives over time: streaming network responses, file reading, event streams, real-time data from WebSockets. `for await...of` makes consuming them as clean as consuming an array.
