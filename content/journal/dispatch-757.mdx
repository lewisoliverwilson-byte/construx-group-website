Shell scripts that work everywhere and have types. This is what build tooling looks like now.

## Basic usage

```ts
import { $ } from 'bun';

// Run a command — throws on non-zero exit
await $`echo Hello, world!`;

// Capture stdout
const output = await $`ls -la`.text();
console.log(output);

// JSON output
const pkg = await $`cat package.json`.json();
console.log(pkg.name, pkg.version);

// Pipe between commands
await $`cat package.json | jq '.dependencies | keys[]'`;
```

## Variables and interpolation

```ts
const dir = './dist';
const file = 'index.js';

// Safe interpolation — no injection possible
await $`ls ${dir}/${file}`;

// Array expansion
const files = ['a.ts', 'b.ts', 'c.ts'];
await $`tsc ${files}`;
// → tsc a.ts b.ts c.ts

// Glob expansion
await $`rm -rf ${'dist/**/*.js'}`;
```

## Error handling

```ts
// Default: throws BunShellError on non-zero exit
try {
  await $`git push origin main`;
} catch (err) {
  console.error('Push failed:', err.exitCode, err.stderr.toString());
}

// Quiet mode — don't throw, check exit code manually
const result = await $`git status`.quiet();
if (result.exitCode !== 0) {
  console.log('Not a git repository');
}
```

## Environment variables

```ts
// Inherit from process, override specific vars
await $`FORCE_COLOR=1 next build`.env({ NODE_ENV: 'production' });

// Read from .env file
const env = await Bun.file('.env').text();
const parsed = Object.fromEntries(
  env.split('\n')
    .filter((l) => l.includes('='))
    .map((l) => l.split('=')),
);
await $`next start`.env(parsed);
```

## Real script example — deploy pipeline

```ts
#!/usr/bin/env bun
// scripts/deploy.ts

import { $ } from 'bun';

const BRANCH   = (await $`git branch --show-current`.text()).trim();
const REGISTRY = 'ghcr.io/construx';
const SHA      = (await $`git rev-parse --short HEAD`.text()).trim();
const TAG      = `${REGISTRY}/website:${SHA}`;

console.log(`Deploying branch=${BRANCH} sha=${SHA}`);

// Build
await $`docker buildx build --platform linux/amd64 -t ${TAG} --push .`;

// Update Kubernetes deployment
await $`kubectl set image deployment/website website=${TAG} -n prod`;
await $`kubectl rollout status deployment/website -n prod --timeout=120s`;

// Tag as latest on main branch
if (BRANCH === 'main') {
  await $`docker tag ${TAG} ${REGISTRY}/website:latest`;
  await $`docker push ${REGISTRY}/website:latest`;
}

console.log('Deploy complete:', TAG);
```

Run it:

```bash
bun run scripts/deploy.ts
```

## Redirect and pipe to files

```ts
// Write stdout to file
await $`npm run build 2>&1`.pipe(Bun.file('build.log'));

// Append
const log = Bun.file('deploy.log');
await $`kubectl get events -n prod`.pipe(log, { flags: 'a' });
```

## Bun Shell vs execa vs shelljs vs zx

Bun Shell: zero dependencies, built into Bun, typed, cross-platform. execa: Node.js process spawning, good API, no shell syntax. shelljs: portable shell commands as functions, older API. zx: Google's shell scripting for Node.js, similar to Bun Shell but requires Node. The Construx default: Bun Shell for Bun projects; zx for Node.js projects that need cross-platform scripts.
