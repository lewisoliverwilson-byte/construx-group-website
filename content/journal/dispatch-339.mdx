The `<Image>` component from `next/image` optimises images automatically. But the defaults aren't always right, and the interaction between `width`, `height`, `sizes`, and `fill` confuses almost everyone. Here's the mental model.

## What Image does automatically

- Converts to **WebP** (or AVIF if the browser supports it) regardless of source format
- **Lazy loads** by default — images below the fold don't load until scrolled into view
- **Prevents layout shift** by reserving space before the image loads (via the intrinsic dimensions)
- Serves from Next.js's built-in image optimisation pipeline (or your CDN's)
- Generates responsive `srcset` automatically from the `sizes` prop

## The size model

The biggest source of confusion is the relationship between `width`/`height` and `sizes`.

```tsx
// Fixed size — always renders at exactly 800x600
<Image
  src="/hero.jpg"
  alt="Hero"
  width={800}
  height={600}
/>
```

`width` and `height` here are the **intrinsic dimensions** — they tell the browser how much space to reserve (preventing layout shift), not what the rendered size will be. The CSS controls actual size.

For a full-width responsive image, use `fill` with a positioned container:

```tsx
// Fill parent container
<div className="relative h-[400px] w-full">
  <Image
    src="/hero.jpg"
    alt="Hero"
    fill
    className="object-cover"
    sizes="100vw"
  />
</div>
```

`fill` removes `width`/`height` requirements — the image fills the container. **Always set `sizes`** when using `fill` or when the image isn't at its full intrinsic size.

## The `sizes` prop

`sizes` tells the browser how wide the image will be at different viewport widths. The browser uses this to pick from the generated `srcset`. Getting it wrong means downloading a 2x larger image than needed.

```tsx
// Wrong: image is 50% wide on desktop but sizes says 100vw
<Image
  src="/product.jpg"
  alt="Product"
  fill
  sizes="100vw"  // browser downloads full-width version even on desktop
/>

// Correct: match your layout
<Image
  src="/product.jpg"
  alt="Product"
  fill
  sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
/>
```

The syntax mirrors CSS media queries. For a grid layout:
- Mobile (< 768px): images are full width → `100vw`
- Tablet (768–1200px): images are 50% width → `50vw`
- Desktop: images are 33% width → `33vw`

## Priority for above-the-fold images

The largest image above the fold should not be lazy loaded — it's part of your LCP (Largest Contentful Paint):

```tsx
<Image
  src="/hero.jpg"
  alt="Hero"
  width={1920}
  height={1080}
  priority         // preloads, no lazy loading
  sizes="100vw"
  className="w-full h-auto"
/>
```

Use `priority` on the hero image of every page. On product pages, use it on the main product image.

## Remote images

Next.js blocks remote images by default (security — prevents your image optimiser from being used as a proxy). Add the domain to `next.config.ts`:

```ts
// next.config.ts
const nextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'images.unsplash.com',
      },
      {
        protocol: 'https',
        hostname: '**.amazonaws.com', // wildcard for S3 subdomains
        pathname: '/uploads/**',      // restrict to specific path
      },
    ],
  },
};
```

## Blurred placeholder

Show a blurred version of the image while it loads:

```tsx
// For local images — Next.js generates the blur automatically
import heroImage from '@/public/hero.jpg';

<Image
  src={heroImage}  // imported directly, not a string path
  alt="Hero"
  placeholder="blur"
  priority
/>

// For remote images — provide the blurDataURL manually
<Image
  src="https://example.com/image.jpg"
  alt="Product"
  width={800}
  height={600}
  placeholder="blur"
  blurDataURL="data:image/jpeg;base64,/9j/4AAQSkZJRgAB..."  // tiny base64 JPEG
/>
```

To generate `blurDataURL` for remote images, use `plaiceholder` at build time:

```ts
import { getPlaiceholder } from 'plaiceholder';

const { base64 } = await getPlaiceholder(imageUrl);
```

## User-uploaded images with Cloudflare Images

For product photos or user avatars where you don't control the source:

```ts
// Transform via Cloudflare Images API
const CLOUDFLARE_ACCOUNT_HASH = process.env.CLOUDFLARE_IMAGES_HASH!;

export function cfImage(imageId: string, variant = 'public') {
  return `https://imagedelivery.net/${CLOUDFLARE_ACCOUNT_HASH}/${imageId}/${variant}`;
}

// Define variants in Cloudflare dashboard:
// public: 1200px wide, auto quality
// thumbnail: 400px wide, 80% quality
// avatar: 200x200 crop
```

```tsx
<Image
  src={cfImage(user.avatarId, 'avatar')}
  alt={user.name}
  width={200}
  height={200}
  className="rounded-full"
/>
```

Cloudflare Images handles storage, optimisation, and CDN delivery for user-uploaded content — no S3 resize lambdas needed.

## Common mistakes

**Setting width/height to CSS pixel size**: `width={200}` means the image has 200px intrinsic dimensions. On a retina display, a 200px-wide image should have 400 intrinsic pixels. Use the actual pixel dimensions of the source image, then size with CSS.

**Not setting `sizes` on fill images**: the browser assumes `100vw` and downloads the largest srcset variant. Always provide a `sizes` string that matches your layout.

**Using priority on every image**: it defeats the purpose. Priority loads the image eagerly, competing with other critical resources. Only use it for the first visible image.

**Wrapping fill images without `position: relative`**: `fill` uses `position: absolute` internally. The parent must have `position: relative` (or `absolute`, `fixed`, etc.) and explicit dimensions.
