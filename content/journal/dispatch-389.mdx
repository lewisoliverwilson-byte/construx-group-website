The traditional model: the server fetches all data, renders the full page, sends it. With streaming, the server sends chunks of HTML as they're ready. The shell (nav, layout, static content) arrives immediately. Slow data-dependent sections stream in when their data resolves.

## How it works in Next.js

Next.js uses React's streaming renderer. When you wrap a component in `<Suspense>`, React renders the fallback immediately and streams the real content when the async work completes.

```tsx
// app/dashboard/page.tsx
import { Suspense } from 'react';
import { RecentActivity } from './RecentActivity';
import { UserStats } from './UserStats';
import { RevenueChart } from './RevenueChart';

export default function DashboardPage() {
  return (
    <div className="grid gap-6">
      {/* Fast — no async, renders immediately */}
      <DashboardHeader />

      {/* Streams in as data resolves */}
      <Suspense fallback={<StatsSkeleton />}>
        <UserStats />
      </Suspense>

      <Suspense fallback={<ChartSkeleton />}>
        <RevenueChart />
      </Suspense>

      <Suspense fallback={<ActivitySkeleton />}>
        <RecentActivity />
      </Suspense>
    </div>
  );
}
```

Each `<Suspense>` boundary is independent. If `RevenueChart` takes 2s and `UserStats` takes 200ms, `UserStats` renders after 200ms without waiting for the chart.

## Server Components with async data fetching

```tsx
// app/dashboard/UserStats.tsx — Server Component
import { db } from '@/db';
import { getUserStats } from '@/lib/analytics';

export async function UserStats() {
  // This await is fine — Suspense handles the loading state
  const stats = await getUserStats();

  return (
    <div className="grid grid-cols-3 gap-4">
      {stats.map((stat) => (
        <StatCard key={stat.label} {...stat} />
      ))}
    </div>
  );
}
```

```tsx
// Parallel fetches — don't await sequentially if they're independent
export async function DashboardData() {
  const [stats, revenue, activity] = await Promise.all([
    getUserStats(),
    getRevenueData(),
    getRecentActivity(),
  ]);

  return <>{/* render with all data */}</>;
}
```

## loading.tsx — automatic route-level Suspense

Create `loading.tsx` in any route folder and Next.js wraps the page in a Suspense boundary automatically:

```tsx
// app/dashboard/loading.tsx
export default function DashboardLoading() {
  return (
    <div className="grid gap-6 animate-pulse">
      <div className="h-8 w-48 bg-surface rounded" />
      <div className="grid grid-cols-3 gap-4">
        {[1, 2, 3].map((i) => (
          <div key={i} className="h-24 bg-surface rounded" />
        ))}
      </div>
      <div className="h-64 bg-surface rounded" />
    </div>
  );
}
```

This is the coarse-grained version. Use nested Suspense boundaries for more granular control.

## Skeleton components

Skeletons should match the shape of the real content to avoid layout shift:

```tsx
function StatsSkeleton() {
  return (
    <div className="grid grid-cols-3 gap-4">
      {[1, 2, 3].map((i) => (
        <div
          key={i}
          className="rounded p-4 flex flex-col gap-2"
          style={{ background: 'rgba(255,255,255,0.03)', border: '1px solid rgba(255,255,255,0.06)' }}
        >
          <div className="h-3 w-20 rounded bg-white/5 animate-pulse" />
          <div className="h-7 w-16 rounded bg-white/8 animate-pulse" />
          <div className="h-2 w-24 rounded bg-white/4 animate-pulse" />
        </div>
      ))}
    </div>
  );
}
```

## Streaming with `use` and Client Components

When you need to stream data into a Client Component:

```tsx
// Server Component — initiates the fetch but doesn't await it
import { Suspense, use } from 'react';

async function ServerWrapper() {
  // Start the fetch — don't await
  const dataPromise = fetchSlowData();

  return (
    <Suspense fallback={<Skeleton />}>
      <ClientComponent dataPromise={dataPromise} />
    </Suspense>
  );
}

// Client Component — reads the promise with `use`
'use client';
function ClientComponent({ dataPromise }: { dataPromise: Promise<Data> }) {
  const data = use(dataPromise);  // Suspends until resolved
  return <>{/* render with data */}</>;
}
```

`use` is like `await` but works inside Client Components and interacts with Suspense boundaries.

## Error boundaries for streaming

Each Suspense boundary can have its own error boundary:

```tsx
// app/dashboard/ErrorBoundary.tsx
'use client';

import { Component, type ReactNode } from 'react';

export class ErrorBoundary extends Component<
  { children: ReactNode; fallback: ReactNode },
  { error: Error | null }
> {
  state = { error: null };

  static getDerivedStateFromError(error: Error) {
    return { error };
  }

  render() {
    if (this.state.error) return this.props.fallback;
    return this.props.children;
  }
}
```

```tsx
// Wrap individual sections
<ErrorBoundary fallback={<RevenueError />}>
  <Suspense fallback={<ChartSkeleton />}>
    <RevenueChart />
  </Suspense>
</ErrorBoundary>
```

Next.js 15 ships `error.tsx` as a file-based equivalent for route-level errors, but manual `ErrorBoundary` wrapping gives you finer control within a page.

## What not to stream

Not everything benefits from streaming. Static content (marketing pages, docs) should be statically generated — streaming adds latency for content that could have been cached entirely. Stream dynamic, user-specific data that can't be cached at the edge.

The mental model: render the shell immediately, stream in the data-dependent parts. Users see something in under 100ms regardless of how long the database takes.
