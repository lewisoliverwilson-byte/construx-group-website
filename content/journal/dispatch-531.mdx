Core Web Vitals are Google's field metrics for page experience. They affect search ranking and — more importantly — they directly measure whether users wait, get confused, or abandon. The three that matter: Largest Contentful Paint (LCP), Interaction to Next Paint (INP), and Cumulative Layout Shift (CLS).

## Measuring first

Before fixing, measure. PageSpeed Insights gives field data from Chrome UX Report (real user data). For local measurement, use `web-vitals`:

```bash
npm install web-vitals
```

```ts
// app/layout.tsx — report vitals
import { useReportWebVitals } from 'next/web-vitals';

export function WebVitalsReporter() {
  useReportWebVitals((metric) => {
    console.log(metric.name, metric.value, metric.rating);
    // rating: 'good' | 'needs-improvement' | 'poor'
  });
  return null;
}
```

Or instrument with Vercel Analytics / Sentry which capture real user metrics.

## LCP (Largest Contentful Paint)

LCP measures how long it takes for the largest content element (usually the hero image or headline) to render. Target: under 2.5s.

**The main culprit: unoptimised hero images.**

```tsx
// ❌ Before — img tag, no preload, no sizing hints
<img src="/hero.jpg" alt="Hero" className="w-full" />

// ✅ After — next/image with priority
import Image from 'next/image';

<Image
  src="/hero.jpg"
  alt="Hero"
  width={1920}
  height={1080}
  priority           // Tells browser to preload — critical for above-fold images
  sizes="100vw"      // Width hint for responsive srcset
  quality={85}
/>
```

`priority` on the above-fold image generates a `<link rel="preload">` in the HTML — the image starts loading before the JavaScript bundle runs.

**Slow server response (TTFB):**

```ts
// Cache server-rendered pages with Next.js revalidation
export const revalidate = 3600;  // Revalidate at most once per hour

// Or use unstable_cache for dynamic data
import { unstable_cache } from 'next/cache';

const getProducts = unstable_cache(
  async () => db.select().from(products),
  ['products'],
  { revalidate: 60 },
);
```

**Too much JavaScript blocking render:**

Use `next/dynamic` for heavy components that aren't needed immediately:

```tsx
import dynamic from 'next/dynamic';

const HeavyChart = dynamic(() => import('./HeavyChart'), {
  loading: () => <div className="h-64 animate-pulse bg-gray-800" />,
  ssr: false,  // Don't render on server if it uses browser APIs
});
```

## INP (Interaction to Next Paint)

INP measures how quickly the page responds to interactions (clicks, taps, key presses). Target: under 200ms.

**Long tasks blocking the main thread:**

```ts
// ❌ Heavy computation synchronous on the main thread
function processLargeDataset(data: Record[]) {
  return data.map(expensiveTransform);
}

// ✅ Use a Web Worker for heavy computation
const worker = new Worker(new URL('./worker.ts', import.meta.url));
worker.postMessage({ data });
worker.onmessage = (e) => setResults(e.data);
```

**Unnecessary re-renders:**

```tsx
// ❌ Component re-renders on every parent update
function ProductCard({ product }: { product: Product }) {
  return <div>{product.name}</div>;
}

// ✅ Memoized when props don't change
const ProductCard = memo(function ProductCard({ product }: { product: Product }) {
  return <div>{product.name}</div>;
});
```

## CLS (Cumulative Layout Shift)

CLS measures how much content jumps around unexpectedly. Target: under 0.1.

**The most common cause: images without dimensions.**

```tsx
// ❌ Image with no size — reserves no space, causes layout shift when it loads
<img src="/avatar.png" alt="Avatar" />

// ✅ Always set width and height (or use next/image which requires them)
<img src="/avatar.png" alt="Avatar" width={48} height={48} />
```

**Dynamic content injected above existing content:**

```tsx
// ❌ Banner appears above content after load — shifts everything down
{showBanner && <PromoBanner />}
<MainContent />

// ✅ Reserve space for the banner
<div style={{ minHeight: showBanner ? '48px' : '0', transition: 'min-height 0.3s' }}>
  {showBanner && <PromoBanner />}
</div>
<MainContent />
```

**Font loading causing text reflow:** use `font-display: swap` and preload critical fonts:

```tsx
// app/layout.tsx
import { Inter } from 'next/font/google';

const inter = Inter({
  subsets:  ['latin'],
  display:  'swap',    // Show fallback font immediately, swap when loaded
  preload:  true,
});
```

## Monitoring

Use Vercel's Speed Insights (one line of setup) or Sentry's Web Vitals integration to track these metrics in production over time. Point-in-time PageSpeed scores are misleading — what matters is the 75th percentile from real users over 28 days, which is what Google uses for ranking.
