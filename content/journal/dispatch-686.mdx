TypeScript evolves conservatively — breaking changes are rare, improvements are additive. TypeScript 5.x brought several improvements that are immediately useful in day-to-day TypeScript development without requiring any architectural changes.

## Stable decorators

TypeScript 4.x had `experimentalDecorators` — an old, unstable proposal. TypeScript 5 supports TC39 Stage 3 decorators, which are different and don't require the flag.

```ts
// No experimentalDecorators flag needed
function logged(target: Function, context: ClassMethodDecoratorContext) {
  const name = String(context.name);
  return function (this: unknown, ...args: unknown[]) {
    console.log(`${name} called with`, args);
    const result = target.apply(this, args);
    console.log(`${name} returned`, result);
    return result;
  };
}

class Calculator {
  @logged
  add(a: number, b: number): number {
    return a + b;
  }
}

// Class decorators
function singleton<T extends { new(...args: unknown[]): unknown }>(cls: T): T {
  let instance: InstanceType<T>;
  return class extends cls {
    constructor(...args: unknown[]) {
      super(...args);
      if (instance) return instance;
      instance = this as InstanceType<T>;
    }
  } as T;
}

@singleton
class Database {
  connected = false;
}

const db1 = new Database();
const db2 = new Database();
console.log(db1 === db2);  // true
```

## Const type parameters

```ts
// Before: loses literal types
function first<T>(arr: T[]): T {
  return arr[0];
}
const result = first(['a', 'b', 'c']);  // type: string (not 'a')

// TypeScript 5: const T preserves literal types
function first<const T>(arr: T[]): T {
  return arr[0];
}
const result = first(['a', 'b', 'c']);  // type: 'a' (correct!)

// Useful for typed config objects
function defineConfig<const T extends Record<string, unknown>>(config: T): T {
  return config;
}

const config = defineConfig({
  port: 3000,
  host: 'localhost',
  env:  'production',
});
// config.env is 'production', not string
```

## extends array in tsconfig

```json
// tsconfig.json — extend multiple base configs
{
  "extends": [
    "@tsconfig/strictest/tsconfig.json",
    "@tsconfig/next/tsconfig.json"
  ],
  "compilerOptions": {
    "outDir": "./dist"
  }
}
```

Useful when combining framework configs with strictness configs without manual merging.

## Improved inference

```ts
// TS 5.4: NoInfer<T> prevents widening in specific positions
function createRoute<T>(
  path: string,
  handler: (ctx: NoInfer<T>) => Response,
  defaultCtx: T,
): void {}

// TS 5.5: inferred type predicates
function isString(value: unknown): value is string {
  return typeof value === 'string';
}
// TypeScript 5.5+ can infer the 'is string' return type automatically:
function isString(value: unknown) {
  return typeof value === 'string';
}
```

## satisfies operator (TS 4.9, widely used in 5.x)

```ts
const COLORS = {
  red:   '#ff0000',
  green: '#00ff00',
  blue:  '#0000ff',
} satisfies Record<string, string>;

// COLORS.red is '#ff0000', not string
// The satisfies check ensures the value conforms to Record<string, string>
// but preserves literal types for autocomplete and narrowing

type Color = keyof typeof COLORS;  // 'red' | 'green' | 'blue'
```

## Strict mode settings that matter

```json
{
  "compilerOptions": {
    "strict":                          true,   // enables all strict checks
    "noUncheckedIndexedAccess":        true,   // arr[0] is T | undefined, not T
    "exactOptionalPropertyTypes":      true,   // { x?: number } won't accept { x: undefined }
    "noPropertyAccessFromIndexSignature": true, // must use obj['key'], not obj.key for index sigs
    "allowUnusedLabels":               false,
    "allowUnreachableCode":            false
  }
}
```

`noUncheckedIndexedAccess` is the most impactful — it prevents the extremely common bug of accessing array elements without checking for undefined. Worth enabling even if it requires fixing existing code.

## TypeScript 5.x compiler performance

TypeScript 5 reduced memory usage by roughly 30% by switching internal data structures and removed legacy `tsc --build` overhead for simple project references. Large monorepos see meaningful CI time reduction from the upgrade alone. No code changes required — just upgrade `typescript` in package.json.
