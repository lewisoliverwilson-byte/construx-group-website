excerpt: "yq is a portable command-line YAML/JSON/TOML/XML processor — it reads structured data, applies expressions in a jq-compatible syntax, and writes the result. Unlike jq (which only handles JSON), yq understands YAML natively, including anchors, aliases, multi-document files, and comments. It can convert between formats (YAML to JSON, JSON to YAML, TOML to YAML), edit files in-place with -i, and merge multiple YAML files. yq is indispensable for processing Kubernetes manifests, Helm values, GitHub Actions workflows, Docker Compose files, and any YAML-heavy pipeline where raw sed/awk would be fragile."

Read YAML as data. Filter with jq syntax. Write back with `-i`. Convert formats freely.

## Basic queries and filtering

```bash
# yq: read and filter YAML files
cat deployment.yaml | yq '.spec.replicas'
# 3

# Select a deeply nested value
yq '.spec.template.spec.containers[0].image' deployment.yaml
# construx/api:1.4.2

# Select all container images in a deployment
yq '.spec.template.spec.containers[].image' deployment.yaml
# construx/api:1.4.2
# construx/proxy:0.9.1

# Filter: select resources by label
yq 'select(.metadata.labels.app == "construx-api")' all-resources.yaml

# Select from a list by index
yq '.spec.containers[0]' pod.yaml       # first container
yq '.spec.containers[-1]' pod.yaml      # last container
yq '.spec.containers[1:3]' pod.yaml     # slice (index 1 and 2)

# Select a key and output as JSON
yq -o json '.spec.resources' deployment.yaml
# {
#   "requests": { "cpu": "500m", "memory": "512Mi" },
#   "limits":   { "cpu": "2000m", "memory": "2Gi" }
# }

# Read from stdin
kubectl get deployment construx-api -o yaml | yq '.spec.replicas'
# 5
```

## Editing files in-place

```bash
# -i: edit the YAML file in-place (like sed -i)

# Update image tag (for scripted deployments)
yq -i '.spec.template.spec.containers[0].image = "construx/api:1.4.3"' deployment.yaml

# Update replicas
yq -i '.spec.replicas = 5' deployment.yaml

# Add a new label
yq -i '.metadata.labels.version = "1.4.3"' deployment.yaml

# Add an element to a list
yq -i '.spec.template.spec.containers += {"name": "sidecar", "image": "construx/proxy:0.9.2"}' deployment.yaml

# Delete a key
yq -i 'del(.spec.template.spec.containers[0].resources.limits)' deployment.yaml

# Conditional update: only update if condition is met
yq -i 'select(.metadata.name == "construx-api") | .spec.replicas = 3' all-deployments.yaml

# Update across multiple files
yq -i '.spec.replicas = 3' deployments/*.yaml

# Increment a value
yq -i '.spec.replicas += 1' deployment.yaml
```

## Format conversion

```bash
# YAML to JSON
yq -o json deployment.yaml

# YAML to JSON (compact/minified)
yq -o json -I 0 deployment.yaml

# JSON to YAML
yq -P '.' data.json   # -P = pretty-print YAML output (default)
cat data.json | yq -o yaml

# Helm values.yaml to JSON (for validation or processing)
yq -o json values.yaml > values.json
jq '.ingress.hosts[0].host' values.json

# TOML to YAML (for config migration)
yq --input-format toml -o yaml Cargo.toml

# XML to YAML
yq --input-format xml -o json pom.xml | jq '.project.version'

# Multi-document YAML (Kubernetes manifest with ---):
# yq handles multi-document by default
yq '.kind' all-resources.yaml   # prints kind for each document
# Deployment
# Service
# ConfigMap

# Select only Deployments from a multi-document file
yq 'select(.kind == "Deployment")' all-resources.yaml
```

## Merging and combining files

```bash
# Merge two YAML files (values from the second override the first)
yq eval-all 'select(fileIndex == 0) * select(fileIndex == 1)' \
  base-values.yaml \
  prod-overrides.yaml

# Merge multiple Kubernetes manifests into one file
yq eval-all '.' deployment.yaml service.yaml configmap.yaml > all-resources.yaml

# Deep merge (merge nested maps recursively)
yq eval-all '. as $item ireduce ({}; . * $item)' base.yaml overlay.yaml

# Combine values from multiple files into a single structure
yq eval-all '[.]' pod-1.yaml pod-2.yaml pod-3.yaml
# Returns a YAML list of all three pod definitions

# Update Kubernetes resources with kubectl + yq
kubectl get deployment construx-api -o yaml | \
  yq '.spec.replicas = 5' | \
  kubectl apply -f -

# Patch Helm values in CI
VALUES=$(yq ".image.tag = \"$CI_COMMIT_SHORT_SHA\"" values.yaml)
helm upgrade construx-api ./charts/construx --values <(echo "$VALUES")
```

## Advanced expressions

```bash
# Arithmetic
yq '.spec.replicas * 2' deployment.yaml     # 10

# String interpolation
yq '"\(.metadata.name) has \(.spec.replicas) replicas"' deployment.yaml
# "construx-api has 5 replicas"

# Map: transform all items in a list
yq '.spec.containers[] | .name + "=" + .image' deployment.yaml
# construx-api=construx/api:1.4.2
# sidecar=construx/proxy:0.9.2

# Reduce: aggregate
yq '[.spec.containers[].resources.limits.cpu] | add' deployment.yaml
# "4500m"  (sum of all CPU limits as strings — careful with units)

# env: substitute environment variables
IMAGE_TAG="1.4.3" yq '.spec.template.spec.containers[0].image = strenv(IMAGE_TAG)' deployment.yaml

# Keys and values
yq '.spec.template.spec.containers[0].env | keys' deployment.yaml
yq '.spec.template.spec.containers[0].env | to_entries' deployment.yaml

# Validate: check if a key exists
yq '.spec.selector | has("matchLabels")' deployment.yaml
# true
```

yq vs jq for YAML: jq only understands JSON — to process YAML you'd need to convert to JSON first (`yq -o json`) and pipe to jq. yq understands YAML natively (anchors, multi-document, comments), supports the same filter syntax, and can write back to YAML without a round-trip through JSON. The practical rule: use jq for JSON APIs and log processing; use yq for Kubernetes manifests, Helm values, and any YAML-centric pipeline. They compose well: `kubectl get pod -o yaml | yq -o json | jq '.status'` works when jq's operators are richer for a specific transformation, but most YAML manipulation is easier in yq directly.
