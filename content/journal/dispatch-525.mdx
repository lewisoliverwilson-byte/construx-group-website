The usual component library trade-off: install a library (MUI, Chakra, Radix) and get fast results with limited customisation, or build from scratch and spend weeks on accessibility, focus management, and keyboard navigation. shadcn/ui takes a different position: copy the component source into your project. You own it, you can modify it, and the primitives are Radix UI (fully accessible) wrapped in Tailwind classes.

## Setup

```bash
npx shadcn-ui@latest init
```

This creates a `components/ui/` directory and updates `tailwind.config.ts` and `globals.css` with CSS variables for the design tokens.

```css
/* globals.css — generated by shadcn/ui */
@layer base {
  :root {
    --background:   0 0% 100%;
    --foreground:   222.2 84% 4.9%;
    --primary:      222.2 47.4% 11.2%;
    --primary-foreground: 210 40% 98%;
    --ring:         222.2 84% 4.9%;
    --radius:       0.5rem;
    /* ... */
  }

  .dark {
    --background:   222.2 84% 4.9%;
    --foreground:   210 40% 98%;
    /* ... */
  }
}
```

The CSS variables map to Tailwind classes like `bg-background`, `text-foreground`, `border-border`. Change a variable, every component using that token updates.

## Adding components

```bash
npx shadcn-ui@latest add button dialog input select table
```

This copies `components/ui/button.tsx`, `components/ui/dialog.tsx`, etc. into your project. They're yours — edit them freely.

## The Button component (what shadcn/ui generates)

```tsx
// components/ui/button.tsx
import { Slot }               from '@radix-ui/react-slot';
import { cva, type VariantProps } from 'class-variance-authority';
import { cn }                 from '@/lib/utils';

const buttonVariants = cva(
  'inline-flex items-center justify-center whitespace-nowrap rounded-md text-sm font-medium transition-colors focus-visible:outline-none focus-visible:ring-1 focus-visible:ring-ring disabled:pointer-events-none disabled:opacity-50',
  {
    variants: {
      variant: {
        default:     'bg-primary text-primary-foreground shadow hover:bg-primary/90',
        destructive: 'bg-destructive text-destructive-foreground shadow-sm hover:bg-destructive/90',
        outline:     'border border-input bg-background shadow-sm hover:bg-accent hover:text-accent-foreground',
        secondary:   'bg-secondary text-secondary-foreground shadow-sm hover:bg-secondary/80',
        ghost:       'hover:bg-accent hover:text-accent-foreground',
        link:        'text-primary underline-offset-4 hover:underline',
      },
      size: {
        default: 'h-9 px-4 py-2',
        sm:      'h-8 rounded-md px-3 text-xs',
        lg:      'h-10 rounded-md px-8',
        icon:    'h-9 w-9',
      },
    },
    defaultVariants: {
      variant: 'default',
      size:    'default',
    },
  },
);

export interface ButtonProps
  extends React.ButtonHTMLAttributes<HTMLButtonElement>,
    VariantProps<typeof buttonVariants> {
  asChild?: boolean;
}

const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ className, variant, size, asChild = false, ...props }, ref) => {
    const Comp = asChild ? Slot : 'button';
    return (
      <Comp className={cn(buttonVariants({ variant, size, className }))} ref={ref} {...props} />
    );
  },
);
```

The `Slot` component allows the button to render as any element (a link, for example) while keeping all the styling and accessibility. The `asChild` pattern is a Radix UI convention.

## Customising the theme

Override the CSS variables in `globals.css` to match your brand:

```css
:root {
  --primary:   24.6 95% 53.1%;  /* Construx orange */
  --radius:    0.25rem;          /* Tighter border radius */
}
```

Or extend the Tailwind config with custom tokens:

```ts
// tailwind.config.ts
export default {
  theme: {
    extend: {
      colors: {
        construx: {
          DEFAULT: '#F97316',
          50:      '#FFF7ED',
          500:     '#F97316',
          600:     '#EA6C10',
          900:     '#7C2D12',
        },
      },
      fontFamily: {
        mono: ['Berkeley Mono', 'Fira Code', 'monospace'],
      },
    },
  },
};
```

## Form composition

shadcn/ui includes form primitives that integrate with React Hook Form and Zod:

```tsx
import { useForm }           from 'react-hook-form';
import { zodResolver }       from '@hookform/resolvers/zod';
import { Form, FormField, FormItem, FormLabel, FormControl, FormMessage } from '@/components/ui/form';
import { Input }             from '@/components/ui/input';
import { Button }            from '@/components/ui/button';
import { z }                 from 'zod';

const schema = z.object({
  email: z.string().email(),
});

export function EmailForm() {
  const form = useForm({ resolver: zodResolver(schema) });

  return (
    <Form {...form}>
      <form onSubmit={form.handleSubmit(console.log)}>
        <FormField
          control={form.control}
          name="email"
          render={({ field }) => (
            <FormItem>
              <FormLabel>Email</FormLabel>
              <FormControl>
                <Input placeholder="you@example.com" {...field} />
              </FormControl>
              <FormMessage />
            </FormItem>
          )}
        />
        <Button type="submit">Subscribe</Button>
      </form>
    </Form>
  );
}
```

Validation errors appear automatically next to the field. No manual error state management.

## The payoff

The Construx website and all its ventures use shadcn/ui as the base layer. The components are owned, customised, and consistent. Accessibility (focus management, keyboard navigation, ARIA attributes) is handled by Radix UI underneath — we don't maintain that complexity. Styling is Tailwind — consistent tokens, no runtime overhead.

The copy-paste model felt strange initially. It's now obviously the right trade-off: full ownership of the component code without the maintenance burden of building accessible primitives from scratch.
