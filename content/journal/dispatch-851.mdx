title: "Envoy circuit breakers and outlier detection in production"
date: "2031-12-10"
excerpt: "Circuit breakers prevent cascade failures: when an upstream service is slow or returning errors, a circuit breaker stops sending requests rather than letting the callers queue and time out. Envoy implements circuit breakers at the cluster level (max connections, pending requests, retries) and outlier detection at the endpoint level (automatic ejection of unhealthy hosts based on consecutive errors or latency). Both operate in real time with no external coordination."
author: "Lewis Wilson"
tag: "Build Log"

Stop sending to broken upstreams. Eject bad endpoints automatically.

## Circuit breaker thresholds

```yaml
# envoy.yaml — cluster with circuit breakers
clusters:
  - name: orders_service
    circuit_breakers:
      thresholds:
        # Default priority (most traffic)
        - priority:               DEFAULT
          max_connections:        1000    # Max concurrent TCP connections
          max_pending_requests:   1000    # Max requests waiting for a connection
          max_requests:           1000    # Max concurrent active requests
          max_retries:            3       # Max concurrent retries in flight
          track_remaining:        true    # Expose remaining capacity in headers

        # High priority (health checks, admin traffic)
        - priority:               HIGH
          max_connections:        200
          max_pending_requests:   200
          max_requests:           200
          max_retries:            4
```

## Outlier detection — eject unhealthy endpoints

```yaml
clusters:
  - name: orders_service
    outlier_detection:
      # Eject after N consecutive 5xx errors
      consecutive_5xx:              5
      consecutive_gateway_failure:  5

      # Eject after N consecutive local origin errors (connection refused, timeout)
      consecutive_local_origin_failure: 3
      enforcing_consecutive_local_origin_failure: 100

      # Periodic analysis interval
      interval:                     { seconds: 10 }

      # Ejection duration (host stays out for at least this long)
      base_ejection_time:           { seconds: 30 }

      # Scale ejection time by number of ejections (host stays out longer each time)
      max_ejection_time:            { seconds: 300 }

      # Never eject more than this fraction of endpoints
      max_ejection_percent:         50

      # Enforce or just monitor (100 = fully enforce, 0 = metrics only)
      enforcing_consecutive_5xx:    100
      enforcing_success_rate:       100

      # Success rate outlier detection — eject endpoints significantly below average
      success_rate_minimum_hosts:   5
      success_rate_request_volume:  100
      success_rate_stdev_factor:    1900  # 1.9 standard deviations
```

## Retry policy — complement to circuit breakers

```yaml
routes:
  - match: { prefix: "/api/orders" }
    route:
      cluster: orders_service
      timeout: { seconds: 30 }
      retry_policy:
        # Retry these error conditions
        retry_on: "5xx,gateway-error,connect-failure,retriable-4xx"
        num_retries:       3
        per_try_timeout:   { seconds: 10 }

        # Exponential backoff between retries
        retry_back_off:
          base_interval:   { milliseconds: 25 }
          max_interval:    { milliseconds: 1000 }

        # Headers that mark a request as safe to retry
        retriable_request_headers:
          - name:          x-idempotency-key
            present_match: true

        # Don't retry if the upstream is already at circuit limit
        host_selection_retry_max_attempts: 3
        retry_host_predicate:
          - name: envoy.retry_host_predicates.previous_hosts
```

## Local rate limiting — protect your service

```bash
# After enabling local_ratelimit filter:
# Request that exceeds the rate limit returns 429

curl -v http://api.construxgroup.io/orders
# < HTTP/1.1 429 Too Many Requests
# < x-rate-limit-limit: 1000
# < x-rate-limit-remaining: 0
# < x-envoy-ratelimited: true
```

Retry budgets: naive retries amplify load during failures. If every client retries 3 times, a 50% error rate becomes 150% load. Envoy's `max_retries` in the circuit breaker limits the total concurrent retries across all requests — when the retry budget is exhausted, further retries are rejected immediately with a 503 rather than making the upstream worse. Set `max_retries` to a fraction of `max_requests` (typically 10-25%) to ensure retries can't cascade into overload.
