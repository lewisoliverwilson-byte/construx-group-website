Next.js middleware (`middleware.ts` in the project root) runs at the edge — before any page or API route handles the request. It's fast, runs globally, and doesn't suffer from serverless cold starts because it runs on the edge runtime, not full Node.js.

Most projects have a minimal middleware, or none at all. Here's what we actually put in it and why.

## Authentication: protect before the page loads

The most common use case: redirect unauthenticated users before the page renders.

```ts
// middleware.ts
import { clerkMiddleware, createRouteMatcher } from '@clerk/nextjs/server';

const isProtectedRoute = createRouteMatcher([
  '/dashboard(.*)',
  '/settings(.*)',
  '/workspace(.*)',
  '/api/(?!webhooks)(.*)', // protect all API routes except webhooks
]);

export default clerkMiddleware(async (auth, req) => {
  if (isProtectedRoute(req)) {
    await auth.protect();
  }
});

export const config = {
  matcher: ['/((?!_next|[^?]*\\.(?:html?|css|js(?!on)|jte?|ttf|woff2?|ico|png|jpg|jpeg|svg|gif|webp)).*)', '/(api|trpc)(.*)'],
};
```

Clerk's `clerkMiddleware` runs on every request, but only calls `auth.protect()` for protected routes. Unauthenticated requests to protected routes get redirected to the sign-in page before any page code runs — no wasted render, no flicker.

The `matcher` pattern excludes static files (CSS, images, fonts) from middleware entirely, since they don't need authentication checks.

## Rate limiting at the edge

The advantage of rate limiting in middleware over rate limiting in route handlers: it runs before any route handler code, so a rate-limited request doesn't consume any serverless function execution time.

```ts
import { Ratelimit } from '@upstash/ratelimit';
import { Redis } from '@upstash/redis';
import { NextRequest, NextResponse } from 'next/server';

const rl = new Ratelimit({
  redis: Redis.fromEnv(),
  limiter: Ratelimit.slidingWindow(100, '1 m'),
  prefix: 'edge_rl',
});

export async function middleware(req: NextRequest) {
  if (req.nextUrl.pathname.startsWith('/api/')) {
    const ip = req.headers.get('cf-connecting-ip') ?? 
               req.headers.get('x-forwarded-for')?.split(',')[0] ?? 
               'anonymous';
    
    const { success } = await rl.limit(ip);
    if (!success) {
      return new NextResponse('Rate limit exceeded', { status: 429 });
    }
  }
  
  return NextResponse.next();
}
```

The edge runtime supports Upstash's HTTP-based Redis client. It doesn't support the standard `ioredis` client, which uses TCP — the edge runtime only allows HTTP outbound connections.

## Redirects that can't be in next.config.js

`next.config.js` redirects are static — they don't read request data beyond the URL. Middleware redirects can be dynamic:

```ts
// Redirect users to their workspace on login
if (req.nextUrl.pathname === '/') {
  const { userId } = auth();
  if (userId) {
    return NextResponse.redirect(new URL('/workspace', req.url));
  }
}

// Redirect legacy URLs
if (req.nextUrl.pathname.startsWith('/app/')) {
  const newPath = req.nextUrl.pathname.replace('/app/', '/workspace/');
  return NextResponse.redirect(new URL(newPath, req.url));
}
```

These run at the edge before any page code, making them faster than a client-side redirect or a page-level `redirect()` call.

## Response headers for security

Security headers that should be present on every response can be set in middleware rather than configuring them in `next.config.js`:

```ts
function addSecurityHeaders(response: NextResponse) {
  response.headers.set('X-Frame-Options', 'DENY');
  response.headers.set('X-Content-Type-Options', 'nosniff');
  response.headers.set('Referrer-Policy', 'strict-origin-when-cross-origin');
  response.headers.set(
    'Permissions-Policy',
    'camera=(), microphone=(), geolocation=()'
  );
  return response;
}

export async function middleware(req: NextRequest) {
  const response = NextResponse.next();
  return addSecurityHeaders(response);
}
```

The advantage of middleware over `next.config.js` headers: middleware can set headers conditionally based on the request. API responses and page responses can have different header sets.

## What middleware can't do

**Access the database.** The edge runtime doesn't have the same Node.js APIs as a full serverless function. You can use HTTP-based clients (Upstash Redis, Neon's HTTP API), but not `pg` or `@neondatabase/serverless` in TCP mode.

**Long-running operations.** Middleware has a 1-second (default) to 30-second (maximum on paid Vercel plans) execution limit on the edge runtime. AWS Amplify's middleware limit is shorter. Keep middleware fast.

**Full Node.js APIs.** `fs`, `crypto` (some APIs), native modules — not available. Web APIs only.

**Per-route middleware.** Next.js middleware is a single file that runs on all matched routes. You can branch on `req.nextUrl.pathname` inside the middleware, but there's no per-route file-based middleware like Express routes.

## The middleware we actually run

For The Hyve on Amplify:

```ts
import { clerkMiddleware, createRouteMatcher } from '@clerk/nextjs/server';
import { Ratelimit } from '@upstash/ratelimit';
import { Redis } from '@upstash/redis';
import { NextResponse } from 'next/server';

const rl = new Ratelimit({
  redis: Redis.fromEnv(),
  limiter: Ratelimit.slidingWindow(200, '1 m'),
  prefix: 'hyve_edge',
});

const isPublicRoute = createRouteMatcher([
  '/sign-in(.*)',
  '/sign-up(.*)',
  '/api/webhooks/(.*)',
]);

export default clerkMiddleware(async (auth, req) => {
  // Rate limit all API routes
  if (req.nextUrl.pathname.startsWith('/api/')) {
    const ip = req.headers.get('x-forwarded-for')?.split(',')[0] ?? 'anon';
    const { success } = await rl.limit(ip);
    if (!success) return new NextResponse('Rate limit exceeded', { status: 429 });
  }

  // Auth check
  if (!isPublicRoute(req)) {
    await auth.protect();
  }
});

export const config = {
  matcher: [
    '/((?!_next/static|_next/image|favicon.ico).*)',
    '/(api|trpc)(.*)',
  ],
};
```

Three things in one file: Clerk authentication, global rate limiting, and route protection. Runs on every request at the edge, before any page or API route code.
