GitHub Actions runs workflows defined as YAML in `.github/workflows/`. Each push, PR, or schedule triggers the workflow. For a Next.js project the core loop is: install, type-check, lint, test, build — then deploy if on main.

## CI workflow

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main, master]
  pull_request:
    branches: [main, master]

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  ci:
    name: Type-check · Lint · Test · Build
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Type check
        run: npx tsc --noEmit

      - name: Lint
        run: npm run lint

      - name: Test
        run: npm run test

      - name: Build
        run: npm run build
        env:
          NEXT_PUBLIC_SITE_URL: https://construxgroup.io
```

The `concurrency` block cancels in-progress runs on the same branch when a new push lands — saves CI minutes on rapid pushes.

## Caching node_modules

```yaml
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
```

`cache: 'npm'` uses the `package-lock.json` hash as the cache key. If deps haven't changed, `npm ci` restores from cache and skips the network install. Cuts install from ~45s to ~5s on a warm cache.

## Environment variables and secrets

Secrets are stored in the repo settings (Settings → Secrets and variables → Actions) and referenced in workflows:

```yaml
      - name: Run integration tests
        run: npm run test:integration
        env:
          DATABASE_URL:        ${{ secrets.DATABASE_URL }}
          UPSTASH_REDIS_URL:   ${{ secrets.UPSTASH_REDIS_URL }}
          CLERK_SECRET_KEY:    ${{ secrets.CLERK_SECRET_KEY }}
```

Never put secrets in the workflow YAML itself. The `${{ secrets.* }}` syntax is the only safe way to inject them — GitHub masks the values in logs automatically.

## Preview deployment on PRs

For projects deploying to Amplify, trigger a preview build via the AWS CLI:

```yaml
  deploy-preview:
    name: Deploy preview
    runs-on: ubuntu-latest
    needs: ci
    if: github.event_name == 'pull_request'

    steps:
      - uses: actions/checkout@v4

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id:     ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: eu-west-2

      - name: Trigger Amplify preview build
        run: |
          aws amplify start-job \
            --app-id ${{ vars.AMPLIFY_APP_ID }} \
            --branch-name ${{ github.head_ref }} \
            --job-type RELEASE
```

## Production deploy on merge

```yaml
  deploy-production:
    name: Deploy to production
    runs-on: ubuntu-latest
    needs: ci
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'

    steps:
      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id:     ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: eu-west-2

      - name: Trigger Amplify production build
        run: |
          aws amplify start-job \
            --app-id ${{ vars.AMPLIFY_APP_ID }} \
            --branch-name main \
            --job-type RELEASE
```

## Matrix builds for multiple Node versions

```yaml
    strategy:
      matrix:
        node-version: ['18', '20', '22']

    steps:
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
```

Useful for library packages. For apps pinned to a runtime (Amplify Node 20), matrix adds noise — just test against the target version.

## Scheduled dependency audits

```yaml
# .github/workflows/audit.yml
name: Security audit

on:
  schedule:
    - cron: '0 9 * * 1'  # Monday 09:00 UTC

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm audit --audit-level=high
```

This runs weekly and surfaces high-severity CVEs in dependencies. Pair with Dependabot (`.github/dependabot.yml`) to auto-open PRs for dependency updates.

## The workflow that runs on every Construx repo

```
push/PR → install → tsc → lint → test → build
                                              ↓ (main only)
                                         deploy to Amplify
```

Type check and lint catch the obvious errors before tests run. Build is last — it's the slowest step and only worth running if everything else passes. The total run time is under 3 minutes on a warm cache.
