title: "Trivy: container and filesystem vulnerability scanning with SBOM generation"
date: "2033-01-07"
excerpt: "Trivy is an all-in-one vulnerability scanner — it scans container images, filesystems, git repos, Kubernetes clusters, and IaC files (Terraform, CloudFormation, Dockerfile) for CVEs, misconfigurations, and secrets. It generates SBOMs (Software Bill of Materials) in SPDX or CycloneDX format. The critical operational feature: Trivy has a local vulnerability database that it downloads and caches, so scans run in milliseconds rather than making API calls to a remote service. In CI, `trivy image --exit-code 1 --severity HIGH,CRITICAL` fails the build on critical vulnerabilities. The difference from grype: Trivy covers IaC misconfigurations and Kubernetes cluster scanning in addition to container images, and its SBOM output is more complete."

Image scan. IaC misconfiguration. K8s cluster scan. SBOM in SPDX/CycloneDX. One tool.

## Container image scanning

```bash
# Install Trivy
brew install aquasecurity/trivy/trivy
# or
curl -sfL https://raw.githubusercontent.com/aquasecurity/trivy/main/contrib/install.sh | sh -s -- -b /usr/local/bin v0.58.0

trivy version
# Version: 0.58.0

# Scan a container image
trivy image construx/api:v1.8.3

# Output:
# construx/api:v1.8.3 (alpine 3.20.2)
# ====================================
# Total: 3 (UNKNOWN: 0, LOW: 1, MEDIUM: 1, HIGH: 0, CRITICAL: 1)
#
# ┌──────────┬──────────────────┬──────────┬──────────────────────────────┐
# │ Library  │ Vulnerability ID │ Severity │ Installed/Fixed Version      │
# ├──────────┼──────────────────┼──────────┼──────────────────────────────┤
# │ libcurl  │ CVE-2024-12345   │ CRITICAL │ 8.5.0 / 8.6.0               │
# │ openssl  │ CVE-2024-67890   │ MEDIUM   │ 3.2.1 / 3.2.2               │
# └──────────┴──────────────────┴──────────┴──────────────────────────────┘

# Filter by severity (only CRITICAL and HIGH)
trivy image --severity HIGH,CRITICAL construx/api:v1.8.3

# Fail the build on CRITICAL vulnerabilities (CI integration)
trivy image --exit-code 1 --severity CRITICAL construx/api:v1.8.3
# exit code 1 if CRITICAL found, 0 otherwise

# Ignore unfixed vulnerabilities (common for base image CVEs)
trivy image --ignore-unfixed construx/api:v1.8.3

# Scan a private registry image
trivy image --username $REGISTRY_USER --password $REGISTRY_PASS \
  registry.construx.io/construx/api:v1.8.3

# Output as JSON (for CI reporting)
trivy image --format json --output trivy-report.json construx/api:v1.8.3

# Output as SARIF (for GitHub Security tab)
trivy image --format sarif --output trivy.sarif construx/api:v1.8.3
```

## SBOM generation

```bash
# Generate SBOM: Software Bill of Materials — list of all components
# SBOM formats: SPDX (ISO standard), CycloneDX (OWASP standard)

# CycloneDX SBOM from a container image
trivy image --format cyclonedx --output sbom.json construx/api:v1.8.3

# SPDX SBOM
trivy image --format spdx-json --output sbom.spdx.json construx/api:v1.8.3

# The SBOM contains:
# - All OS packages (name, version, license, CPE)
# - All language runtime packages (Go modules, npm, pip, gems)
# - Their relationships (what depends on what)
# - Checksums for each component

# Scan an existing SBOM for vulnerabilities (offline)
trivy sbom sbom.json
# Useful: vendor supplies SBOM, you scan it against your own vuln DB

# Attest the SBOM to the image (cosign integration)
trivy image --format cosign-vuln \
  --output vuln-attestation.json \
  construx/api:v1.8.3
cosign attest --type vuln \
  --predicate vuln-attestation.json \
  registry.construx.io/construx/api:v1.8.3
```

## IaC and misconfiguration scanning

```bash
# Scan Terraform files for misconfigurations
trivy config ./terraform/
# Results:
# FAIL: Ensure S3 bucket has public access blocked (HIGH)
#   --> terraform/s3.tf:15 bucket_public_access_block not set
# FAIL: Ensure RDS is not publicly accessible (CRITICAL)
#   --> terraform/rds.tf:28 publicly_accessible = true
# PASS: Ensure EKS has secrets encryption enabled
# PASS: Ensure RDS has backup retention > 7 days

# Scan Dockerfile for best practices
trivy config Dockerfile
# FAIL: Specify tag for base image (MEDIUM)
#   --> FROM golang:latest (use golang:1.23-alpine instead)
# FAIL: Run as non-root user (HIGH)
#   --> no USER directive in Dockerfile
# PASS: No ADD for remote URLs

# Scan Kubernetes manifests for misconfigurations
trivy config k8s/
# FAIL: Container should not run as root (HIGH)
#   --> k8s/deployment.yaml:34 securityContext.runAsNonRoot not set
# FAIL: CPU limits not set (MEDIUM)
#   --> k8s/deployment.yaml:40 resources.limits.cpu not set
# PASS: Pod security standard enforced

# Scan Helm charts
trivy config ./charts/construx-api --helm-set "replicaCount=3"

# Scan CloudFormation templates
trivy config cloudformation.yaml
```

## Kubernetes cluster scanning

```bash
# Scan the entire Kubernetes cluster for vulnerabilities and misconfigurations
trivy k8s --report all cluster

# Output includes:
# - Container images running in the cluster with their CVEs
# - Pod security policy violations
# - RBAC misconfigurations
# - Exposed secrets in ConfigMaps or env vars

# Scan specific namespace
trivy k8s --namespace construx-prod --report summary cluster

# Summary output:
# Namespace: construx-prod
# Workloads: 8
# Images scanned: 12
# CRITICAL: 2  HIGH: 7  MEDIUM: 14  LOW: 22
# Misconfigurations: 5 (runAsRoot: 3, no resource limits: 2)

# Export to HTML report
trivy k8s --report all --format table --output cluster-report.html cluster

# CI integration: scan cluster daily and post to Slack
# (run as a CronJob in-cluster with appropriate RBAC)
apiVersion: batch/v1
kind: CronJob
metadata:
  name: trivy-cluster-scan
  namespace: monitoring
spec:
  schedule: "0 8 * * *"
  jobTemplate:
    spec:
      template:
        spec:
          serviceAccountName: trivy-scanner
          containers:
            - name: trivy
              image: aquasec/trivy:0.58.0
              command:
                - trivy
                - k8s
                - --report
                - summary
                - cluster
```

## CI/CD integration

```yaml
# GitHub Actions: scan on every push, fail on CRITICAL
name: Security Scan
on: [push, pull_request]

jobs:
  trivy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build image
        run: docker build -t construx/api:${{ github.sha }} .

      - name: Scan image
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: construx/api:${{ github.sha }}
          format: sarif
          output: trivy-results.sarif
          severity: CRITICAL,HIGH
          exit-code: 1
          ignore-unfixed: true

      - name: Upload SARIF to GitHub Security tab
        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: trivy-results.sarif

      - name: Generate SBOM
        run: |
          trivy image --format cyclonedx \
            --output sbom.json \
            construx/api:${{ github.sha }}

      - name: Upload SBOM artifact
        uses: actions/upload-artifact@v4
        with:
          name: sbom
          path: sbom.json
```

Trivy vs grype vs Snyk: grype (from Anchore) is the fastest pure-image scanner with excellent SBOM support via syft. Snyk integrates into developer workflows (IDE plugins, PR checks) and has a managed vulnerability database with fix suggestions. Trivy covers the most ground: images, filesystems, IaC, Kubernetes clusters, and SBOMs — one tool for the entire security surface. The tradeoff: Trivy is slower than grype for image-only scans (it does more). The practical split: Trivy for CI pipelines where you want one scanner across images and IaC. grype/syft for SBOM-first workflows where speed matters. Snyk for developer-facing security in IDEs and pull requests.
