Running Next.js in Docker for local development is simple. Running it in production requires more care: the image must be small, the build must not bake in environment variables, and the runtime must be non-root.

## The standalone output mode

Next.js 15 has a `standalone` output mode that copies only the files needed to run the app — no `node_modules` in the output:

```ts
// next.config.ts
import type { NextConfig } from 'next';

const config: NextConfig = {
  output: 'standalone',  // generates .next/standalone with minimal output
};

export default config;
```

The standalone output includes:
- `.next/standalone/` — the server (Node.js app)
- `.next/static/` — static assets
- `public/` — public assets

## Multi-stage Dockerfile

```dockerfile
# Dockerfile

# Stage 1: Install dependencies
FROM node:20-alpine AS deps
WORKDIR /app

COPY package.json package-lock.json ./
RUN npm ci

# Stage 2: Build the app
FROM node:20-alpine AS builder
WORKDIR /app

COPY --from=deps /app/node_modules ./node_modules
COPY . .

# Build args for public env vars only — not secrets
ARG NEXT_PUBLIC_API_URL
ENV NEXT_PUBLIC_API_URL=$NEXT_PUBLIC_API_URL

RUN npm run build

# Stage 3: Production runtime
FROM node:20-alpine AS runner
WORKDIR /app

# Security: don't run as root
RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

# Copy only what's needed to run
COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs

EXPOSE 3000
ENV PORT=3000
ENV HOSTNAME="0.0.0.0"

# Run the standalone server
CMD ["node", "server.js"]
```

The three stages keep each layer clean:
1. `deps` — install dependencies (cached unless lockfile changes)
2. `builder` — build the app (invalidated when code changes)
3. `runner` — minimal runtime image (~100MB vs ~1GB with node_modules)

## Environment variables

The key rule: **public env vars** (`NEXT_PUBLIC_*`) must exist at build time. **Secret env vars** should only exist at runtime.

```dockerfile
# Public vars passed as build args
ARG NEXT_PUBLIC_API_URL
ARG NEXT_PUBLIC_APP_ENV
ENV NEXT_PUBLIC_API_URL=$NEXT_PUBLIC_API_URL
ENV NEXT_PUBLIC_APP_ENV=$NEXT_PUBLIC_APP_ENV
```

```bash
# Build with public vars
docker build \
  --build-arg NEXT_PUBLIC_API_URL=https://api.example.com \
  --build-arg NEXT_PUBLIC_APP_ENV=production \
  -t my-app:latest .
```

Runtime secrets are injected at container start, not baked into the image:

```yaml
# docker-compose.yml
services:
  app:
    image: my-app:latest
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: ${DATABASE_URL}
      STRIPE_SECRET_KEY: ${STRIPE_SECRET_KEY}
      NEXTAUTH_SECRET: ${NEXTAUTH_SECRET}
    env_file:
      - .env.production
```

## .dockerignore

Exclude everything not needed for the build:

```
node_modules
.next
.env*.local
.git
.gitignore
README.md
Dockerfile
docker-compose.yml
*.log
coverage/
.turbo/
```

## Build and run

```bash
# Build the image
docker build -t my-nextjs-app:latest .

# Run locally
docker run -p 3000:3000 \
  -e DATABASE_URL="postgresql://..." \
  -e NEXTAUTH_SECRET="..." \
  my-nextjs-app:latest

# View the image size
docker image inspect my-nextjs-app:latest --format='{{.Size}}' | numfmt --to=iec
```

## Health check

```dockerfile
# Add to the runner stage
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:3000/api/health || exit 1
```

```ts
// app/api/health/route.ts
export async function GET() {
  return Response.json({ status: 'ok', timestamp: new Date().toISOString() });
}
```

## Docker Compose for development

```yaml
# docker-compose.dev.yml
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile.dev
    ports:
      - "3000:3000"
    volumes:
      - .:/app
      - /app/node_modules  # prevent host node_modules from overriding
    environment:
      NODE_ENV: development

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

```dockerfile
# Dockerfile.dev — simpler, no build optimization needed
FROM node:20-alpine
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
CMD ["npm", "run", "dev"]
```

The pattern: use multi-stage builds to separate install, build, and runtime. Never bake secrets into images. Use the standalone output to minimize the runtime image size. Inject runtime configuration as environment variables, not build args.
