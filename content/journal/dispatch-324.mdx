Next.js middleware runs on the Vercel Edge Network (or equivalent) before any page or API route is rendered. It's not Node.js — it's a V8 isolate with a restricted runtime. The reward for working within those constraints is sub-10ms latency, globally distributed.

## What middleware can do

- Redirect or rewrite requests based on path, header, cookie, or geolocation
- Inject request headers (CSP nonces, correlation IDs, auth context)
- Gate access based on a session cookie or JWT
- A/B test by rewriting to different page variants
- Localisation based on `Accept-Language` header

What it cannot do: query a database (no TCP connections), import arbitrary Node.js modules, or do anything that takes more than ~50ms reliably.

## Setup

```ts
// middleware.ts (at project root, not inside /app)
import { NextRequest, NextResponse } from 'next/server';

export function middleware(req: NextRequest) {
  return NextResponse.next();
}

// Controls which routes middleware runs on
export const config = {
  matcher: [
    // Run on everything except static files and internal Next.js routes
    '/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)',
  ],
};
```

## Auth gating

```ts
// middleware.ts
import { NextRequest, NextResponse } from 'next/server';
import { jwtVerify } from 'jose';

const SECRET = new TextEncoder().encode(process.env.JWT_SECRET!);

const PROTECTED = ['/dashboard', '/settings', '/api/user'];

export async function middleware(req: NextRequest) {
  const isProtected = PROTECTED.some((path) => req.nextUrl.pathname.startsWith(path));
  if (!isProtected) return NextResponse.next();

  const token = req.cookies.get('session')?.value;
  if (!token) {
    return NextResponse.redirect(new URL('/login', req.url));
  }

  try {
    const { payload } = await jwtVerify(token, SECRET);
    const res = NextResponse.next();
    // Pass userId to downstream pages via header
    res.headers.set('x-user-id', payload.sub as string);
    return res;
  } catch {
    return NextResponse.redirect(new URL('/login', req.url));
  }
}
```

`jwtVerify` from `jose` is edge-compatible — it doesn't use Node.js crypto. Use it instead of `jsonwebtoken` which requires Node.

## A/B testing

```ts
export function middleware(req: NextRequest) {
  if (!req.nextUrl.pathname.startsWith('/landing')) {
    return NextResponse.next();
  }

  // Bucket by cookie — stable across requests for the same user
  let bucket = req.cookies.get('ab-bucket')?.value;
  if (!bucket) {
    bucket = Math.random() < 0.5 ? 'a' : 'b';
  }

  const url = req.nextUrl.clone();
  url.pathname = `/landing-${bucket}`;

  const res = NextResponse.rewrite(url);
  res.cookies.set('ab-bucket', bucket, { maxAge: 60 * 60 * 24 * 30 }); // 30 days
  return res;
}
```

The user sees `/landing` in their browser but gets served `/landing-a` or `/landing-b`. Both pages exist in your `app/` directory as `app/landing-a/page.tsx` and `app/landing-b/page.tsx`.

## Geolocation and localisation

```ts
export function middleware(req: NextRequest) {
  const country = req.geo?.country ?? 'US';
  const locale = req.nextUrl.locale || getPreferredLocale(req.headers.get('accept-language'));

  // Redirect to localised path if not already there
  if (!req.nextUrl.pathname.startsWith(`/${locale}`)) {
    return NextResponse.redirect(new URL(`/${locale}${req.nextUrl.pathname}`, req.url));
  }

  const res = NextResponse.next();
  res.headers.set('x-country', country);
  return res;
}

function getPreferredLocale(header: string | null): string {
  if (!header) return 'en';
  const locales = ['en', 'fr', 'de', 'es', 'ja'];
  const preferred = header.split(',')[0].trim().slice(0, 2).toLowerCase();
  return locales.includes(preferred) ? preferred : 'en';
}
```

## Header injection

Middleware is the right place to set security headers on every response — they run before any page code, so there's no risk of a page forgetting to add them:

```ts
export function middleware(req: NextRequest) {
  const nonce = crypto.randomUUID().replace(/-/g, '');

  const csp = [
    `default-src 'self'`,
    `script-src 'self' 'nonce-${nonce}'`,
    `style-src 'self' 'nonce-${nonce}'`,
    `img-src 'self' data: https:`,
    `frame-ancestors 'none'`,
  ].join('; ');

  const headers = new Headers(req.headers);
  headers.set('x-nonce', nonce);

  const res = NextResponse.next({ request: { headers } });
  res.headers.set('Content-Security-Policy', csp);
  res.headers.set('X-Frame-Options', 'DENY');
  res.headers.set('X-Content-Type-Options', 'nosniff');
  res.headers.set('Referrer-Policy', 'strict-origin-when-cross-origin');
  return res;
}
```

## The edge runtime constraint

Middleware cannot import:
- `fs`, `path`, `crypto` (Node.js built-ins — use the Web Crypto API instead)
- Database clients (`pg`, `mysql2`, prisma client, drizzle with postgres driver)
- `bcrypt`, `argon2`, or other native add-ons

If you need to check a session that requires a database lookup, validate a JWT in middleware (cheap, edge-compatible) and do the full database lookup in the page or API route that runs in Node.js.

The right mental model: middleware decides routing and injects context. The actual data work happens in Server Components and Route Handlers.
