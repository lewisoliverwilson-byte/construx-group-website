Kubernetes Deployments replace pods with no traffic control — the new version either works or it doesn't, and rollbacks are manual. Argo Rollouts gives you declarative traffic management that ties promotion to real observability signals.

## Install

```bash
kubectl create namespace argo-rollouts
kubectl apply -n argo-rollouts \
  -f https://github.com/argoproj/argo-rollouts/releases/latest/download/install.yaml

# Install the kubectl plugin
curl -LO https://github.com/argoproj/argo-rollouts/releases/latest/download/kubectl-argo-rollouts-linux-amd64
chmod +x kubectl-argo-rollouts-linux-amd64
sudo mv kubectl-argo-rollouts-linux-amd64 /usr/local/bin/kubectl-argo-rollouts
```

## Rollout manifest (canary)

```yaml
# rollouts/construx-api.yaml
apiVersion: argoproj.io/v1alpha1
kind: Rollout
metadata:
  name: construx-api
  namespace: prod
spec:
  replicas: 4
  selector:
    matchLabels:
      app: construx-api
  template:
    metadata:
      labels:
        app: construx-api
    spec:
      containers:
        - name: api
          image: construxgroup/api:v2.14.0
          resources:
            requests: { cpu: 250m, memory: 256Mi }
            limits:   { cpu: 500m, memory: 512Mi }

  strategy:
    canary:
      # Automated analysis before each step
      analysis:
        templates:
          - templateName: api-success-rate
        startingStep: 1
        args:
          - name: service-name
            value: construx-api-canary

      steps:
        - setWeight: 10       # 10% of traffic to canary
        - pause: { duration: 5m }
        - analysis:
            templates:
              - templateName: api-success-rate
        - setWeight: 30
        - pause: { duration: 10m }
        - setWeight: 60
        - pause: { duration: 10m }
        - setWeight: 100      # promote — all traffic to new version
```

## Analysis template (Prometheus)

```yaml
# analysis/api-success-rate.yaml
apiVersion: argoproj.io/v1alpha1
kind: AnalysisTemplate
metadata:
  name: api-success-rate
  namespace: prod
spec:
  args:
    - name: service-name
  metrics:
    - name: success-rate
      interval:         1m
      successCondition: result[0] >= 0.95
      failureLimit:     2
      provider:
        prometheus:
          address: http://prometheus.monitoring.svc.cluster.local:9090
          query: |
            sum(
              rate(http_requests_total{
                service="{{args.service-name}}",
                status!~"5.."
              }[2m])
            ) /
            sum(
              rate(http_requests_total{
                service="{{args.service-name}}"
              }[2m])
            )

    - name: p99-latency-ms
      interval:         1m
      successCondition: result[0] <= 300
      failureLimit:     2
      provider:
        prometheus:
          address: http://prometheus.monitoring.svc.cluster.local:9090
          query: |
            histogram_quantile(0.99,
              rate(http_request_duration_ms_bucket{
                service="{{args.service-name}}"
              }[2m])
            )
```

## Managing rollouts

```bash
# Watch the rollout live
kubectl argo rollouts get rollout construx-api -n prod --watch

# Manually pause / resume
kubectl argo rollouts pause  construx-api -n prod
kubectl argo rollouts resume construx-api -n prod

# Promote immediately (skip remaining steps)
kubectl argo rollouts promote construx-api -n prod

# Abort and roll back to stable
kubectl argo rollouts abort construx-api -n prod
kubectl argo rollouts undo  construx-api -n prod

# Trigger a new deployment
kubectl argo rollouts set image construx-api \
  api=construxgroup/api:v2.15.0 -n prod
```

## Blue-green deployment

```yaml
strategy:
  blueGreen:
    activeService:  construx-api-active    # live traffic
    previewService: construx-api-preview   # test before switching
    autoPromotionEnabled: false            # require manual promotion
    scaleDownDelaySeconds: 60
    prePromotionAnalysis:
      templates:
        - templateName: api-success-rate
```

## Argo Rollouts vs Flagger vs manual scripts

Argo Rollouts: declarative, native Kubernetes, rich analysis templates, great dashboard. Flagger: operator model, auto-detects metrics, Istio/Linkerd native. Manual scripts: fragile, no automatic rollback. Use Argo Rollouts when you are already using Argo CD and want progressive delivery as Kubernetes-native manifests you can diff and review like any other infrastructure.
