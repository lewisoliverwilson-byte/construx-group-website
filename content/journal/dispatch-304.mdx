Server Actions are async functions that run on the server but can be called from client components as if they were local functions. They replace the fetch-to-API-route pattern for mutations, and they compose cleanly with React's form handling.

```ts
// app/actions/posts.ts
'use server';

import { z } from 'zod';
import { revalidatePath } from 'next/cache';
import { db } from '@/lib/db';
import { posts } from '@/lib/schema';
import { getSession } from '@/lib/auth';

const createPostSchema = z.object({
  title: z.string().min(3).max(120),
  content: z.string().min(20),
  tag: z.enum(['Build Log', 'Strategy', 'Product', 'Methodology', 'Process']),
});

export async function createPost(formData: FormData) {
  const session = await getSession();
  if (!session) throw new Error('Unauthorized');

  const parsed = createPostSchema.safeParse({
    title: formData.get('title'),
    content: formData.get('content'),
    tag: formData.get('tag'),
  });

  if (!parsed.success) {
    return { error: parsed.error.flatten().fieldErrors };
  }

  await db.insert(posts).values({
    ...parsed.data,
    authorId: session.userId,
    slug: slugify(parsed.data.title),
  });

  revalidatePath('/journal');
  return { success: true };
}
```

The `'use server'` directive at the top of the file marks every export as a Server Action. Alternatively, add `'use server'` inside an individual function.

## Using actions in forms

The simplest usage: pass the action directly to a `<form>`:

```tsx
// components/CreatePostForm.tsx
'use client';

import { useActionState } from 'react';
import { createPost } from '@/app/actions/posts';

export default function CreatePostForm() {
  const [state, formAction, pending] = useActionState(createPost, null);

  return (
    <form action={formAction}>
      <input name="title" type="text" placeholder="Post title" required />
      <textarea name="content" placeholder="Content" required />
      <select name="tag">
        <option value="Build Log">Build Log</option>
        <option value="Strategy">Strategy</option>
      </select>
      {state?.error && (
        <div className="error">
          {Object.entries(state.error).map(([field, errors]) => (
            <p key={field}>{field}: {errors?.join(', ')}</p>
          ))}
        </div>
      )}
      <button type="submit" disabled={pending}>
        {pending ? 'Creating...' : 'Create post'}
      </button>
    </form>
  );
}
```

`useActionState` manages the pending state and the return value from the action. The form submits without JavaScript if JS is unavailable — progressive enhancement built in.

## Optimistic updates

For mutations where you want the UI to update immediately before the server confirms:

```tsx
'use client';

import { useOptimistic, useTransition } from 'react';
import { toggleLike } from '@/app/actions/likes';

interface Props {
  postId: string;
  initialLikes: number;
  initialLiked: boolean;
}

export default function LikeButton({ postId, initialLikes, initialLiked }: Props) {
  const [isPending, startTransition] = useTransition();
  const [optimisticState, setOptimistic] = useOptimistic(
    { likes: initialLikes, liked: initialLiked },
    (current, action: 'like' | 'unlike') => ({
      likes: action === 'like' ? current.likes + 1 : current.likes - 1,
      liked: action === 'like',
    })
  );

  const handleClick = () => {
    startTransition(async () => {
      setOptimistic(optimisticState.liked ? 'unlike' : 'like');
      await toggleLike(postId);
    });
  };

  return (
    <button onClick={handleClick} disabled={isPending}>
      {optimisticState.liked ? '♥' : '♡'} {optimisticState.likes}
    </button>
  );
}
```

`useOptimistic` takes the current state and an update function. When the action is dispatched, the optimistic state updates immediately; if the server action throws, the UI reverts.

## Error handling

Server Actions throw errors the same way any async function does. Two patterns for handling them on the client:

**Return errors from the action** (for validation errors):

```ts
export async function updateProfile(data: FormData) {
  // ...validation...
  if (!parsed.success) {
    return { error: 'Validation failed', fields: parsed.error.flatten().fieldErrors };
  }
  // ...mutation...
  return { success: true };
}
```

**Throw errors for unexpected failures** (for auth failures, DB errors):

```ts
export async function deletePost(id: string) {
  const session = await getSession();
  if (!session) throw new Error('Unauthorized'); // Caught by error boundary

  await db.delete(posts).where(eq(posts.id, id));
  revalidatePath('/journal');
}
```

Thrown errors bubble to the nearest error boundary. Returned errors stay local to the action caller.

## Calling actions outside forms

Actions are just async functions. You can call them directly in event handlers:

```tsx
import { archivePost } from '@/app/actions/posts';

export default function PostActions({ postId }: { postId: string }) {
  return (
    <button
      onClick={async () => {
        await archivePost(postId);
      }}
    >
      Archive
    </button>
  );
}
```

No `useActionState` needed when you don't care about the return value and don't need progressive enhancement.

## What replaces what

Server Actions replace fetch calls to API routes for mutations. They don't replace API routes for everything — external API consumers, webhook handlers, SSE endpoints, and anything that needs custom headers or status codes still needs `route.ts`. The pattern is: mutations from your own UI go to Server Actions; everything else goes through route handlers.
