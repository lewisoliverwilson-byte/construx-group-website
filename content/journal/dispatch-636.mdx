npm and Yarn hoist all packages into a flat `node_modules`. This means you can `require('some-unlisted-package')` and it works — if some other package happens to install it. pnpm fixes this. It creates a virtualised `node_modules` where only your declared dependencies are accessible. Phantom dependencies become build errors.

## Installation

```bash
npm install -g pnpm

# Or with corepack (Node.js built-in)
corepack enable
corepack prepare pnpm@latest --activate
```

## Basic usage

```bash
pnpm install               # install dependencies
pnpm add react             # add a dependency
pnpm add -D typescript     # add a dev dependency
pnpm remove lodash         # remove a package
pnpm update                # update all packages within semver
pnpm update --latest       # update to latest regardless of semver
pnpm run build             # run scripts
pnpm exec tsc              # run a binary from node_modules
pnpm dlx create-next-app   # run a package without installing (like npx)
```

## .npmrc configuration

```ini
; .npmrc
shamefully-hoist=false     ; default — strict isolation
strict-peer-dependencies=true
auto-install-peers=true
prefer-frozen-lockfile=true ; CI: fail if lockfile is out of date
```

`strict-peer-dependencies=true` makes pnpm fail if peer deps aren't met — catches compatibility issues that npm silently ignores.

## Workspaces (monorepo)

```yaml
# pnpm-workspace.yaml
packages:
  - 'apps/*'
  - 'packages/*'
  - 'services/*'
```

```json
// apps/web/package.json
{
  "dependencies": {
    "@construx/ui":   "workspace:*",
    "@construx/types": "workspace:*"
  }
}
```

```bash
pnpm install                        # install all workspaces
pnpm --filter @construx/ui build    # build one package
pnpm --filter ...@construx/ui build # build @construx/ui and its dependents
pnpm -r run build                   # run build in all workspaces
```

`workspace:*` means "the version in this monorepo". When you publish, pnpm replaces it with the real version number automatically.

## The store

```bash
pnpm store path           # location of the global store (usually ~/.pnpm-store)
pnpm store prune          # remove packages not referenced by any project
pnpm store status         # check store integrity
```

Every installed package is a hard link from the store. If five projects use React 19.0.0, there's one copy on disk and five links. `pnpm install` for a new project is often just linking — downloads only what's genuinely missing.

## Patching dependencies

```bash
pnpm patch react-dom       # creates a temporary editable copy
# edit the files
pnpm patch-commit /tmp/react-dom-patch  # apply as a persistent patch
```

The patch is stored in `patches/react-dom@19.0.0.patch` and applied automatically on every install. No need to fork and maintain the package.

## Catalogs: shared dependency versions in monorepos

```yaml
# pnpm-workspace.yaml
packages:
  - 'apps/*'
  - 'packages/*'

catalog:
  react:      '19.0.0'
  typescript: '5.7.0'
  zod:        '3.24.1'
```

```json
// apps/web/package.json
{
  "dependencies": {
    "react":      "catalog:",
    "typescript": "catalog:",
    "zod":        "catalog:"
  }
}
```

`catalog:` pins to the version in the workspace catalog. Update React once in `pnpm-workspace.yaml` and it updates everywhere.

## pnpm vs npm vs Yarn vs Bun

pnpm wins on: disk efficiency, strict dependency isolation, monorepo tooling, large teams where phantom dependencies are a real problem. npm wins on: compatibility — every tool assumes it. Bun wins on: raw install speed (written in Zig, parallel by default). Yarn wins on: Plug'n'Play, zero-installs, if you've already invested in the ecosystem.

For a new TypeScript monorepo, pnpm is the default recommendation. The strict isolation catches real bugs, the workspace protocol is excellent, and the performance is good enough.

## Troubleshooting

```bash
# package resolution issues
pnpm why react           # why is react installed and what depends on it?
pnpm list --depth=3      # show dependency tree

# lockfile issues
pnpm install --force     # ignore lockfile, reinstall everything

# peer dependency warnings
pnpm install --no-strict-peer-dependencies  # temporary workaround
```
