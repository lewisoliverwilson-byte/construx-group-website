React's re-render model is predictable and fast enough. Signals are faster and require a different mental model.

## What signals are

In React:

```tsx
function Counter() {
  const [count, setCount] = useState(0);
  // This entire component re-renders on every count change
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

With signals, `count` is a reactive value. The DOM updates directly when the signal changes — no component re-render:

```tsx
import { signal } from '@preact/signals-react';

const count = signal(0);

function Counter() {
  // Only the <button> text re-renders — not the function
  return <button onClick={() => count.value++}>{count}</button>;
}
```

The subscription is at the template level. Signals bypass React's re-render cycle entirely.

## Preact Signals for React

```bash
npm install @preact/signals-react
```

```tsx
import { signal, computed, effect } from '@preact/signals-react';

// Define signals outside components — they are global reactive values
const firstName = signal('Lewis');
const lastName  = signal('Wilson');
const fullName  = computed(() => `${firstName.value} ${lastName.value}`);

// Side effects that run when signals change
effect(() => {
  console.log(`Name changed to: ${fullName.value}`);
});

function NameDisplay() {
  return (
    <div>
      <p>Hello, {fullName}</p>
      <input value={firstName} onInput={(e) => (firstName.value = e.currentTarget.value)} />
    </div>
  );
}
```

## Jotai: atom-based signals

```bash
npm install jotai
```

```tsx
import { atom, useAtom, useAtomValue } from 'jotai';

const countAtom    = atom(0);
const doubleAtom   = atom((get) => get(countAtom) * 2);
const isEvenAtom   = atom((get) => get(countAtom) % 2 === 0);

function Counter() {
  const [count, setCount] = useAtom(countAtom);
  return <button onClick={() => setCount((c) => c + 1)}>{count}</button>;
}

function DoubleDisplay() {
  // Only re-renders when doubleAtom changes
  const double = useAtomValue(doubleAtom);
  return <p>Double: {double}</p>;
}

// Async atoms — data fetching
const postsAtom = atom(async () => {
  const res = await fetch('/api/posts');
  return res.json();
});
```

## When to use signals vs React state

**Use React useState/useReducer:** Local component state, form inputs, simple interactive components, anything where predictable render cycles matter more than raw performance.

**Use signals (Preact Signals or Jotai):** Global state that many components read, high-frequency updates (cursor position, scroll), derived values that should update without triggering parent re-renders, real-time data feeds.

**Use TanStack Query for:** Server state — anything that comes from an API. Signals are for client-only state.

The majority of React applications do not need signals. The React Compiler (available since 2030) handles most memoization automatically. Reach for signals when you have measured a specific rendering performance problem that the compiler cannot solve.
