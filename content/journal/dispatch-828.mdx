They can directly import server-only modules, read databases, and access secrets — none of that code is included in the client bundle. Client Components use the 'use client' directive and run in the browser with state and event handlers. The split gives you: server rendering for data fetching, client components only where interactivity is needed."

Server Components fetch data. Client Components handle interaction. The boundary is explicit.

## The mental model

```
app/
├── page.tsx            → Server Component (default)
│   ├── Header.tsx      → Server Component (no 'use client')
│   ├── PostList.tsx     → Server Component — reads db directly
│   └── LikeButton.tsx  → Client Component ('use client' — has onClick)
└── layout.tsx          → Server Component (default)
```

Server Components:
- Run only on the server (never sent to browser)
- Can be `async` — `await` database calls directly
- Cannot use `useState`, `useEffect`, event handlers
- Cannot import browser APIs (window, document)

Client Components:
- Run in the browser (hydrated from server HTML)
- Can use all React hooks
- Cannot directly `await` server-only code
- Mark with `'use client'` at the top of the file

## Server Component — direct database access

```tsx
// app/posts/page.tsx — Server Component (no directive)
import { db }     from '@/lib/db';
import { posts }  from '@/db/schema';
import { desc }   from 'drizzle-orm';
import PostCard   from './PostCard';    // Server Component
import LikeButton from './LikeButton'; // Client Component

// No API route needed — query the db directly
export default async function PostsPage() {
  const recentPosts = await db
    .select()
    .from(posts)
    .where(isNotNull(posts.publishedAt))
    .orderBy(desc(posts.publishedAt))
    .limit(10);

  return (
    <main>
      <h1>Recent Posts</h1>
      <ul>
        {recentPosts.map((post) => (
          <li key={post.id}>
            <PostCard post={post} />
            <LikeButton postId={post.id} initialCount={post.likes} />
          </li>
        ))}
      </ul>
    </main>
  );
}
```

## Client Component — interactivity

```tsx
// app/posts/LikeButton.tsx — Client Component
'use client';

import { useState, useTransition } from 'react';
import { incrementLikes }          from '@/app/actions/likes';  // Server Action

export default function LikeButton({ postId, initialCount }: { postId: string; initialCount: number }) {
  const [count, setCount]           = useState(initialCount);
  const [liked, setLiked]           = useState(false);
  const [isPending, startTransition] = useTransition();

  function handleLike() {
    if (liked) return;
    setLiked(true);
    setCount((c) => c + 1);
    startTransition(async () => {
      await incrementLikes(postId);
    });
  }

  return (
    <button onClick={handleLike} disabled={liked || isPending}>
      {liked ? '❤️' : '🤍'} {count}
    </button>
  );
}
```

## Server Actions — mutations from the client

```ts
// app/actions/likes.ts
'use server';

import { db }    from '@/lib/db';
import { posts } from '@/db/schema';
import { eq, sql } from 'drizzle-orm';
import { auth }  from '@/lib/auth';
import { revalidatePath } from 'next/cache';

export async function incrementLikes(postId: string) {
  const session = await auth();
  if (!session) throw new Error('Unauthorized');

  await db
    .update(posts)
    .set({ likes: sql`${posts.likes} + 1` })
    .where(eq(posts.id, postId));

  revalidatePath(`/posts/${postId}`);
}
```

## Streaming with Suspense

```tsx
// app/dashboard/page.tsx
import { Suspense } from 'react';
import OrderList    from './OrderList';
import Analytics    from './Analytics';

export default function DashboardPage() {
  return (
    <div>
      {/* Renders immediately — no data dependency */}
      <h1>Dashboard</h1>

      {/* Streams in when OrderList resolves */}
      <Suspense fallback={<div>Loading orders…</div>}>
        <OrderList />
      </Suspense>

      {/* Streams in independently — doesn't block OrderList */}
      <Suspense fallback={<div>Loading analytics…</div>}>
        <Analytics />
      </Suspense>
    </div>
  );
}
```

Each Suspense boundary resolves independently. Analytics loading slowly doesn't delay the order list.

RSC vs traditional SSR: traditional SSR fetches all data in `getServerSideProps`, renders the full page, sends it, then hydrates everything. RSC fetches data in each component independently, streams HTML as each resolves, and only hydrates the Client Components. The result: faster time-to-first-byte, smaller client bundle, and no prop drilling for server data.
