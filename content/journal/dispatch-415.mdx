Next.js App Router caches aggressively by default. This is great for performance, confusing for debugging, and dangerous if you don't understand what's being cached where. There are four distinct layers.

## 1. Request memoization

Within a single render pass, identical `fetch()` calls are deduplicated:

```ts
// These two fetch calls run in the same render tree
// Next.js only makes one network request
async function getUser(id: string) {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
}

// Called in UserAvatar and UserProfile — only one fetch
const UserAvatar = async ({ id }: { id: string }) => {
  const user = await getUser(id);  // fetch
  return <img src={user.avatar} />;
};

const UserProfile = async ({ id }: { id: string }) => {
  const user = await getUser(id);  // deduplicated — no second fetch
  return <h1>{user.name}</h1>;
};
```

This is per-request, not persistent. It resets on every page visit.

## 2. Data cache (fetch cache)

`fetch()` results are stored in a persistent cache on the server:

```ts
// Cached indefinitely — persists across requests and deployments
fetch('/api/config', { cache: 'force-cache' });

// Not cached — fresh on every request
fetch('/api/live-data', { cache: 'no-store' });

// Cached, but revalidated every 60 seconds
fetch('/api/posts', { next: { revalidate: 60 } });

// Tagged — can be invalidated explicitly
fetch('/api/posts', { next: { tags: ['posts'] } });
```

For non-fetch data sources (Drizzle, Redis, etc.), use `unstable_cache`:

```ts
import { unstable_cache } from 'next/cache';

const getCachedPosts = unstable_cache(
  async () => {
    return db.query.posts.findMany({ orderBy: desc(posts.createdAt) });
  },
  ['posts'],                    // cache key
  { revalidate: 60, tags: ['posts'] },
);

// Called like a normal function — cached
const posts = await getCachedPosts();
```

## 3. Full Route Cache

Statically rendered pages are cached as HTML on the server. These pages are served instantly without running any server code.

```ts
// app/about/page.tsx — no dynamic data = fully static = Full Route Cache
export default function AboutPage() {
  return <div>About</div>;
}

// app/posts/page.tsx — forces dynamic rendering, opts out of Full Route Cache
export const dynamic = 'force-dynamic';

// app/posts/[id]/page.tsx — static params are pre-rendered
export async function generateStaticParams() {
  const posts = await db.query.posts.findMany({ columns: { slug: true } });
  return posts.map((p) => ({ id: p.slug }));
}
```

To opt specific segments out of static rendering:

```ts
// These force dynamic rendering for the route segment
export const dynamic = 'force-dynamic';    // always dynamic
export const revalidate = 0;               // revalidate on every request
```

## 4. Router Cache (client-side)

The browser caches visited route segments in memory. Navigate back to a page? It loads from the client cache, not the server.

```ts
// Duration (as of Next.js 15):
// - Static segments: cached for 5 minutes
// - Dynamic segments: cached for 30 seconds
```

After a mutation, invalidate the router cache:

```ts
'use client';
import { useRouter } from 'next/navigation';

function DeletePost({ postId }: { postId: string }) {
  const router = useRouter();

  async function handleDelete() {
    await fetch(`/api/posts/${postId}`, { method: 'DELETE' });
    router.refresh();  // clears router cache for current page
  }

  return <button onClick={handleDelete}>Delete</button>;
}
```

## On-demand revalidation

The most important caching control: invalidate by tag after a mutation:

```ts
// app/api/posts/route.ts
import { revalidateTag } from 'next/cache';

export async function POST(req: Request) {
  const data = await req.json();
  await db.insert(posts).values(data);

  // Invalidate all cached data tagged 'posts'
  revalidateTag('posts');

  return Response.json({ success: true });
}
```

```ts
// Revalidate a specific path
import { revalidatePath } from 'next/cache';

revalidatePath('/posts');           // revalidate /posts page
revalidatePath('/posts/[id]', 'page');  // revalidate dynamic segment
revalidatePath('/', 'layout');     // revalidate everything under root layout
```

## The mental model

```
Request → Full Route Cache (HTML, if static)
       ↓ (if dynamic)
       → Data Cache (fetch results)
       ↓ (within render pass)
       → Request Memoization (deduplication)

Browser ← Router Cache (client-side segments)
```

Default behaviors:
- `fetch()` without options: **cached** (force-cache)
- Route Handlers: **not cached** by default in Next.js 15
- Server Actions: **never cached**
- Pages without dynamic functions: **statically rendered**

The debugging heuristic: if your data isn't updating, work from the router cache inward. `router.refresh()` → `revalidatePath` → `revalidateTag` → `no-store` on the fetch.
