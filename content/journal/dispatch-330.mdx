Playwright is a browser automation library from Microsoft. It runs Chromium, Firefox, and WebKit, has first-class TypeScript support, and — critically — uses auto-waiting everywhere so you don't have to sprinkle `sleep()` calls to avoid race conditions.

## Setup

```bash
npm install -D @playwright/test
npx playwright install
```

```ts
// playwright.config.ts
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './e2e',
  fullyParallel: true,
  retries: process.env.CI ? 2 : 0,
  workers: process.env.CI ? 1 : undefined,
  reporter: [['html'], ['line']],
  use: {
    baseURL: 'http://localhost:3000',
    trace: 'on-first-retry', // record trace on failure
    screenshot: 'only-on-failure',
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
  ],
  webServer: {
    command: 'npm run dev',
    url: 'http://localhost:3000',
    reuseExistingServer: !process.env.CI,
  },
});
```

The `webServer` config starts your dev server before tests run and reuses it if already running. On CI, always start fresh.

## Basic test structure

```ts
// e2e/journal.spec.ts
import { test, expect } from '@playwright/test';

test.describe('Journal', () => {
  test('shows dispatch list', async ({ page }) => {
    await page.goto('/journal');
    await expect(page.getByRole('heading', { name: 'The Journal' })).toBeVisible();
    await expect(page.locator('[data-testid="dispatch-list"]').first()).toBeVisible();
  });

  test('navigates to a dispatch', async ({ page }) => {
    await page.goto('/journal');
    // Click the first post link
    const firstPost = page.locator('a[href^="/journal/"]').first();
    const title = await firstPost.textContent();
    await firstPost.click();
    // Verify we landed on a post page
    await expect(page.getByRole('article')).toBeVisible();
  });
});
```

## Selector strategy

Playwright queries should use semantic selectors — roles, labels, accessible names — not implementation-specific CSS classes:

```ts
// Good — semantic and resilient
page.getByRole('button', { name: 'Send message' })
page.getByLabel('Email address')
page.getByText('Subscription activated')
page.getByTestId('dispatch-list') // data-testid for non-semantic elements

// Avoid — brittle
page.locator('.font-mono.text-\\[10px\\]')
page.locator('#submit-btn')
```

Add `data-testid` attributes to elements that don't have a natural semantic identity:

```tsx
<ul data-testid="dispatch-list">
  {posts.map((post) => <PostRow key={post.slug} post={post} />)}
</ul>
```

## Form interaction

```ts
test('contact form submits', async ({ page }) => {
  await page.goto('/contact');

  await page.getByLabel('Your name').fill('Test User');
  await page.getByLabel('Email address').fill('test@example.com');
  await page.getByLabel('Message').fill('This is a test message from Playwright.');

  // Intercept the API call to avoid actually sending email
  await page.route('/api/contact', (route) => {
    route.fulfill({ status: 200, body: JSON.stringify({ ok: true }) });
  });

  await page.getByRole('button', { name: 'Send message' }).click();

  // Verify success state
  await expect(page.getByText('Message sent.')).toBeVisible();
});
```

## Authentication in tests

For tests that require a logged-in state, log in once and save the session to disk:

```ts
// e2e/auth.setup.ts
import { test as setup } from '@playwright/test';
import path from 'path';

const authFile = path.join(__dirname, '../.playwright/auth.json');

setup('authenticate', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill(process.env.TEST_USER_EMAIL!);
  await page.getByLabel('Password').fill(process.env.TEST_USER_PASSWORD!);
  await page.getByRole('button', { name: 'Sign in' }).click();
  await page.waitForURL('/dashboard');
  await page.context().storageState({ path: authFile });
});
```

```ts
// playwright.config.ts
projects: [
  {
    name: 'setup',
    testMatch: /.*\.setup\.ts/,
  },
  {
    name: 'authenticated',
    testDir: './e2e/authenticated',
    dependencies: ['setup'],
    use: { storageState: '.playwright/auth.json' },
  },
],
```

## Avoiding flaky tests

The most common cause of flaky tests is waiting for the wrong thing. Use Playwright's assertion-based waiting instead of `waitForTimeout`:

```ts
// Flaky — arbitrary sleep
await page.waitForTimeout(2000);
await expect(page.getByText('Saved')).toBeVisible();

// Correct — wait for the assertion to pass
await expect(page.getByText('Saved')).toBeVisible({ timeout: 5000 });
```

For network-dependent UI updates, wait for the request to complete:

```ts
const [response] = await Promise.all([
  page.waitForResponse('/api/posts'),
  page.getByRole('button', { name: 'Load more' }).click(),
]);
expect(response.status()).toBe(200);
await expect(page.locator('[data-testid="post-card"]')).toHaveCount(40);
```

## Trace viewer

When a test fails in CI, the trace file shows every action, network request, screenshot, and console log in a timeline. Download the trace artifact and open it with:

```bash
npx playwright show-trace trace.zip
```

This makes diagnosing CI-only failures tractable — you can replay the failure step by step and see exactly what the page looked like at each point.
