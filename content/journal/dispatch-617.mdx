A stream is an EventEmitter that produces or consumes data incrementally. Instead of `readFileSync('/large.csv')` which loads 2GB into RAM, you create a readable stream and process chunks as they arrive.

## The four stream types

**Readable**: produces data (file reads, HTTP responses, database cursors)
**Writable**: consumes data (file writes, HTTP requests, process.stdout)
**Duplex**: both readable and writable (TCP sockets)
**Transform**: duplex that modifies data as it passes through (gzip, encryption, JSON parsing)

## pipeline: the safe way to compose streams

```ts
import { pipeline } from 'node:stream/promises';
import { createReadStream, createWriteStream } from 'node:fs';
import { createGzip } from 'node:zlib';

// Compress a file
await pipeline(
  createReadStream('large.csv'),        // readable: reads the file
  createGzip(),                         // transform: compresses chunks
  createWriteStream('large.csv.gz'),    // writable: writes compressed data
);
```

`pipeline` handles error propagation and cleanup — if any stream in the chain errors, all streams are destroyed. Use `pipeline` over `.pipe()` which leaks on error.

## Creating a readable stream

```ts
import { Readable } from 'node:stream';

// From an async generator (cleanest modern API)
async function* generateNumbers(max: number) {
  for (let i = 0; i <= max; i++) {
    yield `${i}\n`;
    await new Promise((r) => setTimeout(r, 10));  // simulate async work
  }
}

const readable = Readable.from(generateNumbers(1000));
```

```ts
// From an array or iterable
const readable = Readable.from(['hello', ' ', 'world']);

// From a Web ReadableStream (Fetch API response body)
const response = await fetch('https://api.example.com/stream');
const readable = Readable.fromWeb(response.body!);
```

## Creating a transform stream

```ts
import { Transform } from 'node:stream';

// CSV line counter
const lineCounter = new Transform({
  transform(chunk: Buffer, _encoding, callback) {
    const text  = chunk.toString('utf8');
    const lines = text.split('\n').length - 1;
    this.push(`${lines} lines in this chunk\n`);
    callback();
  },
  flush(callback) {
    callback();  // called when all input is consumed
  },
});

await pipeline(
  createReadStream('data.csv'),
  lineCounter,
  process.stdout,
);
```

## Streaming HTTP responses in Next.js

```ts
// app/api/stream/route.ts
export async function GET() {
  const encoder = new TextEncoder();

  const stream = new ReadableStream({
    async start(controller) {
      for (let i = 0; i < 10; i++) {
        controller.enqueue(encoder.encode(`data: event ${i}\n\n`));
        await new Promise((r) => setTimeout(r, 200));
      }
      controller.close();
    },
  });

  return new Response(stream, {
    headers: {
      'Content-Type':  'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection':    'keep-alive',
    },
  });
}
```

```ts
// Client-side: consume the stream
const response = await fetch('/api/stream');
const reader   = response.body!.getReader();
const decoder  = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  console.log(decoder.decode(value));
}
```

## Streaming large database results

```ts
// Postgres cursor with pg-cursor — stream rows instead of loading all at once
import Cursor from 'pg-cursor';

async function* streamPosts(client: PoolClient) {
  const cursor = client.query(new Cursor('SELECT * FROM posts ORDER BY created_at'));
  try {
    while (true) {
      const rows = await cursor.read(100);  // read 100 rows at a time
      if (rows.length === 0) break;
      yield* rows;
    }
  } finally {
    await cursor.close();
  }
}

await pipeline(
  Readable.from(streamPosts(client)),
  new Transform({
    objectMode: true,
    transform(row, _, callback) {
      this.push(JSON.stringify(row) + '\n');
      callback();
    },
  }),
  createWriteStream('export.jsonl'),
);
```

`objectMode: true` lets the transform stream pass JavaScript objects instead of Buffers. The stream processes 100 rows at a time — a 10M-row table stays in memory as ~100 rows at any given moment.

## Backpressure

Streams automatically handle backpressure — if the writable can't keep up with the readable, Node.js pauses the readable until the writable drains. `pipeline` manages this automatically.

If you manually pipe with `.write()`, check the return value:

```ts
const ok = writable.write(chunk);
if (!ok) {
  // Backpressure — wait for drain before writing more
  await once(writable, 'drain');
}
```

## Web Streams vs Node.js Streams

Node.js has two stream APIs: the Node.js native `stream` module (older, EventEmitter-based) and the Web Streams API (`ReadableStream`, `WritableStream`, `TransformStream`) which matches browser APIs.

Web Streams are now the standard for edge runtimes and browser-compatible code. Node.js streams are still the right choice for server-side file I/O and legacy integrations. `Readable.fromWeb()` and `Readable.toWeb()` convert between them.
