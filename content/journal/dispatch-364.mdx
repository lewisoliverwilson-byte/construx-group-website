Keyword search finds exact matches. A user searching "budget phone" won't find a document that says "affordable handset" — different words, same concept. Semantic search embeds both query and documents in a vector space where meaning determines proximity. "Budget phone" and "affordable handset" end up close together.

pgvector is a PostgreSQL extension that stores and queries vectors. You get semantic search without running a separate vector database.

## Setup

```bash
# Enable pgvector on your PostgreSQL instance
psql $DATABASE_URL -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

## Schema

```ts
// db/schema.ts
import { pgTable, text, timestamp, index } from 'drizzle-orm/pg-core';
import { customType } from 'drizzle-orm/pg-core';

// Vector custom type for Drizzle
const vector = customType<{ data: number[]; config: { dimensions: number } }>({
  dataType(config) {
    return `vector(${config?.dimensions ?? 1536})`;
  },
  toDriver(value: number[]) {
    return `[${value.join(',')}]`;
  },
  fromDriver(value: string) {
    return value.slice(1, -1).split(',').map(Number);
  },
});

export const posts = pgTable('posts', {
  id: text('id').primaryKey().$defaultFn(() => crypto.randomUUID()),
  title: text('title').notNull(),
  body: text('body').notNull(),
  excerpt: text('excerpt').notNull(),
  embedding: vector('embedding', { dimensions: 1536 }),
  createdAt: timestamp('created_at').notNull().defaultNow(),
}, (t) => ({
  embeddingIdx: index('posts_embedding_idx')
    .using('hnsw', t.embedding.op('vector_cosine_ops')),
}));
```

HNSW (Hierarchical Navigable Small World) is the index type — it's faster than IVFFlat for most workloads. `vector_cosine_ops` means queries use cosine similarity, which is standard for text embeddings.

## Generating embeddings

```ts
// lib/embeddings.ts
import { embed, embedMany } from 'ai';
import { openai } from '@ai-sdk/openai';

const embeddingModel = openai.embedding('text-embedding-3-small');

export async function generateEmbedding(text: string): Promise<number[]> {
  const { embedding } = await embed({
    model: embeddingModel,
    value: text.replace(/\n/g, ' '),  // normalize newlines
  });
  return embedding;
}

export async function generateEmbeddings(texts: string[]): Promise<number[][]> {
  const { embeddings } = await embedMany({
    model: embeddingModel,
    values: texts.map((t) => t.replace(/\n/g, ' ')),
  });
  return embeddings;
}
```

`text-embedding-3-small` produces 1536-dimensional vectors and costs $0.02 per million tokens — cheap enough to embed everything.

## Indexing posts at write time

```ts
// lib/posts.ts
import { db } from '@/db';
import { posts } from '@/db/schema';
import { generateEmbedding } from './embeddings';

export async function indexPost(postId: string) {
  const post = await db.query.posts.findFirst({ where: eq(posts.id, postId) });
  if (!post) return;

  const textToEmbed = `${post.title}\n\n${post.excerpt}\n\n${post.body.slice(0, 2000)}`;
  const embedding = await generateEmbedding(textToEmbed);

  await db.update(posts)
    .set({ embedding })
    .where(eq(posts.id, postId));
}
```

Embed at write time, not at query time. Each document is embedded once and stored. Queries are embedded on the fly.

## Querying by semantic similarity

```ts
// lib/search.ts
import { sql } from 'drizzle-orm';
import { db } from '@/db';
import { posts } from '@/db/schema';
import { generateEmbedding } from './embeddings';

export async function semanticSearch(query: string, limit = 10) {
  const queryEmbedding = await generateEmbedding(query);
  const vectorStr = `[${queryEmbedding.join(',')}]`;

  const results = await db.execute(sql`
    SELECT
      id, title, excerpt,
      1 - (embedding <=> ${vectorStr}::vector) AS similarity
    FROM posts
    WHERE embedding IS NOT NULL
    ORDER BY embedding <=> ${vectorStr}::vector
    LIMIT ${limit}
  `);

  return results.rows as { id: string; title: string; excerpt: string; similarity: number }[];
}
```

The `<=>` operator is cosine distance (lower = more similar). `1 - distance = similarity` where 1 is identical and 0 is unrelated. Filter out results below a similarity threshold (e.g., 0.75) to avoid returning irrelevant results.

## Hybrid search: keyword + semantic

Semantic search alone misses exact keyword matches. Hybrid search combines both:

```ts
export async function hybridSearch(query: string, limit = 10) {
  const embedding = await generateEmbedding(query);
  const vectorStr = `[${embedding.join(',')}]`;

  // Reciprocal Rank Fusion — blend keyword and semantic results
  const results = await db.execute(sql`
    WITH keyword_results AS (
      SELECT id, title, excerpt, ts_rank(search_vector, query) AS score,
             ROW_NUMBER() OVER (ORDER BY ts_rank(search_vector, query) DESC) AS rank
      FROM posts, to_tsquery('english', ${query.split(' ').join(' & ')}) query
      WHERE search_vector @@ query
    ),
    semantic_results AS (
      SELECT id, title, excerpt,
             1 - (embedding <=> ${vectorStr}::vector) AS score,
             ROW_NUMBER() OVER (ORDER BY embedding <=> ${vectorStr}::vector) AS rank
      FROM posts WHERE embedding IS NOT NULL
    ),
    fused AS (
      SELECT
        COALESCE(k.id, s.id) AS id,
        COALESCE(k.title, s.title) AS title,
        COALESCE(k.excerpt, s.excerpt) AS excerpt,
        COALESCE(1.0 / (60 + k.rank), 0) + COALESCE(1.0 / (60 + s.rank), 0) AS rrf_score
      FROM keyword_results k
      FULL OUTER JOIN semantic_results s ON k.id = s.id
    )
    SELECT id, title, excerpt, rrf_score
    FROM fused
    ORDER BY rrf_score DESC
    LIMIT ${limit}
  `);

  return results.rows;
}
```

Reciprocal Rank Fusion is the standard blending algorithm — no hyperparameter tuning required.

## The embedding dimensions trade-off

`text-embedding-3-small`: 1536 dimensions, fastest, cheapest.
`text-embedding-3-large`: 3072 dimensions, better quality, 2x cost, 2x storage.

For most retrieval tasks, small is sufficient. Use large when ranking accuracy is critical (legal discovery, medical record search).

You can also reduce dimensions to 512 or 256 — OpenAI's third-generation models support Matryoshka representation learning, where you can truncate vectors without catastrophic quality loss.
