Supabase wraps Postgres with the ergonomics of a BaaS (Backend-as-a-Service) without locking you into a proprietary database. The underlying Postgres instance is accessible via direct connection — you can use Prisma, Drizzle, or raw SQL alongside the Supabase client.

## Setup

```bash
npm install @supabase/supabase-js

# Or with local development
npx supabase init
npx supabase start  # starts Postgres, GoTrue, PostgREST, Realtime locally
```

```ts
// lib/supabase.ts
import { createClient } from '@supabase/supabase-js';
import type { Database } from './database.types';  // generated types

export const supabase = createClient<Database>(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
);

// Server-side client with service role (bypasses RLS)
export const supabaseAdmin = createClient<Database>(
  process.env.SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!,
);
```

## TypeScript types from the schema

```bash
# Generate TypeScript types from your database schema
npx supabase gen types typescript --project-id your-project-id > lib/database.types.ts
```

The generated types give you full type safety on all queries:

```ts
const { data: posts, error } = await supabase
  .from('posts')          // type-safe table name
  .select('id, title, created_at, author:users(name, email)')  // typed select
  .eq('status', 'published')
  .order('created_at', { ascending: false })
  .limit(10);

// posts is Post[] | null, with correct types
// posts[0].author.name is string
```

## Authentication

```ts
// Sign up
const { data, error } = await supabase.auth.signUp({
  email:    'lewis@construxgroup.io',
  password: 'securepassword',
  options: {
    data: { username: 'lewis' },  // stored in raw_user_meta_data
  },
});

// Sign in
const { data: session } = await supabase.auth.signInWithPassword({
  email:    'lewis@construxgroup.io',
  password: 'securepassword',
});

// OAuth (Google, GitHub, etc.)
await supabase.auth.signInWithOAuth({
  provider: 'github',
  options:  { redirectTo: 'https://construxgroup.io/auth/callback' },
});

// Current user
const { data: { user } } = await supabase.auth.getUser();

// Sign out
await supabase.auth.signOut();
```

## Next.js Server Components integration

```ts
// lib/supabase-server.ts
import { createServerClient } from '@supabase/ssr';
import { cookies } from 'next/headers';
import type { Database } from './database.types';

export async function createSupabaseServer() {
  const cookieStore = await cookies();
  return createServerClient<Database>(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll:    () => cookieStore.getAll(),
        setAll:    (cs) => cs.forEach(({ name, value, options }) => cookieStore.set(name, value, options)),
      },
    },
  );
}

// app/posts/page.tsx
export default async function PostsPage() {
  const supabase = await createSupabaseServer();
  const { data: posts } = await supabase.from('posts').select('*').eq('status', 'published');

  return <PostList posts={posts ?? []} />;
}
```

## Real-time subscriptions

```ts
// Subscribe to changes in the posts table
const subscription = supabase
  .channel('posts-changes')
  .on(
    'postgres_changes',
    { event: '*', schema: 'public', table: 'posts' },
    (payload) => {
      if (payload.eventType === 'INSERT') {
        setPosts((prev) => [payload.new as Post, ...prev]);
      }
      if (payload.eventType === 'DELETE') {
        setPosts((prev) => prev.filter((p) => p.id !== payload.old.id));
      }
    },
  )
  .subscribe();

// Cleanup
return () => supabase.removeChannel(subscription);
```

Real-time uses Postgres logical replication internally. You can subscribe to specific rows (`filter: 'user_id=eq.${userId}'`), specific columns, or the entire table.

const { data, error } = await supabase.storage

## Row Level Security with Supabase auth

```sql
-- Posts are readable by everyone, writable only by the author
ALTER TABLE posts ENABLE ROW LEVEL SECURITY;

CREATE POLICY "public can read published posts"
  ON posts FOR SELECT
  USING (status = 'published');

CREATE POLICY "users can manage their own posts"
  ON posts FOR ALL
  USING (auth.uid() = author_id)
  WITH CHECK (auth.uid() = author_id);
```

`auth.uid()` returns the ID of the authenticated user from the JWT. This is the key integration point — Supabase's auth system and RLS work together so users can only access their own data, without any application-level filtering.

## Supabase vs Prisma + managed Postgres

Use Supabase when: you want built-in auth, real-time, and storage alongside your database, you're building quickly and want a single platform, or you need row-level security tied to authenticated users.

Use Prisma + Neon/PlanetScale when: you want more control over your ORM, you're already invested in the Prisma ecosystem, or you need features Supabase doesn't expose (complex Prisma generators, Prisma Pulse).

The two aren't mutually exclusive — you can use Prisma against a Supabase Postgres instance for ORM queries while using the Supabase client for auth and storage.
