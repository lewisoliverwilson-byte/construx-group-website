title: "Qdrant: vector database for semantic search and RAG pipelines"
date: "2033-03-17"
excerpt: "Qdrant is a vector database written in Rust, purpose-built for storing and querying high-dimensional vector embeddings. Unlike pgvector (which adds vector search to Postgres), Qdrant is dedicated infrastructure with HNSW (Hierarchical Navigable Small World) indexing that scales to hundreds of millions of vectors without the performance characteristics of a general-purpose database. The use case: store document embeddings generated by Claude/OpenAI, query by semantic similarity ('find documents similar to this query'), and combine with metadata filters ('only documents from last month, tagged infrastructure'). Qdrant's payload filtering runs before the vector search — 'filter by tag, then find nearest neighbors' is efficient because the vector index operates on the pre-filtered subset."

## Collection setup and indexing

```bash
# Install Qdrant
docker run -d \
  --name qdrant \
  -p 6333:6333 \
  -p 6334:6334 \   # gRPC
  -v $PWD/qdrant_storage:/qdrant/storage \
  qdrant/qdrant

# Or deploy on Kubernetes
helm repo add qdrant https://qdrant.github.io/qdrant-helm
helm upgrade --install qdrant qdrant/qdrant \
  --namespace vector-db \
  -f qdrant-values.yaml

# Create a collection: define vector dimensions and distance metric
curl -X PUT http://localhost:6333/collections/construx-docs \
  -H "Content-Type: application/json" \
  -d '{
    "vectors": {
      "size": 1536,               # OpenAI text-embedding-3-small: 1536 dims
      "distance": "Cosine"        # Cosine similarity (1 - cosine distance)
    },
    "optimizers_config": {
      "default_segment_number": 4  # parallelism in query execution
    },
    "hnsw_config": {
      "m": 16,            # number of connections per node (higher = better recall, more RAM)
      "ef_construct": 100 # construction time (higher = better index quality, slower build)
    }
  }'

# Collection with multiple named vectors (e.g., title + body + summary embeddings)
curl -X PUT http://localhost:6333/collections/construx-docs-multi \
  -H "Content-Type: application/json" \
  -d '{
    "vectors": {
      "title": { "size": 1536, "distance": "Cosine" },
      "body":  { "size": 1536, "distance": "Cosine" },
      "sparse": {
        "index": { "on_disk": false }
      }
    }
  }'
```

## Inserting documents with payloads

```go
package vectordb

import (
  "context"
  pb "github.com/qdrant/go-client/qdrant"
  "google.golang.org/grpc"
)

type Document struct {
  ID      string
  Title   string
  Content string
  Tag     string
  Date    string
}

func IndexDocuments(ctx context.Context, client pb.PointsClient, docs []Document, embedFn func(string) ([]float32, error)) error {
  points := make([]*pb.PointStruct, 0, len(docs))

  for _, doc := range docs {
    // Generate embedding for the document content
    vec, err := embedFn(doc.Title + "\n" + doc.Content)
    if err != nil {
      return err
    }

    point := &pb.PointStruct{
      Id: &pb.PointId{
        PointIdOptions: &pb.PointId_Uuid{Uuid: doc.ID},
      },
      Vectors: &pb.Vectors{
        VectorsOptions: &pb.Vectors_Vector{
          Vector: &pb.Vector{Data: vec},
        },
      },
      Payload: map[string]*pb.Value{
        "title": {Kind: &pb.Value_StringValue{StringValue: doc.Title}},
        "tag":   {Kind: &pb.Value_StringValue{StringValue: doc.Tag}},
        "date":  {Kind: &pb.Value_StringValue{StringValue: doc.Date}},
        "chars": {Kind: &pb.Value_IntegerValue{IntegerValue: int64(len(doc.Content))}},
      },
    }
    points = append(points, point)
  }

  // Batch upsert (idempotent — safe to re-run)
  _, err := client.Upsert(ctx, &pb.UpsertPoints{
    CollectionName: "construx-docs",
    Points:         points,
    Wait:           proto.Bool(true),
  })
  return err
}
```

## Semantic search with payload filtering

```bash
# Search: find 5 documents similar to a query, filtered by tag
# The payload filter runs BEFORE vector search (efficient)

curl -X POST http://localhost:6333/collections/construx-docs/points/search \
  -H "Content-Type: application/json" \
  -d '{
    "vector": [0.12, -0.34, 0.56, ...],    # embed the query first
    "limit": 5,
    "filter": {
      "must": [
        {
          "key": "tag",
          "match": { "value": "Build Log" }
        },
        {
          "key": "date",
          "range": {
            "gte": "2033-01-01",
            "lte": "2033-03-17"
          }
        }
      ]
    },
    "with_payload": true,
```

## RAG pipeline: retrieval-augmented generation

```go
// Full RAG pipeline: embed query → retrieve docs → generate answer
package rag

import (
  "context"
  "fmt"
  "github.com/anthropics/anthropic-sdk-go"
)

type RAGPipeline struct {
  qdrant    *QdrantClient
  anthropic *anthropic.Client
}

func (r *RAGPipeline) Answer(ctx context.Context, userQuery string) (string, error) {
  // 1. Embed the user query
  queryVec, err := r.embed(ctx, userQuery)
  if err != nil {
    return "", fmt.Errorf("embed query: %w", err)
  }

  // 2. Retrieve relevant documents from Qdrant
  results, err := r.qdrant.Search(ctx, "construx-docs", queryVec, 5,
    Filter{Tag: "Build Log"},  // only search Build Log entries
  )
  if err != nil {
    return "", fmt.Errorf("vector search: %w", err)
  }

  // 3. Build context from retrieved documents
  var contextDocs string
  for i, doc := range results {
    contextDocs += fmt.Sprintf("Document %d (similarity: %.2f):\nTitle: %s\nContent: %s\n\n",
      i+1, doc.Score, doc.Title, doc.Excerpt)
  }

  // 4. Generate answer with Claude
  msg, err := r.anthropic.Messages.New(ctx, anthropic.MessageNewParams{
    Model:     anthropic.F(anthropic.ModelClaudeSonnet46),
    MaxTokens: anthropic.F(int64(1024)),
    Messages: anthropic.F([]anthropic.MessageParam{
      anthropic.NewUserMessage(anthropic.NewTextBlock(
        fmt.Sprintf(`Based on these documents from the Construx journal, answer the question.

Documents:
%s

Question: %s

Answer based only on the documents provided. If the answer isn't in the documents, say so.`, contextDocs, userQuery),
      )),
    }),
  })
  if err != nil {
    return "", fmt.Errorf("claude generate: %w", err)
  }

  return msg.Content[0].Text, nil
}

// Usage:
// answer, err := pipeline.Answer(ctx, "How does Linkerd handle mTLS certificate rotation?")
// → Claude answers using the 5 most relevant journal entries
```

## Hybrid search: dense + sparse vectors

```bash
# Hybrid search: combine semantic similarity with keyword matching
# Dense vectors: semantic meaning (good for "what is this about?")
# Sparse vectors: exact keyword matches (good for "does this mention 'HNSW'?")

# Generate sparse vector from a query (BM25 or SPLADE)
# Using Qdrant's built-in sparse vector support:

curl -X POST http://localhost:6333/collections/construx-docs-multi/points/search \
  -H "Content-Type: application/json" \
  -d '{
    "vector": {
      "name": "body",
      "vector": [0.12, -0.34, 0.56, ...]
    },
    "limit": 10,
    "with_payload": true
  }'

# Fusion search: combine dense search results with sparse results
# (ReciprocalRankFusion)
curl -X POST http://localhost:6333/collections/construx-docs-multi/points/query \
  -H "Content-Type: application/json" \
  -d '{
    "prefetch": [
      {
        "query": { "nearest": { "dense": [0.12, -0.34, 0.56, ...] } },
        "using": "body",
        "limit": 20
      },
      {
        "query": {
          "nearest": {
            "sparse": {
              "indices": [42, 847, 1923],
              "values":  [0.8, 0.6, 0.4]
            }
          }
        },
        "using": "sparse",
        "limit": 20
      }
    ],
    "query": { "fusion": "rrf" },
    "limit": 5
  }'
```

Qdrant vs pgvector vs Pinecone vs Weaviate: pgvector is the right default for teams already on Postgres who need vector search at moderate scale (< 10M vectors) — no new infrastructure, existing Postgres tooling applies, and pg_embedding with HNSW now rivals dedicated vector DBs at small scale. Qdrant and Weaviate are purpose-built and scale better for large collections (> 50M vectors) with better ANN performance and more filtering flexibility. Pinecone is fully managed with no infrastructure to run, making it the fastest path to production but at higher cost per query at scale. Qdrant's Rust implementation and payload filtering architecture make it the best pure-performance choice for self-hosted vector search. For RAG pipelines where you want hybrid search (semantic + keyword), Qdrant's sparse vector support and query fusion are further ahead than pgvector as of 2033.
