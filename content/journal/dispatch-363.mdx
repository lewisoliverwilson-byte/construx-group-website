Images account for more than 50% of the bytes on a typical web page. Getting image optimization right has a direct effect on Core Web Vitals, bandwidth costs, and user experience — especially on mobile.

Next.js's `Image` component handles format conversion (WebP/AVIF), responsive sizing, lazy loading, and cache headers automatically. But it requires understanding how it works to use it correctly.

## The basics

```tsx
import Image from 'next/image';

// Local image — dimensions are inferred at build time
import heroImage from '@/public/images/hero.jpg';

<Image
  src={heroImage}
  alt="Construx Group headquarters"
  priority  // above-the-fold: load immediately (LCP element)
/>

// Remote image — dimensions required
<Image
  src="https://cdn.construxgroup.io/products/scanner-ui.png"
  alt="Scoutr scanner interface"
  width={1200}
  height={675}
/>
```

For local images, TypeScript import gives you the dimensions automatically. For remote images, you must specify `width` and `height` to prevent layout shift.

## Responsive images

```tsx
// Fills its container — responsive by nature
<div className="relative aspect-video w-full">
  <Image
    src={image}
    alt="Product screenshot"
    fill
    sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
    className="object-cover"
  />
</div>
```

The `sizes` prop is critical for performance. It tells the browser what viewport width the image will occupy at each breakpoint, so it can request the smallest appropriate source. Without it, the browser always requests a large image.

The `sizes` string maps to `srcset` entries that Next.js generates. "At 768px and below, this image is 100% of the viewport width" → the browser requests an image sized for 100vw.

## Priority and lazy loading

```tsx
// Above the fold — always use priority
<Image src={hero} alt="Hero" priority />

// Below the fold — lazy load (default)
<Image src={card} alt="Card" />

// Eager-load for critical images without preload
<Image src={header} alt="Header" loading="eager" />
```

`priority` adds a `<link rel="preload">` tag in the `<head>` and removes lazy loading. Use it for your LCP image — typically the hero image or the first image in a list. Using `priority` on too many images defeats the purpose.

## Remote image domains

```ts
// next.config.ts
const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'cdn.construxgroup.io',
        port: '',
        pathname: '/**',
      },
      {
        protocol: 'https',
        hostname: '*.amazonaws.com',
        pathname: '/construx-assets/**',
      },
    ],
  },
};
```

Wildcards in hostnames (`*.amazonaws.com`) are supported. Never use `domains: ['**']` — it's a security issue that allows Next.js to proxy arbitrary external images.

## Format configuration

```ts
const nextConfig: NextConfig = {
  images: {
    formats: ['image/avif', 'image/webp'],
    // Next.js tries AVIF first, falls back to WebP, then original format
    // AVIF is ~50% smaller than WebP for the same quality
    // But AVIF encoding is slow — enable if your server can handle it
  },
};
```

AVIF saves bandwidth but requires more CPU to encode. On Vercel and Amplify, image optimization happens at the CDN edge with cached results — encoding cost is paid once per image per size per format.

## Generating blur placeholders

```tsx
// Dynamic blur placeholder for remote images
import { getPlaiceholder } from 'plaiceholder';

export async function getImageBlur(src: string) {
  const { base64 } = await getPlaiceholder(src);
  return base64;
}

// Usage
const blurDataURL = await getImageBlur(imageUrl);

<Image
  src={imageUrl}
  alt="Product"
  width={800}
  height={450}
  placeholder="blur"
  blurDataURL={blurDataURL}
/>
```

The blur placeholder prevents layout shift and gives users immediate visual feedback while the image loads.

## Handling user-uploaded images

For user-generated content, images come from your storage bucket. Proxy them through Next.js Image:

```ts
// next.config.ts
images: {
  remotePatterns: [
    {
      protocol: 'https',
      hostname: 'your-bucket.s3.eu-west-2.amazonaws.com',
    },
  ],
},
```

```tsx
// In a component
const userAvatarUrl = user.avatarKey
  ? `https://your-bucket.s3.eu-west-2.amazonaws.com/${user.avatarKey}`
  : null;

{userAvatarUrl && (
  <Image
    src={userAvatarUrl}
    alt={user.name}
    width={40}
    height={40}
    className="rounded-full"
  />
)}
```

## Custom loader for external CDN

If you use Cloudflare Images or a custom image CDN:

```ts
// lib/imageLoader.ts
export default function cloudflareLoader({ src, width, quality }: {
  src: string;
  width: number;
  quality?: number;
}) {
  const params = [`width=${width}`, `quality=${quality ?? 75}`, 'format=auto'];
  return `https://images.construxgroup.io/cdn-cgi/image/${params.join(',')}/${src}`;
}
```

```tsx
// next.config.ts
const nextConfig: NextConfig = {
  images: {
    loader: 'custom',
    loaderFile: './lib/imageLoader.ts',
  },
};
```

## Common mistakes

**Not specifying sizes**: without `sizes`, every image requests a 1080px+ version regardless of where it's displayed.

**Priority on everything**: defeats lazy loading, increases Time to Interactive.

**Using `<img>` instead of `<Image>`**: no optimization, no lazy loading, no format conversion.

**Fixed width without `srcset`**: a 200px wide avatar should never request a 1200px image.

**Missing alt text**: accessibility failure and SEO damage.

The payoff for getting this right: a 40–70% reduction in image payload for most sites, which translates directly to LCP improvements.
