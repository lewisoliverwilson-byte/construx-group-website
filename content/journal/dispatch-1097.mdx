date: "2033-12-18"
excerpt: "Kyverno is a Kubernetes-native policy engine that operates as an admission controller — it intercepts every API request to the Kubernetes API server and applies policies before the object is persisted to etcd. Kyverno policies are written as Kubernetes resources (no Rego, no external DSL), making them readable and maintainable by anyone who knows Kubernetes YAML. Policies have four capabilities: validate (block or audit non-compliant resources — e.g., reject pods without resource limits), mutate (automatically modify incoming resources — e.g., add default labels or inject sidecars), generate (create related resources automatically — e.g., create a NetworkPolicy whenever a new Namespace is created), and verify images (enforce that container images are signed by a trusted key using cosign/Sigstore). Kyverno's policy reports surface compliance status across the existing cluster (not just new admissions) — you can scan all existing Deployments against a policy and see which ones would be blocked. At Construx, Kyverno enforces resource limits on all pods, requires specific labels for cost tracking, blocks images from untrusted registries, and verifies that all container images have a valid cosign signature from the internal CI pipeline before they can be deployed to production."

## Policy examples: validate, mutate, generate, image verify

```yaml
# Kyverno ClusterPolicy: require resource limits on all pods
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-resource-limits
  annotations:
    policies.kyverno.io/title: Require Resource Limits
    policies.kyverno.io/severity: medium
spec:
  validationFailureAction: Enforce   # Enforce (block) or Audit (log only)
  background: true                   # also scan existing resources
  rules:
    - name: validate-cpu-memory-limits
      match:
        any:
          - resources:
              kinds: [Pod]
              namespaces: ["construx-prod", "construx-staging"]
      validate:
        message: "All containers must have CPU and memory limits defined."
        pattern:
          spec:
            containers:
              - name: "*"
                resources:
                  limits:
                    cpu: "?*"        # must be non-empty
                    memory: "?*"

---
# Kyverno ClusterPolicy: mutate — inject cost-tracking labels
# Automatically adds billing labels to pods missing them
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: add-billing-labels
spec:
  rules:
    - name: add-tenant-label
      match:
        any:
          - resources:
              kinds: [Pod]
              namespaces: ["construx-prod"]
      mutate:
        patchStrategicMerge:
          metadata:
            labels:
              +(billing.construx.io/team): "platform"
              +(billing.construx.io/environment): "production"
        spec:
          containers:
            - (name): "*"
              env:
                - +(name): CONSTRUX_BILLING_TEAM
                  value: "platform"

---
# Kyverno ClusterPolicy: generate — create default NetworkPolicy on namespace creation
# Every new namespace automatically gets a deny-all NetworkPolicy
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: generate-default-networkpolicy
spec:
  rules:
    - name: default-deny-all
      match:
        any:
          - resources:
              kinds: [Namespace]
      generate:
        apiVersion: networking.k8s.io/v1
        kind: NetworkPolicy
        name: default-deny-all
        namespace: "{{request.object.metadata.name}}"
        synchronize: true   # keep in sync — if manually deleted, recreate
        data:
          spec:
            podSelector: {}
            policyTypes: [Ingress, Egress]
            # Empty = deny all; services must add explicit allow policies

---
# Kyverno ClusterPolicy: image verification using cosign/Sigstore
# Block any image not signed by the Construx CI pipeline key
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: verify-image-signatures
spec:
  validationFailureAction: Enforce
  background: false
  rules:
    - name: verify-construx-images
      match:
        any:
          - resources:
              kinds: [Pod]
              namespaces: ["construx-prod"]
      verifyImages:
        - imageReferences:
            - "registry.construx.internal/*"
          attestors:
            - count: 1
              entries:
                - keys:
                    publicKeys: |-
                      -----BEGIN PUBLIC KEY-----
                      MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE...
                      -----END PUBLIC KEY-----
                    signatureAlgorithm: ECDSA-P256
          mutateDigest: true    # pin image to digest after verification
          verifyDigest: true
```

## PolicyReport and compliance scanning

```bash
# Kyverno generates PolicyReport resources after background scanning

# View policy violations for all pods in production
kubectl get policyreport -n construx-prod -o json | \
  jq '.items[].results[] | select(.result=="fail") | {policy: .policy, resource: .resources[].name, message: .message}'

# Example output:
# {
#   "policy": "require-resource-limits",
#   "resource": "legacy-job-processor-7f8c9d-x1m2",
#   "message": "All containers must have CPU and memory limits defined."
# }

# Cluster-wide policy report summary
kubectl get clusterpolicyreport -o json | jq '.items[].summary'
# { "pass": 847, "fail": 3, "warn": 0, "error": 0, "skip": 12 }

# Test a policy against a manifest before applying
kubectl apply -f deployment.yaml --dry-run=server
# Error from server: admission webhook "validate.kyverno.svc-fail" denied the request:
# require-resource-limits: validation error: All containers must have CPU and memory limits.
#   rule validate-cpu-memory-limits failed at path /spec/containers/0/resources/limits/

# Install Kyverno via Helm
helm repo add kyverno https://kyverno.github.io/kyverno/
helm install kyverno kyverno/kyverno -n kyverno --create-namespace \
  --set replicaCount=3 \
  --set admissionController.replicas=3 \
  --set backgroundController.replicas=2 \
  --set cleanupController.replicas=1 \
  --set reportsController.replicas=1

# Apply policies from a directory
kubectl apply -f policies/
```

Kyverno vs OPA Gatekeeper vs Pod Security Admission vs manual admission webhooks: OPA Gatekeeper (dispatch-1074) uses Rego — a purpose-built policy language that is powerful but requires learning a new paradigm. Kyverno uses YAML with JMESPath expressions — anyone who knows Kubernetes can write a Kyverno policy. Pod Security Admission (PSA) is the built-in Kubernetes mechanism for enforcing Pod Security Standards (privileged/baseline/restricted) — it covers security posture but has no mutation capability and cannot enforce custom organisational policies like resource limits or label requirements. Manual admission webhooks (a custom Go or Python server) give you maximum flexibility but require building and operating a webhook service. Kyverno's mutation and generate capabilities are its strongest differentiator from Gatekeeper — you can use Kyverno to actively fix non-compliant resources (mutation) and to enforce that namespace creation always produces companion resources (NetworkPolicy, ResourceQuota, LimitRange) atomically. For teams that want policy-as-code without learning Rego, Kyverno is the practical choice.
