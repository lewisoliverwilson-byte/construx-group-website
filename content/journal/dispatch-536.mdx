A webhook endpoint with no signature verification accepts POST requests from anyone on the internet. An attacker who knows your endpoint URL can send a fake `checkout.session.completed` event and unlock paid features without paying. Every webhook from a production service (Stripe, GitHub, Clerk, Resend) includes a signature — verify it.

## How HMAC signatures work

The sender computes `HMAC-SHA256(secret, payload)` and includes the result in a header. The receiver does the same computation with the same secret and compares the result. If they match, the payload is authentic. If the secret is only known to you and the sender, nobody else can forge a valid signature.

## Stripe webhook verification

```ts
// app/api/webhooks/stripe/route.ts
import Stripe from 'stripe';

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);
const secret = process.env.STRIPE_WEBHOOK_SECRET!;

export async function POST(req: Request) {
  const body      = await req.text();   // Must read as text, not JSON
  const sig       = req.headers.get('stripe-signature');

  if (!sig) {
    return Response.json({ error: 'No signature' }, { status: 400 });
  }

  let event: Stripe.Event;
  try {
    // Stripe computes HMAC-SHA256 and checks timestamp to prevent replay attacks
    event = stripe.webhooks.constructEvent(body, sig, secret);
  } catch (err) {
    return Response.json({ error: 'Invalid signature' }, { status: 400 });
  }

  // Now safe to trust the event
  switch (event.type) {
    case 'checkout.session.completed':
      await handleCheckout(event.data.object as Stripe.Checkout.Session);
      break;
  }

  return Response.json({ received: true });
}
```

`constructEvent` also checks the timestamp in the signature — Stripe includes a `t=` timestamp and rejects events older than 5 minutes by default, preventing replay attacks.

## GitHub webhook verification

```ts
// app/api/webhooks/github/route.ts
export async function POST(req: Request) {
  const body      = await req.text();
  const sig       = req.headers.get('x-hub-signature-256');
  const secret    = process.env.GITHUB_WEBHOOK_SECRET!;

  if (!sig) {
    return Response.json({ error: 'No signature' }, { status: 400 });
  }

  const expected = await computeHmac(secret, body);

  if (!timingSafeEqual(sig, `sha256=${expected}`)) {
    return Response.json({ error: 'Invalid signature' }, { status: 401 });
  }

  const payload = JSON.parse(body);
  const event   = req.headers.get('x-github-event');

  if (event === 'push') {
    await handlePush(payload);
  }

  return Response.json({ ok: true });
}

async function computeHmac(secret: string, body: string): Promise<string> {
  const encoder = new TextEncoder();
  const key = await crypto.subtle.importKey(
    'raw',
    encoder.encode(secret),
    { name: 'HMAC', hash: 'SHA-256' },
    false,
    ['sign'],
  );
  const sig = await crypto.subtle.sign('HMAC', key, encoder.encode(body));
  return Array.from(new Uint8Array(sig)).map((b) => b.toString(16).padStart(2, '0')).join('');
}

function timingSafeEqual(a: string, b: string): boolean {
  if (a.length !== b.length) return false;
  let diff = 0;
  for (let i = 0; i < a.length; i++) {
    diff |= a.charCodeAt(i) ^ b.charCodeAt(i);
  }
  return diff === 0;
}
```

**Why timing-safe comparison?** A naive `a === b` returns early on the first character mismatch, leaking timing information that an attacker can use to iteratively guess the correct signature. `timingSafeEqual` always takes the same amount of time regardless of where the strings differ.

## Rolling your own signature verification

For your own webhooks sent to other services:

```ts
// lib/webhooks.ts — sign outgoing webhooks
export async function signPayload(payload: string, secret: string): Promise<string> {
  const encoder = new TextEncoder();
  const key = await crypto.subtle.importKey(
    'raw',
    encoder.encode(secret),
    { name: 'HMAC', hash: 'SHA-256' },
    false,
    ['sign'],
  );
  const sig = await crypto.subtle.sign('HMAC', key, encoder.encode(payload));
  return `sha256=${Buffer.from(sig).toString('hex')}`;
}

// When sending a webhook:
const body = JSON.stringify({ event: 'order.completed', orderId: '123' });
const signature = await signPayload(body, process.env.WEBHOOK_SECRET!);

await fetch(partnerWebhookUrl, {
  method:  'POST',
  headers: {
    'Content-Type':      'application/json',
    'X-Signature-256':   signature,
    'X-Timestamp':       String(Date.now()),
  },
  body,
});
```

## The checklist

1. Always verify the signature before processing any webhook payload
2. Use timing-safe comparison (`crypto.timingSafeEqual` in Node.js or the manual implementation above)
3. Include and verify a timestamp to reject replayed events
4. Read the body as raw text before parsing — parsers normalise JSON which can change the byte sequence the HMAC was computed over
5. Return 200 quickly even for events you don't handle — otherwise the sender retries and your logs fill up
6. Log and alert on signature failures — they're either bugs or probing attempts
