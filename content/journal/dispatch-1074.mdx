title: "OPA Gatekeeper: policy as code for Kubernetes admission control — ConstraintTemplates, dry-run, audit"
date: "2033-10-10"
excerpt: "OPA Gatekeeper integrates the Open Policy Agent (OPA) policy engine as a Kubernetes admission webhook. When you submit a resource to the Kubernetes API server (create a Pod, apply a Deployment), Gatekeeper intercepts the request, evaluates it against your defined policies, and either allows or rejects it with a specific error message. Policies are written in Rego (OPA's policy language) and packaged as ConstraintTemplates — reusable policy blueprints that accept parameters. From a ConstraintTemplate you instantiate Constraint objects that specify which resources are in-scope and what parameter values to enforce. For example, a RequiredLabels ConstraintTemplate can be instantiated as a Constraint that requires every Deployment in the construx-prod namespace to have an owner and team label. Gatekeeper also runs an audit controller that periodically re-evaluates all existing resources against all Constraints and reports violations — so you can see which pre-existing resources are non-compliant without blocking them. Dry-run mode lets you deploy a new Constraint in observation mode (violations are reported but not enforced) before switching to enforcement."

## ConstraintTemplate and Constraint definitions

```yaml
# ConstraintTemplate: reusable policy blueprint in Rego
# This template enforces that required labels are present on resources

apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: k8srequiredlabels
spec:
  crd:
    spec:
      names:
        kind: K8sRequiredLabels    # creates a new CRD for instantiating this policy
      validation:
        openAPIV3Schema:
          type: object
          properties:
            labels:
              type: array
              items: { type: string }
  targets:
    - target: admission.k8s.gatekeeper.sh
      rego: |
        package k8srequiredlabels

        violation[{"msg": msg}] {
          # For every required label...
          required := input.parameters.labels[_]
          # ...that is NOT present in the resource metadata...
          not input.review.object.metadata.labels[required]
          # ...report a violation
          msg := sprintf("Missing required label: %v", [required])
        }
---
# Constraint: instantiation of K8sRequiredLabels for construx-prod Deployments
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: K8sRequiredLabels
metadata:
  name: deployments-must-have-owner
spec:
  enforcementAction: deny        # deny = block; warn = allow but warn; dryrun = audit only
  match:
    kinds:
      - apiGroups: ["apps"]
        kinds:     ["Deployment"]
    namespaces:
      - construx-prod
      - construx-staging
  parameters:
    labels: ["owner", "team", "app"]
```

```yaml
# ConstraintTemplate: block containers running as root

apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: k8snoroot
spec:
  crd:
    spec:
      names:
        kind: K8sNoRoot
  targets:
    - target: admission.k8s.gatekeeper.sh
      rego: |
        package k8snoroot

        violation[{"msg": msg}] {
          # Check all init containers
          c := input.review.object.spec.initContainers[_]
          c.securityContext.runAsNonRoot != true
          msg := sprintf("Init container %v must not run as root", [c.name])
        }

        violation[{"msg": msg}] {
          # Check all regular containers
          c := input.review.object.spec.containers[_]
          c.securityContext.runAsNonRoot != true
          msg := sprintf("Container %v must not run as root", [c.name])
        }
---
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: K8sNoRoot
metadata:
  name: no-root-containers
spec:
  enforcementAction: deny
  match:
    kinds:
      - apiGroups: [""]
        kinds:     ["Pod"]
    excludedNamespaces:
      - kube-system      # exclude system pods that legitimately run as root
      - longhorn-system
```

## Audit and dry-run workflow

```bash
# Gatekeeper installation via Helm
helm repo add gatekeeper https://open-policy-agent.github.io/gatekeeper/charts
helm install gatekeeper gatekeeper/gatekeeper \
  --namespace gatekeeper-system \
  --create-namespace \
  --set replicas=3 \
  --version 3.17.1

# Check constraint violations from the audit controller
kubectl get constraints
# NAME                          ENFORCEMENT-ACTION  TOTAL-VIOLATIONS
# deployments-must-have-owner   deny                3
# no-root-containers            deny                0

# See which resources are violating
kubectl describe k8srequiredlabels deployments-must-have-owner
# Status:
#   Audit Timestamp: 2033-10-10T09:00:12Z
#   Total Violations: 3
#   Violations:
#     Enforcement Action: deny
#     Kind:      Deployment
#     Message:   Missing required label: owner
#     Name:      legacy-worker
#     Namespace: construx-prod
#     Kind:      Deployment
#     Message:   Missing required label: team
#     Name:      legacy-worker
#     Namespace: construx-prod

# Test a policy before deploying (dry-run mode)
# Step 1: deploy constraint with dryrun to observe violations without blocking
kubectl patch k8srequiredlabels/deployments-must-have-owner \
  --type merge -p '{"spec":{"enforcementAction":"dryrun"}}'

# Step 2: check violations accumulate in audit without blocking deployments

# Step 3: switch to warn (allows resource but logs a warning in audit)
kubectl patch k8srequiredlabels/deployments-must-have-owner \
  --type merge -p '{"spec":{"enforcementAction":"warn"}}'

# Step 4: switch to deny once all existing resources are compliant
kubectl patch k8srequiredlabels/deployments-must-have-owner \
  --type merge -p '{"spec":{"enforcementAction":"deny"}}'

# Gatekeeper metrics
# gatekeeper_violations{constraint_kind="K8sRequiredLabels"} 3
# gatekeeper_audit_last_run_time 1.728547212e+09
# gatekeeper_request_duration_seconds_bucket{operation="admit",le="0.01"} 482
```

OPA Gatekeeper vs Kyverno vs PSA (Pod Security Admission) vs manual RBAC: Pod Security Admission (PSA) is Kubernetes built-in and enforces a fixed set of pod security standards (privileged, baseline, restricted) — no custom policies. RBAC controls who can do what (create Deployments, read Secrets) but cannot enforce what the resource contains (label requirements, image registries, resource limits). Kyverno (covered in the journal) is a Kubernetes-native policy engine that uses YAML for policies instead of Rego — lower learning curve, good for teams comfortable with YAML, but less expressive for complex logic. OPA Gatekeeper uses Rego: a purpose-built logic language for policy that handles complex conditions (checking multiple fields, cross-referencing values, list comprehension) that YAML cannot express cleanly. The trade-off is Rego's learning curve — it's a declarative logic language with a different mental model from imperative code. For teams that need standard policies (required labels, no-root, allowed registries), Kyverno is often faster to adopt. For teams with complex multi-condition policies or who are already using OPA elsewhere (API authorization, Terraform policy-as-code), Gatekeeper is the consistent choice.
