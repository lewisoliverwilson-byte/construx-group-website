Workers run in Cloudflare's isolate-based runtime (not Node.js). Each request starts a fresh isolate — the process model is different from a long-running server. Cold starts don't exist because there's no JVM or Node.js process to warm up. The isolate starts in microseconds.

## Basic worker

```ts
// src/index.ts
export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext): Promise<Response> {
    const url = new URL(request.url);

    if (url.pathname === '/health') {
      return Response.json({ status: 'ok', region: request.cf?.colo });
    }

    return new Response('Not found', { status: 404 });
  },
};

interface Env {
  // Bindings declared in wrangler.toml
  KV: KVNamespace;
  DB: D1Database;
  BUCKET: R2Bucket;
  JWT_SECRET: string;
}
```

## Geolocation and edge personalisation

```ts
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const country = request.cf?.country ?? 'US';
    const city = request.cf?.city ?? 'Unknown';
    const timezone = request.cf?.timezone ?? 'UTC';

    // Redirect UK users to UK-specific pricing
    if (country === 'GB' && new URL(request.url).pathname === '/pricing') {
      return Response.redirect('https://construxgroup.io/pricing/uk', 302);
    }

    // Add geolocation context to forwarded request
    const upstreamRequest = new Request(request.url, {
      ...request,
      headers: {
        ...Object.fromEntries(request.headers),
        'x-user-country': country,
        'x-user-city': city,
        'x-user-timezone': timezone,
      },
    });

    return fetch(upstreamRequest);
  },
};
```

## KV: edge-distributed key-value storage

```ts
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);
    const key = url.searchParams.get('key');

    if (!key) return Response.json({ error: 'Missing key' }, { status: 400 });

    // Read from KV — globally distributed, ~1ms latency
    const cached = await env.KV.get(key, 'json');
    if (cached) {
      return Response.json(cached, {
        headers: { 'x-cache': 'hit' },
      });
    }

    // Cache miss — fetch from origin
    const origin = await fetch(`https://api.construxgroup.io/data/${key}`);
    const data = await origin.json();

    // Cache for 5 minutes
    await env.KV.put(key, JSON.stringify(data), { expirationTtl: 300 });

    return Response.json(data, {
      headers: { 'x-cache': 'miss' },
    });
  },
};
```

## D1: SQLite at the edge

```ts
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    if (request.method === 'GET') {
      const results = await env.DB.prepare(
        'SELECT id, title, excerpt FROM posts WHERE published = 1 ORDER BY created_at DESC LIMIT 10'
      ).all();

      return Response.json(results.results);
    }

    if (request.method === 'POST') {
      const body = await request.json<{ title: string; content: string }>();

      const result = await env.DB.prepare(
        'INSERT INTO posts (title, content, created_at) VALUES (?, ?, ?) RETURNING id'
      )
        .bind(body.title, body.content, new Date().toISOString())
        .first<{ id: number }>();

      return Response.json({ id: result?.id }, { status: 201 });
    }

    return new Response('Method not allowed', { status: 405 });
  },
};
```

## Rate limiting with KV

```ts
async function rateLimit(
  request: Request,
  env: Env,
  { limit = 10, window = 60 }: { limit?: number; window?: number } = {}
): Promise<boolean> {
  const ip = request.headers.get('cf-connecting-ip') ?? 'unknown';
  const windowStart = Math.floor(Date.now() / (window * 1000));
  const key = `rate:${ip}:${windowStart}`;

  const current = await env.KV.get(key);
  const count = parseInt(current ?? '0', 10);

  if (count >= limit) return false;

  await env.KV.put(key, String(count + 1), { expirationTtl: window });
  return true;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const allowed = await rateLimit(request, env, { limit: 20, window: 60 });

    if (!allowed) {
      return new Response('Rate limit exceeded', {
        status: 429,
        headers: { 'Retry-After': '60' },
      });
    }

    return fetch(request);
  },
};
```

## Caching responses at the edge

```ts
export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext): Promise<Response> {
    const cache = caches.default;
    const cacheKey = new Request(request.url, request);

    // Check Cloudflare's cache
    let response = await cache.match(cacheKey);
    if (response) return response;

    // Cache miss — fetch from origin
    response = await fetch(request);
    response = new Response(response.body, response);

    // Cache for 5 minutes
    response.headers.set('Cache-Control', 'public, max-age=300');

    // Store in cache (non-blocking)
    ctx.waitUntil(cache.put(cacheKey, response.clone()));

    return response;
  },
};
```

## When to use Workers vs Next.js middleware

**Workers:**
- Auth at the edge before the request reaches your origin (50-100ms savings)
- Geolocation routing where latency to the decision matters
- Heavy caching logic (Cloudflare's cache is global)
- Transformation of third-party APIs without hitting your origin

**Next.js middleware:**
- Auth checks that need access to your database session
- Route-based logic tied to your app's routing
- A/B testing when variants need server-rendered HTML

The patterns overlap. Workers excel when you want to avoid hitting your origin entirely. Middleware is easier when the logic is tightly coupled to your Next.js app.
