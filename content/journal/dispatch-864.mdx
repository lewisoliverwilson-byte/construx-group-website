excerpt: "SurrealDB is a multi-model database: documents, relational, and graph in one engine. SurrealQL is a SQL-like query language extended with graph traversal operators. Records have IDs that are first-class references — `person:lewis->knows->person:alice` traverses a graph edge directly in the query. Permissions are embedded in the schema: a DEFINE TABLE rule restricts what authenticated users can read or write. The binary is a single file, embeds in your application, or runs as a cluster."

Documents + relations + graph. SurrealQL traverses all three. Permissions in schema.

## Start SurrealDB and create schema

```bash
# Run in memory (dev)
surreal start --log debug --user root --pass root memory

# Run with file storage
surreal start --log info --user root --pass root file:///data/surreal.db

# Run in production (RocksDB)
surreal start \
  --user root --pass root \
  --bind 0.0.0.0:8000 \
  file:///data/construx.db
```

```sql
-- Connect with surreal SQL REPL
surreal sql --conn http://localhost:8000 --user root --pass root --ns construx --db prod

-- Define a namespace and database
USE NS construx DB prod;

-- Define tables with types and permissions
DEFINE TABLE order SCHEMAFULL PERMISSIONS
  FOR select WHERE auth.id = customer_id OR auth.role = 'admin'
  FOR create WHERE $auth.id != NONE
  FOR update WHERE auth.id = customer_id AND status IN ['pending']
  FOR delete WHERE auth.role = 'admin';

DEFINE FIELD id           ON order TYPE record<order>;
DEFINE FIELD customer_id  ON order TYPE record<customer>;
DEFINE FIELD status       ON order TYPE string   ASSERT $value IN ['pending','processing','shipped','delivered'];
DEFINE FIELD total_cents  ON order TYPE int      ASSERT $value > 0;
DEFINE FIELD created_at   ON order TYPE datetime DEFAULT time::now();
DEFINE FIELD line_items   ON order TYPE array;
DEFINE FIELD line_items.* ON order TYPE object;

-- Define indexes
DEFINE INDEX idx_order_customer ON order COLUMNS customer_id;
DEFINE INDEX idx_order_status   ON order COLUMNS status;
```

## Graph relations

```sql
-- Create records and relationships
CREATE person:lewis SET name = 'Lewis Wilson', email = 'lewis@construxgroup.io';
CREATE person:alice SET name = 'Alice Chen', email = 'alice@construxgroup.io';

-- Create a graph edge
RELATE person:lewis->knows->person:alice SET
  since     = time::now(),
  strength  = 'strong';

-- Traverse the graph
SELECT ->knows->person.name AS colleagues FROM person:lewis;
-- [{ colleagues: ['Alice Chen'] }]

-- Traverse multiple hops
SELECT ->knows->person->knows->person.name AS two_hops FROM person:lewis;

-- Bidirectional traversal
SELECT <->knows<->person.name AS everyone_known FROM person:lewis;
```

## SurrealQL — document and relational in one query

```sql
-- Create an order with embedded line items (document style)
CREATE order SET
  customer_id = customer:cust-001,
  status      = 'pending',
  total_cents = 4999,
  line_items  = [
    { sku: 'CX-BOLT-M8', qty: 4, price_cents: 1249 },
  ],
  created_at  = time::now();

-- Relational join across record links
SELECT
  id,
  status,
  total_cents,
  customer_id.name     AS customer_name,
  customer_id.email    AS customer_email,
  created_at
FROM order
WHERE status = 'pending'
ORDER BY created_at DESC
LIMIT 10;

-- Full-text search (built-in BM25)
DEFINE ANALYZER order_search TOKENIZERS blank FILTERS lowercase, ascii;
DEFINE INDEX order_fulltext ON order FIELDS line_items[*].sku SEARCH ANALYZER order_search BM25;

SELECT * FROM order WHERE line_items[*].sku @@ 'bolt';
```

## JavaScript SDK

```ts
// lib/surreal.ts
import Surreal from 'surrealdb';

const db = new Surreal();

await db.connect('ws://localhost:8000', {
  namespace: 'construx',
  database:  'prod',
  auth: {
    username: process.env.SURREAL_USER!,
    password: process.env.SURREAL_PASS!,
  },
});

// Type-safe queries
interface Order {
  id:         string;
  customerId: string;
  status:     'pending' | 'processing' | 'shipped';
  totalCents: number;
  createdAt:  string;
}

const orders = await db.query<[Order[]]>(
  'SELECT * FROM order WHERE status = $status ORDER BY created_at DESC LIMIT $limit',
  { status: 'pending', limit: 20 },
);

// Create a record
const [order] = await db.create<Order>('order', {
  customerId: 'customer:cust-001',
  status:     'pending',
  totalCents: 4999,
});

// Graph traversal
const [{ colleagues }] = await db.query<[{ colleagues: string[] }]>(
  'SELECT ->knows->person.name AS colleagues FROM $person',
  { person: 'person:lewis' },
);
```

SurrealDB vs MongoDB + Neo4j: MongoDB is a document database — no native graph. Neo4j is a graph database — no native document model. If you need both, you run two databases and synchronise data between them. SurrealDB is one database that handles both natively. The tradeoff: SurrealDB is newer and has a smaller ecosystem than either MongoDB or Neo4j. For greenfield projects that need both document storage and graph relationships, SurrealDB avoids operational complexity. For projects where MongoDB or Neo4j is already the de-facto standard, the ecosystem advantage of the established tools usually wins.
