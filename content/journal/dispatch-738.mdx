Manual memoization is error-prone. React Compiler moves it to the compiler, which does not make mistakes.

## How it works

Before React Compiler, a component re-renders whenever its parent re-renders or its props change (even if the values are equal). To prevent this, you had to wrap in `React.memo`, wrap callbacks in `useCallback`, and wrap expensive computations in `useMemo`. You had to do this correctly, consistently, and remember to do it.

React Compiler infers which values change and adds memoization automatically. If `expensiveCalculation(data)` only changes when `data` changes, the compiler wraps it. If `handleClick` only changes when `itemId` changes, the compiler wraps it.

## Install

```bash
npm install -D babel-plugin-react-compiler
npm install react-compiler-runtime
```

```ts
// next.config.ts
const nextConfig = {
  experimental: {
    reactCompiler: true,
  },
};

export default nextConfig;
```

That is it. The compiler runs automatically on every file.

## Before and after

```tsx
// Before: manual memoization
import { memo, useMemo, useCallback } from 'react';

const PostCard = memo(function PostCard({ post, onDelete }: Props) {
  const excerpt = useMemo(() => post.content.slice(0, 150) + '…', [post.content]);

  const handleDelete = useCallback(() => {
    onDelete(post.id);
  }, [post.id, onDelete]);

  return (
    <div>
      <h2>{post.title}</h2>
      <p>{excerpt}</p>
      <button onClick={handleDelete}>Delete</button>
    </div>
  );
});
```

```tsx
// After: React Compiler handles it
function PostCard({ post, onDelete }: Props) {
  const excerpt = post.content.slice(0, 150) + '…';

  return (
    <div>
      <h2>{post.title}</h2>
      <p>{excerpt}</p>
      <button onClick={() => onDelete(post.id)}>Delete</button>
    </div>
  );
}
```

The compiled output has the same memoization as the manual version. You write the simple version.

## The ESLint plugin

```bash
npm install -D eslint-plugin-react-compiler
```

```json
// .eslintrc.json or biome.json
{
  "plugins": ["react-compiler"],
  "rules": {
    "react-compiler/react-compiler": "error"
  }
}
```

The compiler requires components and hooks to follow the Rules of Hooks and not mutate props or state directly. Most React code already follows these rules. The ESLint plugin surfaces code the compiler cannot optimize — not errors in your code, but patterns that opt out of automatic memoization.

## What the compiler cannot handle

- Components that mutate refs during render
- Direct DOM manipulation in render
- Components that read from a mutable external store without using `useSyncExternalStore`
- `use client` components that receive non-serializable props from Server Components

The compiler adds `"use no memo"` comments to functions it opts out of automatically. You can add this comment manually to opt out a specific function.

## Performance impact

In practice: components re-render less. The more your component tree, the bigger the gains. For a page with 50 components where most are memoization candidates, React Compiler typically reduces re-renders by 30–70%. The exact number depends on your component structure. Use React DevTools Profiler to measure before and after.
