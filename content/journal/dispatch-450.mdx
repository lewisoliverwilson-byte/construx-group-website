Asking an LLM to return JSON and then parsing it is fragile. The model might return markdown fences around the JSON, omit required fields, use inconsistent field names, or return a value that fails your validator. Structured outputs change this: you define a schema, the model is constrained to return something that matches it, and you get a TypeScript type back with no parsing step.

## Basic usage with the Anthropic SDK

```ts
import Anthropic from '@anthropic-ai/sdk';
import { z } from 'zod';
import { zodToJsonSchema } from 'zod-to-json-schema';

const client = new Anthropic();

const SentimentSchema = z.object({
  sentiment: z.enum(['positive', 'negative', 'neutral']),
  confidence: z.number().min(0).max(1),
  reasoning: z.string(),
});

type Sentiment = z.infer<typeof SentimentSchema>;

export async function classifySentiment(text: string): Promise<Sentiment> {
  const response = await client.messages.create({
    model: 'claude-opus-4-8',
    max_tokens: 256,
    tools: [
      {
        name: 'classify_sentiment',
        description: 'Classify the sentiment of the provided text.',
        input_schema: zodToJsonSchema(SentimentSchema) as Anthropic.Tool['input_schema'],
      },
    ],
    tool_choice: { type: 'tool', name: 'classify_sentiment' },
    messages: [
      {
        role: 'user',
        content: `Classify the sentiment of this text:\n\n${text}`,
      },
    ],
  });

  const toolUse = response.content.find((c) => c.type === 'tool_use');
  if (!toolUse || toolUse.type !== 'tool_use') {
    throw new Error('No tool use in response');
  }

  return SentimentSchema.parse(toolUse.input);
}
```

The `tool_choice: { type: 'tool', name: 'classify_sentiment' }` forces the model to use the tool — guaranteed structured output every time.

## Extraction: pulling structured data from unstructured text

```ts
const ProductSchema = z.object({
  name: z.string(),
  price: z.number().nullable(),
  currency: z.string().nullable(),
  condition: z.enum(['new', 'used', 'refurbished', 'unknown']),
  seller: z.string().nullable(),
  inStock: z.boolean(),
  features: z.array(z.string()).max(10),
});

type Product = z.infer<typeof ProductSchema>;

export async function extractProductData(rawHtml: string): Promise<Product> {
  const response = await client.messages.create({
    model: 'claude-opus-4-8',
    max_tokens: 512,
    tools: [
      {
        name: 'extract_product',
        description: 'Extract structured product data from the provided HTML content.',
        input_schema: zodToJsonSchema(ProductSchema) as Anthropic.Tool['input_schema'],
      },
    ],
    tool_choice: { type: 'tool', name: 'extract_product' },
    messages: [
      {
        role: 'user',
        content: `Extract product information from this HTML:\n\n${rawHtml.slice(0, 4000)}`,
      },
    ],
  });

  const toolUse = response.content.find((c) => c.type === 'tool_use');
  if (!toolUse || toolUse.type !== 'tool_use') throw new Error('Extraction failed');

  return ProductSchema.parse(toolUse.input);
}
```

## Batch extraction with parallel calls

```ts
import { ProductSchema } from './schemas';

export async function extractBatch(items: string[]): Promise<Product[]> {
  const results = await Promise.allSettled(
    items.map((item) => extractProductData(item))
  );

  return results
    .filter((r): r is PromiseFulfilledResult<Product> => r.status === 'fulfilled')
    .map((r) => r.value);
}
```

## Classification with confidence thresholds

```ts
const CategorySchema = z.object({
  category: z.enum([
    'electronics',
    'clothing',
    'home',
    'sports',
    'books',
    'beauty',
    'food',
    'other',
  ]),
  subcategory: z.string().nullable(),
  confidence: z.number().min(0).max(1),
  tags: z.array(z.string()).max(5),
});

export async function categoriseProduct(title: string, description: string) {
  const result = await client.messages.create({
    model: 'claude-haiku-4-5-20251001',  // Haiku is fast and cheap for classification
    max_tokens: 256,
    tools: [
      {
        name: 'categorise',
        description: 'Assign a category to this product.',
        input_schema: zodToJsonSchema(CategorySchema) as Anthropic.Tool['input_schema'],
      },
    ],
    tool_choice: { type: 'tool', name: 'categorise' },
    messages: [
      {
        role: 'user',
        content: `Title: ${title}\nDescription: ${description}\n\nCategorise this product.`,
      },
    ],
  });

  const toolUse = result.content.find((c) => c.type === 'tool_use');
  if (!toolUse || toolUse.type !== 'tool_use') throw new Error('Classification failed');

  const parsed = CategorySchema.parse(toolUse.input);

  // Reject low-confidence classifications
  if (parsed.confidence < 0.7) {
    return { ...parsed, category: 'other' as const, tags: [] };
  }

  return parsed;
}
```

## Multi-step: extract then validate

```ts
const ArbitrageSchema = z.object({
  isArbitrageOpportunity: z.boolean(),
  estimatedProfit: z.number().nullable(),
  confidence: z.number().min(0).max(1),
  reasoning: z.string(),
  risks: z.array(z.string()).max(5),
});

export async function analyseArbitrageOpportunity(
  sourceProduct: Product,
  targetProduct: Product,
): Promise<z.infer<typeof ArbitrageSchema>> {
  const response = await client.messages.create({
    model: 'claude-opus-4-8',
    max_tokens: 512,
    tools: [
      {
        name: 'analyse_arbitrage',
        description: 'Analyse whether this represents a profitable arbitrage opportunity.',
        input_schema: zodToJsonSchema(ArbitrageSchema) as Anthropic.Tool['input_schema'],
      },
    ],
    tool_choice: { type: 'tool', name: 'analyse_arbitrage' },
    messages: [
      {
        role: 'user',
        content: `
Source listing:
${JSON.stringify(sourceProduct, null, 2)}

Target marketplace listing:
${JSON.stringify(targetProduct, null, 2)}

Is this an arbitrage opportunity? Consider: price differential, condition differences, 
marketplace fees (assume 15%), shipping costs (assume 10% of price), and demand signals.
        `.trim(),
      },
    ],
  });

  const toolUse = response.content.find((c) => c.type === 'tool_use');
  if (!toolUse || toolUse.type !== 'tool_use') throw new Error('Analysis failed');

  return ArbitrageSchema.parse(toolUse.input);
}
```

## Handling refusals

When the model can't produce a valid structured output (ambiguous input, content policy), it returns a `tool_use` block with an `error` type or no tool use at all. Catch both:

```ts
export async function safeExtract<T>(
  schema: z.ZodSchema<T>,
  toolName: string,
  prompt: string,
): Promise<T | null> {
  try {
    const response = await client.messages.create({
      model: 'claude-opus-4-8',
      max_tokens: 512,
      tools: [
        {
          name: toolName,
          description: `Extract data according to the ${toolName} schema.`,
          input_schema: zodToJsonSchema(schema) as Anthropic.Tool['input_schema'],
        },
      ],
      tool_choice: { type: 'tool', name: toolName },
      messages: [{ role: 'user', content: prompt }],
    });

    if (response.stop_reason === 'end_turn') return null;  // Model declined

    const toolUse = response.content.find((c) => c.type === 'tool_use');
    if (!toolUse || toolUse.type !== 'tool_use') return null;

    return schema.safeParse(toolUse.input).data ?? null;
  } catch {
    return null;
  }
}
```

## Model choice

- **Haiku**: classification, simple extraction, high-volume calls. Fast and cheap.
- **Sonnet**: complex extraction, multi-field schemas, reasoning about ambiguity.
- **Opus**: arbitrage analysis, multi-step reasoning, anything where accuracy matters more than speed.

Structured outputs work with all Claude models. Pick based on the complexity of the task, not the output format.
