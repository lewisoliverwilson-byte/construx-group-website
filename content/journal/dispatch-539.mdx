Email deliverability is a DNS problem masquerading as an infrastructure problem. The emails are being sent — they're just landing in spam because the receiving server can't verify who sent them. SPF, DKIM, and DMARC are the three authentication layers that fix this.

## SPF (Sender Policy Framework)

SPF is a DNS TXT record that lists which mail servers are authorised to send email for your domain. Receiving servers check the SPF record against the IP of the sending server.

```dns
# DNS TXT record for construxgroup.io
construxgroup.io. IN TXT "v=spf1 include:amazonses.com include:resend.com -all"
```

Breaking this down:
- `v=spf1` — SPF version
- `include:amazonses.com` — allow AWS SES servers
- `include:resend.com` — allow Resend servers
- `-all` — fail (reject) mail from any other server

`-all` is strict. `~all` is a soft fail (spam likely). `-all` is correct for production.

## DKIM (DomainKeys Identified Mail)

DKIM adds a cryptographic signature to outgoing emails. The sending server signs the email with a private key. The receiving server verifies it using the public key published in DNS.

Resend generates DKIM keys for you. After adding your domain in the Resend dashboard, you'll get a CNAME record to add:

```dns
# CNAME record (Resend handles the public key)
resend._domainkey.construxgroup.io. IN CNAME resend._domainkey.resend.com.
```

AWS SES requires you to publish the public key yourself:

```dns
# TXT record for SES DKIM
abc123._domainkey.construxgroup.io. IN TXT "v=DKIM1; k=rsa; p=MIGfMA0G..."
```

You'll get three DKIM CNAME records from SES — add all three.

## DMARC (Domain-based Message Authentication, Reporting & Conformance)

DMARC tells receiving servers what to do when SPF or DKIM fails, and sets up reporting so you get feedback on authentication failures.

```dns
# DMARC TXT record
_dmarc.construxgroup.io. IN TXT "v=DMARC1; p=quarantine; rua=mailto:dmarc@construxgroup.io; pct=100"
```

- `v=DMARC1` — DMARC version
- `p=quarantine` — quarantine (spam folder) messages that fail authentication
- `p=reject` — reject them outright (stricter, use after you're confident in your SPF/DKIM setup)
- `p=none` — monitoring mode only (good starting point)
- `rua=mailto:dmarc@construxgroup.io` — send aggregate reports here
- `pct=100` — apply the policy to 100% of messages

Start with `p=none` and a reporting email. Read the reports for a week to confirm legitimate emails are passing authentication. Then move to `p=quarantine`, then `p=reject`.

## Verifying with Resend

```ts
// lib/email.ts
import { Resend } from 'resend';

const resend = new Resend(process.env.RESEND_API_KEY);

export async function sendTransactionalEmail({
  to,
  subject,
  react,
}: {
  to:      string;
  subject: string;
  react:   React.ReactElement;
}) {
  const { data, error } = await resend.emails.send({
    from:    'Construx <notifications@construxgroup.io>',
    to,
    subject,
    react,
  });

  if (error) {
    throw new Error(`Email failed: ${error.message}`);
  }

  return data;
}
```

The `from` domain must match your verified domain in Resend.

## Custom Return-Path (Bounce Address)

For Resend, add a CNAME for the return-path to improve deliverability further:

```dns
bounces.construxgroup.io. IN CNAME feedback-smtp.us-east-1.amazonses.com.
```

Then configure Resend to use this bounce domain. Messages that bounce are tracked by the bounce address, not your main domain — keeps your sender reputation clean.

## Testing

Before sending in production, test with:

- `dig TXT construxgroup.io` — verify SPF record
- `dig TXT _dmarc.construxgroup.io` — verify DMARC
- [mail-tester.com](https://www.mail-tester.com) — sends you a test address; email it and get a score
- [MXToolbox](https://mxtoolbox.com) — checks SPF, DKIM, DMARC

A score of 10/10 on mail-tester means you're likely to land in the inbox. Anything below 8 will have significant spam folder rate.

## The result

After configuring all three records for Construx's transactional email: delivery rate went from 71% inbox (pre-authentication) to 98.4% inbox. The 28.6% difference was cost-free — just DNS changes.
