Dead code accumulates invisibly. Knip finds it all at once.

## Install

```bash
npm install --save-dev knip
```

## Run

```bash
npx knip
```

Output:

```

  src/lib/legacy-auth.ts
  src/components/OldModal.tsx
  src/hooks/useObsoleteFlag.ts
```

## Config — tell Knip what your entry points are

```jsonc
// knip.json
{
  "entry": [
    "src/app/**/{page,layout,route}.ts{,x}",
    "src/app/**/{page,layout,route}.ts{,x}",
    "src/trigger/**/*.ts",
    "scripts/**/*.ts"
  ],
  "project": ["src/**/*.ts{,x}"],
  "ignore": [
    "src/generated/**",
    "**/*.stories.tsx"
  ],
  "ignoreDependencies": [
    "eslint-config-next"   // used by Next.js, not directly imported
  ]
}
```

## Next.js preset — auto-configured

```jsonc
// knip.json
{
  "$schema": "https://unpkg.com/knip@5/schema.json",
  "next": true   // enables Next.js plugin — knows about app/, pages/, public/
}
```

With the Next.js plugin, Knip understands that `page.tsx`, `layout.tsx`, `route.ts`, and `middleware.ts` are entry points. Exports from these files are not flagged as unused.

## Fix mode

```bash
# Remove unused exports automatically (use with caution)
npx knip --fix

# Dry run — see what would be changed
npx knip --fix --dry-run
```

Fix mode removes `export` keywords from unused exports and deletes imports that become unused as a result. It does not delete unused files — you do that manually after reviewing the list.

## CI integration

```yaml
# .github/workflows/knip.yml
name: Knip
on: [pull_request]

jobs:
  knip:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22' }
      - run: npm ci
      - run: npx knip --reporter compact
```

`--reporter compact` outputs one issue per line, which is easier to read in CI logs.

## Custom reporters

```ts
// knip.reporter.ts
import type { Reporter } from 'knip';

const reporter: Reporter = ({ issues }) => {
  const total = Object.values(issues).reduce((s, i) => s + Object.keys(i).length, 0);
  console.log(`Found ${total} issues`);
  if (total > 0) process.exit(1);
};

export default reporter;
```

```jsonc
// knip.json
{
  "reporter": "./knip.reporter.ts"
}
```

## Knip vs ts-prune vs ESLint no-unused-vars

Knip: whole-project analysis, understands re-exports, framework-aware, finds unused dependencies. ts-prune: simpler, export-focused, less framework awareness. ESLint no-unused-vars: file-level only, catches local unused variables but not cross-file dead exports. The Construx default: Knip runs in CI on every PR. ts-prune is retired.
