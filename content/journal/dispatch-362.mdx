Webhooks are HTTP POST requests from an external service to your application, triggered by events on their side. A payment succeeds → Stripe sends `payment_intent.succeeded` to your `/api/webhooks/stripe`. A repository push → GitHub sends a push event. The pattern is universal.

Two problems every webhook implementation needs to solve: **verification** (is this request actually from the service I trust, or a spoofed payload?) and **reliability** (what happens if the handler throws, or my server is down when the event fires?).

## Webhook signature verification

Every serious webhook sender includes a signature in the request headers. Verify it before processing:

```ts
// app/api/webhooks/stripe/route.ts
import { NextRequest } from 'next/server';
import Stripe from 'stripe';

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);

export async function POST(req: NextRequest) {
  const body = await req.text();  // must read as raw text for signature verification
  const signature = req.headers.get('stripe-signature')!;

  let event: Stripe.Event;

  try {
    event = stripe.webhooks.constructEvent(
      body,
      signature,
      process.env.STRIPE_WEBHOOK_SECRET!,
    );
  } catch (err) {
    console.error('Webhook signature verification failed:', err);
    return new Response('Webhook signature verification failed', { status: 400 });
  }

  // Event is verified — safe to process
  await processStripeEvent(event);
  return new Response('OK', { status: 200 });
}
```

The signature is an HMAC-SHA256 of the raw body, keyed by your webhook signing secret. If anyone tampers with the body, the signature won't match.

**Critical**: always read the body as raw text before verification. Parsing it as JSON first changes the exact byte sequence that was signed.

## Generic signature verification

For services without a convenience library:

```ts
import crypto from 'crypto';

function verifyWebhookSignature(
  body: string,
  signature: string,
  secret: string,
  algorithm: 'sha256' | 'sha1' = 'sha256',
): boolean {
  const computed = crypto
    .createHmac(algorithm, secret)
    .update(body)
    .digest('hex');

  // Use timingSafeEqual to prevent timing attacks
  return crypto.timingSafeEqual(
    Buffer.from(`sha256=${computed}`),
    Buffer.from(signature),
  );
}
```

Always use `timingSafeEqual` — constant-time comparison prevents timing attacks that could reveal the secret through response time differences.

## Idempotency

External services guarantee at-least-once delivery. The same event may arrive multiple times (on retry after your handler returned a 5xx, or on their infrastructure retry logic). Your handler must be idempotent.

```ts
import { db } from '@/db';
import { processedWebhooks } from '@/db/schema';
import { eq } from 'drizzle-orm';

async function processStripeEvent(event: Stripe.Event): Promise<void> {
  // Check if we've already processed this event
  const existing = await db.query.processedWebhooks.findFirst({
    where: eq(processedWebhooks.eventId, event.id),
  });

  if (existing) {
    console.log('Duplicate event, skipping:', event.id);
    return;
  }

  // Process the event
  switch (event.type) {
    case 'customer.subscription.updated':
      await handleSubscriptionUpdate(event.data.object as Stripe.Subscription);
      break;
    case 'invoice.payment_failed':
      await handlePaymentFailed(event.data.object as Stripe.Invoice);
      break;
  }

  // Mark as processed
  await db.insert(processedWebhooks).values({
    eventId: event.id,
    source: 'stripe',
    processedAt: new Date(),
  });
}
```

The schema:

```ts
// db/schema.ts
export const processedWebhooks = pgTable('processed_webhooks', {
  eventId: text('event_id').primaryKey(),
  source: text('source').notNull(),
  processedAt: timestamp('processed_at').notNull().defaultNow(),
}, (t) => ({
  processedAtIdx: index('processed_webhooks_at_idx').on(t.processedAt),
}));
```

## Responding quickly, processing asynchronously

Stripe (and most services) expect a 200 response within 30 seconds. Long processing jobs shouldn't block the response:

```ts
export async function POST(req: NextRequest) {
  const body = await req.text();
  const signature = req.headers.get('stripe-signature')!;
  const event = stripe.webhooks.constructEvent(body, signature, process.env.STRIPE_WEBHOOK_SECRET!);

  // Acknowledge receipt immediately
  // Queue the actual processing as a background job
  await enqueueJob('stripe-webhook', { eventId: event.id, eventType: event.type, payload: event });

  return new Response('Queued', { status: 200 });
}
```

The queue handler does the actual work. If it fails, the queue retries it — not Stripe.

## GitHub webhook verification

```ts
// app/api/webhooks/github/route.ts
import { NextRequest } from 'next/server';
import crypto from 'crypto';

export async function POST(req: NextRequest) {
  const body = await req.text();
  const signature = req.headers.get('x-hub-signature-256') ?? '';

  const hmac = crypto.createHmac('sha256', process.env.GITHUB_WEBHOOK_SECRET!);
  const digest = `sha256=${hmac.update(body).digest('hex')}`;

  if (!crypto.timingSafeEqual(Buffer.from(digest), Buffer.from(signature))) {
    return new Response('Invalid signature', { status: 401 });
  }

  const event = req.headers.get('x-github-event');
  const payload = JSON.parse(body);

  if (event === 'push') {
    await handleRepoPush(payload);
  }

  return new Response('OK');
}
```

## Webhook delivery failure handling

Most services retry failed webhook deliveries with exponential backoff. Design your handler to be safe to receive the same event multiple times — which the idempotency check above handles.

If you need to re-process a failed webhook manually, most services provide a dashboard to replay specific events. Keep the `processedWebhooks` table as evidence — you can delete the row to force reprocessing.

## Testing webhooks locally

```bash
# Stripe CLI: forward webhook events to your local server
stripe listen --forward-to localhost:3000/api/webhooks/stripe

# Trigger a specific event for testing
stripe trigger customer.subscription.updated
```

The Stripe CLI handles signature generation for locally forwarded events, so your verification code works the same as in production.

GitHub provides a "redeliver" button in the webhook delivery logs — useful for testing handlers against real payloads without running live transactions.
