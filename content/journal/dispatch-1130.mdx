date: "2034-03-27"
excerpt: "Apache Pinot is a realtime distributed OLAP datastore designed for user-facing analytics at sub-second query latency. It is used at LinkedIn (where it originated), Uber, Stripe, and Walmart for product analytics — dashboards that show real-time counts, aggregations, and filtering over billions of rows with consistent sub-20ms p99 latency. Pinot's architecture separates ingestion from serving: realtime tables ingest directly from Kafka using a consuming segment that buffers recent data in memory; completed segments are flushed to deep storage (S3) and served from server nodes. Offline tables load pre-built segments from batch pipelines (Spark, Hadoop). Hybrid tables combine both: recent data from realtime segments, historical data from offline segments, with a broker that merges results transparently. Pinot's star-tree index is a pre-aggregated index structure that stores partial aggregations for common grouping combinations — a query like `SELECT count(*), sum(amount) GROUP BY tenantId, productCategory` can be answered entirely from the star-tree without scanning raw rows, enabling sub-millisecond aggregation over billions of records. The upsert feature handles event deduplication and update semantics for streams like order status updates: when a new order event arrives with the same `orderId` but a new `status`, Pinot's upsert table replaces the previous record, maintaining exactly-one-record semantics while still supporting realtime Kafka ingestion."

    "invertedIndexColumns": ["tenantId", "status", "productCategory"],

    // Sorted index: for range queries on the primary sort column

```sql
-- Pinot queries: sub-second aggregation over billions of rows

-- Real-time revenue by tenant in the last hour (uses star-tree)
SELECT
  tenantId,
  COUNT(*) as order_count,
  SUM(totalPence) / 100.0 as revenue_gbp,
  AVG(totalPence) / 100.0 as avg_order_gbp
FROM orders_realtime
WHERE ts > ago('PT1H')
GROUP BY tenantId
ORDER BY revenue_gbp DESC
LIMIT 20
-- Result: 1847 rows, 12ms query time, 8M rows scanned (star-tree avoided full scan)

-- Funnel analysis: conversion rate by product category (hybrid table)
SELECT
  productCategory,
  COUNTIF(status = 'created') as created,
  COUNTIF(status = 'paid') as paid,
  COUNTIF(status = 'shipped') as shipped,
  COUNTIF(status = 'paid') * 100.0 / COUNTIF(status = 'created') as conversion_pct
FROM events_hybrid
WHERE ts > ago('P7D')
GROUP BY productCategory
HAVING created > 1000
ORDER BY conversion_pct DESC

-- Time-series: order volume by minute (uses sorted index on ts)
SELECT
  DATETIMECONVERT(ts, '1:MILLISECONDS:EPOCH', '1:MILLISECONDS:SIMPLE_DATE_FORMAT:yyyy-MM-dd HH:mm:00', '1:MINUTES') as minute,
  COUNT(*) as orders,
  SUM(totalPence) / 100.0 as revenue
FROM orders_realtime
WHERE ts BETWEEN ago('PT1H') AND now()
GROUP BY minute
ORDER BY minute
```

Pinot vs ClickHouse vs Druid vs BigQuery vs Redshift: ClickHouse (dispatch-1105) is Pinot's closest competitor for user-facing analytics — both achieve sub-second aggregation over billions of rows. ClickHouse has better SQL compatibility, simpler operations, and faster point lookups; Pinot has better realtime Kafka ingestion semantics, the upsert table type for CDC-style updates, and the star-tree index for consistent sub-millisecond aggregation on pre-defined grouping patterns. Apache Druid has a similar architecture to Pinot (streaming ingestion, segment-based storage) but was designed for time-series workloads and has weaker upsert semantics. BigQuery and Redshift are batch-oriented: queries take seconds to minutes, making them unsuitable for user-facing dashboards. The practical choice at Construx: ClickHouse for ad-hoc analytics where query flexibility matters more than raw speed on pre-defined dimensions; Pinot for product analytics endpoints where consistent sub-20ms latency is required regardless of query complexity, because the star-tree pre-computation guarantees it.
