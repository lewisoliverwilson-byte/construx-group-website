The Hyve's AI agent builds a large prompt for every workspace invocation: the system prompt (workspace configuration, integration descriptions, team context) plus the conversation history (up to 50 messages). Sending all of this to the Claude API on every invocation is expensive — and unnecessary, since most of the context is static within a session.

Anthropic's prompt caching feature lets us cache the static parts of the prompt and pay only a fraction of the cost for subsequent requests that reuse the cached content.

## How prompt caching works

Normally, every Claude API request is priced per input token. You send 2,000 tokens of system prompt + 1,500 tokens of conversation history = 3,500 input tokens charged at the full rate.

With prompt caching:
1. On the first request, you mark certain parts of the prompt as "cacheable"
2. Claude processes and caches those parts
3. On subsequent requests that include the same content in the same position, the cached version is used
4. Cache hits are charged at a lower rate (currently around 10% of the normal token price)

The cache is keyed by content and position. The same system prompt sent in the same position in subsequent requests will hit the cache.

## What we cache

The system prompt in The Hyve has two parts:

**Static (cacheable):** The workspace description, integration configuration, team composition, and AI behaviour instructions. This changes rarely — only when the workspace configuration changes.

**Dynamic (not cached):** The current time, the invoking user's identity, the channel they're in. This changes on every request.

```ts
const systemPrompt = [
  // Static, cacheable — ends with cache_control marker
  {
    type: 'text' as const,
    text: buildStaticContext(workspace, integrations),
    cache_control: { type: 'ephemeral' as const },
  },
  // Dynamic, not cached
  {
    type: 'text' as const,
    text: buildDynamicContext(user, channel, currentTime),
  },
];
```

The `cache_control: { type: 'ephemeral' }` marker tells Claude to cache the content up to that point. Everything after the marker is processed fresh on each request.

## The conversation history

The conversation history (50 messages) presents a more complex caching opportunity. The history is not fully static — new messages are added as the conversation progresses — but most of it stays the same between invocations in the same session.

We cache the conversation history up to the last 5 messages:

```ts
const messages = [
  // Older messages — cacheable (unlikely to change between invocations)
  ...conversationHistory.slice(0, -5).map((msg, i) => ({
    role: msg.role,
    content: i === conversationHistory.length - 6
      ? [{ type: 'text', text: msg.content, cache_control: { type: 'ephemeral' } }]
      : msg.content,
  })),
  // Recent messages — not cached (likely to change)
  ...conversationHistory.slice(-5).map((msg) => ({
    role: msg.role,
    content: msg.content,
  })),
  // Current user message
  { role: 'user', content: currentMessage },
];
```

This caches the bulk of the conversation history while leaving the recent tail uncached. In practice, a 50-message history with caching enabled means 45 messages are cached and 5 + the current message are fresh.

## The numbers

Before prompt caching:
- System prompt: ~1,200 tokens × full price
- Conversation history: ~2,500 tokens × full price
- Total per invocation: ~3,700 input tokens at full price

After prompt caching (cache hit):
- System prompt: 1,200 tokens × cache price (~10%)
- Older history: 2,000 tokens × cache price (~10%)
- Recent history + current message: ~600 tokens × full price
- Total: 3,200 tokens × 10% + 600 tokens × 100% = 920 effective tokens

That's roughly a 75% reduction in input token cost for a cache hit. The first request per workspace per session still pays full price (cache miss), but subsequent requests in the same session are dramatically cheaper.

## The 5-minute TTL

Anthropic's prompt cache has a 5-minute TTL. If more than 5 minutes passes between invocations in the same workspace, the cache expires and the next request is a cache miss.

This has implications for how we think about agent session management. For active workspaces (frequent invocations), the cache stays warm. For inactive workspaces, the cache expires frequently.

In The Hyve, most invocations happen in bursts during active work sessions. A team using the agent heavily will make many invocations within short time windows — exactly the pattern prompt caching is optimised for.

## What prompt caching doesn't help with

**Output tokens.** Caching only applies to input tokens. The cost of generating the response is unchanged. If the agent generates long responses, output tokens can dominate the cost.

**Single invocations.** A workspace that invokes the agent once and never again gets no benefit from caching — the first request is always a cache miss.

**Frequently-changing context.** If the workspace configuration changes on every request (which it doesn't in normal use), caching doesn't help.

## The implementation detail: consistent token counts

Prompt caching requires that the cached prefix be identical across requests — same content, same position. If the static part of the system prompt varies (different dates formatted in, different workspace IDs in the text), the cache key changes and you get a miss.

We're careful to keep the static and dynamic sections cleanly separated. The static section contains only stable content; time-varying information lives in the dynamic section.

```ts
function buildStaticContext(workspace: Workspace, integrations: Integration[]): string {
  return [
    `Workspace: ${workspace.name}`,
    `Description: ${workspace.description}`,
    `Integrations: ${integrations.map(i => i.name).join(', ')}`,
    // NO timestamps, NO user-specific data here
  ].join('\n');
}

function buildDynamicContext(user: User, channel: Channel, now: Date): string {
  return [
    `Current time: ${now.toISOString()}`,
    `Invoked by: ${user.name} (@${user.handle})`,
    `Channel: #${channel.name}`,
  ].join('\n');
}
```

This separation is the key implementation discipline. It's easy to accidentally put dynamic content in the cached section when you're building the prompt — and if you do, you silently lose the cache hits without any error.

The 70% cost reduction on AI agent invocations is material at scale. For a product where the AI agent is invoked hundreds of times per day across all workspaces, the savings compound quickly.
