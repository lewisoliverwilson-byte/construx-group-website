title: "Dagger: portable CI pipelines as typed code with content-addressed caching"
date: "2032-11-17"
excerpt: "Dagger is a CI/CD engine that runs pipelines written in Go, Python, or TypeScript inside containers on the Dagger Engine — a BuildKit-based runtime. Every pipeline step is a container operation; results are cached by content hash. The same pipeline runs identically on a developer's laptop, in GitHub Actions, or on a self-hosted runner. Secrets are injected as typed `*dagger.Secret` values that are never logged or cached. The module system lets you publish and reuse pipeline components from the Daggerverse — the CI equivalent of npm. The result: CI configuration that you can test, refactor, and type-check before pushing."

Typed pipelines. Content-addressed caching. Local = CI. Secrets as first-class values.

## SDK and module setup

```go
// dagger/main.go — Dagger module definition (dagger init --sdk go --name construx-ci)
package main

import (
    "context"
    "fmt"
)

// ConstruxCI is the module struct — exported methods become dagger functions
type ConstruxCI struct{}

// Build compiles the Go binary for linux/amd64
func (m *ConstruxCI) Build(ctx context.Context, src *Directory) *File {
    return dag.Container().
        From("golang:1.23-alpine").
        WithMountedDirectory("/src", src).
        WithWorkdir("/src").
        WithMountedCache("/root/go/pkg/mod", dag.CacheVolume("go-mod")).
        WithMountedCache("/root/.cache/go-build", dag.CacheVolume("go-build")).
        WithEnvVariable("GOOS", "linux").
        WithEnvVariable("GOARCH", "amd64").
        WithEnvVariable("CGO_ENABLED", "0").
        WithExec([]string{
            "go", "build",
            "-ldflags", "-s -w -X main.version=" + "v1.8.3",
            "-o", "/out/api",
            "./cmd/api",
        }).
        File("/out/api")
}

// Test runs the full test suite with race detection
func (m *ConstruxCI) Test(ctx context.Context, src *Directory) *Container {
    return dag.Container().
        From("golang:1.23-alpine").
        WithMountedDirectory("/src", src).
        WithWorkdir("/src").
        WithMountedCache("/root/go/pkg/mod", dag.CacheVolume("go-mod")).
        WithExec([]string{"go", "test", "-race", "-count=1", "-timeout=5m", "./..."})
}

// Lint runs golangci-lint
func (m *ConstruxCI) Lint(ctx context.Context, src *Directory) *Container {
    return dag.Container().
        From("golangci/golangci-lint:v1.62-alpine").
        WithMountedDirectory("/src", src).
        WithWorkdir("/src").
        WithExec([]string{"golangci-lint", "run", "--timeout", "5m"})
}

// Publish builds the image and pushes to the registry
func (m *ConstruxCI) Publish(
    ctx context.Context,
    src *Directory,
    version string,
    registryUser *Secret,
    registryPass *Secret,
) (string, error) {
    image := dag.Container().
        Build(src, ContainerBuildOpts{Dockerfile: "Dockerfile"}).
        WithRegistryAuth("registry.construx.io", registryUser, registryPass)

    return image.Publish(ctx,
        fmt.Sprintf("registry.construx.io/construx/api:%s", version))
}
```

## Running the pipeline

```bash
# Call individual functions from CLI
dagger call build --src .
# → outputs the compiled binary path

dagger call test --src . stdout
# ok  github.com/construx/api/internal/orders  0.312s
# ok  github.com/construx/api/internal/pricing 0.104s
# ok  github.com/construx/api/cmd/api          0.089s
# PASS

dagger call lint --src . stdout
# golangci-lint found no issues

# Publish with secrets (from environment)
dagger call publish \
  --src . \
  --version v1.8.3 \
  --registry-user env:REGISTRY_USER \
  --registry-pass env:REGISTRY_PASS
# registry.construx.io/construx/api:v1.8.3@sha256:4a9f2b1c…

# Run the full pipeline programmatically
dagger run go run ./ci/pipeline.go

# List all available functions
dagger functions
# NAME      DESCRIPTION
# build     Compile binary for linux/amd64
# test      Run tests with race detector
# lint      Run golangci-lint
# publish   Build and push to registry

# Debug mode: show every operation and cache result
dagger run --debug go run ./ci/pipeline.go
```

## Service containers for integration tests

```go
// Integration tests with real dependencies (Postgres + Redis as sidecar services)
func (m *ConstruxCI) IntegrationTest(ctx context.Context, src *Directory) *Container {
    // Start Postgres as a service container
    postgres := dag.Container().
        From("postgres:16-alpine").
        WithEnvVariable("POSTGRES_DB", "construx_test").
        WithEnvVariable("POSTGRES_USER", "construx").
        WithEnvVariable("POSTGRES_PASSWORD", "test-secret").
        WithExposedPort(5432).
        AsService()

    // Start Redis as a service container
    redis := dag.Container().
        From("redis:7-alpine").
        WithExposedPort(6379).
        AsService()

    // Run integration tests with both services bound
    return dag.Container().
        From("golang:1.23-alpine").
        WithServiceBinding("postgres", postgres).
        WithServiceBinding("redis", redis).
        WithMountedDirectory("/src", src).
        WithWorkdir("/src").
        WithMountedCache("/root/go/pkg/mod", dag.CacheVolume("go-mod")).
        WithEnvVariable("DATABASE_URL",
            "postgres://construx:test-secret@postgres:5432/construx_test?sslmode=disable").
        WithEnvVariable("REDIS_URL", "redis://redis:6379/0").
        WithExec([]string{
            "go", "test",
            "-tags", "integration",
            "-race",
            "-timeout", "10m",
            "./...",
        })
}
```

## GitHub Actions integration

```yaml
# .github/workflows/ci.yml
name: CI
on:
  push:
    branches: [master]
  pull_request:

jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install Dagger
        run: |
          curl -fsSL https://dl.dagger.io/dagger/install.sh | sh
          sudo mv bin/dagger /usr/local/bin/

      - name: Test
        run: dagger call test --src . stdout

      - name: Lint
        run: dagger call lint --src . stdout

      - name: Build
        run: dagger call build --src . export --path ./dist/api

      - name: Publish
        if: github.ref == 'refs/heads/master'
        env:
          REGISTRY_USER: ${{ secrets.REGISTRY_USER }}
          REGISTRY_PASS: ${{ secrets.REGISTRY_PASS }}
          VERSION: ${{ github.sha }}
        run: |
          dagger call publish \
            --src . \
            --version "$VERSION" \
            --registry-user env:REGISTRY_USER \
            --registry-pass env:REGISTRY_PASS

# The pipeline is identical locally and in CI.
# Dagger's content-addressed cache means:
# - if go.sum is unchanged → go-mod-cache hit → skip `go mod download`
# - if source is unchanged → go-build-cache hit → skip compilation
# Each step's inputs are hashed; the cache key is deterministic.
```

Dagger vs Earthly vs plain Bash: plain Bash scripts are portable but have no caching, no types, and no composition. Earthly adds reproducibility and a layer cache to Makefile-style CI. Dagger gives you a full programming language for the pipeline itself — you can write tests for your CI logic, refactor it, import shared modules, and get IDE support. The cache model is the strongest argument: BuildKit's content-addressed cache means CI runs skip steps that haven't changed, regardless of the CI provider. The tradeoff: you're adding a runtime dependency (Dagger Engine) and a Go/Python/TypeScript learning curve for CI configuration.
