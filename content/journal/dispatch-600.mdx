A Stripe webhook is an HTTP POST to your server. Stripe sends one for every payment event: `payment_intent.succeeded`, `customer.subscription.deleted`, `invoice.payment_failed`, and a hundred others. Your job: verify it came from Stripe, process it exactly once, and respond within 30 seconds.

## Setup

```bash
npm install stripe
```

```ts
// lib/stripe.ts
import Stripe from 'stripe';

export const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!, {
  apiVersion: '2024-11-20',
  typescript:  true,
});
```

## Receiving and verifying webhooks

```ts
// app/api/webhooks/stripe/route.ts
import { headers } from 'next/headers';
import Stripe      from 'stripe';
import { stripe }  from '@/lib/stripe';

const webhookSecret = process.env.STRIPE_WEBHOOK_SECRET!;

export async function POST(req: Request) {
  const body      = await req.text();
  const signature = (await headers()).get('stripe-signature')!;

  let event: Stripe.Event;
  try {
    event = stripe.webhooks.constructEvent(body, signature, webhookSecret);
  } catch (err) {
    console.error('Webhook signature verification failed:', err);
    return new Response('Invalid signature', { status: 400 });
  }

  // Process the event
  await handleStripeEvent(event);

  return new Response('OK');
}
```

`constructEvent` verifies the signature using `STRIPE_WEBHOOK_SECRET` from your Stripe dashboard. **Never skip this.** An unverified webhook handler lets anyone trigger your payment logic.

Get the webhook secret from the Stripe dashboard → Webhooks → Add endpoint → Signing secret.

## Handling events idempotently

Stripe may deliver the same event more than once if your server doesn't respond in time. Your handler must be idempotent:

```ts
async function handleStripeEvent(event: Stripe.Event) {
  // Check if we've already processed this event
  const processed = await db.stripeEvent.findUnique({
    where: { stripeEventId: event.id },
  });
  if (processed) return;  // already handled

  // Process based on event type
  switch (event.type) {
    case 'payment_intent.succeeded': {
      const pi = event.data.object as Stripe.PaymentIntent;
      await fulfillOrder(pi.metadata.orderId, pi.amount);
      break;
    }
    case 'customer.subscription.deleted': {
      const sub = event.data.object as Stripe.Subscription;
      await cancelSubscription(sub.customer as string);
      break;
    }
    case 'invoice.payment_failed': {
      const inv = event.data.object as Stripe.Invoice;
      await notifyPaymentFailed(inv.customer_email!, inv.id);
      break;
    }
  }

  // Record that we processed this event
  await db.stripeEvent.create({
    data: { stripeEventId: event.id, type: event.type, processedAt: new Date() },
  });
}
```

Store the event ID and only process if not seen before. The schema:

```sql
CREATE TABLE stripe_events (
  stripe_event_id TEXT PRIMARY KEY,
  type            TEXT NOT NULL,
  processed_at    TIMESTAMPTZ NOT NULL
);
```

## Processing asynchronously

Stripe expects a response within 30 seconds. For slow operations (sending emails, provisioning resources), respond immediately and process in the background:

```ts
export async function POST(req: Request) {
  const body      = await req.text();
  const signature = (await headers()).get('stripe-signature')!;

  let event: Stripe.Event;
  try {
    event = stripe.webhooks.constructEvent(body, signature, webhookSecret);
  } catch {
    return new Response('Invalid signature', { status: 400 });
  }

  // Enqueue for background processing and return immediately
  await queue.add('stripe-event', { eventId: event.id, type: event.type });

  return new Response('OK');  // respond in < 1ms
}
```

Use a job queue (BullMQ, Inngest, Trigger.dev) to process events asynchronously. The queue handles retries if your processor fails.

## Key events to handle

| Event                            | When it fires                              | What to do                          |
|----------------------------------|--------------------------------------------|-------------------------------------|
| `payment_intent.succeeded`       | Payment confirmed                          | Fulfill order, send receipt         |
| `payment_intent.payment_failed`  | Payment declined                           | Notify user, retry or cancel        |
| `customer.subscription.created`  | New subscription starts                    | Provision access                    |
| `customer.subscription.updated`  | Plan changed                               | Update access level                 |
| `customer.subscription.deleted`  | Subscription cancelled or unpaid           | Revoke access                       |
| `invoice.payment_succeeded`      | Renewal payment successful                 | Extend subscription period          |
| `invoice.payment_failed`         | Renewal payment failed                     | Send dunning email, pause access    |
| `checkout.session.completed`     | Checkout flow finished                     | Check payment status, fulfill       |

## The checkout.session.completed trap

`checkout.session.completed` fires when the user completes checkout — not when payment is confirmed. For subscriptions and some payment methods, payment hasn't settled yet. Always check `session.payment_status`:

```ts
case 'checkout.session.completed': {
  const session = event.data.object as Stripe.Checkout.Session;
  if (session.payment_status === 'paid') {
    await fulfillOrder(session.metadata?.orderId);
  }
  // else: wait for payment_intent.succeeded
  break;
}
```

For buy-now-pay-later and delayed payment methods, `payment_status` will be `'unpaid'` at checkout completion. Wait for `payment_intent.succeeded` before fulfilling.
