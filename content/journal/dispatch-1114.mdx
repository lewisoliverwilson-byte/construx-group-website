title: "Cosign and Sigstore: container image signing, SLSA provenance, keyless signing"
date: "2034-02-07"
excerpt: "Cosign (from the Sigstore project) is a tool for signing and verifying container images. The supply chain attack surface in Kubernetes is the container registry: an attacker who can push a malicious image to your registry — or intercept an image pull — can execute arbitrary code in your cluster. Cosign addresses this by cryptographically signing image digests and storing signatures in the same OCI registry as the image (as a special manifest), so verification happens at pull time against a known public key or the Sigstore transparency log (Rekor). Sigstore's keyless signing mode uses OIDC tokens (GitHub Actions, Google, Microsoft identity) to produce short-lived signing keys — instead of managing a long-lived private key, you prove identity via OIDC, sign the image, and the Rekor log records the signature with a timestamp. This means anyone can verify that an image was signed by a specific GitHub Actions workflow from a specific repository commit, with no key management. SLSA (Supply-chain Levels for Software Artifacts) provenance is generated by tools like slsa-github-generator — it produces a signed attestation that records the exact build inputs, workflow, and commit that produced a specific image digest. Combined with Kyverno policies that require signed images and valid SLSA provenance, Cosign enforces a complete software supply chain integrity check at admission time."

## Cosign signing, verification, and Kyverno policy

```bash
# Cosign: sign a container image after building
# Uses keyless signing via GitHub Actions OIDC — no private key to manage

# In GitHub Actions CI pipeline:
# 1. Build image and push to registry
# 2. Sign the image digest with Cosign (keyless via OIDC)

cosign sign \
  --yes \
  --rekor-url=https://rekor.sigstore.dev \
  ghcr.io/construx/orders-api@sha256:a3f8c2d7e1b94f5e6d3a7c8b2e4f1d9a3b7c5e2f4d8a1c6b9e3f7d2a5c8b4e1

# Output:
# Generating ephemeral keys...
# Retrieving signed certificate...
# Successfully verified SCT...
# tlog entry created with index: 148392847
# Pushing signature to: ghcr.io/construx/orders-api

# Verify an image signature (keyless: check against Rekor + OIDC issuer)
cosign verify \
  --certificate-issuer=https://token.actions.githubusercontent.com \
  --certificate-identity-regexp=https://github.com/construx/orders-api/.github/workflows/ \
  ghcr.io/construx/orders-api@sha256:a3f8c2d7e1b94f5e6d3a7c8b2e4f1d9a3b7c5e2f4d8a1c6b9e3f7d2a5c8b4e1

# Output:
# Verification for ghcr.io/construx/orders-api@sha256:a3f8c2d7e1b94f5e6d3a7c8b2e4f1d9a3b7c5e2f4d8a1c6b9e3f7d2a5c8b4e1 --
# The following checks were performed on each of these signatures:
#   - The cosign claims were validated
#   - Existence of the claims in the transparency log was verified offline
#   - The certificate claims matched the expected values
# [{"critical":{"identity":{"docker-reference":"ghcr.io/construx/orders-api"}...

# Attach SLSA provenance attestation to image
cosign attest \
  --yes \
  --predicate slsa-provenance.json \
  --type slsaprovenance \
  ghcr.io/construx/orders-api@sha256:a3f8c2d7e1b94f5e6d3a7c8b2e4f1d9a3b7c5e2f4d8a1c6b9e3f7d2a5c8b4e1

# Verify attestation and extract provenance
cosign verify-attestation \
  --type slsaprovenance \
  --certificate-issuer=https://token.actions.githubusercontent.com \
  --certificate-identity-regexp=https://github.com/construx/orders-api/.github/workflows/slsa.yml \
  ghcr.io/construx/orders-api@sha256:a3f8c2d7e1b94f5e6d3a7c8b2e4f1d9a3b7c5e2f4d8a1c6b9e3f7d2a5c8b4e1 \
  | jq '.payload | @base64d | fromjson | .predicate.buildType'
# "https://slsa.dev/provenance/v1"
```

```yaml
# Kyverno ClusterPolicy: require signed images with valid Cosign signature
# Admission control: blocks unsigned images from being admitted to the cluster

apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-signed-images
spec:
  validationFailureAction: Enforce
  background: false
  rules:
    - name: check-image-signature
      match:
        any:
          - resources:
              kinds: [Pod]
              namespaces: [construx-prod, construx-staging]
      verifyImages:
        - imageReferences:
            - "ghcr.io/construx/*"
          attestors:
            - count: 1
              entries:
                - keyless:
                    subject: "https://github.com/construx/*/actions/workflows/*.yml@refs/heads/main"
                    issuer: "https://token.actions.githubusercontent.com"
                    rekor:
                      url: https://rekor.sigstore.dev
          attestations:
            - predicateType: https://slsa.dev/provenance/v1
              conditions:
                - all:
                    - key: "{{ buildDefinition.buildType }}"
                      operator: Equals
                      value: "https://slsa.dev/provenance/v1"
                    - key: "{{ buildDefinition.externalParameters.workflow.ref }}"
                      operator: Equals
                      value: "refs/heads/main"

---
```

```yaml
# GitHub Actions: full signing pipeline
# .github/workflows/build-sign-push.yml

name: Build, Sign, and Push

on:
  push:
    branches: [main]

permissions:
  id-token:   write   # needed for keyless Cosign signing via OIDC
  packages:   write
  contents:   read
  attestations: write

jobs:
  build-sign:
    runs-on: ubuntu-latest
    outputs:
      digest: ${{ steps.push.outputs.digest }}

    steps:
      - uses: actions/checkout@v4

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push
        id: push
        uses: docker/build-push-action@v5
        with:
          push: true
          tags: ghcr.io/construx/orders-api:${{ github.sha }}

      - name: Install Cosign
        uses: sigstore/cosign-installer@v3

      - name: Sign image
        env:
          COSIGN_EXPERIMENTAL: "1"
        run: |
          cosign sign --yes \
            ghcr.io/construx/orders-api@${{ steps.push.outputs.digest }}

      - name: Generate SBOM with Syft
        uses: anchore/sbom-action@v0
        with:
          image: ghcr.io/construx/orders-api@${{ steps.push.outputs.digest }}
          format: spdx-json
          output-file: sbom.spdx.json

      - name: Attest SBOM
        run: |
          cosign attest --yes \
            --predicate sbom.spdx.json \
            --type spdxjson \
            ghcr.io/construx/orders-api@${{ steps.push.outputs.digest }}

      - name: Generate SLSA provenance
        uses: slsa-framework/slsa-github-generator/.github/workflows/generator_container_slsa3.yml@v2.0.0
        with:
          image: ghcr.io/construx/orders-api
          digest: ${{ steps.push.outputs.digest }}
```

Cosign vs Docker Content Trust (DCT) vs Notary v2 vs in-house key management: Docker Content Trust uses Notary v1 and The Update Framework (TUF) — it's built into Docker but has poor ergonomics and is rarely used in practice. Notary v2 (now ORAS / OCI Referrers API) is the successor standard, used by projects like AWS Signer and Azure Container Registry's signing feature. The core operational difference is key management: traditional signing approaches require managing private keys securely (HSM, Vault), distributing public keys to verifiers, and rotating keys periodically — significant operational burden. Sigstore's keyless approach eliminates the private key: identity-based signing binds the signature to an OIDC identity (a GitHub Actions workflow URL, a Kubernetes service account) that is inherently auditable via the Rekor transparency log. This means you get non-repudiation ("this specific GitHub Actions workflow signed this image") without managing a PKI. For Construx, the combination — Cosign keyless signing in CI, Kyverno policy verification at admission, SLSA provenance attestations — closes the supply chain gap: only images built by verified CI workflows, from known commits, can run in production.
