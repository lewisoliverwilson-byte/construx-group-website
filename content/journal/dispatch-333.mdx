Observability is the difference between "the API is slow" and "the slow part is the database query in `getUser()` called from the `DashboardPage` server component, specifically the join on `orders` that's missing an index." OpenTelemetry gives you that.

## Next.js instrumentation hook

Next.js 14+ has a built-in instrumentation file that runs once on server startup:

```ts
// instrumentation.ts (in project root, next to next.config.ts)
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    // Only run in Node.js — not Edge Runtime
    await import('./instrumentation.node');
  }
}
```

```ts
// instrumentation.node.ts
import { NodeSDK } from '@opentelemetry/sdk-node';
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http';
import { getNodeAutoInstrumentations } from '@opentelemetry/auto-instrumentations-node';
import { Resource } from '@opentelemetry/resources';
import { SEMRESATTRS_SERVICE_NAME } from '@opentelemetry/semantic-conventions';

const sdk = new NodeSDK({
  resource: new Resource({
    [SEMRESATTRS_SERVICE_NAME]: 'construx-web',
  }),
  traceExporter: new OTLPTraceExporter({
    url: process.env.OTEL_EXPORTER_OTLP_ENDPOINT ?? 'http://localhost:4318/v1/traces',
    headers: {
      Authorization: `Bearer ${process.env.OTEL_API_KEY}`,
    },
  }),
  instrumentations: [
    getNodeAutoInstrumentations({
      '@opentelemetry/instrumentation-fs': { enabled: false }, // noisy
    }),
  ],
});

sdk.start();
```

Enable in `next.config.ts`:

```ts
const nextConfig = {
  experimental: {
    instrumentationHook: true,
  },
};
```

## Custom spans

The auto-instrumentation catches HTTP requests and database calls. Add custom spans for business logic:

```ts
// lib/tracing.ts
import { trace, SpanStatusCode } from '@opentelemetry/api';

const tracer = trace.getTracer('construx-web');

export async function withSpan<T>(
  name: string,
  fn: () => Promise<T>,
  attributes?: Record<string, string | number | boolean>,
): Promise<T> {
  return tracer.startActiveSpan(name, async (span) => {
    if (attributes) {
      Object.entries(attributes).forEach(([k, v]) => span.setAttribute(k, v));
    }
    try {
      const result = await fn();
      span.setStatus({ code: SpanStatusCode.OK });
      return result;
    } catch (err) {
      span.setStatus({ code: SpanStatusCode.ERROR, message: String(err) });
      span.recordException(err as Error);
      throw err;
    } finally {
      span.end();
    }
  });
}
```

```ts
// Usage in server component or route handler
import { withSpan } from '@/lib/tracing';

async function getDashboardData(userId: string) {
  return withSpan('getDashboardData', async () => {
    const [user, orders, stats] = await Promise.all([
      withSpan('db.getUser', () => db.users.findUnique({ where: { id: userId } }), { userId }),
      withSpan('db.getOrders', () => db.orders.findMany({ where: { userId } })),
      withSpan('fetchExternalStats', () => fetchFromExternalAPI(userId)),
    ]);
    return { user, orders, stats };
  });
}
```

Now your trace shows exactly which of the three parallel operations was slow.

## Metrics

```ts
// instrumentation.node.ts — add metrics
import { MeterProvider } from '@opentelemetry/sdk-metrics';
import { OTLPMetricExporter } from '@opentelemetry/exporter-metrics-otlp-http';
import { PeriodicExportingMetricReader } from '@opentelemetry/sdk-metrics';

const meterProvider = new MeterProvider({
  resource: sdk['_resource'],
  readers: [
    new PeriodicExportingMetricReader({
      exporter: new OTLPMetricExporter({ url: process.env.OTEL_EXPORTER_OTLP_ENDPOINT }),
      exportIntervalMillis: 10_000,
    }),
  ],
});

// lib/metrics.ts
import { metrics } from '@opentelemetry/api';

const meter = metrics.getMeter('construx-web');

export const checkoutCounter = meter.createCounter('checkout.initiated', {
  description: 'Number of checkout sessions started',
});

export const emailDuration = meter.createHistogram('email.send.duration_ms', {
  description: 'Time to send a transactional email',
});

// Usage
checkoutCounter.add(1, { plan: 'pro', currency: 'gbp' });
emailDuration.record(Date.now() - start, { template: 'welcome' });
```

## Structured logs with trace correlation

Correlate log lines with trace IDs so you can jump from a log to the trace in your observability platform:

```ts
// lib/logger.ts
import { trace } from '@opentelemetry/api';

type LogLevel = 'info' | 'warn' | 'error';

function log(level: LogLevel, message: string, data?: Record<string, unknown>) {
  const span = trace.getActiveSpan();
  const traceId = span?.spanContext().traceId;
  const spanId = span?.spanContext().spanId;

  console[level](
    JSON.stringify({
      level,
      message,
      traceId,
      spanId,
      timestamp: new Date().toISOString(),
      ...data,
    }),
  );
}

export const logger = {
  info: (msg: string, data?: Record<string, unknown>) => log('info', msg, data),
  warn: (msg: string, data?: Record<string, unknown>) => log('warn', msg, data),
  error: (msg: string, data?: Record<string, unknown>) => log('error', msg, data),
};
```

## Backends

- **Grafana + Tempo**: open source, self-hostable. Tempo for traces, Prometheus for metrics, Loki for logs. One dashboard for all three.
- **Honeycomb**: best-in-class query UI. Expensive at scale but excellent DX.
- **Axiom**: log-centric but handles traces. Generous free tier, good for small teams.
- **Datadog / New Relic**: enterprise, full-featured, priced accordingly.

For solo projects or small teams, start with Grafana Cloud's free tier — 50GB traces/month, traces + metrics + logs in one place.

## What to instrument first

1. **Database queries** — the most common source of slow requests. Auto-instrumentation covers Prisma; Drizzle needs manual spans.
2. **External API calls** — auto-instrumented via HTTP client instrumentation.
3. **Auth checks** — slow session verification shows up quickly.
4. **Background jobs** — trace from job enqueue through completion across services.

The first trace that shows you a waterfall with an obvious N+1 query will pay for the setup time ten times over.
