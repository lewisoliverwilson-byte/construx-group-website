A monorepo is a single git repository containing multiple projects. Not a monolith — multiple apps, each independently deployable. The point: shared code lives in packages that all apps consume. A bug fix in `@construx/ui` ships to all apps that use it in one PR.

## When to use a monorepo

**Good fit:**
- Multiple apps sharing a design system or business logic
- A backend and frontend that need to share type definitions
- A team that wants atomic cross-app changes in one PR

**Bad fit:**
- Single app (overhead isn't worth it)
- Teams that need completely independent deployment pipelines
- Different tech stacks (a Go API and a Next.js app don't share much)

## Turborepo setup

```bash
npx create-turbo@latest
```

Or add to an existing repo:

```bash
npm install turbo --save-dev
```

```json
// turbo.json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": [".next/**", "dist/**"]
    },
    "dev": {
      "persistent": true,
      "cache": false
    },
    "lint": {
      "dependsOn": ["^lint"]
    },
    "type-check": {
      "dependsOn": ["^type-check"]
    },
    "test": {
      "dependsOn": ["^build"],
      "outputs": ["coverage/**"]
    }
  }
}
```

`^build` means "run `build` in all dependencies first." If your app depends on `@construx/ui`, `@construx/ui` builds before your app.

## Directory structure

```
construx-group/
  apps/
    web/            # main Next.js site
    admin/          # internal Next.js admin
    api/            # Express/Hono API (if separate)
  packages/
    ui/             # shared React component library
    config/         # shared eslint, tsconfig, tailwind
    db/             # Drizzle schema + client
    types/          # shared TypeScript types
  package.json      # root workspace config
  turbo.json        # pipeline config
  pnpm-workspace.yaml
```

## Package setup

```json
// packages/ui/package.json
{
  "name": "@construx/ui",
  "version": "0.0.0",
  "private": true,
  "exports": {
    "./button": "./src/button.tsx",
    "./card": "./src/card.tsx",
    "./input": "./src/input.tsx"
  },
  "scripts": {
    "build": "tsc --emitDeclarationOnly",
    "lint": "eslint src/",
    "type-check": "tsc --noEmit"
  },
  "devDependencies": {
    "typescript": "^5.0.0"
  },
  "peerDependencies": {
    "react": ">=19.0.0"
  }
}
```

```json
// apps/web/package.json
{
  "name": "web",
  "dependencies": {
    "@construx/ui": "workspace:*",
    "@construx/db": "workspace:*"
  }
}
```

`workspace:*` means "use the version from this monorepo." No npm publishing required.

## Shared TypeScript config

```json
// packages/config/tsconfig/base.json
{
  "compilerOptions": {
    "strict": true,
    "noEmit": true,
    "esModuleInterop": true,
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "lib": ["ES2022"],
    "target": "ES2022"
  }
}
```

```json
// apps/web/tsconfig.json
{
  "extends": "@construx/config/tsconfig/nextjs.json",
  "include": ["next-env.d.ts", "**/*.ts", "**/*.tsx"],
  "exclude": ["node_modules"]
}
```

## Shared ESLint config

```js
// packages/config/eslint/base.js
module.exports = {
  extends: [
    'eslint:recommended',
    'plugin:@typescript-eslint/recommended',
  ],
  rules: {
    'no-console': ['warn', { allow: ['warn', 'error'] }],
  },
};
```

```js
// apps/web/.eslintrc.js
module.exports = {
  extends: ['@construx/config/eslint/nextjs'],
};
```

## Remote caching

Turborepo's most valuable feature: build artifacts (compiled packages, test results) are cached and shared across CI runs and team members.

```bash
# Set up Vercel remote cache (free for Vercel users)
npx turbo login
npx turbo link

# Or use self-hosted cache
TURBO_TOKEN=your-token TURBO_TEAM=your-team turbo build
```

If package A hasn't changed since the last CI run, Turborepo restores its build output from cache instead of rebuilding. Large monorepos with shared packages can cut CI time from 20 minutes to 2 minutes.

## Running commands

```bash
# Build all apps and packages
turbo build

# Run only the web app in dev mode
turbo dev --filter=web

# Run tests for packages that changed since main
turbo test --filter=...[origin/main]

# Build everything that web depends on
turbo build --filter=web...
```

## What you actually get

A monorepo with Turborepo gives you:
- One PR to fix a shared bug and see it applied across all apps
- Type-safe imports from shared packages (no manual syncing)
- One CI pipeline that builds only what changed
- Shared tooling config that stays consistent

The cost: more repo setup complexity, longer clone times, and the need for a consistent tech stack across apps. For two or more apps with significant shared code, the tradeoff pays off quickly.
