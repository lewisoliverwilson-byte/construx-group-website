Parallel routes and intercepting routes are two App Router features that let you compose complex UI patterns without separate page components for each variant.

## Parallel routes: multiple pages in one layout

Parallel routes render multiple "slots" simultaneously. Each slot is a subfolder prefixed with `@`:

```
app/
├── layout.tsx           ← receives @team and @analytics as props
├── page.tsx             ← default slot (@children)
├── @team/
│   └── page.tsx         ← team panel
└── @analytics/
    └── page.tsx         ← analytics panel
```

```tsx
// app/layout.tsx
export default function Layout({
  children,
  team,
  analytics,
}: {
  children:  React.ReactNode;
  team:      React.ReactNode;
  analytics: React.ReactNode;
}) {
  return (
    <div className="grid grid-cols-[1fr_400px] gap-4 h-screen">
      <main>{children}</main>
      <aside className="flex flex-col gap-4">
        {team}
        {analytics}
      </aside>
    </div>
  );
}
```

```tsx
// app/@analytics/page.tsx
export default async function AnalyticsPanel() {
  const data = await fetchAnalytics();  // fetches independently
  return <AnalyticsChart data={data} />;
}
```

Each slot loads independently. If `@analytics` is slow, `@team` doesn't wait. Each slot can have its own `loading.tsx` and `error.tsx` boundaries.

## Default slots

When a route doesn't have a corresponding page for a slot, the slot needs a `default.tsx`:

```
app/
├── layout.tsx             ← has @modal slot
├── page.tsx               ← home page
├── @modal/
│   ├── default.tsx        ← shown when no modal is active (usually null)
│   └── (.)photos/[id]/
│       └── page.tsx       ← modal content
└── photos/
    └── [id]/
        └── page.tsx       ← full page content
```

```tsx
// app/@modal/default.tsx
export default function Default() {
  return null;
}
```

Without a `default.tsx`, navigating to a route that doesn't match the slot's path causes a 404.

## Intercepting routes: different views for the same URL

An intercepting route matches a URL and renders different content depending on how you navigated to it.

The conventions:
- `(.)path` — intercept a route in the same directory
- `(..)path` — intercept a route one level up
- `(..)(..)path` — intercept two levels up
- `(...)path` — intercept from the root

```
app/
├── layout.tsx             ← has @modal slot
├── @modal/
│   ├── default.tsx        ← null when no modal
│   └── (.)photos/[id]/
│       └── page.tsx       ← modal content (intercepted route)
└── photos/
    └── [id]/
        └── page.tsx       ← full page content (direct access)
```

When you click a photo link within the app:
- The URL changes to `/photos/123`
- The `@modal` slot shows `app/@modal/(.)photos/[id]/page.tsx` (the modal)
- The main content stays in place behind the modal

When you navigate directly to `/photos/123` or refresh:
- The `@modal` slot is ignored (no interception on hard navigation)
- The full `app/photos/[id]/page.tsx` renders

## The modal pattern

```tsx
// app/@modal/(.)photos/[id]/page.tsx
import { Modal } from '@/components/ui/Modal';
import { PhotoView } from '@/components/PhotoView';

export default async function PhotoModal({ params }: { params: { id: string } }) {
  const photo = await fetchPhoto(params.id);
  return (
    <Modal>
      <PhotoView photo={photo} />
    </Modal>
  );
}
```

```tsx
// app/photos/[id]/page.tsx — same data, full page layout
export default async function PhotoPage({ params }: { params: { id: string } }) {
  const photo = await fetchPhoto(params.id);
  return (
    <div className="container">
      <PhotoView photo={photo} />
    </div>
  );
}
```

The Modal component typically uses `router.back()` to close:

```tsx
'use client';

import { useRouter } from 'next/navigation';

export function Modal({ children }: { children: React.ReactNode }) {
  const router = useRouter();

  return (
    <div className="fixed inset-0 z-50">
      <div className="absolute inset-0 bg-black/60" onClick={() => router.back()} />
      <div className="relative">{children}</div>
    </div>
  );
}
```

`router.back()` navigates back, which removes the interception. The modal closes; the URL changes back. The experience: click a photo → modal opens. Refresh the page → full photo page. Share the URL → opens as full page.

## When to use these patterns

**Parallel routes**: dashboards where different panels fetch independently, split-pane layouts where each pane can have its own loading state, inbox-style layouts with list + detail.

**Intercepting routes + parallel routes**: the modal pattern (Photos, Twitter/X image viewer, Figma file selector). The pattern is: same URL, different rendering depending on navigation context.

Both features require planning the folder structure carefully before implementation. The `@slot` and `(.)` conventions encode the routing logic in the filesystem — once you understand the map, the implementation is straightforward.
