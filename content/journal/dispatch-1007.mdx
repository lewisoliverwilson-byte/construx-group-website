date: "2033-03-23"
excerpt: "Temporal is a workflow orchestration platform that makes long-running, multi-step processes reliable by default. The core idea: your workflow code runs to completion even if the worker process crashes mid-execution, the network is intermittently unavailable, or any activity fails. Temporal persists the complete execution history — every function call, every result, every sleep, every signal received — in a durable event log. If the worker crashes, Temporal replays the history to resume exactly where execution stopped. This makes timeouts, retries, and compensation logic easy to express in ordinary code instead of state machines spread across multiple services and a database."

Durable execution. Replay-based fault tolerance. Activities with retry policies. Signals and queries.

## Core concepts: workflows and activities

```go
// Temporal programs consist of workflows and activities
// Workflow: the orchestration logic — must be deterministic
// Activity: the actual work (HTTP calls, DB queries, file I/O) — can be non-deterministic

package workflows

import (
  "time"
  "go.temporal.io/sdk/workflow"
  "go.temporal.io/sdk/activity"
)

// OrderWorkflow: places an order, charges the card, fulfills, sends email
// Runs durably — survives worker crashes and network failures
func OrderWorkflow(ctx workflow.Context, order Order) (OrderResult, error) {
  // Activity options: retry policy, timeouts, task queue
  ao := workflow.ActivityOptions{
    StartToCloseTimeout: 30 * time.Second,
    RetryPolicy: &temporal.RetryPolicy{
      InitialInterval:    time.Second,
      BackoffCoefficient: 2.0,
      MaximumInterval:    30 * time.Second,
      MaximumAttempts:    5,
    },
  }
  ctx = workflow.WithActivityOptions(ctx, ao)

  // Step 1: reserve inventory (activity — runs external code)
  var reserved bool
  if err := workflow.ExecuteActivity(ctx, ReserveInventory, order.SKU, order.Qty).Get(ctx, &reserved); err != nil {
    return OrderResult{}, err
  }
  if !reserved {
    return OrderResult{Status: "out_of_stock"}, nil
  }

  // Step 2: charge payment
  var chargeID string
  if err := workflow.ExecuteActivity(ctx, ChargeCard, order.CardToken, order.TotalCents).Get(ctx, &chargeID); err != nil {
    // Compensate: release the reserved inventory
    workflow.ExecuteActivity(ctx, ReleaseInventory, order.SKU, order.Qty)
    return OrderResult{}, err
  }

  // Step 3: fulfill (ship the order)
  var trackingID string
  if err := workflow.ExecuteActivity(ctx, FulfillOrder, order, chargeID).Get(ctx, &trackingID); err != nil {
    // Compensate: refund the charge, release inventory
    workflow.ExecuteActivity(ctx, RefundCharge, chargeID)
    workflow.ExecuteActivity(ctx, ReleaseInventory, order.SKU, order.Qty)
    return OrderResult{}, err
  }

  // Step 4: send confirmation email (best-effort, no retry)
  emailCtx := workflow.WithActivityOptions(ctx, workflow.ActivityOptions{
    StartToCloseTimeout: 10 * time.Second,
    RetryPolicy:         &temporal.RetryPolicy{MaximumAttempts: 1},
  })
  workflow.ExecuteActivity(emailCtx, SendConfirmationEmail, order.Email, trackingID)

  return OrderResult{
    Status:     "fulfilled",
    TrackingID: trackingID,
    ChargeID:   chargeID,
  }, nil
}

// Activity: actual external call — can be retried safely (should be idempotent)
func ChargeCard(ctx context.Context, cardToken string, amountCents int) (string, error) {
  // Call Stripe API
  // Temporal retries this on failure — ensure your payment idempotency key
  info := activity.GetInfo(ctx)
  idempotencyKey := info.WorkflowExecution.ID + "-" + strconv.Itoa(info.Attempt)

  charge, err := stripe.Charges.New(&stripe.ChargeParams{
    Amount:         stripe.Int64(int64(amountCents)),
    Currency:       stripe.String("gbp"),
    Source:         stripe.String(cardToken),
    IdempotencyKey: &idempotencyKey,  // safe to retry with same key
  })
  if err != nil {
    return "", err
  }
  return charge.ID, nil
}
```

## Running workers and starting workflows

```go
// Worker: polls Temporal server for workflow/activity tasks and executes them
package main

import (
  "go.temporal.io/sdk/client"
  "go.temporal.io/sdk/worker"
  "go.temporal.io/sdk/workflow"
)

func main() {
  c, err := client.Dial(client.Options{
    HostPort: "temporal.messaging.svc:7233",
    Namespace: "construx-prod",
  })
  if err != nil {
    log.Fatal("failed to connect to Temporal:", err)
  }
  defer c.Close()

  w := worker.New(c, "construx-orders", worker.Options{
    MaxConcurrentActivityExecutionSize: 100,  // 100 concurrent activities
    MaxConcurrentWorkflowTaskExecutionSize: 50,
  })

  // Register the workflow and activities
  w.RegisterWorkflow(workflows.OrderWorkflow)
  w.RegisterActivity(activities.ReserveInventory)
  w.RegisterActivity(activities.ChargeCard)
  w.RegisterActivity(activities.FulfillOrder)
  w.RegisterActivity(activities.SendConfirmationEmail)
  w.RegisterActivity(activities.RefundCharge)
  w.RegisterActivity(activities.ReleaseInventory)

  if err := w.Run(worker.InterruptCh()); err != nil {
    log.Fatal("worker failed:", err)
  }
}

// Start a workflow from an API handler
func HandleOrder(w http.ResponseWriter, r *http.Request) {
  var order Order
  json.NewDecoder(r.Body).Decode(&order)

  c, _ := client.Dial(client.Options{HostPort: "temporal.messaging.svc:7233"})

  run, err := c.ExecuteWorkflow(r.Context(),
    client.StartWorkflowOptions{
      ID:        "order-" + order.ID,  // unique ID — prevents duplicate orders
      TaskQueue: "construx-orders",
    },
    workflows.OrderWorkflow,
    order,
  )
  if err != nil {
    http.Error(w, "failed to start workflow", 500)
    return
  }

  json.NewEncoder(w).Encode(map[string]string{
    "workflow_id": run.GetID(),
    "run_id":      run.GetRunID(),
  })
}
```

## Signals, queries, and long-running workflows

```go
// Signals: external events sent to a running workflow
// Useful for: user cancellation, external approval, async webhook result

const SignalApprovalResult = "approval-result"

// Approval workflow: waits for a human decision
func ApprovalWorkflow(ctx workflow.Context, request ApprovalRequest) (ApprovalResult, error) {
  // Register signal channel
  approvalCh := workflow.GetSignalChannel(ctx, SignalApprovalResult)

  // Wait up to 7 days for approval
  var approved bool
  workflow.NewSelector(ctx).
    AddReceive(approvalCh, func(ch workflow.ReceiveChannel, more bool) {
      ch.Receive(ctx, &approved)
    }).
    AddFuture(workflow.NewTimer(ctx, 7*24*time.Hour), func(f workflow.Future) {
      approved = false  // timeout = auto-deny
    }).
    Select(ctx)

  if !approved {
    return ApprovalResult{Status: "denied", Reason: "timeout or rejection"}, nil
  }
  return ApprovalResult{Status: "approved"}, nil
}

// Send the approval signal from an API endpoint
func HandleApproval(c client.Client, workflowID string, approved bool) error {
  return c.SignalWorkflow(context.Background(),
    workflowID, "",
    SignalApprovalResult,
    approved,
  )
}

// Queries: inspect running workflow state without modifying it
func SubscriptionWorkflow(ctx workflow.Context, sub Subscription) error {
  // Expose current state via query
  var status string = "active"
  workflow.SetQueryHandler(ctx, "get-status", func() (string, error) {
    return status, nil
  })

  // Run subscription lifecycle: renew monthly, handle cancellation
  for {
    status = "renewing"
    if err := workflow.ExecuteActivity(ctx, RenewSubscription, sub.ID).Get(ctx, nil); err != nil {
      status = "failed"
      return err
    }
    status = "active"

    // Sleep until next renewal (30 days)
    workflow.Sleep(ctx, 30*24*time.Hour)
  }
}

// Query the subscription status from anywhere
func CheckSubscription(c client.Client, workflowID string) string {
  var status string
  c.QueryWorkflow(context.Background(), workflowID, "", "get-status", &status)
  return status  // "active", "renewing", or "failed"
}
```

## Temporal CLI and observability

```bash
# Install Temporal CLI
brew install temporal

# Start local dev server (SQLite backend, no Docker needed)
temporal server start-dev

# List running workflows
temporal workflow list --namespace construx-prod
# WORKFLOW ID     TYPE                STATUS   START TIME
# order-ORD-9876  OrderWorkflow       Running  2033-03-23 09:01:00
# order-ORD-9877  OrderWorkflow       Completed 2033-03-23 09:00:45
# sub-12345       SubscriptionWorkflow Running  2033-01-01 00:00:00

# Describe a workflow (see complete history)
temporal workflow describe \
  --workflow-id=order-ORD-9876 \
  --namespace=construx-prod

# Show workflow history (all events: ActivityScheduled, ActivityCompleted, etc.)
temporal workflow show \
  --workflow-id=order-ORD-9876 \
  --namespace=construx-prod

# Signal a workflow (e.g., cancel an order)
temporal workflow signal \
  --workflow-id=order-ORD-9876 \
  --name=cancel-order \
  --input='{"reason":"customer request"}' \
  --namespace=construx-prod

# Query a workflow
temporal workflow query \
  --workflow-id=sub-12345 \
  --type=get-status \
  --namespace=construx-prod
# "active"

# Metrics: Temporal server exposes Prometheus metrics at :9090
curl -s http://temporal-server:9090/metrics | grep 'temporal_request_total'
# temporal_request_total{namespace="construx-prod",operation="StartWorkflow"} 8472
# temporal_request_total{namespace="construx-prod",operation="PollForActivityTask"} 2847392
```

Temporal vs AWS Step Functions vs Conductor vs custom database state machines: AWS Step Functions is managed, serverless, and integrates natively with Lambda, ECS, and other AWS services — it's the right choice if you're AWS-only and your workflows are primarily AWS service calls. The trade-off: activity code runs in Lambda or ECS, not directly in your application, and the visual designer becomes a maintenance burden for complex workflows. Netflix Conductor is open-source and similar to Temporal architecturally (event log, activities, workers) but has less active community development since Temporal's team forked from Cadence (the Uber-built predecessor to Temporal). Custom database state machines — a `status` column with transitions — work for simple 2-3 step flows but break down with retries, timeouts, compensation logic, and cross-service coordination. Temporal's replay-based durability model is the right architecture for anything with more than three steps or any external service calls that can fail.
