A language model's knowledge is frozen at its training cutoff. RAG (Retrieval-Augmented Generation) fixes this by retrieving relevant documents from your data store and injecting them as context before calling the model. The model answers from your data, not its training.

## The pipeline

1. **Ingest** — chunk your documents, embed each chunk, store in a vector database
2. **Query** — embed the user's question, find the nearest chunks, pass as context
3. **Generate** — call the LLM with the retrieved chunks + user question

## Chunking strategy

How you chunk affects retrieval quality significantly:

```ts
// lib/chunker.ts
type Chunk = { text: string; metadata: Record<string, string> };

export function chunkDocument(
  text: string,
  metadata: Record<string, string>,
  chunkSize = 512,
  overlap = 64,
): Chunk[] {
  const words = text.split(/\s+/);
  const chunks: Chunk[] = [];

  for (let i = 0; i < words.length; i += chunkSize - overlap) {
    const chunk = words.slice(i, i + chunkSize).join(' ');
    if (chunk.trim().length > 0) {
      chunks.push({ text: chunk, metadata });
    }
  }

  return chunks;
}

// Markdown-aware chunker — splits on headings
export function chunkMarkdown(content: string, metadata: Record<string, string>): Chunk[] {
  const sections = content.split(/(?=^#{1,2} )/m);
  return sections
    .filter((s) => s.trim().length > 50)
    .flatMap((section) => {
      if (section.length > 2048) {
        return chunkDocument(section, metadata, 512, 64);
      }
      return [{ text: section, metadata }];
    });
}
```

## Embeddings with Voyage AI

Anthropic recommends Voyage AI for embeddings when using Claude:

```bash
npm install voyageai
```

```ts
// lib/embeddings.ts
import VoyageAI from 'voyageai';

const voyage = new VoyageAI({ apiKey: process.env.VOYAGE_API_KEY! });

export async function embed(texts: string[]): Promise<number[][]> {
  const result = await voyage.embed({
    input: texts,
    model: 'voyage-3',
  });
  return result.data.map((d) => d.embedding);
}

export async function embedQuery(text: string): Promise<number[]> {
  const result = await voyage.embed({
    input: [text],
    model: 'voyage-3',
    inputType: 'query',
  });
  return result.data[0].embedding;
}
```

## Vector storage with pgvector

pgvector adds a vector column type to PostgreSQL. No separate vector database needed:

```sql
-- Enable the extension
CREATE EXTENSION IF NOT EXISTS vector;
```

```ts
// db/schema.ts
import { pgTable, text, timestamp, vector, index } from 'drizzle-orm/pg-core';

export const documentChunks = pgTable('document_chunks', {
  id: text('id').primaryKey().$defaultFn(() => crypto.randomUUID()),
  content: text('content').notNull(),
  embedding: vector('embedding', { dimensions: 1024 }).notNull(),
  source: text('source').notNull(),
  metadata: text('metadata').notNull().default('{}'),
  createdAt: timestamp('created_at').notNull().defaultNow(),
}, (table) => ({
  embeddingIdx: index('idx_chunks_embedding').using('hnsw', table.embedding.op('vector_cosine_ops')),
}));
```

```ts
// Ingest a document
async function ingestDocument(content: string, source: string) {
  const chunks = chunkMarkdown(content, { source });
  const texts = chunks.map((c) => c.text);
  const embeddings = await embed(texts);

  await db.insert(documentChunks).values(
    chunks.map((chunk, i) => ({
      content: chunk.text,
      embedding: embeddings[i],
      source,
      metadata: JSON.stringify(chunk.metadata),
    })),
  );
}
```

## Similarity search

```ts
// lib/retrieval.ts
import { sql } from 'drizzle-orm';

export async function retrieveChunks(
  queryEmbedding: number[],
  limit = 5,
): Promise<Array<{ content: string; source: string; similarity: number }>> {
  const embeddingStr = `[${queryEmbedding.join(',')}]`;

  const results = await db.execute<{
    content: string;
    source: string;
    similarity: number;
  }>(sql`
    SELECT
      content,
      source,
      1 - (embedding <=> ${embeddingStr}::vector) AS similarity
    FROM document_chunks
    ORDER BY embedding <=> ${embeddingStr}::vector
    LIMIT ${limit}
  `);

  return results.rows.filter((r) => r.similarity > 0.7);
}
```

## Generation with retrieved context

```ts
// lib/rag.ts
import { anthropic } from './claude';
import { embedQuery } from './embeddings';
import { retrieveChunks } from './retrieval';

export async function ragQuery(userQuestion: string): Promise<string> {
  // 1. Embed the question
  const queryEmbedding = await embedQuery(userQuestion);

  // 2. Retrieve relevant chunks
  const chunks = await retrieveChunks(queryEmbedding, 5);

  if (chunks.length === 0) {
    return "I don't have enough information to answer that question.";
  }

  // 3. Build context
  const context = chunks
    .map((c, i) => `[Source ${i + 1}: ${c.source}]\n${c.content}`)
    .join('\n\n---\n\n');

  // 4. Generate response
  const message = await anthropic.messages.create({
    model: 'claude-opus-4-8',
    max_tokens: 1024,
    system: `You are a knowledgeable assistant. Answer questions based on the provided context.
If the context doesn't contain enough information, say so.
Always cite which source(s) you're drawing from.`,
    messages: [
      {
        role: 'user',
        content: `Context:\n${context}\n\nQuestion: ${userQuestion}`,
      },
    ],
  });

  return message.content
    .filter((b) => b.type === 'text')
    .map((b) => b.text)
    .join('');
}
```

## Re-ranking

Simple cosine similarity retrieval can surface chunks that are semantically similar but not actually the most relevant. Voyage AI's re-ranker improves this:

```ts
const reranked = await voyage.rerank({
  query: userQuestion,
  documents: chunks.map((c) => c.content),
  model: 'rerank-2',
  topK: 3,
});

const topChunks = reranked.data.map((r) => chunks[r.index]);
```

Re-ranking is especially valuable when you have many retrieved chunks — it narrows to the most relevant before passing to the LLM.

## Caching embeddings

Embedding is the slowest part of ingestion. Cache embeddings for documents that don't change:

```ts
async function embedWithCache(text: string): Promise<number[]> {
  const hash = crypto.createHash('sha256').update(text).digest('hex').slice(0, 16);
  const cached = await redis.get<number[]>(`embed:${hash}`);
  if (cached) return cached;

  const [embedding] = await embed([text]);
  await redis.set(`embed:${hash}`, embedding, { ex: 86400 * 7 });
  return embedding;
}
```

The pattern: chunk carefully, embed once, retrieve by similarity, re-rank if needed, generate with context. Each step has a quality lever.
