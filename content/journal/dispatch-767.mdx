excerpt: "Effect is a TypeScript library for building programs where errors, dependencies, and async operations are explicit in the type signature. An Effect<A, E, R> succeeds with A, fails with E, and requires dependencies R. There are no untyped exceptions, no implicit globals, and no hidden async behavior. For complex applications with many failure modes — API integrations, database operations, external services — Effect makes the error paths as visible as the happy path."

Errors in the type signature. Dependencies injected rather than imported. Async that composes cleanly.

## Install

```bash
npm install effect
```

## Basic Effect

```ts
import { Effect, pipe } from 'effect';

// Effect<string, never, never>
// Succeeds with string, never fails, no dependencies
const hello = Effect.succeed('Hello, Effect');

// Effect<never, Error, never>
// Always fails
const boom = Effect.fail(new Error('something went wrong'));

// Run an effect
const result = await Effect.runPromise(hello);
console.log(result);  // "Hello, Effect"
```

## Typed errors

```ts
import { Effect, Data } from 'effect';

// Tagged errors — discriminated union, no instanceof checks
class NotFoundError extends Data.TaggedError('NotFoundError')<{
  id: string;
}> {}

class DatabaseError extends Data.TaggedError('DatabaseError')<{
  cause: unknown;
}> {}

// Effect<User, NotFoundError | DatabaseError, never>
const getUser = (id: string): Effect.Effect<User, NotFoundError | DatabaseError> =>
  Effect.tryPromise({
    try: () => db.users.findUnique({ where: { id } }),
    catch: (e) => new DatabaseError({ cause: e }),
  }).pipe(
    Effect.flatMap((user) =>
      user ? Effect.succeed(user) : Effect.fail(new NotFoundError({ id })),
    ),
  );
```

## Dependency injection with Context

```ts
import { Context, Layer } from 'effect';

// Define a service interface
class EmailService extends Context.Tag('EmailService')<
  EmailService,
  {
    send: (to: string, subject: string, html: string) => Effect.Effect<void>
  }
>() {}

// Production implementation
const EmailServiceLive = Layer.succeed(EmailService, {
  send: (to, subject, html) =>
    Effect.tryPromise({
      try: () => resend.emails.send({ from: 'hello@construxgroup.io', to, subject, html }),
      catch: (e) => new EmailError({ cause: e }),
    }),
});

// Test implementation
const EmailServiceTest = Layer.succeed(EmailService, {
  send: (to, subject) =>
    Effect.sync(() => console.log(`[TEST] Would send to ${to}: ${subject}`)),
});
```

## Using the service

```ts
// Effect<void, NotFoundError | EmailError, EmailService>
const sendWelcomeEmail = (userId: string) =>
  pipe(
    getUser(userId),
    Effect.flatMap((user) =>
      EmailService.pipe(
        Effect.flatMap((email) =>
          email.send(user.email, 'Welcome!', '<p>Welcome to Construx</p>'),
        ),
      ),
    ),
  );

// Provide the live implementation to run
const program = pipe(
  sendWelcomeEmail('usr_abc'),
  Effect.provide(EmailServiceLive),
);

await Effect.runPromise(program);
```

## Error handling

```ts
// Handle specific errors
const result = pipe(
  getUser('usr_abc'),
  Effect.catchTag('NotFoundError', (err) =>
    Effect.succeed({ id: err.id, email: 'anonymous', name: null }),
  ),
  Effect.catchTag('DatabaseError', (err) =>
    Effect.fail(new ServiceUnavailableError({ cause: err })),
  ),
);

// Match on success and failure
const handled = pipe(
  getUser('usr_abc'),
  Effect.match({
    onSuccess: (user) => `Found: ${user.email}`,
    onFailure: (err) => `Failed: ${err._tag}`,
  }),
);
```

## Schema validation (built-in)

```ts
import { Schema } from 'effect';

const UserSchema = Schema.Struct({
  id:    Schema.UUID,
  email: Schema.String.pipe(Schema.pattern(/^.+@.+\..+$/)),
  age:   Schema.Int.pipe(Schema.between(0, 150)),
});

type User = Schema.Schema.Type<typeof UserSchema>;

const decode = Schema.decodeUnknown(UserSchema);

// Effect<User, ParseError, never>
const parseUser = (raw: unknown) => decode(raw);
```

Effect vs fp-ts vs neverthrow: Effect is more complete (dependency injection, scheduling, streaming) but has a steeper learning curve. fp-ts is purely functional without the runtime overhead. neverthrow is a lightweight Result type without the full Effect system. The Construx default: neverthrow for simple error handling; Effect for complex service-oriented code with many failure modes and dependencies.
