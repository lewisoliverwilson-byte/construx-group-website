Jest is the default test runner for most JavaScript projects. But Jest runs in CommonJS mode by default, which means: transpilation overhead, `__mocks__` directories, manual module mocking, and occasional "works in browser, fails in test" bugs from CommonJS/ESM mismatches. Vitest fixes all of this by running inside Vite.

## Setup

```bash
npm install -D vitest @vitest/ui jsdom @testing-library/react @testing-library/user-event
```

```ts
// vitest.config.ts
import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';
import path from 'path';

export default defineConfig({
  plugins: [react()],
  test: {
    environment:    'jsdom',
    globals:        true,
    setupFiles:     ['./src/test/setup.ts'],
    alias: {
      '@': path.resolve(__dirname, './src'),
    },
  },
});
```

If you have a `vite.config.ts`, you can extend it instead of creating a separate `vitest.config.ts` — Vitest reads both.

```ts
// src/test/setup.ts
import '@testing-library/jest-dom';  // adds .toBeInTheDocument(), .toHaveClass(), etc.
```

## Writing tests

```ts
// src/lib/format.test.ts
import { describe, it, expect } from 'vitest';
import { formatCurrency, formatDate } from './format';

describe('formatCurrency', () => {
  it('formats GBP correctly', () => {
    expect(formatCurrency(1999, 'GBP')).toBe('£19.99');
  });

  it('handles zero', () => {
    expect(formatCurrency(0, 'GBP')).toBe('£0.00');
  });
});

describe('formatDate', () => {
  it('formats ISO date as readable string', () => {
    expect(formatDate('2029-11-23')).toBe('23 November 2029');
  });
});
```

The API is Jest-compatible: `describe`, `it`/`test`, `expect`, `beforeEach`, `afterEach`, `beforeAll`, `afterAll`. Most Jest test suites work in Vitest without changes.

## React component tests

```tsx
// src/components/Button.test.tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { Button } from './Button';

it('calls onClick when clicked', async () => {
  const user    = userEvent.setup();
  const onClick = vi.fn();

  render(<Button onClick={onClick}>Submit</Button>);

  await user.click(screen.getByRole('button', { name: 'Submit' }));

  expect(onClick).toHaveBeenCalledOnce();
});

it('shows disabled state', () => {
  render(<Button disabled>Submit</Button>);
  expect(screen.getByRole('button')).toBeDisabled();
});
```

`vi` is Vitest's equivalent of `jest` — same API for mocking, spying, and timers.

## Mocking

```ts
// Auto mock a module
vi.mock('./db', () => ({
  db: {
    post: {
      findMany: vi.fn().mockResolvedValue([
        { id: '1', title: 'Test post', status: 'published' },
      ]),
    },
  },
}));

// Mock a specific function
vi.spyOn(resend, 'send').mockResolvedValue({ id: 'email-123' });

// Mock time
vi.useFakeTimers();
vi.setSystemTime(new Date('2029-11-23'));
// ... test
vi.useRealTimers();
```

Unlike Jest's `jest.mock()`, Vitest's `vi.mock()` is hoisted automatically using Vite's transform pipeline — no babel plugin needed.

## Coverage

```bash
npm install -D @vitest/coverage-v8

# vitest.config.ts
test: {
  coverage: {
    provider: 'v8',
    reporter: ['text', 'html', 'json'],
    include:  ['src/**/*.{ts,tsx}'],
    exclude:  ['src/**/*.test.{ts,tsx}', 'src/test/**'],
  },
}
```

```bash
vitest run --coverage          # run and generate coverage report
vitest --ui                    # visual test runner + coverage UI
```

`@vitest/coverage-v8` uses V8's native coverage — no instrumentation overhead. `@vitest/coverage-istanbul` is the alternative for Istanbul-compatible reports (needed for some CI integrations).

## Running tests

```bash
vitest              # watch mode (default) — re-runs affected tests on file change
vitest run          # CI mode — run once and exit
vitest run --reporter=verbose  # detailed output per test
vitest ui           # browser-based visual runner
```

Watch mode in Vitest is fast because it uses Vite's module graph. If you change `formatCurrency`, only tests that import it re-run — not the full test suite.

## Snapshot testing

```ts
it('renders correctly', () => {
  const { container } = render(<Card title="Hello" />);
  expect(container.firstChild).toMatchSnapshot();
});
```

Snapshots are stored in `__snapshots__/` next to the test file. Update them with `vitest run -u`.

## When Vitest over Jest

Vitest is the right default for: Next.js (App Router), Vite-based projects, any project using ESM or import aliases, and projects that need fast watch mode. Jest is still reasonable for: projects heavily invested in Jest-specific tooling, React Native (Jest's snapshot serializers are better integrated), or teams that need `jest-environment-node` for complex Node API testing.

For new projects in 2029, Vitest is the better default.
