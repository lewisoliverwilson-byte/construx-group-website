Framer Motion wraps React elements in a `motion.` component and adds animation props. The API is declarative: you describe the start, end, and transition — Motion handles the interpolation and physics.

## Basic animation

```tsx
import { motion } from 'framer-motion';

// Fade in on mount
<motion.div
  initial={{ opacity: 0, y: 20 }}
  animate={{ opacity: 1, y: 0 }}
  transition={{ duration: 0.4, ease: [0.16, 1, 0.3, 1] }}
>
  Content
</motion.div>
```

The easing `[0.16, 1, 0.3, 1]` is a custom cubic bezier — fast start, sharp deceleration. It's the curve used by iOS and is noticeably better than linear or ease-out for entrance animations.

## Exit animations with AnimatePresence

`AnimatePresence` allows components to animate before they unmount. Without it, exit animations don't run because React removes the element immediately.

```tsx
import { AnimatePresence, motion } from 'framer-motion';

function Modal({ isOpen, onClose, children }) {
  return (
    <AnimatePresence>
      {isOpen && (
        <>
          {/* Backdrop */}
          <motion.div
            initial={{ opacity: 0 }}
            animate={{ opacity: 1 }}
            exit={{ opacity: 0 }}
            className="fixed inset-0 bg-black/60"
            onClick={onClose}
          />
          {/* Panel */}
          <motion.div
            initial={{ x: '100%', opacity: 0 }}
            animate={{ x: 0, opacity: 1 }}
            exit={{ x: '100%', opacity: 0 }}
            transition={{ type: 'spring', damping: 26, stiffness: 210 }}
            className="fixed right-0 top-0 h-full w-80"
          >
            {children}
          </motion.div>
        </>
      )}
    </AnimatePresence>
  );
}
```

Always wrap dynamic content in `AnimatePresence` when the presence of elements changes. The `key` prop on animated elements is required when switching between items.

## Spring physics

Spring animations feel physical in a way that duration-based animations don't:

```tsx
// Bouncy — feels playful
transition={{ type: 'spring', stiffness: 400, damping: 15 }}

// Tight — feels responsive, no bounce
transition={{ type: 'spring', stiffness: 300, damping: 30 }}

// Slow, heavy — feels substantial
transition={{ type: 'spring', stiffness: 100, damping: 20 }}
```

Rule of thumb: use spring for UI interactions (button hover, panel open), use duration for decorative animations (fade-in on scroll, background effects).

## Viewport animations — whileInView

```tsx
// Animate when element enters the viewport
<motion.article
  initial={{ opacity: 0, y: 40 }}
  whileInView={{ opacity: 1, y: 0 }}
  viewport={{ once: true, margin: '-80px' }}
  transition={{ duration: 0.6, ease: [0.16, 1, 0.3, 1] }}
>
```

`viewport={{ once: true }}` is important — without it the animation replays every time the element enters the viewport, which feels broken on scroll-up.

## Scroll-linked animations with useScroll

```tsx
import { useScroll, useTransform, motion } from 'framer-motion';
import { useRef } from 'react';

function ParallaxSection() {
  const ref = useRef<HTMLDivElement>(null);
  const { scrollYProgress } = useScroll({ target: ref, offset: ['start end', 'end start'] });
  const y = useTransform(scrollYProgress, [0, 1], ['0%', '20%']);
  const opacity = useTransform(scrollYProgress, [0, 0.5, 1], [0, 1, 0]);

  return (
    <div ref={ref} className="relative h-screen">
      <motion.div style={{ y, opacity }} className="absolute inset-0">
        <img src="/hero.jpg" className="w-full h-full object-cover" />
      </motion.div>
    </div>
  );
}
```

## Layout animations

Layout animations automatically animate changes in size and position:

```tsx
function ExpandableCard({ isExpanded, onToggle }) {
  return (
    <motion.div
      layout
      onClick={onToggle}
      className={isExpanded ? 'h-64' : 'h-16'}
    >
      <motion.h3 layout="position">Card title</motion.h3>
      {isExpanded && (
        <motion.p
          initial={{ opacity: 0 }}
          animate={{ opacity: 1 }}
          exit={{ opacity: 0 }}
        >
          Expanded content
        </motion.p>
      )}
    </motion.div>
  );
}
```

`layout` on the parent handles size changes. `layout="position"` on children prevents them from distorting during the parent's resize.

## Stagger children

```tsx
const containerVariants = {
  hidden: {},
  show: {
    transition: {
      staggerChildren: 0.08,
    },
  },
};

const itemVariants = {
  hidden: { opacity: 0, y: 16 },
  show: { opacity: 1, y: 0, transition: { duration: 0.4, ease: [0.16, 1, 0.3, 1] } },
};

function List({ items }) {
  return (
    <motion.ul variants={containerVariants} initial="hidden" animate="show">
      {items.map((item) => (
        <motion.li key={item.id} variants={itemVariants}>
          {item.name}
        </motion.li>
      ))}
    </motion.ul>
  );
}
```

Variants propagate automatically from parent to children. The parent's `animate="show"` triggers children to animate using their own `show` variant.

## Performance

Keep animations on `opacity` and `transform` (translate, scale, rotate). These are GPU-composited and don't trigger layout. Avoid animating `height`, `width`, `top`, `left` — they cause repaints.

```tsx
// Good — GPU composited
animate={{ opacity: 1, scale: 1.05, x: 10 }}

// Bad — triggers layout
animate={{ height: 200, top: 40 }}
```

For height animations where layout is unavoidable, `motion.div` with `layout` is better than animating `height` directly.
