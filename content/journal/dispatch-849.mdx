TypeScript runs directly. Permissions are explicit. Toolchain is built in.

## Run TypeScript without compilation

```bash
# Run a TypeScript file directly — no tsconfig, no tsc
deno run main.ts

# Run with network and file permissions
deno run --allow-net --allow-read main.ts

# Run from a URL
deno run https://deno.land/std/examples/welcome.ts

# Run with all permissions (use sparingly)
deno run --allow-all main.ts

# REPL
deno repl
```

## HTTP server — built-in Fetch API

```ts
// main.ts — no imports needed for built-in APIs
const server = Deno.serve({ port: 8000 }, async (req: Request) => {
  const url = new URL(req.url);

  if (url.pathname === '/health') {
    return Response.json({ ok: true });
  }

  if (url.pathname === '/orders' && req.method === 'GET') {
    const orders = await fetchOrders();
    return Response.json(orders);
  }

  return new Response('Not found', { status: 404 });
});

console.log('Server running on http://localhost:8000');
await server.finished;
```

## Import from npm (Deno 2)

```ts
// Deno 2 supports npm: specifiers — no install step
import { Hono } from 'npm:hono@4';
import { z }    from 'npm:zod@3';
import postgres  from 'npm:postgres@3';

const app  = new Hono();
const sql  = postgres(Deno.env.get('DATABASE_URL')!);

const OrderSchema = z.object({
  customerId:  z.string().uuid(),
  totalCents:  z.number().int().positive(),
});

app.post('/orders', async (c) => {
  const parsed = OrderSchema.safeParse(await c.req.json());
  if (!parsed.success) return c.json({ errors: parsed.error.errors }, 422);

  const [order] = await sql`
    INSERT INTO orders (customer_id, total_cents)
    VALUES (${parsed.data.customerId}, ${parsed.data.totalCents})
    RETURNING *
  `;

  return c.json(order, 201);
});

Deno.serve({ port: 3000 }, app.fetch);
```

## Built-in test runner

```ts
// orders_test.ts
import { assertEquals, assertRejects } from 'jsr:@std/assert';
import { createOrder }                  from './orders.ts';

Deno.test('createOrder — valid input', async () => {
  const order = await createOrder({ customerId: 'cust-001', totalCents: 4999 });
  assertEquals(order.status, 'pending');
  assertEquals(order.totalCents, 4999);
});

Deno.test('createOrder — rejects zero total', async () => {
  await assertRejects(
    () => createOrder({ customerId: 'cust-001', totalCents: 0 }),
    Error,
    'totalCents must be positive',
  );
});

// Subtests
Deno.test('order status transitions', async (t) => {
  const order = await createOrder({ customerId: 'cust-001', totalCents: 999 });

  await t.step('can move to processing', async () => {
    const updated = await transitionOrder(order.id, 'processing');
    assertEquals(updated.status, 'processing');
  });

  await t.step('cannot move from pending to shipped', async () => {
    await assertRejects(() => transitionOrder(order.id, 'shipped'));
  });
});
```


## Permissions model

```bash
# Fine-grained permission flags
deno run \
  --allow-net=api.construxgroup.io,database.construxgroup.io \
  --allow-read=/tmp,/etc/ssl \
  --allow-env=DATABASE_URL,JWT_SECRET \
  --deny-write \
  main.ts

# If the code tries to access anything not granted:
# error: Requires net access to "stripe.com", specify with --allow-net
```

Deno vs Node.js: Node.js needs TypeScript compilation (tsc / esbuild / swc), a package.json with devDependencies for every tool (eslint, prettier, jest/vitest), and has no permission model — any module can read files or make network requests. Deno ships the whole toolchain in one binary and sandboxes code. The tradeoff: Node.js has a larger ecosystem and more mature npm packages; Deno's `npm:` specifiers close the gap significantly in Deno 2, but some packages with native bindings still don't work.
