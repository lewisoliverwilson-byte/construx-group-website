title: "Tekton Pipelines: cloud-native CI/CD on Kubernetes — Tasks, Pipelines, Triggers, Chains"
date: "2033-12-12"
excerpt: "Tekton is a cloud-native CI/CD framework built on Kubernetes CRDs. Where GitHub Actions runs pipelines on GitHub-managed compute and Argo Workflows (dispatch-1087) is a general-purpose DAG execution engine, Tekton is specifically designed for build and delivery pipelines that run on your own Kubernetes cluster. The core resources are: Task (a sequence of steps, each a container), Pipeline (a DAG of Tasks with parameter and workspace passing between them), TaskRun and PipelineRun (instantiations of Tasks/Pipelines), and Workspace (shared storage between Task steps — a PersistentVolumeClaim or emptyDir). Tekton Triggers adds event-driven pipeline execution: an EventListener receives webhook events (GitHub push, pull request), a TriggerBinding extracts fields from the event payload, and a TriggerTemplate creates a PipelineRun from those fields. Tekton Chains adds supply chain security: it intercepts every TaskRun completion and signs the build attestation (what was built, by what Task, from what source) using Sigstore/cosign, then stores the signature in a transparency log. This gives you a cryptographically verifiable record of every artifact's provenance — which commit triggered the build, which container ran it, what the output image digest is."

## Pipeline definition: build, scan, push, deploy

```yaml
# Task: build container image with Kaniko (no Docker daemon required)
apiVersion: tekton.dev/v1
kind: Task
metadata:
  name: kaniko-build
  namespace: tekton-pipelines
spec:
  params:
    - name: image
      description: Full image ref to push (e.g. registry.construx.internal/orders-api:sha)
    - name: context
      default: "."
    - name: dockerfile
      default: "Dockerfile"
  workspaces:
    - name: source      # git clone workspace
    - name: dockerconfig
      description: Docker registry credentials
  results:
    - name: IMAGE_DIGEST
      description: SHA256 digest of built image
  steps:
    - name: build-and-push
      image: gcr.io/kaniko-project/executor:v1.23.0
      args:
        - --dockerfile=$(workspaces.source.path)/$(params.dockerfile)
        - --context=$(workspaces.source.path)/$(params.context)
        - --destination=$(params.image)
        - --digest-file=$(results.IMAGE_DIGEST.path)
        - --cache=true
        - --cache-repo=registry.construx.internal/kaniko-cache
      volumeMounts:
        - name: docker-config
          mountPath: /kaniko/.docker/
  volumes:
    - name: docker-config
      secret:
        secretName: registry-credentials
        items:
          - key: .dockerconfigjson
            path: config.json

---
# Task: Trivy vulnerability scan — fail pipeline if CRITICAL CVEs found
apiVersion: tekton.dev/v1
kind: Task
metadata:
  name: trivy-scan
  namespace: tekton-pipelines
spec:
  params:
    - name: image
    - name: severity
      default: "CRITICAL,HIGH"
  steps:
    - name: scan
      image: aquasec/trivy:0.57.0
      command: [trivy]
      args:
        - image
        - --exit-code=1
        - --severity=$(params.severity)
        - --ignore-unfixed
        - --format=json
        - --output=/tmp/trivy-report.json
        - $(params.image)

---
# Pipeline: git clone → build → scan → deploy (Argo CD sync)
apiVersion: tekton.dev/v1
kind: Pipeline
metadata:
  name: construx-build-deploy
  namespace: tekton-pipelines
spec:
  params:
    - name: git-url
    - name: git-revision
    - name: image-name
    - name: app-name
  workspaces:
    - name: source
    - name: docker-credentials
  tasks:
    - name: clone
      taskRef:
        resolver: hub
        params:
          - { name: catalog, value: tekton-catalog-tasks }
          - { name: type, value: artifact }
          - { name: kind, value: task }
          - { name: name, value: git-clone }
          - { name: version, value: "0.9" }
      params:
        - { name: url, value: $(params.git-url) }
        - { name: revision, value: $(params.git-revision) }
      workspaces:
        - { name: output, workspace: source }

    - name: build
      runAfter: [clone]
      taskRef:
        name: kaniko-build
      params:
        - name: image
          value: registry.construx.internal/$(params.image-name):$(params.git-revision)
      workspaces:
        - { name: source, workspace: source }
        - { name: dockerconfig, workspace: docker-credentials }

    - name: scan
      runAfter: [build]
      taskRef:
        name: trivy-scan
      params:
        - name: image
          value: registry.construx.internal/$(params.image-name):$(params.git-revision)

    - name: deploy
      runAfter: [scan]
      taskRef:
        resolver: hub
        params:
          - { name: name, value: argocd-task-sync-and-wait }
          - { name: version, value: "0.2" }
      params:
        - name: application-name
          value: $(params.app-name)
        - name: revision
          value: $(params.git-revision)
```

## Tekton Triggers: GitHub webhook → PipelineRun

```yaml
# EventListener: receive GitHub push webhooks
apiVersion: triggers.tekton.dev/v1beta1
kind: EventListener
metadata:
  name: github-push
  namespace: tekton-pipelines
spec:
  serviceAccountName: tekton-triggers-sa
  triggers:
    - name: push-to-main
      interceptors:
        - ref: { name: github }
          params:
            - { name: secretRef, value: { secretName: github-webhook-secret, secretKey: secret } }
            - { name: eventTypes, value: [push] }
        - ref: { name: cel }
          params:
            - name: filter
              value: "body.ref == 'refs/heads/main'"
      bindings:
        - ref: github-push-binding
      template:
        ref: construx-build-deploy-template

---
apiVersion: triggers.tekton.dev/v1beta1
kind: TriggerBinding
metadata:
  name: github-push-binding
spec:
  params:
    - { name: git-url,      value: $(body.repository.clone_url) }
    - { name: git-revision, value: $(body.after) }
    - { name: app-name,     value: $(body.repository.name) }
    - { name: image-name,   value: $(body.repository.name) }

---
apiVersion: triggers.tekton.dev/v1beta1
kind: TriggerTemplate
metadata:
  name: construx-build-deploy-template
spec:
  params:
    - name: git-url
    - name: git-revision
    - name: app-name
    - name: image-name
  resourcetemplates:
    - apiVersion: tekton.dev/v1
      kind: PipelineRun
      metadata:
        generateName: construx-build-deploy-
      spec:
        pipelineRef:
          name: construx-build-deploy
        params:
          - { name: git-url,      value: $(tt.params.git-url) }
          - { name: git-revision, value: $(tt.params.git-revision) }
          - { name: app-name,     value: $(tt.params.app-name) }
          - { name: image-name,   value: $(tt.params.image-name) }
        workspaces:
          - name: source
            volumeClaimTemplate:
              spec:
                accessModes: [ReadWriteOnce]
                resources:
                  requests:
                    storage: 1Gi
          - name: docker-credentials
            secret:
              secretName: registry-credentials
```

Tekton vs GitHub Actions vs Argo Workflows vs Jenkins vs Drone: GitHub Actions is the dominant CI/CD platform for teams whose code is on GitHub — zero infrastructure to manage, excellent GitHub integration (PR status, environment deployments), 30,000+ marketplace actions. For software delivery pipelines triggered by code events, GitHub Actions wins on simplicity. Argo Workflows (dispatch-1087) is a general-purpose DAG execution engine — excellent for ML training pipelines and ETL jobs but not designed with CI/CD-specific concepts (image building, registry push, deployment status). Jenkins is the legacy CI workhorse — deeply configurable but requires significant infrastructure management and Groovy-based Jenkinsfiles that age poorly. Drone is a lightweight Docker-based CI system — simpler than Jenkins but less ecosystem depth than GitHub Actions. Tekton's advantage is running entirely inside your own cluster with no external CI SaaS dependency — every build step runs in a pod on your nodes, credentials never leave your infrastructure, and Tekton Chains provides cryptographic build attestation. For regulated industries (financial services, healthcare, defence) where build provenance and supply chain security are compliance requirements, Tekton with Chains is the production choice.
