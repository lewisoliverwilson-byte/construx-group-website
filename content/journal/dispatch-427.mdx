Both Drizzle and Prisma are production-ready TypeScript ORMs. The choice comes down to your preferences around SQL control, bundle size, and DX. Neither is wrong — they make different tradeoffs.

## The core difference

**Drizzle** is SQL-first. You write TypeScript that maps closely to SQL. The ORM doesn't abstract SQL away — it enhances it with types.

**Prisma** is schema-first. You define your data model in a Prisma schema file, generate a client, and interact with a type-safe client that handles the SQL for you. Less SQL, more abstraction.

## Schema definition

**Drizzle:**

```ts
// db/schema.ts — TypeScript is the schema
import { pgTable, text, timestamp, integer, uuid, index } from 'drizzle-orm/pg-core';

export const users = pgTable('users', {
  id: uuid('id').primaryKey().defaultRandom(),
  email: text('email').notNull().unique(),
  name: text('name').notNull(),
  createdAt: timestamp('created_at').notNull().defaultNow(),
});

export const posts = pgTable('posts', {
  id: uuid('id').primaryKey().defaultRandom(),
  title: text('title').notNull(),
  content: text('content').notNull(),
  authorId: uuid('author_id').notNull().references(() => users.id),
  createdAt: timestamp('created_at').notNull().defaultNow(),
}, (table) => ({
  authorIdx: index('idx_posts_author').on(table.authorId),
}));
```

**Prisma:**

```prisma
// prisma/schema.prisma — separate DSL file
model User {
  id        String   @id @default(uuid())
  email     String   @unique
  name      String
  createdAt DateTime @default(now())
  posts     Post[]
}

model Post {
  id        String   @id @default(uuid())
  title     String
  content   String
  author    User     @relation(fields: [authorId], references: [id])
  authorId  String
  createdAt DateTime @default(now())

  @@index([authorId])
}
```

Drizzle schema lives in TypeScript files and can share types with application code. Prisma schema requires a separate `.prisma` file and a codegen step.

## Querying

**Drizzle:**

```ts
import { db } from '@/lib/db';
import { posts, users } from '@/db/schema';
import { eq, desc, and, like } from 'drizzle-orm';

// Simple query
const recentPosts = await db.query.posts.findMany({
  orderBy: desc(posts.createdAt),
  limit: 10,
  with: { author: true },
});

// Complex query with SQL
const results = await db
  .select({
    post: posts,
    authorName: users.name,
  })
  .from(posts)
  .leftJoin(users, eq(posts.authorId, users.id))
  .where(
    and(
      like(posts.title, `%${query}%`),
      eq(posts.published, true),
    ),
  )
  .orderBy(desc(posts.createdAt))
  .limit(20);
```

**Prisma:**

```ts
import { prisma } from '@/lib/prisma';

// Simple query
const recentPosts = await prisma.post.findMany({
  orderBy: { createdAt: 'desc' },
  take: 10,
  include: { author: true },
});

// Complex query
const results = await prisma.post.findMany({
  where: {
    title: { contains: query },
    published: true,
  },
  orderBy: { createdAt: 'desc' },
  take: 20,
  select: {
    id: true,
    title: true,
    author: { select: { name: true } },
  },
});
```

Drizzle's query syntax feels closer to SQL. Prisma's syntax is more abstracted and arguably more readable for simple queries.

## Raw SQL

**Drizzle:**

```ts
import { sql } from 'drizzle-orm';

// Raw SQL when you need it
const result = await db.execute(sql`
  SELECT id, title,
         ts_rank(to_tsvector('english', content), plainto_tsquery('english', ${query})) AS rank
  FROM posts
  WHERE to_tsvector('english', content) @@ plainto_tsquery('english', ${query})
  ORDER BY rank DESC
  LIMIT 10
`);
```

**Prisma:**

```ts
// Raw SQL with Prisma
const result = await prisma.$queryRaw<Post[]>`
  SELECT id, title FROM posts
  WHERE to_tsvector('english', content) @@ plainto_tsquery('english', ${query})
  ORDER BY ts_rank(to_tsvector('english', content), plainto_tsquery('english', ${query})) DESC
  LIMIT 10
`;
```

Both support raw SQL. Drizzle's `sql` template literal is the more ergonomic option.

## Bundle size and cold starts

Drizzle is significantly smaller:
- Drizzle: ~30KB bundled
- Prisma: Prisma Client is ~10MB (includes engine binaries)

For serverless/edge functions, this matters. Prisma's cold start time is noticeably higher because of the engine binary initialization. Drizzle has no engine — it generates raw SQL and sends it to the database driver.

## Migrations

Both support migrations, but differently.

Drizzle generates SQL migration files that you own and can edit:
```bash
npx drizzle-kit generate  # generates SQL file
npx drizzle-kit migrate   # applies it
```

Prisma uses its own migration engine:
```bash
npx prisma migrate dev    # generates and applies
npx prisma migrate deploy # applies in production
```

Prisma's migration experience is slightly more polished. Drizzle gives you more control over the SQL.

## The recommendation

**Choose Drizzle if:**
- You're on serverless/edge functions (bundle size matters)
- You want full SQL control
- You're comfortable with SQL
- You need a monorepo setup with shared schema types

**Choose Prisma if:**
- You want a more abstracted ORM experience
- Your team isn't SQL-comfortable
- You need Prisma-specific features (Prisma Pulse for real-time, Prisma Accelerate for edge)
- DX over raw control is the priority

Both will serve you well. At Construx, we use Drizzle — the bundle size and edge compatibility are the deciding factors for our serverless deployments.
