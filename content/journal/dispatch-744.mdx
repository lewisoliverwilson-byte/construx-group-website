Workers are stateless. Durable Objects are stateful. Together they cover every edge computing use case.

## Core concept

A Durable Object is a JavaScript class that runs as a single global instance. All requests to a given ID go to the same object. The object has:
- Durable storage (key-value, backed by SQLite in 2031)
- A WebSocket connection it can hold indefinitely
- A guarantee of single-instance — no race conditions

## Define a Durable Object

```ts
// src/chat-room.ts
import { DurableObject } from 'cloudflare:workers';

export class ChatRoom extends DurableObject {
  private sessions: Set<WebSocket> = new Set();

  async fetch(request: Request): Promise<Response> {
    const url = new URL(request.url);

    if (url.pathname === '/ws') {
      // Upgrade to WebSocket
      const { 0: client, 1: server } = new WebSocketPair();
      this.ctx.acceptWebSocket(server);
      return new Response(null, { status: 101, webSocket: client });
    }

    if (url.pathname === '/messages') {
      // Get message history from durable storage
      const messages = await this.ctx.storage.get<string[]>('messages') ?? [];
      return Response.json(messages);
    }

    return new Response('Not found', { status: 404 });
  }

  webSocketMessage(ws: WebSocket, message: string): void {
    // Broadcast to all connected clients in this room
    const data = JSON.parse(message);
    const outgoing = JSON.stringify({ ...data, timestamp: Date.now() });

    for (const session of this.ctx.getWebSockets()) {
      session.send(outgoing);
    }

    // Persist to durable storage
    this.ctx.storage.get<string[]>('messages').then((messages = []) => {
      const updated = [...messages, outgoing].slice(-100); // keep last 100
      this.ctx.storage.put('messages', updated);
    });
  }

  webSocketClose(ws: WebSocket): void {
    ws.close();
  }
}
```

## Worker that routes to the Durable Object

```ts
// src/index.ts
import { ChatRoom } from './chat-room';

export { ChatRoom };  // Must export the class

interface Env {
  CHAT_ROOM: DurableObjectNamespace<ChatRoom>;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    if (url.pathname.startsWith('/room/')) {
      const roomId = url.pathname.split('/')[2];

      // Each room ID gets its own isolated Durable Object instance
      const id     = env.CHAT_ROOM.idFromName(roomId);
      const stub   = env.CHAT_ROOM.get(id);

      return stub.fetch(request);
    }

    return new Response('Not found', { status: 404 });
  },
};
```

## SQLite storage (2031)

```ts
export class RoomState extends DurableObject {
  sql: SqlStorage;

  constructor(ctx: DurableObjectState, env: Env) {
    super(ctx, env);
    this.sql = ctx.storage.sql;

    this.sql.exec(`
      CREATE TABLE IF NOT EXISTS messages (
        id        INTEGER PRIMARY KEY AUTOINCREMENT,
        content   TEXT    NOT NULL,
        author    TEXT    NOT NULL,
        timestamp INTEGER NOT NULL
      )
    `);
  }

  async addMessage(content: string, author: string) {
    this.sql.exec(
      'INSERT INTO messages (content, author, timestamp) VALUES (?, ?, ?)',
      content, author, Date.now(),
    );
  }

  async getMessages(limit = 50) {
    return this.sql.exec(
      'SELECT * FROM messages ORDER BY timestamp DESC LIMIT ?',
      limit,
    ).toArray();
  }
}
```

## Durable Objects vs Redis for real-time

Redis: separate service, network hop, scales horizontally. Durable Objects: co-located with the Worker, no network hop, one instance per room. For features where a room has a single owner (chat, collaborative doc, game session), Durable Objects have lower latency and simpler code. For features that need to query across all rooms, Redis (or a database) is still the right choice.
