excerpt: "iptables is the Linux kernel's packet filtering framework, built on the Netfilter hooks in the network stack. Rules are organised into tables (filter, nat, mangle, raw) and chains (INPUT, OUTPUT, FORWARD, PREROUTING, POSTROUTING). The kernel evaluates rules top-to-bottom, stopping at the first match — rule ordering matters. Connection tracking (conntrack) enables stateful rules: once a connection is ESTABLISHED, return packets are automatically allowed without needing an explicit rule. iptables is being superseded by nftables (unified syntax, better performance, atomic rule updates), but remains ubiquitous in production systems and underpins Docker's networking model."

Rules cascade top-down. First match wins. Conntrack tracks every flow.

## Tables, chains, and the packet path

```bash
# iptables tables and their purpose:
# filter  — default: INPUT, OUTPUT, FORWARD. Accept or drop packets.
# nat     — PREROUTING, POSTROUTING, OUTPUT. Rewrite source/dest addresses.
# mangle  — modify packet headers (TTL, TOS, mark for routing)
# raw     — bypass conntrack for specific traffic (performance optimisation)

# Packet path through netfilter (simplified):
# Incoming: PREROUTING(raw→mangle→nat) → routing decision → INPUT(mangle→filter) → process
# Forwarded: PREROUTING → FORWARD(mangle→filter) → POSTROUTING(mangle→nat) → out
# Outgoing: OUTPUT(raw→mangle→nat→filter) → POSTROUTING → out

# View all rules with line numbers
iptables -L INPUT -n -v --line-numbers
# Chain INPUT (policy DROP)
# num   pkts bytes target  prot opt in  out  source          destination
#   1  42318  18M  ACCEPT  all  --  lo  any  anywhere        anywhere
#   2  1293K 892M  ACCEPT  all  --  any any  anywhere        anywhere       ctstate RELATED,ESTABLISHED
#   3    284  18K  ACCEPT  tcp  --  any any  anywhere        anywhere       tcp dpt:22
#   4      0     0 ACCEPT  tcp  --  any any  anywhere        anywhere       tcp dpt:443
#   5      0     0 ACCEPT  tcp  --  any any  anywhere        anywhere       tcp dpt:80
#   6   8432  504K DROP    all  --  any any  anywhere        anywhere

# Default policy: DROP everything not explicitly accepted
iptables -P INPUT   DROP
iptables -P FORWARD DROP
iptables -P OUTPUT  ACCEPT   # Outbound unrestricted
```

## Stateful firewall — conntrack

```bash
# Flush existing rules (start clean)
iptables -F        # Flush all chains
iptables -X        # Delete user-defined chains
iptables -t nat -F # Flush NAT table

# Stateful base rules
# 1. Loopback always allowed
iptables -A INPUT -i lo -j ACCEPT

# 2. Allow ESTABLISHED and RELATED connections (conntrack)
# This is what makes iptables "stateful" — conntrack tracks:
# NEW          first packet of a connection
# ESTABLISHED  reply packets for a tracked connection
# RELATED      related connections (FTP data channel, ICMP errors)
# INVALID      packets that don't match any conntrack state
iptables -A INPUT  -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 3. SSH with rate limiting (prevent brute force)
iptables -A INPUT -p tcp --dport 22 \
  -m conntrack --ctstate NEW \
  -m recent --set --name SSH --rsource
iptables -A INPUT -p tcp --dport 22 \
  -m conntrack --ctstate NEW \
  -m recent --update --seconds 60 --hitcount 4 --name SSH --rsource \
  -j DROP    # More than 3 new SSH connections per minute → drop

iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT

# 4. Web traffic
iptables -A INPUT -p tcp --dport 80  -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 5. ICMP (ping) — limited rate
iptables -A INPUT -p icmp --icmp-type echo-request -m limit --limit 5/s -j ACCEPT

# 6. Default drop
iptables -P INPUT DROP

# Inspect conntrack table — see all tracked connections
conntrack -L
# tcp  6 86395 ESTABLISHED src=185.230.62.1 dst=203.0.113.42 sport=48291 dport=443
#      [ASSURED] mark=0 use=1
# udp  17 28 src=8.8.8.8 dst=203.0.113.42 sport=53 dport=32841
# Total: 1284 flows active
```

## NAT — network address translation

```bash
# SNAT (Source NAT): rewrite outgoing source address
# Typical use: internal server shares a single public IP
iptables -t nat -A POSTROUTING \
  -s 10.0.0.0/8 \
  -o eth0 \
  -j SNAT --to-source 203.0.113.42

# Masquerade: dynamic SNAT (uses the outbound interface's current IP)
# Use when public IP is dynamic (DHCP)
iptables -t nat -A POSTROUTING -s 10.0.0.0/8 -o eth0 -j MASQUERADE

# DNAT (Destination NAT): port forwarding
# Forward external port 8443 to internal service at 10.0.1.10:443
iptables -t nat -A PREROUTING \
  -i eth0 \
  -p tcp --dport 8443 \
  -j DNAT --to-destination 10.0.1.10:443

# Allow forwarding for the DNAT target
iptables -A FORWARD \
  -d 10.0.1.10 \
  -p tcp --dport 443 \
  -m conntrack --ctstate NEW,ESTABLISHED,RELATED \
  -j ACCEPT

# View NAT table
iptables -t nat -L -n -v
```

## Persisting rules and nftables migration

```bash
# Save rules (survives reboot)
iptables-save > /etc/iptables/rules.v4
ip6tables-save > /etc/iptables/rules.v6

# Restore on boot (Debian/Ubuntu)
# /etc/network/if-pre-up.d/iptables:
iptables-restore < /etc/iptables/rules.v4

# nftables — the modern replacement (same kernel hooks, better syntax)
# View equivalent ruleset in nft format
iptables-translate -A INPUT -p tcp --dport 443 -j ACCEPT
# nft add rule ip filter INPUT tcp dport 443 accept

# Full migration: iptables-translate-all → nft file
iptables-save | iptables-restore-translate > /etc/nftables.conf
# nftables atomically replaces the entire ruleset with one syscall:
nft -f /etc/nftables.conf
# No packet gets through a partial rule update — unlike iptables -F/-A sequences
```

iptables vs nftables: iptables has per-table, per-protocol commands (`iptables`, `ip6tables`, `arptables`, `ebtables`) and no atomic rule replacement — a rule flush followed by a reload has a window where everything is open. nftables unifies all four into one tool with a single rule language, supports sets (match against lists of IPs/ports without multiple rules), and replaces the ruleset atomically. Docker and Kubernetes still generate iptables rules; moving to nftables requires kernel 5.2+ and updating any tooling that reads iptables output. The kernel netfilter hooks underneath are identical — nftables is a better frontend for the same mechanism.
