Background jobs in serverless environments fail silently when functions timeout mid-execution. Inngest solves this by calling your function repeatedly from the last successful step, not from the beginning. You write the happy path; Inngest handles the failure path.

## Install

```bash
npm install inngest
```

## Define a function

```ts
// inngest/functions.ts
import { inngest } from './client';
import { db }      from '@/lib/db';
import { resend }  from '@/lib/resend';

export const onUserSignup = inngest.createFunction(
  { id: 'on-user-signup', retries: 3 },
  { event: 'user/signed.up' },

  async ({ event, step }) => {
    const { userId, email, username } = event.data;

    // Step 1: fetch user (retriable independently)
    const user = await step.run('fetch-user', async () => {
      return db.users.findUniqueOrThrow({ where: { id: userId } });
    });

    // Step 2: send welcome email
    await step.run('send-welcome', async () => {
      await resend.emails.send({
        to:      [email],
        subject: 'Welcome to Construx',
        react:   WelcomeEmail({ username }),
      });
    });

    // Step 3: wait 3 days (function exits and resumes — no timeout)
    await step.sleep('wait-3-days', '3d');

    // Step 4: check onboarding completion
    const complete = await step.run('check-onboarding', async () => {
      const u = await db.users.findUniqueOrThrow({ where: { id: userId } });
      return u.onboardingComplete;
    });

    // Step 5: send reminder if not complete
    if (!complete) {
      await step.run('send-reminder', async () => {
        await resend.emails.send({
          to:      [email],
          subject: 'Complete your Construx setup',
          react:   ReminderEmail({ username }),
        });
      });
    }
  },
);
```

## Inngest client

```ts
// inngest/client.ts
import { Inngest } from 'inngest';

export const inngest = new Inngest({ id: 'construx-api' });
```

## Serve via Route Handler

```ts
// app/api/inngest/route.ts
import { serve }           from 'inngest/next';
import { inngest }         from '@/inngest/client';
import { onUserSignup }    from '@/inngest/functions';
import { generateReport }  from '@/inngest/functions';

export const { GET, POST, PUT } = serve({
  client:    inngest,
  functions: [onUserSignup, generateReport],
});
```

## Sending events

```ts
// From anywhere in your app
import { inngest } from '@/inngest/client';

// On user signup
await inngest.send({
  name: 'user/signed.up',
  data: { userId: user.id, email: user.email, username: user.username },
});

// Schedule a future event
await inngest.send({
  name:       'report/generate.requested',
  data:       { reportId: id },
  ts:         Date.now() + 60 * 60 * 1000,  // in 1 hour
});
```

## Fan-out: parallel steps

```ts
export const generateDailyDigest = inngest.createFunction(
  { id: 'generate-daily-digest' },
  { cron: '0 8 * * *' },  // every day at 08:00

  async ({ step }) => {
    const users = await step.run('get-active-users', () =>
      db.users.findMany({ where: { active: true, digestEnabled: true } }),
    );

    // Fan out: one function invocation per user, in parallel
    await step.sendEvent('send-digests', users.map((u) => ({
      name: 'digest/user.requested',
      data: { userId: u.id },
    })));
  },
);
```

## waitForEvent: event-driven workflows

```ts
export const orderFulfillment = inngest.createFunction(
  { id: 'order-fulfillment' },
  { event: 'order/placed' },

  async ({ event, step }) => {
    await step.run('process-payment', () => stripe.charge(event.data));

    // Wait for warehouse to confirm, up to 24h
    const confirmed = await step.waitForEvent('warehouse-confirmed', {
      event:   'warehouse/order.confirmed',
      match:   'data.orderId',   // match on the same orderId
      timeout: '24h',
    });

    if (!confirmed) {
      await step.run('handle-timeout', () => cancelOrder(event.data.orderId));
      return;
    }

    await step.run('notify-customer', () => sendShipmentEmail(event.data));
  },
);
```

## Inngest vs Upstash Workflow vs Temporal vs BullMQ

Inngest: hosted, great DX, event-driven, fan-out, waitForEvent, rich dashboard. Upstash Workflow: serverless-native, QStash-backed, simpler API, cheaper. Temporal: enterprise-grade, self-hosted (or Temporal Cloud), most powerful, complex setup. BullMQ: Redis-backed, high-throughput queues, requires worker process. Use Inngest for complex event-driven workflows with fan-out and event correlation. Use Upstash Workflow for simpler linear workflows in a Cloudflare/Vercel stack. Use BullMQ for raw queue throughput.
