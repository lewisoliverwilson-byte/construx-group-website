date: "2033-05-25"
excerpt: "Talos Linux is a purpose-built Kubernetes OS designed from first principles for running Kubernetes nodes: no SSH, no shell, no package manager. The entire OS is immutable — the root filesystem is read-only and signed. All administration happens through a gRPC API (talosctl). The OS boots from a minimal image, reads its machine configuration from a URL or cloud metadata, configures networking and Kubernetes components, and joins the cluster — no interactive setup. Because there is no shell, there is no shell vulnerability surface: you can't SSH in and run arbitrary commands even if you have credentials. Configuration changes go through the API, which is auditable and versioned. Talos runs on bare metal, VMs, AWS, GCP, and Azure. The immutability and API-first design make it the right OS for teams that want to treat nodes as cattle: boot, configure via API, replace rather than repair."

Immutable OS. No SSH. No shell. gRPC API. Machine config. API-driven admin.

## Machine configuration and cluster bootstrap

```yaml
# Generate Talos machine config: produces controlplane.yaml, worker.yaml, talosconfig
talosctl gen config construx-prod https://10.0.1.100:6443 \
  --config-patch @patch-common.yaml \
  --config-patch-control-plane @patch-control-plane.yaml \
  --output ./talos/

# patch-common.yaml: shared config applied to all nodes
machine:
  install:
    disk: /dev/nvme0n1
    image: ghcr.io/siderolabs/installer:v1.7.5
    wipe: false

  network:
    hostname: "{{ .NodeName }}"
    nameservers:
      - 10.0.0.1
      - 1.1.1.1

  # Time: NTP servers for clock sync
  time:
    servers:
      - time.cloudflare.com

  # kubelet extra config
  kubelet:
    extraArgs:
      max-pods: "110"
    nodeIP:
      validSubnets:
        - 10.0.0.0/8

  # kernel modules to load
  kernel:
    modules:
      - name: br_netfilter

cluster:
  network:
    podSubnets:
      - 10.244.0.0/16
    serviceSubnets:
      - 10.96.0.0/12

  # etcd: backup config
  etcd:
    extraArgs:
      snapshot-count: "5000"
```

## Node administration with talosctl

```bash
# Apply machine config to a node (replaces SSH config management entirely)
talosctl apply-config \
  --talosconfig ./talos/talosconfig \
  --nodes 10.0.1.100 \
  --file ./talos/controlplane.yaml

# Bootstrap the cluster (first control-plane node only)
talosctl bootstrap --talosconfig ./talos/talosconfig --nodes 10.0.1.100

# Get kubeconfig
talosctl kubeconfig --talosconfig ./talos/talosconfig --nodes 10.0.1.100

# Check node health — all admin via gRPC API, no SSH
talosctl --talosconfig ./talos/talosconfig --nodes 10.0.1.100 health
# [healthcheck] run checks against node
# OK: system disk: 47.2 GB available
# OK: kubelet: running
# OK: etcd: running (leader: true)
# OK: api server: running

# Read system logs (replaces journalctl on traditional nodes)
talosctl --talosconfig ./talos/talosconfig --nodes 10.0.1.100 logs -f

# Read kernel logs
talosctl --talosconfig ./talos/talosconfig --nodes 10.0.1.100 dmesg

# Get node info
talosctl --talosconfig ./talos/talosconfig --nodes 10.0.1.100 get members
# NODE          HOSTNAME       MACHINE TYPE   OS              VERSION   ADDRESSES
# 10.0.1.100   control-01     controlplane   Talos (v1.7.5)  v1.30.2   10.0.1.100
# 10.0.1.101   control-02     controlplane   Talos (v1.7.5)  v1.30.2   10.0.1.101
# 10.0.1.102   control-03     controlplane   Talos (v1.7.5)  v1.30.2   10.0.1.102
# 10.0.2.1     worker-01      worker         Talos (v1.7.5)  v1.30.2   10.0.2.1

# OS upgrade: rolling node upgrade with zero downtime
talosctl --talosconfig ./talos/talosconfig upgrade \
  --nodes 10.0.2.1 \
  --image ghcr.io/siderolabs/installer:v1.7.6
# Drains the node, upgrades, reboots, rejoins cluster automatically

# Kubernetes upgrade
talosctl --talosconfig ./talos/talosconfig upgrade-k8s \
  --to 1.31.0
# Upgrades kube-apiserver, kube-controller-manager, kube-scheduler, kubelet sequentially
```

## Disk encryption and secure boot

```yaml
# Machine config: enable disk encryption with TPM-bound key
# Encrypts the state and ephemeral partitions at rest

machine:
  systemDiskEncryption:
    state:
      provider: luks2
      options:
        - no_read_workqueue
        - no_write_workqueue
      keys:
        # TPM2: key is sealed to the TPM, cannot be extracted
        - nodeID: {}
          slot: 0
        - tpm: {}
          slot: 1

    ephemeral:
      provider: luks2
      keys:
        - nodeID: {}
          slot: 0

# Secure Boot: Talos supports UKI (Unified Kernel Image) signed with your key
# The bootloader, kernel, and initramfs are bundled and signed together
# UEFI SecureBoot verifies the signature before booting
```

Talos vs Ubuntu + kubeadm vs Flatcar vs bottlerocket vs RKE2: Ubuntu + kubeadm is the most familiar but leaves you with a full Linux userspace to patch, SSH to secure, and packages to manage. Flatcar (CoreOS successor) is immutable and auto-updates but retains SSH and a shell. Bottlerocket (AWS) is similar to Talos — API-driven, immutable — but AWS-specific. RKE2 is a Kubernetes distribution (bundled everything including the OS management) from Rancher — opinionated and production-ready but tied to the Rancher ecosystem. Talos's differentiation is the complete elimination of SSH and shell: there is no way to interactively modify a running node — every change goes through the gRPC API and is versioned. For teams that want the strongest possible node hardening posture and are comfortable with API-driven administration, Talos is the most secure baseline.
