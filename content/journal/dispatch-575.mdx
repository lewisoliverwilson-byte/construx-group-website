SVG is a coordinate system with shapes drawn inside it. Animating SVG elements is mostly the same as animating HTML elements — CSS transitions and keyframes work — but SVG has some specific behaviours that catch people out.

## The stroke drawing trick

The most common SVG animation: a line or path that appears to draw itself. The mechanism is `stroke-dasharray` and `stroke-dashoffset`.

`stroke-dasharray` sets the length of dashes and gaps in a stroked path. If you set it to the total length of the path, you get one long dash with a gap equal to the total length.

`stroke-dashoffset` shifts the dashes along the path. At offset = total length, the entire stroke is shifted off the path (invisible). At offset = 0, the stroke is in its natural position (fully visible).

Animating from `stroke-dashoffset: totalLength` to `stroke-dashoffset: 0` draws the line.

```css
.path {
  stroke-dasharray: 400;   /* total path length */
  stroke-dashoffset: 400;  /* start hidden */
  animation: draw 1.2s ease forwards;
}

@keyframes draw {
  to { stroke-dashoffset: 0; }
}
```

To get the total length of a path dynamically:

```ts
const path = document.querySelector('path');
const length = path.getTotalLength();
```

In React with useEffect:

```tsx
import { useEffect, useRef } from 'react';

export function AnimatedPath({ d }: { d: string }) {
  const pathRef = useRef<SVGPathElement>(null);

  useEffect(() => {
    const path = pathRef.current;
    if (!path) return;
    const length = path.getTotalLength();
    path.style.strokeDasharray = String(length);
    path.style.strokeDashoffset = String(length);
    path.style.animation = `draw 1.2s ease forwards`;
  }, []);

  return <path ref={pathRef} d={d} stroke="currentColor" fill="none" />;
}
```

## transform-origin in SVG

CSS transforms on SVG elements have a quirk: `transform-origin` is relative to the SVG viewport, not the element. `transform-origin: 50% 50%` means the center of the viewport, not the center of the element.

For rotation around an element's center, use `transform-box: fill-box`:

```css
.rotate {
  transform-box: fill-box;
  transform-origin: center;
  animation: spin 2s linear infinite;
}

@keyframes spin {
  to { transform: rotate(360deg); }
}
```

`transform-box: fill-box` changes the reference box to the element's bounding box. Now `transform-origin: center` works as expected.

## SMIL: native SVG animation

SVG has its own animation system, SMIL (Synchronized Multimedia Integration Language). It's not widely used because CSS handles most cases, but it's the only native way to animate path morphing and motion along a path.

**Motion along a path**:

```svg
<circle r="5" fill="#F97316">
  <animateMotion dur="3s" repeatCount="indefinite">
    <mpath href="#track" />
  </animateMotion>
</circle>
<path id="track" d="M 10 80 Q 95 10 180 80" fill="none" stroke="rgba(255,255,255,0.1)" />
```

The circle follows the path defined by `#track`. CSS can't do this.

**Path morphing** (animating `d` attribute):

```svg
<path fill="#F97316">
  <animate
    attributeName="d"
    dur="2s"
    repeatCount="indefinite"
    values="M 10 80 Q 95 10 180 80; M 10 80 Q 95 150 180 80; M 10 80 Q 95 10 180 80"
  />
</path>
```

Paths must have the same number of control points for morphing to work correctly. If the point counts differ, the animation will jump rather than morph.

## Framer Motion for complex sequences

For multi-step sequences, staggering, or scroll-triggered SVG animations, Framer Motion's `motion.path` component handles the stroke drawing trick declaratively:

```tsx
import { motion } from 'framer-motion';

export function DrawingPath({ d }: { d: string }) {
  return (
    <svg viewBox="0 0 200 100">
      <motion.path
        d={d}
        stroke="#F97316"
        strokeWidth={2}
        fill="none"
        initial={{ pathLength: 0 }}
        animate={{ pathLength: 1 }}
        transition={{ duration: 1.5, ease: 'easeInOut' }}
      />
    </svg>
  );
}
```

`pathLength` is a Framer Motion shorthand that handles the `stroke-dasharray` trick internally. It normalises the path length to 0–1 regardless of the actual pixel length — no `getTotalLength()` needed.

## Performance considerations

SVG animations run on the main thread unless you restrict yourself to properties that can be composited by the GPU: `transform` and `opacity`. Animating `stroke-dashoffset`, `fill`, `d`, or any geometry property triggers layout or paint and runs on the CPU.

For smooth 60fps SVG animations:
- Use `transform` and `opacity` when possible
- Use `will-change: transform` for elements you know will animate
- For path drawing, `stroke-dashoffset` is unavoidable — keep the number of animated elements low

For complex data visualisations with hundreds of animated paths, consider Canvas instead. SVG is the right choice for UI elements, icons, and illustrations. Canvas is better for dense data rendering.
