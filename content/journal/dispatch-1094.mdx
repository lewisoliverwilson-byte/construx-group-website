title: "Talos Linux: immutable Kubernetes OS — API-driven, no SSH, declarative config"
date: "2033-12-09"
excerpt: "Talos Linux is a minimal, immutable, API-driven operating system designed specifically for running Kubernetes. There is no SSH daemon, no shell, no package manager — the only way to interact with a Talos node is via the Talos API (over mTLS) using the talosctl CLI. The OS runs entirely from a squashfs root that is mounted read-only; all persistent state is isolated to a dedicated disk partition. This immutability means there is no configuration drift between nodes — every control plane node and worker node is identical to what was declared in the machine configuration. Talos bootstraps a Kubernetes cluster from a YAML machine configuration: talosctl gen config generates the config for control plane and worker nodes; the config is applied to each node via talosctl apply-config; talosctl bootstrap initiates etcd and the first control plane node. Upgrades are in-place atomic image swaps — talosctl upgrade points a node at a new Talos OS image, the node downloads it, writes it to the inactive partition, reboots, and Kubernetes takes over restarting pods. At Construx, Talos is the production OS for all bare-metal and VM-based Kubernetes nodes — it eliminates an entire class of node-level configuration problems (SSH key rotation, package drift, kernel parameter changes) and makes node reprovisioning reliable."

## Cluster bootstrap and machine configuration

```yaml
# Machine configuration: Talos control plane node
# Generated by: talosctl gen config construx-prod https://10.0.0.10:6443
# File: controlplane.yaml

version: v1alpha1
debug: false
persist: true

machine:
  type: controlplane
  token: "$(talosctl gen token)"

  certSANs:
    - 10.0.0.10        # VIP (kube-vip or keepalived)
    - construx-k8s.internal

  kubelet:
    extraArgs:
      rotate-server-certificates: true
    clusterDNS:
      - 169.254.2.53   # Talos's local DNS cache

  network:
    hostname: cp-01.construx.internal
    interfaces:
      - interface: eth0
        dhcp: false
        addresses:
          - 10.0.0.11/24
        routes:
          - network: 0.0.0.0/0
            gateway: 10.0.0.1
    nameservers:
      - 10.0.0.1

  install:
    disk: /dev/sda
    image: ghcr.io/siderolabs/installer:v1.7.5
    bootloader: true
    wipe: false         # upgrade: leave data partition intact

  sysctls:
    net.ipv4.ip_forward: "1"
    kernel.perf_event_paranoid: "0"    # allow Pixie eBPF

  kernel:
    modules:
      - name: br_netfilter

  files:
    - path: /etc/cri/conf.d/20-customization.part
      op: create
      content: |
        [plugins."io.containerd.grpc.v1.cri"]
          enable_unprivileged_ports = true

cluster:
  id: construx-prod-cluster-id
  secret: "$(talosctl gen secret)"

  controlPlane:
    endpoint: https://10.0.0.10:6443

  network:
    dnsDomain: cluster.local
    podSubnets:
      - 10.244.0.0/16
    serviceSubnets:
      - 10.96.0.0/12

  etcd:
    advertisedSubnets:
      - 10.0.0.0/24    # only etcd peers on this subnet

  apiServer:
    certSANs:
      - 10.0.0.10
      - construx-k8s.internal
    extraArgs:
      audit-log-path: /var/log/audit/kube-apiserver-audit.log
      audit-policy-file: /etc/kubernetes/audit-policy.yaml
      oidc-issuer-url: https://dex.construx.internal
      oidc-client-id: kubernetes

  proxy:
    disabled: true      # using Cilium kube-proxy replacement

  discovery:
    enabled: true
    registries:
      kubernetes:
        disabled: false
      service:
        disabled: true
```

## talosctl: day-0 bootstrap and day-2 operations

```bash
# Bootstrap a new cluster

# 1. Generate cluster config
talosctl gen config construx-prod https://10.0.0.10:6443 \
  --config-patch-control-plane @patches/controlplane.yaml \
  --config-patch-worker       @patches/worker.yaml \
  --output-dir _out/

# 2. Apply config to each node (before first boot — via talos ISO/PXE)
talosctl apply-config \
  --insecure \
  --nodes 10.0.0.11 \
  --file _out/controlplane.yaml

talosctl apply-config --insecure --nodes 10.0.0.12 --file _out/controlplane.yaml
talosctl apply-config --insecure --nodes 10.0.0.13 --file _out/controlplane.yaml

# 3. Bootstrap etcd on the first control plane node
talosctl bootstrap --nodes 10.0.0.11

# 4. Retrieve kubeconfig
talosctl kubeconfig --nodes 10.0.0.11

# Upgrade a node to a new Talos version (atomic, in-place)
talosctl upgrade \
  --nodes 10.0.0.21 \
  --image ghcr.io/siderolabs/installer:v1.8.0 \
  --wait

# Inspect node state (no SSH — API only)
talosctl get machineconfig --nodes 10.0.0.11
talosctl dmesg --nodes 10.0.0.11 --follow
talosctl logs kubelet --nodes 10.0.0.11 --follow

# Service status on node
talosctl service --nodes 10.0.0.11
# SERVICE  STATE    HEALTH    LAST CHANGE
# apid     Running  OK        4d ago
# containerd Running OK       4d ago
# cri      Running  OK        4d ago
# etcd     Running  OK        4d ago
# kubelet  Running  OK        4d ago
# machined Running  OK        4d ago

# Reset a node back to a clean state (re-provision)
talosctl reset --nodes 10.0.0.21 --graceful --reboot

# Run a pod for one-off debugging (since no shell on node)
kubectl debug node/k8s-worker-01 \
  -it \
  --image=busybox \
  --profile=sysadmin
# This is the escape hatch — runs a privileged debug container on the node
```

Talos vs Flatcar Container Linux vs Bottlerocket vs Ubuntu + kubeadm vs K3OS: Ubuntu + kubeadm is the most flexible option — full OS access, any Kubernetes version, but requires managing OS updates, kernel parameters, SSH keys, and package drift separately. kubeadm is a Kubernetes installer, not an OS — you still need to manage the underlying Linux. Flatcar Container Linux (CoreOS successor) is also immutable, but it uses SSH-based management and has a more traditional init system. AWS Bottlerocket is Amazon's immutable Kubernetes OS for EC2 — correctly optimised for AWS but not for bare-metal or other clouds. K3OS was a minimal OS for K3s (lightweight Kubernetes) — it is no longer maintained. Talos's key differentiator is the full elimination of SSH and a shell: every node operation goes through the Talos gRPC API. This makes Talos nodes fundamentally harder to compromise (no shell means no lateral movement after an SSH credential compromise), easier to reproduce (machine config is the complete system definition), and simpler to scale (nodes are stateless from an OS perspective — just boot with a config and they join the cluster).
