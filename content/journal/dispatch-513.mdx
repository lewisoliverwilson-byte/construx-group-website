Logs tell you what happened. Metrics tell you how much. Traces tell you why it was slow. OpenTelemetry (OTel) is the open standard for all three, with exporters for every major observability backend: Grafana Tempo, Honeycomb, Datadog, Sentry, and the OTEL collector.

## Setup in Next.js

Next.js 13.4+ has native OTel support via `@vercel/otel` or the full OpenTelemetry SDK.

```bash
npm install @vercel/otel @opentelemetry/sdk-trace-node
```

```ts
// instrumentation.ts  (project root — Next.js registers this automatically)
import { registerOTel } from '@vercel/otel';

export function register() {
  registerOTel({
    serviceName: 'construx-group-website',
    traceExporter: 'otlp',
  });
}
```

`instrumentation.ts` is loaded once when the server starts. The `register()` function runs before any route handlers. Set the exporter endpoint via env var:

```
OTEL_EXPORTER_OTLP_ENDPOINT=https://your-otel-collector:4318
```

## Manual spans

Auto-instrumentation traces HTTP requests. For custom spans around business logic:

```ts
import { trace, context, SpanStatusCode } from '@opentelemetry/api';

const tracer = trace.getTracer('construx-api');

export async function semanticSearch(query: string, limit = 10) {
  return tracer.startActiveSpan('semanticSearch', async (span) => {
    try {
      span.setAttribute('query.length', query.length);
      span.setAttribute('limit', limit);

      const embedding = await embedText(query);
      span.addEvent('embedding_complete', { dimensions: embedding.length });

      const results = await db
        .select()
        .from(products)
        .orderBy(cosineDistance(products.embedding, embedding))
        .limit(limit);

      span.setAttribute('results.count', results.length);
      span.setStatus({ code: SpanStatusCode.OK });

      return results;
    } catch (err) {
      span.recordException(err as Error);
      span.setStatus({ code: SpanStatusCode.ERROR });
      throw err;
    } finally {
      span.end();
    }
  });
}
```

The span captures: how long embedding took, how many results returned, any error with full stack. All of this shows up as a child span under the parent HTTP request in your trace viewer.

## Database query tracing with Drizzle

```ts
// lib/db.ts
import { drizzle }    from 'drizzle-orm/postgres-js';
import { trace }      from '@opentelemetry/api';
import postgres       from 'postgres';

const sql = postgres(process.env.DATABASE_URL!);

const tracer = trace.getTracer('db');

export const db = drizzle(sql, {
  logger: {
    logQuery(query, params) {
      const span = tracer.startSpan('db.query', {
        attributes: {
          'db.system':    'postgresql',
          'db.statement': query.slice(0, 200),
          'db.params':    params.length,
        },
      });
      span.end();
    },
  },
});
```

This creates a span for every query. In Grafana Tempo or Honeycomb you'll see individual SQL statements as child spans under the route handler that triggered them.

## Structured logging with trace correlation

Logs are most useful when correlated with traces. Inject the current trace ID into log entries:

```ts
import { trace } from '@opentelemetry/api';

export function log(level: 'info' | 'warn' | 'error', message: string, meta?: object) {
  const span       = trace.getActiveSpan();
  const spanContext = span?.spanContext();

  console[level](JSON.stringify({
    level,
    message,
    timestamp: new Date().toISOString(),
    traceId:   spanContext?.traceId,
    spanId:    spanContext?.spanId,
    ...meta,
  }));
}
```

When you see an error log, the `traceId` field links directly to the trace in Tempo or Honeycomb — you can jump from log to trace in one click.

## Sending to Grafana Cloud

```ts
// instrumentation.ts
import { registerOTel }       from '@vercel/otel';
import { OTLPTraceExporter }  from '@opentelemetry/exporter-trace-otlp-http';

export function register() {
  registerOTel({
    serviceName: 'construx-website',
    traceExporter: new OTLPTraceExporter({
      url:     process.env.GRAFANA_OTLP_ENDPOINT,
      headers: {
        Authorization: `Basic ${Buffer.from(
          `${process.env.GRAFANA_INSTANCE_ID}:${process.env.GRAFANA_API_KEY}`
        ).toString('base64')}`,
      },
    }),
  });
}
```

Grafana Cloud's free tier includes 50GB of traces per month — enough for most projects. Traces older than 14 days are dropped unless you're on a paid plan.

## What to trace

Not everything needs a span. Good candidates:

- External API calls (Claude, Stripe, Resend, OpenAI)
- Database queries that touch large tables or use vector search
- Background job processing
- Cache operations (Redis hit/miss rates)
- Server Actions with significant business logic

Avoid spans on every tiny utility function — the overhead of creating spans adds up, and the noise makes traces harder to read.

## The payoff

The first time you see a full trace — request arrives at the edge, middleware runs, authentication check fires, database query executes (with the SQL text visible), response serialises — it changes how you debug. You stop guessing where the latency is. The trace shows you exactly which span was slow, and the structured log at the same timestamp tells you why.
