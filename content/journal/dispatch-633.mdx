SQLite is the most deployed database in the world — it's in every iPhone, Android device, Chrome installation, and Firefox profile. It's not a toy. It's a battle-tested embedded engine that handles serious workloads when the access pattern fits.

## When SQLite is the right choice

SQLite excels at: single-writer workloads, read-heavy applications, local-first data, embedded databases in desktop/mobile apps, edge runtimes (Cloudflare Workers, Deno Deploy), and developer tooling. It struggles with: high write concurrency from multiple processes, and anything needing replication or horizontal scaling.

Rule of thumb: if your database fits on one server and writes happen serially or rarely, SQLite is simpler and often faster than Postgres.

## Basic usage with Bun

```ts
import { Database } from 'bun:sqlite';

const db = new Database('construx.db');

// Schema
db.run(`
  CREATE TABLE IF NOT EXISTS posts (
    id         TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(8)))),
    title      TEXT NOT NULL,
    content    TEXT NOT NULL,
    status     TEXT NOT NULL DEFAULT 'draft'
               CHECK(status IN ('draft', 'published', 'archived')),
    created_at INTEGER NOT NULL DEFAULT (unixepoch())
  )
`);

// Write
const insert = db.prepare(`
  INSERT INTO posts (title, content) VALUES ($title, $content) RETURNING *
`);
const post = insert.get({ $title: 'Hello SQLite', $content: 'Content here' });

// Read
const posts = db.prepare(`
  SELECT * FROM posts WHERE status = $status ORDER BY created_at DESC LIMIT $limit
`).all({ $status: 'published', $limit: 10 });

// Parameterised queries are automatic — no string interpolation
```

## With Drizzle ORM

```ts
import { drizzle }             from 'drizzle-orm/bun-sqlite';
import { Database }            from 'bun:sqlite';
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core';
import { sql }                 from 'drizzle-orm';

const sqlite = new Database('construx.db');
export const db = drizzle(sqlite);

export const posts = sqliteTable('posts', {
  id:        text('id').primaryKey().default(sql`lower(hex(randomblob(8)))`),
  title:     text('title').notNull(),
  content:   text('content').notNull(),
  status:    text('status', { enum: ['draft', 'published', 'archived'] }).notNull().default('draft'),
  createdAt: integer('created_at', { mode: 'timestamp' }).notNull().default(sql`unixepoch()`),
});

// Full type-safe queries
const published = await db.select().from(posts)
  .where(eq(posts.status, 'published'))
  .orderBy(desc(posts.createdAt))
  .limit(10);
```

## Performance settings

```ts
// Apply WAL mode and other pragmas on connection open
const db = new Database('construx.db');

db.run('PRAGMA journal_mode = WAL');        // concurrent reads + single writer
db.run('PRAGMA synchronous = NORMAL');      // faster writes, safe with WAL
db.run('PRAGMA cache_size = -32000');       // 32 MB page cache
db.run('PRAGMA foreign_keys = ON');         // enforce FK constraints
db.run('PRAGMA busy_timeout = 5000');       // wait up to 5s on locked DB
db.run('PRAGMA mmap_size = 268435456');     // 256 MB memory-mapped I/O
```

WAL (Write-Ahead Log) is the most impactful setting. Without it, any write blocks all reads. With WAL, readers and a single writer coexist without contention.

## Full-text search

```ts
// FTS5 virtual table
db.run(`
  CREATE VIRTUAL TABLE IF NOT EXISTS posts_fts USING fts5(
    title,
    content,
    content='posts',
    content_rowid='rowid'
  )
`);

// Keep FTS in sync with triggers
db.run(`
  CREATE TRIGGER posts_ai AFTER INSERT ON posts BEGIN
    INSERT INTO posts_fts(rowid, title, content) VALUES (new.rowid, new.title, new.content);
  END
`);

// Search
const results = db.prepare(`
  SELECT posts.*, highlight(posts_fts, 0, '<mark>', '</mark>') AS title_hl
  FROM posts_fts
  JOIN posts ON posts.rowid = posts_fts.rowid
  WHERE posts_fts MATCH $query
  ORDER BY rank
  LIMIT 20
`).all({ $query: 'nix reproducible' });
```

SQLite FTS5 supports boolean queries, phrase matching, prefix search, and relevance ranking with BM25.

## SQLite at the edge: Turso

Turso is SQLite replicated globally — read replicas in every Cloudflare region, sub-millisecond reads, primary write node.

```ts
import { createClient } from '@libsql/client';

const db = createClient({
  url:       process.env.TURSO_DATABASE_URL!,
  authToken: process.env.TURSO_AUTH_TOKEN!,
});

const result = await db.execute({
  sql:  'SELECT * FROM posts WHERE status = ? ORDER BY created_at DESC LIMIT ?',
  args: ['published', 10],
});
```

```bash
turso db create construx-prod
turso db replicate construx-prod --location lhr fra sin
turso db show construx-prod
```

## Embedded Replicas: local read, remote write

```ts
// libsql embedded replica: local SQLite file synced from Turso
const db = createClient({
  url:       'file:local.db',            // reads from local file
  syncUrl:   process.env.TURSO_URL!,     // writes to Turso, syncs local
  authToken: process.env.TURSO_AUTH_TOKEN!,
});

await db.sync();  // pull latest writes from Turso into local file
```

Reads hit the local SQLite file — microsecond latency. Writes go to the Turso primary. Periodic sync keeps the local file fresh. This pattern gives you the speed of SQLite with the durability of a replicated database.

## Migrations with drizzle-kit

```bash
# Generate migration from schema change
npx drizzle-kit generate --dialect sqlite --schema ./db/schema.ts

# Apply
npx drizzle-kit migrate

# Or push directly (dev only)
npx drizzle-kit push
```

SQLite's `ALTER TABLE` is limited — you can't drop columns or change constraints without recreating the table. Drizzle handles this automatically in generated migrations.
