The Hyve's AI agent makes real API calls to Claude. At scale, these calls have real cost. Here's how we manage cost without compromising the quality of AI responses.

## The cost model

Claude API pricing (at current rates) is per-token: input tokens and output tokens, with output typically more expensive. For The Hyve, the cost components are:

**System prompt:** A fixed context block that sets up the AI's role, capabilities, and workspace context. This is the same on every call within a workspace.

**Message history context:** Recent messages and retrieved historical messages. This varies per call.

**User query:** The @mention message that triggered the response.

**Output:** The AI's response.

The system prompt is the largest fixed cost — it includes workspace facts, instructions, and the AI's capabilities description. Without caching, this is re-processed on every call.

## Anthropic's prompt caching

Anthropic's prompt caching allows marking a portion of the prompt as cacheable. If the same cacheable content is used in a request within the cache window (5 minutes), the cached content is served at a fraction of the cost (no input processing charge for cached tokens, a small cache read fee).

```ts
const response = await anthropic.messages.create({
  model: 'claude-haiku-4-5-20251001',
  max_tokens: 1024,
  system: [
    {
      type: 'text',
      text: workspaceSystemPrompt, // The stable part — same for all calls in this workspace
      cache_control: { type: 'ephemeral' }, // Mark as cacheable
    },
    {
      type: 'text',
      text: `Current channel: #${channelName}\nRecent context:\n${messageContext}`, // Dynamic part
    },
  ],
  messages: [{ role: 'user', content: userMessage }],
});
```

The `ephemeral` cache type persists for 5 minutes — appropriate for The Hyve where multiple messages in the same workspace within a 5-minute window can share the cached system prompt.

**Cost impact:** The workspace system prompt runs to ~2,000 tokens for a typical workspace. Without caching, 10 AI calls in 5 minutes costs 20,000 input tokens for system prompt alone. With caching, the first call pays 2,000 tokens, calls 2-10 pay only a small cache read fee. At 10 calls, caching reduces system prompt costs by ~80%.

## Context window management

The context window is the total token budget for a call. For Haiku (the model we use for interactive responses), the context window is 200k tokens — large, but not unlimited.

Our context budget:
- System prompt: ~2,000 tokens (cached)
- Recent messages (last 10): ~1,500 tokens average
- Semantic retrieval results (5 retrieved): ~1,000 tokens average
- User query: ~100 tokens average
- Remaining for output: ~1,024 tokens (our max_tokens setting)

Total budget used: ~5,000-6,000 tokens per call. Well within limits, and controlled.

The critical principle: never include the full channel history. A workspace with 10,000 messages would use 100,000+ tokens per call if we naively included all history. The RAG retrieval pattern (embed the query, retrieve top-k relevant past messages) gives the AI relevant context without the cost of the full history.

## Model routing for cost efficiency

Not all AI calls require the same model. We route to different models based on:

```ts
type QueryType = 'quick_answer' | 'document_draft' | 'complex_analysis';

function selectModel(queryType: QueryType): string {
  switch (queryType) {
    case 'quick_answer':
      return 'claude-haiku-4-5-20251001';  // Fast, cheap, good enough
    case 'document_draft':
      return 'claude-sonnet-4-6';          // Better quality for longer content
    case 'complex_analysis':
      return 'claude-opus-4-8';            // Highest quality for complex tasks
  }
}

function classifyQuery(query: string): QueryType {
  const wordCount = query.trim().split(/\s+/).length;
  
  if (query.includes('/draft') || query.includes('/write') || wordCount > 30) {
    return 'document_draft';
  }
  if (query.includes('/analyse') || query.includes('/research') || query.includes('/compare')) {
    return 'complex_analysis';
  }
  return 'quick_answer';
}
```

The classification is simple and fast. The cost difference is significant: Haiku is ~20x cheaper per token than Opus. For a quick factual question ("@hyve what's the capital of France?"), Haiku is the right tool. For a complex document analysis, the quality improvement from Opus is worth the cost.

## The token usage tracking

We track token usage per workspace per day to monitor costs and detect anomalous usage:

```ts
async function trackTokenUsage(
  workspaceId: string,
  model: string,
  usage: { input_tokens: number; output_tokens: number; cache_read_tokens?: number },
) {
  const costs = computeCost(model, usage);
  
  await db.insert(aiUsageLogs).values({
    workspaceId,
    model,
    inputTokens: usage.input_tokens,
    outputTokens: usage.output_tokens,
    cacheReadTokens: usage.cache_read_tokens ?? 0,
    costUsd: costs.totalUsd,
  });
}
```

Daily cost per active workspace at current usage patterns: $0.03-0.08. At scale, this is manageable within the subscription pricing. We've modelled the cost at 10x current usage and it remains sustainable.

## The quality preservation principle

All of the cost optimisation above is designed to maintain response quality. The optimisations that reduce cost without reducing quality:

- Prompt caching reduces re-processing of stable content (no quality impact)
- Context window management removes irrelevant history (slight quality improvement — less noise)
- Model routing matches model capability to task complexity (quality improvement where Haiku is sufficient; Sonnet/Opus for complex tasks)

The optimisation we deliberately avoid: reducing the quality of the semantic retrieval to save cost. Good retrieval is the foundation of good responses. Cheap retrieval produces worse responses. We invest in the retrieval quality and save cost elsewhere.
