SQLite is not a toy database. It is an ACID-compliant relational database used by more applications than any other engine in the world. D1 takes SQLite to the edge — distributed, serverless, and latency-optimised for global applications.

## Create a database

```bash
# Install wrangler if needed
npm install -g wrangler
wrangler login

# Create a D1 database
wrangler d1 create construx-db

# Output:
# ✅ Successfully created DB 'construx-db'!
# [[d1_databases]]
# binding = "DB"
# database_name = "construx-db"
# database_id = "a3b4c5d6-e7f8-..."
```

## wrangler.toml

```toml
name = "construx-api"
main = "src/index.ts"
compatibility_date = "2024-11-01"

[[d1_databases]]
binding      = "DB"
database_name = "construx-db"
database_id  = "a3b4c5d6-e7f8-9012-3456-789abcdef012"
```

## Schema and migrations

```bash
# Create a migration
wrangler d1 migrations create construx-db create-posts

# Generated: migrations/0001_create-posts.sql
```

```sql
-- migrations/0001_create-posts.sql
CREATE TABLE IF NOT EXISTS users (
  id         TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
  username   TEXT NOT NULL UNIQUE,
  email      TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS posts (
  id           TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(16)))),
  title        TEXT NOT NULL,
  slug         TEXT NOT NULL UNIQUE,
  content      TEXT NOT NULL,
  published    INTEGER NOT NULL DEFAULT 0,
  author_id    TEXT NOT NULL REFERENCES users(id),
  published_at TEXT,
  view_count   INTEGER NOT NULL DEFAULT 0
);

CREATE INDEX posts_author_idx     ON posts (author_id);
CREATE INDEX posts_published_idx  ON posts (published);
```

```bash
# Apply migrations (local dev)
wrangler d1 migrations apply construx-db --local

# Apply to production
wrangler d1 migrations apply construx-db --remote
```

## Query in a Worker (raw)

```ts
// src/index.ts
export interface Env {
  DB: D1Database;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const { pathname } = new URL(request.url);

    if (pathname === '/posts') {
      const { results } = await env.DB.prepare(
        'SELECT id, title, slug, published_at FROM posts WHERE published = 1 ORDER BY published_at DESC LIMIT 20',
      ).all<{ id: string; title: string; slug: string; published_at: string }>();

      return Response.json(results);
    }

    if (pathname.startsWith('/posts/')) {
      const slug = pathname.slice(7);
      const post = await env.DB.prepare(
        'SELECT * FROM posts WHERE slug = ? AND published = 1',
      ).bind(slug).first();

      if (!post) return new Response('Not found', { status: 404 });
      return Response.json(post);
    }

    return new Response('Not found', { status: 404 });
  },
};
```

## Drizzle with D1

```ts
// src/db.ts
import { drizzle }    from 'drizzle-orm/d1';
import * as schema    from './schema';
import type { Env }   from './index';

export function createDb(env: Env) {
  return drizzle(env.DB, { schema });
}
```

```ts
// schema.ts
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core';

export const posts = sqliteTable('posts', {
  id:          text('id').primaryKey(),
  title:       text('title').notNull(),
  slug:        text('slug').notNull().unique(),
  content:     text('content').notNull(),
  published:   integer('published', { mode: 'boolean' }).default(false).notNull(),
  authorId:    text('author_id').notNull(),
  publishedAt: text('published_at'),
  viewCount:   integer('view_count').default(0).notNull(),
});
```

```ts
// usage in a Worker
import { eq, desc } from 'drizzle-orm';

const db    = createDb(env);
const posts = await db.query.posts.findMany({
  where:   eq(posts.published, true),
  orderBy: desc(posts.publishedAt),
  limit:   20,
});
```

## D1 vs Turso vs PlanetScale vs Neon

D1: Cloudflare-native, SQLite, global read replicas, tight Workers integration, no TCP, limited to Workers runtime. Turso: SQLite + libSQL, any runtime, edge replicas, works over HTTP/gRPC. PlanetScale: MySQL-compatible, branching, vitess sharding, any runtime. Neon: serverless Postgres, branching, any runtime. Use D1 when you are already on Cloudflare Workers and want zero-config edge SQLite. Use Turso for edge SQLite with runtime flexibility. Use Neon or PlanetScale when you need Postgres-compatible SQL.
