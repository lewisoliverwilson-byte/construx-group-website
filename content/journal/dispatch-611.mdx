Tailwind v4 is a ground-up rewrite of the CSS engine. The output is the same utility classes you know — but the config, the build, and the internals are completely different.

## The big changes

**1. CSS-first configuration**

In v3, configuration lived in `tailwind.config.ts`. In v4, it lives in CSS:

```css
/* app/globals.css */
@import "tailwindcss";

@theme {
  --color-construx:    #F97316;
  --color-text-base:   #F0EFFF;
  --color-text-muted:  rgba(240,239,255,0.6);
  --font-sans:         'Inter', sans-serif;
  --font-mono:         'JetBrains Mono', monospace;
  --radius-sm:         2px;
  --radius-md:         4px;
  --spacing-18:        4.5rem;
}
```

`@theme` variables become Tailwind utilities automatically: `text-construx`, `font-mono`, `rounded-md`, `mt-18`. No config file, no JS.

**2. No PostCSS plugin required**

v3 required a PostCSS setup. v4 ships its own CLI and a Vite plugin:

```bash
npm install tailwindcss@4 @tailwindcss/vite
```

```ts
// vite.config.ts
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  plugins: [tailwindcss()],
});
```

For Next.js, use `@tailwindcss/postcss`:

```bash
npm install tailwindcss@4 @tailwindcss/postcss
```

```js
// postcss.config.js
module.exports = { plugins: { '@tailwindcss/postcss': {} } };
```

**3. CSS variables as design tokens**

Every Tailwind value is now a CSS custom property:

```css
/* Generated automatically by v4 */
:root {
  --color-orange-500:  oklch(70.5% 0.213 47.6);
  --spacing-4:         1rem;
  --font-size-sm:      0.875rem;
  /* ... */
}
```

Your custom properties in `@theme` are merged into this system. Utilities use `var(--color-construx)` under the hood, so they work with CSS-in-JS, web components, and runtime overrides.

**4. Container queries built in**

No plugin needed:

```html
<div class="@container">
  <div class="@sm:grid @sm:grid-cols-2 @lg:grid-cols-3">
    <!-- adapts to container width -->
  </div>
</div>
```

**5. New utilities**

```html
<!-- field-sizing: auto-resizing textarea -->
<textarea class="field-sizing-content">...</textarea>

<!-- not-* variant: negate any utility -->
<div class="not-hover:opacity-50">...</div>

<!-- starting-style: animate initial render -->
<div class="starting:opacity-0 transition-opacity">...</div>

<!-- color-mix utilities -->
<div class="bg-blue-500/50 mix-blend-multiply">...</div>
```

## Migration from v3

The Tailwind team ships an upgrade tool:

```bash
npx @tailwindcss/upgrade@next
```

This handles most of the migration automatically:

1. Removes `tailwind.config.ts` and moves values to `@theme` in CSS
2. Updates import from `@tailwind base/components/utilities` to `@import "tailwindcss"`
3. Updates deprecated utility names (`shadow-sm` → `shadow-xs`, `ring-offset` → `outline-offset`)
4. Updates `content` config to `@source` directives

After running the tool, check:

- Custom plugins: the v4 plugin API changed. Most first-party plugins (`@tailwindcss/typography`, `@tailwindcss/forms`) have v4 releases.
- `theme()` function calls in CSS: use CSS variables instead (`var(--color-construx)`)
- JIT-mode specifics: v4 is always JIT, but some v3 JIT edge cases may behave differently

## v3 class that changed names

```
v3                    v4
shadow-sm        →    shadow-xs
shadow           →    shadow-sm
ring             →    ring-1 (ring now means border-radius ring)
placeholder-*    →    placeholder:text-*
```

Most class names are unchanged. The codemod handles renames automatically.

## Performance

v4's Rust-based parser processes large codebases dramatically faster:

- Cold build: 3-5x faster than v3
- Incremental builds in watch mode: near-instant

For a project with 300+ component files, v4's cold build drops from ~2s to ~400ms.

## Should you migrate?

v4 is stable and production-ready. The migration is straightforward for projects that stick to core utilities. It's more involved if you have:

- Many custom plugins with the v3 plugin API
- Heavy use of `theme()` function in CSS
- Complex `extend` configurations in `tailwind.config.ts`

For new projects: start with v4. For existing projects: run the codemod and check the output before shipping.
