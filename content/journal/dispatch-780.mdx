A TypeScript function is a deployed endpoint. No build, no deploy, no infrastructure.

## HTTP handler

```ts
// @lewis/stripe-webhook — becomes https://lewis-stripe-webhook.web.val.run
export default async function(req: Request): Promise<Response> {
  const signature = req.headers.get('stripe-signature');
  const body      = await req.text();

  // Verify signature
  const event = verifyStripeWebhook(body, signature, Deno.env.get('STRIPE_SECRET')!);
  if (!event) {
    return new Response('Invalid signature', { status: 400 });
  }

  if (event.type === 'payment_intent.succeeded') {
    // Send Slack notification
    await fetch(Deno.env.get('SLACK_WEBHOOK_URL')!, {
      method:  'POST',
      headers: { 'Content-Type': 'application/json' },
      body:    JSON.stringify({ text: `Payment succeeded: $${event.data.object.amount / 100}` }),
    });
  }

  return new Response('OK', { status: 200 });
}
```

URL is `https://lewis-stripe-webhook.web.val.run` immediately.

## Cron jobs

```ts
// @lewis/weekly-digest — runs every Monday at 8am UTC
export default async function() {
  const posts = await fetchLatestPosts();
  const html  = renderDigestEmail(posts);

  await email({
    subject: 'Construx Weekly Digest',
    html,
    to:      ['lewis@construxgroup.io'],
  });

  console.log(`Sent digest with ${posts.length} posts`);
}
```

Schedule: `0 8 * * 1` in the Val Town dashboard.

## Email handler

```ts
// @lewis/contact-form-handler — receives emails sent to lewis@lewis.valtown.email
export default async function(email: Email) {
  const { from, subject, text } = email;

  // Forward to Slack
  await fetch(Deno.env.get('SLACK_WEBHOOK')!, {
    method: 'POST',
    body:   JSON.stringify({
      text: `📧 New contact from ${from}\n*Subject:* ${subject}\n${text}`,
    }),
  });

  // Auto-reply
  await sendEmail({
    to:      from,
    subject: `Re: ${subject}`,
    text:    'Thanks for reaching out. We\'ll get back to you within 24 hours.',
  });
}
```

## Import from npm or esm.sh

```ts
import { Resend } from 'npm:resend';
import { z }      from 'npm:zod';
import ky         from 'https://esm.sh/ky';

const resend = new Resend(Deno.env.get('RESEND_API_KEY'));
```

Val Town runs on Deno, so npm packages work via `npm:` prefix and ESM via URL imports.

## SQLite persistence

```ts
import { sqlite } from 'https://esm.town/v/std/sqlite';

// Create table on first run
await sqlite.execute(`
  CREATE TABLE IF NOT EXISTS page_views (
    id        INTEGER PRIMARY KEY,
    path      TEXT    NOT NULL,
    viewed_at DATETIME DEFAULT CURRENT_TIMESTAMP
  )
`);

// Insert
await sqlite.execute(
  'INSERT INTO page_views (path) VALUES (?)',
  ['/blog/new-post'],
);

// Query
const { rows } = await sqlite.execute(
  'SELECT path, COUNT(*) as views FROM page_views GROUP BY path ORDER BY views DESC LIMIT 10',
);
```

SQLite is per-val, persistent across invocations.

## Share and fork

Every val is public by default (can be made private). You can fork any val — one click copies the code to your account with full edit access. For utilities like Stripe webhook verification, HMAC signing, or cron-driven data fetches, the ecosystem already has working vals to fork.

Val Town vs Cloudflare Workers vs AWS Lambda: Val Town has the lowest friction — edit in browser, no CLI, immediate URL. Cloudflare Workers is faster and scales higher but requires local dev tooling. Lambda has the most configuration options but the most setup. The Construx default: Val Town for internal automations, webhooks, and one-off scripts; Cloudflare Workers for production APIs.
