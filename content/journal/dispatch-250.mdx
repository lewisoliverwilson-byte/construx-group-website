Scoutr's core flow: user pastes a URL, Scoutr extracts the product identifier, fetches data about the product, and returns a margin calculation.

The first step — extracting the product identifier — is more complex than it appears. URLs are messy.

## Amazon ASIN format

Amazon Standard Identification Numbers (ASINs) are 10-character alphanumeric strings. They appear in Amazon URLs in multiple patterns:

```
https://www.amazon.co.uk/dp/B0CKY5YV8H
https://www.amazon.co.uk/dp/B0CKY5YV8H/ref=sr_1_1_sspa
https://www.amazon.co.uk/product-name-here/dp/B0CKY5YV8H
https://www.amazon.co.uk/product-name/dp/B0CKY5YV8H?th=1&psc=1
https://amzn.to/3X9KsPm  ← shortened URL, requires redirect resolution
https://www.amazon.co.uk/gp/product/B0CKY5YV8H
https://www.amazon.co.uk/gp/aw/d/B0CKY5YV8H  ← mobile format
```

The ASIN always follows `/dp/` or `/gp/product/` or `/gp/aw/d/`. The regex:

```ts
function extractAmazonAsin(url: string): string | null {
  // Match the various ASIN positions
  const patterns = [
    /\/dp\/([A-Z0-9]{10})/,
    /\/gp\/product\/([A-Z0-9]{10})/,
    /\/gp\/aw\/d\/([A-Z0-9]{10})/,
    /\/ASIN\/([A-Z0-9]{10})/,
  ];

  for (const pattern of patterns) {
    const match = url.match(pattern);
    if (match?.[1]) return match[1];
  }

  return null;
}
```

ASINs are case-insensitive but Amazon's URLs always use uppercase. The `{10}` length constraint prevents false matches on longer strings that happen to start with `A-Z0-9`.

## The shortened URL problem

Amazon's short URLs (`amzn.to/...`, `amzn.eu/...`) require resolving a redirect to get the real URL with the ASIN. We resolve these server-side:

```ts
async function resolveUrl(url: string): Promise<string> {
  if (!url.includes('amzn.to') && !url.includes('amzn.eu')) {
    return url;
  }

  const response = await fetch(url, {
    method: 'HEAD',
    redirect: 'follow',
  });

  return response.url; // The final URL after redirects
}
```

A `HEAD` request with `redirect: 'follow'` resolves the chain of redirects and returns the final URL without downloading the page body.

## eBay item IDs

eBay item IDs are 12-digit numbers. They appear in URLs as:

```
https://www.ebay.co.uk/itm/123456789012
https://www.ebay.co.uk/itm/product-name/123456789012
https://www.ebay.co.uk/p/123456789012  ← product overview page
https://www.ebay.co.uk/itm/123456789012?hash=item1234&...
```

```ts
function extractEbayItemId(url: string): string | null {
  const patterns = [
    /\/itm\/(?:[^/]+\/)?(\d{10,14})/,
    /\/p\/(\d{10,14})/,
    /[?&]item=(\d{10,14})/,
  ];

  for (const pattern of patterns) {
    const match = url.match(pattern);
    if (match?.[1]) return match[1];
  }

  return null;
}
```

The `{10,14}` range handles eBay's evolving ID format — older item IDs were 12 digits; newer ones can be 13 or 14.

## The normalised product ID

Scoutr uses an internal product ID format that encodes the marketplace and identifier:

```ts
type ProductId = 
  | `amazon:${string}` // e.g. amazon:B0CKY5YV8H
  | `ebay:${string}`   // e.g. ebay:123456789012
  | `unknown:${string}`; // e.g. unknown:${urlHash}

function parseProductId(url: string): ProductId {
  const normalised = url.trim().toLowerCase();

  if (normalised.includes('amazon.co.uk') || normalised.includes('amazon.com') || normalised.includes('amzn.')) {
    const resolvedUrl = normalised.includes('amzn.') ? resolveUrl(url) : url;
    const asin = extractAmazonAsin(await resolvedUrl);
    if (asin) return `amazon:${asin.toUpperCase()}`;
  }

  if (normalised.includes('ebay.co.uk') || normalised.includes('ebay.com')) {
    const itemId = extractEbayItemId(url);
    if (itemId) return `ebay:${itemId}`;
  }

  // Unknown marketplace: hash the URL
  return `unknown:${hashUrl(url)}`;
}
```

The `unknown:` prefix signals to downstream code that we couldn't extract a structured identifier. For unknown URLs, Scoutr attempts a Claude-powered extraction of the product name and category from the page HTML, which then drives a fuzzy marketplace search.

## The validation layer

Before running the extraction, we validate that the URL is a product page, not a category page, search results, or account page:

```ts
const CATEGORY_PATTERNS = [
  /\/s\?/,           // Amazon search
  /\/s\/ref=/,       // Amazon category ref
  /\/b\//,           // Amazon brand/category
  /\/sch\//,         // eBay search
  /\/itm\/[^/]+\/$/  // eBay with no item ID
];

const ACCOUNT_PATTERNS = [
  /\/account/,
  /\/sign-in/,
  /\/signin/,
];

function isProductUrl(url: string): boolean {
  const lower = url.toLowerCase();
  if (CATEGORY_PATTERNS.some((p) => p.test(lower))) return false;
  if (ACCOUNT_PATTERNS.some((p) => p.test(lower))) return false;
  return true;
}
```

If `isProductUrl` returns false, we return an early error: "This looks like a search or category page. Paste a specific product URL."

## The edge cases we found in production

**Variant ASINs.** Amazon product variants (sizes, colours) sometimes have different ASINs from the base product. The URL `/dp/B0CKY5YV8H?th=1` refers to the product but the `?th=1` query param sometimes indicates a variant. We extract the ASIN from the path and ignore query params — this occasionally results in scanning the base product when the user wanted a specific variant, but the data is still a useful approximation.

**Sponsored product URLs.** Amazon sponsored product links go through a tracking redirect: `https://www.amazon.co.uk/sspa/click?ie=UTF8&spc=...&url=...`. The actual product URL is in the `url` parameter, URL-encoded. We detect and unwrap these.

**Merchant-fulfilled URLs.** Some Amazon listings are fulfilled by third-party merchants and have different URL structures. We added a fallback pattern for these based on the production failures we saw.

**eBay "Buy It Now" vs auction pages.** The item ID is the same for both, but the listing type affects our confidence score (auction prices are less predictable than BIN prices).

The parser has evolved through 10+ iterations based on URLs that failed in production. Each new URL pattern that fails gets added as a test case.
