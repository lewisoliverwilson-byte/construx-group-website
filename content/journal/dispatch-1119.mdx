excerpt: "Grafana OnCall is an open-source on-call management system that handles alert routing, escalation chains, on-call schedules, and incident coordination. It integrates with Alertmanager, Grafana, PagerDuty, OpsGenie, and any webhook source, routing alerts to the correct on-call engineer based on schedule, severity, and team. The core model: Integrations receive alerts from monitoring systems; Alert Groups deduplicate and group related alerts (a flapping service generates one alert group, not 200 individual alerts); Routes match alert groups to Escalation Chains; Escalation Chains define the sequence of notifications (notify on Slack after 1 minute, call mobile after 5 minutes, page the secondary on-call after 10 minutes). On-call schedules define who is on duty — overrides handle vacations and ad-hoc swaps. The mobile app receives push notifications for critical pages, with acknowledgment and resolution directly from the phone. OnCall's alert grouping is particularly important: raw Alertmanager sends one notification per firing alert instance, which becomes noise during incidents. OnCall groups alerts by configurable template (e.g., all alerts from the same service in the same namespace group together), giving the on-call engineer a single incident view rather than 50 parallel Slack notifications. At Construx, OnCall routes critical Falco and Alertmanager alerts through a 24/7 escalation chain, with a 15-minute SLA for acknowledgment before it escalates to secondary."

# Templates use Jinja2 to extract fields from alert payload
# Define per-integration in OnCall UI or API

# Title template: extract meaningful title from Alertmanager alert
{% if payload.commonAnnotations.summary %}
  {{ payload.commonAnnotations.summary }}
{% else %}
  {{ payload.commonLabels.alertname }} in {{ payload.commonLabels.namespace }}
{% endif %}

# Grouping key: group related alerts into one alert group
# All alerts from the same service+namespace go into one incident
{{ payload.commonLabels.alertname }}_{{ payload.commonLabels.namespace }}_{{ payload.commonLabels.service }}

# Severity routing: route to different escalation chains by severity
# Used in Route conditions
{% if payload.commonLabels.severity == "critical" %}critical{% else %}warning{% endif %}

# Source URL template: link to Grafana dashboard for the firing service
https://grafana.construx.internal/d/k8s-service?var-namespace={{ payload.commonLabels.namespace }}&var-service={{ payload.commonLabels.service }}

```bash
# OnCall API: manage schedules and escalation chains programmatically

ONCALL_API="https://oncall.construx.internal/api/v1"
TOKEN="${ONCALL_API_TOKEN}"

# List on-call schedules
curl -s -H "Authorization: ${TOKEN}" "${ONCALL_API}/schedules/" | \
  jq '.results[] | {name: .name, type: .type, team: .team}'

# Get current on-call for the primary schedule
curl -s -H "Authorization: ${TOKEN}" \
  "${ONCALL_API}/schedules/$(curl -s -H "Authorization: ${TOKEN}" \
    "${ONCALL_API}/schedules/?name=construx-primary" | jq -r '.results[0].id')/final_shifts/?date_start=$(date -I)&date_end=$(date -I)" | \
  jq '.results[] | {user: .user.username, start: .shift_start, end: .shift_end}'

# Create an override (e.g., swap on-call coverage for a specific date)
curl -s -X POST -H "Authorization: ${TOKEN}" \
  -H "Content-Type: application/json" \
  "${ONCALL_API}/schedules/${SCHEDULE_ID}/overrides/" \
  -d '{
    "start": "2034-02-22T18:00:00Z",
    "end":   "2034-02-23T09:00:00Z",
    "user":  "'"${USER_ID}"'"
  }'

# Acknowledge an alert group (silence notifications)
curl -s -X POST -H "Authorization: ${TOKEN}" \
  "${ONCALL_API}/alertgroups/${ALERT_GROUP_ID}/acknowledge/"

# Resolve an alert group
curl -s -X POST -H "Authorization: ${TOKEN}" \
  "${ONCALL_API}/alertgroups/${ALERT_GROUP_ID}/resolve/"

# Silence all alerts for 2 hours during maintenance
curl -s -X POST -H "Authorization: ${TOKEN}" \
  -H "Content-Type: application/json" \
  "${ONCALL_API}/alertgroups/silence/" \
  -d '{"ids": ["'"${ALERT_GROUP_ID}"'"], "delay": 7200}'
```

OnCall vs PagerDuty vs OpsGenie vs VictorOps vs direct Slack alerting: PagerDuty is the industry standard for enterprise on-call management — excellent mobile apps, deep integrations, proven reliability, and sophisticated escalation policies. Its cost scales with the number of users and integrations. OpsGenie (acquired by Atlassian) is similar in scope and often bundled with Jira Service Management. VictorOps (acquired by Splunk, now Splunk On-Call) focuses on incident collaboration with timeline and chat. Direct Slack alerting (the majority of small teams) has no escalation, no scheduling, and no acknowledgment tracking — critical alerts get lost in channel noise during incidents. Grafana OnCall's differentiation is integration depth with the Grafana observability stack: alert groups link directly to Grafana dashboards, traces in Tempo, and logs in Loki, so the on-call engineer has full context without switching tools. For teams already running Grafana + Alertmanager + Loki, OnCall removes the tool-switching overhead that slows incident response. The open-source version is free and self-hosted; Grafana Cloud offers it as a managed service at a fraction of PagerDuty's per-user cost.
