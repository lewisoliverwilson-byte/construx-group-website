title: "Cosign and Sigstore: supply chain security — signing and verifying container images"
date: "2033-05-07"
excerpt: "Cosign is the signing tool in the Sigstore project — a free, open supply chain security infrastructure. The core operation: sign a container image digest with an ECDSA key or a keyless OIDC-based identity, and push the signature to the OCI registry alongside the image. Verifiers (Kyverno, Admission webhooks, cosign verify in CI) check the signature before allowing the image to run. Keyless signing is the headline feature: no long-lived private key to manage — the signing identity is derived from a short-lived certificate issued by Sigstore's Fulcio CA, backed by an OIDC token from GitHub Actions, Google, or another identity provider. The signature and certificate are logged in Rekor, a public append-only transparency log, making all signatures auditable. The result is a verifiable chain from CI build to deployed container."
author: "Lewis Wilson"

Keyless signing. OIDC identity. Fulcio CA. Rekor transparency log. OCI registry. Kyverno verify.

## Signing in CI (GitHub Actions)

```yaml
# GitHub Actions workflow: build, sign, and push a container image

name: build-and-sign
on:
  push:
    branches: [master]

permissions:
  id-token: write    # required for keyless OIDC signing
  contents: read
  packages: write

jobs:
  build-sign-push:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to registry
        uses: docker/login-action@v3
        with:
          registry: registry.construx.internal
          username: ${{ secrets.REGISTRY_USER }}
          password: ${{ secrets.REGISTRY_PASSWORD }}

      # Build and push — capture the digest for signing
      - name: Build and push
        id: build
        uses: docker/build-push-action@v5
        with:
          push: true
          tags: registry.construx.internal/api:${{ github.sha }}
          outputs: type=registry

      # Sign with cosign keyless — uses the GitHub OIDC token
      # No private key needed — identity is the GitHub Actions workflow URL
      - name: Sign image
        uses: sigstore/cosign-installer@v3
        
      - run: |
          cosign sign --yes \
            registry.construx.internal/api@${{ steps.build.outputs.digest }}
        env:
          COSIGN_EXPERIMENTAL: "1"   # enables keyless signing

      # Attach SBOM (Software Bill of Materials) as an attestation
      - name: Generate SBOM with Syft
        run: |
          syft registry.construx.internal/api:${{ github.sha }} \
            -o spdx-json > sbom.json

      - name: Attach SBOM attestation
        run: |
          cosign attest --yes \
            --type spdxjson \
            --predicate sbom.json \
            registry.construx.internal/api@${{ steps.build.outputs.digest }}
```

## Verifying signatures

```bash
# Verify: confirm the image was signed by the expected GitHub Actions workflow
cosign verify \
  --certificate-identity "https://github.com/lewisoliverwilson-byte/construx-api/.github/workflows/build-and-sign.yaml@refs/heads/master" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  registry.construx.internal/api:latest

# Output on success:
# Verification for registry.construx.internal/api:latest --
# The following checks were performed on each of these signatures:
#   - The cosign claims were validated
#   - Existence of the claims in the transparency log was verified
#   - The code-signing certificate claims were verified
# [
#   {
#     "critical": {
#       "identity": { "docker-reference": "registry.construx.internal/api" },
#       "image": { "docker-manifest-digest": "sha256:a1b2c3..." }
#     },
#     "optional": {
#       "Issuer": "https://token.actions.githubusercontent.com",
#       "Subject": "https://github.com/lewisoliverwilson-byte/construx-api/..."
#     }
#   }
# ]

# Verify SBOM attestation
cosign verify-attestation \
  --type spdxjson \
  --certificate-identity "https://github.com/lewisoliverwilson-byte/construx-api/..." \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  registry.construx.internal/api:latest | jq '.payload | @base64d | fromjson'

# Check Rekor: transparency log entry for the signature
rekor-cli get --uuid <uuid-from-cosign-output>
# Shows: timestamp, signature, certificate, payload — permanently logged
```

## Kyverno image verification policy

```yaml
# Kyverno: enforce that all images in construx-prod are signed
# (pairs with the Kyverno ClusterPolicy from dispatch-1015)

apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: verify-image-signatures
spec:
  validationFailureAction: Enforce
  rules:
    - name: verify-cosign-signature
      match:
        any:
          - resources:
              kinds: [Pod]
              namespaces: [construx-prod, construx-staging]
      verifyImages:
        - imageReferences:
            - "registry.construx.internal/*"
          attestors:
            - count: 1
              entries:
                - keyless:
                    subject: "https://github.com/lewisoliverwilson-byte/*"
                    issuer:  "https://token.actions.githubusercontent.com"
                    rekor:
                      url: https://rekor.sigstore.dev
          # Mutate the image tag to the digest — pins to the exact image that was signed
          mutateDigest: true
          # Verify the SBOM attestation is present
          attestations:
            - predicateType: https://spdx.dev/Document
              attestors:
                - entries:
                    - keyless:
                        subject: "https://github.com/lewisoliverwilson-byte/*"
                        issuer:  "https://token.actions.githubusercontent.com"
```

Cosign vs Notary v2 vs in-house signing with GPG: Notary v2 is the CNCF project for signing OCI artifacts, based on TUF (The Update Framework) — more complex but better for enterprise delegation models (who can sign what). GPG signing is manual, key management is complex, and there is no standard way to attach a signature to an OCI image in a registry-native way. Cosign uses the OCI registry as the storage layer for signatures (stored as OCI artifacts with the `:sha256-<digest>.sig` tag convention), so no external signature server is needed. Keyless signing (via Fulcio + OIDC) eliminates private key management entirely — the signing identity is the CI workflow identity, which is auditable and ephemeral. For teams already on GitHub Actions and wanting supply chain security without key management overhead, keyless Cosign is the fastest path to signed images.
