A marketplace with five listings isn't a marketplace. It's a prototype that looks like a marketplace. For The Marqet to be credible as a destination for professional Claude configurations, it needed density — enough listings that a user in any category could find something useful on the first visit.

The problem: 167 listings is a lot of content. Each listing needed a title, a description, a system prompt, a category, subcategory, and a set of use-case tags. Writing all of that by hand would have taken weeks. Weeks we didn't have.

Here's how we built it instead.

## What The Marqet is

The Marqet is an AI-native marketplace for professional Claude configurations. Think of it like a plugin store, but instead of code, the products are system prompts and workflows — configurations that turn Claude into a specialist for a specific use case.

A researcher configuring Claude for academic literature review needs different instructions than a developer using it for code review, which needs different instructions than a marketer using it for competitive analysis. The Marqet is where those configurations live, discoverable and usable without starting from scratch.

## The taxonomy problem

Before we could generate any content, we needed to know what we were generating. A marketplace needs a taxonomy — categories and subcategories that are coherent enough to navigate but not so granular that they fracture the content.

We landed on four verticals: Professional Services, Content & Writing, Research & Analysis, and Developer Tools. Within each, between four and eight subcategories. Thirty-two subcategories in total, each with a clear definition of what belongs in it.

Getting the taxonomy right took longer than we expected. The first version was too technical — built from the perspective of what Claude can do rather than what users want to accomplish. Claude helped us rethink it from the user's direction, asking "what problem does someone have when they search for this?" for each proposed category. The second version was better. The final version has held up well.

## The content pipeline

With the taxonomy set, we built a generation pipeline:

**Stage one: brief generation.** For each subcategory, we generated a set of use case briefs — one-paragraph descriptions of a specific professional task that a Claude configuration could help with. We generated approximately six briefs per subcategory, then filtered to the ones with the clearest real-world utility.

**Stage two: listing generation.** For each brief, we generated a full listing — title, description, system prompt, tags. The system prompt here was the hard part. Generating a system prompt that actually works well for the described use case required careful constraint. Early versions were too generic. We iterated on the meta-prompt until the output was consistently specific enough to be useful.

**Stage three: quality review.** Every generated listing went through a review pass. Not a human reading every word — a structured evaluation against a rubric: does the description match the system prompt? Is the system prompt specific enough to be useful? Is the claimed use case realistic? About 15% of listings failed this and were regenerated or cut.

**Stage four: categorisation.** Each listing was assigned to a subcategory and tagged. We spot-checked the categorisation manually across a sample and found it accurate enough to ship.

## The honest numbers

We generated approximately 210 listings through the pipeline. 167 passed quality review and shipped. The rest were cut — not because the generation failed, but because they were either too similar to an existing listing or too generic to be useful.

The pipeline took four days to build and run. The manual quality review of the 167 that shipped took around six hours.

Without the pipeline: six weeks of writing, minimum. With it: four days to build, one day to run, one day to review. The ratio matters.

## What we learned about AI-generated content

The concern with AI-generated marketplace listings is obvious: they'll be generic, shallow, and indistinguishable from each other. That concern is real but manageable.

The key is constraint. Unconstrained, a language model will write the most average possible version of the thing you asked for. Tightly constrained — with a specific use case, a specific user, a specific task — it writes something that's actually useful.

The prompts that generated our listings are more specific than most people would write. They specify the professional context, the task, the output format, the constraints. Writing those prompts well is the skill. The generation is the easy part.

## What's next

167 listings is a foundation. The Marqet now has enough content to be useful in every category it covers. The next phase is quality at the top — a smaller number of premium configurations that have been tested and validated against real workflows.

The pipeline is how you get to scale. The handwork is how you get to excellent. Both are necessary. Only one of them can be automated.
