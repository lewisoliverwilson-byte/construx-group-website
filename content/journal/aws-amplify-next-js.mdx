AWS Amplify is the deployment platform for all four Construx sites: the construx-group-website and the three product applications. We chose it for managed Next.js hosting with git-based deployments, without the vendor lock-in concerns of Vercel.

Here's the honest account of the Amplify + Next.js experience.

## The setup

Amplify detects Next.js automatically. Connect a GitHub repository, and Amplify configures the build pipeline:

```yaml
# amplify.yml (auto-generated, customisable)
version: 1
frontend:
  phases:
    preBuild:
      commands:
        - npm ci
    build:
      commands:
        - npm run build
  artifacts:
    baseDirectory: .next
    files:
      - '**/*'
  cache:
    paths:
      - node_modules/**/*
      - .next/cache/**/*
```

Every push to the `master` branch triggers a build. If the build succeeds, the deployment is live within 3-4 minutes.

## What works well

**Preview deployments for branches.** When you open a pull request, Amplify builds and deploys the branch to a unique preview URL (`branch-name.APP_ID.amplifyapp.com`). This is invaluable for reviewing UI changes before merging.

**Environment variables.** Each Amplify app has its own set of environment variables, set in the console. The variables are available to the build process and are injected into the deployment. We store API keys, database connection strings, and feature flags here.

**Edge deployments.** Amplify deploys to AWS CloudFront (their CDN), so static assets are served from edge locations globally. Response times from anywhere in the world are fast for cached content.

**Auto-scaling.** We don't manage server capacity. Amplify handles scale automatically. For a product that might spike in traffic, this is valuable.

## What doesn't work well

**Server Actions and edge functions.** Next.js Server Actions work in Amplify, but the deployment model differs from Vercel. Server components and Server Actions run as Lambda functions rather than on Vercel's Edge Network. This works, but cold start times can be higher than expected — the first request to a Server Action after a quiet period may take 500-1000ms as the Lambda initialises.

**The build cache is unreliable.** Amplify's build cache (`.next/cache`) should speed up subsequent builds by preserving the Next.js compilation cache. In practice, we've found that the cache is invalidated more often than expected, resulting in full rebuild times (2-3 minutes) even for small changes. Vercel handles this significantly better.

**Environment variable configuration is manual.** There's no native way to sync environment variables between local development and Amplify. We maintain a `.env.local` file for development and separately manage the Amplify console environment variables. When we add a new environment variable, it has to be added in both places manually.

**Monorepo support is limited.** All four Construx sites are in separate repositories. If we were using a monorepo (all sites in one repo), Amplify's monorepo support would make configuration more complex. We avoid this by keeping each product in a separate repository.

## The CI/CD workflow

Our deployment workflow:

1. Develop locally, test locally (`npm run dev`)
2. Push to a feature branch
3. Amplify builds and deploys the branch automatically to a preview URL
4. Review the preview, fix any issues
5. Merge to master via pull request
6. Amplify automatically deploys master to production

The TypeScript check (`npx tsc --noEmit`) runs locally before we push. We don't have a formal CI step that blocks the Amplify build on TypeScript errors — the Amplify build would catch type errors that prevent compilation, but not type errors with `skipLibCheck: true`. Stricter CI validation is on the list.

## The cost

Amplify pricing is based on build minutes, data transfer, and request count. For our current traffic:

- Build cost: approximately $3-4/month across all four apps (each build takes 2-4 minutes at $0.01 per build minute)
- Hosting cost: included in the free tier (the first 1000 build minutes and 5GB data transfer per month are free)
- Lambda request cost: minimal at current traffic

Total Amplify cost: roughly $5-10/month across all four apps. This is significantly cheaper than equivalent Vercel Pro pricing.

## The Vercel comparison

Vercel is the default recommendation for Next.js deployment, and for good reason: it's built by the same team that builds Next.js, and the integration is excellent. Edge functions work flawlessly, build caching is reliable, and the developer experience is the best in class.

Why we use Amplify instead:

1. **AWS ecosystem integration.** The Construx products also use RDS (Postgres) and S3 (file storage). Having the hosting in the same AWS environment simplifies networking and access configuration.

2. **Cost at scale.** Vercel Pro is $20/month per user. We run four applications; at scale, Amplify's per-request pricing is lower than Vercel's per-seat pricing.

3. **No vendor lock-in.** Amplify can be replaced with other AWS services (ECS, EC2) without changing the application code. Vercel Edge Functions and Middleware use Vercel-specific APIs.

The trade-off: worse build caching, worse cold start performance, more manual configuration. For our current scale, these trade-offs are acceptable. At higher traffic where cold starts matter more, we'd re-evaluate.
