A webhook is a POST request your service sends to someone else's URL when something happens. On the receiving end, the same three problems appear every time: verifying the payload is genuine, processing it exactly once, and responding fast enough that the sender doesn't retry.

## Signature verification

Every serious webhook provider signs its payloads. Stripe uses HMAC-SHA256 with a timestamp in the header to prevent replay attacks:

```ts
// lib/stripe-webhook.ts
import Stripe from 'stripe';
import { stripe } from './stripe';

export function constructStripeEvent(
  body: string,
  signature: string,
): Stripe.Event {
  const secret = process.env.STRIPE_WEBHOOK_SECRET!;
  return stripe.webhooks.constructEvent(body, signature, secret);
}
```

```ts
// app/api/webhooks/stripe/route.ts
export async function POST(req: Request) {
  const body = await req.text(); // raw body — must not parse JSON first
  const signature = req.headers.get('stripe-signature')!;

  let event: Stripe.Event;
  try {
    event = constructStripeEvent(body, signature);
  } catch {
    return new Response('Invalid signature', { status: 400 });
  }

  await processStripeEvent(event);
  return new Response('OK', { status: 200 });
}
```

The raw body requirement is the common mistake: if you parse JSON before passing to `constructEvent`, the signature check fails because the raw bytes have changed.

## Idempotency

Webhook providers retry on failure. If your endpoint returns 500 or times out, Stripe will retry the same event multiple times. Your handler must be idempotent — processing the same event twice must produce the same result as processing it once.

The pattern: track processed event IDs in the database.

```ts
// lib/webhook-processor.ts
export async function processStripeEvent(event: Stripe.Event) {
  const processed = await db.query(
    'SELECT id FROM processed_webhook_events WHERE event_id = $1',
    [event.id],
  );
  if (processed.rows.length > 0) return; // already handled

  await db.transaction(async (trx) => {
    // Insert first — if this fails, we retry. If it succeeds, we process.
    await trx.query(
      'INSERT INTO processed_webhook_events (event_id, created_at) VALUES ($1, NOW())',
      [event.id],
    );
    await handleEvent(trx, event);
  });
}
```

The transaction ensures that if `handleEvent` fails, the event ID isn't recorded as processed. The next retry will attempt again cleanly.

## Respond fast, process async

Webhook providers have short timeouts — Stripe's is 30 seconds, GitHub's is 10. If your handler does anything slow (sends email, calls an external API, runs a complex database query), you'll timeout and trigger retries.

The fix: acknowledge immediately, enqueue work.

```ts
// app/api/webhooks/stripe/route.ts
import { webhookQueue } from '@/lib/queues';

export async function POST(req: Request) {
  const body = await req.text();
  const signature = req.headers.get('stripe-signature')!;

  let event: Stripe.Event;
  try {
    event = constructStripeEvent(body, signature);
  } catch {
    return new Response('Invalid signature', { status: 400 });
  }

  // Enqueue for async processing — respond in <100ms
  await webhookQueue.add('stripe-event', { event });

  return new Response('Queued', { status: 200 });
}
```

The queue worker handles deduplication, retries, and the actual work. The HTTP handler's only job is signature verification and enqueuing.

## Building a webhook sender

When your product sends webhooks to customers:

```ts
// lib/webhook-sender.ts
import crypto from 'crypto';

interface WebhookEndpoint {
  url: string;
  secret: string;
}

export async function sendWebhook(
  endpoint: WebhookEndpoint,
  eventType: string,
  payload: unknown,
) {
  const body = JSON.stringify({ type: eventType, data: payload });
  const timestamp = Math.floor(Date.now() / 1000);
  const signature = crypto
    .createHmac('sha256', endpoint.secret)
    .update(`${timestamp}.${body}`)
    .digest('hex');

  const res = await fetch(endpoint.url, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-Webhook-Timestamp': String(timestamp),
      'X-Webhook-Signature': `sha256=${signature}`,
    },
    body,
  });

  if (!res.ok) {
    throw new Error(`Webhook delivery failed: ${res.status}`);
  }
}
```

For retry logic, use exponential backoff:

```ts
export async function sendWebhookWithRetry(
  endpoint: WebhookEndpoint,
  eventType: string,
  payload: unknown,
  maxAttempts = 5,
) {
  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    try {
      await sendWebhook(endpoint, eventType, payload);
      return;
    } catch (err) {
      if (attempt === maxAttempts) throw err;
      const delay = Math.min(1000 * 2 ** attempt, 30_000);
      await new Promise((r) => setTimeout(r, delay));
    }
  }
}
```

Delays: 2s, 4s, 8s, 16s, 30s (capped). This matches how Stripe and GitHub retry.

## The delivery log

Track every delivery attempt — customers debugging integrations need to see what was sent and when:

```ts
await db.query(`
  INSERT INTO webhook_deliveries
    (endpoint_id, event_type, payload, status_code, attempt, created_at)
  VALUES ($1, $2, $3, $4, $5, NOW())
`, [endpointId, eventType, JSON.stringify(payload), statusCode, attempt]);
```

Surface this in your dashboard so customers can see delivery history and manually trigger replays.
