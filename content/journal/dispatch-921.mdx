Drop all. Add back only what you need. CAP_NET_BIND_SERVICE for ports, nothing else.

## Inspecting capabilities

```bash
# List all Linux capabilities (Linux 5.1 has 41 capabilities)
man capabilities | grep "CAP_" | head -41

# Key capabilities and what they allow:
# CAP_NET_BIND_SERVICE  — bind ports < 1024 (HTTP :80, HTTPS :443)
# CAP_NET_RAW           — raw/packet sockets (ping, nmap, tcpdump)
# CAP_SYS_PTRACE        — ptrace other processes (strace, gdb)
# CAP_SYS_ADMIN         — broad admin powers (mount, bpf, perf, cgroups) — dangerous
# CAP_DAC_OVERRIDE      — bypass file permission checks — dangerous
# CAP_CHOWN             — change file ownership
# CAP_SETUID/SETGID     — change UID/GID (needed by su, sudo)
# CAP_NET_ADMIN         — network config (ip, tc, iptables) — dangerous
# CAP_KILL              — send signals to any process
# CAP_IPC_LOCK          — lock memory into RAM (needed by databases, HSMs)

# Check capabilities of the current process
capsh --print
# Current: = cap_chown,cap_dac_override,...+ep    (full root: dangerous in containers)
# or for a non-root process:
# Current: =

# Check capabilities of a running process
cat /proc/1847/status | grep Cap
# CapInh: 0000000000000000    (inheritable)
# CapPrm: 0000000000000400    (permitted)
# CapEff: 0000000000000400    (effective)

# Decode the hex capability mask
capsh --decode=0000000000000400
# 0x0000000000000400=cap_net_bind_service

# Check file capabilities (set on the binary itself, not the process)
getcap /usr/bin/ping
# /usr/bin/ping = cap_net_raw+ep   ← ping has CAP_NET_RAW without setuid
```

## Setting capabilities on binaries

```bash
# Grant CAP_NET_BIND_SERVICE to a binary so it can bind :80 without running as root
# This replaces the need to run as root or use setuid
sudo setcap cap_net_bind_service=ep /usr/local/bin/construx-api
getcap /usr/local/bin/construx-api
# /usr/local/bin/construx-api = cap_net_bind_service+ep

# Now construx-api can bind :80 as a non-root user
sudo -u construx /usr/local/bin/construx-api --port 80
# (succeeds without root)

# Grant CAP_NET_RAW to a custom monitoring binary (for ICMP probes)
sudo setcap cap_net_raw+ep /usr/local/bin/construx-prober

# Grant IPC_LOCK to a secrets manager (to lock memory — prevent secrets from swapping)
sudo setcap cap_ipc_lock+ep /usr/local/bin/construx-vault-agent

# Remove all capabilities from a binary
sudo setcap -r /usr/local/bin/construx-api
getcap /usr/local/bin/construx-api
# (no output — capabilities removed)

# List all binaries with file capabilities set
find / -xdev -exec getcap {} \; 2>/dev/null | grep -v "^$"
# /usr/bin/ping = cap_net_raw+ep
# /usr/bin/traceroute6 = cap_net_raw,cap_net_admin+ep
# /usr/local/bin/construx-prober = cap_net_raw+ep
```

## Kubernetes capability management

```yaml
# Drop ALL capabilities, add back only what's needed
# This is the correct security posture for most containers

apiVersion: v1
kind: Pod
spec:
  containers:
  - name: construx-api
    image: construx/api:v1.4.2
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      runAsNonRoot: true
      runAsUser: 10001
      capabilities:
        drop:
          - ALL              # Drop every capability first
        add:
          - NET_BIND_SERVICE # Only add back what's needed

  - name: construx-prober
    image: construx/prober:v1.0.0
    securityContext:
      allowPrivilegeEscalation: false
      capabilities:
        drop:
          - ALL
        add:
          - NET_RAW          # ICMP probes need raw socket access only

---
# PodSecurityAdmission: enforce "restricted" profile (no dangerous capabilities)
apiVersion: v1
kind: Namespace
metadata:
  name: construx
  labels:
    pod-security.kubernetes.io/enforce: restricted        # Enforce no escalation
    pod-security.kubernetes.io/enforce-version: v1.30
    pod-security.kubernetes.io/warn: restricted
    pod-security.kubernetes.io/audit: restricted

# Verify what capabilities a running container has
kubectl exec construx-api-6d9f5c4b8-xk2pq -- capsh --print
# Current: = cap_net_bind_service+ep
# Bounding set: cap_net_bind_service

# OPA/Gatekeeper: policy to deny privileged containers or dangerous capabilities
# (blocks CAP_SYS_ADMIN, CAP_NET_ADMIN, CAP_DAC_OVERRIDE in any pod)
```

## Capability-aware tooling

```bash
# strace needs CAP_SYS_PTRACE — add it per-binary rather than running as root
sudo setcap cap_sys_ptrace+ep /usr/bin/strace
strace -p 1847   # Now works as non-root user with the binary capability

# tcpdump needs CAP_NET_RAW + CAP_NET_ADMIN
sudo setcap cap_net_raw,cap_net_admin+ep /usr/bin/tcpdump

# Running tcpdump in a container without root:
# Add to securityContext.capabilities.add: [NET_RAW, NET_ADMIN]
# This is safer than running as root — it limits the blast radius if compromised

# Check if a container is running as root (Falco rule equivalent):
for pod in $(kubectl get pods -n construx -o name); do
  uid=$(kubectl exec ${pod#*/} -n construx -- id -u 2>/dev/null)
  echo "$pod: UID $uid"
done
# construx-api-xxx: UID 10001   ✓ non-root
# construx-worker-xxx: UID 0    ← running as root — needs to be fixed

# ambient capabilities (Linux 4.3+): capabilities inheritable by child processes
# without explicit capability-aware exec() calls
# Rarely needed in practice — file capabilities cover most cases
capsh --ambient=cap_net_raw -- su construx -c 'ping -c 1 8.8.8.8'
```

Linux capabilities vs seccomp vs AppArmor: capabilities control what privileged operations a process can perform (bind ports, trace processes, configure networking). seccomp controls which system calls a process can make — it's a syscall allowlist/blocklist. AppArmor/SELinux control which files, network addresses, and resources a process can access. Together they form a layered defense: capabilities reduce privilege (no root), seccomp restricts the syscall surface (no dangerous calls even if exploited), and AppArmor confines access to specific paths and sockets. A well-secured container uses all three: capabilities.drop=ALL + needed adds, seccomp RuntimeDefault profile (blocks 300+ dangerous syscalls), and AppArmor or SELinux policy. The Docker/Kubernetes defaults are a reasonable starting point; the hardened posture adds these explicitly in the pod spec.
