Next.js gives you three patterns for backend communication: Route Handlers (REST), tRPC (RPC with full type safety), and Server Actions (direct function calls from the server). Each has a distinct use case.

## REST Route Handlers: the default choice

For APIs consumed by external clients, mobile apps, or when you need a documented public API:

```ts
// app/api/posts/route.ts
import { NextRequest } from 'next/server';
import { z } from 'zod';
import { auth } from '@/auth';
import { db } from '@/db';

const createPostSchema = z.object({
  title: z.string().min(1).max(200),
  content: z.string().min(1),
  tag: z.enum(['Strategy', 'Build Log', 'Product', 'Methodology']),
});

export async function GET(req: NextRequest) {
  const { searchParams } = req.nextUrl;
  const tag = searchParams.get('tag');
  const limit = Number(searchParams.get('limit') ?? '20');

  const posts = await db.query.posts.findMany({
    where: tag ? eq(posts.tag, tag) : undefined,
    orderBy: [desc(posts.createdAt)],
    limit: Math.min(limit, 100),
    columns: { content: false },  // exclude large content field from list
  });

  return Response.json(posts, {
    headers: { 'Cache-Control': 'public, s-maxage=60' },
  });
}

export async function POST(req: NextRequest) {
  const session = await auth();
  if (!session?.user) {
    return Response.json({ error: 'Unauthorized' }, { status: 401 });
  }

  const body = await req.json();
  const result = createPostSchema.safeParse(body);
  if (!result.success) {
    return Response.json({ error: result.error.flatten() }, { status: 400 });
  }

  const post = await db.insert(posts)
    .values({ ...result.data, authorId: session.user.id })
    .returning();

  return Response.json(post[0], { status: 201 });
}
```

```ts
// app/api/posts/[id]/route.ts
export async function PATCH(
  req: NextRequest,
  { params }: { params: { id: string } }
) {
  const session = await auth();
  const post = await db.query.posts.findFirst({
    where: and(eq(posts.id, params.id), eq(posts.authorId, session?.user?.id ?? '')),
  });

  if (!post) return Response.json({ error: 'Not found' }, { status: 404 });

  const body = await req.json();
  const updated = await db.update(posts)
    .set(body)
    .where(eq(posts.id, params.id))
    .returning();

  return Response.json(updated[0]);
}
```

## tRPC: type-safe RPC for internal APIs

When the API is only consumed by your own Next.js frontend — no external clients — tRPC eliminates the serialization layer and gives you end-to-end type safety:

```bash
npm install @trpc/server @trpc/client @trpc/react-query @trpc/next @tanstack/react-query zod
```

```ts
// server/trpc.ts
import { initTRPC, TRPCError } from '@trpc/server';
import { auth } from '@/auth';

const t = initTRPC.context<{ session: Awaited<ReturnType<typeof auth>> }>().create();

export const router = t.router;
export const publicProcedure = t.procedure;
export const protectedProcedure = t.procedure.use(({ ctx, next }) => {
  if (!ctx.session?.user) throw new TRPCError({ code: 'UNAUTHORIZED' });
  return next({ ctx: { ...ctx, user: ctx.session.user } });
});
```

```ts
// server/routers/posts.ts
import { router, protectedProcedure, publicProcedure } from '../trpc';

export const postsRouter = router({
  list: publicProcedure
    .input(z.object({ tag: z.string().optional(), limit: z.number().default(20) }))
    .query(async ({ input }) => {
      return db.query.posts.findMany({
        where: input.tag ? eq(posts.tag, input.tag) : undefined,
        limit: input.limit,
        orderBy: [desc(posts.createdAt)],
      });
    }),

  create: protectedProcedure
    .input(createPostSchema)
    .mutation(async ({ input, ctx }) => {
      return db.insert(posts).values({ ...input, authorId: ctx.user.id }).returning();
    }),

  delete: protectedProcedure
    .input(z.object({ id: z.string() }))
    .mutation(async ({ input, ctx }) => {
      const post = await db.query.posts.findFirst({
        where: and(eq(posts.id, input.id), eq(posts.authorId, ctx.user.id)),
      });
      if (!post) throw new TRPCError({ code: 'NOT_FOUND' });
      await db.delete(posts).where(eq(posts.id, input.id));
    }),
});
```

```tsx
// Client usage — fully type-safe, autocompletes correctly
function PostList() {
  const { data: posts } = trpc.posts.list.useQuery({ tag: 'Build Log', limit: 10 });

  return posts?.map((p) => <PostCard key={p.id} post={p} />);
}

function CreatePost() {
  const utils = trpc.useUtils();
  const create = trpc.posts.create.useMutation({
    onSuccess: () => utils.posts.list.invalidate(),
  });

  return (
    <button onClick={() => create.mutate({ title: 'New post', content: '...', tag: 'Build Log' })}>
      Create
    </button>
  );
}
```

If you rename a field in the router, the client immediately shows a TypeScript error. No manual type sync.

## Server Actions: skip the network for mutations

For mutations that only happen in one place and don't need to be called from a REST client:

```ts
// app/actions/posts.ts
'use server';

import { auth } from '@/auth';
import { revalidatePath } from 'next/cache';

export async function createPost(formData: FormData) {
  const session = await auth();
  if (!session?.user) throw new Error('Unauthorized');

  const title = formData.get('title') as string;
  const content = formData.get('content') as string;

  await db.insert(posts).values({
    title,
    content,
    authorId: session.user.id,
  });

  revalidatePath('/journal');
}
```

```tsx
// No fetch(), no loading state management
function CreatePostForm() {
  return (
    <form action={createPost}>
      <input name="title" required />
      <textarea name="content" required />
      <button type="submit">Create post</button>
    </form>
  );
}
```

Server Actions eliminate the round-trip for simple mutations: they run on the server, revalidate the cache, and the page updates. No API endpoint to write, no fetch to manage.

## When to use each

| Scenario | Choice |
|----------|--------|
| External API consumers (mobile, partners) | REST Route Handlers |
| Public API with documentation | REST Route Handlers |
| Full-stack Next.js, no external consumers | tRPC |
| Simple form submissions, one-shot mutations | Server Actions |
| Complex mutations with optimistic updates | tRPC mutation |
| File uploads | REST Route Handler (tRPC handles this poorly) |

The rule: REST for external-facing APIs, tRPC for internal full-stack type safety, Server Actions for simple mutations where you want to skip the client-side fetch entirely.
