title: "Nix: reproducible builds, declarative packages, and the Nix store"
date: "2032-08-25"
excerpt: "Nix is a purely functional package manager built on a single principle: the same inputs always produce the same output. Every package is stored at a content-addressed path in /nix/store — a hash of all its inputs (source, dependencies, build flags, compiler version). This makes packages immutable and installation side-effect-free: two versions of the same package coexist without conflict because they live at different paths. nix-shell and nix develop give you a reproducible development shell with exact package versions — no more 'it works on my machine'. NixOS takes this further: the entire OS is a derivation, and switching OS versions is an atomic operation backed by symlink. The trade-off: Nix has a steep learning curve, a large store footprint, and a non-standard package expression language (the Nix expression language, a lazy functional DSL)."
author: "Lewis Wilson"
tag: "Build Log"
---

Every package is a hash. Same hash = same binary. Environments are isolated by construction.

## The Nix store and derivations

```bash
# The Nix store: /nix/store/<hash>-<name>-<version>/
# Hash is a SHA-256 of ALL inputs: source, dependencies, build flags, env vars
ls /nix/store/ | head -10
# 0abc123...-curl-8.6.0/
# 1def456...-openssl-3.3.1/
# 2ghi789...-construx-api-1.4.2/
# 3jkl012...-glibc-2.39/

# Two versions of the same package coexist with zero conflict
ls /nix/store/ | grep "^.*-openssl"
# 1def456...-openssl-3.3.1/   ← used by construx-api
# 9xyz999...-openssl-3.2.4/   ← used by an older tool

# Check a package's closure (all transitive dependencies)
nix-store --query --requisites /nix/store/2ghi789...-construx-api-1.4.2
# /nix/store/3jkl012...-glibc-2.39
# /nix/store/1def456...-openssl-3.3.1
# /nix/store/4mno345...-zlib-1.3.1
# ... (full closure, exact versions)

# nix-hash: compute the hash of a path (for manual inspection)
nix-hash --flat --type sha256 /path/to/source.tar.gz

# Garbage collection: remove store paths no longer reachable from any GC root
nix-collect-garbage -d    # -d = delete old generations of user profiles too
nix-store --gc            # conservative GC (keeps current profile generation)

# Check store disk usage
du -sh /nix/store
nix-store --query --size /nix/store/2ghi789...-construx-api-1.4.2
```

## nix-shell and nix develop — reproducible dev environments

```bash
# nix-shell: drop into a shell with the listed packages available
# No installation, no PATH pollution outside the shell

# One-off: get a shell with specific tools
nix-shell -p ripgrep bat fd fzf jq

# With a specific nixpkgs version (pinned)
nix-shell -p ripgrep --pure -I nixpkgs=channel:nixos-24.05

# shell.nix: project-local reproducible environment
cat shell.nix
# { pkgs ? import <nixpkgs> {} }:
# pkgs.mkShell {
#   buildInputs = with pkgs; [
#     go_1_22
#     golangci-lint
#     postgresql_16
#     redis
#     kubectl
#     k9s
#   ];
#   shellHook = ''
#     export PGDATA=$PWD/.pg
#     export DATABASE_URL="postgres://localhost/construx_dev"
#   '';
# }

# Enter the shell
nix-shell   # reads shell.nix from current directory

# Flakes: modern Nix with pinned inputs and a standard schema
cat flake.nix
# {
#   inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-24.05";
#   outputs = { self, nixpkgs }: let
#     pkgs = nixpkgs.legacyPackages.x86_64-linux;
#   in {
#     devShells.x86_64-linux.default = pkgs.mkShell {
#       packages = with pkgs; [ go_1_22 postgresql_16 redis kubectl ];
#     };
#   };
# }

nix develop   # uses flake.nix — reproducible, pinned, shareable
```

## Writing a Nix package derivation

```bash
# default.nix: package a Go binary with Nix
{ lib, buildGoModule, fetchFromGitHub }:

buildGoModule rec {
  pname = "construx-api";
  version = "1.4.2";

  src = fetchFromGitHub {
    owner = "construx";
    repo  = "construx-api";
    rev   = "v${version}";
    sha256 = "sha256-abc123...";   # nix-prefetch-url fills this in
  };

  vendorHash = "sha256-def456...";   # hash of the Go module cache

  ldflags = [
    "-s" "-w"
    "-X main.version=${version}"
  ];

  meta = with lib; {
    description = "Construx API server";
    license     = licenses.mit;
    maintainers = with maintainers; [ lewisw ];
  };
}

# Build it
nix-build -A construx-api

# Result is a symlink to /nix/store/<hash>-construx-api-1.4.2/
./result/bin/construx-api --version
# construx-api v1.4.2
```

## NixOS: the OS as a derivation

```bash
# /etc/nixos/configuration.nix — the entire OS declared in one file
{ config, pkgs, ... }:
{
  system.stateVersion = "24.05";

  networking.hostName = "prod-01";
  networking.firewall.allowedTCPPorts = [ 80 443 8080 ];

  users.users.construx = {
    isNormalUser  = true;
    extraGroups   = [ "docker" ];
    openssh.authorizedKeys.keys = [ "ssh-ed25519 AAAA..." ];
  };

  services.postgresql = {
    enable      = true;
    package     = pkgs.postgresql_16;
    settings    = { max_connections = 200; shared_buffers = "2GB"; };
  };

  environment.systemPackages = with pkgs; [
    btop htop vim git curl jq
    kubectl k9s
  ];

  # Rebuild: applies changes atomically, rolls back on failure
  # nixos-rebuild switch
  # nixos-rebuild test     (applies without making it the boot default)
  # nixos-rebuild boot     (applies on next boot only)
}

# Switch to new configuration
nixos-rebuild switch

# List generations (every switch creates a new one)
nix-env --list-generations
# 47   2032-07-01  (current)
# 46   2032-06-28
# 45   2032-06-15

# Roll back to previous generation
nixos-rebuild switch --rollback
# Or at the boot loader: select any previous generation from the GRUB menu
```

## Home Manager — user-level Nix

```bash
# Home Manager: manage dotfiles and user packages with Nix
# ~/.config/home-manager/home.nix

{ config, pkgs, ... }:
{
  home.username = "construx";
  home.homeDirectory = "/home/construx";
  home.stateVersion = "24.05";

  home.packages = with pkgs; [
    btop fzf ripgrep fd bat jq yq
    go_1_22 kubectl k9s
    gh ghq delta   # git tools
  ];

  programs.zsh = {
    enable = true;
    autocd = true;
    history.size = 100000;
    initExtra = ''
      eval "$(fzf --zsh)"
    '';
  };

  programs.git = {
    enable    = true;
    userName  = "Lewis Wilson";
    userEmail = "lewis@construx.io";
    delta.enable = true;
    extraConfig.push.default = "current";
  };
}

# Apply
home-manager switch

# Rollback user environment (separate from NixOS generations)
home-manager generations
home-manager switch --flake .#construx@prod-01
```

Nix vs Docker vs devcontainers: Docker gives you isolation via namespaces and a layered filesystem — great for production deployments and service encapsulation. Devcontainers extend Docker for development. Nix gives you reproducibility without isolation — you share the host kernel and namespace, but every tool is pinned to an exact hash. The practical difference: a Docker container is a unit of deployment; a Nix environment is a unit of reproducibility. They compose: build your Go binary in a Nix flake, then COPY the binary into a minimal Docker image (distroless or from pkgs.dockerTools.buildImage). You get reproducible builds and minimal runtime containers. The cost: /nix/store grows without bounds until garbage collection; the expression language has a learning curve; and Nix's evaluation model (lazy, functional) is unlike any other package manager. Start with nix-shell for dev environments — the value is immediate, the commitment is minimal.
