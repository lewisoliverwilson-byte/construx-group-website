title: "Crossplane: cloud infrastructure as Kubernetes resources with GitOps"
date: "2032-12-26"
excerpt: "Crossplane turns cloud resources (AWS RDS, S3, GCP CloudSQL, Azure CosmosDB) into Kubernetes Custom Resources. You define what you want in a YAML manifest, `kubectl apply` it, and Crossplane's controllers provision and continuously reconcile the actual cloud resource to match. Drift — manual changes made via the AWS console or Terraform — is detected and corrected automatically within 60 seconds. Compositions let platform teams define opinionated CRDs (a `PostgresDatabase` that encapsulates RDS + security groups + backups) that application teams use without needing to know AWS. The entire infrastructure lifecycle — provision, update, delete — goes through git and ArgoCD, the same as application code."

Cloud resources as CRDs. Continuous reconciliation. Drift detection. GitOps for infra.

## Provider setup and claims

```bash
# Install Crossplane
helm repo add crossplane-stable https://charts.crossplane.io/stable
helm install crossplane crossplane-stable/crossplane \
  --namespace crossplane-system \
  --create-namespace

# Install the AWS family provider (modular — install only what you need)
kubectl apply -f - <<'EOF'
apiVersion: pkg.crossplane.io/v1
kind: Provider
metadata:
  name: upbound-provider-aws-rds
spec:
  package: xpkg.upbound.io/upbound/provider-aws-rds:v1.14.0
EOF

kubectl apply -f - <<'EOF'
apiVersion: pkg.crossplane.io/v1
kind: Provider
metadata:
  name: upbound-provider-aws-s3
spec:
  package: xpkg.upbound.io/upbound/provider-aws-s3:v1.14.0
EOF

# Configure IRSA credentials (no static keys)
kubectl apply -f - <<'EOF'
apiVersion: aws.upbound.io/v1beta1
kind: ProviderConfig
metadata:
  name: construx-aws
spec:
  credentials:
    source: IRSA
EOF

# Check providers are healthy
kubectl get providers
# NAME                         INSTALLED  HEALTHY  PACKAGE
# upbound-provider-aws-rds     True       True     upbound/provider-aws-rds:v1.14.0
# upbound-provider-aws-s3      True       True     upbound/provider-aws-s3:v1.14.0

# Provision an S3 bucket
kubectl apply -f - <<'EOF'
apiVersion: s3.aws.upbound.io/v1beta1
kind: Bucket
metadata:
  name: construx-logs
spec:
  forProvider:
    region: eu-west-1
    serverSideEncryptionConfiguration:
      rules:
        - applyServerSideEncryptionByDefault:
            sseAlgorithm: aws:kms
    versioning:
      enabled: true
    lifecycleRules:
      - enabled: true
        expiration:
          days: 90
  providerConfigRef:
    name: construx-aws
EOF

# Watch provisioning
kubectl get bucket construx-logs -w
# NAME             READY  SYNCED  EXTERNAL-NAME     AGE
# construx-logs    False  True    construx-logs     10s
# construx-logs    True   True    construx-logs     45s
```

## Compositions — platform abstractions

```yaml
# Platform team defines a PostgresDatabase CRD
# Application teams use it without knowing AWS details

# Step 1: Define the CompositeResourceDefinition (the new CRD)
apiVersion: apiextensions.crossplane.io/v1
kind: CompositeResourceDefinition
metadata:
  name: xpostgresdatabases.platform.construx.io
spec:
  group: platform.construx.io
  names:
    kind: XPostgresDatabase
    plural: xpostgresdatabases
  claimNames:
    kind: PostgresDatabase      # what dev teams create in their namespace
    plural: postgresdatabases
  connectionSecretKeys:         # keys to write to the connection secret
    - endpoint
    - port
    - username
    - password
  versions:
    - name: v1alpha1
      served: true
      referenceable: true
      schema:
        openAPIV3Schema:
          type: object
          properties:
            spec:
              type: object
              properties:
                parameters:
                  type: object
                  properties:
                    env:
                      type: string
                      enum: [dev, staging, production]
                    size:
                      type: string
                      enum: [small, medium, large]
                      default: medium
                    storageGB:
                      type: integer
                      default: 50
                      minimum: 20
                      maximum: 1000
                  required: [env]

---
# Step 2: Composition — implement XPostgresDatabase using RDS
apiVersion: apiextensions.crossplane.io/v1
kind: Composition
metadata:
  name: xpostgresdatabases-aws
  labels:
    provider: aws
    env: production
spec:
  compositeTypeRef:
    apiVersion: platform.construx.io/v1alpha1
    kind: XPostgresDatabase

  writeConnectionSecretsToNamespace: crossplane-system

  resources:
    - name: rds-instance
      base:
        apiVersion: rds.aws.upbound.io/v1beta1
        kind: Instance
        spec:
          forProvider:
            region: eu-west-1
            engine: postgres
            engineVersion: "16.3"
            autoMinorVersionUpgrade: true
            multiAz: true
            storageEncrypted: true
            backupRetentionPeriod: 7
            deletionProtection: true
            skipFinalSnapshot: false
          writeConnectionSecretsToRef:
            namespace: crossplane-system
      patches:
        # Map 'size' to instanceClass
        - type: FromCompositeFieldPath
          fromFieldPath: spec.parameters.size
          toFieldPath: spec.forProvider.instanceClass
          transforms:
            - type: map
              map:
                small:  db.t4g.small
                medium: db.t4g.medium
                large:  db.r8g.xlarge
        # Map 'storageGB' to allocatedStorage
        - type: FromCompositeFieldPath
          fromFieldPath: spec.parameters.storageGB
          toFieldPath: spec.forProvider.allocatedStorage
      connectionDetails:
        - name: endpoint
          fromFieldPath: status.atProvider.address
        - name: port
          type: FromValue
          value: "5432"
```

```yaml
# Step 3: Application team creates a PostgresDatabase claim
# (they don't need to know anything about RDS, security groups, or subnets)
apiVersion: platform.construx.io/v1alpha1
kind: PostgresDatabase
metadata:
  name: api-database
  namespace: construx-prod
spec:
  parameters:
    env: production
    size: medium
    storageGB: 100
  # Crossplane writes connection details to this secret
  writeConnectionSecretToRef:
    name: api-database-connection
```

## Drift detection and reconciliation

```bash
# Crossplane runs a reconciliation loop (default: every 60s)
# If someone changes the RDS instance via the AWS console:

# Before: instanceClass = db.t4g.medium
# Manual change in AWS console: instanceClass → db.t4g.large

# After 60 seconds, Crossplane detects the drift:
kubectl get events -n construx-prod --field-selector reason=SyncFailed
# LAST SEEN  REASON     OBJECT                        MESSAGE
# 45s        SyncFailed Instance/api-database-rds     drift detected: instanceClass=db.t4g.large, desired=db.t4g.medium

# Crossplane reverts to db.t4g.medium automatically
# This enforces that git is the source of truth

# Override drift correction (when you intentionally want to allow a manual change)
kubectl annotate managed api-database-rds \
  crossplane.io/paused=true
# Now Crossplane won't reconcile this resource until you remove the annotation

# View all managed resources across all providers
kubectl get managed
# NAME                           SYNCED  READY  EXTERNAL-NAME
# api-database-rds.rds.aws...   True    True   construx-api-db-prod
# construx-logs.s3.aws...       True    True   construx-logs
# redis-cluster.elasticache...  True    True   construx-redis-prod
```

Crossplane vs Terraform for infrastructure-as-code: Terraform has a 10-year head start, a huge provider ecosystem, and a plan/apply workflow that shows exactly what will change before it happens. Crossplane's advantage is continuous reconciliation — it doesn't just apply and forget, it watches and corrects drift. This makes it natural for GitOps: every git push triggers reconciliation, manual changes are automatically reverted, and the cluster is always the source of truth. The practical choice: Terraform for existing infrastructure teams that already have pipelines and state management. Crossplane for greenfield Kubernetes-native platforms where you want GitOps for infrastructure with the same ArgoCD workflow as applications.
