excerpt: "Grafana Alloy is the next-generation telemetry agent from Grafana Labs, replacing the previous generation of separate agents (Grafana Agent, Promtail, OpenTelemetry Collector). Alloy runs a single binary that can ingest all signal types — metrics (Prometheus scrape, OTLP), logs (Kubernetes pod logs, systemd journal, file tailing), traces (OTLP, Jaeger, Zipkin), and profiles (pprof) — and route them to any compatible backend. The pipeline is configured in River (a Grafana-specific HCL-like language) as a directed graph of components: sources produce data, processors transform it, and exporters send it. Because Alloy implements the OpenTelemetry Collector component model, it can replace a separate OTel Collector deployment entirely. Alloy runs as a Kubernetes DaemonSet for host-level telemetry (pod log collection, node metrics) or as a standalone Deployment for gateway mode (receiving OTLP from instrumented services and forwarding to Grafana Cloud or self-hosted backends). Grafana Alloy's Kubernetes-specific components handle the complexity of Kubernetes service discovery (auto-discovering pods and their labels) and annotation-driven scrape configuration, reducing the boilerplate required to get metrics from a new service to near zero."

## Alloy pipeline configuration

```hcl
// Alloy config: config.alloy (River language)
// Unified pipeline: Kubernetes pod logs → Loki, pod metrics → Prometheus, OTLP traces → Tempo

// ── LOGS: collect pod logs and forward to Loki ──────────────────────────────

// Discover pods with metadata for log labeling
discovery.kubernetes "pods" {
  role = "pod"
}

// Relabel pod metadata into useful Loki labels
discovery.relabel "pod_logs" {
  targets = discovery.kubernetes.pods.targets
  rule {
    source_labels = ["__meta_kubernetes_pod_label_app"]
    target_label  = "app"
  }
  rule {
    source_labels = ["__meta_kubernetes_namespace"]
    target_label  = "namespace"
  }
  rule {
    source_labels = ["__meta_kubernetes_pod_name"]
    target_label  = "pod"
  }
}

// Tail pod log files from the node
loki.source.kubernetes "pod_logs" {
  targets    = discovery.relabel.pod_logs.output
  forward_to = [loki.process.drop_debug.receiver]
}

// Drop DEBUG logs before forwarding (reduce cost)
loki.process "drop_debug" {
  stage.drop {
    expression = '"level":"debug"'
  }
  forward_to = [loki.write.default.receiver]
}

loki.write "default" {
  endpoint {
    url = "http://loki.monitoring.svc.cluster.local:3100/loki/api/v1/push"
  }
}

// ── METRICS: scrape pods with prometheus.io annotations ─────────────────────

// Auto-discover pods with prometheus.io/scrape: "true" annotation
discovery.relabel "metrics_pods" {
  targets = discovery.kubernetes.pods.targets
  rule {
    source_labels = ["__meta_kubernetes_pod_annotation_prometheus_io_scrape"]
    action        = "keep"
    regex         = "true"
  }
  rule {
    source_labels = ["__meta_kubernetes_pod_annotation_prometheus_io_port"]
    action        = "replace"
    target_label  = "__address__"
    regex         = "(.+)"
    replacement   = "${1}"
  }
}

prometheus.scrape "pods" {
  targets    = discovery.relabel.metrics_pods.output
  forward_to = [prometheus.remote_write.mimir.receiver]
}

prometheus.remote_write "mimir" {
  endpoint {
    url = "http://mimir.monitoring.svc.cluster.local:9009/api/v1/push"
  }
}

// ── TRACES: receive OTLP and forward to Tempo ────────────────────────────────

otelcol.receiver.otlp "default" {
  grpc { endpoint = "0.0.0.0:4317" }
  http { endpoint = "0.0.0.0:4318" }
  output {
    traces = [otelcol.processor.batch.default.input]
  }
}

otelcol.processor.batch "default" {
  output {
    traces = [otelcol.exporter.otlp.tempo.input]
  }
}

otelcol.exporter.otlp "tempo" {
  client {
    endpoint = "tempo.monitoring.svc.cluster.local:4317"
    tls { insecure = true }
  }
}
```

## DaemonSet deployment and self-monitoring

```yaml
# Alloy runs as a DaemonSet for node-level telemetry collection
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name:      alloy
  namespace: monitoring
spec:
  template:
    spec:
      serviceAccountName: alloy
      containers:
        - name:  alloy
          image: grafana/alloy:v1.4.2
          args:
            - run
            - /etc/alloy/config.alloy
            - --server.http.listen-addr=0.0.0.0:12345  # UI and metrics
            - --cluster.enabled=true                     # cluster mode: shards scrape work
            - --cluster.join-addresses=alloy.monitoring.svc.cluster.local:12345
          ports:
            - { name: http,        containerPort: 12345 }
            - { name: otlp-grpc,   containerPort: 4317  }
            - { name: otlp-http,   containerPort: 4318  }
          volumeMounts:
            - { name: config,    mountPath: /etc/alloy              }
            - { name: varlog,    mountPath: /var/log,   readOnly: true }
            - { name: varlibdockercontainers, mountPath: /var/lib/docker/containers, readOnly: true }
      volumes:
        - name: config
          configMap: { name: alloy-config }
        - name: varlog
          hostPath: { path: /var/log }
        - name: varlibdockercontainers
          hostPath: { path: /var/lib/docker/containers }
      # Run as root to read /var/log (required for log collection)
      securityContext:
        runAsUser: 0
```

```bash
# Alloy UI: River pipeline visualizer at http://alloy-node:12345
# Shows the component graph (sources → processors → exporters) and per-component metrics

# Alloy cluster mode: shards scrape targets across DaemonSet pods
# pod 0 scrapes nodes 0-3, pod 1 scrapes nodes 4-7, etc.
# Prevents duplicate scrapes when multiple Alloy pods are running

# Self-monitoring metrics (Alloy exposes its own pipeline metrics)
# alloy_component_controller_evaluations_total{component_id="prometheus.scrape.pods"} 1821
# alloy_logs_bytes_total{component_id="loki.source.kubernetes.pod_logs"} 4.21e+10
# otelcol_exporter_sent_spans_total{exporter="otlp/tempo"} 1.84e+07
# prometheus_remote_write_samples_total{url="http://mimir..."} 4.82e+08

# Hot reload: Alloy watches the config file and reloads without restart
kubectl rollout restart daemonset/alloy -n monitoring   # only needed for binary updates
# For config-only changes: Alloy reloads on ConfigMap update automatically
```

Grafana Alloy vs separate OTel Collector + Promtail + Grafana Agent: Running separate agents per signal type (OTel Collector for traces, Promtail for logs, Grafana Agent or Prometheus node_exporter for metrics) works but adds DaemonSet proliferation — three DaemonSets consuming node resources for what is fundamentally one job: collecting telemetry. Alloy consolidates this into a single DaemonSet with a unified River pipeline. The trade-off: River is a new language to learn, and Alloy is newer than the individual agents it replaces — the Promtail and OTel Collector communities have more documentation. For teams starting fresh on the Grafana stack (Loki + Tempo + Mimir/Prometheus), Alloy is the recommended path. For teams with existing Promtail or Grafana Agent deployments, migration to Alloy is straightforward — Alloy can import most existing Prometheus scrape configs and Promtail pipeline stages with minor syntax adjustments.
