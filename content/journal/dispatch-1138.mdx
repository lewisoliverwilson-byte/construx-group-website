date: "2034-04-20"
excerpt: "Pulumi ESC (Environments, Secrets, and Configuration) is a secrets and configuration management platform that solves the proliferation of secrets management tools across an organisation: Vault for Kubernetes, AWS Secrets Manager for Lambda, .env files for local development, GitHub Secrets for CI, and Doppler for some services — resulting in secrets scattered across six different systems with no unified view. ESC centralises all configuration and secrets into composable environments: a `construx/prod` environment imports from `construx/base` (shared configuration) and `construx/aws-prod` (AWS credentials via OIDC), and applications open this environment to get a unified set of resolved secrets and configuration values. The OIDC integration with AWS, Azure, and GCP enables short-lived dynamic credentials: instead of storing long-lived AWS access keys, ESC generates temporary credentials via AssumeRoleWithWebIdentity when an environment is opened — the credentials expire in one hour and are never stored. The `esc run` command wraps any command with environment variables populated from ESC: `esc run construx/prod -- terraform plan` injects all secrets as environment variables for the duration of the command. For Pulumi Infrastructure as Code, ESC environments are the natural configuration layer — a stack references an ESC environment rather than storing Pulumi Config secrets locally, enabling the same IaC stack to deploy to prod or staging by switching the environment."

## Pulumi ESC environment configuration

```yaml
# Pulumi ESC: construx/prod environment definition
# Composable: imports base config, adds prod-specific overrides

values:
  # Import shared configuration from base environment
  imports:
    - construx/base
    - construx/aws-prod   # AWS credentials via OIDC

  # Static configuration (non-secret)
  config:
    aws:
      region: eu-west-2
    app:
      env: production
      log_level: info
      max_connections: 100
    construx:
      domain: construx.io
      cluster: construx-prod

  # Dynamic secrets: resolved at open-time from Vault
  vault:
    login:
      fn::open::pulumi-secrets:  # open Pulumi-managed secret
        project: construx
        name: vault-token

  secrets:
    STRIPE_API_KEY:
      fn::secret:
        ciphertext: ZXNj...  # ESC-encrypted

    DATABASE_URL:
      fn::join:
        - ""
        - - "postgresql://"
          - ${vault.db_user}
          - ":"
          - ${vault.db_password}
          - "@postgres.construx-prod.svc.cluster.local:5432/construx"

    JWT_SIGNING_KEY:
      fn::secret:
        ciphertext: ZXNj...

  # AWS OIDC: dynamic short-lived credentials (1h expiry, never stored)
  aws:
    login:
      fn::open::aws-login:
        oidc:
          duration: 1h
          roleArn: arn:aws:iam::123456789012:role/pulumi-esc-prod
          sessionName: pulumi-esc-${context.rootEnvironment.name}
    session: ${aws.login}

  environmentVariables:
    AWS_ACCESS_KEY_ID:     ${aws.login.accessKeyId}
    AWS_SECRET_ACCESS_KEY: ${aws.login.secretAccessKey}
    AWS_SESSION_TOKEN:     ${aws.login.sessionToken}
    STRIPE_API_KEY:        ${secrets.STRIPE_API_KEY}
    DATABASE_URL:          ${secrets.DATABASE_URL}
    JWT_SIGNING_KEY:       ${secrets.JWT_SIGNING_KEY}
    APP_ENV:               ${config.app.env}
```

```bash
# Pulumi ESC CLI: open environments and run commands

# Install ESC CLI
curl -fsSL https://get.pulumi.com/esc/install.sh | sh

# Login to Pulumi Cloud
esc login

# Open environment: print resolved configuration and secrets
esc open construx/prod --format dotenv
# AWS_ACCESS_KEY_ID=ASIA1234...
# AWS_SECRET_ACCESS_KEY=abc123...  (temporary, 1h)
# STRIPE_API_KEY=sk_live_...
# DATABASE_URL=postgresql://...
# APP_ENV=production

# Run a command with environment variables injected from ESC
esc run construx/prod -- terraform plan
esc run construx/prod -- aws s3 ls s3://construx-data-lake/
esc run construx/prod -- kubectl get pods -n construx-prod
esc run construx/staging -- pytest tests/integration/ -v

# Run without shell (direct exec — no shell injection risk)
esc run construx/prod -- /usr/bin/aws s3 sync ./dist s3://construx-assets/

# Compare environments (useful for debugging prod/staging differences)
esc open construx/prod --format json > prod.json
esc open construx/staging --format json > staging.json
diff <(jq -S . prod.json) <(jq -S . staging.json)

# List all environments
esc env ls

# Show environment history (who changed what, when)
esc env history construx/prod --limit 10
```

Pulumi ESC vs Doppler vs 1Password Secrets Automation vs Vault vs SOPS: Doppler is the closest competitor — a centrally managed secrets platform with environment composability, dynamic secret injection, and integrations for Kubernetes, GitHub Actions, and CLI. Doppler's UX is excellent and developer onboarding is fast. The key difference: Pulumi ESC is designed to integrate with Pulumi IaC natively (environments are the config layer for Pulumi stacks), while Doppler is standalone. 1Password Secrets Automation bridges 1Password vaults (where security teams already store credentials) to developer workflows — good for organisations already on 1Password but adds dependency on 1Password's pricing model. Vault (HashiCorp) is the enterprise standard for secrets management — more powerful, more policy control, more complex to operate. SOPS encrypts secrets in Git without requiring a running service — the simplest approach for teams that don't need dynamic credentials or multi-environment composition. Pulumi ESC's differentiator is the OIDC dynamic credential model: by generating temporary AWS/Azure/GCP credentials at use-time via OIDC, it eliminates the class of incidents caused by long-lived static credentials being rotated too infrequently or accidentally exposed in logs. The `esc run` pattern — wrapping any command with injected environment variables — works with any tool that respects environment variables, making it immediately applicable without application code changes.
