## Feature flag setup — PostHog dashboard

```json
{
  "key":        "checkout-v2",
  "name":       "Checkout V2 Redesign",
  "filters": {
    "groups": [
      {
        "rollout_percentage": 10,
        "properties": [
          { "key": "$geoip_country_code", "value": "GB", "operator": "exact" }
        ]
      }
    ]
  },
  "variants": [
    { "key": "control",   "rollout_percentage": 50 },
    { "key": "treatment", "rollout_percentage": 50 }
  ],
  "payloads": {
    "control":   { "layout": "single-page", "animation": false },
    "treatment": { "layout": "multi-step",  "animation": true  }
  }
}
```

## Server-side evaluation — Node.js

```ts
// lib/flags.ts
import { PostHog } from 'posthog-node';

const posthog = new PostHog(process.env.POSTHOG_API_KEY!, {
  host:            process.env.POSTHOG_HOST,
  personalApiKey:  process.env.POSTHOG_PERSONAL_API_KEY,  // required for local eval
});

// Evaluate a flag for a user — no network call if personal API key is set
export async function isEnabled(flag: string, userId: string, properties?: Record<string, unknown>): Promise<boolean> {
  return posthog.isFeatureEnabled(flag, userId, { personProperties: properties });
}

export async function getVariant(flag: string, userId: string): Promise<string | boolean> {
  return posthog.getFeatureFlag(flag, userId) ?? false;
}

export async function getPayload<T>(flag: string, userId: string): Promise<T | null> {
  return posthog.getFeatureFlagPayload(flag, userId) as T | null;
}

// Usage in an API route
export async function POST(req: Request) {
  const { userId } = await getSession(req);

  const variant = await getVariant('checkout-v2', userId);
  const payload = await getPayload<{ layout: string; animation: boolean }>('checkout-v2', userId);

  return Response.json({ variant, layout: payload?.layout ?? 'single-page' });
}
```

## Client-side — React hook

```ts
// hooks/useFlag.ts
'use client';
import { usePostHog } from 'posthog-js/react';

export function useFlag(flag: string): boolean {
  const posthog = usePostHog();
  return posthog?.isFeatureEnabled(flag) ?? false;
}

export function useVariant(flag: string): string | boolean | undefined {
  const posthog = usePostHog();
  return posthog?.getFeatureFlag(flag);
}

// Usage
function CheckoutPage() {
  const variant = useVariant('checkout-v2');

  if (variant === 'treatment') return <CheckoutMultiStep />;
  return <CheckoutSinglePage />;
}
```

## Override in development

```ts
// Local override — forces flag on for your session
posthog.featureFlags.override({ 'checkout-v2': 'treatment' });
```

## Capture flag exposure event

```ts
// Manually capture — use when the flag controls a non-visual behaviour
posthog.capture('$feature_flag_called', {
  $feature_flag:         'checkout-v2',
  $feature_flag_response: variant,
});

// PostHog auto-captures this when you call isFeatureEnabled/getFeatureFlag
// Set sendFeatureFlagEvents: false to disable auto-capture
```

## Rollout strategy — the Construx pattern

```
Week 1: internal (team only — hardcoded user IDs in flag)
Week 2: 1% of GB users
Week 3: 10% if error rate unchanged
Week 4: 50% — run A/B test for 2 weeks
Week 6: 100% if variant wins, roll back if not
```

Feature flags vs environment variables: env vars are deploy-time configuration. Feature flags are runtime configuration — you change them without a deploy. The Construx default: env vars for secrets and infrastructure config; PostHog flags for all product feature rollouts and A/B tests.
