Infrastructure as typed functions. No config files, no deployment YAML.

## Define an API endpoint

```ts
import { api } from 'encore.dev/api';

// POST /users — creates a user, no Express/Hono setup required
export const createUser = api(
  { method: 'POST', path: '/users', expose: true },
  async (req: CreateUserRequest): Promise<CreateUserResponse> => {
    const user = await db.user.create({
      data: { email: req.email, name: req.name },
    });
    return { id: user.id, email: user.email };
  },
);

interface CreateUserRequest  { email: string; name: string }
interface CreateUserResponse { id: string;    email: string }
```

Encore generates an OpenAPI spec, a type-safe client, and request validation from the types automatically.

## Database — declare, don't configure

```ts
import { SQLDatabase } from 'encore.dev/storage/sqldb';

const db = new SQLDatabase('users', {
  migrations: './migrations',
});

// Use it anywhere in the service — connection pooling handled
const user = await db.queryRow`
  SELECT id, email, name FROM users WHERE id = ${userId}
`;
```

No `DATABASE_URL`, no pg connection pool setup. Encore provisions the database in the cloud and wires it locally.

## Pub/Sub — typed topics

```ts
import { Topic, Subscription } from 'encore.dev/pubsub';

interface UserCreated {
  userId: string;
  email:  string;
}

// Publisher
export const userCreatedTopic = new Topic<UserCreated>('user-created', {
  deliveryGuarantee: 'at-least-once',
});

await userCreatedTopic.publish({ userId: user.id, email: user.email });

// Subscriber — different service
const _ = new Subscription(userCreatedTopic, 'send-welcome-email', {
  handler: async (event: UserCreated) => {
    await resend.emails.send({
      to:      event.email,
      subject: 'Welcome to Construx',
      html:    welcomeTemplate(event),
    });
  },
});
```

## Cron jobs

```ts
import { CronJob } from 'encore.dev/cron';

// Runs every Monday at 9am UTC
const weeklyDigest = new CronJob('weekly-digest', {
  schedule: '0 9 * * 1',
  endpoint: sendWeeklyDigest,
});

export const sendWeeklyDigest = api(
  { method: 'POST', path: '/internal/digest' },
  async (): Promise<{ sent: number }> => {
    const subscribers = await db.queryAll`SELECT email FROM subscribers`;
    await Promise.all(subscribers.map(sendDigestEmail));
    return { sent: subscribers.length };
  },
);
```

## Service-to-service calls — type-safe, no HTTP boilerplate

```ts
// Call another Encore service — typed, traced, no fetch boilerplate
import { authService } from '~encore/clients';

const session = await authService.validateToken({ token: req.headers.authorization });
if (!session.valid) {
  throw new APIError(ErrCode.Unauthenticated, 'Invalid token');
}
```

Encore generates the client from the service definition. In production, calls go service-to-service; locally, everything runs in a single process.

## Local dev dashboard

```bash
encore run
```

Localhost dashboard at `http://localhost:9400`:
- Live API explorer (send requests, see responses)
- Distributed trace viewer for every request
- Database viewer
- Pub/Sub topic inspector

## Deploy

```bash
encore app create construx-api
git push encore main
```

Encore provisions RDS/Cloud SQL, SQS/Pub/Sub, and deploys containers automatically. No Terraform, no Docker build pipeline.

Encore vs traditional setup: traditional requires Express/Hono + pg + connection pooling + SQS SDK + Terraform + Docker + CI/CD pipeline — 2-3 days of setup. Encore collapses all of that. The tradeoff: you're coupled to Encore's deployment model. The Construx default: Encore for new internal services; existing infrastructure stays on its current stack.
