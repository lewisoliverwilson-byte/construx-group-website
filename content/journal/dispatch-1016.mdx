excerpt: "ScyllaDB is a Cassandra-compatible wide-column store rewritten in C++ with a shard-per-core architecture. Where Cassandra uses a JVM with GC pauses and a thread-per-request model, Scylla uses the Seastar async framework: one OS thread per CPU core, each thread owning a shard of data and a network queue, with no locking between shards. The result is lower and more consistent latency — p99 latencies that would be 50-200ms in Cassandra are typically 5-20ms in Scylla for the same hardware. The Cassandra Query Language (CQL) and client compatibility is maintained, so migration is a driver swap. Scylla is the right choice when you need Cassandra's data model (wide rows, time-series, high write throughput) but can't tolerate JVM GC jitter or want better hardware efficiency."

Shard-per-core. Seastar. CQL-compatible. No GC pauses. Wide rows. Time-series.

## Schema design and table creation

```sql
-- ScyllaDB uses CQL (Cassandra Query Language)
-- Connect with: cqlsh scylla.storage.svc 9042

-- Keyspace: defines replication strategy
CREATE KEYSPACE construx
  WITH replication = {
    'class': 'NetworkTopologyStrategy',
    'eu-west': 3      -- 3 replicas in eu-west datacenter
  }
  AND durable_writes = true;

USE construx;

-- Wide-column table: user events partitioned by user_id
-- Clustering key defines the sort order within a partition
CREATE TABLE user_events (
  user_id     uuid,
  occurred_at timestamp,
  event_type  text,
  payload     blob,
  session_id  uuid,
  PRIMARY KEY (user_id, occurred_at, event_type)
) WITH CLUSTERING ORDER BY (occurred_at DESC, event_type ASC)
  AND compaction = {
    'class': 'TimeWindowCompactionStrategy',
    'compaction_window_unit': 'DAYS',
    'compaction_window_size': 1    -- compact one day at a time
  }
  AND gc_grace_seconds = 86400;   -- tombstone grace period

-- Time-series table: sensor readings partitioned by device + day
-- Partition key includes the day bucket to bound partition size
CREATE TABLE sensor_readings (
  device_id    uuid,
  day          date,
  recorded_at  timestamp,
  temperature  float,
  pressure     float,
  humidity     float,
  PRIMARY KEY ((device_id, day), recorded_at)
) WITH CLUSTERING ORDER BY (recorded_at DESC)
  AND compaction = {'class': 'TimeWindowCompactionStrategy',
                    'compaction_window_unit': 'HOURS',
                    'compaction_window_size': 6};

-- Secondary index: query by event_type without scanning all partitions
-- (ScyllaDB secondary indexes are local — one per shard — not global)
CREATE INDEX ON user_events (event_type);

-- Materialized view: pre-built read path for different access pattern
CREATE MATERIALIZED VIEW user_events_by_session AS
  SELECT * FROM user_events
  WHERE session_id IS NOT NULL AND user_id IS NOT NULL AND occurred_at IS NOT NULL AND event_type IS NOT NULL
  PRIMARY KEY (session_id, occurred_at, user_id, event_type)
  WITH CLUSTERING ORDER BY (occurred_at DESC);
```

## Reads, writes, and lightweight transactions

```python
from cassandra.cluster import Cluster
from cassandra.policies import DCAwareRoundRobinPolicy, TokenAwarePolicy
from cassandra.auth import PlainTextAuthProvider

cluster = Cluster(
    contact_points=['scylla.storage.svc'],
    port=9042,
    load_balancing_policy=TokenAwarePolicy(
        DCAwareRoundRobinPolicy(local_dc='eu-west')
    ),
    auth_provider=PlainTextAuthProvider(
        username='construx_api',
        password=os.environ['SCYLLA_PASSWORD']
    ),
)
session = cluster.connect('construx')

# Prepared statements: always use prepared statements for repeated queries
INSERT_EVENT = session.prepare("""
    INSERT INTO user_events (user_id, occurred_at, event_type, payload, session_id)
    VALUES (?, ?, ?, ?, ?)
    USING TTL 7776000   -- 90 days TTL
""")

FETCH_EVENTS = session.prepare("""
    SELECT occurred_at, event_type, payload
    FROM user_events
    WHERE user_id = ?
      AND occurred_at > ?
    LIMIT 100
""")

# Write: fire and forget (consistency level ONE for high throughput)
from cassandra import ConsistencyLevel
session.execute(
    INSERT_EVENT,
    (user_id, datetime.utcnow(), 'page_view', payload_bytes, session_id),
    consistency_level=ConsistencyLevel.ONE,
)

# Read: quorum for consistent reads across replicas
rows = session.execute(
    FETCH_EVENTS,
    (user_id, datetime.utcnow() - timedelta(days=7)),
    consistency_level=ConsistencyLevel.LOCAL_QUORUM,
)

# Lightweight transaction (LWT): compare-and-swap via Paxos
# Use sparingly — 5-10x more expensive than a normal write
session.execute("""
    INSERT INTO construx.locks (resource_id, held_by, acquired_at)
    VALUES (%s, %s, %s)
    IF NOT EXISTS
""", (resource_id, worker_id, datetime.utcnow()))
```

ScyllaDB vs Cassandra vs DynamoDB vs ClickHouse for time-series: Cassandra works but GC pauses make p99 latencies unpredictable at scale — Scylla fixes this with C++ and shard-per-core. DynamoDB is fully managed and has predictable latency, but the partition throughput limits and cost at high write rates are a constraint. ClickHouse is the right choice when you want fast analytical queries over time-series (aggregations, window functions, funnel analysis) but is not designed for point lookups by primary key. Scylla is the right choice when you need fast point reads and writes (single-digit millisecond p99), have a well-defined access pattern via partition + clustering key, and want Cassandra's schema flexibility without the JVM.
