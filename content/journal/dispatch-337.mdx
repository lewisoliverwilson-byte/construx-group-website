Rate limiting is one of those things you only think about after you need it. A contact form that sends 10,000 emails overnight, an AI endpoint that gets hammered by a scraper, a search route that hits your database 500 times per second from a single IP. All of these are preventable.

## Sliding window rate limit with Upstash

Upstash provides a serverless Redis-compatible store with a native rate limiter. It works at the Edge — no cold starts, no connection pooling needed.

```bash
npm install @upstash/ratelimit @upstash/redis
```

```ts
// lib/ratelimit.ts
import { Ratelimit } from '@upstash/ratelimit';
import { Redis } from '@upstash/redis';

const redis = Redis.fromEnv(); // UPSTASH_REDIS_REST_URL + UPSTASH_REDIS_REST_TOKEN

export const apiRateLimit = new Ratelimit({
  redis,
  limiter: Ratelimit.slidingWindow(20, '1 m'), // 20 requests per minute
  analytics: true,
  prefix: 'ratelimit:api',
});

export const authRateLimit = new Ratelimit({
  redis,
  limiter: Ratelimit.slidingWindow(5, '15 m'), // 5 attempts per 15 minutes
  analytics: true,
  prefix: 'ratelimit:auth',
});

export const aiRateLimit = new Ratelimit({
  redis,
  limiter: Ratelimit.tokenBucket(10, '1 m', 10), // 10 tokens per minute, refilled at 10/min
  analytics: true,
  prefix: 'ratelimit:ai',
});
```

## Middleware-level limiting

Apply rate limits in middleware to block requests before they reach any route handler:

```ts
// middleware.ts
import { NextRequest, NextResponse } from 'next/server';
import { apiRateLimit } from '@/lib/ratelimit';

function getIdentifier(req: NextRequest): string {
  // Use forwarded IP from Vercel/Cloudflare, fall back to direct IP
  const forwarded = req.headers.get('x-forwarded-for');
  const ip = forwarded ? forwarded.split(',')[0].trim() : '127.0.0.1';
  return ip;
}

export async function middleware(req: NextRequest) {
  if (req.nextUrl.pathname.startsWith('/api/')) {
    const identifier = getIdentifier(req);
    const { success, limit, remaining, reset } = await apiRateLimit.limit(identifier);

    if (!success) {
      return new NextResponse(
        JSON.stringify({ error: 'Too many requests', retryAfter: Math.ceil((reset - Date.now()) / 1000) }),
        {
          status: 429,
          headers: {
            'Content-Type': 'application/json',
            'X-RateLimit-Limit': String(limit),
            'X-RateLimit-Remaining': '0',
            'X-RateLimit-Reset': String(reset),
            'Retry-After': String(Math.ceil((reset - Date.now()) / 1000)),
          },
        },
      );
    }

    const res = NextResponse.next();
    res.headers.set('X-RateLimit-Limit', String(limit));
    res.headers.set('X-RateLimit-Remaining', String(remaining));
    res.headers.set('X-RateLimit-Reset', String(reset));
    return res;
  }
}

export const config = {
  matcher: ['/api/:path*'],
};
```

## Route-level limiting with user context

For authenticated routes, rate limit by user ID rather than IP (IPs change, users don't):

```ts
// app/api/ai/route.ts
import { aiRateLimit } from '@/lib/ratelimit';
import { auth } from '@/auth';

export async function POST(req: Request) {
  const session = await auth();
  if (!session?.user?.id) {
    return Response.json({ error: 'Unauthorized' }, { status: 401 });
  }

  // Rate limit per user, not per IP
  const { success, remaining, reset } = await aiRateLimit.limit(session.user.id);

  if (!success) {
    return Response.json(
      {
        error: 'Rate limit exceeded',
        message: 'AI requests are limited to 10 per minute.',
        retryAfter: Math.ceil((reset - Date.now()) / 1000),
      },
      {
        status: 429,
        headers: {
          'Retry-After': String(Math.ceil((reset - Date.now()) / 1000)),
          'X-RateLimit-Remaining': '0',
        },
      },
    );
  }

  // Proceed with AI call
  const body = await req.json();
  // ...
}
```

## Different limits per plan

Pro users get higher limits. Encode the tier in the rate limit key:

```ts
const tier = session.user.plan === 'pro' ? 'pro' : 'free';
const limit = tier === 'pro' ? 100 : 10;

const ratelimiter = new Ratelimit({
  redis,
  limiter: Ratelimit.slidingWindow(limit, '1 m'),
  prefix: `ratelimit:ai:${tier}`,
});

const { success } = await ratelimiter.limit(session.user.id);
```

## Client-side handling

Show a friendly error and the retry countdown when rate limited:

```tsx
'use client';

async function callAI(prompt: string) {
  const res = await fetch('/api/ai', {
    method: 'POST',
    body: JSON.stringify({ prompt }),
  });

  if (res.status === 429) {
    const { retryAfter } = await res.json();
    throw new Error(`Rate limit exceeded. Try again in ${retryAfter} seconds.`);
  }

  if (!res.ok) throw new Error('Request failed');
  return res.json();
}
```

## Without Upstash: in-memory for single-instance

For local dev or single-instance apps, a simple in-memory map works:

```ts
// lib/ratelimit-memory.ts
const requests = new Map<string, { count: number; resetAt: number }>();

export function checkRateLimit(key: string, limit: number, windowMs: number): boolean {
  const now = Date.now();
  const entry = requests.get(key);

  if (!entry || entry.resetAt < now) {
    requests.set(key, { count: 1, resetAt: now + windowMs });
    return true;
  }

  if (entry.count >= limit) return false;

  entry.count++;
  return true;
}
```

This doesn't survive restarts and doesn't work across multiple instances — use it only in development.

## What to limit

- **Auth endpoints** (login, password reset): 5 per 15 minutes per IP
- **AI endpoints**: 10-100 per minute per user depending on plan
- **Contact forms**: 3 per hour per IP
- **Search**: 60 per minute per IP (generous but prevents scrapers)
- **Webhooks**: no limit (Stripe/GitHub need to reach you reliably)

The rule: limit anything a user or bot could call in a tight loop. Don't limit webhooks you don't control.
