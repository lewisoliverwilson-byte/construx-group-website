excerpt: "Tilt is a local development environment orchestrator for Kubernetes — it reads a Tiltfile (Python-like DSL), builds container images, applies manifests, watches for file changes, and live-updates running containers without a full rebuild. The key feature is `live_update`: Tilt syncs changed files directly into the running container and runs a command to reload the process, skipping the Docker build layer. For Go and similar compiled languages, Tilt can rebuild only the binary and rsync it in, cutting iteration time from 2 minutes to under 5 seconds. The Tilt web UI shows all services, their logs, build status, and dependency graph in real time — a local control plane for the dev cluster."

File changes → live sync into container. No full rebuild. Web UI shows all services.

## Tiltfile basics

```python
# Tiltfile: Python-like DSL that describes your dev environment
# Tilt reads this on startup, then watches for changes

# Build a Docker image and apply a Kubernetes manifest
docker_build('construx/api', '.')
k8s_yaml('k8s/deployment.yaml')
k8s_resource('construx-api', port_forwards='8080:8080')

# Multiple services: each gets its own build + manifest
docker_build('construx/api',    './services/api')
docker_build('construx/worker', './services/worker')
docker_build('construx/web',    './web')

k8s_yaml(kustomize('k8s/overlays/dev'))   # use kustomize overlay

# Port forwarding (Tilt manages the kubectl port-forward)
k8s_resource('construx-api',    port_forwards='8080:8080')
k8s_resource('construx-worker', port_forwards='9090:9090')
k8s_resource('postgres',        port_forwards='5432:5432')
```

## Live update — skip the full Docker build

```python
# live_update: sync files into the running container and reload
# Avoids full image rebuild — only syncs the diff

docker_build(
  'construx/api',
  '.',
  live_update=[
    # Sync Go source files into the container
    sync('./services/api', '/app'),

    # After sync: rebuild the binary inside the container
    run('cd /app && go build -o /usr/local/bin/construx-api ./cmd/api'),

    # Restart the process (Tilt kills and re-starts the container entrypoint)
    restart_container(),
  ],
  # Dockerfile uses a multi-stage build — live update uses the final stage
)

# For interpreted languages (Python, Node): even simpler
docker_build(
  'construx/web',
  './web',
  live_update=[
    sync('./web/src', '/app/src'),   # sync JS source
    run('cd /app && pnpm build --filter changed'),  # incremental build
    # No restart needed — webpack dev server picks up changes
  ],
)

# fall_back_on: if these files change, do a full rebuild instead of live update
# (e.g. go.mod, package.json, Dockerfile changes require a new base image)
docker_build(
  'construx/api',
  '.',
  live_update=[...],
  ignore=['**/*.md', '**/testdata'],
)
```

## Resource dependencies and triggers

```python
# resource_deps: declare dependency ordering
# Tilt starts postgres before construx-api, waits for readiness probe

k8s_resource(
  'construx-api',
  resource_deps=['postgres', 'redis'],
  port_forwards='8080:8080',
)

# Local resources: run commands on the host (not in cluster)
local_resource(
  'db-migrate',
  cmd='DATABASE_URL=postgres://localhost:5432/construx go run ./cmd/migrate up',
  deps=['./migrations'],       # re-run when migration files change
  resource_deps=['postgres'],  # wait for postgres to be ready
)

local_resource(
  'codegen',
  cmd='go generate ./...',
  deps=['./api/*.go', './schema.graphql'],
  auto_init=True,
  trigger_mode=TRIGGER_MODE_AUTO,
)

# Buttons: add clickable actions to the Tilt UI
local_resource(
  'seed-db',
  cmd='go run ./cmd/seed',
  resource_deps=['db-migrate'],
  trigger_mode=TRIGGER_MODE_MANUAL,   # only run when button clicked
)
```

## Tilt extensions and helpers

```python
# Load community extensions
load('ext://helm_resource', 'helm_resource', 'helm_repo')
load('ext://namespace', 'namespace_create', 'namespace_inject')
load('ext://secret', 'secret_from_dict')

# Create namespace if it doesn't exist
namespace_create('construx-dev')

# Inject all resources into a specific namespace
k8s_yaml(namespace_inject(kustomize('k8s/overlays/dev'), 'construx-dev'))

# helm_resource: deploy a Helm chart + watch for value changes
helm_repo('bitnami', 'https://charts.bitnami.com/bitnami')
helm_resource(
  'postgres',
  'bitnami/postgresql',
  namespace='construx-dev',
  flags=['--set', 'auth.database=construx', '--set', 'auth.password=devpassword'],
  resource_deps=[],
)

# Secret from dict (base64-encoded automatically)
k8s_yaml(secret_from_dict('construx-dev-secrets', {
  'DATABASE_URL': 'postgres://construx:devpassword@postgres:5432/construx',
  'REDIS_URL': 'redis://redis:6379',
}))
```

## CLI and web UI

```bash
# Start Tilt (reads Tiltfile in current directory)
tilt up

# Tilt web UI: http://localhost:10350
# Shows:
#   - All resources (Pods, Services, Jobs, local_resources)
#   - Build status (green/red/building)
#   - Log streams per resource
#   - Dependency graph (requires --stream flag)
#   - Manual trigger buttons

# Run without web UI (headless CI mode)
tilt ci
# Builds all resources, waits for readiness, exits 0 on success

# Tear down all resources
tilt down

# Show what Tilt would do without actually running
tilt alpha tiltfile-result

# Watch build logs for a specific resource
tilt logs construx-api -f

# Trigger a manual resource
tilt trigger seed-db
```

Tilt vs Skaffold vs Garden: Skaffold is Google's equivalent — `skaffold dev` watches files and rebuilds/redeploys. Tilt adds the web UI, the Python-like Tiltfile DSL for complex dependency graphs, and live_update which syncs files without rebuilding the image at all. Garden is the most powerful (full DAG-based builds, remote caching, test orchestration) but also the heaviest. The practical split: Skaffold for simple services where the defaults work, Tilt for multi-service dev environments where the web UI and live_update latency improvements matter, Garden for monorepos with complex build graphs and distributed teams. The live_update feature is Tilt's clearest win — dropping a Go service rebuild from 90 seconds to 4 seconds by syncing the binary and restarting the process makes iteration fundamentally different.
