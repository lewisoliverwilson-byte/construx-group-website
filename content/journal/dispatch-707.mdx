JavaScript is fast enough for most things. WebAssembly is for the rest: resizing a 20MP image in under 50ms, encrypting 100MB of data before upload, running an ML inference model in the browser without a server round-trip.

## Rust to Wasm

```bash
# Install wasm-pack
cargo install wasm-pack

# Create a new Rust library
cargo new --lib wasm-image-processor
cd wasm-image-processor
```

```toml
# Cargo.toml
[lib]
crate-type = ["cdylib"]

[dependencies]
wasm-bindgen = "0.2"
image        = "0.25"
```

```rust
// src/lib.rs
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn resize_image(input: &[u8], width: u32, height: u32) -> Vec<u8> {
    let img = image::load_from_memory(input).expect("failed to decode image");
    let resized = img.resize(width, height, image::imageops::FilterType::Lanczos3);
    let mut output = Vec::new();
    resized
        .write_to(&mut std::io::Cursor::new(&mut output), image::ImageFormat::Jpeg)
        .expect("failed to encode");
    output
}

#[wasm_bindgen]
pub fn compress_jpeg(input: &[u8], quality: u8) -> Vec<u8> {
    let img = image::load_from_memory(input).expect("failed to decode");
    let mut output = Vec::new();
    let encoder = image::codecs::jpeg::JpegEncoder::new_with_quality(
        &mut std::io::Cursor::new(&mut output),
        quality,
    );
    img.write_with_encoder(encoder).expect("failed to encode");
    output
}
```

wasm-pack build --target web

## Using from JavaScript/TypeScript

```ts
// lib/imageProcessor.ts
import init, { resize_image, compress_jpeg } from './pkg/wasm_image_processor';

let initialised = false;

async function ensureInit() {
  if (!initialised) {
    await init();
    initialised = true;
  }
}

export async function resizeImage(
  file: File,
  width: number,
  height: number,
): Promise<Blob> {
  await ensureInit();

  const buffer   = await file.arrayBuffer();
  const input    = new Uint8Array(buffer);
  const output   = resize_image(input, width, height);  // runs at near-native speed
  return new Blob([output], { type: 'image/jpeg' });
}

export async function compressJpeg(file: File, quality: number): Promise<Blob> {
  await ensureInit();
  const input  = new Uint8Array(await file.arrayBuffer());
  const output = compress_jpeg(input, quality);
  return new Blob([output], { type: 'image/jpeg' });
}
```

## Using in a Next.js component

```tsx
'use client';
import { useState }      from 'react';
import { resizeImage }   from '@/lib/imageProcessor';

export function ImageResizer() {
  const [result, setResult] = useState<string | null>(null);
  const [status, setStatus] = useState('');

  const handleFile = async (e: React.ChangeEvent<HTMLInputElement>) => {
    const file = e.target.files?.[0];
    if (!file) return;

    setStatus('Resizing…');
    const start = performance.now();
    const blob  = await resizeImage(file, 800, 600);  // Wasm does the work
    const ms    = (performance.now() - start).toFixed(0);

    setResult(URL.createObjectURL(blob));
    setStatus(`Done in ${ms}ms (${(blob.size / 1024).toFixed(0)} KB)`);
  };

  return (
    <div>
      <input type="file" accept="image/*" onChange={handleFile} />
      <p>{status}</p>
      {result && <img src={result} alt="resized" />}
    </div>
  );
}
```

## WASI: Wasm outside the browser

```ts
// Node.js with WASI
import { WASI }       from 'wasi';
import { readFileSync } from 'fs';

const wasi = new WASI({ version: 'preview1', args: process.argv });
const wasm  = await WebAssembly.compile(readFileSync('./module.wasm'));
const instance = await WebAssembly.instantiate(wasm, wasi.getImportObject());
wasi.start(instance);
```

## Wasm vs JavaScript vs native

Wasm: near-native speed, no GC pauses for Rust/C code, sandboxed, portable. JavaScript: slower for CPU-bound work, excellent for DOM/IO, JIT-compiled. Native: fastest, no sandboxing, OS-specific. The right tool: JavaScript for web app logic and async I/O, Wasm for CPU-bound computation in the browser, native for server-side performance-critical code.
