Every device on a private network automatically. No firewall rules.

## Install

```bash
# macOS
brew install tailscale

# Linux — one command
curl -fsSL https://tailscale.com/install.sh | sh

# Docker (for CI runners, servers)
docker run -d \
  --name=tailscaled \
  -v /var/lib:/var/lib \
  -v /dev/net/tun:/dev/net/tun \
  --network=host \
  --cap-add=NET_ADMIN \
  --cap-add=SYS_MODULE \
  tailscale/tailscale:latest \
  tailscaled
```

## Connect

```bash
# Authenticate and join your tailnet
tailscale up

# Server/headless — use auth key from admin console
tailscale up --authkey tskey-auth-xxxxxxxxxxxx

# Show status
tailscale status
```

## SSH without key management

```bash
# Enable Tailscale SSH on the target machine
tailscale up --ssh

# SSH from anywhere on your tailnet — no key needed
ssh lewis@vps-fra01
ssh lewis@100.64.0.3
```

Tailscale SSH uses the same authentication as your tailnet login. No authorized_keys, no key rotation.

## ACL policy

```json
// Tailscale admin console → Access Controls (HuJSON)
{
  "acls": [
    // Developers can access all servers
    { "action": "accept", "src": ["tag:developer"], "dst": ["tag:server:*"] },
    // CI runners can reach the staging server only
    { "action": "accept", "src": ["tag:ci"], "dst": ["tag:staging:*"] },
    // Exit node — only admins can use it
    { "action": "accept", "src": ["group:admin"], "dst": ["tag:exit-node:*"] }
  ],
  "ssh": [
    {
      "action": "accept",
      "src":    ["tag:developer"],
      "dst":    ["tag:server"],
      "users":  ["autogroup:nonroot"]
    }
  ],
  "tagOwners": {
    "tag:developer": ["autogroup:admin"],
    "tag:server":    ["autogroup:admin"],
    "tag:ci":        ["autogroup:admin"],
    "tag:exit-node": ["autogroup:admin"]
  }
}
```

## Exit node — route traffic through a device

```bash
# Enable a server as an exit node
tailscale up --advertise-exit-node

# On a client — use the exit node
tailscale up --exit-node=100.64.0.8

# Route only specific subnets
tailscale up --advertise-routes=192.168.1.0/24
```

## CI integration — GitHub Actions

```yaml
# .github/workflows/deploy.yml
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Connect to Tailscale
        uses: tailscale/github-action@v2
        with:
          authkey: ${{ secrets.TAILSCALE_AUTHKEY }}
          tags:    tag:ci

      # Now the runner is on your tailnet
      - name: Deploy to staging
        run: ssh deploy@staging-server "cd /app && git pull && pm2 restart app"
```

## Funnel — expose a local server to the internet

```bash
# Expose localhost:3000 as a public HTTPS URL — no port forwarding needed
tailscale funnel 3000

# Share during development
# Accessible at: https://dev-macbook.your-tailnet.ts.net
```

Funnel routes public traffic through Tailscale's infrastructure to your device. Similar to ngrok but with your tailnet hostname and no rate limits.

Tailscale vs self-hosted WireGuard: Tailscale requires no VPN server setup, handles NAT traversal automatically, provides an admin UI, and costs $6/user/month for teams. Self-hosted WireGuard is free but requires a server, manual peer config, and no admin UI. The Construx default: Tailscale for team connectivity; self-hosted WireGuard where data sovereignty is required or at very large device counts.
