You write real code: loops, conditionals, classes, functions, imports — and Pulumi executes it to provision cloud resources through provider SDKs. The state model is similar to Terraform (resource graph, plan/apply cycle), but the language choice unlocks patterns that HCL can't express cleanly: creating 50 identical resources with a for loop, extracting shared logic into functions, writing unit tests for infrastructure, or generating resource definitions from an OpenAPI spec."

## Pulumi TypeScript — AWS EKS cluster

```typescript
// index.ts — construx production EKS cluster

import * as pulumi from "@pulumi/pulumi";
import * as aws from "@pulumi/aws";
import * as eks from "@pulumi/eks";

const config = new pulumi.Config();
const region = aws.config.region ?? "eu-west-1";

// VPC with public and private subnets
const vpc = new aws.ec2.Vpc("construx-vpc", {
  cidrBlock: "10.0.0.0/16",
  enableDnsHostnames: true,
  enableDnsSupport: true,
  tags: { Name: "construx-prod", Environment: "prod" },
});

// Private subnets across 3 AZs — loop instead of repeating 3 times
const azs = ["a", "b", "c"];
const privateSubnets = azs.map((az, i) =>
  new aws.ec2.Subnet(`construx-private-${az}`, {
    vpcId: vpc.id,
    cidrBlock: `10.0.${i}.0/24`,
    availabilityZone: `${region}${az}`,
    tags: {
      Name: `construx-private-${az}`,
      "kubernetes.io/role/internal-elb": "1",   // K8s needs this for ALB controller
    },
  })
);

// EKS cluster — high-level component handles OIDC, managed node groups, etc.
const cluster = new eks.Cluster("construx-eks", {
  vpcId: vpc.id,
  privateSubnetIds: privateSubnets.map(s => s.id),
  instanceType: "m7g.xlarge",
  minSize: 3,
  maxSize: 20,
  desiredCapacity: 6,
  version: "1.30",
  enabledClusterLogTypes: ["api", "audit", "authenticator"],
  tags: { Environment: "prod", Team: "platform" },
});

// Export values for use by other Pulumi stacks or CI/CD
export const kubeconfig = pulumi.secret(cluster.kubeconfig);
export const clusterName = cluster.core.cluster.name;
export const vpcId = vpc.id;
```

## Pulumi Go — S3 bucket with lifecycle policies

```go
// main.go — construx backup bucket in Go

package main

import (
    "fmt"
    "github.com/pulumi/pulumi-aws/sdk/v6/go/aws/s3"
    "github.com/pulumi/pulumi/sdk/v3/go/pulumi"
    "github.com/pulumi/pulumi/sdk/v3/go/pulumi/config"
)

func main() {
    pulumi.Run(func(ctx *pulumi.Context) error {
        cfg := config.New(ctx, "")
        env := cfg.Require("environment")

        // Bucket with versioning enabled
        bucket, err := s3.NewBucket(ctx, fmt.Sprintf("construx-backups-%s", env), &s3.BucketArgs{
            VersioningV2: &s3.BucketVersioningV2Args{
                Status: pulumi.String("Enabled"),
            },
            ServerSideEncryptionConfiguration: &s3.BucketServerSideEncryptionConfigurationArgs{
                Rule: &s3.BucketServerSideEncryptionConfigurationRuleArgs{
                    ApplyServerSideEncryptionByDefault: &s3.BucketServerSideEncryptionConfigurationRuleApplyServerSideEncryptionByDefaultArgs{
                        SseAlgorithm: pulumi.String("aws:kms"),
                    },
                },
            },
        })
        if err != nil {
            return err
        }

        // Lifecycle: move to Glacier after 30 days, delete after 2 years
        _, err = s3.NewBucketLifecycleConfigurationV2(ctx, "backup-lifecycle", &s3.BucketLifecycleConfigurationV2Args{
            Bucket: bucket.ID(),
            Rules: s3.BucketLifecycleConfigurationV2RuleArray{
                &s3.BucketLifecycleConfigurationV2RuleArgs{
                    Id:     pulumi.String("archive-and-expire"),
                    Status: pulumi.String("Enabled"),
                    Transitions: s3.BucketLifecycleConfigurationV2RuleTransitionArray{
                        &s3.BucketLifecycleConfigurationV2RuleTransitionArgs{
                            Days:         pulumi.Int(30),
                            StorageClass: pulumi.String("GLACIER"),
                        },
                    },
                    Expiration: &s3.BucketLifecycleConfigurationV2RuleExpirationArgs{
                        Days: pulumi.Int(730),
                    },
                },
            },
        })

        ctx.Export("backupBucketArn", bucket.Arn)
        return err
    })
}
```

## Stack management and state

```bash
# Pulumi state is stored in Pulumi Cloud (default) or a backend you control
# Use S3 as the state backend (self-hosted, no Pulumi Cloud dependency)
pulumi login s3://construx-pulumi-state/prod

# Initialize a new stack
pulumi stack init prod

# Preview changes (diff between current state and desired state)
pulumi preview --stack prod

# Apply changes
pulumi up --stack prod

# View current state
pulumi stack --stack prod
pulumi stack output --stack prod

# Import an existing resource into Pulumi state (adopt without recreating)
pulumi import aws:ec2/vpc:Vpc construx-existing-vpc vpc-0a1b2c3d4e5f6a7b8 --stack prod

# Export state for debugging
pulumi stack export --stack prod > state.json

# Move a resource to a different stack
pulumi state move --source prod --dest staging 'urn:pulumi:prod::construx::aws:ec2/vpc:Vpc::construx-vpc'

# Destroy specific resources
pulumi destroy --target 'urn:pulumi:prod::construx::aws:ec2/vpc:Vpc::construx-old-vpc' --stack prod
```

## Testing infrastructure code

```typescript
// infrastructure.test.ts — unit tests without creating real resources

import * as pulumi from "@pulumi/pulumi";
import { expect } from "chai";

// Mock Pulumi to not create real resources during tests
pulumi.runtime.setMocks({
  newResource: (type, name, inputs) => {
    return {
      id: `${name}-id`,
      state: inputs,
    };
  },
  call: (token, args) => {
    return {};
  },
});

describe("construx infrastructure", () => {
  let infra: typeof import("./index");

  before(async () => {
    infra = await import("./index");
  });

  it("VPC should have DNS hostnames enabled", async () => {
    const vpc = infra.vpc;
    const enableDnsHostnames = await new Promise<boolean>(resolve =>
      vpc.enableDnsHostnames.apply(v => resolve(v ?? false))
    );
    expect(enableDnsHostnames).to.equal(true);
  });

  it("should create 3 private subnets (one per AZ)", async () => {
    const subnets = infra.privateSubnets;
    expect(subnets).to.have.length(3);
  });

  it("EKS cluster version should be 1.30", async () => {
    const version = await new Promise<string>(resolve =>
      infra.cluster.core.cluster.version.apply(v => resolve(v ?? ""))
    );
    expect(version).to.equal("1.30");
  });
});
```

Pulumi vs Terraform: Terraform uses HCL, a declarative DSL — readable, but limited. Dynamic resource creation requires count and for_each with significant cognitive overhead; reusing logic requires modules with explicit variable passing. Pulumi uses real languages, so creating 50 resources in a loop is a for loop, sharing logic is a function or class, and testing is a unit test framework. The trade-off: Terraform has a larger ecosystem, more providers, and HCL is easier to read for ops teams without development experience. Pulumi is better when your infrastructure has programmatic complexity — generating resources from API specs, composing infrastructure components, writing property graph tests. For a small static infrastructure, Terraform is simpler. For infrastructure that needs to be generated, parameterised, or tested programmatically, Pulumi is more expressive.
