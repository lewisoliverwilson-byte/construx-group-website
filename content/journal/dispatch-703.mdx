Tailwind v3 required a JavaScript config file and a PostCSS setup. v4 moves everything into CSS, which is where it belonged. The result is simpler setup, faster builds, and a more natural extension model.

## Install

```bash
npm install tailwindcss@4 @tailwindcss/vite
# or for Next.js:
npm install tailwindcss@4 @tailwindcss/postcss
```

## Setup: Next.js (PostCSS)

```js
// postcss.config.mjs
export default {
  plugins: {
    '@tailwindcss/postcss': {},
  },
};
```

```css
/* app/globals.css */
@import "tailwindcss";

/* That's it. No content config. No plugin registration. */
```

## CSS-first configuration

```css
/* app/globals.css */
@import "tailwindcss";

@theme {
  /* Override defaults or add new values */
  --color-brand:    #F97316;
  --color-brand-50: #FFF7ED;

  --font-family-sans: 'Inter Variable', sans-serif;
  --font-family-mono: 'JetBrains Mono', monospace;

  --spacing-18: 4.5rem;
  --spacing-22: 5.5rem;

  --radius-brand: 3px;

  --animate-fade-in:  fade-in 0.3s ease;
  --animate-slide-up: slide-up 0.4s ease;
}

@keyframes fade-in {
  from { opacity: 0; }
  to   { opacity: 1; }
}

@keyframes slide-up {
  from { transform: translateY(8px); opacity: 0; }
  to   { transform: translateY(0);   opacity: 1; }
}
```

These values are immediately available as Tailwind utilities:
- `text-brand` → `color: #F97316`
- `bg-brand-50` → `background: #FFF7ED`
- `font-mono` → `font-family: JetBrains Mono`
- `p-18` → `padding: 4.5rem`
- `rounded-brand` → `border-radius: 3px`
- `animate-fade-in` → `animation: fade-in 0.3s ease`

## Variants (no changes from v3)

```html
<!-- Still works exactly the same -->
<div class="text-sm hover:text-brand md:text-base dark:text-white
            group-hover:opacity-100 peer-checked:text-green-500
            data-[active=true]:font-bold">
```

## Custom utilities

```css
@utility card {
  background: rgba(1,1,10,0.97);
  border: 1px solid rgba(255,255,255,0.07);
  border-radius: 3px;
}

@utility text-gradient-brand {
  background: linear-gradient(135deg, #F97316, #FBBF24);
  -webkit-background-clip: text;
  -webkit-text-fill-color: transparent;
  background-clip: text;
}
```

## Migrating from v3

```bash
# Official migration tool
npx @tailwindcss/upgrade
```

The migration tool handles most changes automatically:
- Removes `tailwind.config.ts`
- Converts `content`, `theme`, and `plugins` to CSS `@theme` and `@utility` directives
- Updates import statements
- Fixes v3→v4 breaking class renames (e.g. `shadow-sm` → `shadow-xs`)

## Class renames (breaking)

```
v3               v4
shadow-sm        shadow-xs
shadow           shadow-sm
ring             ring-3
blur-sm          blur-xs
rounded-sm       rounded-xs
overflow-ellipsis text-ellipsis
```

## Vite setup (non-Next.js)

```ts
// vite.config.ts
import { defineConfig }    from 'vite';
import tailwindcss         from '@tailwindcss/vite';

export default defineConfig({
  plugins: [tailwindcss()],
});
```

## v4 vs v3 performance

v4 uses a Rust-based engine (Lightning CSS) for the parser and optimizer. Typical project builds drop from 1.2s to 120ms for a cold build, and from 400ms to 40ms for incremental rebuilds. The content scanning engine uses file system watchers and heuristics rather than regex on file contents — the no-config approach is also the faster approach.

## Tailwind v4 vs UnoCSS vs vanilla CSS

Tailwind v4: zero-config, fast, excellent ecosystem (shadcn, Headless UI), one import. UnoCSS: fully customizable, atomic CSS engine, pure-on-demand with no scan. Vanilla CSS: maximum control, custom properties, no framework weight. Tailwind v4 is the pragmatic choice for teams that want a good constraint set without managing a design system from scratch.
