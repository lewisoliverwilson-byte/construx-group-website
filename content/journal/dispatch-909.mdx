date: "2032-06-02"
excerpt: "strace traces every system call a process makes — open, read, write, mmap, connect, epoll_wait — and the kernel's response. This makes it possible to debug programs without source code: you can see exactly which files they open, which ports they connect to, where they spend time waiting, and which calls are returning errors. strace is the tool for diagnosing 'permission denied' errors, finding which config file an app is actually reading, tracing a process that's stuck, or understanding why a binary fails with no useful error message."

No source code needed. If it runs, you can trace it.

## Basic tracing

```bash
# Trace a command from start — see every syscall
strace ls /tmp
# execve("/usr/bin/ls", ["ls", "/tmp"], 0x... /* env vars */) = 0
# brk(NULL)                               = 0x55a9b2c4d000
# ...
# openat(AT_FDCWD, "/tmp", O_RDONLY|O_NONBLOCK|O_CLOEXEC|O_DIRECTORY) = 3
# getdents64(3, /* 14 entries */, 32768)  = 392
# write(1, "file1.txt  file2.txt\n", 21)  = 21
# close(3)                                = 0
# exit_group(0)                           = ?

# Attach to a running process by PID (doesn't stop it)
strace -p 1847
# strace: Process 1847 attached
# epoll_wait(9, [], 128, 4990)            = 0
# ...

# Follow child processes (essential for multi-process apps)
strace -f ./construx-server
# [pid 1847] clone(child_stack=NULL, flags=CLONE_CHILD_CLEARTID|CLONE_CHILD_SETTID|SIGCHLD, ...) = 1848
# [pid 1848] execve("/usr/lib/construx/worker", ...) = 0

# Trace only specific syscall families — much less noise
strace -e trace=file ls /tmp          # Only file-related calls
strace -e trace=network curl https://api.construx.io/
strace -e trace=openat,read,write,close cat /etc/hostname

# Count syscalls and time spent in each — performance view
strace -c -p 1847
# % time     seconds  usecs/call     calls    errors syscall
# -------  ---------  ----------  --------  -------- --------
#  61.43   0.041230          41       1006           epoll_wait
#  24.17   0.016223           8       1872           read
#   8.31   0.005577           3       1872           write
#   4.12   0.002762          92         30           futex
```

## Debugging file access and permission errors

```bash
# Find which config file an app is actually reading
strace -e openat construx-api 2>&1 | grep -v "= -1"
# openat(AT_FDCWD, "/etc/construx/config.yaml", O_RDONLY) = 3
# openat(AT_FDCWD, "/var/lib/construx/state.db", O_RDWR|O_CREAT) = 4

# Track down a "permission denied" — -1 EACCES is the failure
strace -e openat construx-api 2>&1 | grep "EACCES\|EPERM"
# openat(AT_FDCWD, "/etc/construx/secrets.env", O_RDONLY) = -1 EACCES (Permission denied)

# Find every file opened by a process tree
strace -f -e openat -p $(pgrep -d, construx) 2>&1 | \
  grep -oP '"[^"]*"' | sort | uniq
# "/etc/construx/config.yaml"
# "/var/lib/construx/state.db"
# "/proc/self/status"
# "/tmp/construx.lock"

# Watch for log file writes — useful when an app writes errors silently
strace -e write -p 1847 2>&1 | grep -A1 'write(2'
# write(2, "ERROR: database connection lost\n", 32) = 32

# Trace a process that hangs — see what syscall it's blocked on
strace -p 1847 -e trace=futex,epoll_wait,select,poll,read
# epoll_wait(9, [], 128, -1)  <-- hung here: waiting forever, timeout -1
```

## Network and socket tracing

```bash
# Trace all network calls — find what address a service connects to
strace -e trace=network construx-worker 2>&1 | grep "connect\|bind\|accept"
# socket(AF_INET6, SOCK_STREAM|SOCK_CLOEXEC|SOCK_NONBLOCK, IPPROTO_TCP) = 5
# connect(5, {sa_family=AF_INET6, sin6_port=htons(5432), sin6_addr=::ffff:10.0.1.4}, 28) = -1 EINPROGRESS

# See DNS resolution — glibc does it via read/write to /etc/resolv.conf + UDP
strace -e trace=openat,connect,sendto,recvfrom construx-worker 2>&1 | head -30

# Find which port a process binds to
strace -e bind -p 1847 2>&1
# bind(5, {sa_family=AF_INET6, sin6_port=htons(8080), sin6_addr=IN6ADDR_ANY_INIT}, 28) = 0

# Trace SSL/TLS — won't see plaintext (that's in userspace), but you can see the connect
strace -e trace=connect,read,write -p 1847 2>&1 | grep connect
```

## Advanced: capturing output and timing

```bash
# Write strace output to a file (strace goes to stderr by default)
strace -o /tmp/strace-construx.log -f ./construx-api
# Useful for large traces — grep the file afterward

# Add timestamps — absolute (-t), relative (-r), or microseconds (-T per call)
strace -T -e openat ls /tmp
# openat(AT_FDCWD, "/tmp", O_RDONLY|O_NONBLOCK|O_CLOEXEC|O_DIRECTORY) = 3 <0.000041>

strace -tt -e openat ls /tmp
# 14:32:07.441201 openat(AT_FDCWD, "/tmp", ...) = 3

# Decode string arguments (default is 32 chars — increase for full paths)
strace -s 256 -e openat ls /tmp

# Profile a slow startup — which calls take the most wall time?
strace -T -f -c ./construx-api 2>&1 | head -5
# % time     seconds  usecs/call     calls    errors syscall
#  38.2    0.412300        1374       300           futex
#  21.7    0.234110         782       300           read

# Quick: find why a binary fails immediately
strace ./broken-binary 2>&1 | tail -5
# execve("./broken-binary", ...) = -1 ENOENT (No such file or directory)
# ...or:
# openat(AT_FDCWD, "/lib/x86_64-linux-gnu/libcrypto.so.3", O_RDONLY) = -1 ENOENT
```

strace vs lsof vs /proc: strace shows syscalls in real time as they happen — it's dynamic. lsof shows currently open file descriptors for running processes — it's a snapshot. /proc gives you the same via /proc/PID/fd (file descriptors), /proc/PID/net/tcp (connections), /proc/PID/maps (memory mappings) without needing a tool installed. strace has overhead: attaching to a production process slows it down (ptrace interception on every syscall). For prod debugging, prefer /proc and perf over strace, or use strace on a replica. The sweet spot: strace for development debugging and one-off production incidents; lsof and /proc for lower-overhead production inspection.
