The IAM mental model: principals (users, roles, services) perform actions on resources. Policies define what's allowed. By default, everything is denied. You explicitly allow what you need.

## IAM components

- **User**: a long-term identity, typically for a human. Avoid giving IAM users long-term keys — use roles.
- **Role**: a temporary identity that can be assumed. Used by services, EC2 instances, Lambda functions, and GitHub Actions.
- **Policy**: a JSON document that allows or denies actions on resources.
- **Group**: a collection of users that share policies.

## Writing a least-privilege policy

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadS3Assets",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::construx-assets",
        "arn:aws:s3:::construx-assets/*"
      ]
    },
    {
      "Sid": "WriteS3Uploads",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:DeleteObject"
      ],
      "Resource": "arn:aws:s3:::construx-assets/uploads/*"
    }
  ]
}
```

Scope to the minimum: specific actions (not `s3:*`), specific resources (not `*`), and specific prefixes within resources where possible.

## ECS task role (service-to-AWS access)

```hcl
# Terraform: task role for the API service
resource "aws_iam_role" "api_task" {
  name = "construx-api-task"

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Action    = "sts:AssumeRole"
      Effect    = "Allow"
      Principal = { Service = "ecs-tasks.amazonaws.com" }
    }]
  })
}

resource "aws_iam_role_policy" "api_task" {
  name = "construx-api-task-policy"
  role = aws_iam_role.api_task.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = ["s3:GetObject", "s3:PutObject"]
        Resource = "arn:aws:s3:::${aws_s3_bucket.assets.id}/*"
      },
      {
        Effect   = "Allow"
        Action   = ["ssm:GetParameter", "ssm:GetParameters"]
        Resource = "arn:aws:ssm:${var.region}:${data.aws_caller_identity.current.account_id}:parameter/construx/prod/*"
      },
      {
        Effect   = "Allow"
        Action   = ["ses:SendEmail"]
        Resource = "*"
        Condition = {
          StringEquals = { "ses:FromAddress" = "noreply@construxgroup.io" }
        }
      }
    ]
  })
}
```

The ECS task assumes this role automatically — no credentials in environment variables, no rotation needed. AWS injects temporary credentials via the metadata service.

## GitHub Actions OIDC (no long-term keys)

```hcl
# Terraform: trust GitHub Actions OIDC provider
resource "aws_iam_openid_connect_provider" "github" {
  url = "https://token.actions.githubusercontent.com"
  client_id_list  = ["sts.amazonaws.com"]
  thumbprint_list = ["6938fd4d98bab03faadb97b34396831e3780aea1"]
}

resource "aws_iam_role" "github_deploy" {
  name = "construx-github-deploy"

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Allow"
      Action    = "sts:AssumeRoleWithWebIdentity"
      Principal = { Federated = aws_iam_openid_connect_provider.github.arn }
      Condition = {
        StringEquals = {
          "token.actions.githubusercontent.com:aud" = "sts.amazonaws.com"
        }
        StringLike = {
          "token.actions.githubusercontent.com:sub" = "repo:lewisoliverwilson-byte/construx-group-website:*"
        }
      }
    }]
  })
}
```

```yaml
# .github/workflows/deploy.yml
- uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: arn:aws:iam::123456789012:role/construx-github-deploy
    aws-region:    eu-west-2
# No AWS_ACCESS_KEY_ID or AWS_SECRET_ACCESS_KEY needed
# GitHub exchanges an OIDC token for temporary AWS credentials
```

OIDC eliminates long-term access keys. No key to rotate, no key to leak.

## Policy analysis with IAM Access Analyzer

```bash
# Check if a role has more permissions than it uses
aws iam generate-service-last-accessed-details --arn arn:aws:iam::123456789:role/construx-api-task

# After a few minutes, retrieve the results
aws iam get-service-last-accessed-details --job-id <job-id>
```

IAM Access Analyzer shows which services a role has accessed in the last 90 days. If a role has S3 permissions but hasn't accessed S3 in 90 days, you can safely remove them.

## Common IAM mistakes

```json
// Don't do this — wildcard action and resource
{
  "Effect": "Allow",
  "Action": "*",
  "Resource": "*"
}

// Don't do this — overly broad action
{
  "Effect": "Allow",
  "Action": "s3:*",
  "Resource": "arn:aws:s3:::my-bucket/*"
}

// Don't do this — no resource constraint
{
  "Effect": "Allow",
  "Action": ["ec2:TerminateInstances"],
  "Resource": "*"
}
```

```json
// Do this instead — specific actions, specific resources
{
  "Effect": "Allow",
  "Action": ["ec2:TerminateInstances"],
  "Resource": "arn:aws:ec2:eu-west-2:123456789:instance/*",
  "Condition": {
    "StringEquals": { "aws:ResourceTag/Environment": "dev" }
  }
}
```

Tag-based conditions (`aws:ResourceTag/Environment`) restrict actions to resources with specific tags — deploy workers can only terminate instances tagged as dev.
