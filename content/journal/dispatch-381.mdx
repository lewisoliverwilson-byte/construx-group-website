Performance is a feature. Core Web Vitals are the standard for measuring it — they're what Google uses to rank pages, and they correlate with user engagement metrics. The three that matter: LCP, INP, and CLS.

## The three metrics

**LCP (Largest Contentful Paint)** — how long until the largest element on screen is visible. Measures perceived load speed. Target: under 2.5 seconds.

**INP (Interaction to Next Paint)** — how long from user interaction (click, tap, keystroke) until the page updates. Measures responsiveness. Target: under 200ms.

**CLS (Cumulative Layout Shift)** — how much the page layout shifts unexpectedly during load. Measures visual stability. Target: under 0.1.

## Measuring in production

Synthetic testing (Lighthouse, WebPageTest) measures a simulated visit. Real User Monitoring (RUM) measures actual users on actual devices and networks.

```ts
// lib/vitals.ts — report Core Web Vitals to your analytics
import { onCLS, onINP, onLCP, type Metric } from 'web-vitals';

function sendToAnalytics(metric: Metric) {
  const body = JSON.stringify({
    name: metric.name,
    value: metric.value,
    rating: metric.rating,  // 'good', 'needs-improvement', 'poor'
    delta: metric.delta,
    id: metric.id,
    navigationType: metric.navigationType,
    url: window.location.pathname,
  });

  navigator.sendBeacon('/api/vitals', body);
}

onCLS(sendToAnalytics);
onINP(sendToAnalytics);
onLCP(sendToAnalytics);
```

```ts
// app/api/vitals/route.ts
```

## Performance budgets in Lighthouse CI

Automate Lighthouse runs in CI and fail the build if a metric regresses:

```bash
npm install -D @lhci/cli
```

```json
// lighthouserc.json
{
  "ci": {
    "collect": {
      "numberOfRuns": 3,
      "url": ["http://localhost:3000", "http://localhost:3000/ventures", "http://localhost:3000/journal"]
    },
    "assert": {
      "assertions": {
        "categories:performance": ["error", { "minScore": 0.8 }],
        "categories:accessibility": ["error", { "minScore": 0.9 }],
        "first-contentful-paint": ["warn", { "maxNumericValue": 2000 }],
        "largest-contentful-paint": ["error", { "maxNumericValue": 2500 }],
        "cumulative-layout-shift": ["error", { "maxNumericValue": 0.1 }],
        "total-blocking-time": ["warn", { "maxNumericValue": 300 }]
      }
    },
    "upload": {
      "target": "lhci",
      "serverBaseUrl": "https://lhci.your-domain.com",
      "token": "your-build-token"
    }
  }
}
```

```yaml
# .github/workflows/ci.yml
  lighthouse:
    name: Lighthouse CI

      - uses: actions/checkout@v4
```

## LCP optimizations

The most impactful fixes for LCP:

```tsx
// 1. Prioritize the LCP image
<Image
  src="/hero.jpg"
  alt="Hero"
  priority          // adds fetchpriority="high" — skip lazy loading
  sizes="100vw"
  fill
/>

// 2. Preload critical fonts
// app/layout.tsx
<link rel="preconnect" href="https://fonts.googleapis.com" />

// 3. Avoid render-blocking JavaScript
// Move non-critical scripts to load after page is interactive
<Script src="https://analytics.example.com/js/v2.js" strategy="lazyOnload" />

// 4. Use a CDN for images
// next.config.ts
images: {
  formats: ['image/avif', 'image/webp'],
  remotePatterns: [{ protocol: 'https', hostname: 'cdn.construxgroup.io' }],
}
```

## CLS fixes

Layout shifts happen when elements load in after the initial paint and push things around:

```tsx
// Fix 1: Always specify width and height on images
<Image src="/logo.png" alt="Logo" width={120} height={40} />

// Fix 2: Reserve space for dynamic content with a skeleton
function PostCard({ post }: { post: Post | null }) {
  if (!post) {
    return <div className="h-32 animate-pulse bg-white/5 rounded" />;
  }
  return <article>{/* content */}</article>;
}

// Fix 3: Avoid dynamically injecting content above existing content
// Bad: prepending a notification banner that shifts content down
// Good: use a fixed overlay or allocate space ahead of time
```

## INP optimizations

Interaction responsiveness depends on main-thread availability:

```tsx
// Use useTransition for state updates that aren't urgent
import { useTransition } from 'react';

function FilterBar() {
  const [isPending, startTransition] = useTransition();
  const [filter, setFilter] = useState('all');

  const handleChange = (value: string) => {
    startTransition(() => setFilter(value));  // deprioritize the re-render
  };

  return (
    <select onChange={(e) => handleChange(e.target.value)}>
      {/* options */}
    </select>
  );
}

// Use useDeferredValue for computed output
import { useDeferredValue, useMemo } from 'react';

function SearchResults({ query }: { query: string }) {
  const deferredQuery = useDeferredValue(query);

  const results = useMemo(
    () => allPosts.filter((p) => p.title.includes(deferredQuery)),
    [deferredQuery],
  );

  return <ul>{results.map(/* ... */)}</ul>;
}
```

## The dashboard

Store vitals measurements and track the 75th percentile — that's the number Google uses for its CWV assessment. The 75th percentile means 75% of users are getting at or better than this experience.

If your p75 LCP is 4.5 seconds, 25% of users are seeing LCP slower than that. Fix the slow tail, not the mean.
