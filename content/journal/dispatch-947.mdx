Server-side copy. Checksum verify. `rclone check` to diff. `--bwlimit` to throttle.

## Configuration and remotes

```bash
# rclone config: interactive configuration wizard
rclone config

# Or write config directly to ~/.config/rclone/rclone.conf:
cat ~/.config/rclone/rclone.conf
# [s3-prod]
# type = s3
# provider = AWS
# access_key_id = AKIAIOSFODNN7EXAMPLE
# secret_access_key = wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
# region = eu-west-1
#
# [r2-backup]
# type = s3
# provider = Cloudflare
# access_key_id = abc123...
# secret_access_key = xyz789...
# endpoint = https://abc123.r2.cloudflarestorage.com
#
# [gcs-archive]
# type = google cloud storage
# project_number = 123456789
# service_account_file = /etc/construx/gcs-key.json

# List configured remotes
rclone listremotes
# s3-prod:
# r2-backup:
# gcs-archive:

# Test a remote (list buckets)
rclone lsd s3-prod:
# -1 2032-01-01 00:00:00 -1 construx-raw
# -1 2032-03-01 00:00:00 -1 construx-processed

# Environment variable config (for CI — no config file needed)
export RCLONE_S3_ACCESS_KEY_ID="$AWS_ACCESS_KEY_ID"
export RCLONE_S3_SECRET_ACCESS_KEY="$AWS_SECRET_ACCESS_KEY"
rclone ls :s3:construx-raw   # on-the-fly remote
```

## Sync, copy, and check

```bash
# sync: mirror source to destination (DELETES destination files not in source)
# Use --dry-run first to see what would happen
rclone sync ./data s3-prod:construx-raw/data --dry-run
rclone sync ./data s3-prod:construx-raw/data --progress

# copy: copy without deleting (safe — destination can have extra files)
rclone copy ./data s3-prod:construx-raw/data --progress

# --checksum: verify integrity by comparing checksums (not just size+mtime)
# Slower but catches silent corruption
rclone sync ./data r2-backup:construx-backup --checksum --progress

# check: diff two locations without transferring — find what's out of sync
rclone check s3-prod:construx-raw r2-backup:construx-backup
# 12,847 files compared: 12,843 match, 4 differ
# ERROR : orders/2032-08-29.parquet: sizes differ
# ERROR : events/2032-09-01.json: file not in destination

# --combined: show combined status per file (=match, *differ, +only-in-source, -only-in-dest)
rclone check s3-prod:construx-raw r2-backup:construx-backup --combined - | head -20

# move: copy then delete source (useful for one-time migration)
rclone move s3-prod:construx-raw/tmp r2-backup:construx-processed --delete-empty-src-dirs
```

## Server-side copy and performance

```bash
# Server-side copy: data never leaves the cloud (between two S3-compatible remotes)
# Much faster — no upload/download through your machine
rclone copy s3-prod:construx-raw r2-backup:construx-backup \
  --no-traverse \
  --transfers 32 \
  --checkers 64

# --transfers: number of parallel file transfers (default 4)
# --checkers: number of parallel stat checks (default 8)
# Tune these based on file size and network:
# Many small files: increase --checkers (stat is the bottleneck)
# Few large files:  increase --transfers (transfer is the bottleneck)

# --s3-upload-concurrency: multipart upload concurrency (default 4)
rclone copy ./large-dataset.parquet s3-prod:construx-raw/ \
  --s3-upload-concurrency 16 \
  --s3-chunk-size 64M

# --bwlimit: throttle bandwidth (useful for background sync)
rclone sync ./data r2-backup:construx-backup --bwlimit 50M   # 50 MiB/s max

# --bwlimit with schedule (limit during business hours, unlimited at night)
rclone sync ./data r2-backup:construx-backup \
  --bwlimit "09:00,20M 18:00,off"

# --cutoff-mode: handle large files differently
# hard:  skip files > cutoff (don't fail)
# soft:  don't start new files after cutoff
# cautious: don't upload files that would take longer than threshold
rclone sync ./data s3-prod:construx-raw --max-size 5G
```

## Cloud-to-cloud migration

```bash
# Migrate S3 → Cloudflare R2 (server-side, no local data movement)
# Step 1: check what needs to move
rclone check s3-prod:construx-raw r2-backup:construx-raw \
  --combined /tmp/migration-diff.txt

wc -l /tmp/migration-diff.txt   # total files compared
grep '^+' /tmp/migration-diff.txt | wc -l   # files only on S3 (to migrate)
grep '^*' /tmp/migration-diff.txt | wc -l   # files that differ

# Step 2: copy all S3 data to R2 (server-side)
rclone copy s3-prod:construx-raw r2-backup:construx-raw \
  --transfers 64 \
  --checkers 128 \
  --progress \
  --stats-one-line \
  --log-file /var/log/rclone-migration.log

# Step 3: verify checksums after migration
rclone check s3-prod:construx-raw r2-backup:construx-raw --checksum
# No errors → migration complete

# Step 4: update application config, redirect DNS/endpoints, decommission S3

# Ongoing sync: keep R2 as a backup mirror of S3
# /etc/cron.d/rclone-sync
# 0 4 * * * construx rclone sync s3-prod:construx-raw r2-backup:construx-raw \
#   --checksum --transfers 32 --log-file /var/log/rclone.log 2>&1
```

## Mount and serve

```bash
# mount: expose a remote as a FUSE filesystem (read/write)
rclone mount r2-backup:construx-backup /mnt/backup \
  --daemon \
  --vfs-cache-mode writes \   # cache writes locally before upload
  --vfs-cache-max-age 24h \
  --transfers 8

# Browse it like a local filesystem
ls /mnt/backup/
du -sh /mnt/backup/orders/

# Unmount
fusermount -u /mnt/backup

# serve http: expose a remote over HTTP (static file server)
rclone serve http s3-prod:construx-public \
  --addr 0.0.0.0:8080 \
  --read-only

# serve sftp: expose a remote as an SFTP server
rclone serve sftp r2-backup:construx-backup \
  --addr 0.0.0.0:2222 \
  --key ~/.ssh/rclone-sftp-host-key

# serve s3: expose any remote as an S3-compatible API
# Useful for tools that only speak S3
rclone serve s3 gcs-archive:construx-archive \
  --addr 0.0.0.0:9000
```

rclone vs aws s3 CLI vs gsutil: the native CLIs (aws s3 cp, gsutil cp) are tightly integrated with their respective clouds and often faster for single-cloud operations. rclone's advantage is backend-agnosticism: one tool for every cloud, server-side copy between any two S3-compatible remotes, and unified checksum verification across backends. The `rclone check --checksum` command is the clearest win — it verifies data integrity by computing and comparing checksums, something `aws s3 sync` doesn't do by default. For large-scale migrations, rclone's `--transfers` and `--checkers` tuning and server-side copy make it the right choice over manual scripting.
