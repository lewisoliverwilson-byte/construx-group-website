Status pages and uptime monitoring are the kind of infrastructure that third-party services sell as a service: Statuspage.io, Freshstatus, Betterstack. These are good products. We built our own because the requirements are simple and the data should live in our system.

Here's what we built.

## The requirements

**Uptime checks:** Each product should be checked every 60 seconds from an external location. A 200 response from the health endpoint means up; anything else means down.

**Incident recording:** Outages should be recorded with start time, end time, and duration. Historical uptime % should be computable from this data.

**Status page:** A public page showing current status and 90-day history for each product.

**Alerts:** When a product goes down, notify us immediately (Slack, email). When it comes back up, notify us again.

## The health endpoint

Each product exposes a `/api/health` endpoint:

```ts
// Scoutr's health endpoint
export async function GET() {
  const checks = await Promise.allSettled([
    db.execute(sql`SELECT 1`),
    redis.ping(),
  ]);

  const allHealthy = checks.every((c) => c.status === 'fulfilled');

  return Response.json(
    {
      status: allHealthy ? 'ok' : 'degraded',
      ts: new Date().toISOString(),
      checks: {
        db: checks[0].status === 'fulfilled' ? 'ok' : 'fail',
        cache: checks[1].status === 'fulfilled' ? 'ok' : 'fail',
      },
    },
    { status: allHealthy ? 200 : 503 },
  );
}
```

The health endpoint checks that the database and cache are reachable. A 200 means fully operational; a 503 means degraded. The monitor only cares about the HTTP status code — the JSON body is for human debugging.

## The uptime checker

The checker runs as a Node.js script on a small DigitalOcean droplet — not on Amplify, because a self-check from the same infrastructure that hosts the product doesn't catch infrastructure-level failures.

```ts
const MONITORS = [
  { name: 'Scoutr', url: 'https://scoutr.io/api/health', alertName: 'scoutr' },
  { name: 'The Marqet', url: 'https://themarqet.shop/api/health', alertName: 'marqet' },
  { name: 'The Hyve', url: 'https://thehyve.io/api/health', alertName: 'hyve' },
];

async function checkMonitor(monitor: (typeof MONITORS)[number]) {
  const start = Date.now();
  try {
    const res = await fetch(monitor.url, {
      signal: AbortSignal.timeout(10_000),
      headers: { 'User-Agent': 'ConstruxMonitor/1.0' },
    });
    const latencyMs = Date.now() - start;

    await recordCheck({
      monitor: monitor.alertName,
      status: res.ok ? 'up' : 'down',
      statusCode: res.status,
      latencyMs,
    });

    if (!res.ok) {
      await handleDownEvent(monitor, res.status);
    } else {
      await handleRecovery(monitor);
    }
  } catch (err) {
    await recordCheck({ monitor: monitor.alertName, status: 'down', statusCode: 0, latencyMs: Date.now() - start });
    await handleDownEvent(monitor, 0);
  }
}
```

The checker runs every 60 seconds via a setInterval loop. We chose 60s because it's fast enough to catch outages promptly and slow enough to avoid generating excessive load.

## Incident management

An incident is created when a monitor transitions from up to down, and closed when it transitions back:

```sql
CREATE TABLE uptime_checks (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  monitor     text NOT NULL,
  status      text NOT NULL, -- 'up' | 'down'
  status_code int NOT NULL,
  latency_ms  int NOT NULL,
  checked_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE incidents (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  monitor     text NOT NULL,
  started_at  timestamptz NOT NULL,
  resolved_at timestamptz,
  duration_s  int GENERATED ALWAYS AS (
    EXTRACT(EPOCH FROM (COALESCE(resolved_at, now()) - started_at))::int
  ) STORED
);
```

The `duration_s` generated column makes it easy to query total downtime per monitor per period:

```sql
-- 90-day uptime per monitor
SELECT
  monitor,
  COUNT(*) FILTER (WHERE status = 'up') * 100.0 / COUNT(*) AS uptime_pct,
  ROUND(SUM(CASE WHEN status = 'down' THEN latency_ms ELSE 0 END) / 1000.0) AS downtime_s
FROM uptime_checks
WHERE checked_at > now() - INTERVAL '90 days'
GROUP BY monitor;
```

## The status page

The status page is a Next.js page that fetches the last 90 days of check data and renders it:

```tsx
export default async function StatusPage() {
  const checks = await getUptimeData();
  
  return (
    <div>
      {checks.map((monitor) => (
        <MonitorRow
          key={monitor.name}
          name={monitor.name}
          status={monitor.currentStatus}
          uptimePct={monitor.uptimePct}
          latencyP50={monitor.latencyP50}
          history={monitor.dailyHistory} // Array of 90 day objects
        />
      ))}
    </div>
  );
}
```

The daily history renders as a 90-segment bar chart where each segment represents one day: green if 100% uptime, orange if partial, red if a full outage.

## Alerting

Alerts go to a Slack webhook. When a monitor goes down:

```ts
async function sendDownAlert(monitor: Monitor, statusCode: number) {
  await fetch(process.env.SLACK_WEBHOOK_URL!, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      text: `🔴 *${monitor.name}* is DOWN`,
      blocks: [
        {
          type: 'section',
          text: {
            type: 'mrkdwn',
            text: `*${monitor.name}* returned HTTP ${statusCode || 'TIMEOUT'} at <!date^${Math.floor(Date.now() / 1000)}^{time}|now>.`,
          },
        },
        {
          type: 'actions',
          elements: [
            { type: 'button', text: { type: 'plain_text', text: 'View Logs' }, url: `https://construxgroup.io/internal/logs?monitor=${monitor.alertName}` },
          ],
        },
      ],
    }),
  });
}
```

Recovery alerts include the incident duration so we know immediately how long the outage lasted.

## The total cost

The DigitalOcean droplet running the monitor: $6/month. The status page itself: free (it's part of the Next.js site). The monitoring database: reuses the existing Supabase instance.

Statuspage.io starts at $29/month. We saved $276/year and have full control over the data. The only cost is the time it took to build, which was about a day.

For more complex monitoring needs (multi-region, synthetic transaction monitoring, complex alerting rules), third-party services are worth the cost. For "is the site returning 200s?", this approach is sufficient and more informative.
