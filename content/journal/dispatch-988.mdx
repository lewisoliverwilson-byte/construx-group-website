title: "Cosign: container image signing, verification, and SBOM attestation"
date: "2033-01-25"
excerpt: "Cosign is a Sigstore tool for signing and verifying container images — it attaches cryptographic signatures to images in the OCI registry alongside the image manifest, using either a key pair or keyless signing via OIDC (GitHub Actions, GitLab CI). Keyless signing is the modern approach: the signing identity is the CI workflow's OIDC token, not a long-lived key. Attestations extend signing to structured metadata — you can attach an SBOM (CycloneDX), a vulnerability scan result (Trivy output), or a custom provenance statement to the image and verify it before deployment. Combined with Kyverno or Gatekeeper admission controllers, you can enforce that only signed images from trusted CI pipelines run in production."

Image signing. Keyless via OIDC. SBOM attestation. Admission controller enforcement.

## Key-based signing

```bash
# Install cosign
brew install cosign
cosign version
# GitVersion: v2.4.1

# Generate a signing key pair
cosign generate-key-pair
# Enter password for private key:
# Private key written to cosign.key
# Public key written to cosign.pub

# Sign an image (stores the signature in the registry alongside the manifest)
cosign sign \
  --key cosign.key \
  registry.construx.io/construx/api:v1.8.3
# Pushing signature to: registry.construx.io/construx/api
# ✔ Signature pushed to registry.construx.io/construx/api

# Verify a signed image
cosign verify \
  --key cosign.pub \
  registry.construx.io/construx/api:v1.8.3
# ✔ 1 valid signature(s) found
# {
#   "critical": {
#     "identity": { "docker-reference": "registry.construx.io/construx/api" },
#     "image": { "docker-manifest-digest": "sha256:4a9f2b1c..." }
#   },
#   "optional": {
#     "Bundle": { ... }
#   }
# }

# Where the signature lives:
# registry.construx.io/construx/api:sha256-4a9f2b1c....sig
# (a separate tag in the same registry, not in the image itself)
```

## Keyless signing with OIDC

```bash
# Keyless signing: no key pair needed — identity is the OIDC token
# The signature is tied to the CI workflow identity, not a secret key
# Signatures are logged in Rekor (a public, tamper-evident transparency log)

# GitHub Actions: sign after pushing (OIDC is available in the workflow)
# No COSIGN_KEY needed — the runner's OIDC token is the signing identity

# .github/workflows/publish.yml
- name: Sign the published Docker image
  env:
    COSIGN_EXPERIMENTAL: "true"   # enable keyless mode
  run: |
    cosign sign \
      --yes \
      registry.construx.io/construx/api@${{ steps.build-push.outputs.digest }}
    # Signs with: identity = github.com/construx/construx-api/.github/workflows/publish.yml
    # Logged in Rekor at https://rekor.sigstore.dev

# Verify keyless signature
cosign verify \
  --certificate-identity=\
"https://github.com/construx/construx-api/.github/workflows/publish.yml@refs/heads/master" \
  --certificate-oidc-issuer=https://token.actions.githubusercontent.com \
  registry.construx.io/construx/api:v1.8.3
# ✔ 1 valid signature found

# The verification proves:
# 1. This exact image digest was signed by
# 2. The GitHub Actions workflow at that path
# 3. Running on the master branch
# 4. At a specific point in time (logged in Rekor)

# Lookup a signature in Rekor (the transparency log)
cosign triangulate registry.construx.io/construx/api:v1.8.3
# registry.construx.io/construx/api:sha256-4a9f2b1c....sig

rekor-cli get \
  --log-index 12345678 \
  --format json | jq .
```

## Attestations — SBOM and vulnerability data

```bash
# Attestations: structured metadata attached to an image (not just a signature)
# Format: DSSE (Dead Simple Signing Envelope) wrapping an in-toto predicate

# Attach a CycloneDX SBOM attestation
trivy image --format cyclonedx --output sbom.json construx/api:v1.8.3

cosign attest \
  --key cosign.key \
  --type cyclonedx \
  --predicate sbom.json \
  registry.construx.io/construx/api:v1.8.3
# Pushing attestation to: registry.construx.io/construx/api

# Verify the SBOM attestation
cosign verify-attestation \
  --key cosign.pub \
  --type cyclonedx \
  registry.construx.io/construx/api:v1.8.3 \
  | jq '.payload | @base64d | fromjson | .predicate.components | length'
# 142  ← number of components in the SBOM

# Attach a vulnerability scan attestation
trivy image --format cosign-vuln --output vuln.json construx/api:v1.8.3

cosign attest \
  --key cosign.key \
  --type vuln \
  --predicate vuln.json \
  registry.construx.io/construx/api:v1.8.3

# Verify: image was scanned and has no CRITICAL CVEs
cosign verify-attestation \
  --key cosign.pub \
  --type vuln \
  registry.construx.io/construx/api:v1.8.3 \
  | jq '.payload | @base64d | fromjson | .predicate.scanner.result.Results[].Vulnerabilities
       | map(select(.Severity == "CRITICAL")) | length'
# 0  ← no critical CVEs at time of attestation

# Custom provenance attestation (SLSA build provenance)
cosign attest \
  --key cosign.key \
  --type slsaprovenance \
  --predicate provenance.json \
  registry.construx.io/construx/api:v1.8.3
```

## Admission controller enforcement

```yaml
# Kyverno: enforce that all pods in construx-prod run signed images

apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-signed-images
spec:
  validationFailureAction: Enforce
  background: false
  rules:
    - name: check-image-signature
      match:
        any:
          - resources:
              kinds: [Pod]
              namespaces: [construx-prod, construx-staging]
      verifyImages:
        - imageReferences:
            - "registry.construx.io/construx/*"
          mutateDigest: true   # replace tag with digest for immutability
          required: true
          attestors:
            - count: 1
              entries:
                - keys:
                    publicKeys: |-
                      -----BEGIN PUBLIC KEY-----
                      MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE...
                      -----END PUBLIC KEY-----

    # Require SBOM attestation for production images
    - name: require-sbom-attestation
      match:
        any:
          - resources:
              kinds: [Pod]
              namespaces: [construx-prod]
      verifyImages:
        - imageReferences:
            - "registry.construx.io/construx/*"
          attestations:
            - predicateType: https://cyclonedx.org/bom
              conditions:
                - all:
                    - key: "{{ components | length(@) }}"
                      operator: GreaterThan
                      value: 0   # SBOM must be non-empty
```

```bash
# Test: try to run an unsigned image in construx-prod
kubectl run test-unsigned \
  --image=nginx:latest \
  --namespace=construx-prod
# Error from server: admission webhook "mutate.kyverno.svc" denied the request:
# [require-signed-images] nginx:latest is not signed

# Only signed, attested images from the CI pipeline can run in production
```

Cosign vs Notary v2: Notary v2 (now Notation) is the OCI standard for image signing — it uses a different storage format (OCI referrers API) and is backed by CNCF. Cosign is Sigstore's tool and has broader adoption, simpler UX, and the keyless OIDC flow. Both store signatures in the registry. The Sigstore ecosystem (cosign + Rekor + Fulcio) provides the transparency log and OIDC-based signing infrastructure that makes keyless signing practical. For new projects, cosign + keyless is the lowest-friction path. Notation is the choice if you need strict OCI spec compliance or enterprise key management integration via plugins.
