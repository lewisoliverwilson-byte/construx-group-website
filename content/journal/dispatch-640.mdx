Kysely sits between raw SQL and an ORM. It has the control of SQL with the safety of TypeScript. The query builder is typed against your schema — a typo in a column name is a compile error, not a runtime failure.

## Schema types

```ts
// db/schema.ts — type your database tables
interface Database {
  users: {
    id:         string;
    email:      string;
    name:       string | null;
    active:     boolean;
    created_at: Date;
  };
  posts: {
    id:        string;
    title:     string;
    content:   string;
    status:    'draft' | 'published' | 'archived';
    author_id: string;
    created_at: Date;
  };
  post_tags: {
    post_id: string;
    tag_id:  string;
  };
  tags: {
    id:   string;
    name: string;
  };
}
```

## Connection

```ts
// db/index.ts
import { Kysely, PostgresDialect } from 'kysely';
import { Pool }                    from 'pg';
import type { Database }           from './schema';

export const db = new Kysely<Database>({
  dialect: new PostgresDialect({
    pool: new Pool({ connectionString: process.env.DATABASE_URL }),
  }),
});
```

## Queries

```ts
import { db } from '@/db';

// Select all
const users = await db.selectFrom('users').selectAll().execute();
// users: { id: string; email: string; name: string | null; active: boolean; created_at: Date }[]

// Select specific columns
const emails = await db
  .selectFrom('users')
  .select(['id', 'email'])
  .where('active', '=', true)
  .execute();
// emails: { id: string; email: string }[]

// With filter
const post = await db
  .selectFrom('posts')
  .selectAll()
  .where('id', '=', postId)
  .executeTakeFirst();
// post: { ... } | undefined

// Join
const postsWithAuthors = await db
  .selectFrom('posts')
  .innerJoin('users', 'users.id', 'posts.author_id')
  .select([
    'posts.id',
    'posts.title',
    'posts.status',
    'users.email as author_email',
    'users.name as author_name',
  ])
  .where('posts.status', '=', 'published')
  .orderBy('posts.created_at', 'desc')
  .limit(10)
  .execute();
```

## Mutations

```ts
// Insert
const [newPost] = await db
  .insertInto('posts')
  .values({
    id:        generateId(),
    title:     'New post',
    content:   'Content here',
    status:    'draft',
    author_id: userId,
  })
  .returningAll()
  .execute();

// Update
const updated = await db
  .updateTable('posts')
  .set({ status: 'published' })
  .where('id', '=', postId)
  .where('author_id', '=', userId)
  .returningAll()
  .executeTakeFirst();

// Delete
await db
  .deleteFrom('posts')
  .where('id', '=', postId)
  .execute();

// Upsert
await db
  .insertInto('post_tags')
  .values({ post_id: postId, tag_id: tagId })
  .onConflict((oc) => oc.columns(['post_id', 'tag_id']).doNothing())
  .execute();
```

## Transactions

```ts
const result = await db.transaction().execute(async (trx) => {
  const user = await trx
    .insertInto('users')
    .values({ id: generateId(), email, name })
    .returningAll()
    .executeTakeFirstOrThrow();

  await trx
    .insertInto('posts')
    .values({ id: generateId(), title: 'First post', content: 'Welcome!', status: 'published', author_id: user.id })
    .execute();

  return user;
});
```

`executeTakeFirstOrThrow()` throws if no row is returned — useful when you expect exactly one result.

## CTEs and subqueries

```ts
// CTE
const publishedCounts = await db
  .with('published', (db) =>
    db.selectFrom('posts')
      .select(['author_id', db.fn.count<number>('id').as('count')])
      .where('status', '=', 'published')
      .groupBy('author_id'),
  )
  .selectFrom('published')
  .innerJoin('users', 'users.id', 'published.author_id')
  .select(['users.email', 'published.count'])
  .orderBy('published.count', 'desc')
  .execute();

// Subquery in WHERE
const prolificAuthors = await db
  .selectFrom('users')
  .selectAll()
  .where('id', 'in',
    db.selectFrom('posts')
      .select('author_id')
      .where('status', '=', 'published')
      .groupBy('author_id')
      .having(db.fn.count('id'), '>', 5),
  )
  .execute();
```

## Raw expressions

```ts
import { sql } from 'kysely';

// Raw SQL fragment
const results = await db
  .selectFrom('posts')
  .select([
    'id',
    'title',
    sql<number>`char_length(content)`.as('content_length'),
    sql<string>`to_tsvector('english', title || ' ' || content)`.as('tsvec'),
  ])
  .execute();

// Raw WHERE clause
await db
  .selectFrom('posts')
  .selectAll()
  .where(sql`created_at > now() - interval '7 days'`)
  .execute();
```

## Kysely vs Drizzle

Both are type-safe SQL query builders. Kysely has a more SQL-like API — CTEs, window functions, and complex joins feel natural. Drizzle has closer integration with migration tooling and works better at the edge (Cloudflare Workers, Vercel Edge). Use Kysely when: you're writing complex queries and want the API to mirror SQL. Use Drizzle when: edge runtime support matters, or you want the schema definition and migration tooling in one place.
