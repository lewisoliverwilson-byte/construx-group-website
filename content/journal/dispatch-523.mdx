Next.js middleware runs on every request before the page renders. It's a single function in `middleware.ts` at the project root. Because it runs at the edge — at CDN nodes closest to the user — it's fast, but constrained: no Node.js APIs, no direct database access.

## The basic structure

```ts
// middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(req: NextRequest) {
  // Inspect: req.url, req.method, req.headers, req.cookies, req.nextUrl, req.geo
  // Mutate: return NextResponse.next(), redirect(), rewrite(), or a Response

  return NextResponse.next();
}

// Which paths middleware runs on
export const config = {
  matcher: [
    // Match everything except Next.js internals and static files
    '/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)',
  ],
};
```

The `matcher` controls which paths trigger the middleware. Skip static assets — running middleware on every PNG is wasteful.

## Auth gate with Clerk

```ts
// middleware.ts
import { clerkMiddleware, createRouteMatcher } from '@clerk/nextjs/server';

const isPublic = createRouteMatcher([
  '/',
  '/sign-in(.*)',
  '/sign-up(.*)',
  '/journal(.*)',
  '/ventures(.*)',
  '/api/webhooks(.*)',
  '/api/public(.*)',
]);

export default clerkMiddleware((auth, req) => {
  if (!isPublic(req)) {
    auth().protect();  // Redirect to /sign-in if not authenticated
  }
});

export const config = {
  matcher: ['/((?!_next|.*\\..*).*)'],
};
```

Clerk's middleware verifies the JWT at the edge — no database call. Unauthenticated requests to protected routes get redirected before the origin server sees them.

## Redirect rules

```ts
export function middleware(req: NextRequest) {
  const { pathname } = req.nextUrl;

  // Legacy URL redirect
  if (pathname.startsWith('/blog/')) {
    return NextResponse.redirect(
      new URL(pathname.replace('/blog/', '/journal/'), req.url),
      { status: 301 },
    );
  }

  // Maintenance mode
  if (process.env.MAINTENANCE_MODE === 'true' && pathname !== '/maintenance') {
    return NextResponse.redirect(new URL('/maintenance', req.url));
  }

  return NextResponse.next();
}
```

## Injecting headers

Headers set in middleware are available in Server Components via `headers()`:

```ts
import { headers } from 'next/headers';

// In middleware:
const res = NextResponse.next();
res.headers.set('x-user-country', req.geo?.country ?? 'unknown');
res.headers.set('x-pathname', req.nextUrl.pathname);
return res;

// In a Server Component:
const country  = headers().get('x-user-country');
const pathname = headers().get('x-pathname');
```

Useful for passing geolocation or routing context to Server Components without re-computing it there.

## Rate limiting at the edge

```ts
import { Ratelimit } from '@upstash/ratelimit';
import { Redis }     from '@upstash/redis/cloudflare';

const ratelimit = new Ratelimit({
  redis:   Redis.fromEnv(),
  limiter: Ratelimit.slidingWindow(30, '60s'),
});

export async function middleware(req: NextRequest) {
  // Only rate-limit API routes
  if (req.nextUrl.pathname.startsWith('/api/')) {
    const ip = req.ip ?? req.headers.get('x-forwarded-for') ?? '127.0.0.1';
    const { success, remaining } = await ratelimit.limit(ip);

    if (!success) {
      return new Response(
        JSON.stringify({ error: 'Too many requests' }),
        { status: 429, headers: { 'Content-Type': 'application/json' } },
      );
    }

    const res = NextResponse.next();
    res.headers.set('x-ratelimit-remaining', String(remaining));
    return res;
  }

  return NextResponse.next();
}
```

## Composing multiple concerns

When middleware does several things, compose with early returns:

```ts
export async function middleware(req: NextRequest) {
  const { pathname } = req.nextUrl;

  // 1. Redirects (fastest — no async)
  if (pathname.startsWith('/old-path')) {
    return NextResponse.redirect(new URL('/new-path', req.url), 301);
  }

  // 2. Auth (Clerk JWT verification — synchronous after initial load)
  if (isProtected(pathname)) {
    const { userId } = getAuth(req);
    if (!userId) return NextResponse.redirect(new URL('/sign-in', req.url));
  }

  // 3. Rate limiting (async — Upstash HTTP call)
  if (pathname.startsWith('/api/')) {
    const { success } = await ratelimit.limit(req.ip ?? 'anon');
    if (!success) return new Response('Rate limited', { status: 429 });
  }

  return NextResponse.next();
}
```

Order matters: cheap synchronous checks first, async calls last.

## What doesn't belong in middleware

- Database queries (no TCP, use HTTP-based clients only)
- Heavy computation
- Business logic that belongs in the route handler or Server Component
- Long-running processes (timeout: 30s on Vercel, shorter elsewhere)

Middleware is a filter, not a handler. Keep it focused on routing, auth, and rate limiting — anything that must run before the request reaches the origin.
