Scoutr's core output is a recommendation: buy or pass, with a confidence score from 0-100. The score is the interface between raw data (eBay fees, historical prices, sales velocity) and actionable human decisions.

Here's how the model works.

## The inputs

For any eBay listing, Scoutr gathers:

**Source price.** The retail price at the scanning location (input from the user).

**eBay sold price distribution.** The last 30-90 days of completed listings for the same or equivalent product. We pull this from eBay's sold listings search.

**Fee structure.** eBay's final value fee (category-dependent, typically 11-14%), PayPal processing (or Stripe if selling via eBay's managed payments), packing cost (user-configurable default), shipping estimate.

**Sales velocity.** How many units sold in the trailing 30 days? A product with 3 recent sales is different from one with 300.

**Listing saturation.** How many active listings exist for this product? A heavily-saturated listing category produces downward price pressure.

## The margin calculation

The core calculation is straightforward:

```ts
interface MarginCalc {
  sourcePrice: number;        // What we pay at the shop
  ebayFee: number;            // Percentage fee
  shippingCost: number;       // Estimated shipping out
  packingCost: number;        // Per-order packing
  targetSalePrice: number;    // p40 of sold price distribution
}

function calculateMargin(calc: MarginCalc): number {
  const { sourcePrice, ebayFee, shippingCost, packingCost, targetSalePrice } = calc;
  
  const fees = targetSalePrice * (ebayFee / 100);
  const totalCost = sourcePrice + shippingCost + packingCost + fees;
  const profit = targetSalePrice - totalCost;
  const margin = (profit / targetSalePrice) * 100;
  
  return Math.round(margin * 10) / 10; // One decimal
}
```

We use the p40 (40th percentile) of the sold price distribution, not the median. The reasoning: a seller competing in an existing market will price competitively to ensure sales — not at the maximum historical price. The p40 represents a conservative, achievable target price.

## From margin to confidence score

A positive margin isn't sufficient for a buy recommendation. A product with a 15% margin and 2 sales in 30 days is less attractive than a product with a 12% margin and 50 sales in 30 days. The confidence score encodes this.

The score is a weighted composite:

```ts
interface ScoringInputs {
  marginPct: number;          // Calculated profit margin %
  salesVelocity: number;      // Sales per 30 days
  listingSaturation: number;  // Active competing listings
  priceConsistency: number;   // Standard deviation / mean price (lower = more consistent)
  dataAge: number;            // Days since most recent sold listing
}

function calculateConfidence(inputs: ScoringInputs): number {
  const { marginPct, salesVelocity, listingSaturation, priceConsistency, dataAge } = inputs;

  // Margin component (0-40 points)
  const marginScore = Math.min(40, Math.max(0, marginPct * 2));

  // Velocity component (0-30 points) — log scale to avoid overweighting high-velocity items
  const velocityScore = Math.min(30, Math.log1p(salesVelocity) * 8);

  // Saturation penalty (0-15 points removed)
  const saturationPenalty = Math.min(15, listingSaturation * 0.5);

  // Price consistency component (0-20 points)
  // priceConsistency = stddev / mean; lower = more consistent = higher score
  const consistencyScore = Math.min(20, Math.max(0, 20 - (priceConsistency * 40)));

  // Data freshness penalty (0-10 points removed) — penalise old data
  const freshnessPenalty = Math.min(10, Math.max(0, (dataAge - 14) * 0.5));

  const raw = marginScore + velocityScore + consistencyScore - saturationPenalty - freshnessPenalty;
  return Math.round(Math.min(100, Math.max(0, raw)));
}
```

## The buy/pass threshold

The default threshold is 60. A confidence score ≥ 60 produces a buy recommendation; below 60, pass.

The threshold is user-configurable for professional users who want to adjust their risk tolerance. A conservative reseller might set 70; an aggressive one might set 50. The default is calibrated to a reasonable risk-reward balance for a typical eBay reseller.

## Handling uncertainty

The most important edge case: insufficient data. If a product has fewer than 3 sold listings in the trailing 90 days, we can't generate a reliable sold price distribution.

In this case, the model:
1. Flags the confidence score with a data insufficiency warning
2. Applies a maximum cap of 55 (below the buy threshold)
3. Displays the warning prominently in the result

This prevents a false buy signal on products with sparse data. A product with 1 sold listing at a great price might be an anomaly, not a repeatable opportunity.

## Calibration

How do we know the model is right? We compare predicted confidence scores against actual resell outcomes for users who report their results.

The pattern we track: of items scored 80-100, what percentage produce positive margin when sold? Of items scored 40-60, what percentage produce positive margin?

Current calibration:
- 80-100 confidence: 87% positive outcome rate
- 60-79 confidence: 71% positive outcome rate  
- 40-59 confidence: 48% positive outcome rate
- < 40 confidence: 24% positive outcome rate

The model is well-calibrated for high-confidence recommendations (87% accuracy above 80) and appropriately uncertain for mid-range ones. The sub-40 group performing at 24% is expected — these are marginal or losing picks.

## The roadmap

The current model is rule-based with carefully tuned weights. The next iteration: train a gradient-boosted model on the accumulated outcome data. With sufficient training data (we're approaching it), a learned model will outperform a hand-tuned rule-based one.

The hand-tuned model is interpretable: a user can understand why a product scored 72 by looking at the breakdown. A gradient-boosted model is less interpretable but more accurate. The tradeoff between interpretability and accuracy is one we'll manage by keeping the explanation layer even if the model underneath changes.
