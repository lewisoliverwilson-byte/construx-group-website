One binary. No plugins. Replaces ESLint and Prettier.

## Install

```bash
bun add -D @biomejs/biome
bunx @biomejs/biome init
```

  "formatter": {

## Scripts

```json
{
  "scripts": {
    "lint":        "biome lint ./src",
    "lint:fix":    "biome lint --write ./src",
    "format":      "biome format --write ./src",
    "check":       "biome check ./src",
    "check:ci":    "biome ci ./src"
  }
}
```

`biome check` runs lint + format check together. `biome ci` exits non-zero on any issue — use this in CI.

## CI integration

```yaml
# .github/workflows/ci.yml
- name: Biome check
  run: bunx biome ci --reporter=github .
  # --reporter=github annotates PRs with inline comments for each lint error
```

## Migrate from ESLint + Prettier

```bash
# Biome provides a migration command
bunx @biomejs/biome migrate eslint --write    # Reads .eslintrc, converts rules
bunx @biomejs/biome migrate prettier --write  # Reads .prettierrc, converts options

# Remove the old tools
bun remove eslint prettier @typescript-eslint/parser @typescript-eslint/eslint-plugin \
  eslint-config-next eslint-plugin-react prettier-plugin-tailwindcss
```

## Suppressing a specific rule

```ts
// biome-ignore lint/suspicious/noExplicitAny: third-party SDK types
function callLegacySDK(input: any): void {
  legacySDK.call(input);
}
```

Biome vs ESLint + Prettier: ESLint has a vastly larger plugin ecosystem — if you need airbnb, unicorn, or custom rules, ESLint is required. Biome covers the common cases fast. The Construx default: Biome for all new projects; ESLint only where a specific plugin is essential (e.g., eslint-plugin-react-hooks rules not yet in Biome).
