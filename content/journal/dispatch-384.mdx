Dark mode is table stakes in 2028. Users expect it. The failure mode is not implementing it at all, or implementing it with hardcoded color overrides that become unmaintainable. The correct architecture uses design tokens — CSS custom properties that swap at the theme level.

## Design tokens as CSS custom properties

```css
/* app/globals.css */
:root {
  /* Surfaces */
  --color-bg: #ffffff;
  --color-bg-subtle: #f8fafc;
  --color-bg-muted: #f1f5f9;

  /* Text */
  --color-text-primary: #0f172a;
  --color-text-secondary: #475569;
  --color-text-tertiary: #94a3b8;

  /* Borders */
  --color-border: #e2e8f0;
  --color-border-strong: #cbd5e1;

  /* Brand */
  --color-accent: #f97316;
  --color-accent-dim: rgba(249, 115, 22, 0.1);
}

[data-theme='dark'] {
  --color-bg: #000008;
  --color-bg-subtle: #0a0a1a;
  --color-bg-muted: rgba(255, 255, 255, 0.04);

  --color-text-primary: #f0efff;
  --color-text-secondary: rgba(240, 239, 255, 0.7);
  --color-text-tertiary: rgba(240, 239, 255, 0.35);

  --color-border: rgba(255, 255, 255, 0.08);
  --color-border-strong: rgba(255, 255, 255, 0.14);

  --color-accent: #f97316;
  --color-accent-dim: rgba(249, 115, 22, 0.12);
}

@media (prefers-color-scheme: dark) {
  :root:not([data-theme='light']) {
    /* Same as [data-theme='dark'] — system default */
    --color-bg: #000008;
    /* ... etc */
  }
}
```

Now every component uses the tokens, not hardcoded values:

```tsx
// Before: hardcoded — breaks in dark mode
<div className="bg-white text-gray-900">

// After: token-driven — works in both themes
<div style={{ background: 'var(--color-bg)', color: 'var(--color-text-primary)' }}>
```

## Tailwind integration with CSS variables

```ts
// tailwind.config.ts
import type { Config } from 'tailwindcss';

export default {
  content: ['./app/**/*.{ts,tsx}', './components/**/*.{ts,tsx}'],
  darkMode: ['selector', '[data-theme="dark"]'],  // or 'class' for Tailwind v3
  theme: {
    extend: {
      colors: {
        bg: 'var(--color-bg)',
        'bg-subtle': 'var(--color-bg-subtle)',
        'text-primary': 'var(--color-text-primary)',
        'text-secondary': 'var(--color-text-secondary)',
        border: 'var(--color-border)',
        accent: 'var(--color-accent)',
      },
    },
  },
} satisfies Config;
```

```tsx
// Now Tailwind classes use the tokens
<div className="bg-bg text-text-primary border border-border">
  <p className="text-text-secondary">Hello</p>
</div>

// And dark mode variants work automatically
<button className="bg-white dark:bg-bg-subtle">
```

## System preference detection with user override

```tsx
// components/ThemeProvider.tsx
'use client';

import { createContext, useContext, useEffect, useState } from 'react';

type Theme = 'light' | 'dark' | 'system';

const ThemeContext = createContext<{
  theme: Theme;
  resolvedTheme: 'light' | 'dark';
  setTheme: (theme: Theme) => void;
}>({ theme: 'system', resolvedTheme: 'dark', setTheme: () => {} });

export function ThemeProvider({ children }: { children: React.ReactNode }) {
  const [theme, setThemeState] = useState<Theme>('system');
  const [resolvedTheme, setResolvedTheme] = useState<'light' | 'dark'>('dark');

  useEffect(() => {
    // Read from localStorage on mount
    const stored = localStorage.getItem('theme') as Theme | null;
    if (stored) setThemeState(stored);
  }, []);

  useEffect(() => {
    const mediaQuery = window.matchMedia('(prefers-color-scheme: dark)');
    const systemTheme = mediaQuery.matches ? 'dark' : 'light';

    const resolved = theme === 'system' ? systemTheme : theme;
    setResolvedTheme(resolved);
    document.documentElement.setAttribute('data-theme', resolved);

    // Listen for system preference changes
    const handler = (e: MediaQueryListEvent) => {
      if (theme === 'system') {
        const newResolved = e.matches ? 'dark' : 'light';
        setResolvedTheme(newResolved);
        document.documentElement.setAttribute('data-theme', newResolved);
      }
    };

    mediaQuery.addEventListener('change', handler);
    return () => mediaQuery.removeEventListener('change', handler);
  }, [theme]);

  const setTheme = (newTheme: Theme) => {
    setThemeState(newTheme);
    localStorage.setItem('theme', newTheme);
  };

  return (
    <ThemeContext.Provider value={{ theme, resolvedTheme, setTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

export const useTheme = () => useContext(ThemeContext);
```

```tsx
// components/ThemeToggle.tsx
function ThemeToggle() {
  const { theme, setTheme } = useTheme();
  const options: Theme[] = ['light', 'dark', 'system'];

  return (
    <div className="flex items-center gap-1">
      {options.map((opt) => (
        <button
          key={opt}
          onClick={() => setTheme(opt)}
          className={`px-2 py-1 font-mono text-[9px] uppercase tracking-widest transition-colors ${
            theme === opt ? 'text-accent' : 'text-text-secondary hover:text-text-primary'
          }`}
        >
          {opt}
        </button>
      ))}
    </div>
  );
}
```

## Avoiding flash of wrong theme

Without server-side theme detection, the page renders in the default theme for a frame before JavaScript runs and applies the correct theme. Fix with an inline script:

```tsx
// app/layout.tsx
<head>
  <script
    dangerouslySetInnerHTML={{
      __html: `
        (function() {
          try {
            var stored = localStorage.getItem('theme');
            var system = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
            var theme = stored || 'system';
            document.documentElement.setAttribute('data-theme', theme === 'system' ? system : theme);
          } catch (e) {}
        })();
      `,
    }}
  />
</head>
```

This script runs before anything renders, so there's no flash.

## Contrast traps in dark mode

The two most common dark mode contrast failures:

**1. Inverted contrast on images and icons**: a dark image on a white background becomes a white image on a near-black background — high contrast. But a light-colored illustration on a dark background can look washed out. Use `filter: brightness(0.8)` on images that appear in dark mode if needed.

**2. Insufficient contrast on secondary text**: gray text on white might be fine at 4.8:1 contrast, but the same gray on a dark background at `rgba(240,239,255,0.35)` might fail WCAG at dark backgrounds. Check every text color in both themes with Chrome DevTools or axe.

**3. Shadows**: `box-shadow` with dark colors disappears on dark backgrounds. Use a lighter, more transparent shadow in dark mode, or use `border` instead for elevation cues.

The rule: define tokens first, build with tokens always. Never patch dark mode with overrides.
