The traditional pattern: wait for all data, then render the full page. The problem: one slow database query holds the entire page hostage. Suspense breaks this by letting fast parts stream immediately while slow parts show a fallback until they're ready.

## The basic pattern

```tsx
// app/dashboard/page.tsx
import { Suspense } from 'react';
import { UserGreeting } from './UserGreeting';
import { RecentScans } from './RecentScans';
import { ScanResultsSkeleton } from './skeletons';

export default function DashboardPage() {
  return (
    <div>
      {/* Fast: no data needed, renders immediately */}
      <UserGreeting />

      {/* Slow: waits for DB query — shows skeleton until ready */}
      <Suspense fallback={<ScanResultsSkeleton />}>
        <RecentScans />
      </Suspense>
    </div>
  );
}
```

```tsx
// app/dashboard/RecentScans.tsx — Server Component
import { db } from '@/lib/db';

export async function RecentScans() {
  // This query can take as long as it needs — the rest of the page is already streaming
  const scans = await db.query.scans.findMany({
    orderBy: (s, { desc }) => desc(s.createdAt),
    limit: 10,
    with: { product: true },
  });

  return (
    <ul>
      {scans.map((scan) => (
        <li key={scan.id}>{scan.product.title} — {scan.alertLevel}</li>
      ))}
    </ul>
  );
}
```

The browser receives the HTML for `UserGreeting` immediately. When `RecentScans` finishes, its HTML streams in and replaces the skeleton — without a client-side re-fetch.

## Parallel data fetching

Multiple `Suspense` boundaries run in parallel:

```tsx
// app/dashboard/page.tsx
export default function DashboardPage() {
  return (
    <div className="grid grid-cols-2 gap-6">
      {/* These three queries run in parallel — no waterfall */}
      <Suspense fallback={<StatsSkeleton />}>
        <ScanStats />
      </Suspense>

      <Suspense fallback={<AlertsSkeleton />}>
        <RecentAlerts />
      </Suspense>

      <Suspense fallback={<ActivitySkeleton />}>
        <ActivityFeed />
      </Suspense>
    </div>
  );
}
```

Without Suspense, these would be sequential: page waits for all three. With three `Suspense` boundaries, each section streams independently as soon as its data arrives.

## Avoid data waterfalls

A waterfall happens when Server Components fetch sequentially instead of in parallel:

```tsx
// ✗ WATERFALL — waits 300ms, then 200ms, then 150ms = 650ms total
async function Dashboard() {
  const user = await getUser();           // 300ms
  const scans = await getScans(user.id); // 200ms — waits for user
  const alerts = await getAlerts(user.id); // 150ms — waits for scans
}

// ✓ PARALLEL — all fire at once, resolves in 300ms total
async function Dashboard() {
  const [user, scans, alerts] = await Promise.all([
    getUser(),
    getScans(),
    getAlerts(),
  ]);
}
```

When one piece of data depends on another, that waterfall is unavoidable — but only fetch the dependency first, then fire everything else in parallel.

## Loading UI with loading.tsx

Next.js has a file-based convention for Suspense boundaries:

```
app/
  dashboard/
    page.tsx        ← the real content
    loading.tsx     ← automatic Suspense fallback for the whole page
    layout.tsx
```

```tsx
// app/dashboard/loading.tsx
export default function DashboardLoading() {
  return (
    <div className="space-y-4">
      <div className="h-8 w-48 bg-zinc-800 animate-pulse rounded" />
      <div className="h-64 bg-zinc-800 animate-pulse rounded" />
    </div>
  );
}
```

`loading.tsx` wraps the entire `page.tsx` in a `Suspense` boundary automatically. Use it for coarse loading states, and explicit `<Suspense>` wrappers for fine-grained streaming within a page.

## Skeleton components

```tsx
// components/skeletons/ScanResultsSkeleton.tsx
export function ScanResultsSkeleton() {
  return (
    <div className="space-y-3">
      {Array.from({ length: 5 }).map((_, i) => (
        <div key={i} className="flex items-center gap-3">
          <div
            className="h-4 bg-zinc-800 animate-pulse rounded"
            style={{ width: `${60 + (i % 3) * 15}%`, animationDelay: `${i * 100}ms` }}
          />
          <div className="h-4 w-16 bg-zinc-800 animate-pulse rounded" />
        </div>
      ))}
    </div>
  );
}
```

Stagger the animation delays — skeletons that pulse in sequence feel more natural than synchronised ones.

## Error boundaries

Pair `Suspense` with error handling:

```tsx
'use client';

import { ErrorBoundary } from 'react-error-boundary';
import { Suspense } from 'react';

function ScanErrorFallback({ error, resetErrorBoundary }: { error: Error; resetErrorBoundary: () => void }) {
  return (
    <div className="p-4 border border-red-900/30 rounded text-sm text-red-400">
      <p>Failed to load scans: {error.message}</p>
      <button onClick={resetErrorBoundary} className="mt-2 underline">
        Retry
      </button>
    </div>
  );
}

export function ScanResultsWithBoundary() {
  return (
    <ErrorBoundary FallbackComponent={ScanErrorFallback}>
      <Suspense fallback={<ScanResultsSkeleton />}>
        <RecentScans />
      </Suspense>
    </ErrorBoundary>
  );
}
```

Without an error boundary, an error in `RecentScans` bubbles up and crashes the nearest `Suspense` ancestor — which might be the entire page. Wrap each critical section in its own `ErrorBoundary` so failures are contained.

## The impact

With Suspense streaming, Time to First Byte (TTFB) stays low — the initial HTML is small and fast. The page becomes interactive in sections as data arrives. Users see something meaningful within milliseconds, rather than waiting for the slowest query before seeing anything.
