Web scraping with Playwright is qualitatively different from scraping with Cheerio or curl. Playwright runs a real browser — JavaScript executes, SPAs render, lazy-loaded content appears. The cost is speed and resource usage; the gain is access to any site that renders in a browser.

## Project setup

```bash
npm install playwright
npx playwright install chromium
```

```ts
// scraper/index.ts
import { chromium, Browser, BrowserContext } from 'playwright';
```

## The browser context pattern

Reuse browser contexts across requests. Creating a new browser instance per request is the most common performance mistake:

```ts
// Bad: new browser per scrape
async function scrapeProduct(url: string) {
  const browser = await chromium.launch();
  const page = await browser.newPage();
  // ... scrape
  await browser.close();
}

// Good: reuse browser, create context per logical session
class Scraper {
  private browser: Browser | null = null;

  async getBrowser(): Promise<Browser> {
    if (!this.browser) {
      this.browser = await chromium.launch({ headless: true });
    }
    return this.browser;
  }

  async scrapeProduct(url: string): Promise<Product> {
    const browser = await this.getBrowser();
    const context = await browser.newContext({
      userAgent: 'Mozilla/5.0 (compatible; MarqetBot/1.0)',
      viewport:  { width: 1280, height: 720 },
    });
    const page = await context.newPage();

    try {
      await page.goto(url, { waitUntil: 'networkidle', timeout: 30000 });
      return this.extract(page);
    } finally {
      await context.close(); // always clean up the context
    }
  }
}
```

A browser context is like an incognito window — isolated cookies, storage, and cache. Create one per logical scraping session, close it when done.

## Selectors that survive site updates

CSS selectors tied to class names break when the site updates:

```ts
// Fragile: relies on obfuscated class name
await page.$('.product-details--a9kL3 .price--2mN8d');

// Better: semantic selectors
await page.getByTestId('product-price');

// Better: accessible role selectors
await page.getByRole('heading', { name: /price/i });

// Better: text-based with context
await page.locator('section:has-text("Price") >> span.amount');

// Better: XPath for data attributes
await page.locator('[data-product-price]');
```

Prefer data attributes, accessible roles, and text-based selectors over class names. Class names are implementation details; data attributes and roles are intentional.

## Structured extraction

```ts
async function extractProduct(page: Page): Promise<Product | null> {
  try {
    const name = await page.locator('h1[data-product-name]').textContent({ timeout: 5000 });
    if (!name) return null;

    const priceText = await page.locator('[data-price]').textContent();
    const price     = parsePriceText(priceText ?? '');

    const available = await page.locator('[data-availability]').getAttribute('data-value');

    return {
      name:      name.trim(),
      price,
      available: available === 'in-stock',
      scrapedAt: new Date(),
      url:       page.url(),
    };
  } catch (err) {
    console.error('Extraction failed:', err);
    return null;
  }
}

function parsePriceText(text: string): number | null {
  const match = text.match(/[\d,]+\.?\d*/);
  if (!match) return null;
  return parseFloat(match[0].replace(',', ''));
}
```

Always handle null — selectors may not find elements if the page structure changes. Return `null` rather than throwing so the scraper can continue with other products.

## Rate limiting and retry logic

```ts
import pLimit from 'p-limit';
import pRetry from 'p-retry';

const limit = pLimit(3); // max 3 concurrent scrapes

async function scrapeWithRetry(url: string): Promise<Product | null> {
  return pRetry(
    () => limit(() => scraper.scrapeProduct(url)),
    {
      retries: 3,
      onFailedAttempt: (error) => {
        console.log(`Attempt ${error.attemptNumber} failed. ${error.retriesLeft} retries left.`);
        // wait between retries
      },
      minTimeout:       1000,
      factor:           2,       // exponential backoff
    },
  );
}

// Add delay between batches
async function delay(ms: number) {
  return new Promise(resolve => setTimeout(resolve, ms));
}

for (const batch of chunks(urls, 10)) {
  await Promise.all(batch.map(url => scrapeWithRetry(url)));
  await delay(2000); // 2 seconds between batches
}
```

Rate limiting is as much about being a good citizen as about avoiding blocks. Hammering a server at full speed causes real harm and gets your IP banned. Three concurrent requests with backoff is a reasonable default.

## Handling blocks and bot detection

Some sites actively detect scrapers:

```ts
const context = await browser.newContext({
  // Rotate user agents
  userAgent: randomUserAgent(),
  // Include typical browser headers
  extraHTTPHeaders: {
    'Accept-Language': 'en-GB,en;q=0.9',
    'Accept-Encoding': 'gzip, deflate, br',
  },
});

// Disable automation detection flags
await context.addInitScript(() => {
  Object.defineProperty(navigator, 'webdriver', { get: () => false });
});
```

For heavily protected sites, consider a residential proxy service (Bright Data, Oxylabs). Datacenter IPs are often blocked; residential IPs are much harder to detect.

## The Marqet scraper architecture

The Marqet monitors ~170 product listings across multiple retailers. The scraper runs in a cron job every 6 hours:

1. Load all active product URLs from Postgres
2. Chunk into batches of 10
3. Scrape each batch with 3 concurrent workers and 2-second inter-batch delay
4. Write results to a `price_snapshots` table
5. Compare with previous snapshot, flag significant changes

```ts
// The data model
const priceSnapshots = pgTable('price_snapshots', {
  id:         text('id').primaryKey().default(sql`gen_random_uuid()`),
  productId:  text('product_id').references(() => products.id),
  price:      numeric('price', { precision: 10, scale: 2 }),
  available:  boolean('available'),
  scrapedAt:  timestamp('scraped_at').defaultNow(),
});
```

Keeping a full history of price snapshots enables price history charts, drop alerts, and trend analysis — features that require the historical data even if you only show the current price.
