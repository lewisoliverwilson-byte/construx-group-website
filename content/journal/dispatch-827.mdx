excerpt: "Packer automates the creation of machine images. You define a base OS, a list of provisioners (shell scripts, Ansible playbooks), and the target image format (AWS AMI, GCE image, Docker image). Packer launches an instance, runs the provisioners, takes a snapshot, and terminates the instance. The resulting image is immutable — deploys replace instances, not update them. This eliminates configuration drift between instances."

Bake once. Deploy everywhere. No configuration drift.

## HCL template

```hcl
# construx-api.pkr.hcl
packer {
  required_plugins {
    amazon = {
      version = ">= 1.3.3"
      source  = "github.com/hashicorp/amazon"
    }
    ansible = {
      version = ">= 1.1.2"
      source  = "github.com/hashicorp/ansible"
    }
  }
}

variable "aws_region"     { type = string default = "eu-west-1" }
variable "instance_type"  { type = string default = "t3.medium" }
variable "ami_name_prefix" { type = string default = "construx-api" }

locals {
  timestamp = formatdate("YYYY-MM-DD'T'hh:mm:ssZ", timestamp())
  ami_name  = "${var.ami_name_prefix}-${local.timestamp}"
}

source "amazon-ebs" "construx-api" {
  region        = var.aws_region
  instance_type = var.instance_type

  source_ami_filter {
    filters = {
      name                = "ubuntu/images/hvm-ssd/ubuntu-noble-24.04-amd64-server-*"
      root-device-type    = "ebs"
      virtualization-type = "hvm"
    }
    owners      = ["099720109477"]  # Canonical
    most_recent = true
  }

  ami_name        = local.ami_name
  ami_description = "Construx API server — Ubuntu 24.04, Bun, Caddy, systemd"

  ami_regions = ["eu-west-1", "us-east-1"]

  tags = {
    Name        = local.ami_name
    Environment = "production"
    BuildDate   = local.timestamp
    ManagedBy   = "packer"
  }
}

build {
  name    = "construx-api"
  sources = ["source.amazon-ebs.construx-api"]

  provisioner "shell" {
    script = "scripts/install.sh"
  }

  provisioner "ansible" {
    playbook_file = "ansible/hardening.yml"
    extra_arguments = ["--extra-vars", "ansible_become_pass=''"]
  }

  provisioner "shell" {
    script = "scripts/configure.sh"
  }

  post-processor "manifest" {
    output = "manifest.json"
  }
}
```

## Install script

```bash
#!/bin/bash
# scripts/install.sh
set -euo pipefail

# Wait for apt to be available
while fuser /var/lib/dpkg/lock-frontend >/dev/null 2>&1; do sleep 1; done

apt-get update -q
apt-get install -yq curl unzip git jq awscli

# Install Bun
curl -fsSL https://bun.sh/install | BUN_INSTALL=/usr/local bash
ln -s /usr/local/bin/bun /usr/bin/bun

# Install Caddy
apt-get install -yq debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/caddy-stable-archive-keyring.gpg] https://dl.cloudsmith.io/public/caddy/stable/deb/debian any-version main" > /etc/apt/sources.list.d/caddy-stable.list
apt-get update && apt-get install -yq caddy

echo "✓ system packages installed"
```

## Build and deploy workflow

```bash
# Build the AMI (takes ~5 minutes)
packer build -var-file=prod.pkrvars.hcl construx-api.pkr.hcl

# Read the new AMI ID from the manifest
NEW_AMI=$(cat manifest.json | jq -r '.builds[-1].artifact_id' | cut -d: -f2)
echo "New AMI: $NEW_AMI"

# Update the launch template to use the new AMI
aws ec2 create-launch-template-version \
  --launch-template-name construx-api \
  --source-version '$Latest' \
  --launch-template-data "{\"ImageId\":\"$NEW_AMI\"}"

# Trigger a rolling update of the Auto Scaling Group
aws autoscaling start-instance-refresh \
  --auto-scaling-group-name construx-api-asg \
  --preferences '{"MinHealthyPercentage":90,"InstanceWarmup":60}'
```

## CI/CD pipeline integration

```yaml
# .github/workflows/build-ami.yml
on:
  push:
    branches: [master]
    paths:
      - 'infra/**'
      - 'scripts/**'
      - 'ansible/**'

jobs:
  build-ami:
    runs-on: ubuntu-latest
    permissions:
      id-token: write  # For OIDC AWS auth
    steps:
      - uses: actions/checkout@v4

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::123456789012:role/packer-role
          aws-region: eu-west-1

      - name: Setup Packer
        uses: hashicorp/setup-packer@v3
        with:
          version: '1.11.2'

      - name: Build AMI
        run: packer build -var-file=prod.pkrvars.hcl construx-api.pkr.hcl

      - name: Deploy to Auto Scaling Group
        run: |
          NEW_AMI=$(cat manifest.json | jq -r '.builds[-1].artifact_id' | cut -d: -f2)
          aws ec2 create-launch-template-version ...
          aws autoscaling start-instance-refresh ...
```

Packer + ASG rolling updates vs Docker: Docker gives you faster image builds and more portable images. Packer AMIs boot faster (no container runtime layer), have lower attack surface (no Docker daemon), and work directly with AWS EC2 Auto Scaling Groups. The Construx default: Docker for services where portability matters; Packer for stateful services or when the EC2 AMI lifecycle fits the deployment model.
