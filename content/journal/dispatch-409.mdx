TypeScript's utility types are type-level functions. They take a type as input and return a new type. The goal: stop redefining shapes that already exist in your codebase.

## The foundational ones

**`Partial<T>`** — makes all properties optional:

```ts
type User = { id: string; name: string; email: string; role: 'admin' | 'user' };

type UserUpdate = Partial<User>;
// { id?: string; name?: string; email?: string; role?: 'admin' | 'user' }

async function updateUser(id: string, updates: Partial<User>) {
  return db.update(users).set(updates).where(eq(users.id, id));
}
```

**`Required<T>`** — opposite of Partial. Makes all properties required:

```ts
type Config = { timeout?: number; retries?: number; baseUrl?: string };

// Config validated at startup — all fields must be present
type ResolvedConfig = Required<Config>;
```

**`Pick<T, K>`** — keeps only the listed keys:

```ts
type UserPreview = Pick<User, 'id' | 'name'>;
// { id: string; name: string }

// Useful for API responses — expose only what the client needs
function getPublicProfile(user: User): Pick<User, 'id' | 'name'> {
  return { id: user.id, name: user.name };
}
```

**`Omit<T, K>`** — removes the listed keys:

```ts
type CreateUserInput = Omit<User, 'id'>;
// { name: string; email: string; role: 'admin' | 'user' }

// New users don't have an ID yet — DB generates it
async function createUser(input: CreateUserInput) {
  return db.insert(users).values(input).returning();
}
```

## Record

`Record<K, V>` — creates an object type with keys `K` and values `V`:

```ts
// Map of status to display label
const statusLabels: Record<'active' | 'suspended' | 'churned', string> = {
  active: 'Active',
  suspended: 'Suspended',
  churned: 'Churned',
};

// If you add a status, TypeScript will require a label for it
type Status = 'active' | 'suspended' | 'churned' | 'trial';
const labels: Record<Status, string> = {
  active: 'Active',
  suspended: 'Suspended',
  churned: 'Churned',
  trial: 'Trial',  // required — TS errors if missing
};
```

## Extract and Exclude

These filter union types:

```ts
type Events = 'click' | 'focus' | 'blur' | 'keydown' | 'keyup';

// Keep only keyboard events
type KeyboardEvents = Extract<Events, 'keydown' | 'keyup'>;
// 'keydown' | 'keyup'

// Remove keyboard events
type MouseEvents = Exclude<Events, 'keydown' | 'keyup'>;
// 'click' | 'focus' | 'blur'
```

More practically, with object types:

```ts
type ApiResponse =
  | { status: 'success'; data: User[] }
  | { status: 'error'; message: string }
  | { status: 'loading' };

type SuccessResponse = Extract<ApiResponse, { status: 'success' }>;
// { status: 'success'; data: User[] }
```

## ReturnType and Parameters

Extract the return type or parameter types of a function:

```ts
async function getUser(id: string) {
  return db.query.users.findFirst({ where: eq(users.id, id) });
}

type UserResult = Awaited<ReturnType<typeof getUser>>;
// typeof db.query.users.findFirst result — inferred automatically

// Useful when you can't import the type directly
type GetUserParams = Parameters<typeof getUser>;
// [id: string]
```

## Awaited

Unwrap a Promise type:

```ts
type UserPromise = Promise<User>;
type ResolvedUser = Awaited<UserPromise>;
// User

// Useful with ReturnType for async functions
type FetchResult = Awaited<ReturnType<typeof fetch>>;
// Response
```

## NonNullable

Removes `null` and `undefined` from a union:

```ts
type MaybeUser = User | null | undefined;
type DefiniteUser = NonNullable<MaybeUser>;
// User

// Useful after a null check
function process(user: User | null) {
  if (!user) return;
  // user is User here, but if you need the type explicitly:
  const definite: NonNullable<typeof user> = user;
}
```

## Readonly

Prevents mutation — useful for config objects and constants:

```ts
const PLAN_LIMITS = {
  starter: { seats: 3, storage: '5GB' },
  pro: { seats: 20, storage: '50GB' },
  enterprise: { seats: Infinity, storage: 'Unlimited' },
} as const;  // more restrictive than Readonly

type PlanLimits = Readonly<typeof PLAN_LIMITS>;
```

## Building your own

Utility types compose. A common pattern: `DeepPartial` for nested optional updates:

```ts
type DeepPartial<T> = T extends object
  ? { [P in keyof T]?: DeepPartial<T[P]> }
  : T;

type Settings = {
  theme: { color: string; font: string };
  notifications: { email: boolean; push: boolean };
};

type SettingsUpdate = DeepPartial<Settings>;
// { theme?: { color?: string; font?: string }; notifications?: { ... } }
```

Or `OptionalExcept` — required on some keys, optional on the rest:

```ts
type OptionalExcept<T, K extends keyof T> = Required<Pick<T, K>> & Partial<Omit<T, K>>;

// User where email is required, everything else optional
type UserWithEmail = OptionalExcept<User, 'email'>;
// { email: string; id?: string; name?: string; role?: ... }
```

The principle: type definitions are code. Utility types let you derive types from existing ones instead of keeping two copies in sync.
