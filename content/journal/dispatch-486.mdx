Content Security Policy is a browser security feature that limits what resources your page can load. Without CSP, an XSS vulnerability lets an attacker run arbitrary JavaScript — stealing session tokens, making requests on behalf of the user, or redirecting to phishing pages. With a tight CSP, the injected script has nowhere to run.

## The header

```http
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-{RANDOM}';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:;
  font-src 'self';
  connect-src 'self' https://api.posthog.com https://us.i.posthog.com;
  media-src 'none';
  object-src 'none';
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self';
  upgrade-insecure-requests;
```

Each directive restricts a resource type:
- `default-src 'self'` — fallback: only load from same origin
- `script-src 'nonce-{RANDOM}'` — scripts must have a matching nonce attribute
- `style-src 'unsafe-inline'` — Tailwind requires inline styles (or use nonces)
- `img-src https:` — images can load from any HTTPS source (for product images)
- `object-src 'none'` — no Flash or plugins
- `frame-ancestors 'none'` — page cannot be embedded in iframes (clickjacking prevention)

## Nonce-based scripts in Next.js

Nonces are the secure way to allow inline scripts and specific external scripts. Each request gets a unique nonce — the CSP includes it, and every allowed script tag must have `nonce=` matching it.

```ts
// middleware.ts
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  const nonce = Buffer.from(crypto.randomUUID()).toString('base64');

  const csp = [
    `default-src 'self'`,
    `script-src 'self' 'nonce-${nonce}' 'strict-dynamic'`,
    `style-src 'self' 'unsafe-inline'`,
    `img-src 'self' data: https:`,
    `font-src 'self'`,
    `connect-src 'self' https://api.posthog.com https://us.i.posthog.com`,
    `object-src 'none'`,
    `frame-ancestors 'none'`,
    `base-uri 'self'`,
    `form-action 'self'`,
    `upgrade-insecure-requests`,
  ].join('; ');

  const response = NextResponse.next({
    request: {
      headers: new Headers({
        ...Object.fromEntries(request.headers.entries()),
        'x-nonce': nonce,
      }),
    },
  });

  response.headers.set('Content-Security-Policy', csp);
  return response;
}
```

```tsx
// app/layout.tsx — read the nonce from headers
import { headers } from 'next/headers';
import Script from 'next/script';

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  const nonce = (await headers()).get('x-nonce') ?? '';

  return (
    <html>
      <head>
        {/* Analytics script — requires nonce */}
        <Script
          src="https://eu-assets.i.posthog.com/static/chunk.js"
          nonce={nonce}
          strategy="afterInteractive"
        />
      </head>
      <body>{children}</body>
    </html>
  );
}
```

## Report-Only mode for testing

Deploy CSP in report-only mode first — violations are logged but not blocked:

```http
Content-Security-Policy-Report-Only:
  default-src 'self';
  script-src 'self' 'nonce-{NONCE}';
  report-uri /api/csp-report;
```

```ts
// app/api/csp-report/route.ts
export async function POST(req: Request) {
  const report = await req.json();
  console.error('CSP violation:', report['csp-report']);
  // Or send to your logging service
  return new Response(null, { status: 204 });
}
```

Run in report-only mode for a week, fix all violations, then switch to enforcing mode.

## Common violations and fixes

**Inline event handlers** — remove `onclick="..."` attributes, use `addEventListener` instead.

**Inline styles from libraries** — either allow `'unsafe-inline'` for styles (less ideal but common), or ensure the library supports nonces.

**External scripts** — add the domain to `script-src`, or load via `<Script nonce={nonce}>`.

**Data URIs for images** — add `data:` to `img-src` (already included in the header above).

**Third-party iframes** — add the domain to `frame-src`, or remove the embed.

## Additional security headers

CSP is one of several security headers to set:

```ts
// middleware.ts — full security header set
response.headers.set('Content-Security-Policy', csp);
response.headers.set('X-Frame-Options', 'DENY');
response.headers.set('X-Content-Type-Options', 'nosniff');
response.headers.set('Referrer-Policy', 'strict-origin-when-cross-origin');
response.headers.set('Permissions-Policy', 'camera=(), microphone=(), geolocation=()');
response.headers.set(
  'Strict-Transport-Security',
  'max-age=63072000; includeSubDomains; preload',
);
```

`Strict-Transport-Security` (HSTS) prevents downgrade attacks — once a browser has seen this header, it will only connect over HTTPS for the specified duration. Submit to the [HSTS preload list](https://hstspreload.org) to have your domain hardcoded into browsers.

## Auditing with securityheaders.com

After deploying, check `https://securityheaders.com/?q=construxgroup.io` for a score and specific recommendations. An A+ rating means the common attack vectors are covered. The gap between "we deployed a CSP" and "we deployed a CSP correctly" is wider than it looks.
