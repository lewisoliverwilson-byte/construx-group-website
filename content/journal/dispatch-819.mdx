TLS by default. Two-line reverse proxy. No certificate management.

## Caddyfile — basic reverse proxy

```caddy
# Caddyfile
construxgroup.io {
  reverse_proxy localhost:3000
}

api.construxgroup.io {
  reverse_proxy localhost:4000 {
    header_up Host {upstream_hostport}
    transport http {
      tls
    }
  }
}
```

Caddy automatically:
- Obtains a TLS certificate from Let's Encrypt for both domains
- Redirects HTTP to HTTPS
- Renews certificates before they expire
- Enables HTTP/2 and HTTP/3

## Headers and security

```caddy
construxgroup.io {
  reverse_proxy localhost:3000

  header {
    Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
    X-Content-Type-Options    "nosniff"
    X-Frame-Options           "DENY"
    Referrer-Policy           "strict-origin-when-cross-origin"
    Permissions-Policy        "camera=(), microphone=(), geolocation=()"
    -Server                   # Remove Server header
  }

  encode zstd gzip
}
```

## Rate limiting (Caddy module)

```caddy
construxgroup.io {
  route /api/* {
    rate_limit {
      zone api {
        key    {remote_host}
        events 100
        window 1m
      }
    }
    reverse_proxy localhost:4000
  }
}
```

## File server with SPA fallback

```caddy
static.construxgroup.io {
  root * /var/www/static
  file_server

  # SPA fallback — serve index.html for unknown paths
  try_files {path} /index.html
}
```

## Access log — structured JSON

```caddy
{
  log {
    format json
    output file /var/log/caddy/access.log {
      roll_size     100mb
      roll_keep     10
      roll_keep_for 720h
    }
  }
}
```

## Docker deployment

```yaml
# docker-compose.yaml
services:
  caddy:
    image: caddy:2.9-alpine
    restart: always
    ports:
      - '80:80'
      - '443:443'
      - '443:443/udp'  # HTTP/3 (QUIC)
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy-data:/data      # Certificate storage
      - caddy-config:/config  # Caddy config cache

  web:
    image: construx/web:latest
    expose: ['3000']

  api:
    image: construx/api:latest
    expose: ['4000']
```

## Wildcard certificates (Cloudflare DNS challenge)

```caddy
{
  acme_dns cloudflare {env.CF_API_TOKEN}
}

*.construxgroup.io {
  @api host api.construxgroup.io
  handle @api { reverse_proxy localhost:4000 }

  @app host app.construxgroup.io
  handle @app { reverse_proxy localhost:3000 }
}
```

Caddy vs Nginx: Nginx has more configuration options, a larger plugin ecosystem, and handles very high-traffic scenarios with more tuning. Caddy requires zero TLS configuration — the default is correct. For most projects, Caddy's defaults are better than Nginx's manual configuration. The Construx default: Caddy for all VPS deployments where TLS automation matters; Nginx only when an existing Nginx config or specific module is required.
