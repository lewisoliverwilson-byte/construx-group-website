Documents are stored as JSON in indices, sharded across nodes for scale and replicated for fault tolerance. Elasticsearch 8.x added dense vector search (k-NN) natively, making it a unified store for traditional keyword search and embedding-based semantic search. ## Query DSL — full-text search and filtering

```json
// Multi-match query: search across multiple fields
GET /journal/_search
{
  "query": {
    "bool": {
      "must": [
        {
          "multi_match": {
            "query": "kubernetes network policy",
            "fields": ["title^3", "excerpt"],    // title boosted 3x
            "type": "best_fields",
            "fuzziness": "AUTO"                   // Typo tolerance (0/1/2 based on word length)
          }
        }
      ],
      "filter": [
        { "term":  { "tag": "Build Log" } },
        { "range": { "date": { "gte": "2032-01-01" } } }
      ]
    }
  },
  "sort": [
    { "_score": { "order": "desc" } },
    { "date":   { "order": "desc" } }
  ],
  "highlight": {
    "fields": {
      "title":   {},
      "excerpt": { "fragment_size": 200, "number_of_fragments": 1 }
    }
  },
  "size": 10,
  "from": 0    // Pagination: skip first N results
}
```

## Vector search — semantic similarity (k-NN)

```python
# Generate embeddings and index them alongside text fields
# Requirements: openai, elasticsearch

from openai import OpenAI
from elasticsearch import Elasticsearch, helpers

client_oai = OpenAI()
es = Elasticsearch("http://localhost:9200")

def get_embedding(text: str) -> list[float]:
    response = client_oai.embeddings.create(
        input=text,
        model="text-embedding-3-small"   # 1536 dimensions
    )
    return response.data[0].embedding

# Index documents with embeddings
def index_doc(doc: dict):
    embedding = get_embedding(f"{doc['title']} {doc['excerpt']}")
    es.index(
        index="journal",
        id=doc["id"],
        document={**doc, "embedding": embedding}
    )

# Semantic search: find documents similar to a query
def semantic_search(query: str, k: int = 5):
    query_embedding = get_embedding(query)
    result = es.search(
        index="journal",
        knn={
            "field": "embedding",
            "query_vector": query_embedding,
            "k": k,
            "num_candidates": 50   # Consider top 50 candidates per shard
        },
        # Hybrid: combine vector similarity with BM25 text score
        query={"multi_match": {"query": query, "fields": ["title", "excerpt"]}},
        rank={"rrf": {}}   # Reciprocal Rank Fusion: merge vector + text rankings
    )
    return [hit["_source"]["title"] for hit in result["hits"]["hits"]]

results = semantic_search("distributed systems consensus algorithms")
# Returns semantically similar dispatches even without exact keyword matches
```

Elasticsearch vs ClickHouse for analytics: Both handle large-scale data analysis, but with different tradeoffs. Elasticsearch indexes every field at write time (inverted index) — great for ad-hoc full-text search but writes are slower and storage is larger. ClickHouse uses columnar storage and defers computation to query time — writes are fast (append-only), queries are fast for aggregations over specific columns, but full-text search is limited. At Construx, ClickHouse handles time-series analytics (orders per day, revenue trends) and Elasticsearch handles user-facing search (typo-tolerant, relevance-ranked) — different tools for different access patterns.
