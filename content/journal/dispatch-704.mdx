Remix is built on the premise that web fundamentals are not a workaround — they are the architecture. Forms POST. Redirects redirect. Cache-Control headers actually get set. The result is applications that work without JavaScript and are fast with it.

## Install

```bash
npx create-remix@latest my-app
cd my-app
npm run dev
```

## Route file: loader + action + component

```tsx
// app/routes/posts.$slug.tsx
import { json, redirect }         from '@remix-run/node';
import { useLoaderData, Form }    from '@remix-run/react';
import type { LoaderFunctionArgs, ActionFunctionArgs } from '@remix-run/node';
import { db }                      from '~/lib/db';
import { requireAuth }             from '~/lib/auth';

// Runs on the server, before the component renders
export async function loader({ params, request }: LoaderFunctionArgs) {
  const user = await requireAuth(request);   // redirect if not logged in
  const post = await db.posts.findUniqueOrThrow({
    where:   { slug: params.slug },
    include: { author: true },
  });
  return json({ post, user });
}

// Handles POST from <Form> — runs on the server
export async function action({ params, request }: ActionFunctionArgs) {
  const user     = await requireAuth(request);
  const formData = await request.formData();
  const intent   = formData.get('intent');

  if (intent === 'delete') {
    await db.posts.delete({ where: { slug: params.slug, authorId: user.id } });
    return redirect('/posts');
  }

  if (intent === 'like') {
    await db.likes.create({ data: { postId: params.slug, userId: user.id } });
    return json({ liked: true });
  }
}

// Component — receives loader data via useLoaderData
export default function PostPage() {
  const { post, user } = useLoaderData<typeof loader>();

  return (
    <article>
      <h1>{post.title}</h1>
      <p>by {post.author.name}</p>
      <div dangerouslySetInnerHTML={{ __html: post.content }} />

      {/* Form with no JavaScript: submits, action runs, page reloads */}
      <Form method="post">
        <button name="intent" value="like">♥ Like</button>
        {user.id === post.authorId && (
          <button name="intent" value="delete">Delete</button>
        )}
      </Form>
    </article>
  );
}
```

## Error boundaries

```tsx
// Error boundary at the route level — doesn't crash the whole app
export function ErrorBoundary() {
  const error = useRouteError();
  if (isRouteErrorResponse(error) && error.status === 404) {
    return <div>Post not found</div>;
  }
  return <div>Something went wrong</div>;
}
```

## Cache-Control

```tsx
export function headers() {
  return {
    'Cache-Control': 'public, max-age=60, stale-while-revalidate=3600',
  };
}
```

Remix exposes HTTP headers as a first-class return value from each route. CDNs and browsers respect them without extra configuration.

## Remix vs Next.js vs SvelteKit

Remix: form-centric, HTTP-native, excellent progressive enhancement, Vite-powered, React. Next.js: App Router with React Server Components, streaming, excellent static generation. SvelteKit: Svelte, leaner runtime, excellent performance, smaller ecosystem. Remix is the right choice when your application is form-heavy and you want progressive enhancement by default. Next.js is the right choice when you need React Server Components, ISR, or Vercel's edge network.
