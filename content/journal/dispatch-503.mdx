Server Actions are functions that run on the server but can be called from client components directly — no `fetch`, no API route boilerplate, no manual JSON parsing. The client sends a POST request automatically; Next.js handles the transport. For form submissions and mutations, they're often the right default.

## Basic form action

```tsx
// app/contact/actions.ts
'use server';

import { z } from 'zod';
import { resend } from '@/lib/resend';

const ContactSchema = z.object({
  name:    z.string().min(1, 'Name is required'),
  email:   z.string().email('Invalid email'),
  message: z.string().min(10, 'Message too short'),
});

export async function submitContact(formData: FormData) {
  const raw = {
    name:    formData.get('name'),
    email:   formData.get('email'),
    message: formData.get('message'),
  };

  const parsed = ContactSchema.safeParse(raw);

  if (!parsed.success) {
    return { error: parsed.error.flatten().fieldErrors };
  }

  await resend.emails.send({
    from:    'Construx Group <hello@construxgroup.io>',
    to:      ['lewis@construxgroup.io'],
    subject: `Contact from ${parsed.data.name}`,
    html:    `<p>${parsed.data.message}</p>`,
    replyTo: parsed.data.email,
  });

  return { success: true };
}
```

```tsx
// app/contact/page.tsx
import { submitContact } from './actions';

export default function ContactPage() {
  return (
    <form action={submitContact}>
      <input name="name"    required />
      <input name="email"   type="email" required />
      <textarea name="message" required />
      <button type="submit">Send</button>
    </form>
  );
}
```

This works without any client-side JavaScript — the form works as a standard HTML form with a server-side handler. Progressive enhancement by default.

## useActionState for loading and error states

```tsx
'use client';

import { useActionState } from 'react';
import { submitContact } from './actions';

const initialState = { error: null, success: false };

export function ContactForm() {
  const [state, action, pending] = useActionState(submitContact, initialState);

  return (
    <form action={action}>
      <input name="name" required disabled={pending} />
      {state.error?.name && (
        <p className="text-red-500 text-sm">{state.error.name[0]}</p>
      )}

      <input name="email" type="email" required disabled={pending} />
      {state.error?.email && (
        <p className="text-red-500 text-sm">{state.error.email[0]}</p>
      )}

      <textarea name="message" required disabled={pending} />
      {state.error?.message && (
        <p className="text-red-500 text-sm">{state.error.message[0]}</p>
      )}

      <button type="submit" disabled={pending}>
        {pending ? 'Sending...' : 'Send message'}
      </button>

      {state.success && <p className="text-green-500">Message sent!</p>}
    </form>
  );
}
```

`useActionState` needs the action to accept a previous state as the first argument:

```ts
export async function submitContact(
  prevState: { error: Record<string, string[]> | null; success: boolean },
  formData: FormData,
) {
  // ...same as before
  return { error: null, success: true };
}
```

## Button-triggered actions

Server Actions aren't just for forms — call them from any event handler:

```tsx
'use client';

import { useState, useTransition } from 'react';
import { archivePost } from './actions';

export function ArchiveButton({ postId }: { postId: string }) {
  const [isPending, startTransition] = useTransition();

  return (
    <button
      onClick={() => startTransition(() => archivePost(postId))}
      disabled={isPending}
    >
      {isPending ? 'Archiving...' : 'Archive'}
    </button>
  );
}
```

`useTransition` marks the transition as non-urgent, keeping the UI responsive while the action runs.

## Optimistic updates with useOptimistic

```tsx
'use client';

import { useOptimistic, useTransition } from 'react';
import { toggleLike } from './actions';

interface Post {
  id:      string;
  likes:   number;
  liked:   boolean;
}

export function LikeButton({ post }: { post: Post }) {
  const [isPending, startTransition] = useTransition();
  const [optimisticPost, addOptimisticLike] = useOptimistic(
    post,
    (state, liked: boolean) => ({
      ...state,
      liked,
      likes: liked ? state.likes + 1 : state.likes - 1,
    }),
  );

  return (
    <button
      onClick={() =>
        startTransition(() => {
          addOptimisticLike(!optimisticPost.liked);
          toggleLike(post.id);
        })
      }
      disabled={isPending}
    >
      {optimisticPost.liked ? '♥' : '♡'} {optimisticPost.likes}
    </button>
  );
}
```

`useOptimistic` updates immediately in the UI; if the server action fails, it reverts.

## Authentication in Server Actions

```ts
// actions.ts
'use server';

import { getServerSession } from 'next-auth';
import { authOptions } from '@/lib/auth';
import { redirect } from 'next/navigation';

export async function deletePost(postId: string) {
  // Always authenticate in Server Actions — they're POST endpoints
  const session = await getServerSession(authOptions);
  if (!session) redirect('/login');

  const post = await db.select().from(posts).where(eq(posts.id, postId)).limit(1);
  if (!post[0] || post[0].userId !== session.user.id) {
    throw new Error('Not authorized');
  }

  await db.delete(posts).where(eq(posts.id, postId));
  redirect('/dashboard');
}
```

Never trust the client in a Server Action. Validate auth, validate ownership, and throw rather than silently failing.

## When to use Server Actions vs tRPC

**Use Server Actions when:**
- It's a form submission (the HTML form action integration is cleaner)
- The mutation doesn't need to return complex data
- You want progressive enhancement (works without JS)
- It's a simple CRUD operation in the same Next.js project

**Use tRPC when:**
- You need type-safe queries (not just mutations)
- You're building a mobile app or separate frontend that shares the API
- You need subscriptions or real-time features
- The API is consumed by multiple clients

Both are valid. Server Actions reduce boilerplate for forms in Next.js apps. tRPC is better when the API needs to be more general-purpose.
