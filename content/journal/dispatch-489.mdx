Long-lived feature branches cause merge conflicts and accumulate drift. Feature flags solve this differently: merge to main immediately, control visibility from the dashboard. You can ship a half-built feature hidden behind a flag, gradually roll it out by percentage, and kill the switch if something breaks — no deployment required.

## Setup

```bash
npm install posthog-js posthog-node
```

```tsx
// app/providers.tsx
'use client';

import posthog from 'posthog-js';
import { PostHogProvider } from 'posthog-js/react';
import { useEffect } from 'react';

export function PostHogProviderWrapper({ children }: { children: React.ReactNode }) {
  useEffect(() => {
    posthog.init(process.env.NEXT_PUBLIC_POSTHOG_KEY!, {
      api_host: process.env.NEXT_PUBLIC_POSTHOG_HOST ?? 'https://eu.i.posthog.com',
      capture_pageview: false,  // Handle manually for Next.js router
      capture_pageleave: true,
      persistence: 'localStorage',
    });
  }, []);

  return <PostHogProvider client={posthog}>{children}</PostHogProvider>;
}
```

## Client-side flags

```tsx
'use client';

import { useFeatureFlagEnabled, useFeatureFlagPayload } from 'posthog-js/react';

function PricingPage() {
  const newPricingEnabled = useFeatureFlagEnabled('new-pricing-ui');
  const config = useFeatureFlagPayload('scan-limit-config') as { limit: number } | null;

  if (newPricingEnabled) {
    return <NewPricingUI />;
  }

  return <ExistingPricingUI scanLimit={config?.limit ?? 50} />;
}
```

`useFeatureFlagEnabled` returns `undefined` while flags are loading, then `true` or `false`. Guard against the undefined state to prevent flicker:

```tsx
function FeatureGated({ flag, children }: { flag: string; children: React.ReactNode }) {
  const enabled = useFeatureFlagEnabled(flag);

  // Render nothing until flag resolves — prevents layout shift
  if (enabled === undefined) return null;
  if (!enabled) return null;

  return <>{children}</>;
}
```

## Server-side flags

For Server Components and Server Actions, use the Node.js PostHog client:

```ts
// lib/posthog-server.ts
import { PostHog } from 'posthog-node';

export const posthogServer = new PostHog(process.env.POSTHOG_KEY!, {
  host: process.env.POSTHOG_HOST ?? 'https://eu.i.posthog.com',
  flushAt: 1,   // Flush after every event in serverless
  flushInterval: 0,
});
```

```ts
// app/dashboard/page.tsx — Server Component
import { posthogServer } from '@/lib/posthog-server';
import { getCurrentUser } from '@/lib/auth';

export default async function DashboardPage() {
  const user = await getCurrentUser();

  const newDashboardEnabled = await posthogServer.isFeatureEnabled(
    'new-dashboard-v2',
    user.id,
    {
      personProperties: {
        email: user.email,
        role: user.role,
        plan: user.plan,
      },
    },
  );

  // Shut down client to flush events before serverless function exits
  await posthogServer.shutdown();

  if (newDashboardEnabled) return <NewDashboard />;
  return <Dashboard />;
}
```

## Multivariate flags

```ts
// Returns 'control', 'treatment-a', or 'treatment-b'
const variant = await posthogServer.getFeatureFlag('checkout-experiment', userId);

switch (variant) {
  case 'control':      return <OriginalCheckout />;
  case 'treatment-a':  return <SinglePageCheckout />;
  case 'treatment-b':  return <MultiStepCheckout />;
  default:             return <OriginalCheckout />;
}
```

## Rollout patterns

**Percentage rollout** — start at 5%, monitor error rates, increase to 10%, 25%, 50%, 100%:
```
Flag: new-scan-engine
Rollout: 5% of all users
Groups: none
```

**Internal testing** — target by email domain:
```
Flag: new-dashboard-v2
Rollout: 100% where email contains @construxgroup.io
```

**Beta cohort** — target a saved PostHog cohort (users who opted into beta):
```
Flag: experimental-features
Rollout: 100% of cohort: "beta-testers"
```

## Cleaning up flags

Feature flags accumulate. Set a calendar reminder to delete flags after the rollout completes. The process:

1. Flag at 100% → schedule cleanup
2. Remove flag evaluation code from the codebase
3. Delete the flag from PostHog dashboard
4. Remove the `undefined` guard (component always renders now)

Uncleaned flags become permanent branches in the code and hidden PostHog API calls. A quarterly flag audit is worth the 30 minutes.

## Local override

During development, override flags without touching PostHog:

```ts
// posthog.init({
//   bootstrap: {
//     featureFlags: {
//       'new-dashboard-v2': true,
//       'scan-limit-config': { limit: 100 },
//     },
//   },
// })
```

Or use PostHog's toolbar (injected when you're logged into PostHog and visit the site) to toggle flags on any environment without code changes.
