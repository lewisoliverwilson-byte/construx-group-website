Tailwind v4 is a ground-up rewrite. The `tailwind.config.js` file is gone. Configuration moves to CSS. The engine is Rust-based (via Lightning CSS) and roughly 10x faster than v3. The utility class API mostly stays the same — migrations are lighter than you'd expect.

## Installation

```bash
npm install tailwindcss@next @tailwindcss/vite
# or with PostCSS:
npm install tailwindcss@next @tailwindcss/postcss
```

```css
/* app/globals.css — this replaces tailwind.config.js */
@import "tailwindcss";

/* Custom theme tokens */
@theme {
  --color-brand: oklch(65% 0.22 30);
  --color-brand-dim: oklch(65% 0.22 30 / 0.5);
  --font-mono: 'JetBrains Mono', ui-monospace, monospace;
  --spacing-18: 4.5rem;
  --radius-sm: 2px;
}

/* Custom utilities */
@utility text-balance {
  text-wrap: balance;
}

/* Responsive variants via container queries */
@custom-variant sidebar (&:where(.sidebar &));
```

## Theme tokens in v4

v3 used a JS object. v4 uses CSS custom properties defined in `@theme`:

```css
@theme {
  /* Colors — accessible as Tailwind utilities */
  --color-construx: #F97316;
  --color-text-base: #F0EFFF;
  --color-text-muted: rgba(240, 239, 255, 0.6);
  --color-bg-base: #05050F;
  --color-border: rgba(255, 255, 255, 0.08);

  /* Typography */
  --font-sans: 'Space Grotesk', system-ui, sans-serif;
  --font-mono: 'JetBrains Mono', ui-monospace, monospace;
  --text-display: clamp(3rem, 8vw, 7rem);

  /* Spacing */
  --spacing-18: 4.5rem;
  --spacing-22: 5.5rem;

  /* Shadows */
  --shadow-terminal: 0 0 0 1px rgba(0,0,0,0.5), 0 20px 60px rgba(0,0,0,0.6);
}
```

These become utilities automatically:
- `--color-construx` → `text-construx`, `bg-construx`, `border-construx`
- `--spacing-18` → `p-18`, `mt-18`, `gap-18`

## v4 vs v3 config migration

```js
// v3: tailwind.config.js
module.exports = {
  theme: {
    extend: {
      colors: {
        construx: '#F97316',
        'text-base': '#F0EFFF',
      },
      fontFamily: {
        sans: ['Space Grotesk', 'system-ui'],
        mono: ['JetBrains Mono', 'ui-monospace'],
      },
    },
  },
};
```

```css
/* v4: globals.css — equivalent config */
@import "tailwindcss";

@theme {
  --color-construx: #F97316;
  --color-text-base: #F0EFFF;
  --font-sans: 'Space Grotesk', system-ui, sans-serif;
  --font-mono: 'JetBrains Mono', ui-monospace, monospace;
}
```

## New: container queries built in

v3 required the `@tailwindcss/container-queries` plugin. v4 ships it:

```html
<!-- The container -->
<div class="@container">
  <!-- Child responds to container width, not viewport -->
  <div class="grid grid-cols-1 @sm:grid-cols-2 @lg:grid-cols-3">
    ...
  </div>
</div>
```

## New: 3D transform utilities

```html
<div class="rotate-x-12 rotate-y-6 perspective-500 transform-3d">
  <!-- rotateX, rotateY, perspective — all built in -->
</div>
```

## New: `not-*` variants

```html
<button class="not-disabled:hover:bg-construx disabled:opacity-50">
  <!-- bg only applies when NOT disabled -->
</button>

<li class="not-last:border-b border-border">
  <!-- border on all except last child -->
</li>
```

## New: arbitrary properties shorthand

```html
<!-- v3: use square brackets for arbitrary CSS -->
<div class="[mask-image:linear-gradient(to_bottom,black,transparent)]">

<!-- v4: same, but shorter with CSS variables -->
<div style="--tw-mask: linear-gradient(...)" class="[mask-image:var(--tw-mask)]">
```

## Performance

v4's Rust-based engine processes ~3x more CSS per millisecond vs v3's JS engine. On a large project:
- v3: ~600ms incremental rebuild
- v4: ~35ms incremental rebuild

Full builds similarly faster. The difference is noticeable in development.

## Breaking changes worth knowing

**Removed**: `dark:` is now opt-in via `@custom-variant dark (&:where(.dark *))`. The default media-query dark mode still works.

**Changed**: `ring` now adds a 1px ring by default (v3 defaulted to 3px). Check buttons and inputs.

**Changed**: `shadow` now uses `oklch` colors. Custom shadow colours need oklch equivalents or fall back.

**Changed**: `content-['']` now requires escaping for spaces: `content-['hello_world']`.

## Migration

Run the official codemod:

```bash
npx @tailwindcss/upgrade
```

It handles 90% of cases. Manual review needed for custom plugins, complex `@apply` usage, and any JavaScript that reads the config file at runtime.

The class API is stable enough that most React components don't need changes — the migration is mostly configuration format.
