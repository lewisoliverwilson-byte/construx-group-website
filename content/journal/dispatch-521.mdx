Both WebSockets and Server-Sent Events (SSE) let the server push data to the browser without the client polling. The difference is direction: WebSockets are full-duplex (both sides can send), SSE is server-to-client only. Most real-time features only need one direction.

## Server-Sent Events

SSE uses a plain HTTP connection with `Content-Type: text/event-stream`. The server keeps the connection open and writes events as they happen. The browser's `EventSource` API handles reconnection automatically.

```ts
// app/api/stream/route.ts
export async function GET(req: Request) {
  const encoder = new TextEncoder();

  const stream = new ReadableStream({
    async start(controller) {
      function send(data: string, event?: string) {
        const chunk = event
          ? `event: ${event}\ndata: ${data}\n\n`
          : `data: ${data}\n\n`;
        controller.enqueue(encoder.encode(chunk));
      }

      send(JSON.stringify({ status: 'connected' }), 'init');

      // Stream AI response tokens
      const aiStream = await streamFromClaude(/* ... */);

      for await (const chunk of aiStream) {
        send(JSON.stringify({ token: chunk }), 'token');
      }

      send(JSON.stringify({ done: true }), 'done');
      controller.close();
    },
  });

  return new Response(stream, {
    headers: {
      'Content-Type':  'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection':    'keep-alive',
    },
  });
}
```

```tsx
// Client — EventSource API
'use client';

import { useState, useEffect } from 'react';

export function StreamingOutput({ prompt }: { prompt: string }) {
  const [tokens, setTokens] = useState('');

  useEffect(() => {
    const source = new EventSource(`/api/stream?prompt=${encodeURIComponent(prompt)}`);

    source.addEventListener('token', (e) => {
      const { token } = JSON.parse(e.data);
      setTokens((t) => t + token);
    });

    source.addEventListener('done', () => source.close());
    source.onerror = () => source.close();

    return () => source.close();
  }, [prompt]);

  return <p>{tokens}</p>;
}
```

SSE works over HTTP/1.1 (single connection per `EventSource`) and HTTP/2 (multiplexed over the same connection as other requests). Reconnection is built-in — if the connection drops, `EventSource` retries automatically. No libraries needed.

## WebSockets

WebSockets upgrade an HTTP connection to a persistent TCP socket. Both sides can send messages at any time. You need a WebSocket server — not a standard HTTP endpoint.

```ts
// server.ts — separate WebSocket server (not Next.js API routes)
import { WebSocketServer } from 'ws';

const wss = new WebSocketServer({ port: 8080 });

wss.on('connection', (ws) => {
  ws.on('message', (data) => {
    const msg = JSON.parse(data.toString());

    // Broadcast to all connected clients
    wss.clients.forEach((client) => {
      if (client.readyState === WebSocket.OPEN) {
        client.send(JSON.stringify({ type: 'message', ...msg }));
      }
    });
  });

  ws.on('close', () => {
    console.log('Client disconnected');
  });
});
```

```tsx
// Client
'use client';

import { useState, useEffect, useRef } from 'react';

export function Chat({ roomId }: { roomId: string }) {
  const [messages, setMessages] = useState<string[]>([]);
  const ws = useRef<WebSocket | null>(null);

  useEffect(() => {
    ws.current = new WebSocket(`wss://chat.construxgroup.io/room/${roomId}`);

    ws.current.onmessage = (e) => {
      const { type, text } = JSON.parse(e.data);
      if (type === 'message') setMessages((m) => [...m, text]);
    };

    return () => ws.current?.close();
  }, [roomId]);

  function send(text: string) {
    ws.current?.send(JSON.stringify({ text }));
  }

  return (
    <div>
      {messages.map((m, i) => <p key={i}>{m}</p>)}
      <button onClick={() => send('hello')}>Send</button>
    </div>
  );
}
```

## When to use which

**SSE is the right choice when:**
- Server pushes data, client doesn't need to send back in real-time
- AI token streaming (by far the most common modern use case)
- Live feed updates (prices, scores, notifications)
- Progress updates for long-running jobs
- You're on Next.js and want to stay in the Route Handler model

**WebSockets are the right choice when:**
- Bidirectional low-latency communication is required
- Collaborative editing (multiple clients sending/receiving simultaneously)
- Multiplayer games
- Chat with typing indicators, delivery receipts, presence

**The Hyve uses WebSockets** for its real-time channel updates — multiple users sending messages, typing indicators, and presence all require bidirectional traffic. The API product uses SSE for streaming AI responses — one direction, standard HTTP.

## Deploying

SSE works on Vercel and Amplify — it's just HTTP. WebSockets require a server that maintains connections (not serverless functions, which terminate after the response). Options for WebSocket deployment: Railway, Fly.io, a dedicated EC2 instance, or Vercel's newer fluid compute (still in beta for WebSocket support).
