Logs tell you what happened. Traces tell you when things happened, how long they took, and which service they happened in. For a request that touches an API route, a database, an external service, and an AI model, logs alone won't surface a 500ms spike in database query time or a slow LLM response.

OpenTelemetry (OTel) is the open standard for distributed tracing. It's vendor-agnostic — you instrument once and export to Grafana, Honeycomb, Jaeger, or any OTLP-compatible backend.

## Installing

```bash
npm install @opentelemetry/sdk-node \
  @opentelemetry/auto-instrumentations-node \
  @opentelemetry/exporter-trace-otlp-http \
  @opentelemetry/resources \
  @opentelemetry/semantic-conventions
```

## The instrumentation file

Next.js 15 has first-class support for OpenTelemetry via an `instrumentation.ts` file in the project root:

```ts
// instrumentation.ts
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    const { NodeSDK } = await import('@opentelemetry/sdk-node');
    const { OTLPTraceExporter } = await import('@opentelemetry/exporter-trace-otlp-http');
    const { getNodeAutoInstrumentations } = await import('@opentelemetry/auto-instrumentations-node');
    const { Resource } = await import('@opentelemetry/resources');
    const { SEMRESATTRS_SERVICE_NAME, SEMRESATTRS_SERVICE_VERSION } = await import('@opentelemetry/semantic-conventions');

    const sdk = new NodeSDK({
      resource: new Resource({
        [SEMRESATTRS_SERVICE_NAME]: 'construx-website',
        [SEMRESATTRS_SERVICE_VERSION]: process.env.NEXT_PUBLIC_BUILD_ID ?? 'local',
      }),
      traceExporter: new OTLPTraceExporter({
        url: process.env.OTEL_EXPORTER_OTLP_ENDPOINT ?? 'http://localhost:4318/v1/traces',
        headers: {
          'x-honeycomb-team': process.env.HONEYCOMB_API_KEY ?? '',
        },
      }),
      instrumentations: [
        getNodeAutoInstrumentations({
          '@opentelemetry/instrumentation-fs': { enabled: false },
        }),
      ],
    });

    sdk.start();
  }
}
```

The `NEXT_RUNTIME === 'nodejs'` guard prevents this from running on the Edge runtime, which can't load Node.js modules.

## Opt in to Next.js instrumentation hook

```ts
// next.config.ts
const nextConfig: NextConfig = {
  experimental: {
    instrumentationHook: true,
  },
};
```

With this set, Next.js automatically calls `register()` on startup. All HTTP requests, database queries (via pg, mysql2, etc.), and outbound fetch calls are auto-instrumented.

## Manual spans for custom operations

Auto-instrumentation covers the framework. For custom business logic — the AI call, the margin calculation, the batch job — add manual spans:

```ts
// lib/tracing.ts
import { trace, SpanStatusCode } from '@opentelemetry/api';

const tracer = trace.getTracer('construx-app');

export async function withSpan<T>(
  name: string,
  attributes: Record<string, string | number | boolean>,
  fn: () => Promise<T>,
): Promise<T> {
  return tracer.startActiveSpan(name, { attributes }, async (span) => {
    try {
      const result = await fn();
      span.setStatus({ code: SpanStatusCode.OK });
      return result;
    } catch (err) {
      span.setStatus({
        code: SpanStatusCode.ERROR,
        message: err instanceof Error ? err.message : 'Unknown error',
      });
      span.recordException(err as Error);
      throw err;
    } finally {
      span.end();
    }
  });
}
```

Usage in route handlers:

```ts
// app/api/scan/route.ts
import { withSpan } from '@/lib/tracing';

export async function POST(req: Request) {
  const { asin } = await req.json();

  const scanResult = await withSpan(
    'scan.run',
    { 'scan.asin': asin, 'scan.source': 'api' },
    () => runScan(asin),
  );

  if (await isEnabled('ai-scan-enrichment')) {
    const enriched = await withSpan(
      'scan.enrich',
      { 'scan.asin': asin, 'ai.model': 'claude-sonnet-4-6' },
      () => runAiEnrichment(scanResult),
    );
    return Response.json({ ...scanResult, enrichment: enriched });
  }

  return Response.json(scanResult);
}
```

Now your trace for a scan request shows: `http.POST /api/scan` → `scan.run` → (database query) → `scan.enrich` → (Anthropic API call). The latency of each segment is visible.

## Instrumenting the Anthropic SDK

The OTel auto-instrumentations don't know about the Anthropic SDK specifically, but since it uses `fetch` internally, the outbound HTTP call is captured automatically. You get the URL and status code, but not the model name or token counts.

Add a wrapper to capture the Anthropic-specific attributes:

```ts
// lib/ai.ts
import Anthropic from '@anthropic-ai/sdk';
import { withSpan } from '@/lib/tracing';

const client = new Anthropic();

export async function callClaude(params: {
  prompt: string;
  systemPrompt?: string;
  model?: string;
  maxTokens?: number;
}): Promise<{ text: string; inputTokens: number; outputTokens: number }> {
  const model = params.model ?? 'claude-sonnet-4-6';

  return withSpan(
    'anthropic.messages.create',
    {
      'ai.model': model,
      'ai.max_tokens': params.maxTokens ?? 1024,
      'ai.system_prompt_chars': params.systemPrompt?.length ?? 0,
    },
    async () => {
      const response = await client.messages.create({
        model,
        max_tokens: params.maxTokens ?? 1024,
        system: params.systemPrompt,
        messages: [{ role: 'user', content: params.prompt }],
      });

      const text = response.content[0].type === 'text' ? response.content[0].text : '';

      // Add token counts to the span after the response
      const span = trace.getActiveSpan();
      span?.setAttributes({
        'ai.input_tokens': response.usage.input_tokens,
        'ai.output_tokens': response.usage.output_tokens,
      });

      return {
        text,
        inputTokens: response.usage.input_tokens,
        outputTokens: response.usage.output_tokens,
      };
    },
  );
}
```

## Propagating trace context across services

When Scoutr's Next.js app calls The Hyve's API, the trace context needs to propagate so both sides appear in the same trace. The OTel SDK handles this automatically for `fetch` calls via the W3C Trace Context header (`traceparent`).

The receiving service needs to extract the context:

```ts
// In The Hyve's Express server
import { propagation, context } from '@opentelemetry/api';

app.use((req, res, next) => {
  const ctx = propagation.extract(context.active(), req.headers);
  context.with(ctx, next);
});
```

With propagation configured on both ends, a trace that starts in Scoutr and calls The Hyve's API shows a single unified timeline across both services.

## What to look for in traces

**P99 latency by span name.** If `anthropic.messages.create` has a p99 of 8 seconds but the overall request p99 is 9 seconds, AI is almost all of your tail latency.

**Database query patterns.** Auto-instrumentation for pg captures query text and duration. N+1 queries (many short queries in a loop) show up immediately in a trace — you can see fifty `SELECT` spans where there should be one.

**Error rates by span.** A spike in `SpanStatusCode.ERROR` on `scan.run` isolates where failures are happening without digging through log aggregation.
