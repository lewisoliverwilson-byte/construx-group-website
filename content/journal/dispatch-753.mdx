A queue that lives where your compute already runs. No Redis server, no extra deployment.

## Create a queue

```bash
npx wrangler queues create construx-jobs
```

## wrangler.toml

```toml
name = "construx-api"
main = "src/index.ts"
compatibility_date = "2031-01-01"

# Producer binding — send messages to the queue
[[queues.producers]]
binding  = "JOB_QUEUE"
queue    = "construx-jobs"

# Consumer binding — process messages from the queue
[[queues.consumers]]
queue                = "construx-jobs"
max_batch_size       = 10
max_batch_timeout    = 30
max_retries          = 3
dead_letter_queue    = "construx-jobs-dlq"
```

## Send a message (producer)

```ts
// src/index.ts
export interface Env {
  JOB_QUEUE: Queue;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const { type, payload } = await request.json<{ type: string; payload: unknown }>();

    // Non-blocking — returns immediately
    await env.JOB_QUEUE.send({ type, payload, sentAt: Date.now() });

    return Response.json({ queued: true }, { status: 202 });
  },
};
```

## Process messages (consumer)

```ts
// src/consumer.ts
export default {
  async queue(batch: MessageBatch<{ type: string; payload: unknown }>, env: Env): Promise<void> {
    for (const msg of batch.messages) {
      try {
        await processJob(msg.body, env);
        msg.ack();
      } catch (err) {
        // Nack — message goes back to queue (up to max_retries)
        msg.retry({ delaySeconds: 60 });
        console.error('Job failed, retrying:', err);
      }
    }
  },
};

async function processJob(body: { type: string; payload: unknown }, env: Env) {
  if (body.type === 'send-email') {
    await sendEmail(body.payload as EmailPayload, env);
    return;
  }
  if (body.type === 'generate-invoice') {
    await generateInvoice(body.payload as InvoicePayload, env);
    return;
  }
  throw new Error(`Unknown job type: ${body.type}`);
}
```

## Batch acknowledgement

```ts
async queue(batch: MessageBatch, env: Env): Promise<void> {
  const results = await Promise.allSettled(
    batch.messages.map((msg) => processJob(msg.body, env)),
  );

  for (let i = 0; i < batch.messages.length; i++) {
    if (results[i].status === 'fulfilled') {
      batch.messages[i].ack();
    } else {
      batch.messages[i].retry();
    }
  }
}
```

## Delayed delivery

```ts
// Deliver message in 10 minutes
await env.JOB_QUEUE.send(
  { type: 'reminder', userId: 'abc' },
  { delaySeconds: 600 },
);
```

## Dead letter queue — inspect failed messages

```bash
# Failed messages land in the DLQ after max_retries exhausted
npx wrangler queues consumer add construx-jobs-dlq --script dlq-handler
```

```ts
// dlq-handler — log or alert on permanent failures
export default {
  async queue(batch: MessageBatch, env: Env): Promise<void> {
    for (const msg of batch.messages) {
      await env.ALERT_WEBHOOK.fetch('https://hooks.slack.com/...', {
        method: 'POST',
        body:   JSON.stringify({ text: `Job permanently failed: ${JSON.stringify(msg.body)}` }),
      });
      msg.ack();
    }
  },
};
```

## Cloudflare Queues vs BullMQ vs Trigger.dev

Queues: native to Cloudflare Workers, zero infrastructure, global by default, best for Workers-first architectures. BullMQ: Redis-backed, mature API, 100k+ jobs/s, best for Node.js servers with existing Redis. Trigger.dev: managed, real-time observability, best for long-running user-facing workflows. The Construx default: Cloudflare Queues when already on Workers; BullMQ on Node.js; Trigger.dev for complex multi-step sequences.
