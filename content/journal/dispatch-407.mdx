CDK (Cloud Development Kit) is AWS's answer to Terraform: define infrastructure in a real programming language, synthesize it to CloudFormation, deploy with the CDK CLI. The advantage over raw CloudFormation is type safety, code reuse, and the full power of TypeScript — loops, conditionals, abstractions.

## Bootstrap and project setup

```bash
npm install -g aws-cdk
cdk bootstrap aws://ACCOUNT_ID/us-east-1
```

```bash
mkdir infra && cd infra
cdk init app --language typescript
```

This creates the CDK project structure. The key files:

```
infra/
  bin/
    app.ts          # entry point — instantiates stacks
  lib/
    app-stack.ts    # your infrastructure definitions
  cdk.json          # CDK config
  cdk.out/          # synthesized CloudFormation (gitignored)
```

## A typical Next.js stack

```ts
// lib/app-stack.ts
import * as cdk from 'aws-cdk-lib';
import * as s3 from 'aws-cdk-lib/aws-s3';
import * as cloudfront from 'aws-cdk-lib/aws-cloudfront';
import * as origins from 'aws-cdk-lib/aws-cloudfront-origins';
import * as rds from 'aws-cdk-lib/aws-rds';
import * as ec2 from 'aws-cdk-lib/aws-ec2';
import * as secretsmanager from 'aws-cdk-lib/aws-secretsmanager';
import { Construct } from 'constructs';

export class AppStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    // VPC — isolated network for private resources
    const vpc = new ec2.Vpc(this, 'AppVpc', {
      maxAzs: 2,
      natGateways: 1,
    });

    // RDS PostgreSQL
    const dbSecret = new secretsmanager.Secret(this, 'DbSecret', {
      generateSecretString: {
        secretStringTemplate: JSON.stringify({ username: 'app' }),
        generateStringKey: 'password',
        excludeCharacters: '"@/',
      },
    });

    const database = new rds.DatabaseInstance(this, 'Database', {
      engine: rds.DatabaseInstanceEngine.postgres({
        version: rds.PostgresEngineVersion.VER_16,
      }),
      instanceType: ec2.InstanceType.of(
        ec2.InstanceClass.T4G,
        ec2.InstanceSize.MICRO,
      ),
      vpc,
      vpcSubnets: { subnetType: ec2.SubnetType.PRIVATE_WITH_EGRESS },
      credentials: rds.Credentials.fromSecret(dbSecret),
      databaseName: 'app',
      backupRetention: cdk.Duration.days(7),
      deletionProtection: true,
    });

    // S3 — user uploads
    const uploadsBucket = new s3.Bucket(this, 'Uploads', {
      versioned: true,
      encryption: s3.BucketEncryption.S3_MANAGED,
      blockPublicAccess: s3.BlockPublicAccess.BLOCK_ALL,
      lifecycleRules: [
        {
          // Delete incomplete multipart uploads after 7 days
          abortIncompleteMultipartUploadAfter: cdk.Duration.days(7),
        },
      ],
    });

    // CloudFront — CDN for uploads
    const distribution = new cloudfront.Distribution(this, 'UploadsDistribution', {
      defaultBehavior: {
        origin: origins.S3BucketOrigin.withOriginAccessControl(uploadsBucket),
        viewerProtocolPolicy: cloudfront.ViewerProtocolPolicy.REDIRECT_TO_HTTPS,
        cachePolicy: cloudfront.CachePolicy.CACHING_OPTIMIZED,
      },
    });

    // Outputs — values needed by the app
    new cdk.CfnOutput(this, 'DatabaseEndpoint', {
      value: database.instanceEndpoint.hostname,
    });
    new cdk.CfnOutput(this, 'UploadsBucketName', {
      value: uploadsBucket.bucketName,
    });
    new cdk.CfnOutput(this, 'CdnDomain', {
      value: distribution.distributionDomainName,
    });
  }
}
```

## Environments and context

Different environments (dev, staging, prod) should be separate stacks with different configurations:

```ts
// bin/app.ts
import * as cdk from 'aws-cdk-lib';
import { AppStack } from '../lib/app-stack';

const app = new cdk.App();

const env = {
  account: process.env.CDK_DEFAULT_ACCOUNT,
  region: process.env.CDK_DEFAULT_REGION,
};

new AppStack(app, 'AppDev', {
  env,
  tags: { Environment: 'dev' },
});

new AppStack(app, 'AppProd', {
  env,
  tags: { Environment: 'production' },
});
```

Parameterize with CDK context or environment-specific config:

```ts
// lib/app-stack.ts
interface AppStackProps extends cdk.StackProps {
  environment: 'dev' | 'staging' | 'production';
}

export class AppStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props: AppStackProps) {
    super(scope, id, props);

    const isProd = props.environment === 'production';

    const database = new rds.DatabaseInstance(this, 'Database', {
      instanceType: isProd
        ? ec2.InstanceType.of(ec2.InstanceClass.T4G, ec2.InstanceSize.MEDIUM)
        : ec2.InstanceType.of(ec2.InstanceClass.T4G, ec2.InstanceSize.MICRO),
      multiAz: isProd,
      backupRetention: isProd ? cdk.Duration.days(30) : cdk.Duration.days(1),
      deletionProtection: isProd,
      // ...
    });
  }
}
```

## Custom constructs

Reusable infrastructure patterns can be encapsulated as constructs:

```ts
// lib/constructs/secure-bucket.ts
import * as s3 from 'aws-cdk-lib/aws-s3';
import * as cloudfront from 'aws-cdk-lib/aws-cloudfront';
import * as origins from 'aws-cdk-lib/aws-cloudfront-origins';
import { Construct } from 'constructs';

interface SecureBucketProps {
  prefix: string;
}

export class SecureBucket extends Construct {
  readonly bucket: s3.Bucket;
  readonly distribution: cloudfront.Distribution;
  readonly cdnUrl: string;

  constructor(scope: Construct, id: string, props: SecureBucketProps) {
    super(scope, id);

    this.bucket = new s3.Bucket(this, 'Bucket', {
      bucketName: `${props.prefix}-${this.node.addr.slice(0, 8)}`,
      versioned: true,
      encryption: s3.BucketEncryption.S3_MANAGED,
      blockPublicAccess: s3.BlockPublicAccess.BLOCK_ALL,
    });

    this.distribution = new cloudfront.Distribution(this, 'Distribution', {
      defaultBehavior: {
        origin: origins.S3BucketOrigin.withOriginAccessControl(this.bucket),
        viewerProtocolPolicy: cloudfront.ViewerProtocolPolicy.REDIRECT_TO_HTTPS,
      },
    });

    this.cdnUrl = `https://${this.distribution.distributionDomainName}`;
  }
}
```

```ts
// lib/app-stack.ts — use the construct
const uploads = new SecureBucket(this, 'Uploads', { prefix: 'app-uploads' });
const avatars = new SecureBucket(this, 'Avatars', { prefix: 'app-avatars' });
```

## Deployment workflow

```bash
# Preview changes
cdk diff AppProd

# Deploy
cdk deploy AppProd

# Deploy all stacks
cdk deploy --all

# Destroy (careful in prod)
cdk destroy AppDev
```

In CI/CD (GitHub Actions):

```yaml
- name: Deploy infrastructure
  run: |
    cd infra
    npm ci
    npx cdk deploy AppProd --require-approval never
  env:
    AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
    AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
```

## Hotswap deployments

For Lambda functions and ECS tasks, CDK supports hotswap — deploying code changes without recreating the full CloudFormation stack:

```bash
cdk deploy --hotswap AppProd
```

This skips CloudFormation entirely for eligible changes and updates the resource directly. 10x faster for Lambda code updates during development.

The pattern: one stack per environment, custom constructs for repeated patterns, diff before every prod deploy. Infrastructure drift is a production incident waiting to happen — CDK makes the current state auditable and reproducible.
