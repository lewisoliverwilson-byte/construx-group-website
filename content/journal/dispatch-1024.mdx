excerpt: "Kubescape is a Kubernetes security platform that scans clusters, manifests, Helm charts, and CI pipelines against security frameworks: NSA/CISA Kubernetes Hardening Guidance, MITRE ATT&CK, CIS Benchmarks, and SOC 2. It identifies misconfigurations — containers running as root, missing network policies, overly permissive RBAC roles, images pulled without digests — and assigns a risk score across the cluster. Kubescape runs as a CLI (scan before deploy), as a Kubernetes operator (continuous in-cluster scanning with policy enforcement), and integrates with Prometheus for metric-based alerting when the cluster's risk score rises above a threshold. The RBAC scanner is particularly useful: it maps every ServiceAccount, ClusterRoleBinding, and Role to what actions they can take and flags ones that have cluster-admin or wildcard permissions beyond what their workload requires."

## Cluster scanning and framework coverage

```bash
# Install Kubescape
curl -s https://raw.githubusercontent.com/kubescape/kubescape/master/install.sh | /bin/bash

# Scan the live cluster against the NSA/CISA Kubernetes Hardening Guidance
kubescape scan framework nsa --kubeconfig ~/.kube/construx-prod

# Output:
# ┌──────────────────────────────────────────────────────────────────────┐
# │ Control                              │ Passed │ Failed │ Risk Score │
# ├──────────────────────────────────────┼────────┼────────┼────────────┤
# │ C-0002 Exec into container           │ 47     │ 3      │ 6%         │
# │ C-0009 Resource limits               │ 44     │ 6      │ 12%        │
# │ C-0016 Allow privilege escalation    │ 50     │ 0      │ 0%         │
# │ C-0017 Containers running as root    │ 48     │ 2      │ 4%         │
# │ C-0034 Automatic SA token mount      │ 41     │ 9      │ 18%        │
# │ C-0044 Container security context    │ 50     │ 0      │ 0%         │
# │ C-0055 Linux capabilities            │ 47     │ 3      │ 6%         │
# └──────────────────────────────────────┴────────┴────────┴────────────┘
# Overall risk score: 7.8%   (lower is better)

# Scan against MITRE ATT&CK framework
kubescape scan framework mitre --kubeconfig ~/.kube/construx-prod

# Scan manifests in CI (before deployment)
kubescape scan framework nsa \
  --format json \
  --output kubescape-report.json \
  ./k8s/

# Fail CI if risk score above threshold
kubescape scan framework nsa ./k8s/ --fail-threshold 10
# Exit code 1 if risk score > 10%

# Scan a Helm chart before installation
helm template construx-api ./charts/construx-api \
  --values values.prod.yaml \
  | kubescape scan framework nsa -
```

## RBAC analysis

```bash
# RBAC scanner: map who can do what across the cluster
kubescape scan control C-0065 --kubeconfig ~/.kube/construx-prod
# C-0065: Cluster-admin binding

# Output:
# Failed Resources:
# ServiceAccount: construx-prod/legacy-admin   (bound to cluster-admin ClusterRole)
# ServiceAccount: kube-system/dashboard        (bound to cluster-admin ClusterRole)
# ServiceAccount: construx-prod/debug          (bound to cluster-admin ClusterRole)

# More detailed RBAC audit
kubescape scan framework nsa \
  --include-namespaces construx-prod \
  --format json \
  | jq '.results[] | select(.controlID == "C-0065") | .failedPaths'

# Fix: replace cluster-admin binding with minimal required permissions
# Before: ClusterRoleBinding → cluster-admin
# After: RoleBinding (namespace-scoped) → custom Role with only the needed verbs

kubectl get clusterrolebinding -o json \
  | jq '.items[] | select(.roleRef.name == "cluster-admin") | .subjects'
# Shows every subject with cluster-admin — start removing the ones that don't need it
```

## Kubescape Operator — continuous in-cluster scanning

```yaml
# Deploy Kubescape Operator: continuous scanning + Prometheus metrics

helm repo add kubescape https://kubescape.github.io/helm-charts/
helm upgrade --install kubescape kubescape/kubescape-operator \
  --namespace kubescape \
  --create-namespace \
  --set clusterName=construx-prod \
  --set capabilities.continuousScan=enable \
  --set capabilities.vulnerabilityScan=enable \
  --set prometheus.enabled=true   # expose metrics on :8080/metrics

---
# PrometheusRule: alert when risk score rises above threshold
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: kubescape-risk-alerts
  namespace: kubescape
spec:
  groups:
    - name: kubescape
      rules:
        - alert: HighKubernetesRiskScore
          expr: kubescape_cluster_compliance_score < 90
          for: 10m
          labels:
            severity: warning
          annotations:
            summary: "Cluster compliance score below 90%"
            description: "Kubescape risk score: {{ $value }}%"

        - alert: CriticalMisconfiguration
          expr: kubescape_resources_failed{severity="critical"} > 0
          for: 5m
          labels:
            severity: critical
          annotations:
            summary: "Critical Kubernetes misconfiguration detected"
```

Kubescape vs Polaris vs Checkov vs kube-bench vs manual RBAC review: Polaris focuses on Kubernetes best practices (resource limits, liveness probes, security context) — good UX but doesn't map to specific compliance frameworks. Checkov scans IaC (Terraform, Kubernetes manifests, Helm, Dockerfiles) with 1000+ built-in checks — excellent for pre-deploy scanning across multiple artifact types. kube-bench specifically tests CIS Kubernetes Benchmark compliance by running checks against the kubelet and API server configuration — node-level, not workload-level. Kubescape maps to established frameworks (NSA, MITRE, CIS) which is what compliance auditors recognise, making it easier to produce reports for SOC 2 or ISO 27001 evidence. The RBAC analysis is the most practically useful part: finding ServiceAccounts with cluster-admin they don't need is something manual review misses at scale.
