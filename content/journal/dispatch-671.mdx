Traditional search is keyword-based — it finds documents that contain the search terms. Semantic search finds documents that are conceptually similar to the query, regardless of exact word match. The query "how do I reset my password" matches "account recovery" even though none of the words overlap. Vectors encode meaning, not spelling.

## What embeddings are

An embedding is a vector — an array of floating-point numbers — that represents the semantic content of a piece of text. Similar texts produce similar vectors. The embedding model maps arbitrary text to a consistent space where proximity means semantic similarity.

```ts
import OpenAI from 'openai';

const openai = new OpenAI();

// Embed a piece of text
const { data } = await openai.embeddings.create({
  model: 'text-embedding-3-small',
  input: 'How do I reset my password?',
});

const embedding = data[0].embedding;  // number[] with 1536 dimensions
```

## pgvector (Postgres extension)

```sql
-- Enable the extension
CREATE EXTENSION IF NOT EXISTS vector;

-- Add a vector column to an existing table
ALTER TABLE documents ADD COLUMN embedding vector(1536);

-- Create an index for fast approximate nearest neighbour search
CREATE INDEX ON documents USING hnsw (embedding vector_cosine_ops);
```

```ts
import { neon } from '@neondatabase/serverless';

const sql = neon(process.env.DATABASE_URL!);

// Store a document with its embedding
await sql`
  INSERT INTO documents (content, embedding)
  VALUES (${content}, ${JSON.stringify(embedding)}::vector)
`;

// Semantic search: find the 5 most similar documents
const results = await sql`
  SELECT id, content, 1 - (embedding <=> ${JSON.stringify(queryEmbedding)}::vector) AS similarity
  FROM documents
  ORDER BY embedding <=> ${JSON.stringify(queryEmbedding)}::vector
  LIMIT 5
`;
```

Operators: `<=>` cosine distance, `<->` Euclidean distance, `<#>` negative inner product.

## RAG (Retrieval-Augmented Generation)

```ts
async function ragQuery(question: string): Promise<string> {
  // 1. Embed the question
  const { data } = await openai.embeddings.create({
    model: 'text-embedding-3-small',
    input: question,
  });
  const qvec = data[0].embedding;

  // 2. Find relevant documents
  const docs = await sql`
    SELECT content
    FROM knowledge_base
    ORDER BY embedding <=> ${JSON.stringify(qvec)}::vector
    LIMIT 4
  `;

  const context = docs.map((d: { content: string }) => d.content).join('\n\n');

  // 3. Generate an answer using the retrieved context
  const completion = await openai.chat.completions.create({
    model: 'claude-opus-4-8',
    messages: [
      {
        role:    'system',
        content: `Answer questions using the provided context. If the context doesn't contain the answer, say so.\n\nCONTEXT:\n${context}`,
      },
      { role: 'user', content: question },
    ],
  });

  return completion.choices[0].message.content ?? '';
}
```

## Pinecone (managed vector database)

```ts
import { Pinecone } from '@pinecone-database/pinecone';

const pc    = new Pinecone({ apiKey: process.env.PINECONE_API_KEY! });
const index = pc.index('construx-docs');

// Upsert vectors
await index.upsert([
  {
    id:       'doc-1',
    values:   embedding,
    metadata: { title: 'Getting Started', url: '/docs/start', source: 'docs' },
  },
]);

// Query
const result = await index.query({
  vector:          queryEmbedding,
  topK:            5,
  includeMetadata: true,
  filter:          { source: { $eq: 'docs' } },
});

const matches = result.matches.map((m) => ({ id: m.id, score: m.score, ...m.metadata }));
```

## Chunking strategies

Long documents need to be split before embedding — embedding models have token limits and perform better on focused chunks.

```ts
function chunkText(text: string, maxTokens = 400, overlap = 50): string[] {
  const words  = text.split(/\s+/);
  const chunks: string[] = [];
  let i = 0;

  while (i < words.length) {
    const chunk = words.slice(i, i + maxTokens).join(' ');
    chunks.push(chunk);
    i += maxTokens - overlap;  // overlap ensures context continuity at chunk boundaries
  }

  return chunks;
}
```

Chunk at paragraph or section boundaries when possible — semantic chunks outperform fixed-size chunks.

## pgvector vs Pinecone vs Qdrant

pgvector: add vector search to your existing Postgres — no new service, simple ops. Best for most use cases. Pinecone: fully managed, scales to billions of vectors, no ops overhead — worth it at scale or if Postgres isn't already in your stack. Qdrant: open-source, self-hostable, rich filtering, faster than pgvector at high scale. For most applications, pgvector on Neon or Supabase is the right starting point.
