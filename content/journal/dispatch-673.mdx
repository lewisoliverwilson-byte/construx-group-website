Turborepo caches builds. Nx caches builds, knows which projects are affected by a change, generates code, runs affected tests only, and provides a visual dependency graph. The tradeoff is more configuration — but for large teams, the tooling pays for itself.

## Setup

```bash
npx create-nx-workspace@latest construx --preset=next
# Or add to an existing monorepo:
npx nx@latest init
```

## Project structure

```
apps/
  web/          # Next.js app
  api/          # Express/Hono API
  mobile/       # React Native
libs/
  shared/
    ui/         # Shared React components
    types/      # Shared TypeScript types
    utils/      # Shared utilities
  feature/
    auth/       # Auth logic (shared between web and api)
    billing/    # Billing logic
nx.json
project.json (per project)
```

## nx.json: workspace config

```json
{
  "$schema": "./node_modules/nx/schemas/nx-schema.json",
  "targetDefaults": {
    "build": {
      "dependsOn": ["^build"],
      "inputs":    ["production", "^production"],
      "cache":     true
    },
    "test": {
      "inputs":  ["default", "^production", "{workspaceRoot}/jest.preset.js"],
      "cache":   true
    },
    "lint": {
      "inputs":  ["default", "{workspaceRoot}/.eslintrc.json"],
      "cache":   true
    }
  },
  "namedInputs": {
    "default":    ["{projectRoot}/**/*", "sharedGlobals"],
    "production": ["default", "!{projectRoot}/**/*.spec.ts", "!{projectRoot}/jest.config.ts"],
    "sharedGlobals": []
  }
}
```

## Running tasks

```bash
# Run build for a single project
nx build web

# Run tests only for affected projects (since last commit)
nx affected -t test

# Run lint across all projects in parallel
nx run-many -t lint

# Run multiple targets for a project
nx run-many -t build test lint --projects=web,api

# View the project graph in browser
nx graph

# Show what's affected by recent changes
nx affected:graph
```

## Code generators

```bash
# Generate a new React library
nx g @nx/react:library feature-auth --directory=libs/feature/auth

# Generate a new Next.js app
nx g @nx/next:app dashboard

# Generate a React component in a library
nx g @nx/react:component LoginForm --project=feature-auth

# Generate an API route
nx g @nx/node:library api-routes --directory=libs/api
```

Generators scaffold files, update imports, and wire up the project graph. No manual file creation or config editing.

## Remote caching with Nx Cloud

```bash
# Connect to Nx Cloud (free tier available)
npx nx connect

# All subsequent task results are cached remotely
nx run-many -t build  # cache hit for unchanged projects: pulled from cloud
```

Nx Cloud distributes the cache across all developers and CI. The first team member who builds a package stores the result; everyone else restores from cache.

## Distributed task execution (DTE)

```yaml
# .github/workflows/ci.yml
- name: Run affected tests
  run: npx nx affected -t test --parallel=3 --base=origin/main

# Nx Cloud distributes tasks across CI agents automatically
# Halves CI time for large monorepos
```

## Nx vs Turborepo

Turborepo: simpler, one config file, great for teams who want fast builds with minimal investment. Nx: more features (generators, affected computation, project graph, DTE, plugin ecosystem), more configuration. Use Turborepo when you want to be productive in 30 minutes. Use Nx when you're managing a large monorepo with multiple teams and need code generation, consistent tooling, and distributed execution.
