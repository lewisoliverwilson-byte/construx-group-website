excerpt: "The WebAssembly Component Model is a standard for composing WASM modules with typed interfaces. A component exports and imports functions with rich types (records, lists, options, variants) via WIT (WebAssembly Interface Types) definitions. Components written in Rust, Python, Go, or C can call each other without FFI boilerplate — the runtime handles serialisation across the component boundary. Wasmtime runs components server-side; the browser runs them via the standard WASM API."

Typed interfaces between modules. Compose across languages. Runs everywhere WASM runs.

## Define a component interface with WIT

```wit
// wit/orders.wit
package construx:orders@1.0.0;

interface types {
  record order {
    id:          string;
    customer-id: string;
    total-cents: u64;
    status:      order-status;
  }

  enum order-status {
    pending,
    processing,
    shipped,
    delivered,
    cancelled,
  }

  variant order-error {
    not-found(string),
    validation-failed(string),
    payment-declined,
  }
}

interface order-service {
  use types.{order, order-error};

  create-order: func(customer-id: string, total-cents: u64) -> result<order, order-error>;
  get-order:    func(id: string) -> result<order, order-error>;
  list-orders:  func(customer-id: string, limit: u32) -> list<order>;
}

world order-world {
  export order-service;
}
```

## Implement a component in Rust

```rust
// src/lib.rs
use exports::construx::orders::order_service::{Guest, Order, OrderError, OrderStatus};

wit_bindgen::generate!({
    world: "order-world",
    exports: { world: Component },
});

struct Component;

impl Guest for Component {
    fn create_order(customer_id: String, total_cents: u64) -> Result<Order, OrderError> {
        if total_cents == 0 {
            return Err(OrderError::ValidationFailed("total must be positive".to_string()));
        }

        Ok(Order {
            id:          format!("order-{}", uuid_v4()),
            customer_id,
            total_cents,
            status:      OrderStatus::Pending,
        })
    }

    fn get_order(id: String) -> Result<Order, OrderError> {
        // Fetch from storage (via imported host functions)
        let data = storage::get(&id)
            .ok_or_else(|| OrderError::NotFound(id.clone()))?;
        Ok(serde_json::from_slice(&data).unwrap())
    }

    fn list_orders(customer_id: String, limit: u32) -> Vec<Order> {
        storage::scan_prefix(&format!("orders/{}", customer_id))
            .take(limit as usize)
            .map(|data| serde_json::from_slice(&data).unwrap())
            .collect()
    }
}
```

```bash
# Build the Rust component
cargo build --target wasm32-wasip1 --release
wasm-tools component new target/wasm32-wasip1/release/orders.wasm \
  -o orders-component.wasm

# Verify the component
wasm-tools component wit orders-component.wasm
```

## Implement a component in Python

```python
# app.py — Python implementation of the same WIT interface
from orders import exports
from orders.exports.order_service import Order, OrderError, OrderStatus

class OrderServiceImpl(exports.OrderService):
    def create_order(self, customer_id: str, total_cents: int) -> Order:
        if total_cents <= 0:
            raise OrderError.ValidationFailed("total must be positive")
        return Order(
            id=f"order-{generate_id()}",
            customer_id=customer_id,
            total_cents=total_cents,
            status=OrderStatus.PENDING,
        )
```

```bash
# Build Python component with componentize-py
pip install componentize-py
componentize-py --wit-path wit/ --world order-world \
  componentize app -o orders-python.wasm
```

## Compose components with wasm-tools

```bash
# Compose the Rust order service with a Python analytics component
# The composed component links their imports/exports at the type level
wasm-tools compose \
  orders-component.wasm \
  analytics-component.wasm \
  -o composed.wasm

# Run with Wasmtime
wasmtime run --wasm component-model composed.wasm
```

## Run in Node.js with jco

```bash
# Transpile a WASM component to JavaScript + WASM for Node.js / browser
npx jco transpile orders-component.wasm -o dist/orders/

# Generated files:
# dist/orders/orders.js      — JavaScript bindings
# dist/orders/orders.core.wasm — underlying WASM binary
```

```ts
// Use the transpiled component in Node.js
import { createOrder, getOrder } from './dist/orders/orders.js';

const order = createOrder('cust-001', 4999n);
console.log(order.id, order.status);
// order-a3f9b2c1 pending
```

WASM Component Model vs gRPC: gRPC uses Protocol Buffers over HTTP/2 — language-independent, network-based, with code generation. The WASM Component Model is in-process — components call each other via direct function calls with the runtime handling type marshalling. No network, no serialisation overhead beyond the ABI boundary. Components share the same process but are isolated (no direct memory access between components unless explicitly imported). For in-process composition across languages, components. For network services that need language independence and service discovery, gRPC.
