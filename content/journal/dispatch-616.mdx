React Query solves a problem that's easy to underestimate: remote data is not the same as local state. It has a lifecycle — it can be stale, it needs to be refetched, it can fail and be retried, and the same data might be needed in multiple components simultaneously. React Query manages all of this automatically.

## Setup

```bash
npm install @tanstack/react-query @tanstack/react-query-devtools
```

```tsx
// app/providers.tsx
'use client';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { ReactQueryDevtools } from '@tanstack/react-query-devtools';
import { useState } from 'react';

export function Providers({ children }: { children: React.ReactNode }) {
  const [queryClient] = useState(() => new QueryClient({
    defaultOptions: {
      queries: {
        staleTime:   60 * 1000,  // data is fresh for 1 minute
        gcTime:      5 * 60 * 1000,  // cache for 5 minutes after unused
        retry:       1,
        refetchOnWindowFocus: false,
      },
    },
  }));

  return (
    <QueryClientProvider client={queryClient}>
      {children}
      <ReactQueryDevtools initialIsOpen={false} />
    </QueryClientProvider>
  );
}
```

## useQuery: fetching data

```ts
// v5: single options object (no more positional arguments)
const { data, isLoading, isError, error } = useQuery({
  queryKey: ['posts', { status: 'published', page: 1 }],
  queryFn:  async () => {
    const res = await fetch('/api/posts?status=published&page=1');
    if (!res.ok) throw new Error('Failed to fetch posts');
    return res.json() as Promise<Post[]>;
  },
  staleTime: 30 * 1000,  // override default for this query
});
```

The `queryKey` array uniquely identifies the query. Queries with the same key share cache. Include all variables that affect the result in the key — `['posts', { status, page }]` not just `['posts']`.

## useMutation: writing data

```ts
const { mutate, isPending, error } = useMutation({
  mutationFn: async (newPost: CreatePostInput) => {
    const res = await fetch('/api/posts', {
      method:  'POST',
      headers: { 'Content-Type': 'application/json' },
      body:    JSON.stringify(newPost),
    });
    if (!res.ok) throw new Error('Failed to create post');
    return res.json() as Promise<Post>;
  },
  onSuccess: (newPost) => {
    // Invalidate and refetch the posts list
    queryClient.invalidateQueries({ queryKey: ['posts'] });
    // Or: add the new post to the cache directly
    queryClient.setQueryData(['posts', newPost.id], newPost);
  },
  onError: (err) => {
    toast.error(err.message);
  },
});

// Usage
mutate({ title: 'New post', content: '...' });
```

## Optimistic updates

```ts
const { mutate } = useMutation({
  mutationFn: updatePost,
  onMutate: async (updatedPost) => {
    // Cancel outgoing refetches (prevent overwriting optimistic update)
    await queryClient.cancelQueries({ queryKey: ['post', updatedPost.id] });

    // Snapshot current value
    const previous = queryClient.getQueryData(['post', updatedPost.id]);

    // Optimistically update
    queryClient.setQueryData(['post', updatedPost.id], (old: Post) => ({
      ...old,
      ...updatedPost,
    }));

    return { previous };  // returned as context
  },
  onError: (err, updatedPost, context) => {
    // Rollback on error
    queryClient.setQueryData(['post', updatedPost.id], context?.previous);
  },
  onSettled: (post) => {
    // Always refetch to sync with server
    queryClient.invalidateQueries({ queryKey: ['post', post?.id] });
  },
});
```

## useSuspenseQuery: data with Suspense

v5 introduces `useSuspenseQuery` — a version that integrates cleanly with React Suspense and ErrorBoundary:

```tsx
// The component throws a Promise if loading, an Error if failed
function PostList() {
  const { data: posts } = useSuspenseQuery({
    queryKey: ['posts'],
    queryFn:  fetchPosts,
  });

  return (
    <ul>
      {posts.map((p) => <li key={p.id}>{p.title}</li>)}
    </ul>
  );
}

// Wrap with Suspense and ErrorBoundary
function PostsPage() {
  return (
    <ErrorBoundary fallback={<ErrorState />}>
      <Suspense fallback={<SkeletonList />}>
        <PostList />
      </Suspense>
    </ErrorBoundary>
  );
}
```

With `useSuspenseQuery`, `data` is always defined — no need for `isLoading` checks inside the component.

## Prefetching

```ts
// Prefetch on hover (desktop)
async function prefetchPost(id: string) {
  await queryClient.prefetchQuery({
    queryKey: ['post', id],
    queryFn:  () => fetchPost(id),
  });
}

// Prefetch on the server (Next.js App Router)
// app/posts/page.tsx
export default async function PostsPage() {
  const queryClient = new QueryClient();
  await queryClient.prefetchQuery({
    queryKey: ['posts'],
    queryFn:  fetchPosts,
  });

  return (
    <HydrationBoundary state={dehydrate(queryClient)}>
      <PostList />
    </HydrationBoundary>
  );
}
```

## staleTime vs gcTime

`staleTime`: how long data is considered fresh. During this period, a component that mounts with the query already cached won't trigger a background refetch.

`gcTime` (was `cacheTime` in v4): how long unused cached data is kept before it's garbage collected. A query with no subscribers is removed after this duration.

For most data: `staleTime: 60_000` (fresh for 1 minute, refetch in background after). For real-time data: `staleTime: 0` (always refetch). For static data: `staleTime: Infinity` (never refetch).
