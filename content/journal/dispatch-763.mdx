Monorepo tasks that skip unchanged packages. This is what CI should have always looked like.

## Install

```bash
npm install turbo --save-dev
```

## turbo.json — task pipeline

```json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "inputs":    ["$TURBO_DEFAULT$", ".env*"],
      "outputs":   [".next/**", "dist/**"]
    },
    "test": {
      "dependsOn": ["^build"],
      "inputs":    ["**/*.ts{,x}", "**/*.test.ts{,x}"],
      "outputs":   ["coverage/**"]
    },
    "lint": {
      "inputs": ["**/*.ts{,x}", ".eslintrc*"]
    },
    "type-check": {
      "inputs": ["**/*.ts{,x}", "tsconfig*.json"]
    },
    "dev": {
      "cache":     false,
      "persistent": true
    }
  }
}
```

`^build` means: run `build` in all upstream dependencies first. `$TURBO_DEFAULT$` includes all tracked files — you only need to list additions.

## Monorepo structure

```
apps/
  website/          # Next.js app
  dashboard/        # Another Next.js app
packages/
  ui/               # Shared React components
  db/               # Drizzle schema + db client
  email/            # React Email templates
  utils/            # Shared utilities
```

```json
// packages/ui/package.json
{
  "name": "@construx/ui",
  "exports": {
    ".": "./src/index.ts"
  },
  "scripts": {
    "build": "tsc --project tsconfig.build.json",
    "type-check": "tsc --noEmit"
  }
}
```

## Run tasks

```bash
# Build all packages in dependency order
npx turbo build

# Run only affected packages (compares to main branch)
npx turbo build --filter=[main...HEAD]

# Run for a specific app and its dependencies
npx turbo build --filter=website...

# Parallel dev servers
npx turbo dev
```

## Remote caching with Vercel

```bash
# Link to Vercel remote cache
npx turbo link

# CI automatically uses remote cache — no extra config
```

## Self-hosted remote cache

```ts
// turbo.json — point to self-hosted endpoint
{
  "remoteCache": {
    "enabled":   true,
    "apiUrl":    "https://cache.construxgroup.io",
    "signature": true
  }
}
```

Any S3-compatible endpoint works as a remote cache backend. `ducktape-cache` and `turborepo-remote-cache` are popular self-hosted options.

## CI config

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]

env:
  TURBO_TOKEN:   ${{ secrets.TURBO_TOKEN }}
  TURBO_TEAM:    construx

jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }  # needed for --filter=[main...HEAD]
      - uses: actions/setup-node@v4
        with: { node-version: '22', cache: 'npm' }
      - run: npm ci
      - run: npx turbo build lint type-check test --filter=[main...HEAD]
```

With remote caching, the `--filter=[main...HEAD]` flag limits work to changed packages. The remote cache means even the changed packages skip unchanged tasks.

## Turborepo vs Nx vs Lerna

Turborepo: minimal config, excellent caching, Vercel-integrated, best DX for Next.js monorepos. Nx: more opinionated, plugin system, powerful for large enterprise monorepos. Lerna: version management focus, less about task caching, often used with Nx. The Construx default: Turborepo for any multi-package project. The cache hit rate on CI pays for the setup cost within the first week.
