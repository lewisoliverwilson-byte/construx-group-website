excerpt: "WireGuard is a VPN protocol built into the Linux kernel since 5.6. Its codebase is 4,000 lines — compared to 100,000+ for OpenVPN — which makes it auditable, fast, and simple to configure. A WireGuard tunnel is configured as a network interface with a config file, a private key, and a list of peer public keys. Setup takes minutes. The protocol uses modern cryptography (Curve25519, ChaCha20, Poly1305) and has no legacy cipher negotiation."

A VPN you can set up in ten minutes and audit in an afternoon.

## Install

```bash
# Ubuntu/Debian
sudo apt install wireguard

# macOS (client only)
brew install wireguard-tools
```

## Generate keys

```bash
# Server
wg genkey | tee server_private.key | wg pubkey > server_public.key

# Each client
wg genkey | tee client_private.key | wg pubkey > client_public.key

# Keep private keys private — never share them
chmod 600 server_private.key client_private.key
```

## Server config

```ini
# /etc/wireguard/wg0.conf — on the server
[Interface]
PrivateKey = <server_private_key>
Address    = 10.8.0.1/24
ListenPort = 51820
DNS        = 1.1.1.1

# Enable IP forwarding (for routing traffic through the VPN)
PostUp   = iptables -A FORWARD -i %i -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i %i -j ACCEPT; iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE

[Peer]
# dev-laptop
PublicKey  = <client_1_public_key>
AllowedIPs = 10.8.0.2/32

[Peer]
# ci-runner-01
PublicKey  = <client_2_public_key>
AllowedIPs = 10.8.0.3/32
```

## Client config

```ini
# /etc/wireguard/wg0.conf — on each client
[Interface]
PrivateKey = <client_private_key>
Address    = 10.8.0.2/32
DNS        = 1.1.1.1

[Peer]
PublicKey  = <server_public_key>
Endpoint   = your-server-ip:51820

# Route all traffic through VPN
AllowedIPs = 0.0.0.0/0, ::/0

# Keep connection alive through NAT
PersistentKeepalive = 25
```

## Start and enable

```bash
# Server
sudo systemctl enable --now wg-quick@wg0
sudo wg show

# Enable IP forwarding permanently
echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

## Monitor

```bash
# Live peer status
sudo wg show

# Per-peer traffic
sudo wg show wg0 transfer

# Add a peer without restarting
sudo wg set wg0 peer <new_client_pubkey> allowed-ips 10.8.0.4/32
```

## wg-easy — web UI for WireGuard

```yaml
# docker-compose.yml
services:
  wg-easy:
    image: ghcr.io/wg-easy/wg-easy:latest
    environment:
      WG_HOST:           your-server.com
      PASSWORD_HASH:     $2b$12$...  # bcrypt hash of admin password
      WG_DEFAULT_ADDRESS: 10.8.0.x
      WG_DEFAULT_DNS:    1.1.1.1
    volumes:
      - wg-easy:/etc/wireguard
    ports:
      - '51820:51820/udp'
      - '51821:51821/tcp'   # web UI
    cap_add: [NET_ADMIN, SYS_MODULE]
    sysctls:
      - net.ipv4.conf.all.src_valid_mark=1
      - net.ipv4.ip_forward=1

volumes:
  wg-easy:
```

wg-easy provides a web UI for managing peers — generate client configs with a QR code, revoke peers, and monitor traffic without touching config files.

WireGuard vs OpenVPN vs Tailscale: WireGuard is a protocol — fast, modern, kernel-native. OpenVPN is heavier but more configurable for enterprise scenarios. Tailscale uses WireGuard under the hood with a managed control plane — zero server setup, peer-to-peer mesh, ACL policies. The Construx default: Tailscale for development team connectivity; self-hosted WireGuard for production infrastructure where data sovereignty matters.
