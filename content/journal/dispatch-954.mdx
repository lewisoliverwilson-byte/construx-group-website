`core.pager = delta`. Syntax highlighting on every diff. Side-by-side for reviews. Zero config once set.

## Installation and git configuration

```bash
# Install delta (Rust binary — fast, single binary)
# macOS
brew install git-delta

# Linux (Debian/Ubuntu)
cargo install git-delta
# or download from GitHub releases

# Configure git to use delta as the pager
git config --global core.pager delta
git config --global interactive.diffFilter 'delta --color-only'
git config --global delta.navigate true    # n/N to jump between diff sections
git config --global delta.light false      # dark terminal theme
git config --global merge.conflictstyle zdiff3   # best with delta

# ~/.gitconfig equivalent:
cat ~/.gitconfig | grep -A 10 '\[delta\]'
# [delta]
#   navigate    = true
#   light       = false
#   side-by-side = false      # or true for side-by-side by default
#   line-numbers = true
#   syntax-theme = Dracula    # uses bat's theme names
#   file-style   = bold yellow
#   hunk-header-style = file line-number
#   diff-so-fancy = false
#
# [interactive]
#   diffFilter = delta --color-only  # for git add -p
```

## Diff, show, and log

```bash
# delta transforms diff output automatically via core.pager
git diff HEAD~1..HEAD

# Output (with delta):
# ─────────────────────────────────────────────────────────
# services/api/orders/handler.go
# ─────────────────────────────────────────────────────────
#  42  42 │ func (h *Handler) CreateOrder(w http.ResponseWriter, r *http.Request) {
#  43     │-   order, err := h.service.Create(r.Context(), parseInput(r))
#     43 │+   input, err := parseOrderInput(r)
#     44 │+   if err != nil {
#     45 │+       http.Error(w, "invalid input", http.StatusBadRequest)
#     46 │+       return
#     47 │+   }
#     48 │+   order, err := h.service.Create(r.Context(), input)
#  44  49 │   if err != nil {
# (green = added, red = removed, with syntax highlighting)

# git show: view a commit with delta paging
git show abc123

# git log -p: show all commits with their diffs
git log -p HEAD~5..HEAD

# git stash show: view a stash diff
git stash show -p stash@{0}

# git blame: delta adds color and reformats blame output
git blame services/api/orders/handler.go
```

## Side-by-side mode

```bash
# Enable side-by-side globally
git config --global delta.side-by-side true

# Or use the --side-by-side flag per-command
git diff --side-by-side HEAD~1..HEAD

# Side-by-side output:
# ┌──────────────────────────────────────┬──────────────────────────────────────┐
# │ services/api/orders/handler.go:43    │ services/api/orders/handler.go:43    │
# │                                      │                                      │
# │  order, err := h.service.Create(    │  input, err := parseOrderInput(r)   │
# │    r.Context(), parseInput(r))       │  if err != nil {                     │
# │                                      │      http.Error(w, "invalid input",  │
# │                                      │          http.StatusBadRequest)      │
# │                                      │      return                          │
# │                                      │  }                                   │
# │                                      │  order, err := h.service.Create(    │
# │                                      │    r.Context(), input)               │
# └──────────────────────────────────────┴──────────────────────────────────────┘

# --width: override terminal width (useful for narrower panes)
git diff HEAD~1 | delta --width 160 --side-by-side

# Disable side-by-side for a single command (override global config)
git diff HEAD~1 | delta --side-by-side=false
```

## Merge conflict resolution

```bash
# delta understands merge conflicts:
# Configure zdiff3 conflict style for richer output
git config --global merge.conflictstyle zdiff3

# When you open a conflicted file, delta colors it:
# <<<<<<< HEAD (red header)
# [current version in red]
# ||||||| base (yellow — only with zdiff3)
# [common ancestor in yellow — shows what both sides changed from]
# ======= (separator)
# [incoming version in green]
# >>>>>>> feature/my-branch (green header)

# With zdiff3 + delta, you can see WHAT changed on both sides
# relative to the common ancestor — much easier to understand

# grep: delta highlights grep matches
git grep 'parseOrderInput' | delta
# (syntax-highlighted output with match context)
```

## Themes and customization

```bash
# delta uses bat's syntax themes
delta --list-syntax-themes | head -20
# 1337
# Coldark-Cold
# Coldark-Dark
# Dracula
# Monokai Extended
# Nord
# OneHalfDark
# Solarized (dark)
# Visual Studio Dark+

# Try a theme without changing config
git diff HEAD~1 | delta --syntax-theme "Nord"

# Custom colors for diff headers
cat ~/.gitconfig
# [delta]
#   syntax-theme  = Dracula
#   file-style    = bold yellow ul
#   file-decoration-style = none
#   hunk-header-style     = file line-number syntax
#   hunk-header-decoration-style = cyan box
#   minus-style   = syntax "#3f0001"  # dark red background for deletions
#   plus-style    = syntax "#003800"  # dark green background for additions
#   line-numbers-zero-style   = "#3b4261"
#   line-numbers-left-style   = cyan
#   line-numbers-right-style  = cyan

# diff-highlight compatibility mode (similar visual to diff-highlight + diff-so-fancy)
git diff HEAD~1 | delta --diff-so-fancy
```

delta vs diff-so-fancy vs difftastic: diff-so-fancy is the older, shell-based alternative — it does basic highlighting but doesn't understand syntax. difftastic is structurally aware — it parses the code into an AST and diffs at the syntax level (moves don't show as delete+add, they show as a single change). delta is in the middle: it does syntax highlighting via tree-sitter but diffs at the line level like git does. The practical choice: delta for daily `git diff` (fast, beautiful, zero configuration overhead), difftastic for reviewing large refactors where line-level diffs are noisy (a function moved to another file shows as two separate changes in delta but as a move in difftastic). Configure both as aliases and switch based on the review context.
