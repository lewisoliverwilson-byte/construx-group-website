title: "Argo CD: GitOps continuous delivery for Kubernetes"
date: "2032-04-06"
excerpt: "Argo CD is a declarative GitOps CD tool for Kubernetes: it watches a Git repository for Kubernetes manifests (raw YAML, Helm charts, Kustomize overlays, or Jsonnet) and continuously reconciles the live cluster state to match. The Git repository becomes the single source of truth — deployments happen by merging to a branch, not by running kubectl apply. Argo CD monitors for drift (cluster state diverging from Git) and can auto-sync to correct it. It provides a web UI, CLI (argocd), and Prometheus metrics for observability into what's deployed where."

Git is the source of truth. Drift is detected. Sync is automatic.

## Application definition and structure

```yaml
# apps/construx-api/application.yaml — the Argo CD Application CRD
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: construx-api
  namespace: argocd          # Argo CD runs in its own namespace
  finalizers:
    - resources-finalizer.argocd.argoproj.io  # Cascade-delete on app removal

spec:
  project: construx-prod     # AppProject: defines RBAC and allowed sources

  source:
    repoURL: https://git.construx.io/k8s/construx-apps
    targetRevision: HEAD      # Tracks main branch; could pin to a tag
    path: apps/construx-api   # Directory with manifests within the repo

  destination:
    server: https://kubernetes.default.svc   # In-cluster API server
    namespace: construx

  syncPolicy:
    automated:
      prune: true             # Delete resources removed from Git
      selfHeal: true          # Re-sync if cluster drifts from Git
      allowEmpty: false       # Don't prune everything if the source becomes empty

    syncOptions:
      - CreateNamespace=true
      - PrunePropagationPolicy=foreground
      - ApplyOutOfSyncOnly=true    # Only re-apply changed resources

    retry:
      limit: 3                # Retry failed syncs up to 3 times
      backoff:
        duration: 30s
        factor: 2
        maxDuration: 5m
```

## App-of-apps pattern — managing multiple applications

```yaml
# The "app-of-apps" pattern: one root Application that deploys other Applications
# apps/root-application.yaml (deployed manually once to bootstrap)

apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: root
  namespace: argocd
spec:
  source:
    repoURL: https://git.construx.io/k8s/construx-apps
    targetRevision: HEAD
    path: apps              # Directory containing all Application manifests
  destination:
    server: https://kubernetes.default.svc
    namespace: argocd
  syncPolicy:
    automated:
      prune: true
      selfHeal: true

# Repository structure:
# apps/
#   construx-api/
#     application.yaml       ← Application CR
#     deployment.yaml        ← actual Kubernetes resources
#     service.yaml
#     hpa.yaml
#   construx-worker/
#     application.yaml
#     ...
#   nats-cluster/
#     application.yaml
#     ...
```

## CLI workflow — inspect, diff, sync

```bash
# Login to Argo CD API server
argocd login argocd.construx.internal --username admin --grpc-web

# List all applications
argocd app list
# NAME                 CLUSTER      NAMESPACE  PROJECT       STATUS  HEALTH
# construx-api         in-cluster   construx   construx-prod Synced  Healthy
# construx-analytics   in-cluster   construx   construx-prod OutOfSync Degraded

# Show detailed application status
argocd app get construx-api
# Summary:
#   Server:    https://kubernetes.default.svc
#   Namespace: construx
#   URL:       https://argocd.construx.internal/applications/construx-api
#   Repo:      https://git.construx.io/k8s/construx-apps
#   Target:    HEAD
#   Path:      apps/construx-api
#   SyncWindow: Sync Allowed
# History ID  Date                          Revision
#   8         2032-03-25 14:32:01 UTC       a4f8c2d
#   7         2032-03-24 09:15:44 UTC       b7e9d1f

# Show diff between desired (Git) and live state
argocd app diff construx-analytics
# ===== apps/v1/Deployment construx/construx-analytics =====
# +  minReadySeconds: 30          ← added in Git, not yet in cluster

# Sync a specific app (apply Git state to cluster)
argocd app sync construx-analytics

# Hard refresh — ignore cache, re-fetch from Git and cluster
argocd app get construx-analytics --hard-refresh

# Rollback to a previous version
argocd app rollback construx-api 7   # Roll back to history ID 7
```

## Progressive delivery with Argo Rollouts

```yaml
# Replace Deployment with Rollout for canary/blue-green strategies
# apps/construx-api/rollout.yaml

apiVersion: argoproj.io/v1alpha1
kind: Rollout
metadata:
  name: construx-api
  namespace: construx
spec:
  replicas: 10
  selector:
    matchLabels:
      app: construx-api
  template:
    metadata:
      labels:
        app: construx-api
    spec:
      containers:
        - name: construx-api
          image: construx.registry.io/construx-api:v2.4.1

  strategy:
    canary:
      steps:
        - setWeight: 10           # 10% traffic to canary
        - pause:
            duration: 5m          # Wait 5 minutes
        - setWeight: 30           # 30%
        - pause: {}               # Pause indefinitely (manual gate)
        - setWeight: 100          # Full rollout

      canaryService: construx-api-canary
      stableService: construx-api-stable
      trafficRouting:
        nginx:
          stableIngress: construx-api-ingress

# Monitor the rollout
argocd-rollouts get rollout construx-api --watch
```

GitOps vs push-based CD: Traditional CD (Jenkins, GitHub Actions deploy steps) pushes changes to the cluster — the pipeline has kubectl credentials and applies manifests during a pipeline run. GitOps is pull-based — Argo CD runs inside the cluster, pulls from Git, and applies. The security model is inverted: instead of giving your CI system cluster access, you give Argo CD Git access. Drift detection is a bonus: Argo CD continuously monitors and alerts (or auto-corrects) if someone runs kubectl apply manually outside the GitOps flow. The tradeoff is Git as the bottleneck — every change, including hotfixes, must go through a Git commit, which can feel slow in an incident.
