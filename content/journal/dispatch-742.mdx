Node.js 22 LTS is the boring choice. Boring means stable, supported, and running in production everywhere.

## What changed in Node.js 22

### Native glob and recursive rm

```ts
import { glob, rm } from 'node:fs/promises';

// Before: needed glob package
// After: built in
const tsFiles = await Array.fromAsync(glob('src/**/*.ts'));

// Recursive delete without rimraf
await rm('dist', { recursive: true, force: true });
```

### Built-in WebSocket client

```ts
// No need for ws package for client-side WebSocket
const ws = new WebSocket('wss://api.construxgroup.io/ws');

ws.addEventListener('open', () => {
  ws.send(JSON.stringify({ type: 'subscribe', channel: 'notifications' }));
});

ws.addEventListener('message', (event) => {
  const data = JSON.parse(event.data);
  console.log('received:', data);
});
```

### require(ESM) — synchronous CJS/ESM interop

```ts
// CJS file (.cjs or type: "commonjs")
// Can now require() ES modules directly
const { myExport } = require('./my-esm-module.mjs');
// No longer requires dynamic import() or top-level await
```

This resolves the longest-running pain point in the Node.js ecosystem: mixing CJS and ESM packages.

### Improved watch mode

```bash
# Re-runs the script when any file it imports changes
node --watch src/server.ts

# Watch specific files only
node --watch-path=src src/server.ts
```

`--watch` is now production-quality. It replaces `nodemon` for most development use cases.

## Node.js 22 vs Bun vs Deno

The real comparison is not about features — it is about ecosystem and deployment:

**Node.js 22 LTS:** Runs everywhere. Every hosting provider supports it. Every npm package targets it. No surprises. The safe default for a new project with no special requirements.

**Bun:** Faster startup (5-10x), faster package installs (10-25x), TypeScript native. Growing ecosystem compatibility. Best for: scripts, CLIs, new projects where you control the runtime. Not yet universally supported by hosting providers.

**Deno 2:** Secure by default, TypeScript native, npm compatible. Good tooling (fmt, lint, test built in). Growing hosting support. Best for: security-conscious deployments, projects that want permission-based file/network access.

## Targeting Node.js 22

```json
// package.json
{
  "engines": {
    "node": ">=22.0.0"
  }
}
```

```ts
// tsconfig.json
{
  "compilerOptions": {
    "target": "ES2022",
    "lib":    ["ES2022"],
    "module": "NodeNext"
  }
}
```

```yaml
# .node-version or .nvmrc
22
```

## What Node.js 22 does not have

No built-in TypeScript execution (use tsx or Bun). No built-in test runner UI (use Vitest). No built-in formatter or linter (use Biome). No built-in bundler (use Vite or esbuild). Node.js is a runtime, not a full toolchain. The toolchain sits around it.
