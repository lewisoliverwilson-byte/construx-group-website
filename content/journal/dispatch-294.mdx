Drizzle is an ORM in the sense that it gives you type-safe access to your database from TypeScript. It's not an ORM in the sense of abstracting away SQL — you see the SQL, you write the SQL-like query builder, and the generated queries are what you'd write by hand.

This is the right approach for products where query performance matters and you don't want to be surprised by what your ORM sends to the database.

## Schema definition

Schemas are defined in TypeScript, which becomes the source of truth for both the database structure and the TypeScript types:

```ts
// packages/db/src/schema/scans.ts
import {
  pgTable,
  uuid,
  text,
  numeric,
  timestamp,
  index,
  integer,
} from 'drizzle-orm/pg-core';
import { users } from './users';

export const scans = pgTable(
  'scans',
  {
    id: uuid('id').primaryKey().defaultRandom(),
    userId: uuid('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
    asin: text('asin').notNull(),
    title: text('title'),
    buyPrice: numeric('buy_price', { precision: 10, scale: 2 }).notNull(),
    salePrice: numeric('sale_price', { precision: 10, scale: 2 }).notNull(),
    margin: numeric('margin', { precision: 10, scale: 2 }),
    marginPct: numeric('margin_pct', { precision: 5, scale: 2 }),
    confidence: text('confidence', { enum: ['HIGH', 'MEDIUM', 'LOW'] }),
    source: text('source', { enum: ['manual', 'bulk', 'api'] }).default('manual'),
    scannedAt: timestamp('scanned_at', { withTimezone: true }).defaultNow().notNull(),
  },
  (table) => ({
    userIdx: index('scans_user_idx').on(table.userId, table.scannedAt.desc()),
    asinIdx: index('scans_asin_idx').on(table.asin),
  }),
);

// Inferred types — no duplication
export type Scan = typeof scans.$inferSelect;
export type NewScan = typeof scans.$inferInsert;
```

The `$inferSelect` and `$inferInsert` types are derived from the schema. If you add a column, both the database migration and the TypeScript type update together.

## Basic queries

```ts
import { db } from '@/lib/db';
import { scans } from '@/lib/schema';
import { eq, desc, and, gte, lte, count, avg } from 'drizzle-orm';

// Select with filter
const userScans = await db
  .select()
  .from(scans)
  .where(eq(scans.userId, userId))
  .orderBy(desc(scans.scannedAt))
  .limit(50);

// Typed return: Scan[]
```

```ts
// Insert
const [newScan] = await db.insert(scans)
  .values({
    userId,
    asin: 'B08N5WRWNW',
    buyPrice: '12.00',
    salePrice: '25.00',
    margin: '9.00',
    marginPct: '36.00',
    confidence: 'HIGH',
  })
  .returning();

// Typed return: Scan
```

```ts
// Update
await db.update(scans)
  .set({ margin: newMargin, marginPct: newMarginPct })
  .where(eq(scans.id, scanId));
```

## Joins

```ts
import { users } from '@/lib/schema';

// Inner join — Drizzle infers column names from schema
const scansWithUser = await db
  .select({
    scanId: scans.id,
    asin: scans.asin,
    margin: scans.margin,
    userName: users.name,
    userEmail: users.email,
  })
  .from(scans)
  .innerJoin(users, eq(scans.userId, users.id))
  .where(eq(scans.confidence, 'HIGH'))
  .orderBy(desc(scans.scannedAt));

// Return type is inferred from the select object — no cast needed
type ScansWithUser = typeof scansWithUser[number];
```

## Aggregations

```ts
// Portfolio stats for a user
const [stats] = await db
  .select({
    totalScans: count(scans.id),
    avgMargin: avg(scans.marginPct),
    highConfidenceCount: count(sql`CASE WHEN ${scans.confidence} = 'HIGH' THEN 1 END`),
  })
  .from(scans)
  .where(
    and(
      eq(scans.userId, userId),
      gte(scans.scannedAt, startDate),
      lte(scans.scannedAt, endDate),
    )
  );
```

## Transactions

```ts
// Scan + portfolio item creation in a transaction
const result = await db.transaction(async (tx) => {
  const [scan] = await tx.insert(scans)
    .values({ userId, asin, buyPrice, salePrice, margin, marginPct })
    .returning();

  const [portfolioItem] = await tx.insert(portfolioItems)
    .values({ userId, scanId: scan.id, asin, targetMarginPct: '30.00' })
    .returning();

  return { scan, portfolioItem };
});
```

If either insert throws, the transaction rolls back automatically.

## Migrations

Drizzle's migration workflow: modify the schema file, generate a migration, apply it.

```bash
# Generate migration from schema diff
npx drizzle-kit generate

# Apply pending migrations
npx drizzle-kit migrate
```

The generated migration is a plain SQL file in `drizzle/migrations/`. You can read it, edit it, and commit it. No opaque migration state — it's just SQL.

```sql
-- drizzle/migrations/0004_add_scan_confidence.sql
ALTER TABLE scans ADD COLUMN confidence text CHECK (confidence IN ('HIGH', 'MEDIUM', 'LOW'));
CREATE INDEX scans_confidence_idx ON scans (confidence) WHERE confidence IS NOT NULL;
```

## Querying raw SQL for complex operations

When the query builder doesn't cover what you need, escape to raw SQL:

```ts
import { sql } from 'drizzle-orm';

// Window function for scan ranking within a user's history
const rankedScans = await db.execute(sql`
  SELECT
    id,
    asin,
    margin_pct,
    scanned_at,
    RANK() OVER (PARTITION BY user_id ORDER BY margin_pct DESC) as margin_rank
  FROM scans
  WHERE user_id = ${userId}
    AND scanned_at > NOW() - INTERVAL '30 days'
`);
```

The `sql` tagged template literal is parameterised — values are passed as query parameters, not string-interpolated. No SQL injection risk.

## Connection pooling

In a Next.js serverless environment, connections need pooling. Each Lambda invocation creates a new process; without pooling, you'd exhaust Postgres's connection limit quickly:

```ts
// packages/db/src/client.ts
import { Pool } from 'pg';
import { drizzle } from 'drizzle-orm/node-postgres';
import * as schema from './schema';

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 5,              // Max 5 connections per Lambda instance
  idleTimeoutMillis: 10_000,
  connectionTimeoutMillis: 3_000,
});

export const db = drizzle(pool, { schema });
```

With PgBouncer or Supabase's connection pooler in front of Postgres, the `max` per instance can be lower — the pooler handles connection multiplexing at the infrastructure level.

## Why not Prisma

Prisma is excellent for teams that want to think less about SQL. The generated client is ergonomic, the schema language is cleaner than Drizzle's TypeScript DSL, and the VS Code extension is polished.

The reasons we chose Drizzle: raw SQL escape hatch without ceremony, migration files are readable SQL, no Prisma Client generation step, and the query builder maps closely enough to SQL that performance debugging is straightforward. For products where we care about the exact query hitting the database, Drizzle is the better fit.
