Content Security Policy (CSP) is a whitelist for your app. It tells the browser: these are the only sources from which you're allowed to load scripts, styles, images, and fonts. If an attacker injects a `<script>` tag pointing to their server, the browser refuses to load it.

CSP doesn't prevent XSS vulnerabilities from existing — but it prevents them from executing.

## The header structure

CSP is set via the `Content-Security-Policy` header. Each directive controls a resource type:

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-RANDOM_VALUE';
  style-src 'self' 'nonce-RANDOM_VALUE' https://fonts.googleapis.com;
  img-src 'self' data: https://your-cdn.com;
  font-src 'self' https://fonts.gstatic.com;
  connect-src 'self' https://api.anthropic.com https://posthog.com;
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self';
```

The key directives:
- `default-src 'self'` — fallback for unspecified directives, allow only same origin
- `script-src` — controls JavaScript loading; `'nonce-...'` allows inline scripts with a specific nonce
- `frame-ancestors 'none'` — prevents your site being embedded in iframes (blocks clickjacking)
- `base-uri 'self'` — prevents base tag injection
- `form-action 'self'` — prevents forms from submitting to external URLs

## Implementation in Next.js

Next.js middleware is the right place to set CSP, since it runs on every request and can generate a per-request nonce:

```ts
// middleware.ts
import { NextRequest, NextResponse } from 'next/server';
import crypto from 'crypto';

function generateNonce(): string {
  return crypto.randomBytes(16).toString('base64');
}

export function middleware(req: NextRequest) {
  const nonce = generateNonce();

  const csp = [
    `default-src 'self'`,
    `script-src 'self' 'nonce-${nonce}' https://cdn.posthog.com`,
    `style-src 'self' 'nonce-${nonce}' https://fonts.googleapis.com`,
    `img-src 'self' data: blob: https://*.amazonaws.com`,
    `font-src 'self' https://fonts.gstatic.com`,
    `connect-src 'self' https://us.posthog.com https://api.anthropic.com`,
    `frame-ancestors 'none'`,
    `base-uri 'self'`,
    `form-action 'self'`,
    `upgrade-insecure-requests`,
  ].join('; ');

  const headers = new Headers(req.headers);
  headers.set('x-nonce', nonce);

  const res = NextResponse.next({ request: { headers } });
  res.headers.set('Content-Security-Policy', csp);
  return res;
}
```

Pass the nonce via header to your layout so it can inject it into `<script>` and `<style>` tags:

```tsx
// app/layout.tsx
import { headers } from 'next/headers';

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  const nonce = (await headers()).get('x-nonce') ?? '';

  return (
    <html>
      <head>
        <script
          nonce={nonce}
          dangerouslySetInnerHTML={{
            __html: `window.__nonce='${nonce}'`,
          }}
        />
      </head>
      <body>{children}</body>
    </html>
  );
}
```

Third-party scripts (analytics, chat widgets) also need the nonce:

```tsx
<Script
  src="https://cdn.posthog.com/posthog.js"
  nonce={nonce}
  strategy="afterInteractive"
/>
```

## Report-only mode for rollout

Don't start with enforcement. Start with `Content-Security-Policy-Report-Only` — it reports violations without blocking anything:

```ts
res.headers.set('Content-Security-Policy-Report-Only', csp + `; report-uri /api/csp-report`);
```

```ts
// app/api/csp-report/route.ts
export async function POST(req: Request) {
  const report = await req.json();
  console.error('[CSP Violation]', JSON.stringify(report));
  // Send to your observability platform
  return new Response(null, { status: 204 });
}
```

Run in report-only for a week. Watch the violations. Add legitimate sources to your policy. Then switch to enforcement mode.

## Common pitfalls

**`'unsafe-inline'` defeats CSP for scripts.** If you add it to allow inline event handlers or `<script>` tags, you've opened the hole CSP was meant to close. Use nonces instead.

**`'unsafe-eval'` opens eval-based attacks.** Some libraries (older bundlers, certain animation libraries) require `eval`. Find alternatives or use a strict-dynamic approach.

**Third-party tag managers are CSP's natural enemy.** GTM injects arbitrary scripts. If you use it, you'll need `'unsafe-inline'` or a very permissive `script-src`. The security tradeoff is real — GTM and a strict CSP are in tension.

A CSP that takes a week to tune properly is normal. The violations report mode is how you find everything that needs to be in the whitelist before you can enforce it.
