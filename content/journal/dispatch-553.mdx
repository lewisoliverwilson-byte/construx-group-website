Getting a language model to produce structured JSON reliably has historically required prompt engineering ("respond in JSON format", "do not include markdown code fences") and defensive parsing. Structured outputs eliminate this entirely — you define a schema, the model produces exactly that schema, every time.

## The basic pattern

```ts
import Anthropic from '@anthropic-ai/sdk';
import { z } from 'zod';

const client = new Anthropic();

// Define your schema
const ProductSchema = z.object({
  name:        z.string(),
  category:    z.enum(['electronics', 'clothing', 'furniture', 'food']),
  price:       z.number().positive(),
  inStock:     z.boolean(),
  tags:        z.array(z.string()),
  description: z.string().max(200),
});

type Product = z.infer<typeof ProductSchema>;
```

```ts
// Request structured output
const response = await client.messages.create({
  model: 'claude-opus-4-8',
  max_tokens: 1024,
  tools: [{
    name:        'extract_product',
    description: 'Extract product information from the provided text',
    input_schema: {
      type: 'object',
      properties: {
        name:        { type: 'string' },
        category:    { type: 'string', enum: ['electronics', 'clothing', 'furniture', 'food'] },
        price:       { type: 'number' },
        inStock:     { type: 'boolean' },
        tags:        { type: 'array', items: { type: 'string' } },
        description: { type: 'string' },
      },
      required: ['name', 'category', 'price', 'inStock', 'tags', 'description'],
    },
  }],
  tool_choice: { type: 'tool', name: 'extract_product' },
  messages: [{
    role:    'user',
    content: `Extract product info from: "Sony WH-1000XM5 wireless headphones, £279, available now. 
              Industry-leading noise cancelling, 30hr battery, premium audio quality."`,
  }],
});

// Parse the structured output
const toolUse = response.content.find(b => b.type === 'tool_use');
if (!toolUse || toolUse.type !== 'tool_use') throw new Error('No tool use in response');

const product = ProductSchema.parse(toolUse.input);
// product is typed as Product, guaranteed to match the schema
```

The `tool_choice: { type: 'tool', name: 'extract_product' }` forces the model to use the tool rather than responding in text. The model cannot respond with anything other than a valid call to `extract_product`.

## Classification at scale

Structured outputs are particularly useful for classification tasks — run thousands of items through Claude and get consistent, typed results:

```ts
const ClassificationSchema = z.object({
  category:   z.enum(['complaint', 'question', 'praise', 'refund_request', 'other']),
  sentiment:  z.enum(['positive', 'neutral', 'negative']),
  priority:   z.enum(['low', 'medium', 'high', 'urgent']),
  summary:    z.string().max(100),
  actionRequired: z.boolean(),
});

async function classifyTicket(ticketText: string) {
  const response = await client.messages.create({
    model:      'claude-haiku-4-5-20251001', // use Haiku for high-volume classification
    max_tokens: 512,
    tools: [{
      name: 'classify_ticket',
      description: 'Classify a customer support ticket',
      input_schema: {
        type: 'object',
        properties: {
          category:       { type: 'string', enum: ['complaint', 'question', 'praise', 'refund_request', 'other'] },
          sentiment:      { type: 'string', enum: ['positive', 'neutral', 'negative'] },
          priority:       { type: 'string', enum: ['low', 'medium', 'high', 'urgent'] },
          summary:        { type: 'string' },
          actionRequired: { type: 'boolean' },
        },
        required: ['category', 'sentiment', 'priority', 'summary', 'actionRequired'],
      },
    }],
    tool_choice: { type: 'tool', name: 'classify_ticket' },
    messages: [{ role: 'user', content: ticketText }],
  });

  const toolUse = response.content.find(b => b.type === 'tool_use');
  if (!toolUse || toolUse.type !== 'tool_use') throw new Error('Expected tool use');

  return ClassificationSchema.parse(toolUse.input);
}
```

Run this across thousands of support tickets in parallel with `Promise.all`. Each result is typed and validated.

## Error handling

Structured outputs via tool use don't fail in ways that need complex handling — if the model uses the tool (which it's forced to by `tool_choice`), the input will match the declared schema. The main failure mode is the model returning content without using the tool:

```ts
const toolUse = response.content.find(b => b.type === 'tool_use');
if (!toolUse) {
  // This shouldn't happen with tool_choice: { type: 'tool' }
  // but handle it defensively
  throw new Error(`Unexpected response: ${JSON.stringify(response.content)}`);
}
```

Validate with Zod after parsing for type-narrowing, even if you trust the model:

```ts
const result = ProductSchema.safeParse(toolUse.input);
if (!result.success) {
  console.error('Schema mismatch:', result.error);
  throw new Error('Unexpected schema from model');
}
```

## Model selection

Use `claude-haiku-4-5-20251001` for high-volume, simple classification tasks. Use `claude-sonnet-4-6` for complex extraction and reasoning. Use `claude-opus-4-8` for the most nuanced tasks where accuracy matters most.

Haiku handles simple classification at a fraction of the cost of Opus and at low latency. For 10,000 support tickets per day, the cost difference is significant. For a one-off complex analysis where accuracy is paramount, use Opus.

## What we use this for

Scoutr uses structured outputs to classify product listings by category, extract pricing signals from unstructured retailer descriptions, and tag products with normalised attributes. Before structured outputs, we spent significant effort on prompt engineering and response parsing. Now it's a schema definition and a typed response.
