Monorepos without a build system become slow because every package rebuilds from scratch on every CI run. Turborepo solves this with a content-addressed cache and a task graph that knows what depends on what.

## Setup

```bash
npm install turbo --save-dev
# or add to an existing monorepo
npx create-turbo@latest
```

## turbo.json

```json
{
  "$schema": "https://turbo.build/schema.json",
  "globalDependencies": ["**/.env.*local"],
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "inputs":  ["$TURBO_DEFAULT$", ".env*"],
      "outputs": [".next/**", "!.next/cache/**", "dist/**"]
    },
    "typecheck": {
      "dependsOn": ["^build"],
      "outputs": []
    },
    "lint": {
      "outputs": []
    },
    "test": {
      "dependsOn": ["build"],
      "outputs": ["coverage/**"],
      "cache": false
    },
    "dev": {
      "cache": false,
      "persistent": true
    }
  }
}
```

The `^` prefix on `dependsOn` means "all packages this one depends on must complete their `build` first." No explicit ordering needed — Turbo derives the graph from your `package.json` workspace dependencies.

## Workspace structure

```
construx-monorepo/
├── apps/
│   ├── web/          # Next.js app
│   ├── api/          # Hono API server
│   └── docs/         # Documentation site
├── packages/
│   ├── ui/           # Shared React components
│   ├── db/           # Prisma schema + client
│   ├── config-ts/    # Shared tsconfig
│   └── config-eslint/ # Shared ESLint config
├── package.json      # Workspaces definition
└── turbo.json
```

```json
// package.json (root)
{
  "name": "construx-monorepo",
  "workspaces": ["apps/*", "packages/*"],
  "scripts": {
    "build":     "turbo build",
    "dev":       "turbo dev",
    "lint":      "turbo lint",
    "typecheck": "turbo typecheck",
    "test":      "turbo test"
  },
  "devDependencies": {
    "turbo": "^2.0.0"
  }
}
```

## Running tasks

```bash
# Build all packages and apps in dependency order
turbo build

# Build only the web app and its dependencies
turbo build --filter=web

# Build everything that has changed since the last git tag
turbo build --filter=[HEAD^1]

# Build packages affected by changes in a specific file
turbo build --filter=...[packages/ui]

# Run dev for web and api in parallel
turbo dev --filter=web --filter=api

# Dry run: see what would execute without running it
turbo build --dry-run
```

## Remote caching (Vercel)

```bash
# Authenticate with Vercel's remote cache
npx turbo login
npx turbo link

# Now CI builds share the cache with every developer's machine
# First run builds; all subsequent runs hit the cache if inputs are unchanged
```

```yaml
# .github/workflows/ci.yml
- name: Build
  run: turbo build
  env:
    TURBO_TOKEN:    ${{ secrets.TURBO_TOKEN }}
    TURBO_TEAM:     ${{ vars.TURBO_TEAM }}
    # These two env vars activate remote caching automatically
```

## Self-hosted remote cache

```bash
# Use ducktape-cache or your own S3 bucket instead of Vercel
npm install --save-dev @ducktape/cache

# turbo.json
{
  "remoteCache": {
    "apiUrl": "https://cache.construxgroup.io"
  }
}
```

## Pipeline output

```
• Packages in scope: web, api, ui, db
• Running build in 4 packages

 Tasks:    4 successful, 4 total
 Cached:   3 cached, 4 total
 Time:     843ms >>> FULL TURBO
```

`FULL TURBO` means every task was a cache hit. No compilation occurred — outputs were restored from cache in under a second.

## Turborepo vs Nx vs Lerna

Turborepo: fast cache-first build system, minimal config, Vercel-hosted remote cache. Best for teams adopting monorepos without wanting to learn a complex toolchain. Nx: more opinionated, code generators, module federation, plugin ecosystem, enterprise-grade. Lerna: package publishing and versioning, not a build system — now delegates scheduling to Nx. Use Turborepo when you want monorepo build speed without ceremony.
