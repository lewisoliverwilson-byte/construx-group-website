title: "Tetragon: eBPF-based runtime security and enforcement in Kubernetes"
date: "2033-04-13"
excerpt: "Tetragon is a Cilium sub-project that uses eBPF to observe and enforce security policy at the Linux kernel level. Unlike Falco (which intercepts syscalls via the kernel module or eBPF and reports events) or OPA/Kyverno (which enforce Kubernetes admission policy), Tetragon can enforce in-kernel: a TracingPolicy can drop a syscall, kill a process, or SIGKILL a container before the action completes. Tetragon attaches eBPF programs to kernel functions (kprobes, tracepoints, LSM hooks) and streams structured events — process executes, file opens, network connects, privilege escalations — as JSON to stdout, from where they feed into Loki, Kafka, or a SIEM. The in-kernel enforcement is the differentiator: you can write a policy that kills any process that opens /etc/shadow outside a known path, and the enforcement happens before the syscall returns."

TracingPolicy. In-kernel enforcement. Process lifecycle. Network observability. LSM hooks.

## TracingPolicy: observe and enforce

```yaml
# TracingPolicy: attaches eBPF programs to kernel events
# Selector matches pods; kprobes/tracepoints define what to watch

# Policy: alert on any write to /etc/passwd or /etc/shadow
apiVersion: cilium.io/v1alpha1
kind: TracingPolicy
metadata:
  name: protect-etc-passwd
spec:
  kprobes:
    - call: "security_file_open"
      syscall: false
      return: false
      args:
        - index: 0
          type: "file"
      selectors:
        # Match: file path contains /etc/passwd or /etc/shadow
        - matchArgs:
            - index: 0
              operator: "Prefix"
              values:
                - "/etc/passwd"
                - "/etc/shadow"
          matchActions:
            # SIGKILL the process attempting the open
            - action: Sigkill
          matchNamespaces:
            - namespace: Pid
              operator: NotIn
              values: ["0"]   # exclude host PIDs (root kernel threads)

---
# Policy: detect privilege escalation — process calls setuid(0)
apiVersion: cilium.io/v1alpha1
kind: TracingPolicy
metadata:
  name: detect-setuid-escalation
spec:
  kprobes:
    - call: "sys_setuid"
      syscall: true
      args:
        - index: 0
          type: "int"
      selectors:
        - matchArgs:
            - index: 0
              operator: Equal
              values:
                - "0"     # setuid(0) = escalate to root
          matchActions:
            - action: Post   # emit an event (observe only — don't kill)

---
# Policy: block outbound connections to non-approved CIDRs from sensitive pods
apiVersion: cilium.io/v1alpha1
kind: TracingPolicy
metadata:
  name: block-egress-from-payment-pods
spec:
  kprobes:
    - call: "tcp_connect"
      syscall: false
      args:
        - index: 0
          type: "sock"
      selectors:
        - matchPodLabels:
            - key: app
              operator: In
              values: ["construx-payments"]
          matchArgs:
            - index: 0
              operator: NotDPrefix    # not in approved CIDR
              values:
                - "10.0.0.0/8"
                - "192.168.0.0/16"
          matchActions:
            - action: Sigkill
```

## Event streaming and SIEM integration

```bash
# Tetragon streams structured JSON events to stdout
# kubectl logs -n kube-system -l app.kubernetes.io/name=tetragon -c export-stdout

# Example process_exec event:
# {
#   "process_exec": {
#     "process": {
#       "exec_id": "a1b2c3d4",
#       "pid": 8291,
#       "uid": 0,
#       "cwd": "/",
#       "binary": "/bin/sh",
#       "arguments": "-c 'cat /etc/shadow'",

# 🚀 process  construx-prod/construx-api-7d9f4b-xk2qr  /bin/sh -c cat /etc/shadow

tetra getevents --namespace construx-prod --event-types PROCESS_EXEC --output json | jq '.process_exec.process | {pod: .pod.name, binary, arguments}'
```

## Network and file observability

```yaml
# TracingPolicy: observe all DNS lookups from production pods
apiVersion: cilium.io/v1alpha1
kind: TracingPolicy
metadata:
  name: observe-dns-prod
spec:
  tracepoints:
    - subsystem: "net"
      event: "net_dev_xmit"
      args: []
      selectors:
        - matchNamespaces:
            - namespace: NetNs
          matchActions:
            - action: Post

---
# TracingPolicy: alert on unexpected binary executions
# Any exec in a container that isn't in the approved list
apiVersion: cilium.io/v1alpha1
kind: TracingPolicy
metadata:
  name: unexpected-exec
spec:
  kprobes:
    - call: "security_bprm_check"
      syscall: false
      args:
        - index: 0
          type: "linux_binprm"
      selectors:
        - matchPodLabels:
            - key: tetragon.io/enforce
              operator: In
              values: ["strict"]
          matchArgs:
            - index: 0
              operator: NotPrefix
              values:
                - "/usr/bin/node"
                - "/usr/bin/python3"
                - "/app/"
                - "/usr/local/bin/"
          matchActions:
            - action: Post   # alert; don't kill (observation phase first)
```

Tetragon vs Falco vs OPA/Kyverno vs seccomp: Falco uses eBPF or a kernel module to observe syscalls and generate alerts — it is observability only, no in-kernel enforcement. Kyverno and OPA/Gatekeeper run as Kubernetes admission webhooks — they intercept API server requests (pod creation, ConfigMap updates) but cannot see runtime behaviour inside running containers. seccomp profiles restrict syscalls for a container at start time but can't make dynamic decisions based on file path or network destination. Tetragon's advantage is runtime enforcement with kernel-level granularity: stop a specific process writing to a specific path while leaving everything else intact, without deploying a new container image or restarting anything. The cost is complexity: TracingPolicy requires understanding kprobe/tracepoint internals, and aggressive enforcement policies can break legitimate workloads if written incorrectly.
