`ILIKE '%keyword%'` has two problems: it can't use an index (it scans every row), and it treats all matches as equally relevant. Postgres full-text search solves both. It tokenises text into lexemes, builds an inverted index with GIN, and ranks results by relevance. For most applications, it's the right answer before adding Elasticsearch.

## The concepts

- **tsvector** — a sorted list of normalised tokens (lexemes) with position information: `'apple':1 'juice':2 'organic':3`
- **tsquery** — a search query: `'apple & juice'`, `'apple | orange'`, `'apple:*'` (prefix)
- **GIN index** — Generalized Inverted Index — maps each lexeme to the rows containing it. Makes search O(matching rows) not O(all rows).
- **ts_rank** — scores a match by how often and where terms appear in the document.

## Schema setup

```sql
-- Add a tsvector column to your table
ALTER TABLE products
  ADD COLUMN search_vector tsvector
  GENERATED ALWAYS AS (
    setweight(to_tsvector('english', coalesce(title, '')), 'A') ||
    setweight(to_tsvector('english', coalesce(description, '')), 'B') ||
    setweight(to_tsvector('english', coalesce(category, '')), 'C')
  ) STORED;

-- GIN index on the tsvector column
CREATE INDEX products_search_idx ON products USING GIN(search_vector);
```

`setweight` assigns A–D weights to different fields. Title matches (weight A) rank higher than description matches (weight B). The `STORED` keyword means Postgres maintains the tsvector automatically when the underlying columns change.

## Drizzle schema

```ts
// db/schema.ts
import { pgTable, text, uuid, customType } from 'drizzle-orm/pg-core';
import { sql } from 'drizzle-orm';

const tsvector = customType<{ data: string }>({
  dataType() {
    return 'tsvector';
  },
});

export const products = pgTable('products', {
  id: uuid('id').primaryKey().defaultRandom(),
  title: text('title').notNull(),
  description: text('description'),
  category: text('category').notNull(),

  searchVector: tsvector('search_vector').generatedAlwaysAs(
    sql`
      setweight(to_tsvector('english', coalesce(title, '')), 'A') ||
      setweight(to_tsvector('english', coalesce(description, '')), 'B') ||
      setweight(to_tsvector('english', coalesce(category, '')), 'C')
    `,
    { mode: 'stored' },
  ),
});
```

## Querying

```ts
import { db } from '@/db';
import { products } from '@/db/schema';
import { sql, desc } from 'drizzle-orm';

export async function searchProducts(query: string, limit = 20) {
  // Convert user query to tsquery — handles punctuation and case
  // websearch_to_tsquery supports "phrase search" and -exclusions
  const tsQuery = sql`websearch_to_tsquery('english', ${query})`;

  return db
    .select({
      id: products.id,
      title: products.title,
      category: products.category,
      rank: sql<number>`ts_rank(${products.searchVector}, ${tsQuery})`,
    })
    .from(products)
    .where(sql`${products.searchVector} @@ ${tsQuery}`)
    .orderBy(desc(sql`ts_rank(${products.searchVector}, ${tsQuery})`))
    .limit(limit);
}
```

## Prefix search for autocomplete

`websearch_to_tsquery` requires complete words. For real-time autocomplete (matching as the user types), use `to_tsquery` with the `:*` prefix operator:

```ts
export async function autocompleteProducts(partial: string, limit = 8) {
  if (partial.trim().length < 2) return [];

  // Convert "lego te" → 'lego:* & te:*'
  const terms = partial.trim().split(/\s+/);
  const tsQuery = sql`to_tsquery('english', ${
    terms.map((t) => `${t}:*`).join(' & ')
  })`;

  return db
    .select({ id: products.id, title: products.title })
    .from(products)
    .where(sql`${products.searchVector} @@ ${tsQuery}`)
    .orderBy(desc(sql`ts_rank(${products.searchVector}, ${tsQuery})`))
    .limit(limit);
}
```

## Highlighted excerpts

`ts_headline` returns the matched text with highlighted terms — useful for showing context snippets in results:

```ts
export async function searchWithHighlights(query: string) {
  const tsQuery = sql`websearch_to_tsquery('english', ${query})`;

  return db
    .select({
      id: products.id,
      title: products.title,
      excerpt: sql<string>`ts_headline(
        'english',
        ${products.description},
        ${tsQuery},
        'MaxWords=25, MinWords=10, StartSel=<mark>, StopSel=</mark>'
      )`,
      rank: sql<number>`ts_rank(${products.searchVector}, ${tsQuery})`,
    })
    .from(products)
    .where(sql`${products.searchVector} @@ ${tsQuery}`)
    .orderBy(desc(sql`ts_rank(${products.searchVector}, ${tsQuery})`))
    .limit(20);
}
```

The `StartSel` and `StopSel` options let you wrap matched terms in any HTML — `<mark>` for native browser highlighting, or a custom class.

## Multi-language support

`english` is the text search configuration — it uses an English stemmer (so "running" matches "run"). For multi-language content:

```sql
-- Auto-detect language using pg_catalog
setweight(to_tsvector(detect_language(title), title), 'A')

-- Or default to 'simple' which doesn't stem — matches exact words
setweight(to_tsvector('simple', title), 'A')
```

`simple` is the safe choice when you can't guarantee language — it lower-cases and strips punctuation but doesn't apply language-specific stemming.

## When to upgrade to pgvector

Full-text search doesn't understand synonyms, typos, or semantic similarity. "Sofa" doesn't match "couch". "Nexr.js" doesn't match "Next.js". For semantic search — where meaning matters more than exact word matching — use pgvector with text embeddings. The two complement each other: full-text search for precision, pgvector for recall. A hybrid search combines both scores.
