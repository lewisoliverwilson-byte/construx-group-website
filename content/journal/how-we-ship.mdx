This is not a pitch. It's a process document. If you've read the manifesto and wondered what "AI-first" actually looks like when someone is sitting at a laptop building something, this is the closest thing to a field report.

## The stack

Every Construx venture is built on the same core stack: Next.js 15 on the frontend, React 19, TypeScript throughout, Tailwind CSS for styling, AWS Amplify for hosting and CI/CD. The AI integration layer varies by product — Scoutr and The Marqet use the Anthropic SDK with direct Claude API calls, The Hyve has a vector-memory architecture on top of Claude — but the shell is identical.

That uniformity is deliberate. The goal is to eliminate the category of decisions that don't create competitive advantage. TypeScript or JavaScript? Next.js or Remix? AWS or Vercel? These questions burn time and the answers don't matter as much as people think. We made the calls once, documented them, and they're now non-decisions for every subsequent venture.

## The actual build loop

When we start a new venture — or a major feature on an existing one — the loop looks like this.

**Step one: get to a conversation.** Not a design doc, not a spec, not a Figma file. A conversation with Claude about what we're building, why, and where the edges are. We paste in context — competitive landscape, user research if we have it, the shape of the data model we're imagining — and iterate until we have a clear mental model of what we're shipping. This typically takes an hour. The artifact is a shared understanding, not a document.

**Step two: scaffolding in Claude Code.** Claude Code is the CLI tool built on top of Claude, designed for agentic software development. We open the terminal, navigate to the project directory, and start working with Claude Code. The first session is almost always about structure: generating the file layout, the routing, the initial component tree, the database schema. Claude Code can read the entire codebase in context, so it understands the conventions we use and stays consistent with them across sessions.

**Step three: iterative feature building.** Each feature starts with a natural language description of what it should do. Claude Code proposes an implementation, we react to it, it adjusts. The back-and-forth is faster than typing the code manually — but more importantly, it surfaces things we hadn't thought about. A good AI system finds the edge cases you glossed over in the design conversation.

**Step four: ship to a staging URL.** AWS Amplify deploys every commit on a branch to a unique preview URL automatically. This means we can share working software with each other — or with early users — within minutes of pushing a change. No manual deployment. No "it works on my machine." A URL, sent to the right person, is the fastest possible feedback loop.

**Step five: production merge.** When something is ready, we merge to `master`. Amplify auto-deploys. We monitor the deployment logs for a few minutes, check the production URL, and it's live.

The entire loop — from "I want to add this feature" to "it's live on the production domain" — routinely runs in a few hours for non-trivial features. That speed isn't unique to us. It's what the current tools enable for anyone willing to use them properly.

## Where Claude specifically earns its role

Claude Code is the most efficient part of the stack for three specific things:

**Boilerplate elimination.** Anything that follows a pattern — a new page with the same layout and metadata as existing pages, a new API route with the same validation structure, a new component that conforms to the design system — takes about 30 seconds to generate. The compounding effect of never typing boilerplate is larger than it sounds.

**Cross-file consistency.** Traditional development has a category of errors that arise from touching one file without updating five others that depended on it. Claude Code reads the whole codebase. When we add a field to a TypeScript interface, it finds every consumer. When we rename a function, it finds every call site. This is table stakes for any large codebase but it's particularly valuable for a two-person team where there's no dedicated QA.

**First drafts of hard things.** Complex features — a vector similarity search, a real-time collaborative channel, a dynamic OG image generator — benefit most from having a capable first draft to react to. A first draft that almost works is dramatically better than a blank screen. Almost-works code is reviewable, fixable, and teachable in a way that pseudocode isn't.

## What it doesn't replace

Claude Code is not a replacement for judgment. It has no opinion about whether what we're building is the right thing. It doesn't push back when we're building the wrong abstraction. It doesn't notice when a feature conflicts with a product goal because it doesn't hold the product goal in mind the way a senior engineer would.

These gaps are not a criticism of the tool. They are the correct division of labour. We are responsible for the product decisions. Claude Code is responsible for the implementation velocity. The only way the partnership breaks down is if we confuse the two.

## The honest number

If forced to estimate: Claude Code reduces the time to ship a given feature by somewhere between 50% and 80%, depending on how well-patterned it is. That's not a number we've measured rigorously. It's calibrated from feel, from watching how long features took before we had these tools versus after.

The more important number is what that multiplier enables. A two-person team operating at 3x the output of a traditional two-person team has the throughput of a six-person team. A portfolio of three ventures becomes achievable. Fast iteration on what the market responds to becomes achievable. Keeping each venture at a quality bar that justifies charging for it becomes achievable.

That's why the stack matters. Not because Next.js is better than Remix. Because the aggregate tooling choice determines the rate at which we can learn and ship.
