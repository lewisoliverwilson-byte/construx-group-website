When The Marqet had 20 listings, browse was sufficient. You could see every listing on one page. The category structure was navigation enough.

At 167 listings, browse is insufficient. A buyer looking for "someone to analyse whether a multi-pack product would sell better split into singles" can't find that by browsing the Analysis category. The listing exists — but the buyer won't find it without search.

The search had to be semantic. Here's what that means in practice.

## Why keyword search fails here

Keyword search is effective when buyers know the exact terminology. "eBay fee calculator" as a search on a listings platform would return any listing containing those words. If the listing is titled "platform cost estimator for resellers," it won't match.

Our listings are professional service descriptions. The terminology used by sellers to describe their services often differs from the terminology buyers use to search for them. A seller writing a listing about sourcing strategy might use "product identification workflow." A buyer searching for that service might search "how to find products to flip."

Vector similarity — semantic search — matches on meaning rather than exact words. Both "product identification workflow" and "how to find products to flip" sit close to the same point in embedding space. A semantic search for either would return the same listings.

## The implementation

Every listing description is embedded when the listing is published or updated:

```ts
async function embedListing(listing: Listing) {
  const textToEmbed = `${listing.title}. ${listing.description}. Category: ${listing.category}.`;
  
  const response = await anthropic.messages.create({
    model: 'claude-3-haiku-20240307',
    max_tokens: 1,
    messages: [{ role: 'user', content: textToEmbed }],
  });
  
  // Use the embeddings API
  const embedding = await anthropic.embeddings.create({
    model: 'claude-3-haiku-20240307',
    input: textToEmbed,
  });

  await db.update(listings).set({
    embedding: embedding.embedding,
    embeddedAt: new Date(),
  }).where(eq(listings.id, listing.id));
}
```

The search query is embedded at query time using the same model, and we retrieve the closest listings by cosine distance:

```sql
SELECT
  l.*,
  (l.embedding <=> $1) AS distance
FROM listings l
WHERE l.status = 'active'
ORDER BY distance ASC
LIMIT 20;
```

The `<=>` operator in pgvector computes cosine distance. Lower distance = more similar. The top 20 results by cosine distance are the semantic search results.

## Hybrid search

Pure semantic search has a failure mode: it can return conceptually related but practically irrelevant results. A search for "eBay batch processing tool" might return a listing about "Amazon wholesale research" because wholesale research and batch processing are conceptually adjacent in embedding space.

We add a hybrid layer: semantic search retrieves candidates, then a keyword filter removes candidates that don't contain at least one word from the query (after stopword removal). This prevents results that are semantically adjacent but practically unrelated.

```ts
function hybridFilter(results: Listing[], query: string): Listing[] {
  const stopwords = new Set(['a', 'an', 'the', 'for', 'to', 'in', 'and', 'or', 'is', 'that', 'with']);
  const queryWords = query
    .toLowerCase()
    .split(/\s+/)
    .filter(w => w.length > 2 && !stopwords.has(w));

  if (queryWords.length === 0) return results; // don't filter if query is all stopwords

  return results.filter(listing => {
    const text = `${listing.title} ${listing.description}`.toLowerCase();
    return queryWords.some(word => text.includes(word));
  });
}
```

The hybrid filter removes the "technically related but practically wrong" results while preserving the semantic flexibility for synonym and terminology gaps.

## Search UX decisions

**Instant results.** Search fires on input with 300ms debounce — no explicit search button. Users see results update as they type.

**Result explanation.** Each result shows a small "match" indicator — the specific phrase from the listing that's closest to the query. This helps buyers quickly evaluate relevance without reading the full listing.

**Empty state guidance.** When search returns zero results, we show the closest partial match and suggest a category browse. "No exact match — closest service:" followed by the single highest-similarity result, regardless of whether it passed the hybrid filter.

**Recent searches.** The last 5 search queries are stored in localStorage and shown on focus when the search field is empty. Buyers refining their search across sessions can pick up where they left off.

## Performance

Embedding each search query takes approximately 200-400ms (round trip to the Claude API). For a search UI that shows results as the user types, this is too slow.

We cache the embeddings for recent queries:

```ts
const embeddingCache = new Map<string, number[]>();

async function getQueryEmbedding(query: string): Promise<number[]> {
  const normalized = query.trim().toLowerCase();
  if (embeddingCache.has(normalized)) return embeddingCache.get(normalized)!;
  
  const embedding = await computeEmbedding(normalized);
  embeddingCache.set(normalized, embedding);
  return embedding;
}
```

The in-process cache is fine for development; in production we use Redis with a 1-hour TTL. The same query embedding is reused across all users searching the same terms within the hour.

The database query itself (cosine distance across 167 embeddings) takes under 5ms. pgvector with an HNSW index would be faster at scale; at 167 listings, a sequential scan is fast enough.

## Metrics

Search was introduced three months into The Marqet's operation. In the first month:

- 34% of sessions that used search converted to a listing view, vs 18% for category browse
- Average session length for search users was 4.2 minutes vs 2.8 minutes for browse-only users
- Search users made purchases at 2.1x the rate of browse-only users

The search-to-purchase conversion differential is the most important signal: users who search know what they want, and good search helps them find it. The semantic search approach is handling the terminology gap correctly — buyers are finding services they'd never have found with keyword search.
