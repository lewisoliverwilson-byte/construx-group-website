---
title: "WireGuard: modern VPN — cryptographically simple, kernel-native, fast"
date: "2033-08-05"
excerpt: "WireGuard is a modern VPN protocol implemented as a Linux kernel module (and userspace implementations for other platforms). The design is deliberately minimal: the entire codebase is ~4,000 lines (compared to OpenVPN's ~100,000), there is one handshake protocol (Noise_IKpsk2 from the Noise Protocol Framework), one cipher (ChaCha20-Poly1305), and one key exchange (Curve25519 ECDH). Each peer has a public/private keypair, and a WireGuard interface is configured with a list of allowed peers (their public key + allowed IP ranges). When a packet arrives for a peer's IP, the interface encapsulates it in UDP and sends it to the peer's endpoint — no connection state, no handshake visible to the network, no ports left open. If there is no traffic, there is nothing to observe. WireGuard is used as the transport layer for Tailscale (which adds a control plane on top), for site-to-site VPN between Kubernetes clusters, and for connecting cloud infrastructure to on-premises networks."
author: "Lewis Wilson"
tag: "Build Log"

Noise protocol. Curve25519. ChaCha20-Poly1305. Interface-level routing. Kernel module.

## Peer configuration

```bash
# WireGuard: generate keypairs and configure peers
# All config is symmetric — both sides configure each other as peers

# Generate keypair for each host
wg genkey | tee /etc/wireguard/private.key | wg pubkey > /etc/wireguard/public.key
chmod 600 /etc/wireguard/private.key

# Server: /etc/wireguard/wg0.conf
# Listens on UDP 51820, routes VPN subnet 10.100.0.0/24
[Interface]
Address    = 10.100.0.1/24
ListenPort = 51820
PrivateKey = <server-private-key>

# PostUp/PreDown: firewall rules — allow forwarding through wg0
PostUp   = iptables -A FORWARD -i %i -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PreDown  = iptables -D FORWARD -i %i -j ACCEPT; iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE

# Peer: construx-api worker (Kubernetes node 10.0.2.10)
[Peer]
PublicKey           = <worker-01-public-key>
AllowedIPs          = 10.100.0.2/32   # this peer's VPN IP
PersistentKeepalive = 25              # send keepalive every 25s (keeps NAT mappings alive)

# Peer: on-premises database server
[Peer]
PublicKey           = <onprem-db-public-key>
AllowedIPs          = 10.100.0.10/32, 192.168.1.0/24  # VPN IP + on-prem LAN
Endpoint            = vpn.construx.onprem:51820        # known endpoint for on-prem peer

---

# Client (worker-01): /etc/wireguard/wg0.conf
[Interface]
Address    = 10.100.0.2/24
PrivateKey = <worker-01-private-key>

[Peer]
PublicKey  = <server-public-key>
Endpoint   = vpn.construx.internal:51820
AllowedIPs = 10.100.0.0/24   # route VPN subnet through this peer

# Bring up the interface
wg-quick up wg0

# Verify peer status
wg show wg0
# interface: wg0
#   public key: <server-public-key>
#   private key: (hidden)
#   listening port: 51820
#
# peer: <worker-01-public-key>
#   endpoint: 10.0.2.10:51820
#   allowed ips: 10.100.0.2/32
#   latest handshake: 14 seconds ago
#   transfer: 142 MiB received, 89 MiB sent
#   persistent keepalive: every 25 seconds
```

## Kubernetes cluster-to-cluster mesh

```yaml
# Kubernetes: WireGuard site-to-site mesh
# Connect three Kubernetes clusters: eu-west-2, us-east-1, ap-southeast-1

# DaemonSet: WireGuard gateway pod on each cluster's edge node
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: wireguard-gateway
  namespace: vpn
spec:
  selector:
    matchLabels:
      app: wireguard-gateway
  template:
    spec:
      nodeSelector:
        node-role.kubernetes.io/gateway: "true"   # only gateway nodes
      hostNetwork: true
      containers:
        - name: wireguard
          image: masipcat/wireguard-go:latest
          securityContext:
            capabilities:
              add: [NET_ADMIN]
          env:
            - name: WG_PRIVATE_KEY
              valueFrom:
                secretKeyRef:
                  name: wireguard-keys
                  key: private-key
          volumeMounts:
            - name: wireguard-config
              mountPath: /etc/wireguard
      volumes:
        - name: wireguard-config
          configMap:
            name: wireguard-config
```

```bash
# Per-cluster routing: announce pod CIDRs across mesh

# eu-west-2 cluster gateway: wg0.conf
[Interface]
Address    = 10.200.0.1/32
PrivateKey = <eu-west-2-private-key>
ListenPort = 51820

[Peer]
PublicKey  = <us-east-1-public-key>
Endpoint   = gateway.us-east-1.construx.internal:51820
AllowedIPs = 10.200.0.2/32, 10.244.1.0/24  # us-east-1 pod CIDR

[Peer]
PublicKey  = <ap-southeast-1-public-key>
Endpoint   = gateway.ap-southeast-1.construx.internal:51820
AllowedIPs = 10.200.0.3/32, 10.244.2.0/24  # ap pod CIDR

# Test cross-cluster pod connectivity
kubectl exec -n default construx-api-pod -- \
  curl -s http://10.244.1.42:8080/health   # Pod in us-east-1 cluster
# {"status":"ok","cluster":"us-east-1"}

# Performance: WireGuard in-kernel throughput
iperf3 -c 10.100.0.2 -t 30
# [  5] 0.00-30.00 sec  18.4 GBytes  5.13 Gbits/sec   ← ~5Gbps through WireGuard tunnel
# Compared to OpenVPN: ~500 Mbps on same hardware
```

WireGuard vs OpenVPN vs IPsec vs Tailscale: OpenVPN runs in userspace, has a large codebase (auditing is hard), is slow (TLS overhead + userspace copy), and uses certificates (significant PKI management). IPsec is kernel-native and fast, but the IKE key exchange protocol is complex, the configuration is error-prone, and compatibility across vendors is inconsistent. Tailscale uses WireGuard as its transport but adds a control plane (coordination server, DERP relay for NAT traversal, ACL policies, SSO integration, MagicDNS) — the result is zero-config WireGuard mesh networking without manually exchanging public keys. WireGuard's advantage over OpenVPN/IPsec is simplicity: fewer lines of code, a modern cryptographic primitive set with no negotiation (you can't choose a weak cipher by accident), faster handshake, and kernel-level throughput. For building your own VPN infrastructure or cluster-to-cluster links where you control both ends, WireGuard is the default choice. For teams that want managed mesh networking without operating a coordination server, Tailscale or Headscale (self-hosted Tailscale control plane) builds on WireGuard.
