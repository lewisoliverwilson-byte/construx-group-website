excerpt: "Tokio is Rust's async runtime: a work-stealing thread pool that drives futures to completion. An async function in Rust compiles to a state machine — it suspends at each .await point and is resumed by the runtime when the awaited future is ready. Tokio::spawn launches a task (a future that runs concurrently on the thread pool). Channels (mpsc, oneshot, broadcast) connect tasks. select! races multiple futures. The result is safe concurrency with zero-cost abstraction — no garbage collector, no runtime overhead."

Futures compile to state machines. Tokio drives them. No GC, no runtime tax.

## Basic async task structure

```rust
// src/main.rs
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    // Spawn concurrent tasks
    let task_a = tokio::spawn(fetch_orders());
    let task_b = tokio::spawn(process_queue());

    // Wait for both — returns (Result<_>, Result<_>)
    let (orders, queue) = tokio::join!(task_a, task_b);
    println!("orders: {:?}, queue: {:?}", orders.unwrap(), queue.unwrap());
}

async fn fetch_orders() -> Vec<Order> {
    sleep(Duration::from_millis(100)).await;
    vec![]
}

async fn process_queue() -> usize {
    sleep(Duration::from_millis(50)).await;
    42
}
```

## Channels — connect async tasks

```rust
use tokio::sync::mpsc;

#[tokio::main]
async fn main() {
    let (tx, mut rx) = mpsc::channel::<Order>(1024);

    // Producer task
    let producer = tokio::spawn(async move {
        for order in fetch_orders_from_db().await {
            tx.send(order).await.expect("channel closed");
        }
        // tx drops here — receiver gets None after last message
    });

    // Consumer task
    let consumer = tokio::spawn(async move {
        while let Some(order) = rx.recv().await {
            process_order(order).await;
        }
        println!("all orders processed");
    });

    tokio::try_join!(producer, consumer).unwrap();
}
```

## Axum web server — async HTTP handler

```rust
// src/main.rs
use axum::{Router, routing::get, routing::post, Json, extract::State};
use sqlx::PgPool;
use serde::{Deserialize, Serialize};

#[derive(Clone)]
struct AppState { db: PgPool }

#[derive(Serialize)]
struct Order { id: String, status: String, total_cents: i64 }

#[derive(Deserialize)]
struct CreateOrder { customer_id: String, total_cents: i64 }

async fn list_orders(State(state): State<AppState>) -> Json<Vec<Order>> {
    let orders = sqlx::query_as!(
        Order,
        "SELECT id, status, total_cents FROM orders ORDER BY created_at DESC LIMIT 20"
    )
    .fetch_all(&state.db)
    .await
    .unwrap();

    Json(orders)
}

async fn create_order(
    State(state): State<AppState>,
    Json(body): Json<CreateOrder>,
) -> Json<Order> {
    let order = sqlx::query_as!(
        Order,
        "INSERT INTO orders (customer_id, total_cents) VALUES ($1, $2) RETURNING id, status, total_cents",
        body.customer_id,
        body.total_cents,
    )
    .fetch_one(&state.db)
    .await
    .unwrap();

    Json(order)
}

#[tokio::main]
async fn main() {
    let db = PgPool::connect(&std::env::var("DATABASE_URL").unwrap()).await.unwrap();
    let state = AppState { db };

    let app = Router::new()
        .route("/orders",     get(list_orders))
        .route("/orders",     post(create_order))
        .with_state(state);

    let listener = tokio::net::TcpListener::bind("0.0.0.0:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
```

## select! — race multiple futures

```rust
use tokio::select;
use tokio::time::{sleep, Duration};

async fn process_with_timeout(order_id: &str) -> Result<(), &'static str> {
    select! {
        result = process_order(order_id) => {
            result.map_err(|_| "processing failed")
        }
        _ = sleep(Duration::from_secs(30)) => {
            Err("timeout")
        }
    }
}

// select! with channels
async fn worker(mut rx: Receiver<Order>, mut shutdown: Receiver<()>) {
    loop {
        select! {
            Some(order) = rx.recv() => {
                process_order_item(order).await;
            }
            _ = shutdown.recv() => {
                println!("shutting down gracefully");
                break;
            }
        }
    }
}
```

## Bounded concurrency with semaphore

```rust
use tokio::sync::Semaphore;
use std::sync::Arc;

async fn process_orders_bounded(orders: Vec<Order>) {
    let semaphore = Arc::new(Semaphore::new(10));  // Max 10 concurrent

    let handles: Vec<_> = orders.into_iter().map(|order| {
        let sem = Arc::clone(&semaphore);
        tokio::spawn(async move {
            let _permit = sem.acquire().await.unwrap();
            // _permit is released when dropped at end of scope
            process_order(order).await;
        })
    }).collect();

    for handle in handles {
        handle.await.unwrap();
    }
}
```

Tokio vs async-std vs smol: Tokio is the dominant async runtime — it's what most libraries (Axum, sqlx, reqwest, Lapin) target. async-std mirrors the stdlib API surface. smol is minimal and composable. In practice, if you're using Axum, sqlx, or reqwest, you're using Tokio — they list `tokio` as a required runtime. The choice is made for you by your dependencies.
