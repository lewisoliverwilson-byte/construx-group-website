SQLite handles most data problems that do not need multi-writer concurrency. Bun makes it trivially easy to use.

## Basic usage

```ts
import { Database } from 'bun:sqlite';

// In-memory (cleared when process exits)
const db = new Database(':memory:');

// On disk
const db = new Database('data/app.db');

// WAL mode for better concurrent reads
const db = new Database('data/app.db', { create: true });
db.run('PRAGMA journal_mode = WAL');
```

## Schema and queries

```ts
import { Database } from 'bun:sqlite';

const db = new Database('construx.db');

// Create table
db.run(`
  CREATE TABLE IF NOT EXISTS posts (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    slug      TEXT    NOT NULL UNIQUE,
    title     TEXT    NOT NULL,
    content   TEXT    NOT NULL,
    published INTEGER NOT NULL DEFAULT 0,
    created   TEXT    NOT NULL DEFAULT (datetime('now'))
  )
`);

// Prepared statements — compile once, execute many times
const insert = db.prepare(
  'INSERT INTO posts (slug, title, content) VALUES ($slug, $title, $content)',
);
const getAll    = db.prepare('SELECT * FROM posts WHERE published = 1 ORDER BY created DESC');
const getBySlug = db.prepare<{ slug: string }>('SELECT * FROM posts WHERE slug = $slug');

// Insert
insert.run({ $slug: 'bun-sqlite', $title: 'Bun SQLite', $content: '…' });

// Query all
const posts = getAll.all();

// Query one
const post = getBySlug.get({ $slug: 'bun-sqlite' });
```

## Transactions

```ts
// Batch insert in a transaction — much faster than individual inserts
const insertMany = db.transaction((rows: { slug: string; title: string }[]) => {
  for (const row of rows) {
    insert.run({ $slug: row.slug, $title: row.title, $content: '' });
  }
});

insertMany(posts);  // All succeed or all fail
```

SQLite transactions are synchronous and fast. Inserting 10 000 rows in a transaction is ~100ms. Without a transaction it is ~10s (one fsync per insert).

## Type-safe queries with Drizzle

```ts
import { drizzle }        from 'drizzle-orm/bun-sqlite';
import { Database }       from 'bun:sqlite';
import { sql }            from 'drizzle-orm';
import { sqliteTable, text, integer } from 'drizzle-orm/sqlite-core';

const sqlite = new Database('construx.db');
const db     = drizzle(sqlite);

const posts = sqliteTable('posts', {
  id:        integer('id').primaryKey({ autoIncrement: true }),
  slug:      text('slug').notNull().unique(),
  title:     text('title').notNull(),
  content:   text('content').notNull(),
  published: integer('published', { mode: 'boolean' }).notNull().default(false),
  created:   text('created').notNull().default(sql`(datetime('now'))`),
});

// Fully typed query
const allPosts = await db.select().from(posts).where(eq(posts.published, true));
// allPosts: Array<{ id: number; slug: string; title: string; ... }>
```

## Use cases

Script that processes a CSV: load rows into SQLite, query and transform, write output. Local development cache: store API responses to avoid hitting rate limits during development. Cloudflare D1: same API, runs at the edge. CLI tools that need persistent state. Bun SQLite is also useful as the test database — fast, no setup, no teardown, no connection pool.

## When not to use SQLite

Multiple writers from different processes will hit WAL mode limits. High-concurrency write workloads need Postgres. Data that changes frequently across multiple services needs a shared database server. SQLite is a single-file, single-process database. It is not a drop-in replacement for Postgres — it is a different tool for a different problem.
