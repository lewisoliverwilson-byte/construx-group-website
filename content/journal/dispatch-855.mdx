excerpt: "Kafka Streams is a library (not a separate cluster) for building stateful stream processing applications on top of Kafka. You write a topology — a graph of processors — and deploy it as a regular JVM application. State stores (RocksDB under the hood) hold aggregated data locally and are backed up to Kafka compacted topics. Multiple instances of the same application form a consumer group and automatically partition work. No external cluster, no YARN, no Flink."

A library, not a cluster. State stored locally. Backed up to Kafka.

## Basic topology — filter and transform

```java
// OrderEnrichmentApp.java
import org.apache.kafka.streams.*;
import org.apache.kafka.streams.kstream.*;
import java.util.Properties;

public class OrderEnrichmentApp {
    public static void main(String[] args) {
        Properties props = new Properties();
        props.put(StreamsConfig.APPLICATION_ID_CONFIG,    "order-enrichment");
        props.put(StreamsConfig.BOOTSTRAP_SERVERS_CONFIG, "kafka:9092");
        props.put(StreamsConfig.DEFAULT_KEY_SERDE_CLASS_CONFIG,   Serdes.String().getClass());
        props.put(StreamsConfig.DEFAULT_VALUE_SERDE_CLASS_CONFIG, Serdes.String().getClass());

        StreamsBuilder builder = new StreamsBuilder();

        // Read from orders topic
        KStream<String, Order> orders = builder.stream("orders",
            Consumed.with(Serdes.String(), orderSerde));

        // Filter: only paid orders
        KStream<String, Order> paid = orders.filter(
            (key, order) -> "paid".equals(order.getStatus())
        );

        // Enrich with customer data from a KTable (compacted Kafka topic)
        KTable<String, Customer> customers = builder.table("customers",
            Consumed.with(Serdes.String(), customerSerde));

        KStream<String, EnrichedOrder> enriched = paid
            .selectKey((key, order) -> order.getCustomerId())
            .join(customers,
                (order, customer) -> new EnrichedOrder(order, customer),
                Joined.with(Serdes.String(), orderSerde, customerSerde)
            );

        enriched.to("orders-enriched", Produced.with(Serdes.String(), enrichedSerde));

        KafkaStreams streams = new KafkaStreams(builder.build(), props);
        streams.start();
        Runtime.getRuntime().addShutdownHook(new Thread(streams::close));
    }
}
```

## Windowed aggregation — count orders per minute

```java
// Count orders per customer per 5-minute window
KStream<String, Order> orders = builder.stream("orders");

KTable<Windowed<String>, Long> orderCounts = orders
    .groupBy((key, order) -> order.getCustomerId())
    .windowedBy(TimeWindows.ofSizeWithNoGrace(Duration.ofMinutes(5)))
    .count(Materialized.as("order-counts-store"));

// Convert windowed results to a flat stream
orderCounts.toStream()
    .map((windowedKey, count) -> KeyValue.pair(
        windowedKey.key(),
        new RateAlert(windowedKey.key(), count, windowedKey.window().start())
    ))
    .filter((key, alert) -> alert.getCount() > 100)  // Alert if > 100 orders/5min
    .to("order-rate-alerts");
```

## Interactive queries — read state from another instance

```java
// Start with a REST endpoint that exposes local state
@RestController
public class OrderCountController {
    private final KafkaStreams streams;

    @GetMapping("/order-counts/{customerId}")
    public Long getOrderCount(@PathVariable String customerId) {
        ReadOnlyKeyValueStore<String, Long> store = streams
            .store(StoreQueryParameters.fromNameAndType(
                "order-counts-store",
                QueryableStoreTypes.keyValueStore()
            ));
        return store.get(customerId);
    }

    // For distributed queries — route to the instance that owns the partition
    @GetMapping("/order-counts/{customerId}/distributed")
    public Long getDistributed(@PathVariable String customerId) {
        KeyQueryMetadata metadata = streams.queryMetadataForKey(
            "order-counts-store", customerId, Serdes.String().serializer()
        );

        if (metadata.activeHost().equals(localHost)) {
            return getOrderCount(customerId);
        }

        // Forward to the correct instance via HTTP
        return restTemplate.getForObject(
            "http://" + metadata.activeHost() + "/order-counts/" + customerId,
            Long.class
        );
    }
}
```

## Error handling — dead letter queue

```java
// Custom uncaught exception handler
streams.setUncaughtExceptionHandler((throwable) -> {
    if (throwable instanceof RecoverableException) {
        // Replace this stream thread — keep the app running
        return StreamThreadExceptionResponse.REPLACE_THREAD;
    }
    // Shutdown the application — escalate to operations
    return StreamThreadExceptionResponse.SHUTDOWN_APPLICATION;
});

// Production error handler — route bad records to a DLQ topic
DeserializationExceptionHandler dlqHandler = (context, record, exception) -> {
    producer.send(new ProducerRecord<>("orders-dlq",
        record.key(), record.value()
    ));
    return DeserializationHandlerResponse.CONTINUE;
};
props.put(StreamsConfig.DEFAULT_DESERIALIZATION_EXCEPTION_HANDLER_CLASS_CONFIG,
    dlqHandler.getClass());
```

Kafka Streams vs Flink: Flink is a separate distributed processing cluster — more powerful (exactly-once processing, event time with watermarks, complex CEP), but operationally heavier. Kafka Streams is a library that runs in your application process — no separate cluster, no operations overhead beyond your Kafka cluster itself. For aggregations and joins on a single Kafka cluster, Streams is simpler. For cross-source joins, complex event patterns, or sub-second event-time windows, Flink's watermark handling is more expressive.
