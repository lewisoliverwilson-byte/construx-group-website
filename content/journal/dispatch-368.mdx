The basic Stripe subscription is straightforward: create a price, attach a customer, done. The complexity emerges when you need usage-based pricing (pay per API call, per GB, per active user), mid-cycle plan changes, and the billing management flows that let customers upgrade, downgrade, and cancel without calling support.

## Usage-based pricing with meters

Stripe Billing Meters (GA since 2024) let you report usage events and bill based on them:

```ts
// lib/stripe.ts
import Stripe from 'stripe';

export const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);

// Report a usage event to Stripe
export async function reportUsage(
  customerId: string,
  meterId: string,
  value: number,
) {
  await stripe.billing.meterEvents.create({
    event_name: meterId,
    payload: {
      stripe_customer_id: customerId,
      value: String(value),
    },
  });
}
```

```ts
// Usage in your application
await reportUsage(customer.stripeCustomerId, 'api_calls', requestCount);
await reportUsage(customer.stripeCustomerId, 'storage_gb', storageUsed);
```

Stripe aggregates these events and bills at the end of the billing cycle based on the price's aggregation strategy (sum, max, or last value in period).

## Creating metered prices

```ts
// One-time setup to create a metered price
const meter = await stripe.billing.meters.create({
  display_name: 'API Calls',
  event_name: 'api_calls',
  default_aggregation: { formula: 'sum' },
});

const price = await stripe.prices.create({
  currency: 'gbp',
  recurring: {
    interval: 'month',
    meter: meter.id,
    usage_type: 'metered',
  },
  billing_scheme: 'tiered',
  tiers_mode: 'graduated',
  tiers: [
    { up_to: 10000, unit_amount: 0 },      // First 10k calls free
    { up_to: 100000, unit_amount: 1 },     // £0.01 per call up to 100k
    { up_to: 'inf', unit_amount_decimal: '0.5' },  // £0.005 per call beyond
  ],
});
```

Graduated tiers mean the customer pays the price for each tier independently — not a flat rate that kicks in at a threshold.

## Handling plan changes

Plan upgrades and downgrades mid-cycle require proration. Stripe handles the math:

```ts
// Upgrade a subscription to a new price
export async function changePlan(
  subscriptionId: string,
  newPriceId: string,
) {
  const subscription = await stripe.subscriptions.retrieve(subscriptionId);

  return stripe.subscriptions.update(subscriptionId, {
    proration_behavior: 'create_prorations',  // charge/credit for remaining period
    items: [{
      id: subscription.items.data[0].id,
      price: newPriceId,
    }],
    // Immediately invoice the proration rather than waiting for cycle end
    billing_cycle_anchor: 'unchanged',
    payment_behavior: 'pending_if_incomplete',
  });
}
```

`proration_behavior: 'create_prorations'` creates a proration credit for unused time on the old plan and a charge for the new plan. These appear as line items on the next invoice.

## The billing portal

Let customers manage their own subscriptions without building the UI:

```ts
// app/api/billing-portal/route.ts
import { auth } from '@/auth';
import { stripe } from '@/lib/stripe';

export async function POST(req: Request) {
  const session = await auth();
  if (!session?.user) return Response.json({ error: 'Unauthorized' }, { status: 401 });

  const { returnUrl } = await req.json();

  const user = await db.query.users.findFirst({
    where: eq(users.id, session.user.id),
  });

  const portalSession = await stripe.billingPortal.sessions.create({
    customer: user!.stripeCustomerId,
    return_url: returnUrl ?? `${process.env.APP_URL}/dashboard`,
  });

  return Response.json({ url: portalSession.url });
}
```

```tsx
// Client component
async function openBillingPortal() {
  const { url } = await fetch('/api/billing-portal', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ returnUrl: window.location.href }),
  }).then((r) => r.json());

  window.location.href = url;
}
```

The Stripe Billing Portal handles: plan upgrades/downgrades, payment method updates, invoice history, subscription cancellation with configurable pause/cancel options.

## Tracking subscription state

Maintain a local copy of subscription state for fast reads:

```ts
// db/schema.ts
export const subscriptions = pgTable('subscriptions', {
  id: text('id').primaryKey(),  // Stripe subscription ID
  userId: text('user_id').notNull().references(() => users.id),
  status: text('status', {
    enum: ['active', 'past_due', 'canceled', 'paused', 'trialing'],
  }).notNull(),
  priceId: text('price_id').notNull(),
  currentPeriodEnd: timestamp('current_period_end').notNull(),
  cancelAtPeriodEnd: boolean('cancel_at_period_end').notNull().default(false),
  updatedAt: timestamp('updated_at').notNull().defaultNow(),
});
```

```ts
// Keep in sync via webhook
async function handleSubscriptionEvent(event: Stripe.Event) {
  const sub = event.data.object as Stripe.Subscription;

  await db.insert(subscriptions)
    .values({
      id: sub.id,
      userId: sub.metadata.userId,
      status: sub.status as SubscriptionStatus,
      priceId: sub.items.data[0].price.id,
      currentPeriodEnd: new Date(sub.current_period_end * 1000),
      cancelAtPeriodEnd: sub.cancel_at_period_end,
    })
    .onConflictDoUpdate({
      target: subscriptions.id,
      set: {
        status: sql`excluded.status`,
        priceId: sql`excluded.price_id`,
        currentPeriodEnd: sql`excluded.current_period_end`,
        cancelAtPeriodEnd: sql`excluded.cancel_at_period_end`,
        updatedAt: new Date(),
      },
    });
}
```

## Free trials

```ts
// Creating a subscription with a trial period
const subscription = await stripe.subscriptions.create({
  customer: customer.id,
  items: [{ price: priceId }],
  trial_period_days: 14,
  payment_settings: {
    save_default_payment_method: 'on_subscription',
  },
  expand: ['latest_invoice.payment_intent'],
});
```

Collecting a card during trial signup improves trial-to-paid conversion — users who've added a card convert at 2–3x the rate of those who haven't.

## The most common billing mistakes

1. **Not verifying webhook signatures** — anyone can POST to your webhook endpoint.
2. **Not handling duplicate events** — Stripe retries; your handler must be idempotent.
3. **Querying Stripe for subscription status on every request** — slow and rate-limited; use your local database.
4. **Not sending trial expiry emails** — 7 days, 3 days, 1 day before. Each reminder lifts conversion.
5. **No dunning** — Stripe's payment retry logic (Smart Retries) reduces involuntary churn automatically. Enable it.
