The classic problem with LLM outputs: you ask for JSON, you sometimes get JSON, sometimes get JSON wrapped in a markdown code block, sometimes get JSON with a preamble paragraph. Defensive parsing code piles up. Zod schemas parse optimistically. Edge cases reach production.

The Anthropic API's tool use feature solves this structurally. You define a JSON schema, the model is constrained to produce output that matches it. The output is always valid, always typed, always parseable.

## The pattern

Instead of asking Claude to "respond in JSON", define a tool with the shape you want and ask Claude to call it:

```ts
import Anthropic from '@anthropic-ai/sdk';
import { z } from 'zod';
import { zodToJsonSchema } from 'zod-to-json-schema';

const client = new Anthropic();

const ScanEnrichmentSchema = z.object({
  title: z.string().describe('Clean, canonical product title'),
  category: z.enum(['Electronics', 'Home & Kitchen', 'Sports', 'Toys', 'Beauty', 'Other']),
  keyFeatures: z.array(z.string()).max(5).describe('Top 3-5 product features, concise'),
  targetBuyer: z.string().describe('One-sentence description of who typically buys this'),
  resellNotes: z.string().describe('Any notable resell considerations — seasonality, competition, margin factors'),
  confidence: z.enum(['HIGH', 'MEDIUM', 'LOW']).describe('How confident in this enrichment given the product data'),
});

type ScanEnrichment = z.infer<typeof ScanEnrichmentSchema>;

export async function enrichScan(rawProductData: {
  title: string;
  description: string;
  asin: string;
  category: string;
}): Promise<ScanEnrichment> {
  const response = await client.messages.create({
    model: 'claude-sonnet-4-6',
    max_tokens: 1024,
    tools: [
      {
        name: 'enrich_scan',
        description: 'Enrich raw Amazon product data with structured analysis for resell intelligence',
        input_schema: zodToJsonSchema(ScanEnrichmentSchema),
      },
    ],
    tool_choice: { type: 'tool', name: 'enrich_scan' },
    messages: [
      {
        role: 'user',
        content: `Analyse this product for resell potential:

Title: ${rawProductData.title}
Category: ${rawProductData.category}
ASIN: ${rawProductData.asin}
Description: ${rawProductData.description.slice(0, 500)}`,
      },
    ],
  });

  // Tool use response is always the tool_use block
  const toolUse = response.content.find((block) => block.type === 'tool_use');
  if (!toolUse || toolUse.type !== 'tool_use') {
    throw new Error('Expected tool_use response from Claude');
  }

  // Parse and validate with Zod — this should always succeed with structured outputs
  return ScanEnrichmentSchema.parse(toolUse.input);
}
```

The `tool_choice: { type: 'tool', name: 'enrich_scan' }` forces Claude to call exactly that tool. There's no prose in the response, no wrapping, no ambiguity.

## Why Zod + zodToJsonSchema

Defining the schema in Zod means you get TypeScript types for free. The `z.infer<typeof ScanEnrichmentSchema>` type is the return type of the function — no separate type definition, no risk of drift between the schema and the type.

`zod-to-json-schema` converts the Zod schema to the JSON Schema format the Anthropic API expects:

```bash
npm install zod-to-json-schema
```

The conversion handles most Zod primitives correctly: `z.string()`, `z.number()`, `z.enum()`, `z.array()`, `z.object()`, `.describe()` becomes the JSON Schema `description`. Complex Zod types (`.refine()`, `.transform()`) don't convert, so keep the tool schemas to structural validation only.

## Extracting multiple structured values in one call

For richer analysis, put everything in one tool:

```ts
const MarketAnalysisSchema = z.object({
  pricePosition: z.enum(['PREMIUM', 'MID_MARKET', 'BUDGET']),
  competitionLevel: z.enum(['HIGH', 'MEDIUM', 'LOW']),
  seasonalPattern: z.object({
    isSeasonal: z.boolean(),
    peakMonths: z.array(z.number().min(1).max(12)).optional(),
  }),
  aiInsight: z.string().describe('One-sentence insight about this product\'s resell potential'),
  flags: z.array(z.enum([
    'GATED_CATEGORY',
    'BRAND_RESTRICTED',
    'HIGH_RETURN_RATE',
    'FRAGILE',
    'OVERSIZED',
    'FAST_MOVING',
  ])).describe('Any relevant operational flags for this product'),
});
```

One API call, one validated response, multiple typed fields. No post-processing regex, no conditional parsing.

## Error handling

Even with structured outputs, the model can fail (rate limit, network error, the response times out). Wrap calls defensively:

```ts
export async function enrichScanSafe(
  rawProductData: Parameters<typeof enrichScan>[0],
): Promise<ScanEnrichment | null> {
  try {
    return await enrichScan(rawProductData);
  } catch (err) {
    console.error('[AI] enrichScan failed', {
      asin: rawProductData.asin,
      error: err instanceof Error ? err.message : 'Unknown error',
    });
    return null;
  }
}
```

Return `null` on failure. The caller decides whether a missing enrichment is fatal (it usually isn't — the scan result without enrichment is still useful).

## Prompt engineering is still relevant

Structured outputs guarantee the shape of the output. They don't guarantee the quality. A `confidence: 'HIGH'` on a wrong classification is worse than `confidence: 'LOW'` on a correct one.

The system prompt still matters:

```ts
const ENRICHMENT_SYSTEM_PROMPT = `You are a resell intelligence analyst specialising in Amazon marketplace data.

Your job is to analyse product listings and provide structured enrichment for a resell intelligence platform used by professional Amazon sellers.

Key instructions:
- Be conservative with confidence ratings. HIGH confidence requires clear, unambiguous product data.
- The targetBuyer should be specific and actionable ("parents of children aged 3-8 seeking affordable educational toys" not "families").
- Flag GATED_CATEGORY for any product in a category that typically requires Amazon approval (Toys, Beauty, Grocery, etc.).
- Flag BRAND_RESTRICTED for well-known brands that block third-party resellers.
- resellNotes should surface anything a seller might not know: known competition spikes, seasonality, quality complaints from reviews.`;
```

Good structured output prompting: define what quality looks like in the system prompt, let the schema enforce the shape.

## Caching enrichments

AI enrichment is expensive per call. Cache the result by ASIN:

```ts
export async function getOrCreateEnrichment(
  asin: string,
  rawProductData: Parameters<typeof enrichScan>[0],
): Promise<ScanEnrichment | null> {
  // Check for existing enrichment
  const existing = await db
    .select()
    .from(scanEnrichments)
    .where(eq(scanEnrichments.asin, asin))
    .limit(1);

  // Return cached if fresher than 7 days
  if (existing[0] && isWithinDays(existing[0].createdAt, 7)) {
    return existing[0].data as ScanEnrichment;
  }

  // Generate new enrichment
  const enrichment = await enrichScanSafe(rawProductData);
  if (!enrichment) return null;

  // Upsert
  await db.insert(scanEnrichments)
    .values({ asin, data: enrichment })
    .onConflictDoUpdate({
      target: scanEnrichments.asin,
      set: { data: enrichment, createdAt: new Date() },
    });

  return enrichment;
}
```

Product data doesn't change daily. A 7-day cache on enrichments means most scans return instantly with no API call.
