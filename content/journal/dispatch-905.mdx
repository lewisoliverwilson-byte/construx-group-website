---
title: "git worktree: parallel branch development without stashing"
date: "2032-05-21"
excerpt: "git worktree lets you check out multiple branches of the same repository simultaneously in separate directories. Each worktree shares the same .git object store (no data duplication) but has its own working tree and index. This solves the constant stash-switch-work-switch-pop pattern when you need to interrupt a feature branch to fix a bug: just `git worktree add ../repo-hotfix hotfix/ssl-cert` and work in the hotfix directory while your feature branch stays exactly where it was. IDE state, shell history, and server processes don't get disrupted."
author: "Lewis Wilson"
tag: "Build Log"
---

Three branches, three directories, one .git. No stashing.

## Basic worktree workflow

```bash
# Your main repository
cd ~/code/construx-group-website
git branch
# * master
# feat/meilisearch-integration

# Add a worktree for a hotfix — creates a new directory with the branch checked out
git worktree add ../construx-website-hotfix hotfix/ssl-cert-renewal
# Preparing worktree (new branch 'hotfix/ssl-cert-renewal')
# HEAD is now at a4f8c2d feat: MeilisearchPanel on journal page

# Add a worktree for an existing branch
git worktree add ../construx-website-feat feat/meilisearch-integration
# HEAD is now at b7e9d1f wip: search UI wiring

# List all worktrees
git worktree list
# /code/construx-group-website          a4f8c2d [master]
# /code/construx-website-hotfix         a4f8c2d [hotfix/ssl-cert-renewal]
# /code/construx-website-feat           b7e9d1f [feat/meilisearch-integration]

# Each directory is fully independent
ls ../construx-website-hotfix/
# app/ components/ content/ ...  (same files, different branch state)

# Work on the hotfix — no stashing needed
cd ../construx-website-hotfix
# Edit files...
git add . && git commit -m "fix: renew wildcard cert before expiry"

# Meanwhile, the feature branch is exactly where you left it
cd ~/code/construx-group-website
git status
# On branch master
# nothing to commit, working tree clean
```

## How worktrees share state

```bash
# All worktrees share the same .git directory (via a .git file that points to it)
cat ../construx-website-hotfix/.git
# gitdir: /code/construx-group-website/.git/worktrees/construx-website-hotfix

# Object store is shared — no duplication of git objects
du -sh .git/objects/
# 48M   .git/objects/  # Same for all worktrees

# Each worktree has its own index (staging area)
ls .git/worktrees/construx-website-hotfix/
# HEAD  gitdir  index  locked

# A branch can only be checked out in ONE worktree at a time
git worktree add ../another-feat feat/meilisearch-integration
# fatal: 'feat/meilisearch-integration' is already checked out at
#        '/code/construx-website-feat'

# Create a detached HEAD worktree (useful for CI-like builds at a specific commit)
git worktree add --detach ../construx-website-tag v1.4.2
```

## Real workflows

```bash
# Workflow: interrupt feature work for an urgent hotfix
# 1. You're deep in a feature branch with 10 files changed
# 2. Production incident requires an immediate fix

# OLD approach (painful):
git stash push -m "wip: meilisearch search UI"
git checkout master && git checkout -b hotfix/ssl-cert
# ...fix...
git commit && git checkout feat/meilisearch-integration
git stash pop   # Sometimes conflicts

# NEW approach with worktree:
git worktree add ../hotfix-$(date +%Y%m%d) -b hotfix/ssl-cert-renewal
cd ../hotfix-$(date +%Y%m%d)
# ...fix in clean environment, dev server still running in original tree...
git commit -m "fix: renew wildcard cert before expiry"
git push origin hotfix/ssl-cert-renewal
cd ~/code/construx-group-website   # Feature branch: untouched, dev server still running

# Workflow: compare two versions side-by-side
git worktree add ../v1-comparison v1.0.0
# Now run the two versions simultaneously on different ports:
# Terminal 1: npm run dev -- --port 3000 (current master)
# Terminal 2: cd ../v1-comparison && npm run dev -- --port 3001 (v1.0.0)

# Workflow: run CI checks locally in a separate worktree (doesn't affect dev server)
git worktree add ../ci-check origin/ci-branch
cd ../ci-check && npm run test:ci
```

## Cleanup and management

```bash
# Remove a worktree when done (must have no uncommitted changes)
git worktree remove ../construx-website-hotfix

# Force remove (even if dirty)
git worktree remove --force ../construx-website-hotfix

# Prune stale worktree entries (if directory was deleted manually)
git worktree prune

# Lock a worktree to prevent accidental removal (useful for long-running CI)
git worktree lock ../construx-website-hotfix --reason "running load tests"
git worktree unlock ../construx-website-hotfix

# Move a worktree to a different path
git worktree move ../construx-website-hotfix ../archive/hotfix-ssl

# List with verbose info
git worktree list --porcelain
# worktree /code/construx-group-website
# HEAD a4f8c2d3b1e9f7a1b2c3d4e5f6a7b8c9d0e1f2a3
# branch refs/heads/master
#
# worktree /code/construx-website-feat
# HEAD b7e9d1f4c3a2e5b6c7d8e9f0a1b2c3d4e5f6a7b
# branch refs/heads/feat/meilisearch-integration
```

git worktree vs git stash: Stash is a temporary commit stored on a stack — it saves your changes and clears the working tree, but you're still on the same branch, same directory, and you have to remember to pop it. Worktree creates a separate directory with an independent working tree — you can have both branches open simultaneously, run different dev servers on different ports, and never worry about losing stash context to accidental pops or conflicts. Stash is fine for a 30-second context switch; worktree is better for anything that takes more than a few minutes.
