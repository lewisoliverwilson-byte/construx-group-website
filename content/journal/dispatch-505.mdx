The OpenAI chat completion API became the de facto standard for LLM interfaces. Anthropic, Mistral, Groq, Together AI, Ollama, and LM Studio all implement a compatible version of it. This means switching providers is mostly a configuration change.

## The compatibility interface

```ts
// The core OpenAI chat completion interface that everyone implements
interface ChatCompletionRequest {
  model:    string;
  messages: Array<{ role: 'system' | 'user' | 'assistant'; content: string }>;
  max_tokens?:   number;
  temperature?:  number;
  stream?:       boolean;
  tools?:        Tool[];
  tool_choice?:  ToolChoice;
}
```

## Vercel AI SDK: provider-agnostic setup

The Vercel AI SDK abstracts over providers. Switching is a one-line change:

```ts
import { generateText } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';
import { openai }    from '@ai-sdk/openai';
import { groq }      from '@ai-sdk/groq';
import { ollama }    from 'ollama-ai-provider';

// Same call, different providers
const { text: anthropicText } = await generateText({
  model:  anthropic('claude-opus-4-8-20251101'),
  prompt: 'Explain quantum entanglement in one paragraph.',
});

const { text: groqText } = await generateText({
  model:  groq('llama-3.3-70b-versatile'),
  prompt: 'Explain quantum entanglement in one paragraph.',
});

const { text: localText } = await generateText({
  model:  ollama('llama3.2'),  // Local — no API key needed
  prompt: 'Explain quantum entanglement in one paragraph.',
});
```

## Environment-based provider selection

```ts
// lib/ai.ts — select provider from environment
import { anthropic } from '@ai-sdk/anthropic';
import { openai }    from '@ai-sdk/openai';
import { groq }      from '@ai-sdk/groq';
import { ollama }    from 'ollama-ai-provider';
import type { LanguageModel } from 'ai';

export function getModel(): LanguageModel {
  const provider = process.env.AI_PROVIDER ?? 'anthropic';

  switch (provider) {
    case 'anthropic':
      return anthropic(process.env.ANTHROPIC_MODEL ?? 'claude-opus-4-8-20251101');
    case 'openai':
      return openai(process.env.OPENAI_MODEL ?? 'gpt-4o');
    case 'groq':
      return groq(process.env.GROQ_MODEL ?? 'llama-3.3-70b-versatile');
    case 'ollama':
      return ollama(process.env.OLLAMA_MODEL ?? 'llama3.2');
    default:
      throw new Error(`Unknown AI provider: ${provider}`);
  }
}

// Usage — no provider code in business logic
import { generateText } from 'ai';
import { getModel }     from '@/lib/ai';

const { text } = await generateText({
  model:  getModel(),
  prompt: '...',
});
```

## Ollama for local development

Ollama runs models locally — useful for development without API costs and for testing prompts without hitting rate limits:

```bash
# Install Ollama
brew install ollama

# Pull a model
ollama pull llama3.2
ollama pull qwen2.5:7b
ollama pull phi4

# Serve (auto-starts on install)
ollama serve  # Runs at http://localhost:11434
```

```ts
// Use with the OpenAI SDK directly (Ollama is OpenAI-compatible)
import OpenAI from 'openai';

const ollama = new OpenAI({
  baseURL: 'http://localhost:11434/v1',
  apiKey:  'ollama',  // Required but ignored
});

const response = await ollama.chat.completions.create({
  model:    'llama3.2',
  messages: [{ role: 'user', content: 'Hello!' }],
});
```

## Groq: fast inference

Groq's LPU inference chips make open-weight models run at 500+ tokens/second — much faster than hosted GPT-4 or Claude. Useful for latency-sensitive paths:

```bash
npm install @ai-sdk/groq
```

```ts
import { groq }         from '@ai-sdk/groq';
import { generateText } from 'ai';

// Fast inference for non-critical paths
const { text } = await generateText({
  model:      groq('llama-3.3-70b-versatile'),
  prompt:     '...',
  maxTokens:  512,
});
```

Groq is often 10x cheaper than Claude/GPT-4 for the equivalent open model. The quality ceiling is lower, but for classification, extraction, and formatting tasks, it's often enough.

## Provider routing by task type

```ts
// Route to the right provider based on what the task requires
function getModelForTask(task: 'complex-reasoning' | 'fast-extraction' | 'local-dev'): LanguageModel {
  switch (task) {
    case 'complex-reasoning':
      return anthropic('claude-opus-4-8-20251101');  // Best quality
    case 'fast-extraction':
      return groq('llama-3.3-70b-versatile');         // Fast + cheap
    case 'local-dev':
      return ollama('llama3.2');                       // Free, offline
  }
}

// In production
const productSummary = await generateText({
  model:  getModelForTask('fast-extraction'),  // Groq for speed
  prompt: `Summarise this product: ${title}`,
});

const marketAnalysis = await generateText({
  model:  getModelForTask('complex-reasoning'),  // Claude for depth
  prompt: `Analyse this market: ${data}`,
});
```

## Where compatibility breaks

The OpenAI API spec is a baseline, not a ceiling. Provider-specific features break compatibility:

- **Tool use format**: Anthropic's tool use JSON structure differs from OpenAI's. Use the Vercel AI SDK's abstraction or handle per-provider.
- **Context windows**: Claude Opus has 200k tokens, GPT-4o has 128k, most Ollama models default to 4k. Prompts that work on Claude may truncate on smaller models.
- **System prompts**: Anthropic handles system prompts differently internally — use the SDK to abstract this.
- **Vision**: Not all models accept image inputs. Check capabilities before sending image content to Groq or Ollama models.
- **Streaming**: Most providers support streaming but the SSE format varies slightly. Use the SDK rather than raw `fetch`.

The Vercel AI SDK handles most of these differences. When you need provider-specific features (Claude's vision, Anthropic's tool choice, extended thinking), drop down to the provider SDK directly.
