date: "2034-01-29"
excerpt: "Envoy is a high-performance L7 proxy used as the data plane for Istio, Contour, AWS App Mesh, and as a standalone edge proxy. Its xDS (extension Discovery Service) protocol is the mechanism by which a control plane (like Istiod, Envoy Gateway, or a custom gRPC server) dynamically configures Envoy proxies without restarting them. xDS consists of several discovery services: LDS (Listener Discovery Service — which ports Envoy listens on), RDS (Route Discovery Service — HTTP routing rules), CDS (Cluster Discovery Service — upstream services with load balancing config), EDS (Endpoint Discovery Service — individual IP:port instances of an upstream), and SDS (Secret Discovery Service — TLS certificates and keys). The ADS (Aggregated Discovery Service) bundles all resource types through a single gRPC stream, enabling consistent ordering of updates (so a new Route referencing a new Cluster arrives after the Cluster is already active). Envoy's dynamic configuration model is what makes service meshes operationally feasible — instead of restarting thousands of sidecar proxies to update routing rules, the control plane pushes incremental updates to all Envoy instances simultaneously."

## Envoy static config and xDS bootstrap

```yaml
# Envoy static configuration (bootstrap) — used before xDS connection is established
# envoy.yaml

admin:
  address:
    socket_address: { address: 0.0.0.0, port_value: 9901 }

static_resources:
  listeners:
    - name: listener_0
      address:
        socket_address: { address: 0.0.0.0, port_value: 8080 }
      filter_chains:
        - filters:
            - name: envoy.filters.network.http_connection_manager
              typed_config:
                "@type": type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
                stat_prefix: ingress_http
                access_log:
                  - name: envoy.access_loggers.stdout
                    typed_config:
                      "@type": type.googleapis.com/envoy.extensions.access_loggers.stream.v3.StdoutAccessLog
                http_filters:
                  - name: envoy.filters.http.router
                    typed_config:
                      "@type": type.googleapis.com/envoy.extensions.filters.http.router.v3.Router
                route_config:
                  name: local_route
                  virtual_hosts:
                    - name: local_service
                      domains: ["*"]
                      routes:
                        - match: { prefix: "/api/v1/orders" }
                          route:
                            cluster: orders_api
                            timeout: 30s
                            retry_policy:
                              retry_on: 5xx,reset,connect-failure
                              num_retries: 3
                              per_try_timeout: 10s
                        - match: { prefix: "/api/v1/payments" }
                          route:
                            weighted_clusters:
                              clusters:
                                - name: payments_api_v1
                                  weight: 90
                                - name: payments_api_v2
                                  weight: 10
                              total_weight: 100
  clusters:
    - name: orders_api
      connect_timeout: 5s
      type: STRICT_DNS
      lb_policy: LEAST_REQUEST
      load_assignment:
        cluster_name: orders_api
        endpoints:
          - lb_endpoints:
              - endpoint:
                  address:
                    socket_address:
                      address: orders-api.construx-prod.svc.cluster.local
                      port_value: 8080

# xDS dynamic configuration: point Envoy at the control plane
dynamic_resources:
  ads_config:
    api_type: GRPC
    transport_api_version: V3
    grpc_services:
      - envoy_grpc:
          cluster_name: xds_cluster
  cds_config:
    resource_api_version: V3
    ads: {}
  lds_config:
    resource_api_version: V3
    ads: {}

static_resources:
  clusters:
    - name: xds_cluster
      connect_timeout: 5s
      type: STRICT_DNS
      http2_protocol_options: {}   # xDS uses HTTP/2 gRPC
      load_assignment:
        cluster_name: xds_cluster
        endpoints:
          - lb_endpoints:
              - endpoint:
                  address:
                    socket_address:
                      address: istiod.istio-system.svc.cluster.local
                      port_value: 15010
```

Envoy xDS vs NGINX vs HAProxy vs Traefik: NGINX is a battle-tested high-performance proxy with excellent static configuration — the standard for edge serving static content and TLS termination. Its reload model (SIGHUP) works well for static configurations, but dynamic updates require either a full reload (brief connection disruption) or using NGINX Plus's dynamic upstreams API. HAProxy is the reference implementation for load balancing — well-understood operational model, excellent performance, and a rich status dashboard. Neither NGINX nor HAProxy has a dynamic API equivalent to Envoy's xDS — they are designed for static or semi-static configuration managed by external tools. Traefik supports dynamic configuration via its provider model (Kubernetes Ingress, Docker labels, Consul Catalog) — operationally simpler than Envoy for basic use cases. Envoy xDS is the protocol that enables fully dynamic service mesh data planes: configuration changes (new service, route update, certificate rotation) propagate to all Envoy proxies in milliseconds via gRPC streams, with no restart and no connection disruption. This is what makes Istio, AWS App Mesh, and Envoy Gateway operationally viable at scale — the control plane pushes incremental updates, and Envoy applies them without interrupting existing connections.
