title: "Nix flakes: reproducible development environments and CI builds"
date: "2031-11-10"
excerpt: "Nix flakes pin every dependency — the compiler, build tools, system libraries, language runtimes — to a content-addressed hash in flake.lock. The result is a development environment that is byte-for-byte identical across macOS, Linux, and CI. nix develop drops you into a shell with every tool available; nix build produces a derivation whose output hash is deterministic. No more 'works on my machine' — the machine is defined in the flake."

Lock the entire environment, not just npm packages. Reproducible by construction.

## flake.nix — development shell

```nix
# flake.nix
{
  description = "Construx API development environment";

  inputs = {
    nixpkgs.url     = "github:NixOS/nixpkgs/nixos-24.11";
    flake-utils.url = "github:numtide/flake-utils";
  };

  outputs = { self, nixpkgs, flake-utils }:
    flake-utils.lib.eachDefaultSystem (system:
      let
        pkgs = nixpkgs.legacyPackages.${system};
      in {
        devShells.default = pkgs.mkShell {
          buildInputs = with pkgs; [
            # Runtime
            nodejs_22
            bun

            # Database
            postgresql_16
            redis

            # Infrastructure
            kubectl
            helm
            terraform
            awscli2

            # Dev tools
            git
            jq
            curl
            httpie
            just        # Task runner
            watchexec   # File watcher

            # Language tools
            nodePackages.typescript
            nodePackages.typescript-language-server
          ];

          shellHook = ''
            echo "construx dev environment"
            echo "node $(node --version) | bun $(bun --version) | pg $(psql --version | head -1)"
            export PGDATA="$PWD/.pgdata"
            export PGHOST="localhost"
            export PGPORT="5433"
          '';
        };

        # Formatter for nix files
        formatter = pkgs.nixfmt-rfc-style;
      }
    );
}
```

## Enter the dev shell

```bash
# First time — builds and caches all dependencies
nix develop

# In CI (no interactive shell)
nix develop --command bun test

# With direnv — auto-activates on cd
echo "use flake" > .envrc
direnv allow
# Now every `cd construx-api` automatically loads the nix environment

# Show what's in the flake
nix flake show
# ├── devShells
# │   ├── aarch64-darwin
# │   │   └── default: development environment 'nix-shell'
# │   └── x86_64-linux
# │       └── default: development environment 'nix-shell'
```

## flake.nix — build a Node.js application

```nix
{
  description = "Construx API";

  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-24.11";

  outputs = { self, nixpkgs }:
    let
      system = "x86_64-linux";
      pkgs   = nixpkgs.legacyPackages.${system};
    in {
      packages.${system}.default = pkgs.buildNpmPackage {
        pname   = "construx-api";
        version = "1.4.2";
        src     = ./.;

        npmDepsHash = "sha256-abc123...";  # Generated by prefetch-npm-deps

        buildPhase = ''
          npm run build
        '';

        installPhase = ''
          mkdir -p $out/lib
          cp -r dist node_modules $out/lib/
          mkdir -p $out/bin
          cat > $out/bin/construx-api <<EOF
          #!/bin/sh
          exec node $out/lib/dist/index.js "\$@"
          EOF
          chmod +x $out/bin/construx-api
        '';
      };
    };
}
```

## Build and run

```bash
# Build the derivation — output is content-addressed
nix build .#

# Run the built output
./result/bin/construx-api

# Build produces a store path — identical hash across machines
nix build . --print-out-paths
# /nix/store/a3f9b2c1d4e5f6a7-construx-api-1.4.2

# Check the store path won't change (useful in CI)
nix build . && nix store verify ./result
```

## CI — GitHub Actions with Nix

```yaml
# .github/workflows/ci.yaml
name: CI

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: DeterminateSystems/nix-installer-action@v13

      - uses: DeterminateSystems/magic-nix-cache-action@v7
        # Caches nix store paths — subsequent runs are fast

      - name: Run tests
        run: nix develop --command bun test

      - name: Build
        run: nix build .

      - name: Verify reproducibility
        run: |
          nix build . --out-link result-1
          nix build . --out-link result-2
          diff -r result-1 result-2 && echo "Reproducible build confirmed"
```

## flake.lock — what pins everything

```json
{
  "nodes": {
    "nixpkgs": {
      "locked": {
        "lastModified": 1732800000,
        "narHash":      "sha256-Gptc5VF...AAAAAAE=",
        "owner":        "NixOS",
        "repo":         "nixpkgs",
        "rev":          "ae2e6b3d4c1f9a2b7e4d8c3f1a9b2e4d8c3f1a9b",
        "type":         "github"
      }
    }
  }
}
```

Nix vs Docker for dev environments: Docker gives you an isolated container with pinned images, but the image build itself can be non-reproducible (apt-get installs non-pinned packages). Nix pins every dependency to a content hash — the derivation hash changes if any input changes. Both guarantee isolation; Nix guarantees reproducibility at the package level. The tradeoff: Nix has a steeper learning curve and a different mental model, but the nix develop shell integrates with your host OS (editor, file system, processes) without Docker's container boundary.
