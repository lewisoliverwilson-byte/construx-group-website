The TypeScript compile cycle is fine for production builds. For scripts, seeds, migrations, and one-off tasks, you want to run `tsx seed.ts` and have it work immediately. No `tsc`, no `dist/` folder, no intermediate files.

## tsx: fast TypeScript execution

```bash
npm install -D tsx

# Run any TypeScript file
tsx seed.ts
tsx scripts/migrate.ts

# Watch mode for development
tsx watch src/server.ts

# As a Node.js loader (for esm compatibility)
node --import tsx/esm src/server.ts
```

```json
// package.json scripts
{
  "scripts": {
    "dev":      "tsx watch src/server.ts",
    "seed":     "tsx scripts/seed.ts",
    "migrate":  "tsx scripts/migrate.ts",
    "generate": "tsx scripts/generate-types.ts"
  }
}
```

## tsx tsconfig

```json
// tsconfig.json
{
  "compilerOptions": {
    "module":         "ESNext",
    "moduleResolution": "bundler",
    "target":         "ES2022",
    "strict":         true,
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

tsx respects `tsconfig.json` for path aliases — `@/lib/db` resolves correctly.

## Common use cases

```ts
// scripts/seed.ts
import { db }    from '@/lib/db';
import { faker } from '@faker-js/faker';

async function seed() {
  console.log('Seeding database…');

  await db.users.deleteMany();
  await db.posts.deleteMany();

  const users = await db.users.createMany({
    data: Array.from({ length: 10 }, () => ({
      username: faker.internet.username(),
      email:    faker.internet.email(),
    })),
  });

  console.log(`Created ${users.count} users`);
  process.exit(0);
}

seed().catch(console.error);
```

```bash
tsx scripts/seed.ts
# → Seeding database…
# → Created 10 users
```

## ts-node: TypeScript with type checking

```bash
npm install -D ts-node

# Run with full type checking
ts-node src/check-config.ts

# Skip type checking (faster, behaves like tsx)
ts-node --transpile-only src/server.ts

# ESM projects
ts-node --esm src/server.ts
```

## Shebang scripts

```ts
#!/usr/bin/env tsx
// scripts/deploy.ts

import { execSync } from 'child_process';

const branch = execSync('git branch --show-current').toString().trim();
if (branch !== 'master') {
  console.error(`Must be on master, currently on ${branch}`);
  process.exit(1);
}

console.log('Running build…');
execSync('npm run build', { stdio: 'inherit' });

console.log('Deploying…');
execSync('amplify publish --yes', { stdio: 'inherit' });
```

```bash
chmod +x scripts/deploy.ts
./scripts/deploy.ts
```

## tsx vs ts-node vs Bun vs esbuild

tsx: fast (esbuild-powered), no type checking, path alias support, best for scripts. ts-node: slow (full TypeScript compiler), type checking, same paths support. Bun: runtime + package manager + bundler, fastest script execution, best for Bun-native projects. esbuild: just the bundler — use when you need full build control. For scripts in a Node.js project: tsx. For scripts where type errors matter: ts-node. If you are on Bun: just run TypeScript with `bun run script.ts`.
