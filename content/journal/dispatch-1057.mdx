excerpt: "Encore is a backend framework for TypeScript and Go where infrastructure is declared alongside application code using type-safe primitives. Instead of provisioning an SQS queue in Terraform and then writing AWS SDK code to publish to it, you declare a `const queue = new Queue<T>()` in your application code — Encore provisions the queue in your cloud, generates the SDK, handles serialisation, dead-letter queues, and wires it up. The same applies to databases (`const db = new SQLDatabase('name', ...)`), cron jobs (`new CronJob('name', {schedule: '0 * * * *'}, handler)`), and pub/sub topics. The Encore Platform generates an architecture diagram from your code, provides local development with automatically provisioned infrastructure (local Postgres, queues), preview environments per pull request (separate cloud environments per branch), and a deployment pipeline that can target AWS, GCP, or self-hosted Kubernetes. The key insight: infrastructure should be a detail of the code, not a separate configuration layer."

## Service and API definition

```typescript
// TypeScript: Encore application — services, APIs, databases

import { api, APIError } from "encore.dev/api";
import { SQLDatabase } from "encore.dev/storage/sqldb";
import { Topic, Subscription } from "encore.dev/pubsub";
import { CronJob } from "encore.dev/cron";

// Database: Encore provisions PostgreSQL automatically
const db = new SQLDatabase("orders", {
    migrations: "./migrations",   // SQL migration files in ./migrations/
});

// Pub/sub topic: Encore provisions SQS (AWS) or Cloud Pub/Sub (GCP)
export const OrderCreated = new Topic<{ orderId: string; tenantId: string; totalPence: number }>(
    "order-created",
    { deliveryGuarantee: "at-least-once" }
);

// API endpoint: type-safe, automatically generates OpenAPI spec
export const createOrder = api(
    { expose: true, method: "POST", path: "/orders", auth: true },
    async (req: { tenantId: string; productId: string; quantity: number; paymentMethodId: string }): Promise<{ orderId: string }> => {
        const orderId = crypto.randomUUID();
        const totalPence = await lookupProductPrice(req.productId) * req.quantity;

        await db.exec`
            INSERT INTO orders (id, tenant_id, product_id, quantity, total_pence, status)
            VALUES (${orderId}, ${req.tenantId}, ${req.productId}, ${req.quantity}, ${totalPence}, 'pending')
        `;

        // Publish to queue — Encore handles serialisation and delivery
        await OrderCreated.publish({ orderId, tenantId: req.tenantId, totalPence });

        return { orderId };
    }
);

export const getOrder = api(
    { expose: true, method: "GET", path: "/orders/:orderId", auth: true },
    async ({ orderId }: { orderId: string }): Promise<Order> => {
        const row = await db.queryRow<Order>`
            SELECT id, tenant_id, status, total_pence, created_at
            FROM orders WHERE id = ${orderId}
        `;
        if (!row) throw APIError.notFound("order not found");
        return row;
    }
);

// Cron job: runs on schedule — Encore provisions the trigger
const _ = new CronJob("send-daily-digest", {
    title:    "Send daily revenue digest to all tenants",
    schedule: "0 9 * * 1-5",   // 9am weekdays
    endpoint: sendDailyDigest,
});

export const sendDailyDigest = api(
    { expose: false },
    async (): Promise<void> => {
        const tenants = await db.query<{ tenantId: string }>`
            SELECT DISTINCT tenant_id FROM orders WHERE created_at > NOW() - INTERVAL '1 day'
        `;
        for await (const { tenantId } of tenants) {
            await sendDigestEmail(tenantId);
        }
    }
);
```

## Pub/sub subscription and service-to-service calls

```typescript
// payments service: subscribes to OrderCreated, calls Stripe, updates status

import { Subscription } from "encore.dev/pubsub";
import { api, APIError } from "encore.dev/api";
import { createOrder } from "~encore/clients";   // type-safe client, generated by Encore

// Subscribe to the OrderCreated topic from the orders service
const _ = new Subscription(OrderCreated, "process-payment", {
    handler: async (event) => {
        // Charge the payment
        const charge = await stripe.charges.create({
            amount:   event.totalPence,
            currency: "gbp",
            source:   await getPaymentMethod(event.tenantId),
            metadata: { orderId: event.orderId },
            idempotencyKey: event.orderId,
        });

        // Call another service's API — type-safe, no HTTP client boilerplate
        await updateOrderStatus({ orderId: event.orderId, status: "confirmed", chargeId: charge.id });
    },
});

// Service-to-service call: Encore generates type-safe clients
// No manual HTTP clients, no OpenAPI codegen step
const client = new createOrder.Client({ baseURL: "https://api.construx.internal" });
const { orderId } = await client.createOrder({
    tenantId: "10001",
    productId: "prod-8b2f",
    quantity: 1,
    paymentMethodId: "pm_xxx",
});
```

Encore vs NestJS vs Fastify vs plain Express vs tRPC: Express and Fastify are HTTP frameworks — they handle routing and middleware but have no opinion on infrastructure. You provision queues, databases, and cron jobs yourself via Terraform/CDK, and maintain separate SDKs and type definitions for inter-service communication. NestJS adds structure (modules, decorators, DI) but still requires separate infrastructure provisioning. tRPC gives type-safe RPC between TypeScript services but only covers HTTP calls — no queues, no cron, no database provisioning. Encore's bet is that the separation between 'application code' and 'infrastructure code' is artificial: if a queue is a detail of how your service processes work, it should be declared next to the code that uses it. The tradeoff: Encore is opinionated about both code structure and deployment targets (AWS, GCP, or self-hosted on Kubernetes via their open-source infrastructure layer). Teams that need to stay on a specific infrastructure configuration (existing VPCs, custom IAM, specific Kubernetes setup) may find Encore's automation conflicts with their existing approach. For new backend services where you want batteries-included infrastructure without maintaining separate Terraform, Encore is a compelling starting point.
