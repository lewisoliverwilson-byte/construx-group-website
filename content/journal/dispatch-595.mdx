Transactional email — account confirmations, password resets, receipts, notifications — needs to be reliable, fast, and inspectable. Resend is built for developers: a simple API, a React email component library, and first-class TypeScript support.

## Setup

```bash
npm install resend
```

```ts
// lib/resend.ts
import { Resend } from 'resend';

export const resend = new Resend(process.env.RESEND_API_KEY);
```

Create an API key in the Resend dashboard, add a verified sending domain, and set `RESEND_API_KEY` in your environment.

## Sending an email

```ts
// Basic send
const { data, error } = await resend.emails.send({
  from:    'Construx <noreply@construxgroup.io>',
  to:      ['lewis@construxgroup.io'],
  subject: 'Your account is ready',
  html:    '<p>Welcome to Construx.</p>',
});

if (error) {
  console.error('Email send failed:', error);
}
```

The `from` field must use a verified domain. The response includes an `id` you can use to look up delivery status.

## React Email: composing with components

React Email lets you write email templates as React components. It renders them to HTML and plain text.

```bash
npm install @react-email/components react react-dom
```

```tsx
// emails/WelcomeEmail.tsx
import {
  Body, Container, Head, Heading, Html, Link, Preview, Text
} from '@react-email/components';

interface WelcomeEmailProps {
  username: string;
  loginUrl: string;
}

export default function WelcomeEmail({ username, loginUrl }: WelcomeEmailProps) {
  return (
    <Html>
      <Head />
      <Preview>Welcome to Construx, {username}</Preview>

```

## Batch sending

```ts
// Send to multiple recipients in one API call
const { data, error } = await resend.batch.send([
  {
    from:    'Construx <noreply@construxgroup.io>',
    to:      ['user1@example.com'],
    subject: 'Invoice #1001',
    html:    invoiceHtml,
  },
  {
    from:    'Construx <noreply@construxgroup.io>',
    to:      ['user2@example.com'],
    subject: 'Invoice #1002',
    html:    invoiceHtml2,
  },
]);
```

Batch sends up to 100 emails per call. Each email in the batch gets its own ID for tracking.

## Webhooks: delivery events

Resend sends webhook events for delivery lifecycle: `email.sent`, `email.delivered`, `email.bounced`, `email.complained`, `email.opened`, `email.clicked`.

```ts
// app/api/webhooks/resend/route.ts
import { headers } from 'next/headers';
import { Webhook } from 'svix';

const secret = process.env.RESEND_WEBHOOK_SECRET!;

export async function POST(req: Request) {
  const body    = await req.text();
  const wh      = new Webhook(secret);
  const hdrs    = await headers();

  let event: { type: string; data: Record<string, unknown> };
  try {
    event = wh.verify(body, {
      'svix-id':        hdrs.get('svix-id')!,
      'svix-timestamp': hdrs.get('svix-timestamp')!,
      'svix-signature': hdrs.get('svix-signature')!,
    }) as typeof event;
  } catch {
    return new Response('Invalid signature', { status: 400 });
  }

  if (event.type === 'email.bounced') {
    // Mark the email as invalid in your database
    await markEmailBounced(event.data.to as string);
  }

  if (event.type === 'email.complained') {
    // Unsubscribe the user from marketing emails
    await unsubscribeEmail(event.data.to as string);
  }

  return new Response('OK');
}
```

Always verify webhook signatures. Resend uses Svix to sign events.

## Retrieving email status

```ts
// Check delivery status of a specific email
const { data } = await resend.emails.get('email-id-from-send-response');
console.log(data?.last_event); // 'delivered', 'bounced', etc.
```

## Domain setup

Before sending, verify your domain in the Resend dashboard. You'll add:
- SPF record: `v=spf1 include:amazonses.com ~all`
- DKIM records: Resend provides these per domain
- DMARC record: `v=DMARC1; p=none; rua=mailto:dmarc@construxgroup.io`

Deliverability depends on SPF, DKIM, and DMARC being correctly configured. Without them, email goes to spam regardless of the sending API.

## Rate limits

- Free plan: 100 emails/day, 1 domain
