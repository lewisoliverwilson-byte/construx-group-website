Components developed in isolation are testable, documented, and composable. Storybook provides the workshop where you build the parts before assembling the product.

## Install

```bash
npx storybook@latest init
# Detects your framework (Next.js, Vite, etc.) and configures automatically
```

## Writing stories

```tsx
// components/Button/Button.stories.tsx
import type { Meta, StoryObj } from '@storybook/react';
import { Button }              from './Button';

const meta: Meta<typeof Button> = {
  title:     'UI/Button',
  component: Button,
  tags:      ['autodocs'],  // auto-generates documentation page
  args: {
    variant:  'primary',
    size:     'md',
    disabled: false,
  },
  argTypes: {
    variant:  { control: 'select', options: ['primary', 'secondary', 'ghost', 'danger'] },
    size:     { control: 'select', options: ['sm', 'md', 'lg'] },
    disabled: { control: 'boolean' },
  },
};

export default meta;
type Story = StoryObj<typeof meta>;

export const Primary: Story = {
  args: { children: 'Click me', variant: 'primary' },
};

export const Loading: Story = {
  args: { children: 'Saving…', isLoading: true, variant: 'primary' },
};

export const Danger: Story = {
  args: { children: 'Delete post', variant: 'danger' },
};

// Story with custom render
export const WithIcon: Story = {
  render: (args) => (
    <Button {...args}>
      <TrashIcon size={14} />
      Delete
    </Button>
  ),
};
```

## Interaction testing (play functions)

```tsx
import { userEvent, within, expect } from '@storybook/test';

export const FormSubmit: Story = {
  render: () => <SignupForm onSubmit={() => {}} />,
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);

    await userEvent.type(canvas.getByLabelText('Email'), 'lewis@construxgroup.io');
    await userEvent.type(canvas.getByLabelText('Password'), 'SecurePass123!');
    await userEvent.click(canvas.getByRole('button', { name: 'Sign up' }));

    await expect(canvas.getByText('Check your email')).toBeInTheDocument();
  },
};
```

## Decorators: global providers

```tsx
// .storybook/preview.tsx
import type { Preview }   from '@storybook/react';
import { ThemeProvider }  from '@/components/ThemeProvider';
import { QueryClient }    from '@tanstack/react-query';
import '../app/globals.css';

const preview: Preview = {
  decorators: [
    (Story) => (
      <ThemeProvider defaultTheme="dark">
        <div style={{ padding: '24px', background: 'var(--bg)' }}>
          <Story />
        </div>
      </ThemeProvider>
    ),
  ],
  parameters: {
    backgrounds: {
      default: 'dark',
      values: [
        { name: 'dark',  value: '#01010a' },
        { name: 'light', value: '#ffffff' },
      ],
    },
  },
};

export default preview;
```

## Vitest integration (Storybook 8)

```ts
// vitest.config.ts
import { defineConfig }          from 'vitest/config';
import { storybookTest }         from '@storybook/experimental-addon-vitest/plugin';

export default defineConfig({
  plugins:  [storybookTest()],
  test: {
    browser: {
      enabled:  true,
      provider: 'playwright',
      name:     'chromium',
    },
  },
});
```

```bash
# Run all story tests
vitest --project=storybook
```

## Chromatic: visual regression testing

```bash
# Install
npm install --save-dev chromatic

# Run
npx chromatic --project-token=your_token
```

Chromatic takes a screenshot of every story and compares it to the baseline. Any pixel change is flagged for review. For design systems and component libraries, this catches unintended visual regressions before they reach production.

## Storybook vs direct unit tests

Storybook stories and component unit tests serve different purposes. Stories document components and catch visual regressions via Chromatic. Unit tests verify logic. Play functions in stories test interaction at the component level. The combination covers both. Use Storybook for shared component libraries and design systems. For application-specific components that are hard to isolate, integration or E2E tests are more appropriate.
