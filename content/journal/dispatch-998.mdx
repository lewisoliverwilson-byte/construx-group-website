excerpt: "Grafana Alloy is the successor to Grafana Agent — a unified observability collector that runs metrics scraping (Prometheus-compatible), log collection (Loki), and trace forwarding (OpenTelemetry) in a single binary with a single configuration language called River. River is a declarative HCL-inspired language where you define components (prometheus.scrape, loki.source.kubernetes, otelcol.exporter) and wire them together with references. The pipeline is visible in a built-in UI at :12345 that shows component health, data flow rates, and configuration. Alloy replaces the need to run separate agents for each signal type — one DaemonSet handles everything."

River pipeline language. Single binary. Prometheus + Loki + OTel in one. Component health UI.

## River configuration language

```hcl
// /etc/alloy/config.alloy
// River: declarative pipeline — define components, wire with references

// ── METRICS ─────────────────────────────────────────────────────────────────

// Kubernetes pod auto-discovery for Prometheus scraping
discovery.kubernetes "pods" {
  role = "pod"
  namespaces {
    names = ["construx-prod", "construx-staging", "monitoring"]
  }
}

// Apply relabeling rules (same as Prometheus relabel_configs)
discovery.relabel "pods" {
  targets = discovery.kubernetes.pods.targets

  // Keep only pods annotated for scraping
  rule {
    source_labels = ["__meta_kubernetes_pod_annotation_prometheus_io_scrape"]
    action        = "keep"
    regex         = "true"
  }

  // Use the pod-annotated metrics path if set
  rule {
    source_labels = ["__meta_kubernetes_pod_annotation_prometheus_io_path"]
    target_label  = "__metrics_path__"
    regex         = "(.+)"
  }

  // Expose namespace and pod as labels
  rule {
    source_labels = ["__meta_kubernetes_namespace"]
    target_label  = "namespace"
  }
  rule {
    source_labels = ["__meta_kubernetes_pod_name"]
    target_label  = "pod"
  }
}

// Scrape the discovered pods
prometheus.scrape "pods" {
  targets    = discovery.relabel.pods.output
  forward_to = [prometheus.remote_write.victoriametrics.receiver]

  scrape_interval = "15s"
  scrape_timeout  = "10s"
}

// Remote write to VictoriaMetrics
prometheus.remote_write "victoriametrics" {
  endpoint {
    url = "http://vminsert.monitoring.svc:8480/insert/0/prometheus/api/v1/write"
    queue_config {
      max_shards           = 8
      max_samples_per_send = 10000
    }
  }

  external_labels = {
    cluster = "eu-west-1",
    region  = "eu-west-1",
  }
}
```

## Log collection with Loki components

```hcl
// ── LOGS ─────────────────────────────────────────────────────────────────────

// Collect logs from all Kubernetes pods
loki.source.kubernetes "pods" {
  targets    = discovery.relabel.pods.output
  forward_to = [loki.process.add_labels.receiver]
}

// Process logs: extract level from JSON, drop debug in prod
loki.process "add_labels" {
  forward_to = [loki.write.default.receiver]

  // Extract level from JSON log lines
  stage.json {
    expressions = {
      level = "level",
      msg   = "msg",
    }
  }

  // Promote level to a label (enables fast filtering)
  stage.labels {
    values = {
      level = "",  // empty string = use the extracted value
    }
  }

  // Drop debug logs in production namespace
  stage.match {
    selector = `{namespace="construx-prod"} |= ""` 
    pipeline_stages {
      stage.drop {
        expression    = "level=~\"debug|trace\""
        drop_counter_reason = "debug_log_dropped"
      }
    }
  }

  // Parse request duration for metrics-from-logs
  stage.regex {
    expression = `completed in (?P<duration_ms>[0-9]+)ms`
  }
  stage.metrics {
    metric.histogram {
      name    = "log_request_duration_ms"
      help    = "Request duration parsed from log lines"
      source  = "duration_ms"
      buckets = [10, 50, 100, 500, 1000, 5000]
    }
  }
}

// Write logs to Loki
loki.write "default" {
  endpoint {
    url = "http://loki.monitoring.svc:3100/loki/api/v1/push"
  }
}
```

## Trace collection and tail sampling

```hcl
// ── TRACES ───────────────────────────────────────────────────────────────────

// Receive traces from applications via OTLP
otelcol.receiver.otlp "default" {
  grpc {
    endpoint = "0.0.0.0:4317"
  }
  http {
    endpoint = "0.0.0.0:4318"
  }
  output {
    traces = [otelcol.processor.tail_sampling.default.input]
  }
}

// Tail sampling: keep all errors, 1% of successful traces
otelcol.processor.tail_sampling "default" {
  decision_wait = "10s"

  policy {
    name = "always-sample-errors"
    type = "status_code"
    status_code {
      status_codes = ["ERROR"]
    }
  }

  policy {
    name = "always-sample-slow"
    type = "latency"
    latency {
      threshold_ms = 1000
    }
  }

  policy {
    name = "sample-rest"
    type = "probabilistic"
    probabilistic {
      sampling_percentage = 1
    }
  }

  output {
    traces = [otelcol.exporter.otlp.tempo.input]
  }
}

// Export traces to Tempo
otelcol.exporter.otlp "tempo" {
  client {
    endpoint = "tempo-distributor.monitoring.svc:4317"
    tls {
      insecure = true
    }
  }
  sending_queue {
    num_consumers  = 10
    queue_size     = 10000
  }
}
```

## Alloy UI and debugging

```bash
# Alloy serves a web UI at :12345
# Shows component graph, health, data flow rates

# View component health via API
curl -s http://alloy:12345/api/v0/web/components | jq '.[] | {id, health: .health.state}'
# { "id": "prometheus.scrape.pods",          "health": "healthy" }
# { "id": "prometheus.remote_write.victoriametrics", "health": "healthy" }
# { "id": "loki.source.kubernetes.pods",     "health": "healthy" }
# { "id": "loki.write.default",              "health": "healthy" }
# { "id": "otelcol.receiver.otlp.default",   "health": "healthy" }
# { "id": "otelcol.processor.tail_sampling.default", "health": "healthy" }
# { "id": "otelcol.exporter.otlp.tempo",     "health": "healthy" }

# View self-telemetry (Alloy exposes its own metrics)
curl -s http://alloy:12345/metrics | grep 'alloy_component'
# alloy_component_controller_evaluations_total{component_id="prometheus.scrape.pods"} 12847
# alloy_component_controller_evaluation_duration_seconds{component_id="prometheus.scrape.pods",quantile="0.99"} 0.003
# alloy_component_dependencies_wait_seconds{component_id="loki.write.default"} 0

# Validate config before deploying
alloy fmt /etc/alloy/config.alloy > /dev/null && echo "config valid"

# Live reload (Alloy watches the config file by default)
kill -HUP $(pidof alloy)
# level=info component=alloy msg="config reloaded successfully"

# Debug a specific component
curl -s 'http://alloy:12345/api/v0/web/components/prometheus.scrape.pods' | jq .
# Shows: targets count, last scrape time, errors, labels
```

Alloy vs Prometheus + Promtail + OTel Collector separately: running three separate DaemonSets for metrics, logs, and traces multiplies your infrastructure overhead — three sets of resource limits, three ConfigMaps, three rollout operations when you update configuration. Alloy unifies them into one binary with one config file and one upgrade. The River language also lets you share discovery results between signals: discover Kubernetes pods once, use the same targets for both Prometheus scraping and Loki log collection. The trade-off is a larger binary and less maturity than the individual components (Alloy 1.x vs Prometheus's decades of battle-testing). For teams starting fresh on observability or consolidating a sprawling agent setup, Alloy is the right architectural direction.
