Firebase's appeal is the instant backend — auth, database, storage, all configured in minutes. Its weakness is a non-relational data model that becomes a constraint as your app grows. Supabase gives you the Firebase experience with a real Postgres database underneath.

## Setup

```bash
npm install @supabase/supabase-js
```

```ts
// lib/supabase.ts
import { createClient } from '@supabase/supabase-js';
import type { Database } from './database.types';  // generated from schema

export const supabase = createClient<Database>(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
);

// Server-side client with service role key (bypasses RLS)
export const supabaseAdmin = createClient<Database>(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!,
);
```

## Database operations

```ts
// Select with filters
const { data: posts, error } = await supabase
  .from('posts')
  .select('id, title, created_at, author:profiles(name, avatar_url)')
  .eq('published', true)
  .order('created_at', { ascending: false })
  .limit(10);

// Insert
const { data: post } = await supabase
  .from('posts')
  .insert({ title: 'Hello world', content: '...', author_id: userId })
  .select()
  .single();

// Update
await supabase
  .from('posts')
  .update({ published: true, published_at: new Date().toISOString() })
  .eq('id', postId);

// Delete
await supabase.from('posts').delete().eq('id', postId);

// Upsert
await supabase
  .from('user_preferences')
  .upsert({ user_id: userId, theme: 'dark', updated_at: new Date().toISOString() });
```

## Authentication

```ts
import { createClientComponentClient } from '@supabase/auth-helpers-nextjs';

const supabase = createClientComponentClient<Database>();

// Sign up
const { data, error } = await supabase.auth.signUp({
  email:    'lewis@construxgroup.io',
  password: 'secure-password',
  options: {
    data: { name: 'Lewis Wilson' },  // stored in user_metadata
  },
});

// Sign in with OAuth
await supabase.auth.signInWithOAuth({
  provider: 'github',
  options:  { redirectTo: `${location.origin}/auth/callback` },
});

// Get current session
const { data: { session } } = await supabase.auth.getSession();
const user = session?.user;

// Sign out
await supabase.auth.signOut();
```

## Row Level Security (RLS)

```sql
-- Enable RLS on the posts table
ALTER TABLE posts ENABLE ROW LEVEL SECURITY;

-- Users can only read published posts or their own drafts
CREATE POLICY "Read posts" ON posts
  FOR SELECT USING (
    published = true OR auth.uid() = author_id
  );

-- Users can only insert posts as themselves
CREATE POLICY "Create posts" ON posts
  FOR INSERT WITH CHECK (auth.uid() = author_id);

-- Users can only update their own posts
CREATE POLICY "Update own posts" ON posts
  FOR UPDATE USING (auth.uid() = author_id);
```

RLS policies run in Postgres — enforced at the database level regardless of how the query reaches the database.

## Realtime subscriptions

```ts
// Subscribe to changes on a table
const channel = supabase
  .channel('posts-changes')
  .on(
    'postgres_changes',
    { event: '*', schema: 'public', table: 'posts', filter: `author_id=eq.${userId}` },
    (payload) => {
      console.log('Change received:', payload);
      // payload.eventType: 'INSERT' | 'UPDATE' | 'DELETE'
      // payload.new: new row data
      // payload.old: old row data (for UPDATE and DELETE)
    },
  )
  .subscribe();

// Unsubscribe when done
supabase.removeChannel(channel);
```

## Storage

```ts
// Upload a file
const { data, error } = await supabase.storage
  .from('avatars')
  .upload(`${userId}/avatar.png`, file, {
    contentType: 'image/png',
    upsert:      true,
  });

// Get a public URL
const { data: { publicUrl } } = supabase.storage
  .from('avatars')
  .getPublicUrl(`${userId}/avatar.png`);

// Download (for private buckets)
const { data: blob } = await supabase.storage.from('documents').download(`${userId}/report.pdf`);
```

## Supabase vs Firebase vs PlanetScale

Supabase: open-source, Postgres, SQL, self-hostable. Firebase: proprietary, NoSQL (Firestore), no SQL, excellent mobile SDKs. PlanetScale: MySQL-compatible, serverless, branching for schema migrations — database only, no auth or storage. Use Supabase when you want a relational database with an integrated auth and storage layer and the option to self-host.
