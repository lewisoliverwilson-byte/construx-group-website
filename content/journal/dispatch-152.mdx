There's a tension in every professional tool between beginner accessibility and expert power. Simplify too much and you lose the advanced users who need depth. Add too much and you overwhelm newcomers and clutter the interface for everyone.

Progressive disclosure is the pattern that resolves this tension. Show the simple version first; reveal complexity as users demonstrate readiness for it. Here's how we've applied it across the Construx products.

## The principle

Progressive disclosure isn't about hiding features — it's about sequencing exposure. A user sees what they need to see at their current stage of use; more is available when they need it, without cluttering the experience before they do.

The failure mode of progressive disclosure is over-application: putting important features behind too many clicks because "most users won't need it." This is patronising and drives power users to competitors that trust them with their own tools.

The goal: a beginner can complete their task without being overwhelmed; an expert can access everything without being slowed down.

## Scoutr: staged results

Scoutr's scan result has two levels of information:

**Level 1 (always visible):** Confidence score, margin %, buy or pass recommendation. Three numbers. This is everything a user needs to make a purchase decision in the aisle.

**Level 2 (expandable):** Fee breakdown (eBay fees, shipping estimate, packing cost, VAT implication), historical sold prices, listing count, seasonal trend, comparable sold items. This is the evidence behind the recommendation.

Most users look at Level 1, make the decision, and move on. Power users open Level 2 to verify the margin calculation or check the sales velocity.

The distinction matters because in a physical retail environment, time is limited. A user scanning 40 items in an hour needs fast decisions. Opening the detail panel on every result would slow them down. But having the panel available — and remembering whether they tend to open it — means the interface adapts to their actual usage pattern without configuration.

We track whether a user typically expands the detail panel. Users who expand it on more than 60% of scans see it expanded by default. This isn't a setting; it's the interface learning the user's behaviour.

## The Marqet: filtered complexity

The Marqet's listing creation flow has 14 possible fields. Showing all 14 on first open is overwhelming and produces worse listings — sellers fill in required fields and skip optional ones because the form feels like too much work.

Our approach:

**Phase 1 (always shown):** Category, service description, pricing, contact method. The minimum required to go live.

**Phase 2 (shown after save):** Portfolio images, case studies, availability calendar, certifications. Enrichment that improves conversion.

**Phase 3 (shown for active listings):** Analytics view, A/B test variants, promoted listing options. Optimisation available once the listing is live.

Each phase is surfaced with context: "Add a portfolio to increase enquiries by 35%" is more actionable than "Optional: Portfolio images". The expansion feels earned rather than bureaucratic.

Power users who know what they want can access any field at any time through the "Full form" toggle. The phases are a default sequence, not a gate.

## The Hyve: keyboard-first power layer

The Hyve's power users are heavy keyboard users. They know the exact channel they want to navigate to, the exact command they want to run, the exact message they want to search.

We built a command palette (`Cmd+K`) that exposes all workspace actions as text commands:

```
> /channel sales        → jump to #sales
> /search last 7 days   → filtered message search
> /invite lewis@...     → invite member
> /archive #channel     → archive channel
```

The command palette is invisible to casual users who navigate by clicking. Power users who discover it (via the keyboard shortcut shown in the nav tooltip) never go back to the mouse for navigation.

The key design decision: the command palette doesn't gatekeep — everything in it is also accessible through the normal UI. It's a speed layer, not a power layer. Users don't have to earn it; they just have to discover it.

## Anti-patterns we avoided

**Wizard flows for everything.** Step-by-step wizards reduce cognitive load for first-time users but are maddening for experienced ones. We use wizards only for genuinely complex, one-time setup flows (initial workspace configuration in The Hyve). Routine actions use direct interfaces.

**"Advanced settings" catch-all.** Dumping everything into an "Advanced" tab is not progressive disclosure — it's admission that you haven't thought about information architecture. Every feature should live somewhere logical, and "advanced" should mean genuinely infrequently needed, not "we didn't know where to put this."

**Tooltips that cover content.** Contextual help is good; tooltips that appear on every interface element are noise. We use inline helper text only on first use, with a way to dismiss it permanently.

**Modals for everything.** Modals interrupt flow. Inline expansion (accordions, expandable sections) is usually better for progressive disclosure than modals because the user stays in context.

## What power users actually want

In interviews with Scoutr's most active users, three things came up consistently:

**Speed.** Power users have efficient workflows. Anything that adds friction to the common path — an extra click, a confirmation dialog for a reversible action, a loading state that feels longer than it needs to — is noticed.

**Memory.** Tools that remember your preferences, your last state, your usual patterns are experienced as intelligent. Tools that make you configure the same thing on every session are experienced as dumb.

**Control.** Power users want to know what the tool is doing and why. Black-box recommendations without explanation are distrusted. The confidence score in Scoutr comes with an expandable breakdown specifically because power users want to verify it.

Design for power users by removing friction from their existing workflow. The beginner experience benefits from this too — the same speed improvements that power users value make the interface feel responsive and capable for everyone.
