The Marqet launched with open listings — anyone could create an account and list services without any vetting. This is the right call at launch (friction kills early supply) but creates a problem at scale: buyers can't distinguish capable sellers from bad actors, and bad actors have no barrier to entry.

After 90 days and enough volume to see patterns, we built the verification system.

## What verification actually means

Verification is a claim: "we checked X about this seller." It is not a guarantee of quality or outcome. Buyers who understand this are better served than buyers who conflate verification with endorsement.

We verify two things:

**Identity verification:** The seller is a real person or registered business, not a fake account. We verify via government-issued ID (individual sellers) or Companies House registration (UK businesses) or equivalent.

**Ownership of claimed credentials:** If a seller claims to be a chartered accountant, a certified designer, or a licensed contractor, we verify the credential is real and current. We don't verify claimed skills that can't be independently checked ("10 years of experience in brand strategy").

We explicitly do not verify quality. Verified sellers range from exceptional to mediocre. Verification means identity and credentials are real, not that the work will be good.

## The verification flow

```
1. Seller submits verification request with:
   - Government ID (passport, driving licence, national ID)
   - Optional: credential documentation (certificates, registration numbers)
   - Optional: business registration number

2. Automated checks:
   - ID document authenticity (format validation, not forensic)
   - Credential number validation against public registers where available
     (Companies House: automated; chartered bodies: manual or API depending on body)

3. Manual review (within 24 hours):
   - Cross-reference submitted ID against account details
   - Verify professional credentials against primary sources
   - Flag any inconsistencies for follow-up

4. Result:
   - Verified (basic): identity confirmed
   - Verified (professional): identity + credential confirmed
   - Rejected: document unclear, credential not confirmed, inconsistency detected

5. Badge applied to profile + listing cards
```

The manual review step is the bottleneck. At current volumes (20-30 verification requests per week), we handle it without a dedicated ops function. At 10x, we'd need to automate more or hire.

## The verification badge design

The badge appears in two places: the seller's profile header and each listing card. Design decisions:

**What the badge says:** "Verified" — not "verified professional" or "identity verified." The hover tooltip explains: "Identity verified by The Marqet. Professional credentials verified where applicable." Full verification details on the seller's profile.

**What the badge doesn't say:** We don't show a checkmark without context. A checkmark alone is ambiguous ("verified what?"). The word "Verified" with the tooltip is more honest about what we've checked.

**Colour:** The same teal used for The Marqet's accent throughout the UI. It's on-brand and distinguishable from the orange of alerts and the green of completion states.

**Size:** Small — 12px chip on listing cards, 14px on profiles. Verification is a signal, not the lead element. The seller's name, ratings, and listing content are more prominent.

## The seller score

Beyond verification, we compute a seller score based on observable behaviour:

```ts
interface SellerScore {
  completionRate: number;     // % of accepted contracts completed
  disputeRate: number;        // % of contracts that went to dispute
  responseTime: number;       // median hours to first message response
  repeatBuyerRate: number;    // % of buyers who return for a second contract
  averageRating: number;      // average buyer rating (1-5)
}

function computeSellerTier(score: SellerScore, contractCount: number): SellerTier {
  if (contractCount < 5) return 'new';  // Not enough data
  
  const isTopPerformer = (
    score.completionRate >= 0.95 &&
    score.disputeRate <= 0.03 &&
    score.responseTime <= 4 &&
    score.repeatBuyerRate >= 0.20 &&
    score.averageRating >= 4.7
  );
  
  const isStandard = (
    score.completionRate >= 0.85 &&
    score.disputeRate <= 0.08 &&
    score.averageRating >= 4.0
  );
  
  if (isTopPerformer) return 'top';
  if (isStandard) return 'standard';
  return 'review';  // Below standard — flagged for internal monitoring
}
```

The tier isn't shown to buyers directly. It informs:
- Listing placement (higher-tier sellers get slightly better default placement)
- Dispute resolution priority (top sellers get faster resolution)
- Internal monitoring (review-tier sellers trigger additional screening on new listings)

We considered showing the tier publicly but decided against it. Public tiers create gaming incentives (sellers optimise for tier metrics rather than buyer outcomes) and can stigmatise sellers in recovery who are genuinely improving.

## The honest trade-offs

**False positives:** We have verified sellers who subsequently underperformed. Verification doesn't prevent this — we can only respond by revoking verification if trust signals deteriorate significantly.

**False negatives:** Exceptional unverified sellers exist. Some experienced freelancers haven't gone through verification because they don't need the badge to win contracts. Verification is a signal, not the only signal.

**Gaming:** The verification process can be gamed by someone with fraudulent documents. We're not running forensic document analysis — we're running a plausibility check. The verification reduces bad actors who can't be bothered to fabricate documents, not determined fraudsters.

**Cost:** The manual review step costs time. At current volume this is sustainable. We're not profitable enough yet to absorb a dedicated ops headcount.

None of these trade-offs are dealbreakers. Trust systems in marketplaces are probabilistic, not binary. The system we have reduces risk and increases buyer confidence — that's the right outcome, even imperfectly.
