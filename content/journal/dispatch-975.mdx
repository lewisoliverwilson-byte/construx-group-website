title: "Karpenter: node autoscaling for Kubernetes by workload shape"
date: "2032-12-17"
excerpt: "Karpenter is a Kubernetes node autoscaler built by AWS that provisions nodes based on the exact resource requirements of pending pods — instead of scaling predefined node groups, Karpenter selects the cheapest instance type that satisfies the pod's CPU, memory, GPU, and architecture constraints. It integrates with AWS Spot interruption handling, consolidates underutilized nodes, and can replace nodes running old AMIs via rolling drift detection. The key difference from Cluster Autoscaler: CA scales node groups (you define the groups); Karpenter provisions individual nodes from a pool of instance types, selecting the optimal one per workload. This produces lower costs (better bin-packing) and faster scale-out (no need to wait for ASG warmup)."

Node provisioning by pod shape. Spot handling. Node consolidation. Rolling AMI replacement.

## NodePool and EC2NodeClass

```yaml
# NodePool: defines what kinds of nodes Karpenter can provision
apiVersion: karpenter.sh/v1
kind: NodePool
metadata:
  name: construx-general
spec:
  template:
    metadata:
      labels:
        karpenter.sh/nodepool: construx-general
    spec:
      nodeClassRef:
        group: karpenter.k8s.aws
        kind: EC2NodeClass
        name: construx-default

      # Allow any combination of these requirements
      requirements:
        - key: kubernetes.io/arch
          operator: In
          values: [amd64, arm64]
        - key: karpenter.sh/capacity-type
          operator: In
          values: [spot, on-demand]  # prefer spot, fall back to on-demand
        - key: karpenter.k8s.aws/instance-category
          operator: In
          values: [c, m, r]         # compute, memory, general purpose
        - key: karpenter.k8s.aws/instance-generation
          operator: Gt
          values: ["3"]             # 4th gen and newer only
        - key: karpenter.k8s.aws/instance-size
          operator: NotIn
          values: [nano, micro, small]  # minimum viable instance

  # Disruption: when to remove nodes
  disruption:
    consolidationPolicy: WhenEmptyOrUnderutilized
    consolidateAfter: 1m       # consolidate after 1 minute of underutilization
    expireAfter: 720h          # replace nodes older than 30 days (AMI drift)

  limits:
    cpu: "1000"               # max total CPU across all Karpenter-managed nodes
    memory: 4000Gi

---
# EC2NodeClass: AWS-specific node configuration
apiVersion: karpenter.k8s.aws/v1
kind: EC2NodeClass
metadata:
  name: construx-default
spec:
  amiSelectorTerms:
    - alias: al2023@latest    # always use latest Amazon Linux 2023 AMI

  subnetSelectorTerms:
    - tags:
        karpenter.sh/discovery: construx-prod  # find subnets by tag

  securityGroupSelectorTerms:
    - tags:
        karpenter.sh/discovery: construx-prod

  role: KarpenterNodeRole-construx-prod  # IAM role for nodes

  # User data (cloud-init): runs on node startup
  userData: |
    #!/bin/bash
    /etc/eks/bootstrap.sh construx-prod \
      --kubelet-extra-args '--max-pods=110'

  blockDeviceMappings:
    - deviceName: /dev/xvda
      ebs:
        volumeSize: 50Gi
        volumeType: gp3
        iops: 3000
        throughput: 125
        deleteOnTermination: true
        encrypted: true
```

## GPU and specialized workloads

```yaml
# NodePool for GPU workloads (ML training)
apiVersion: karpenter.sh/v1
kind: NodePool
metadata:
  name: construx-gpu
spec:
  template:
    spec:
      nodeClassRef:
        group: karpenter.k8s.aws
        kind: EC2NodeClass
        name: construx-gpu

      requirements:
        - key: kubernetes.io/arch
          operator: In
          values: [amd64]
        - key: karpenter.sh/capacity-type
          operator: In
          values: [spot]            # GPU spot instances can be 70% cheaper
        - key: karpenter.k8s.aws/instance-family
          operator: In
          values: [p3, p4, g4dn, g5]   # GPU instance families
        - key: karpenter.k8s.aws/instance-size
          operator: In
          values: [xlarge, 2xlarge, 4xlarge, 12xlarge]

      taints:
        - key: nvidia.com/gpu
          value: "true"
          effect: NoSchedule        # only GPU-tolerating pods scheduled here

  disruption:
    consolidationPolicy: WhenEmpty  # don't consolidate mid-training
    expireAfter: 24h

---
# Pod that triggers GPU node provisioning
apiVersion: v1
kind: Pod
metadata:
  name: construx-training-job
spec:
  tolerations:
    - key: nvidia.com/gpu
      operator: Exists
      effect: NoSchedule
  containers:
    - name: trainer
      image: construx/ml-trainer:latest
      resources:
        requests:
          nvidia.com/gpu: "1"
          memory: 32Gi
          cpu: "8"
        limits:
          nvidia.com/gpu: "1"
  # Karpenter selects the cheapest GPU instance that fits 1 GPU + 32Gi + 8 CPU
```

## Spot interruption handling

```bash
# Karpenter handles Spot interruption notices automatically:
# 1. AWS sends a 2-minute interruption warning via EC2 Spot Instance Interruption Notice
# 2. Karpenter cordon the node (no new pods scheduled)
# 3. Karpenter drains pods (respects PodDisruptionBudgets)
# 4. Pods are rescheduled on other nodes
# 5. Karpenter provisions a new Spot or on-demand node as needed

# Monitor Karpenter events
kubectl get events -n kube-system --field-selector reason=SpotInterrupted

# Check which nodes Karpenter manages
kubectl get nodes -l karpenter.sh/nodepool=construx-general

# View Karpenter metrics (Prometheus)
kubectl port-forward -n kube-system svc/karpenter 8080:8080 &
curl http://localhost:8080/metrics | grep karpenter_nodes

# Karpenter-specific metrics:
# karpenter_nodes_created_total           — nodes provisioned
# karpenter_nodes_terminated_total        — nodes removed
# karpenter_pods_startup_duration_seconds — time from pending to running
# karpenter_interruption_received_messages_total — spot interruptions

# Consolidation: Karpenter actively removes underutilized nodes
# When pods on a node can fit on other existing nodes:
# → Karpenter migrates pods and terminates the empty node
# Result: cluster right-sizes itself without manual intervention
kubectl logs -n kube-system -l app.kubernetes.io/name=karpenter | grep "consolidation"
# INFO  consolidation: calculated 3 nodes to remove (saving $0.42/hr)
```

## Drift and AMI rolling updates

```bash
# Karpenter drift: automatically replaces nodes running outdated AMIs
# expireAfter: 720h in NodePool → nodes older than 30 days are replaced

# When drift is detected (new AMI available or node exceeds expireAfter):
# 1. Karpenter provisions a new node with the latest AMI
# 2. Cordons and drains the old node (respects PDBs)
# 3. Terminates the old node when drained

# Force AMI update (trigger drift detection manually)
kubectl annotate nodeclaim \
  -l karpenter.sh/nodepool=construx-general \
  karpenter.sh/do-not-disrupt-

# Check node AMI versions
kubectl get nodes -l karpenter.sh/nodepool=construx-general \
  -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.metadata.labels.karpenter\.k8s\.aws/instance-ami-id}{"\n"}{end}'

# View all NodeClaims (Karpenter's node lifecycle objects)
kubectl get nodeclaims
# NAME                            TYPE            CAPACITY    ZONE          NODE
# construx-general-7f9b2c         m6i.2xlarge     spot        eu-west-1a    ip-10-0-1-15...
# construx-general-8k3n4p         c6i.xlarge      on-demand   eu-west-1b    ip-10-0-2-22...
# construx-gpu-2m1q5r             g4dn.xlarge     spot        eu-west-1a    ip-10-0-3-10...
```

Karpenter vs Cluster Autoscaler: Cluster Autoscaler (CA) scales predefined Auto Scaling Groups — you define the node groups, CA adjusts their sizes. The limitation: you must predict and pre-define the node shapes you'll need. Karpenter picks the optimal instance type from a pool of thousands of options, considering Spot availability, price, and your workload's exact requirements. The result: Karpenter typically achieves 20-40% lower EC2 costs through better instance selection and more aggressive consolidation. The tradeoff: Karpenter is more complex to configure correctly (NodePools, EC2NodeClass, disruption policies) and is AWS-specific (though GCP and Azure support is in development).
