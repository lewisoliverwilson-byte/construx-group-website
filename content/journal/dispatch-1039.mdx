date: "2033-06-27"
excerpt: "Turso is a database platform built on libSQL (an open-source fork of SQLite) that enables per-tenant databases at the edge. The model: each tenant gets their own database (a libSQL instance) that can be embedded in any runtime or accessed over HTTPS. Turso manages database provisioning, replication to edge locations, and sync. The key use case is multi-tenancy: instead of isolating tenants with row-level security in a shared database, each tenant gets their own database — no cross-tenant query risk, schema migrations per tenant, and the ability to move tenants between plans by migrating their database. Turso's libSQL driver runs in Node.js, Bun, Cloudflare Workers, and Deno. The embedded mode (used in Electron apps or desktop tools) runs SQLite directly in the process with sync to a remote Turso database when online."

libSQL. Per-tenant databases. Edge replication. Embedded mode. HTTP protocol. SQLite-compatible.

## Creating and querying databases

```bash
# Turso CLI
turso auth login

# Create a database (each tenant gets their own)
turso db create construx-tenant-10001 --location lhr   # London edge location
# Created database construx-tenant-10001 at group default in 1.3s
# URL: libsql://construx-tenant-10001-construx.turso.io

# Create a token for the database
turso db tokens create construx-tenant-10001 --expiration none
# eyJhbGciOi...

# List databases
turso db list
# NAME                    LOCATION  SIZE   CONNECTIONS
# construx-tenant-10001  lhr       2.1MB  0
# construx-tenant-10002  lhr       1.8MB  0

# Create a group (replicated to multiple locations)
turso group create construx-prod --location lhr,cdg,ams

# Create a database in the group (automatically replicated to all locations)
turso db create construx-tenant-10001 --group construx-prod
```

## Connecting and querying

```typescript
// TypeScript: Turso client (libSQL driver)

import { createClient } from "@libsql/client";

// Per-tenant connection factory
function getTenantDb(tenantId: string) {
    return createClient({
        url:       `libsql://construx-tenant-${tenantId}.turso.io`,
        authToken: process.env[`TURSO_TOKEN_${tenantId}`]
                   ?? process.env.TURSO_ADMIN_TOKEN,
    });
}

// Use in API handler
export async function GET(req: Request) {
    const tenantId = req.headers.get("X-Tenant-ID");
    const db = getTenantDb(tenantId);

    const { rows } = await db.execute(
        "SELECT * FROM products WHERE status = ? ORDER BY created_at DESC LIMIT 20",
        ["active"],
    );

    return Response.json({ products: rows });
}

// Transactions
const db = getTenantDb("10001");
const transaction = await db.transaction("write");
try {
    await transaction.execute({
        sql: "INSERT INTO orders (id, user_id, total_pence) VALUES (?, ?, ?)",
        args: [orderId, userId, totalPence],
    });
    await transaction.execute({
        sql: "UPDATE inventory SET stock = stock - ? WHERE product_id = ?",
        args: [quantity, productId],
    });
    await transaction.commit();
} catch (err) {
    await transaction.rollback();
    throw err;
}

// Batch: run multiple statements in one round trip
const results = await db.batch([
    { sql: "SELECT count(*) FROM orders WHERE status = ?", args: ["pending"] },
    { sql: "SELECT count(*) FROM orders WHERE status = ?", args: ["completed"] },
    { sql: "SELECT sum(total_pence) FROM orders WHERE created_at > ?", args: [thirtyDaysAgo] },
]);
const [pending, completed, revenue] = results;
```

## Per-tenant provisioning and migration

```typescript
// Provision a new tenant database on signup
async function provisionTenantDatabase(tenantId: string, planTier: string) {
    const response = await fetch("https://api.turso.tech/v1/databases", {
        method: "POST",
        headers: {
            Authorization: `Bearer ${process.env.TURSO_ORG_TOKEN}`,
            "Content-Type": "application/json",
        },
        body: JSON.stringify({
            name:     `construx-tenant-${tenantId}`,
            group:    "construx-prod",
            location: getEdgeLocation(planTier), // "lhr" for EU, "iad" for US
        }),
    });

    const { database } = await response.json();

    // Create an auth token for this database
    const tokenResponse = await fetch(
        `https://api.turso.tech/v1/databases/construx-tenant-${tenantId}/auth/tokens`,
        {
            method: "POST",
            headers: { Authorization: `Bearer ${process.env.TURSO_ORG_TOKEN}` },
        },
    );
    const { jwt: token } = await tokenResponse.json();

    // Store the token in your secrets manager (External Secrets Operator / Vault)
    await storeSecret(`TURSO_TOKEN_${tenantId}`, token);

    // Run initial migrations on the new database
    const db = createClient({ url: database.hostname, authToken: token });
    await db.execute(`CREATE TABLE products (
        id TEXT PRIMARY KEY,
        name TEXT NOT NULL,
        price_pence INTEGER NOT NULL,
        status TEXT DEFAULT 'active',
        created_at DATETIME DEFAULT CURRENT_TIMESTAMP
    )`);
    await db.execute(`CREATE INDEX idx_products_status ON products (status, created_at DESC)`);

    return { databaseUrl: database.hostname, tenantId };
}

// Schema migration across all tenant databases
// (run in a batch job — one migration per tenant database)
async function migrateAllTenants(migrationSql: string) {
    const databases = await listTursoDatabases();
    const results = await Promise.allSettled(
        databases.map(async (db) => {
            const client = getTenantDb(db.tenantId);
            await client.execute(migrationSql);
            return db.tenantId;
        }),
    );
    const failures = results.filter(r => r.status === "rejected");
    if (failures.length > 0) console.error("Migration failed for:", failures);
}
```

Turso vs PlanetScale vs shared PostgreSQL with RLS vs per-tenant PostgreSQL schemas: Shared PostgreSQL with RLS (row-level security) is simple to start but complex at scale — all tenant data is in one database, so one bad query can affect all tenants, and performance is shared. Per-tenant PostgreSQL schemas (schema-per-tenant) avoids some cross-tenant risk but still shares a PostgreSQL instance, and connection counts per tenant add up. PlanetScale (Vitess/MySQL) supports database-per-tenant but MySQL connection overhead limits how many databases you can run. Turso's advantage is the libSQL embedded mode and the edge replication — each database can be < 1MB for small tenants and sits at the edge closest to that tenant's users. The SQLite-compatible API means no new query language and works with Drizzle, Prisma, and raw SQL. The constraint: SQLite's write scalability (one writer at a time) means Turso is not suitable for tenants with high concurrent write rates — it's best for read-heavy SaaS where most tenants write occasionally.
