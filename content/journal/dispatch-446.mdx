Both Prisma and Drizzle solve the same problem: type-safe database queries in TypeScript. They take different approaches and have meaningfully different tradeoffs.

## Prisma: schema-first

Prisma uses a dedicated `.prisma` schema file. You define models, and Prisma generates the client:

```prisma
// schema.prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

model User {
  id        String   @id @default(cuid())
  email     String   @unique
  name      String?
  posts     Post[]
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

model Post {
  id        String   @id @default(cuid())
  title     String
  content   String
  published Boolean  @default(false)
  author    User     @relation(fields: [authorId], references: [id])
  authorId  String
  createdAt DateTime @default(now())
}
```

```ts
// Queries are type-safe, autocompleted
const user = await prisma.user.findUnique({
  where: { email: 'lewis@construxgroup.io' },
  include: { posts: { where: { published: true } } },
});

user?.posts.forEach((post) => {
  console.log(post.title);  // TypeScript knows post.title is string
});
```

## Drizzle: code-first

Drizzle defines schema in TypeScript files. No schema language to learn:

```ts
// db/schema.ts
import { pgTable, text, boolean, timestamp } from 'drizzle-orm/pg-core';
import { relations } from 'drizzle-orm';

export const users = pgTable('users', {
  id: text('id').primaryKey().$defaultFn(() => crypto.randomUUID()),
  email: text('email').notNull().unique(),
  name: text('name'),
  createdAt: timestamp('created_at').defaultNow().notNull(),
  updatedAt: timestamp('updated_at').defaultNow().notNull(),
});

export const posts = pgTable('posts', {
  id: text('id').primaryKey().$defaultFn(() => crypto.randomUUID()),
  title: text('title').notNull(),
  content: text('content').notNull(),
  published: boolean('published').default(false).notNull(),
  authorId: text('author_id').notNull().references(() => users.id),
  createdAt: timestamp('created_at').defaultNow().notNull(),
});

export const usersRelations = relations(users, ({ many }) => ({
  posts: many(posts),
}));

export const postsRelations = relations(posts, ({ one }) => ({
  author: one(users, { fields: [posts.authorId], references: [users.id] }),
}));
```

```ts
// Queries are closer to SQL
const user = await db.query.users.findFirst({
  where: eq(users.email, 'lewis@construxgroup.io'),
  with: { posts: { where: eq(posts.published, true) } },
});
```

## Direct SQL comparison

```ts
// Prisma — fluent API
const result = await prisma.post.findMany({
  where: {
    published: true,
    author: { email: { contains: '@construxgroup.io' } },
  },
  orderBy: { createdAt: 'desc' },
  take: 10,
  select: { id: true, title: true, author: { select: { name: true } } },
});

// Drizzle — SQL-like
const result = await db
  .select({
    id: posts.id,
    title: posts.title,
    authorName: users.name,
  })
  .from(posts)
  .innerJoin(users, eq(posts.authorId, users.id))
  .where(
    and(
      eq(posts.published, true),
      like(users.email, '%@construxgroup.io'),
    )
  )
  .orderBy(desc(posts.createdAt))
  .limit(10);
```

## Migrations

**Prisma:**
```bash
npx prisma migrate dev --name add_post_tags
# Generates SQL migration file, applies it, regenerates client
```

**Drizzle:**
```bash
npx drizzle-kit generate
npx drizzle-kit migrate
# Generates SQL from schema diff, you run it explicitly
```

## Raw SQL escape hatch

```ts
// Prisma
const result = await prisma.$queryRaw<Post[]>`
  SELECT * FROM "Post"
  WHERE to_tsvector('english', title) @@ plainto_tsquery('english', ${query})
  LIMIT 20
`;

// Drizzle — uses tagged template sql``
const result = await db.execute(sql`
  SELECT * FROM posts
  WHERE to_tsvector('english', title) @@ plainto_tsquery('english', ${query})
  LIMIT 20
`);
```

## When to choose each

**Choose Prisma when:**
- You want the most ergonomic API with the least SQL knowledge required
- Your team finds the Prisma schema language clearer than TypeScript
- You want Prisma Studio (GUI for your database) during development
- Relations and nested queries are common

**Choose Drizzle when:**
- You want full SQL control with type safety on top
- You prefer schema-in-code (TypeScript all the way down)
- You're performance-conscious (Drizzle produces leaner queries)
- You do a lot of raw SQL anyway

**The actual difference in practice**: Prisma is higher-level — it handles more for you but is harder to override. Drizzle is closer to the metal — more control, slightly more verbose, but fewer surprises.

At Construx, we use Drizzle for its SQL transparency. When a query performs badly, the fix is clear because you can see exactly what SQL is being generated.
