Next.js is the right choice for applications. Astro is the right choice for content sites — documentation, blogs, marketing pages — where the goal is fast HTML delivery.

## Create a project

```bash
npm create astro@latest my-site
cd my-site
npm run dev
```

## File-based routing

```
src/
  pages/
    index.astro          → /
    about.astro          → /about
    blog/
      index.astro        → /blog
      [slug].astro       → /blog/:slug
  layouts/
    Base.astro
  components/
    Header.astro
    Card.astro
```

## Astro components

```astro
---
// src/pages/index.astro
// Frontmatter — runs at build time on the server
import { getCollection } from 'astro:content';
import Layout           from '../layouts/Base.astro';
import Card             from '../components/Card.astro';

const posts = await getCollection('blog');
const latest = posts
  .sort((a, b) => b.data.date.valueOf() - a.data.date.valueOf())
  .slice(0, 6);
---

<!-- HTML template — zero JS shipped by default -->
<Layout title="Home">
  <h1>Latest posts</h1>
  <div class="grid">
    {latest.map((post) => (
      <Card title={post.data.title} href={`/blog/${post.slug}`} />
    ))}
  </div>
</Layout>
```

## Content Collections

```ts
// src/content/config.ts
import { defineCollection, z } from 'astro:content';

const blog = defineCollection({
  type:   'content',
  schema: z.object({
    title:       z.string(),
    date:        z.date(),
    excerpt:     z.string().optional(),
    tags:        z.array(z.string()).default([]),
    draft:       z.boolean().default(false),
  }),
});

export const collections = { blog };
```

```astro
---
// src/pages/blog/[slug].astro
import { getCollection } from 'astro:content';

export async function getStaticPaths() {
  const posts = await getCollection('blog', ({ data }) => !data.draft);
  return posts.map((post) => ({
    params: { slug: post.slug },
    props:  { post },
  }));
}

const { post } = Astro.props;
const { Content } = await post.render();
---

<article>
  <h1>{post.data.title}</h1>
  <Content />
</article>
```

## Islands: add interactivity where needed

```astro
---
import ReactCounter from '../components/Counter.tsx';
import VueChart     from '../components/Chart.vue';
---

<!-- Static HTML — no JS -->
<p>This text ships as pure HTML.</p>

<!-- Hydrate immediately when the page loads -->
<ReactCounter client:load initialCount={0} />

<!-- Hydrate when the component enters the viewport -->
<VueChart client:visible data={chartData} />

<!-- Hydrate only on user interaction -->
<ReactCounter client:idle />
```

Each `client:` directive is an island. Only that component ships JavaScript. Everything else is static HTML.

## Astro vs Next.js

Astro: content-first, near-zero JS by default, framework-agnostic, excellent for documentation and marketing. Next.js: application-first, full React ecosystem, server actions, streaming. Use Astro when your pages are mostly static content. Use Next.js when your pages have significant interactivity or need server-side logic per request. The two are not competitors — they solve different problems.
