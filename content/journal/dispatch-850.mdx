excerpt: "Envoy is a high-performance proxy written in C++. It is the data plane in service meshes (Istio, AWS App Mesh) and a standalone edge proxy. Envoy is configured via xDS APIs — gRPC streaming APIs that push route, cluster, listener, and endpoint configuration dynamically without restarting the proxy. This enables zero-downtime configuration changes, blue/green traffic splits, and circuit breaker policies that update in real time as your fleet changes."

L4 and L7 proxy. xDS for live config. Circuit breakers and retries built in.

## Static configuration — bootstrap envoy.yaml

```yaml
# envoy.yaml — static configuration (suitable for local dev and small deployments)
static_resources:
  listeners:
    - name:    listener_0
      address:
        socket_address: { address: 0.0.0.0, port_value: 10000 }
      filter_chains:
        - filters:
            - name: envoy.filters.network.http_connection_manager
              typed_config:
                "@type": type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
                stat_prefix: ingress_http
                route_config:
                  name: local_route
                  virtual_hosts:
                    - name:    construx_api
                      domains: ["*"]
                      routes:
                        - match: { prefix: "/api/orders" }
                          route:
                            cluster: orders_service
                            timeout: { seconds: 30 }
                            retry_policy:
                              retry_on: "5xx,gateway-error,connect-failure"
                              num_retries: 3
                              per_try_timeout: { seconds: 10 }
                        - match: { prefix: "/" }
                          route: { cluster: web_service }
                http_filters:
                  - name: envoy.filters.http.router
                    typed_config:
                      "@type": type.googleapis.com/envoy.extensions.filters.http.router.v3.Router

  clusters:
    - name:                 orders_service
      connect_timeout:      { seconds: 5 }
      type:                 STRICT_DNS
      lb_policy:            LEAST_REQUEST
      load_assignment:
        cluster_name: orders_service
        endpoints:
          - lb_endpoints:
              - endpoint:
                  address:
                    socket_address: { address: orders-api, port_value: 3000 }
              - endpoint:
                  address:
                    socket_address: { address: orders-api-2, port_value: 3000 }

      # Circuit breaker configuration
      circuit_breakers:
        thresholds:
          - priority:      DEFAULT
            max_connections:     1000
            max_pending_requests: 1000
            max_requests:        1000
            max_retries:         3

      # Outlier detection — automatic ejection of unhealthy endpoints
      outlier_detection:
        consecutive_5xx:               5
        interval:                      { seconds: 10 }
        base_ejection_time:            { seconds: 30 }
        max_ejection_percent:          50
        enforcing_consecutive_5xx:     100
```

## xDS — dynamic configuration via control plane

```yaml
# Dynamic bootstrap — configuration comes from a control plane (e.g., Istio Pilot)
dynamic_resources:
  lds_config:
    resource_api_version: V3
    api_config_source:
      api_type:             GRPC
      transport_api_version: V3
      grpc_services:
        - envoy_grpc:
            cluster_name: xds_cluster

  cds_config:
    resource_api_version: V3
    api_config_source:
      api_type:             GRPC
      transport_api_version: V3
      grpc_services:
        - envoy_grpc:
            cluster_name: xds_cluster

static_resources:
  clusters:
    - name:             xds_cluster
      connect_timeout:  { seconds: 5 }
      type:             STRICT_DNS
      load_assignment:
        cluster_name: xds_cluster
        endpoints:
          - lb_endpoints:
              - endpoint:
                  address:
                    socket_address: { address: pilot.istio-system, port_value: 15010 }
```

## Traffic splitting — blue/green and canary

```yaml
# Route 10% of /api traffic to the canary cluster, 90% to stable
routes:
  - match: { prefix: "/api/" }
    route:
      weighted_clusters:
        clusters:
          - name:   api_stable
            weight: 90
          - name:   api_canary
            weight: 10
        total_weight: 100
      timeout: { seconds: 30 }
```

## Envoy admin API — live stats and config

```bash
# Access admin interface (never expose publicly)
curl http://localhost:9901/stats | grep "cluster.orders_service"
# cluster.orders_service.upstream_rq_total: 18241
# cluster.orders_service.upstream_rq_2xx: 18103

curl http://localhost:9901/clusters | grep "health_flags"
```

## Rate limiting with envoy filter

```yaml
http_filters:
  - name: envoy.filters.http.local_ratelimit
    typed_config:
      "@type": type.googleapis.com/udpa.type.v1.TypedStruct
      type_url: type.googleapis.com/envoy.extensions.filters.http.local_ratelimit.v3.LocalRateLimit
      value:
        stat_prefix: http_local_rate_limiter
        token_bucket:
          max_tokens:          1000
          tokens_per_fill:     1000
          fill_interval:       { seconds: 1 }
        filter_enabled:
          runtime_key:   local_rate_limit_enabled
          default_value: { numerator: 100, denominator: HUNDRED }
        response_headers_to_add:
          - header:   { key: x-rate-limit-limit,     value: "1000" }
          - header:   { key: x-rate-limit-remaining, value: "%DYNAMIC_METADATA(local_rate_limit:remaining)%" }
```

Envoy vs nginx: nginx is configuration-file driven — every change requires a reload (though nginx can reload without dropping connections). Envoy is API-driven — xDS pushes configuration changes in milliseconds without any reload. Nginx has a larger module ecosystem and is simpler to operate standalone. Envoy is designed as a programmable infrastructure component: it integrates with service meshes, supports gRPC-based control planes, and exposes richer telemetry via Prometheus. For service meshes and dynamic microservice environments, Envoy. For static configurations and edge termination, nginx.
