Deno was created by Ryan Dahl (the creator of Node.js) as a re-do with the benefit of hindsight. Deno 2 makes the key move that v1 didn't: full npm compatibility. You can now run most Node.js code in Deno without changes.

## Getting started

```bash
curl -fsSL https://deno.land/install.sh | sh

# Run TypeScript natively
deno run main.ts

# No configuration file needed
# No package.json, no tsconfig.json, no eslint.config.js required
```

## TypeScript without configuration

```ts
// main.ts — TypeScript, no compilation step
import { Hono } from 'npm:hono';

const app = new Hono();

app.get('/api/posts', async (c) => {
  const posts = await fetch('https://jsonplaceholder.typicode.com/posts');
  return c.json(await posts.json());
});

Deno.serve({ port: 3000 }, app.fetch);
```

```bash
deno run --allow-net main.ts
```

Deno runs TypeScript directly using the V8 engine + Rust-based transpiler. No `ts-node`, no `tsx`, no build step.

## npm compatibility

```ts
// npm: prefix imports npm packages
import express from 'npm:express@4';
import { z }   from 'npm:zod@3';
import Stripe  from 'npm:stripe';

// Node.js built-ins work too
import { readFile } from 'node:fs/promises';
import path         from 'node:path';
```

```bash
# Or use a package.json (Deno 2 is fully compatible)
deno install   # install from package.json
deno run dev   # run 'dev' script from package.json
```

Deno 2 supports `package.json` natively. Existing Node.js projects often run with just `deno run main.ts`.

## Permissions: secure by default

Deno requires explicit permissions for file system, network, and environment access:

```bash
# Grant only what you need
deno run --allow-read=./data --allow-write=./output main.ts
deno run --allow-net=api.example.com main.ts
deno run --allow-env=DATABASE_URL main.ts

# Or grant all (not recommended for production)
deno run --allow-all main.ts
```

A Deno script can't read arbitrary files or make network requests without explicit permission. This is useful for running untrusted scripts or third-party tools — you can see exactly what they're asking for.

## Standard library

Deno ships a standard library (`@std/`) with well-tested utilities:

```ts
import { join, extname } from 'jsr:@std/path';
import { walk }          from 'jsr:@std/fs';
import { bold, red }     from 'jsr:@std/fmt/colors';
import { parse }         from 'jsr:@std/csv';

// No npm equivalents needed for common tasks
const files = walk('./src', { exts: ['.ts', '.tsx'] });
for await (const entry of files) {
  console.log(bold(entry.path));
}
```

JSR (JavaScript Registry) is the modern package registry for Deno (and Node.js). It enforces TypeScript-first packages.

## Built-in tooling

```bash
deno fmt         # format all TypeScript/JavaScript files (opinionated, no config)
deno lint        # lint (built-in rules, no ESLint config needed)
deno test        # run tests
deno doc main.ts # generate documentation
deno compile main.ts  # compile to a single executable binary
deno task dev    # run custom tasks from deno.json
```

No separate tools: no Prettier, no ESLint, no Jest. All built in, all zero-config.

## Configuration (optional)

```json
// deno.json
{
  "tasks": {
    "dev":   "deno run --watch --allow-all main.ts",
    "test":  "deno test --allow-all",
    "build": "deno compile --allow-all --output ./dist/server main.ts"
  },
  "imports": {
    "@/": "./src/"
  },
  "compilerOptions": {
    "strict": true
  }
}
```

`deno.json` replaces `package.json` scripts, `tsconfig.json`, and import aliases. It's optional — Deno works without it.

## Deno Deploy: edge deployment

```bash
npm install -g deployctl
deployctl deploy --project=construx main.ts
```

Deno Deploy runs your code in V8 isolates across 35+ regions — similar to Cloudflare Workers. Supported APIs: Fetch, Web Crypto, Deno KV (built-in key-value store), WebSockets, and most Deno standard library functions.

```ts
// Deno KV: a globally replicated key-value store
const kv = await Deno.openKv();
await kv.set(['users', userId], { name, email, createdAt });
const user = await kv.get(['users', userId]);
```

## When Deno vs Node.js

**Use Deno for**: scripts, CLI tools, new greenfield services, projects where the security model matters, teams that want zero-config TypeScript.

**Stick with Node.js for**: existing projects with native modules, teams heavily invested in the npm ecosystem, projects that deploy to platforms without Deno support (Lambda without the Deno layer, etc.).

The gap is narrowing. Deno 2's npm compatibility means most Node.js code runs in Deno. The tooling story (built-in formatter, linter, test runner, compiler) is genuinely better than Node.js's ecosystem of separate tools.
