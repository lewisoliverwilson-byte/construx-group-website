ESLint plus Prettier means two config files, two tool chains, occasional rule conflicts, and slow CI runs. Biome is one binary that does both, faster.

## Install

```bash
npm install --save-dev --save-exact @biomejs/biome
npx @biomejs/biome init
```

That creates `biome.json`. Add scripts to `package.json`:

```json
{
  "scripts": {
    "lint":    "biome lint src/",
    "format":  "biome format --write src/",
    "check":   "biome check --write src/",
    "ci":      "biome ci src/"
  }
}
```

`check` runs lint and format in one pass. `ci` runs both without writing (exits non-zero if anything fails).


## Migrate from ESLint + Prettier

```bash
# Biome provides a migration command
npx @biomejs/biome migrate eslint  --write
npx @biomejs/biome migrate prettier --write

# Then remove old tools
npm uninstall eslint prettier @typescript-eslint/parser @typescript-eslint/eslint-plugin \
  eslint-config-prettier eslint-plugin-prettier

# Delete old config files
rm .eslintrc.* .prettierrc.* .eslintignore .prettierignore
```

The migration command reads your existing config and writes equivalent Biome rules. Not 100% rule parity — some ESLint rules have no Biome equivalent — but the most common ones migrate cleanly.

## VS Code integration

```json
// .vscode/settings.json
{
  "editor.defaultFormatter":          "biomejs.biome",
  "editor.formatOnSave":              true,
  "editor.codeActionsOnSave": {
    "quickfix.biome":                 "explicit",
    "source.organizeImports.biome":   "explicit"
  },
  "[typescript]": {
    "editor.defaultFormatter": "biomejs.biome"
  },
  "[typescriptreact]": {
    "editor.defaultFormatter": "biomejs.biome"
  }
}
```

Install the Biome VS Code extension: `biomejs.biome`.

## CI

```yaml
- name: Biome check
  run:  npx @biomejs/biome ci --reporter=github src/
```

`--reporter=github` annotates PRs inline with lint errors. No separate lint and format steps — one command, one result.

## Performance

```bash
# Format 1000 TypeScript files
time biome format src/
# → 0.18s

time prettier --write "src/**/*.{ts,tsx}"
# → 4.6s
```

The speed comes from Rust and true parallelism. Biome processes files in parallel across all CPU cores. Prettier is single-threaded.

## Biome vs ESLint + Prettier vs oxlint

Biome: one tool, Rust speed, good rule coverage, formats and lints. ESLint: maximum rule coverage, best ecosystem, slower. oxlint: fastest linter only (no formatter), great ESLint rule compatibility. Biome is the right default for new TypeScript projects. ESLint stays relevant for projects that need specific plugins (storybook, testing-library) that Biome does not yet support.
