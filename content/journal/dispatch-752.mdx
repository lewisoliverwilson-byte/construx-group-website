Server Components are not SSR. The mental model is different and the distinction matters.

## The split

```
Server Components         Client Components
────────────────────────  ──────────────────────────
Run on server only        Run on server + client
Zero JS bundle impact     Included in JS bundle
Direct DB / FS access     No DB / FS access
No hooks (useState etc.)  Full React API
No browser APIs           Full browser API
Async by default          Sync (except for new use())
```

Server Components are the default in Next.js App Router. Client Components require `'use client'` at the top of the file.

## Server Component — data fetching

```tsx
// app/dashboard/page.tsx — no 'use client' = Server Component
import { db }    from '@/lib/db';
import { users } from '@/lib/schema';

export default async function DashboardPage() {
  // Direct database access — no API route needed
  const allUsers = await db.select().from(users).limit(10);

  return (
    <ul>
      {allUsers.map((u) => (
        <li key={u.id}>{u.email}</li>
      ))}
    </ul>
  );
}
```

This ships zero JavaScript for the list rendering. The HTML arrives complete.

## Async in Server Components

```tsx
// Waterfall — sequential
const user      = await getUser(id);
const workspace = await getWorkspace(user.workspaceId);

// Parallel — use Promise.all
const [user, workspace] = await Promise.all([
  getUser(id),
  getWorkspace(id),
]);
```

## Client Component — interactivity

```tsx
'use client';
import { useState } from 'react';

export function Counter({ initialCount }: { initialCount: number }) {
  const [count, setCount] = useState(initialCount);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

## Passing Server Component data to Client Components

```tsx
// app/dashboard/page.tsx — Server Component
import { Counter } from './Counter';
import { db }      from '@/lib/db';

export default async function DashboardPage() {
  const { clickCount } = await db.query.stats.findFirst();

  // Server fetches → passes as prop to Client Component
  return <Counter initialCount={clickCount} />;
}
```

Only serialisable values (strings, numbers, plain objects, arrays) can cross the boundary. Functions, class instances, and non-serialisable types cannot.

## Context from Server Components

```tsx
// Can't use React context in Server Components
// Pattern: fetch in server, pass as prop
export default async function Layout({ children }: { children: React.ReactNode }) {
  const session = await getServerSession();
  return <SessionProvider session={session}>{children}</SessionProvider>;
}
```

`SessionProvider` is a Client Component that wraps `children` (which may include Server Components) in a context provider. The Server Component tree renders as RSC payload; the Client Component provides context only to other Client Components beneath it.

## Streaming with Suspense

```tsx
// app/dashboard/page.tsx
import { Suspense } from 'react';

export default function DashboardPage() {
  return (
    <div>
      <h1>Dashboard</h1>
      {/* Slow data — show skeleton while loading */}
      <Suspense fallback={<AnalyticsSkeleton />}>
        <AnalyticsPanel />  {/* Server Component with slow query */}
      </Suspense>
    </div>
  );
}
```

The page HTML streams in: the shell renders immediately, `AnalyticsPanel` arrives when its async work completes. No loading state code needed in the Client.

## When to use each

Server Component: data fetching, rendering from DB/CMS/API, auth checks, large library imports that should not be in the bundle. Client Component: event handlers, useState, useEffect, browser APIs, third-party libraries that require client APIs. The rule: default to Server Components, add `'use client'` only at the point where interactivity begins.
