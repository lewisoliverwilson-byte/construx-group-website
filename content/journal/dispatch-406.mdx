OAuth 2.0 is a delegation protocol, not an authentication protocol. The confusion matters: OAuth tells you that a user authorized your app to access their GitHub account — it doesn't tell you who the user is. OpenID Connect (OIDC) sits on top of OAuth to add identity. Providers like Google and GitHub implement both.

## The flow

```
1. User clicks "Sign in with GitHub"
2. Your app redirects to GitHub with: client_id, redirect_uri, scope, state
3. User authorizes on GitHub
4. GitHub redirects back to your app with: code, state
5. Your server exchanges code for access_token (server-to-server, client_secret included)
6. Your server uses access_token to fetch user profile from GitHub API
7. You create or update the user in your database and issue a session
```

The `state` parameter is a CSRF token — generate it, store it in a cookie, verify it matches when GitHub sends the user back.

## Auth.js setup

Auth.js (formerly NextAuth.js v5) handles the entire flow:

```bash
npm install next-auth@beta
```

```ts
// auth.ts
import NextAuth from 'next-auth';
import GitHub from 'next-auth/providers/github';
import Google from 'next-auth/providers/google';
import { DrizzleAdapter } from '@auth/drizzle-adapter';
import { db } from '@/lib/db';

export const { handlers, auth, signIn, signOut } = NextAuth({
  adapter: DrizzleAdapter(db),
  providers: [
    GitHub({
      clientId: process.env.GITHUB_CLIENT_ID!,
      clientSecret: process.env.GITHUB_CLIENT_SECRET!,
    }),
    Google({
      clientId: process.env.GOOGLE_CLIENT_ID!,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
      authorization: {
        params: {
          prompt: 'consent',
          access_type: 'offline',  // get refresh token
          response_type: 'code',
        },
      },
    }),
  ],
  callbacks: {
    session({ session, user }) {
      session.user.id = user.id;
      return session;
    },
  },
});
```

```ts
// app/api/auth/[...nextauth]/route.ts
import { handlers } from '@/auth';
export const { GET, POST } = handlers;
```

## Account linking

Users may sign in with GitHub first, then try Google with the same email. Without handling this, they'll end up with two separate accounts.

```ts
// auth.ts
export const { handlers, auth, signIn, signOut } = NextAuth({
  // ...
  callbacks: {
    async signIn({ user, account, profile }) {
      if (!user.email) return false;

      // Check if a user with this email already exists
      const existingUser = await db.query.users.findFirst({
        where: eq(users.email, user.email),
      });

      if (existingUser && account) {
        // Link the new provider to the existing account
        await db.insert(accounts).values({
          userId: existingUser.id,
          provider: account.provider,
          providerAccountId: account.providerAccountId,
          type: account.type,
          access_token: account.access_token,
          refresh_token: account.refresh_token,
          expires_at: account.expires_at,
        }).onConflictDoNothing();

        return true;
      }

      return true;
    },
  },
});
```

## Custom OAuth provider

For a provider not built into Auth.js:

```ts
import NextAuth from 'next-auth';

export const { handlers, auth } = NextAuth({
  providers: [
    {
      id: 'linear',
      name: 'Linear',
      type: 'oauth',
      clientId: process.env.LINEAR_CLIENT_ID!,
      clientSecret: process.env.LINEAR_CLIENT_SECRET!,
      authorization: {
        url: 'https://linear.app/oauth/authorize',
        params: { scope: 'read write' },
      },
      token: 'https://api.linear.app/oauth/token',
      userinfo: 'https://api.linear.app/graphql',
      async profile(profile) {
        // Linear returns GraphQL — fetch the actual user
        const res = await fetch('https://api.linear.app/graphql', {
          method: 'POST',
          headers: {
            'Content-Type': 'application/json',
            Authorization: `Bearer ${profile.access_token}`,
          },
          body: JSON.stringify({ query: '{ viewer { id name email avatarUrl } }' }),
        });
        const { data } = await res.json();
        return {
          id: data.viewer.id,
          name: data.viewer.name,
          email: data.viewer.email,
          image: data.viewer.avatarUrl,
        };
      },
    },
  ],
});
```

## Storing access tokens for API calls

If you need to call the provider's API on behalf of the user after sign-in, you need the access token. Store it in the database via the adapter — the `accounts` table holds `access_token` and `refresh_token` automatically.

```ts
// Retrieve a stored access token to call GitHub API as the user
async function getGitHubToken(userId: string): Promise<string | null> {
  const account = await db.query.accounts.findFirst({
    where: and(
      eq(accounts.userId, userId),
      eq(accounts.provider, 'github'),
    ),
  });

  if (!account?.access_token) return null;

  // Check expiry (GitHub tokens don't expire, but others do)
  if (account.expires_at && account.expires_at < Date.now() / 1000) {
    return refreshToken(account);
  }

  return account.access_token;
}

async function refreshToken(account: typeof accounts.$inferSelect): Promise<string | null> {
  if (!account.refresh_token) return null;

  const response = await fetch('https://github.com/login/oauth/access_token', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Accept: 'application/json' },
    body: JSON.stringify({
      client_id: process.env.GITHUB_CLIENT_ID,
      client_secret: process.env.GITHUB_CLIENT_SECRET,
      grant_type: 'refresh_token',
      refresh_token: account.refresh_token,
    }),
  });

  const tokens = await response.json();

  await db.update(accounts)
    .set({
      access_token: tokens.access_token,
      refresh_token: tokens.refresh_token ?? account.refresh_token,
      expires_at: tokens.expires_in ? Math.floor(Date.now() / 1000) + tokens.expires_in : null,
    })
    .where(eq(accounts.id, account.id));

  return tokens.access_token;
}
```

## Scopes

Request only what you need. Broad scopes reduce conversion — users are more likely to authorize `read:user` than `repo` (full repository access).

```ts
GitHub({
  clientId: process.env.GITHUB_CLIENT_ID!,
  clientSecret: process.env.GITHUB_CLIENT_SECRET!,
  // Default: read:user, user:email — enough for auth
  // Add 'repo' only if you need repository access
});
```

For Google, the minimum for auth is the `openid`, `email`, and `profile` scopes, which are included by default.

## Production checklist

**Redirect URIs** — Add both `http://localhost:3000/api/auth/callback/github` (dev) and `https://yourdomain.com/api/auth/callback/github` (prod) in the GitHub OAuth app settings. Mismatched redirect URIs are the most common OAuth error.

**NEXTAUTH_SECRET** — Required in production. Generate with `openssl rand -base64 32`.

**NEXTAUTH_URL** — Set to your production domain. Auth.js uses it to construct callback URLs.

**Error handling** — OAuth errors come back as query params (`?error=access_denied`). Handle them in your sign-in page.

```ts
// app/auth/error/page.tsx
export default function AuthError({
  searchParams,
}: {
  searchParams: { error?: string };
}) {
  const message = {
    OAuthAccountNotLinked: 'An account with this email already exists. Sign in with your original provider.',
    OAuthCallbackError: 'Something went wrong during sign in. Please try again.',
    AccessDenied: 'Access was denied.',
  }[searchParams.error ?? ''] ?? 'An error occurred during sign in.';

  return <div>{message}</div>;
}
```

The pattern: Auth.js handles the protocol; you handle account linking, token storage, and scope selection based on what you actually need.
