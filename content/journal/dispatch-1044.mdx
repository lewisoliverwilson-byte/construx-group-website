title: "Apache Iceberg: open table format for analytics — ACID transactions on object storage"
date: "2033-07-12"
excerpt: "Apache Iceberg is an open table format for large-scale analytic datasets stored on object storage (S3, GCS, ADLS). A table format defines how files are organised, how schemas are tracked, and how queries discover which files to read. The original Hive format stored this metadata in a centralised metastore, which became a bottleneck and a single point of failure. Iceberg stores table metadata as JSON and Avro files alongside the data files — no external metastore required. Iceberg adds ACID transactions: concurrent writers use optimistic concurrency with snapshot isolation, each commit creates a new metadata snapshot without modifying existing files. Time travel is native: query any historical snapshot by timestamp or snapshot ID. Schema evolution is safe: add, rename, reorder, and drop columns without rewriting data files. Hidden partitioning: Iceberg tracks partition transforms in metadata so queries don't need to know the physical partitioning scheme."

## Creating and querying Iceberg tables

```sql
-- Spark SQL: create and manage Iceberg tables
-- Iceberg integrates with Spark, Trino, Flink, DuckDB, StarRocks

-- Create an Iceberg table on S3
CREATE TABLE construx_catalog.analytics.orders (
  order_id      BIGINT,
  tenant_id     STRING,
  status        STRING,
  total_pence   BIGINT,
  created_at    TIMESTAMP,
  processed_at  TIMESTAMP
)
USING iceberg
PARTITIONED BY (
  months(created_at),   -- hidden partition: Iceberg stores month(created_at) metadata
  tenant_id             -- explicit partition: high-cardinality partition for tenant isolation
)
LOCATION 's3://construx-lakehouse/analytics/orders'
TBLPROPERTIES (
  'write.parquet.compression-codec' = 'zstd',
  'write.target-file-size-bytes'    = '134217728',   -- 128MB target per file
  'write.delete.mode'               = 'merge-on-read',
  'history.expire.max-snapshot-age-ms' = '604800000' -- 7 days snapshot retention
);

-- Insert data (ACID: concurrent writers don't conflict)
INSERT INTO construx_catalog.analytics.orders
SELECT order_id, tenant_id, status, total_pence, created_at, now()
FROM staging.raw_orders
WHERE processed_at IS NULL;

-- Query with automatic partition pruning (no need to filter on partition column)
SELECT
  tenant_id,
  count(*)                         AS order_count,
  sum(total_pence) / 100.0        AS revenue_gbp,
  avg(total_pence) / 100.0        AS avg_order_gbp
FROM construx_catalog.analytics.orders
WHERE created_at >= TIMESTAMP '2033-01-01'
  AND status = 'completed'
GROUP BY tenant_id
ORDER BY revenue_gbp DESC;

-- Time travel: query data as of a past snapshot
SELECT count(*) FROM construx_catalog.analytics.orders
TIMESTAMP AS OF '2033-06-01 00:00:00';  -- query historical state

-- By snapshot ID
SELECT count(*) FROM construx_catalog.analytics.orders
VERSION AS OF 3821749562104812;

-- Schema evolution: add a column (no data rewrite)
ALTER TABLE construx_catalog.analytics.orders
ADD COLUMN discount_pence BIGINT AFTER total_pence;

-- Rename a column (safe — Iceberg tracks column IDs, not names)
ALTER TABLE construx_catalog.analytics.orders
RENAME COLUMN processed_at TO fulfilled_at;
```

## Compaction and maintenance

```python
# PySpark: Iceberg table maintenance
# Run as a scheduled job — compacts small files, expires old snapshots

from pyspark.sql import SparkSession

spark = (
    SparkSession.builder
    .config("spark.sql.extensions", "org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions")
    .config("spark.sql.catalog.construx_catalog", "org.apache.iceberg.spark.SparkCatalog")
    .config("spark.sql.catalog.construx_catalog.type", "glue")    # AWS Glue as Iceberg catalog
    .config("spark.sql.catalog.construx_catalog.warehouse", "s3://construx-lakehouse/")
    .getOrCreate()
)

# Compact small files: rewrite data files into 128MB target size
spark.sql("""
    CALL construx_catalog.system.rewrite_data_files(
        table => 'analytics.orders',
        strategy => 'binpack',
        options => map(
            'target-file-size-bytes', '134217728',
            'min-input-files', '5'   -- only compact if ≥5 small files exist
        )
    )
""")

# Expire old snapshots: remove metadata for snapshots older than 7 days
spark.sql("""
    CALL construx_catalog.system.expire_snapshots(
        table => 'analytics.orders',
        older_than => TIMESTAMP '2033-07-05 00:00:00',
        retain_last => 5   -- always keep at least 5 snapshots regardless of age
    )
""")

# Remove orphan files: data files not referenced by any snapshot
# (can accumulate from failed writes)
spark.sql("""
    CALL construx_catalog.system.remove_orphan_files(
        table => 'analytics.orders',
        older_than => TIMESTAMP '2033-07-05 00:00:00'
    )
""")

# Rewrite manifests: optimise manifest files for query planning
spark.sql("""
    CALL construx_catalog.system.rewrite_manifests(
        table => 'analytics.orders'
    )
""")

# Show table history
spark.sql("SELECT * FROM construx_catalog.analytics.orders.history").show(10, truncate=False)
# +--------------------+-------------------+---------+-------------------+
# |made_current_at     |snapshot_id        |parent_id|is_current_ancestor|
# +--------------------+-------------------+---------+-------------------+
# |2033-07-12 09:00:01 |3821749562104812   |...      |true               |
# |2033-07-12 06:00:00 |3821749562104811   |...      |true               |
```

## DuckDB and Trino integration

```sql
-- DuckDB: query Iceberg tables locally (no Spark required)
INSTALL iceberg;
LOAD iceberg;

-- Scan an Iceberg table directly from S3
SELECT count(*), sum(total_pence) / 100.0 AS revenue_gbp
FROM iceberg_scan('s3://construx-lakehouse/analytics/orders',
    allow_moved_paths = true);

-- Trino: query Iceberg at scale (distributed SQL over Iceberg on S3)
-- trino-config/catalog/iceberg.properties:
-- connector.name=iceberg
-- iceberg.catalog.type=glue
-- hive.metastore.glue.region=eu-west-2
-- iceberg.file-format=PARQUET
-- iceberg.compression-codec=ZSTD

-- Query from Trino CLI
SELECT
    date_trunc('day', created_at)  AS day,
    count(*)                       AS orders,
    sum(total_pence) / 100.0       AS revenue_gbp
FROM iceberg.analytics.orders
WHERE created_at BETWEEN TIMESTAMP '2033-06-01' AND TIMESTAMP '2033-07-01'
  AND status = 'completed'
GROUP BY 1
ORDER BY 1;
```

Apache Iceberg vs Delta Lake vs Apache Hudi vs Hive: Hive's table format stores partition metadata in a centralised metastore and uses file-listing for query planning — slow on S3 (thousands of LIST calls), no ACID, schema changes require data rewrites. Delta Lake (Databricks) adds ACID via a `_delta_log` transaction log but is tightly integrated with the Databricks ecosystem. Apache Hudi focuses on near-real-time CDC use cases with record-level upserts. Iceberg is the most open of the three: the spec is vendor-neutral, and Spark, Trino, Flink, Dremio, StarRocks, DuckDB, and PyIceberg all have first-class support. Iceberg's hidden partitioning is a significant UX improvement over Hive and Delta: consumers query without knowing the physical layout, and partitioning can be changed without rewriting data. For new lakehouses on S3, Iceberg is the default choice unless you're already deep in the Databricks ecosystem (Delta) or need record-level CDC with sub-minute latency (Hudi).
