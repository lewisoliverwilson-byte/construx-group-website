date: "2032-01-04"
excerpt: "ClickHouse materialized views are incrementally updated aggregations: when a row is inserted into the source table, ClickHouse automatically updates the materialized view with the contribution of that row. No batch job, no scheduler. The view's storage engine is usually AggregatingMergeTree, which stores partial aggregation states and merges them lazily. The result is a table you can query at microsecond latency that reflects all data up to the last insert — real-time analytics without Spark."

Aggregate on insert. Query the view. Real-time without a scheduler.

## Source table and materialized view

```sql
-- Source table: raw order events
CREATE TABLE order_events (
  event_time   DateTime64(3, 'UTC'),
  order_id     String,
  customer_id  String,
  status       LowCardinality(String),
  total_cents  UInt64,
  region       LowCardinality(String)
)
ENGINE = MergeTree()
ORDER BY (event_time, customer_id);

-- Materialized view: orders per hour per region
-- AggregatingMergeTree stores partial states that are merged on read
CREATE TABLE orders_hourly_agg (
  hour         DateTime,
  region       LowCardinality(String),
  order_count  AggregateFunction(count),
  total_cents  AggregateFunction(sum, UInt64),
  unique_cust  AggregateFunction(uniqExact, String)
)
ENGINE = AggregatingMergeTree()
ORDER BY (hour, region);

-- The view populates orders_hourly_agg when rows are inserted into order_events
CREATE MATERIALIZED VIEW orders_hourly_mv
TO orders_hourly_agg
AS SELECT
  toStartOfHour(event_time)   AS hour,
  region,
  countState()                AS order_count,
  sumState(total_cents)       AS total_cents,
  uniqExactState(customer_id) AS unique_cust
FROM order_events
WHERE status = 'paid'
GROUP BY hour, region;
```

## Query the materialized view

```sql
-- Query the aggregated view — sub-millisecond for billions of source rows
SELECT
  hour,
  region,
  countMerge(order_count)              AS orders,
  sumMerge(total_cents) / 100.0        AS total_gbp,
  uniqExactMerge(unique_cust)          AS unique_customers,
  sumMerge(total_cents) / countMerge(order_count) / 100.0 AS avg_order_value
FROM orders_hourly_agg
WHERE hour >= now() - INTERVAL 7 DAY
GROUP BY hour, region
ORDER BY hour DESC, orders DESC;

-- Result:
-- 2031-12-28 14:00:00 │ eu-west-2 │ 841  │ 4,205.00 │ 791  │ 4.99
-- 2031-12-28 14:00:00 │ us-east-1 │ 612  │ 3,060.00 │ 588  │ 4.99
-- 2031-12-28 13:00:00 │ eu-west-2 │ 773  │ 3,865.00 │ 741  │ 5.00
```

## Chained materialized views — daily from hourly

```sql
-- Daily aggregation built on top of the hourly MV
CREATE TABLE orders_daily_agg (
  day          Date,
  region       LowCardinality(String),
  order_count  AggregateFunction(count),
  total_cents  AggregateFunction(sum, UInt64),
  unique_cust  AggregateFunction(uniqExact, String)
)
ENGINE = AggregatingMergeTree()
ORDER BY (day, region);

CREATE MATERIALIZED VIEW orders_daily_mv
TO orders_daily_agg
AS SELECT
  toDate(hour)                   AS day,
  region,
  countMergeState(order_count)   AS order_count,
  sumMergeState(total_cents)     AS total_cents,
  uniqExactMergeState(unique_cust) AS unique_cust
FROM orders_hourly_agg
GROUP BY day, region;
```

## Projections — alternative sort orders on the same data

```sql
-- Primary: ordered by (event_time, customer_id)
-- Projection: also ordered by (customer_id, event_time) for fast per-customer queries
ALTER TABLE order_events ADD PROJECTION orders_by_customer (
  SELECT * ORDER BY customer_id, event_time
);

-- Materialise the projection for existing data
ALTER TABLE order_events MATERIALISE PROJECTION orders_by_customer;

-- ClickHouse automatically selects the projection when the query benefits from it
SELECT * FROM order_events WHERE customer_id = 'cust-001' ORDER BY event_time;
-- Uses the orders_by_customer projection — scans only rows for that customer
```

## Monitor MV health

```sql
-- Check if the MV is keeping up with inserts
SELECT
  database,
  table,
  query,
  read_rows,
  written_rows,
  elapsed
FROM system.query_log
WHERE query LIKE '%materialized%'
  AND type = 'QueryFinish'
ORDER BY event_time DESC
LIMIT 10;

-- Check for errors in MV processing
SELECT * FROM system.query_log
WHERE type = 'ExceptionWhileProcessing'
  AND query LIKE '%orders_hourly_mv%'
ORDER BY event_time DESC;
```

ClickHouse materialized views vs dbt: dbt runs SQL transformations on a schedule (hourly, daily) as full-table rebuilds or incremental appends. Between runs, the output is stale. ClickHouse materialized views update synchronously on insert — every inserted row immediately contributes to the aggregation. dbt is simpler to write and debug (plain SQL, version-controlled), but inherently batch. ClickHouse MVs are incremental by design, with no scheduler to maintain, but partial states are harder to inspect and debug when something goes wrong.
